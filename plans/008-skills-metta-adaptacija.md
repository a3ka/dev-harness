# План 008 — скилы Мэтта: четыре адаптации и встройка в воркфлоу

Номер выдан механизмом: `next_id.sh PLAN` → 008, тег `id/PLAN/008`.

## Причина

Решение владельца 2026-08-18 по разбору `mattpocock/skills` (клон прочитан целиком, разбор в
сессии): взять ЧЕТЫРЕ скила — `grilling`(+`grill-me`), `writing-for-agents`, `tdd`,
`diagnosing-bugs` — и **встроить их в воркфлоу так, чтобы агенты знали, КОГДА что запускать**.
Отказы записаны с причинами (to-spec, handoff, setup/triage/tickets, инженерные сессийные) —
сильные эквиваленты у нас уже есть, второй источник не заводим.

Предмет закрывает шаг 6 ROADMAP («два скила» — разбор расширил до четырёх с обоснованием).

## Подход — сам следует новому регламенту

Гриллинг владельца → контракт 003 → критик (порог) → заморозка → раздача исполнителю по зонам →
адверсарий → ревьюер. План описывает; контракт замораживает; скилы не устав — инструмент.

## Сквозные решения

- **Скилы живут в репозитории**, `skills/` в корне, раздаются пином — не руками по машинам.
  Первый шаг — замер: откуда omp открывает скилы (`--skills`, discovery) — профиль или проект;
  если только профиль — пин-слой кладёт их туда при `npm run overlay`.
- **Язык тел скилов** — развилка для гриллинга (вопрос 2): норма «всё по-русски» против
  преобученности leading words Мэтта на английском.
- **Указатели, не пересказ**: встройка в воркфлоу — по грамматике самого `writing-for-agents`:
  в каждой роли строка-указатель («когда X — открой skills/…/SKILL.md»), в `AGENTS.md` — раздел
  «Скилы» с фронтированными словами-триггерами. Никаких пересказов тел в ролях.
- **Зоны — по связности правок** (уроки Н-22, пять экземпляров): каталог `skills/` целиком в
  зону исполнителя; правки ролей с указателями — в зону архитектора; `AGENTS.md` — архитектор со
  строкой владельца (устав).

## Шаги — с зависимостями, порядок проверен

1. **Замер discovery omp** (архитектор): куда omp смотрит за скилами; фиксация пути.
2. **Гриллинг владельца** (архитектор, скил `grilling` — первое живое применение): раунды по
   фронтиру до пустоты; выход — ответы на развилки, они ложатся в контракт.
3. **Контракт 003** (архитектор): предмет, критерий готовности командами, зоны, перечень
   указателей по ролям. Замер следующего номера: `next_id.sh CONTRACT` → 003.
4. **Критик, один круг** (порог: блокирует только обход).
5. **Заморозка** `freeze_contract.sh`.
6. **Раздача** (исполнитель): четыре тела скилов адаптированы и положены в `skills/`, overlay
   кладёт их в профиль omp, фикстура-проверка: скил ОБНАРУЖИВАЕТСя сессией (захват запуска).
7. **Встройка** (архитектор, своя зона): указатели в `roles/architect.md`, `roles/implementer.md`,
   раздел в `AGENTS.md`; правки `AGENTS.md` — со строкой владельца в коммите.
8. **Судьи**: адверсарий (обходы: скил не обнаруживается; указатель не срабатывает; скил
   противоречит норме), ревьюер (область, сырой вывод).

## Приёмка — командами

1. Каталог `skills/` содержит ровно четыре адаптации; `git ls-files skills/ | wc -l` — числом из
   вывода, не памяти.
2. `bash scripts/check_skills.sh` → 0 — НОВЫЙ барьер: каждый скил обнаруживается omp
   (захват запуска с `--skills=<имя>`), фронтматтер в грамматике; отсутствующий/кривой → 1.
3. `grep -c 'skills/' roles/architect.md roles/implementer.md` — ≥ 1 указателя в каждом.
4. `npm run check:antiplacebo`, `check:ci-parity`, `check:charter`, `check:zones`, `check:gen`
   → 0; `check:skills` в CI.
5. Живой прогон: сессия отвечает словом из тела скила при триггере-указателе (гриллинг-раунд
   открывается по «прогрильли меня»).

## Что НЕ входит

Остальные 29 скилов репозитория; перевод всего корпуса; скилы для судей (их предмет — вердикты,
не инженерия); изменения регламента кругов.

## Риски, названные прямо

- Discovery omp может требовать профильного каталога — тогда overlay обязан класть скилы туда,
  и «в репозитории» значит «источник», а не «место чтения».
- Порог «скил обнаруживается» — захват запуска, не семантика: скил, который читается и
  игнорируется, механизмом не ловится — `cognitive-only`, ловец ревьюер.
