- [ ] **С-1 (implementer; совет).** `ln -s` идёт по ссылке, которую несёт закреплённое дерево.
  - **Фрагмент.** `scripts/check_architecture_contract.sh:274`:
    `if ! ln -s "$(cd "$root/node_modules" && pwd -P)" "$tmp/node_modules" 2>/dev/null; then`.
    Нет ни `-n`/`-T`, ни проверки, что `$tmp/node_modules` ещё не существует.
  - **Что не так.** Если `git archive` пина уже выгрузил `node_modules`, видны два исхода.
    - (а) `node_modules` в пине — ССЫЛКА на каталог. `ln` идёт по ней и создаёт
      `<цель>/node_modules -> <донор>/node_modules` ВНЕ выгрузки. `rm -rf "$tmp"`
      эту ссылку не убирает. Повторный `arch187_model_prepare` в том же make_task
      падает на «File exists» и печатает ложную причину
      `ARCH_BRIEF_DEPS: node_modules выгрузки не подключить`. Если ссылка ведёт
      в `node_modules` донора, донор изменён. Это против инварианта 1
      «cleanup удаляет только свою выгрузку — донор не трогается».
      Мир D5, OBJECT: rc 1, в каталоге-жертве появилось
      `node_modules -> …/w-architecture/node_modules`. На базе жертва не тронута.
    - (б) `node_modules` в пине — КАТАЛОГ. Ссылка ложится внутрь него, и
      исполняются модули, закоммиченные в пин, а не модули донора с равным lock.
      Мир D6: rc 0, в паке `PIN_VENDORED`, `DEP203_OK` нет.
  - **Почему совет, а не блок.** Пин с закоммиченным `node_modules` — не
    конформный npm-вход по Демаркации 203. Кроме того, дверь и так исполняет
    `tooling/checks/cli.js` пина с полными правами, так что новой возможности
    злоумышленнику нет. Остаётся случайная поломка: `.gitignore` с
    `node_modules/` не игнорирует ССЫЛКУ `node_modules`.
  - **Простая форма.** Тот же приём, что у ссылки `cli.js` в 187 (`:248`). Перед `ln`:
    `if [ -e "$tmp/node_modules" ] || [ -L "$tmp/node_modules" ]; then rm -rf "$tmp"; ARCH187_REFUSAL="ARCH_BRIEF_DEPS: закреплённое дерево несёт node_modules: $root; npm ci на закреплённом пине"; return 1; fi`.
    Другой вариант — `ln -sT`. Строки приёмки 203 эта правка проходит: в мирах
    батареи пин `node_modules` не несёт.
