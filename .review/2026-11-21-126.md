## Советы

- [x] **С-1 (architect; выжившие М2 и М3 — равносильные мутанты на bash 5.2; остаточный риск — см. «Закрытие»).** Строки `trap 'exit 143' TERM` и `trap 'exit 130' INT` (`scripts/check_architecture_contract.sh:514-515`) ни одна клетка не прибивает.
  - М2 (нет строки 514) и М3 (нет строки 515): `--repo` на полной копии дерева — rc 0, `CELLS=82 FAILURES=0`. В моей пробе через `timeout -s TERM|INT 0.9` группе и при TERM только родителю — тоже leftover=[].
  - Причина: GNU bash 5.2.21 выполняет EXIT-ловушку подоболочки, даже когда та умирает от TERM или INT. Проба: `( trap "echo exit-trap-ran" EXIT; sleep 5 ) & kill -TERM $!` печатает `exit-trap-ran`, `sub_rc=143`.
  - Свойство «файл не переживает сигнал» без этих строк не нарушается, поэтому это не блок.
  - По 050: явные ловушки страхуют от оболочки, которая EXIT при смерти от сигнала не выполняет, и задают явный rc 128+N. Более простая форма проходит те же строки приёмки только на этом bash. Совет: либо принять как явную защиту и записать в лист, что строки 514-515 равносильны на bash 5.2, либо снять их. Мутантом это не ловится, решать по весу.
- [x] **С-2 (architect; М5 выжил батарею — порядок «ловушка до mktemp» не прибит; остаточный риск — см. «Закрытие»).** М5 ставит три ловушки после `mktemp` и проверки `[ -f ]`. На полной копии `--repo` даёт rc 0, `CELLS=82 FAILURES=0`.
  - Окно достижимо. Случайный TERM группе в первые 70 мс вызова формы `$(arch187_brief …)` (300 попыток на вариант): М5 — 2 утечки `tmp.*` из 300, дверь OBJECT — 0 из 300. Медианное время от старта до `mktemp` — 32 мс, жизнь `mktemp` — 1–3 мс, весь вызов — около 64 мс.
  - Детерминированно окно открывает шим `mktemp` в PATH: настоящий `mktemp`, затем `sleep 1`, сигнал группе во время sleep. Дверь OBJECT: leftover=[] на TERM и на INT. М5: `leftover=['tmp.…']` на TERM и на INT. call-1 `d23d301ddd`: тоже утечка.
  - В двери OBJECT порядок верный (`:512-517`), поэтому это не блок. Это пробел батареи: регрессия к М5 пройдёт зелёной.
  - Что закрыть: клетка `brief-signal-alloc-window` с таким шимом и TERM/INT группе (ожидание leftover=[]) плюс стаб «ловушка после mktemp». На М5 клетка должна покраснеть.
- [x] **С-3 (оркестратор → следующий предмет; тот же класс дефекта вне диффа; остаточный риск — см. «Закрытие»).** В `arch187_model_check` есть `mktemp` без сигнальной ловушки: `scripts/check_architecture_contract.sh:572-579`. Rm там только при нормальном возврате. Вызов идёт из `:960`, долгий шаг — `check --base` модели.
  - Код был в main до этого PR (`git show f9f029592b:scripts/check_architecture_contract.sh`, строка 534). Дифф Б-5 его не трогал, а скоуп вызова 2 — только Б-1 брифа. Поэтому это не блок и не требование к PR #1205.
  - При TERM/INT группе во время `check --base` файл stderr, по построению, должен оставаться в TMPDIR. [INFERENCE] Пробой не измерено: в скоуп вызова не входит.
  - Совет: отдельный предмет или пункт плана — та же форма (подоболочка + EXIT до mktemp), со своей клеткой.
- [x] **С-4 (на заметку; остаточное окно честной двери; остаточный риск — см. «Закрытие»).** Даже с ловушкой до `mktemp` окно остаётся. Если сигнал убивает сам `mktemp` между созданием файла и печатью имени, имя до `errf` не доходит.
  - Это микросекунды внутри coreutils. В моей развёртке 0 из 300, при шиме «создал, напечатал, ждёт» — 0 утечек: присваивание успевает до ловушки.
