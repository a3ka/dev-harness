# Находки ревьюера — 129, круг 1

- [ ] **R129-1 (БЛОКИРУЕТ; семантика, инвариант 2; заявленное ≠ сделанному).**
  Обязательство: инвариант 2 замороженного `frozen/contracts/129/1` — «ребёнок получает
  `[<селектор запасной модели тира>, ...patterns]`».
  Фрагмент: `.omp/extensions/fallback-route.ts:111,121` —
  `const [primary, ...tail] = patterns` … `model: [target, ...tail.filter((p) => p !== target)]`:
  `patterns[0]` (исчерпанный примарий) из списка ВЫБРОШЕН.
  Наблюдение (стенд реального omp 18.3.1, `P129_KEEP=1`, лог omp «Configured subagent runtime
  model fallback chain», `role: subagent:Child129`): с реализацией —
  `"requested":["stub-zai/glm"]`; с честной моделью батареи на том же мире —
  `"requested":["stub-zai/glm","stub-anthropic/opus"]`. Коммит f977f6ee0 при этом утверждает
  «ребёнок получает список [селектор fallback тира, ...patterns]» — описание не совпадает с кодом.
  Последствие: у ребёнка в цепочке нет примария тира на всю его жизнь (живая цепочка `slow`
  = `["zai/glm-5.3"]` = сам F), т.е. после восстановления провайдера P отказ F у долгоживущего
  ребёнка некуда отвести. Честно: в моём одноразовом мире «x-stale» (P: quota соседу/ok ребёнку,
  F: ok соседу/400 ребёнку) оба варианта умирают одинаково — P в cooldown omp; различие
  исхода в стенде за бюджет не построено, различие интерфейса хука — построено (лог выше).
  Починка: `model: [target, ...patterns]` (или с отсевом дубля `target`, но с `primary`).

- [ ] **R129-2 (БЛОКИРУЕТ по норме 050; ACCIDENTAL).**
  Фрагмент: `fallback-route.ts:94-95` — `const turn = snapshot ?? (event as TurnSnapshot)`:
  ветвь «снимок хода без обёртки `message`». Отсутствующее свойство: ни контракт
  (§Существующее 4: `message_end` с `stopReason`/`errorStatus`/`errorMessage` хода), ни клетка
  c1–c6, ни строка приёмки такой формы события не требуют; потребителя нет. Более простая форма,
  проходящая те же строки приёмки: только `event.message` — ровно так у честной модели
  `model/fallback-route.ts:40`, `battery.py --model` → rc 0 «cells=6 red=0» (мой прогон).
  Ветвь вдобавок расширяет сигнал: любой объект события с полями хода на верхнем уровне
  засчитывается исчерпанием. Починка: удалить ветвь.
