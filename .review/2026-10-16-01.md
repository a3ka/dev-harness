## Открыто — блокирует

- [x] **Рв-PP-1 (дефект, fail-open нового барьера).** Строка
  `git -C "$ROOT" cat-file -e "${LIVE_MAIN}^{commit}" 2>/dev/null || return 1` в `merges_main_into_wip`
  молча выключает запрет, когда объекта живого main нет локально. Это тот же класс «объекта origin нет
  в основном чекауте», ради которого делался фикс. Проба P3g: origin/main ушёл вперёд, клон не обновлён,
  push формы merge main→wip в wip/999 → rc=0 без единой строки вывода. Отсутствующее свойство:
  отказ здесь должен быть именованным, как у диапазона. Чинить можно двумя способами: именованный ОТКАЗ
  или проверка предков по локальному `refs/remotes/origin/main` либо `main`, раз предок устаревшего main
  остаётся предком живого.
  - ЗАКРЫТ круг 2 (`5742418f1`, вердикт `verdicts/review/prepush-failopen-v2.md`): выбран именованный ОТКАЗ («проверить слияние на merge main невозможно … git fetch origin
    main»). P3g r2 rc=1, P3g' rc=1; без merge в диапазоне ложного отказа нет: P4, P4' (удаление ref), P4m — rc=0.
- [x] **Рв-PP-2 (дыра, обход нового барьера).** Запрет проверяет, лежит ли сам второй родитель в истории
  живого main. Проба P3e: на локальном main один невыпушенный коммит, `git merge --no-ff <локальный main>`
  в wip → rc=0, хотя merge приносит в wip весь main. Это обычное состояние основного чекаута (запись
  журнала закоммичена на main, но ещё не запушена) и та самая форма рецидивов Н-191/Н-294

  отклоняться. Более простая форма, проверенная на объектах проб: `! merge-base --is-ancestor

  int-форму P3c.
