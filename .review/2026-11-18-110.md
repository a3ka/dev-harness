# Находки ревьюера: owner-PR #1093

Правка — за автором ADR (владелец/консультант в его мандате). Доказательства и сырой вывод — в вердикте.

## Блоки

- [ ] Б-1. ADR:9, :11 — перенос санкции на новый OBJECT проверяется `git diff --stat`, а он не отличает «добавлены только поле `СДАЧА:` и лист» от смысловой правки контракта той же формы и не показывает, что изменённый файл унаследован из main. Закрывающее свойство: условие п.3 проверяется содержанием дельты по путям предмета (ЗОНА-строки контракта + путь из `СДАЧА:`): в контракте только добавленные строки поля сдачи, удалённых строк нет; лист — новый файл по пути из `СДАЧА:`; каждый иной изменённый путь совпадает с блобом main (`git diff <main> <новый> -- <путь>` пуст); в запись п.5 идёт этот вывод (или его sha256), а не `--stat`.
- [ ] Б-2. ADR:5 — область перечнем «198–204» включает Complior-mob 204, чей закоммиченный контракт объявляет себя НЕ экранным («шаблон 132 не экранный — экраны остаются в 198–203», origin/main моба `0c507af`, `.harness/contracts/204-gespraech-host-shvy.md:3`); критерий «полный экранный трек» в дереве не определён, а у моба 201 и 204 слова «ТРЕК» нет вовсе; номера 198–201 без репозитория совпадают с предметами харнесса станции (198 реестр моделей, 199 Sol в изоляции, 200 окно заморозки, 201 done-дверь), а оговорка «независимо от того, какая сессия их ведёт» отвязывает номер от сессии. Закрывающее свойство: область — один критерий с репозиторием, который на закоммиченных деревьях даёт ровно перечень (например: Complior-mob `.harness/contracts/NNN-*.md` с «экранный» в строке `КЛАСС ЗАДАЧИ:`, и станция `contracts/147`, `148`, `149`); 204 исключён либо включён прямо словом владельца как не экранный.
- [ ] Б-3. ADR:7–11, :20 — новые правила (счёт, основание от судьи реализации, перенос санкции) без механизма, без пометки `cognitive-only` и без записанного остаточного риска (AGENTS.md:218–219, правило 1); ловцы названы только в «условии пересмотра». Закрывающее свойство: в ADR есть строка `cognitive-only` с остаточным риском (что машина не ловит: перенос при смысловой дельте, счёт санкций, применение вне области) и ловцами.

## Советы

- [ ] С-1. - [ ] С-2. ADR:10 — «третий и дальнейший узкий вызов одной роли по предмету»: по этой ADR санкционируется только критик (п.2 бюджет ревьюера/адверсария не меняет); «одной роли» читается как расширение на других судей. Точнее — «третий и дальнейший узкий вызов критика по санкции консультанта».
- [ ] С-3. ADR:7–8 — не сказано, что КАП КРУГОВ заморозки остаётся (`scripts/freeze_contract.sh:442–540`, AGENTS.md шаг 3): при трёх и более кругах `freeze_contract` откажет без вердикта арбитра или строки `РАЗРЕШИЛ-ВЛАДЕЛЕЦ:`, а санкция консультанта такой строки не даёт (AGENTS.md правило 11). Ожидание «не держать экраны на словах владельца» с этим не сходится; оговорка убережёт сессии от ложной надежды.
