# Контракт 010 — топология оркестратор/архитектор (декларативная часть)

Номер выдан механизмом: `next_id.sh CONTRACT` → 010, тег `id/CONTRACT/010`. Предмет — решение
владельца (2026-08-24) по уроку Н-47: MiniMax вёл сессию, совмещая оркестратора и архитектора,
и выбрал предмет (009), не оправданный измеренной болью. Разделение ролей ловит этот класс:
frontier-выбор и ред-тесты — на сильной модели (Opus/glm), ведение сессии — на дешёвой (MiniMax).

**Некодовая, декларативная** задача (роли, конфиг, норма). Приёмка делится на ФОРМУ (исполняемые
команды — артефакты на месте, ключевые разделы присутствуют, изменения внесены) и СЕМАНТИКУ
(роль реально несёт обязанности, architect реально стал субагентом) — семантика механически не
измеряется (правило 8: смысл порогом не мерят) и объявлена `cognitive-only` с ловцом-ревьюером.
Механизмы-гейты, ПРИНУЖДАЮЩИЕ топологию (переворот `models_actual`, оправдание болью в
`check_contract_ready`, триггер делегирования, fallback-проверка), — отдельный предмет **011** с
красными тестами (нарезка B, грилинг 2026-08-24, Q1).

## §Предмет — что делаем

Развести ведущую сессию и автора конструкции на две роли:

1. **`roles/orchestrator.md` (новая)** — ведущая сессия. Роль модели `@default` (MiniMax-M3).
   Инвентарь РОВНО: `read, grep, glob, bash, edit, task, todo` (без `write` — новые файлы,
   барьеры/фикстуры, создаёт `architect`; `edit` нужен для ведения HANDOFF; `bash` — git-коммиты,
   теги). Тело роли ОБЯЗАНО нести: стартап-протокол, список обязанностей, раздел «чего НЕ делает
   сам». Обязанности: собеседник владельца; при новом предмете вызывает `architect`-субагента за
   frontier-вариантами; показывает варианты владельцу, собирает решение; после утверждения
   вызывает `architect` за ред-тестами; раздаёт `implementer` по зонам; проводит судей
   (критик → адверсарий → ревьюер); коммитит; ведёт HANDOFF; **приземляет майлстоун** (теги
   `frozen`/`done`, слияние; правку НОРМЫ при приземлении — только со строкой `РАЗРЕШИЛ-ВЛАДЕЛЕЦ:`
   от владельца, правило 11). НЕ делает САМ: frontier-выбор, ред-тесты, суд, реализацию.

   **cognitive-only (до 011):** правило «оркестратор не пишет ред-тесты/предмет сам» механизма
   ЕЩЁ НЕ имеет — `bash` обходит любой инвентарный запрет (`cat > file`). До предмета 011 (триггер

   риск назван прямо: между 010 и 011 оркестратор физически способен вписать ред-тесты сам;

## §Что значит готово

**ФОРМА (исполняемо — команды в §Приёмка):** артефакты на месте, ключевые разделы присутствуют,
изменения внесены этим майлстоуном. Форма закрывает грубые обходы (пустое тело роли, неизменённые
`architect.md`/`AGENTS.md`), но НЕ доказывает годность по смыслу.

**СЕМАНТИКА (`cognitive-only`, ловец — ревьюер чтением):** роль orchestrator реально исполнима по
обязанностям; architect реально переописан субагентом; `AGENTS.md` реально отражает новую
топологию. Механически смысл не измеряется (правило 8) — проверяет ревьюер перед приземлением.
Это законный тип приёмки некодового контракта (AGENTS.md шаг 1: «для некодовой задачи — контракт
другого типа»), а не ослабленный критерий кодового.

## §Зоны

РАБОТА НЕ РАЗДАЁТСЯ: первая перекройка топологии ведётся одним автором (Opus-архитектор в этой сессии + владелец) текущим раскладом по прямому слову владельца — топологию, вводящую разделение ролей, нельзя исполнять по этому же разделению, его ещё нет (курица-яйцо, правило 13).

Пояснение (проза, не машинная строка выше): «не раздаётся» касается только деления РЕАЛИЗАЦИИ на
зоны `architect`↔`implementer`. Декларативную правку веду сам — файлы: `roles/orchestrator.md`,
`roles/architect.md`, `scripts/roles.ts`, `workshop`, `.omp/config.yml`, `.omp/agents/`,
`AGENTS.md`, `contracts/010-*.md`, `NABLIUDENIA.md`, `HANDOFF.md`. Это НЕ обход регламента судей:
критик (круг 1+) и ревьюер (перед приземлением, несёт cognitive-only семантику) проходят как
всегда; адверсарий пропущен — 010 некодовый, красных тестов, которые он ломает, нет (вернётся в
011). Механизмы-гейты 011 раздаются уже по новой топологии.
