# Контракт 010 — топология оркестратор/архитектор (декларативная часть)

Номер выдан механизмом: `next_id.sh CONTRACT` → 010, тег `id/CONTRACT/010`. Предмет — решение
владельца (2026-08-24) по уроку Н-47: MiniMax вёл сессию, совмещая оркестратора и архитектора,
и выбрал предмет (009), не оправданный измеренной болью. Разделение ролей ловит этот класс:
frontier-выбор и ред-тесты — на сильной модели (Opus/glm), ведение сессии — на дешёвой (MiniMax).

Это **некодовая, декларативная** задача (роли, конфиг, норма) — приёмка предъявляется проверяемыми
командами, а не красными тестами. Механизмы-гейты, принуждающие топологию (переворот
`models_actual`, оправдание болью в `check_contract_ready`, триггер делегирования, fallback-проверка),
— отдельный предмет **011** с красными тестами (нарезка B, грилинг 2026-08-24, Q1).

## §Предмет — что делаем

Развести ведущую сессию и автора конструкции на две роли:

1. **`roles/orchestrator.md` (новая)** — ведущая сессия. Модель `@default` (MiniMax-M3, дёшево).
   Инвентарь `read, grep, glob, bash, edit, task, todo` — БЕЗ `write` (новые файлы —
   барьеры/фикстуры — создаёт `architect`; `edit` нужен оркестратору для ведения HANDOFF).
   Оговорка: герметичного разделения инвентарём НЕТ (`bash` обходит через `cat > file`) —
   «оркестратор не пишет ред-тесты сам» держится триггером делегирования (предмет 011), не
   инвентарём; убирание `write` — косметическое сужение соблазна.
   Обязанности: собеседник владельца; при новом предмете вызывает `architect`-субагента за
   frontier-вариантами; показывает варианты владельцу и собирает решение; после утверждения
   вызывает `architect` за ред-тестами; раздаёт `implementer` по зонам; проводит судей
   (критик → адверсарий → ревьюер) по регламенту; коммитит; ведёт HANDOFF; **приземляет
   майлстоун** (теги `frozen`/`done`, слияние; правку НОРМЫ при приземлении — только со строкой
   `РАЗРЕШИЛ-ВЛАДЕЛЕЦ:` от владельца, правило 11). НЕ делает САМ: frontier-выбор, ред-тесты
   (это `architect`), суд (судьи), реализацию (`implementer`).

2. **`roles/architect.md` (правка)** — теперь СУБАГЕНТ, не ведущая сессия. Вызывается
   оркестратором для двух вещей: (а) frontier — предложить варианты развития с ОПРАВДАНИЕМ
   измеренной болью (ссылка на `Н-NN` с ценой; проверить, что боль не `ЗАКРЫТО`); (б) ред-тесты
   (барьер + фикстуры + обманные стабы — одной пачкой). НЕ ведёт сессию, НЕ говорит с владельцем
   напрямую (только через оркестратора-посредника — прямого канала субагент↔владелец нет).

3. **Стартап-протокол — у ОБОИХ ролей.** И оркестратор, и архитектор при старте/вызове читают
   ДЕРЕВО сами (HANDOFF → активный контракт+вердикты → NABLIUDENIA → ROADMAP), не доверяя
   пересказу. Урок Н-47/HANDOFF: MiniMax доверял устаревшей стенограмме вместо дерева — субагент,
   получивший только выжимку оркестратора, повторит дефект.

4. **`workshop` (лаунчер)** — `SESSION_ROLE` меняется с `architect` на `orchestrator`: сессия
   поднимается оркестратором на его модели. Механика подъёма (промпт из `gen-harness --prompt`,
   модель из `.omp/agents/<роль>.md`) не меняется — меняется только имя роли сессии.

5. **`.omp/config.yml` + `.omp/agents/`** — роль orchestrator объявлена (модель `@default`);
   architect остаётся `@slow` (glm-5.2 primary). Fallback-множество `{glm-5.2, opus}` и его
   проверка — предмет 011 (механизм), здесь только запись в норме, что fallback БУДЕТ.

6. **`AGENTS.md` (устав)** — раздел «Три роли»/«Сессию ведёт РОЛЬ» переписывается: сессию ведёт
   `orchestrator`, `architect` — субагент frontier+ред-тестов. Правка устава требует строки
   `РАЗРЕШИЛ-ВЛАДЕЛЕЦ:` в изменяющем коммите (правило 11).

## §Зоны

РАБОТА НЕ РАЗДАЁТСЯ: первая перекройка топологии ведётся одним автором (Opus-архитектор в этой сессии + владелец) текущим раскладом по прямому слову владельца — топологию, вводящую разделение ролей, нельзя исполнять по этому же разделению, его ещё нет (курица-яйцо, правило 13).

Пояснение (проза, не машинная строка выше): «не раздаётся» касается только деления РЕАЛИЗАЦИИ
на зоны `architect`↔`implementer` — декларативную правку (`roles/`, `workshop`, `.omp/`,
`AGENTS.md`) веду сам. Это НЕ обход регламента судей: критик (круг 1) и ревьюер (перед
приземлением) проходят как всегда; адверсарий пропущен — 010 некодовый, красных тестов, которые
он ломает, нет (вернётся в 011). Механизмы-гейты 011 раздаются уже по новой топологии.
