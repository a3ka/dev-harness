## Предмет

Слово владельца 2026-10-03 (дословно, HANDOFF «ГДЕ МЫ» §Н-186а):
«бугфикс двери 072 — ПЕРВЫМ, до продолжения 078/071». Четыре предмета

Предмет (г). Ветка `ctx` жёсткого режима (≥`CTX_HARD`, по умолчанию 500000)
ждёт живых субагентов, но с таймаутом: пока изменение <2 мин — сторож

журналы состарились — маркер ставится как в обычном режиме; если по
истечении 30 минут всё ещё есть свежие — маркер ставится
ПРИНУДИТЕЛЬНО с записью в отчёт/HANDOFF имён живых субагентов (не
молчаливая принудительная смерть).

~12:48 оборвал ТРИ живых task-субагента, не дождавшись завершения; двое

## Frontier (по коду)

- **В1 «env полностью, без флага»** — опираться только на
  `GIT_AUTHOR_NAME`/`GIT_COMMITTER_NAME`. ОТВЕРГНУТ: env-переменные
  bash не наследуются автоматически в каждый под-процесс одинаково;
  оркестратор может запустить дверь через `env -i`, и env не дойдёт;
  явный флаг --as надёжнее и читаем в прогоне (видно в логах кто
  вызвал), env — невидим.
- **В2 «только --as, без env»** — обязательный аргумент, иначе отказ.
  ОТВЕРГНУТ: env-источник полезен для оркестратора (выставляется в
  панели tmux перед вызовом); лишать его — обкрадывать живой сценарий.
  Оба источника принимаются, приоритет: env > --as > отказ.
- **В3 «читать `.git/config user.name` СКРЕСТЯ с env»** — если
  file-config есть — брать его, иначе env. ОТВЕРГНУТ: регрессия Н-56 —
  file-config `user.name` в репозитории ЗАПРЕЩЁН; чтение его снова
  открывает вознинг. Дверь НЕ должна знать про file-config.
- **В4 «сторож контекста спрашивает процесс omp»** — через PID-дерево
  `orch-loop`. ОТВЕРГНУТ: оркестратор может судить, но
  `as_u pgrep` от root не видит процессы harness-omp (omp запущен
  через `node --enable-source-maps …`); прямой опрос свежести
  журналов — дешевле и наблюдаемым.
- **В5 «опрашивать `SESS_GLOB` целиком»** — все `.jsonl` текущей
  сессии. ОТВЕРГНУТ: `SESS_GLOB` глобит файлы сессий, а не субъектов
  (один `.jsonl` = одна orch-сессия, не субагент). Субагентские
  журналы — в КАТАЛОГЕ сессии (`<TIMESTAMP>_<UUID>/<Имя>.jsonl`).
- **В6 «после таймаута 30 мин всё равно рестарт + имена»** — молча
  довести до логического конца. ВЫБРАН: 30 минут — реалистичный
  потолок для завершения субагента (живые спавны редко превышают);
  после потолка — ПРИНУДИТЕЛЬНЫЙ маркер с отчётом, иначе окно
  «вечный сторож» обходит и сторож, и наблюдателя.
- **В7 «отчёт пишется в `/var/lib/orch-peak/ctx-$sess.killed`»** —
  state-файл. ОТВЕРГНУТ: state-файлы уходят в `/var/lib/orch-peak/`,
  root-only; harness-цикл не видит. HANDOFF — место, которое
  читает следующая сессия, а не `/var/lib`. ВЫБРАН: писать в
  отчёт `$REPORT` (тот же путь, что и `wait_saved` уже использует,
  `$UHOME/orch-peak-report.txt`); оркестратор читает его при подъёме.
- **В8 «polling через `date` без `sleep`»** — busy-wait. ОТВЕРГНУТ:
  busy-wait жжёт CPU и `wait_saved` уже использует `sleep $POLL`.

Переиспользованы конвенции: именованные отказы stderr + rc 1 (прецедент
двери 072, `gc_agent_branches.sh:273-275`); санитизация git-env
(прецедент `check_no_leak.sh:217-225`); тест-шов `ORCH_SESS_DIR`
(магический путь сессии для тестов двери); шов `OPS_SERVER_SBIN_DST`
(`ops/server/install.sh`); модуль `SESS_GLOB`/`cur_ctx`
(`orch-peak:23,78-83`) — расширяется новой функцией `live_subagents`
для опроса субагентских журналов; формат отчёта — тот же `printf` в
`$REPORT`, что использует `wait_saved:55-58` (согласованный канал).
Вторая конвенция не строится.

## Инварианты

1. **Identity — env / --as / отказ.** Дверь читает identity строго в
   порядке (первый непустой побеждает):
   (а1) `GIT_AUTHOR_NAME` из окружения;
   (а2) `GIT_COMMITTER_NAME` из окружения;
   (а3) значение флага `--as <имя>`, переданного дверям явным
        аргументом.
   Все три пусты (или содержит ошибку грамматики — пробелы,
   непечатные символы, пустая строка после `--as`) → именованный
   отказ rc 1 «identity двери не определена: ни env
   GIT_AUTHOR_NAME/GIT_COMMITTER_NAME, ни --as», маркер НЕ ставится.
   `.git/config user.name` НЕ читается и не требуется условием
   (в1) контракта 072. Допустимая форма `--as`: один позиционный
   аргумент после `--as`; `--as` без значения или с пустой строкой →
   отказ (тот же маркер); `--as --as` или `--as foo --as bar` →
   отказ «--as задан дважды». ПИННУТЫ: имя маркера «identity двери
   не определена» — дословно; канал — stderr; порядок приоритета —
   фиксированный.

2. **Identity ног (в1)/(в2) контракта 072 заменена.** Нога (в1)
   identity в контракте 072 использовала `git config user.name`;
   новая нога сравнивает АВТОРА последнего коммита HANDOFF.md с
   identity, полученной из (1). Нога (в2) — committer-дата
   HANDOFF-коммита > стартового следа сессии — без изменений.

3. **Живые субагенты — отказ, если журнал свежий.** Дверь
   перечисляет субагентские `.jsonl` в текущей сессии:
   путь сессии = `<...>/sessions/--home-harness-dev-harness--/<TS>_<UUID>`,
   где `<TS>_<UUID>` — basename САМОГО СВЕЖЕГО `<...>/sessions/--home-harness-dev-harness--/*.jsonl`
   по mtime (та же логика, что `cur_ctx` в `orch-peak:78-83`,
   ИЗВЛЕЧЁННАЯ в отдельную функцию `current_session_dir`). Свежесть =
   `mtime файла > now - 120s`. Клетки: каталог сессии не существует
   ИЛИ в нём нет `.jsonl` файлов → проход (нет живых субагентов).
   В каталоге есть хотя бы один `.jsonl` И его mtime > now-120s →
   именованный отказ rc 1 «живые субагенты: <имена>» (перечисление
   имён ВСЕХ свежих журналов через запятую, в алфавитном порядке
   basename без `.jsonl`); маркер НЕ ставится. Все `.jsonl` > 2
   минуты → проход. Тест-шов: `ORCH_SESS_DIR` переопределяет
   каталог сессии (умолчание — вычисленное); при переопределении
   шва дверь не читает умолчательный путь.

4. **Тест-шовы.** Помимо существующих `ORCH_RESTART_MARKER`,
   `ORCH_SESSION_START` контракта 072 — добавлены:
   `ORCH_SESS_DIR` (каталог текущей сессии для ноги (3));
   `--as <имя>` (имя identity для ноги (1));
   в `ops/server/root/orch-peak` — `ORCH_HARD_GRACE` (таймаут
   жёсткого режима, умолчание 1800 сек), `ORCH_HARD_POLL` (интервал
   опроса, умолчание 60 сек). При переопределении шва дверь НЕ
   читает и НЕ пишет умолчательный путь того же шва.

5. **fail-closed rc 2 сохранён.** Существующий fail-closed rc 2
   («NOT_IMPLEMENTED: …») — нет git / не репозиторий / нет
   origin/main / нет HANDOFF.md / стартовый след нечитаем —
   остаётся; identity-нога (1) НЕ выдаёт rc 2 — её отказ всегда
   rc 1 с маркером «identity двери не определена». `git config
   user.name` НЕ входит в rc 2 (НЕ «нечем проверить»: identity
   может прийти из env/--as, file-config не единственный путь).

6. **Коды возврата двери** (шапка «Коды возврата:» дополнена):
   0 — маркер поставлен (stdout несёт «ПЕРЕЗАПУСК»);
   1 — именованный отказ (причина в stderr, маркер не ставится);
   2 — нечем проверить (NOT_IMPLEMENTED: …).

7. **Сторож контекста: мягкий режим (CTX_SOFT) — дополненная
   фраза.** В `ops/server/root/orch-peak`, ветка `elif [ "$ctx"
   -ge "$CTX_SOFT" ]` (после существующего текста `say …`),
   добавлена ЯВНАЯ фраза (дословно, перед отправкой в панель):
   «новых спавнов не начинай, дождись завершения текущих
   субагентов, затем перезапуск дверью». Фраза добавляется ОДНИМ
   предложением в существующее сообщение; существующий текст не
   правится и не переписывается — КОНКАТЕНАЦИЯ. Сверка
   установленного == репо (sha256) — обязательна ПОСЛЕ правки
   (`bash ops/server/install.sh verify` с швом `OPS_SERVER_SBIN_DST`
   на тестовую песочницу); rc 0 + «сверка: 9/9» — установленное
   == репо; rc ≠ 0 — отказ с именем расходящегося файла
   (прецедент `ops/server/install.sh verify`).

8. **Сторож контекста: жёсткий режим (CTX_HARD) — ожидание с
   таймаутом.** В `ops/server/root/orch-peak`, ветка `if [ "$ctx"
   -ge "$CTX_HARD" ]`, ДО вызова `wait_saved` (который судит
   коммиты/пуши) добавлен опрос живых субагентов по образцу
   инварианта 3 (mtime > now-120s): пока хотя бы один субагентский
   `.jsonl` в текущей сессии свежий — сторож опрашивает каждые
   `ORCH_HARD_POLL` секунд (умолчание 60), до `ORCH_HARD_GRACE`
   секунд (умолчание 1800 = 30 минут) с момента входа в жёсткий
   режим. Клетки:
   (г1) на входе в жёсткий режим свежих субагентов НЕТ → маркер
        ставится сразу (как обычный режим — поведение инварианта
        жёсткого режима СОХРАНЕНО для случая «уже вышли»);
   (г2) на входе есть свежие, опрос доходит до таймаута — все
        состарились ДО таймаута → маркер ставится (как г1);
   (г3) на входе есть свежие, по истечении `ORCH_HARD_GRACE` всё
        ещё есть свежие → маркер ставится ПРИНУДИТЕЛЬНО + в отчёт
        `$REPORT` пишется строка «живые субагенты погибнут:
        <имена через запятую>» (тот же формат перечисления, что в
        инварианте 3); отчёт создаётся атомарно (tmp+mv), если
        субагентов состарилось не полностью — содержимое ДОПИСЫВАЕТСЯ
        к существующему отчёту, а не затирается (если субагентов
        состарилось полностью — отчёт НЕ создаётся);
   (г4) опрос внутри цикла НЕ блокирует таймер `orch-ctx.timer`
        (цикл — `while : ; do … sleep $ORCH_HARD_POLL … done`,
        выход по таймауту или по очистке свежести);
   (г5) имена «погибнут» — это список свежих на момент истечения
        таймаута, а не на момент входа (могли появиться новые).

10. **Отчёт `$REPORT` для принудительного маркера.** Канал — тот же,
    что у `wait_saved:55-58`: `printf '%s … — НЕ сохранено/не
    отправлено к сроку:\n%s\n' "$why" … | as_u tee "$REPORT"`. Для
    предмета (г) формат «живые субагенты погибнут: <имена>» —

## Остаточный риск (назван прямо)

- Перезапуск через 30 минут принудительной смерти — `ORCH_HARD_GRACE`
  реалистичен, но для СВЕРХДЛИННЫХ субагентов (скажем, спавн-критик
  с большой пробой) 30 минут может быть мало; принудительная смерть
  ловится отчётом с именами; оркестратор следующей сессии читает
  отчёт `$REPORT` и помечает субагента как потерянного (прецедент
  ревьюер 071v2 погиб при рестарте 12:48 2026-10-03).
- `ORCH_SESS_DIR` определяется как КАТАЛОГ самой свежей orch-сессии;
  если оркестратор запустил дверь в момент между двумя сессиями
  (сразу после `orch-loop` поднял новую сессию, а старая ещё не
  gc), тест может смотреть на СТАРУЮ сессию; окно секунды названо,
  реальный путь фиксируется `SESS_GLOB` и `cur_ctx` (та же логика).
- Identity из env читается напрямую из shell-окружения процесса
  двери; если orch-loop сбрасывает env (`env -i`), identity
  берётся из `--as` (приоритет env > --as, но env пуст →
  отказ); оркестратор ОБЯЗАН передать identity через `--as` или
  env — это дисциплина `roles/orchestrator.md`, не предмет
  контракта.
- Файл `ops/server/root/orch-peak` доступен только под root;
  структурные тесты предмета (в)/(г) — content-only. Полный прогон
  `orch-peak ctx` (отправка сообщения в tmux, маркер через

  тестирования harness; live-проверка — на станции 148.251.131.204
