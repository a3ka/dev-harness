## Frontier (по коду)

- **В1 «env полностью, без флага»** — опираться только на
  `GIT_AUTHOR_NAME`/`GIT_COMMITTER_NAME`. ОТВЕРГНУТ: env-переменные
  bash не наследуются автоматически в каждый под-процесс одинаково;
  оркестратор может запустить дверь через `env -i`, и env не дойдёт;
  явный флаг --as надёжнее и читаем в прогоне (видно в логах кто
  вызвал), env — невидим.
- **В2 «только --as, без env»** — обязательный аргумент, иначе отказ.
  ОТВЕРГНУТ: env-источник полезен для оркестратора (выставляется в
  панели tmux перед вызовом); лишать его — обкрадывать живой сценарий.
  Оба источника принимаются, приоритет: env > --as > отказ.
- **В3 «читать `.git/config user.name` СКРЕСТЯ с env»** — если
  file-config есть — брать его, иначе env. ОТВЕРГНУТ: регрессия Н-56 —
  file-config `user.name` в репозитории ЗАПРЕЩЁН; чтение его снова
  открывает вознинг. Дверь НЕ должна знать про file-config.
- **В4 «сторож контекста спрашивает процесс omp»** — через PID-дерево
  `orch-loop`. ОТВЕРГНУТ: оркестратор может судить, но
  `as_u pgrep` от root не видит процессы harness-omp (omp запущен
  через `node --enable-source-maps …`); прямой опрос свежести
  журналов — дешевле и наблюдаемым.
- **В5 «опрашивать `SESS_GLOB` целиком»** — все `.jsonl` текущей
  сессии. ОТВЕРГНУТ: `SESS_GLOB` глобит файлы сессий, а не субъектов
  (один `.jsonl` = одна orch-сессия, не субагент). Субагентские
  журналы — в КАТАЛОГЕ сессии (`<TIMESTAMP>_<UUID>/<Имя>.jsonl`).
- **В6 «после таймаута 30 мин всё равно рестарт + имена»** — молча
  довести до логического конца. ВЫБРАН: 30 минут — реалистичный
  потолок для завершения субагента (живые спавны редко превышают);
  после потолка — ПРИНУДИТЕЛЬНЫЙ маркер с отчётом, иначе окно
  «вечный сторож» обходит и сторож, и наблюдателя.
- **В7 «отчёт пишется в `/var/lib/orch-peak/ctx-$sess.killed`»** —
  state-файл. ОТВЕРГНУТ: state-файлы уходят в `/var/lib/orch-peak/`,
  root-only; harness-цикл не видит. HANDOFF — место, которое
  читает следующая сессия, а не `/var/lib`. ВЫБРАН: писать в
  отчёт `$REPORT` (тот же путь, что и `wait_saved` уже использует,
  `$UHOME/orch-peak-report.txt`); оркестратор читает его при подъёме.
- **В8 «polling через `date` без `sleep`»** — busy-wait. ОТВЕРГНУТ:
  busy-wait жжёт CPU и `wait_saved` уже использует `sleep $POLL`.
- **В9 «нога (д') проверяет `git config user.name`»** — `git config
  --get user.name` без `--local`, через каскад env/config. ОТВЕРГНУТ:
  это эффективный идентититет git-ПРОЦЕССА, не состояние ФАЙЛА
  `.git/config`; env/--c перекроют file-config и нога (д') пропустит
  загрязнение. Нога (д') должна читать ФАЙЛ `.git/config` НАПРЯМУЮ,
  независимо от того, что в env.
- **В10 «нога (д') в `scripts/check_no_leak.sh`»** — общий детектор
  024. ОТВЕРГНУТ: `check_no_leak.sh` — runtime-детектор в ноге 072
  (г), судит РАЗОВЫЙ прогон; pre-commit-барьер `scripts/check_staged.sh`
  — точка на КАЖДЫЙ коммит, и семантика другая (отказ rc 1 ДО
  коммита). Слияние двух детекторов в одну ногу — нарушение правила
  «один предмет — один механизм» (прецедент 047 §различный шов).

- **В11 «поведенческий прогон orch-peak под sudo в батарее»** —
  полный root-прогон с живой tmux-панелью. ОТВЕРГНУТ: батарея

  живая панель — побочный эффект станции. ВЫБРАН: тест-шов

Переиспользованы конвенции: именованные отказы stderr + rc 1 (прецедент

## Инварианты

1. **Identity — env / --as / отказ.** Дверь читает identity строго в
   порядке (первый непустой побеждает):
   (а1) `GIT_AUTHOR_NAME` из окружения;
   (а2) `GIT_COMMITTER_NAME` из окружения;
   (а3) значение флага `--as <имя>`, переданного дверям явным
        аргументом.
   Все три пусты (или содержит ошибку грамматики — пробелы,
   непечатные символы, пустая строка после `--as`) → именованный
   отказ rc 1 «identity двери не определена: ни env
   GIT_AUTHOR_NAME/GIT_COMMITTER_NAME, ни --as», маркер НЕ ставится.

    git-config репозитория `$ROOT` (НЕ эффективный идентититет
    git-процесса) ДО продолжения по автору/зонам/staged. Правила:
    (д'0) Разрешение общего git-dir: `COMMON_DIR="$(git -C "$ROOT"
        rev-parse --git-common-dir)"`; относительный результат
        отсчитывается от `$ROOT` (в главном чекауте git-common-dir
        == `.git` — каталог; в linked worktree — абсолютный путь
        к общему git-dir; живая проба критика к1). Общий файл
        конфигурации — `"$COMMON_DIR/config"`: в обычном
        репозитории это `$ROOT/.git/config`; в linked worktree
        `$ROOT/.git` — ФАЙЛ-ссылка `gitdir:`, не каталог, и прямое
        чтение `$ROOT/.git/config` НЕ видит загрязнение общего

## Модель угроз

ЗАЩИЩАЕТ:
- отсутствие file-config identity — дверь берёт имя из env или флага --as и работает, отказ «identity двери не определена» только при пустых обоих источниках (регрессия NOT_IMPLEMENTED снята);
- env-данную identity без file-config — дверь работает без записи user.name в .git/config, вознинг файла не нужен (Н-56 соблюдён);
- identity из флага --as <имя> — дверь работает, имя видно в логах вызова;
- чужой, пустой или двойной --as (несколько значений, пустая строка) — именованный отказ rc 1, маркер не ставится;
- перезапуск при живых субагентах (свежесть журнала < 2 мин) — дверь отказывает «живые субагенты: <имена>», маркер не ставится (Н-185 бугфикс);
- перезапуск при сверхдолгих субагентах (≥ ORCH_HARD_GRACE) — принудительный маркер только с отчётом «живые субагенты погибнут: <имена>», не молчаливая смерть;
- загрязнение общего git-config worktree-через-worktree (user.name/user.email записаны в общий файл ИЗ ЛЮБОГО worktree, включая linked worktree) — pre-commit отказ rc 1 «identity в общем .git/config запрещена», коммит не создан (предмет (д'));
- коммит с -c/env identity при ЧИСТОМ общем config — проход: нога (д') судит состояние файла, а не эффективную identity процесса;
- загрязнённый общий config при ВЫСТАВЛЕННОЙ env identity — отказ (д') всё равно происходит: нога читает файл напрямую, env не перекрывает состояние файла (сценарий «выставил env, забыл почистить file-config» ловится);
- подмену репозитория окружением — санитизация git-env (инв. 11).

НЕ ЗАЩИЩАЕТ:
- подделку самих значений GIT_AUTHOR_NAME/GIT_COMMITTER_NAME — источник под контролем оркестратора и его панели tmux, механической проверки подлинности нет;
- подмену --as мимо двери (прямой вызов git с чужим именем, минуя дверь) — прозой роли и судьями, не механизмом;
- подмену стартового следа сессии руками — тот же класс, что ручной touch маркера, за границами предмета;
- детектор утечки и собственно гейт 072 — фиксируются замороженным семейством fixtures/perezapusk_sessii/, не этим контрактом;
- запись user.* в ПОДМНОЖЕСТВА config, невидимые прямому чтению общего файла (includeIf-каскады с абсолютным путём) — нога (д') читает общий файл напрямую, класс назван в §Остаточный риск;
- инжекцию новых субагентов за время опроса — снапшот свежести фиксируется на момент решения, окно нового спавна названо;
- гонку «сторож поставил маркер → orch-loop ещё не поднял новую сессию → субагент успел закоммитить» — порядок оркестратора и обвязки, не двери;
- живой умолчательный путь SESS_GLOB для батареи — тест-швы ORCH_SESS_DIR/ORCH_PEAK_TEST отвязывают батарею от живых путей станции;
- ORCH_HARD_GRACE = 0 (нулевой таймаут) — реализация принимает любое положительное конечное число, ноль остаётся выбором реализатора.

## Остаточный риск (назван прямо)

- Перезапуск через 30 минут принудительной смерти — `ORCH_HARD_GRACE`
  реалистичен, но для СВЕРХДЛИННЫХ субагентов (скажем, спавн-критик
  с большой пробой) 30 минут может быть мало; принудительная смерть
  ловится отчётом с именами; оркестратор следующей сессии читает
  отчёт `$REPORT` и помечает субагента как потерянного (прецедент
  ревьюер 071v2 погиб при рестарте 12:48 2026-10-03).
- Нога (д') ловит ТОЛЬКО прямое загрязнение общего git-config
  (`user.name`/`user.email` записаны в общий файл, разрешённый
  через `git rev-parse --git-common-dir`). Если оркестратор/
  субагент использует `--local`-семантику через другой механизм
  (например, `git -c includeIf.gitdir:...path=... config` с
  абсолютным путём к общему config), нога (д') пропустит (читает
  общий файл НАПРЯМУЮ, не includeIf-каскад); класс вне предмета —
  норма Н-85 (env-санитизация) и `roles/orchestrator.md`
  (дисциплина) остаются механизмом защиты от этого класса.
- `ORCH_SESS_DIR` определяется как КАТАЛОГ самой свежей orch-сессии;
  если оркестратор запустил дверь в момент между двумя сессиями
  (сразу после `orch-loop` поднял новую сессию, а старая ещё не
  gc), тест может смотреть на СТАРУЮ сессию; окно секунды названо,
  реальный путь фиксируется `SESS_GLOB` и `cur_ctx` (та же логика).
- Identity из env читается напрямую из shell-окружения процесса
  двери; если orch-loop сбрасывает env (`env -i`), identity
  берётся из `--as` (приоритет env > --as, но env пуст →
  отказ); оркестратор ОБЯЗАН передать identity через `--as` или
  env — это дисциплина `roles/orchestrator.md`, не предмет
  контракта.
- Файл `ops/server/root/orch-peak` доступен только под root.
  Поведенческие клетки в3/г6-г8 идут через тест-шов
  `ORCH_PEAK_TEST`: он ПОДМЕНЯЕТ `as_u`/`say`/`pane`/`omp_pids`/
  `kill_session` (инв. 4), поэтому батареёй НЕ наблюдаются:
  доставка сообщения в реальную tmux-панель, исполнение
  `runuser`, реальные сигналы kill, живой systemd-таймер
  `orch-ctx.timer`. Полный прогон `orch-peak ctx` под root с
  живой панелью остаётся за пределами автоматизированного
  тестирования harness; live-проверка — на станции 148.251.131.204
  через ручной `sudo bash ops/server/install.sh root && systemctl
  daemon-reload && systemctl restart orch-ctx.timer`. Тайминги
  клеток сжаты (GRACE 1-8 сек против продукционных 1800/900):
  батарея доказывает ПОРЯДОК решения (ждать → маркер → отчёт),
  не продукционные интервалы.
- Реализационная пачка добавляет `scripts/lib_session.sh` —
  общий источник `current_session_dir`/`live_subagents_in`;
  без этой библиотеки дверь и сторож разойдутся молча на новом
  `SESS_GLOB`. Bootstrap-защита: `if [ -f … ]; then . … ; fi` —
  прецедент `freeze_contract.sh` и `mint_line.sh`.
