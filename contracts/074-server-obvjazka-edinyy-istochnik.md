## Инварианты

1. **Снапшот побайтно.** Девять файлов таблицы выше лежат в дереве по
   указанным путям и равны пинам sha256 (клетка к5; на станции — живая
   сверка к5b). Источник — станция, не память: реализационная пачка
   вправе переснять файлы со станции; расхождение с пинами = красное
   (дрейф станции — слово владельца, не молчаливая правка пинов).
2. **CLI установщика.** `ops/server/install.sh` принимает РОВНО одну
   подкоманду: `user` | `root` | `verify`; прочее/пусто — rc 2
   `NOT_IMPLEMENTED` со строкой использования.
3. **user-часть.** Копирует ops/server/user/orch-loop в
   `${OPS_SERVER_BIN_DST:-$HOME/.local/bin}/orch-loop`, режим 755,
   перезачитывает sha256 адресата против источника; успех — rc 0 со
   строкой `установлено: <путь>`; расхождение/отказ записи — rc 1,
   именованный отказ с именем файла.
4. **root-часть отдельно + euid-гард.** Подкоманда `root` под euid ≠ 0
   отказывает rc 1 с дословной фразой `root-часть требует euid 0` и НЕ
   пишет ничего ни по каким адресатам. Под euid 0: orch-peak →
   `${OPS_SERVER_SBIN_DST:-/usr/local/sbin}/orch-peak` (755, root:root),
   7 юнитов → `${OPS_SERVER_ETC_DST:-/etc/systemd/system}/` (644,
   root:root), перезачитывание sha256 каждого; rc 0 / rc 1 с именем файла.
   Владелец root:root — свойство живой root-установки (слова владельца:
   «harness не должен иметь права его менять»); под harness не наблюдаемо —
   судится гардом (к4) и живой сверкой станции (к5b).
5. **verify.** Только читает: для каждого из 9 файлов сравнивает адресата
   (швы respected) с источником репо; все равны — rc 0, stdout
   `сверка: 9/9`; любое расхождение/отсутствие — rc 1, stderr на каждый
   файл `ОТКАЗ: расхождение <путь>` (имя файла обязательно). Клетка к3
   батареи параметризована по всем девяти адресатам: по одной негативной
   пробе на каждый файл — user-файл, root-файл, 7 юнитов (вердикт к1:
   сверка одного выбранного файла не проходит приёмку).
6. **Тест-швы.** `OPS_SERVER_SRC` (источник, умолчание — каталог скрипта),

## Модель угроз

ЗАЩИЩАЕТ:
- потерю обвязки при переустановке станции — 9 файлов в репо, пин sha256
  (клетки к5/к5b), переустановка = `install.sh` из репо;
- дрейф «станция ушла, репо отстало» — живая сверка к5b на станции и
  `verify` на любом клоне: расхождение = rc 1 с именем файла (клетка к3,
  параметризована по всем девяти адресатам — сверка одного выбранного
  файла не проходит приёмку, вердикт к1);
- слепую установку (копия без проверки) — перезачитывание sha256 после
  копирования — как в verify, так и в самой команде user: cp-шина батареи
  портит запись по пути, отказ обязана давать команда установки (клетка
  к1b; Н-39: вход — код батареи);
- запись harness'ом в root-пути — euid-гард подкоманды root: отказ rc 1
  ДО любых обращений к адресатам, наблюдаем на швовых адресатах (клетка к4);
- тихую порчу байтов установки — оракул в памяти батареи (пины сняты до
  вызова субъекта, правило 8); наблюдаем на входе user-конвергенции (к1);
- незнание новой сессии об обвязке — указатели HANDOFF/роли (к7) и
  инвентарь README (к6): чек-строки структурные, grep -F; отрицательный
  мир указателей строится СРЕЗАНИЕМ строк из текущих документов —
  различимость не зависит от приземления указателей (режим LANDSIM,
  вердикт к1);
- рост роли сверх потолка — клетка к7 судит wc -c ≤ 51200.

НЕ ЗАЩИЩАЕТ:
- root-часть happy path под euid 0 (chown root:root, /usr/local/sbin) —
  под harness не наблюдаем; судится гардом к4 + живой сверкой к5b +
  глазом владельца на живой установке (остаточный риск ниже);
- содержание README сверх чек-строк (полнота описаний) — грамматика 027
  судит структурные строки, не прозу; ловец — ревьюер;
- сам станционный orch-peak/таймеры как механизмы (исполняемость, расписание)
  — предмет переносит их побайтно, не проектирует; ловец — владелец;
- дрейф станции МЕЖДУ замером пинов и реализацией — по построению красный
  (к5/к5b): решение за владельцем (пересъём = новая пачка пинов).

## Красные предъявления

Носитель — fixtures/ops_server/red_server_obvjazka_074.sh (прямое
предъявление, семья probe-only 034, вне case_*-глоба раннера), раннер —
fixtures/_krasnye_074.sh. Состав обманной части и привязки к входам живут
ТОЛЬКО в коде батареи (Н-39); контракт несёт инварианты и rc-команды.
Счёт предъявлений — прогоном батареи (стаб-пак + диффпроба + честная часть).

Красное ДО реализации — г0, fail-fast по отсутствию субъекта: на дереве
без ops/server/install.sh раннер даёт rc 1 c stderr «ОТКАЗ: предмет
отсутствует — в дереве нет ops/server/install.sh», при этом обманная часть
исполняется и полностью зелёна (стаб-пак 7/7 + диффпроба 7/7) —
различимость батареи не зависит от честного кода. ДО-мера пачки: на
1293e0c `grep -rc ops/server` по дереву = 0.

Зелёное симуляцией (А-318): `FIXSIM=1` — батарея строит в скратче
throwaway-симуляцию честного install.sh (грамматика инвариантов 2-7) и
обязана дать rc 0 целиком: честная часть 7/7 + стаб-пак 7/7 + диффпроба
7/7. Симуляция умирает вместе со скратчем, в дереве её нет.

Зелёное на приземлённом (требование вердикта к1, блокирующая 1):
`LANDSIM=1` — батарея строит скратч-дерево, где строки-указатели
инвариантов 9-10 УЖЕ стоят в роли и HANDOFF (идемпотентное применение к
текущим документам), субъект — та же честная симуляция, и обязана дать
rc 0 целиком: отрицательный мир s6 лишается указателей срезанием из
приземлённых документов, поэтому различимость к7/s6 не зависит от
состояния честного дерева. После реального приземления то же
доказательство даёт любой обычный прогон.

Демаркация контрпримеров: конформные входы — миры, где 9 адресатов
побайтно равны источникам репо (зелёный мир), миры с РОВНО ОДНИМ
искажённым адресатом — каждый из девяти по очереди (мир расхождения),
запуск root под euid ≠ 0 со швовыми
адресатами, дерево с/без субъекта и документов. Валидный контрпример =
инвариантность к путям скратча ∧ расхождение честного предмета и обманной
заглушки на конформном входе. Пины фиксированы (сняты со станции), значения
не рандомны: предмет — побайтовая идентичность, а не инвариантность к
значениям.
