# Контракт 215 — отказ провайдера ПО СОДЕРЖАНИЮ (cyber_policy и подобные) переводит агента на запасную модель тира (`.omp/extensions/fallback-route.ts` + батарея 129)

СТАТУС: ЧЕРНОВИК-ЗАТРАВКА (bootstrap: `make_task --role architect` требует существующий `contracts/215-*.md`; текст контракта пишет architect по заданию станции — затравка не является ни спекой, ни критерием; заменяется целиком).

## Боль
Слово владельца 23.11: «я хочу чтобы настройки у нас были созданы так, чтобы мы могли переключать модели агентам на лету или они сами автоматом переключались на резервные модели, как указано у нас в конфиг файле»; «Модели (2): станции — кодовый контракт: отказ провайдера по содержанию (cyber_policy и подобные) переводит агента на запасную модель тира; батарея 129 расширяется.»
Измерено 23.11 (консультант, бэк Critic190K08, omp 18.18.8, лог `omp.2026-11-23…` pid 1498324): три раза «agent turn ended with provider error … Codex error event: This content was flagged for possible cybersecurity risk» — ни retry, ни `model_change`, хотя `session_init` содержит `retryFallback.chain=[zai/glm-5.3]`; `errorId` 53248, `stopDetails` нет.
Разбор по коду (scout, 23.11; `inbox-STANCIJA-RAZBOR-FALLBACK-1400.txt`): `.omp/extensions/fallback-route.ts` переключает ТОЛЬКО при исчерпании провайдера — ход `stopReason=error`, `errorStatus=429` и `retry-after-ms>300000` (`:41–42`, `:93–101`); подмена на спавне субагента (`before_subagent_spawn`, `:105–129`) при `autoFallback===true` тира и провайдере цели ≠ провайдера примария; 400/5xx/короткий 429/ОТКАЗ ПО СОДЕРЖАНИЮ — не переключает по контракту 129 (инварианты 1 и 4; клетки c3/c4 батареи 129). Штатные `retry.fallbackChains` omp (`.omp/config.yml:124–130`) на отказ классификатора по содержанию в этом наблюдении не сработали; в репозитории есть обратные случаи (omp ушёл на фолбек на «Refusal (cyber)»: NABLIUDENIA_ARCHITECT.md:8763–8766, HANDOFF.md:1671,1699–1700) — причина расхождения по коду не определяется (нужен разбор логов `~/.omp/profiles/dev/logs/omp.<date>.<pid>.log`).

## Решение
Кодовый контракт: (а) расширение ловит ход агента, завершившийся провайдерским отказом ПО СОДЕРЖАНИЮ (маркеры: текст ошибки «flagged for possible cybersecurity risk», `cyber_policy`, content-filter коды провайдеров — точный закрытый список выписывает architect по замеру логов), и подменяет модель СУБАГЕНТА на запасную модель его тира (`autoFallback:true`, провайдер цели ≠ провайдера отказавшего) — на спавне и на повторе; (б) решение: считается ли такой отказ «суждением о содержании» (по omp — прибивка к фолбэку без cooldown) — architect фиксирует в контракте и стенде; (в) инварианты 129 сохраняются для прочих ошибок (400/5xx/короткий 429 не переключают; «подмена на любой ошибке» запрещена — Frontier(4)); (г) батарея 129 расширяется клетками: отказ по содержанию → запасная; повторный отказ запасной → стоп с именованной ошибкой; примарий без отказа не подменяется; чужой отказ другого тира не влияет; обманные стабы к новым ветвям привязывает architect по коду (Н-39); (д) ПРОВОДКА: при правке `fallback-route.ts`/`agent_models.json` батарея гоняется на станции с реальным omp до land (норма 129).
