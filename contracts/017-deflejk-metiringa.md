## Предмет

Пять срезов; 1 ⊥ 2 ⊥ 5, срез 3 опирается на 1–2 (событие уже существует), срез 4 — пробы
архитектора, красные ДО раздачи (Н-39: привязка стабов к входам — по коду проб).

**Срез 1 — upstream-стаб на событии (Q1).** `stub_upstream`: listen(0) + запись
фактического порта в файл В listen-callback (событие, симметрично репорту прокси
контракта 007); из фикстурного пути убираются free_port (сейчас scripts/check_metering.sh:103)
и ss-поллинг готовности (:151-153). Ожидание готовности — СОБЫТИЕ: файл-порт от
listen-callback при живом процессе (kill -0), затем healthz-попытка. Потолок ожидания —
живость процесса: тикать до смерти/бюджета, не ранний break (А-18); вариант Б (широкое
окно времени) допустим ТОЛЬКО как потолок бюджета тиков внутри А, не как самостоятельный
механизм (Q1). Гибель до listen — именованный отказ с причиной; живой процесс без записи
порта — именованный отказ «не репортит порт»: различимость «медленный» vs «мёртвый» vs
«не репортит» — предмет класса, а не угадывание по таймауту.

**Срез 2 — ветвь (и) на :0 (Q1).** Свой прокси ветви (и) — proxy_port=0 вместо free_port
(:913); после proxy_up порт перечитывается из конфига (proxy_up уже переписывает cfg.port
на фактический) — запросы ветви идут на фактический порт.

**Срез 3 — proxy_up: событие → healthz (Q1).** Ждать файл-порт (процесс жив по kill -0),
потом мерить healthz; окно времени умирает как класс — медленный старт node перестаёт
выглядеть отказом. Убрать мёртвый portup в gen_config (:295 — main немедленно переписывает
upstream на порт стаба); retry-ветка EADDRINUSE с free_port (:235) умирает вместе с
классом: на bind :0 гонки нет по построению. free_port остаётся только вне фикстурного
пути (cold-start и прочие режимы).

**Срез 4 — пробный слой port0 у архитектора (Q1).** Живёт в
`fixtures/verify_antiplacebo/probe_port0.sh`: туда же перенесены зелёные с контракта 007
p0.gen/p0.up/p0.conc/p0.src; рядом три новые пробы. Привязка ко входам — по коду пробы,
НЕ проза здесь (Н-39). Инварианты проб: p0.stub — upstream-стаб назначает порт ОС
(listen 0), репортит его файлом-событием из listen-callback, запись порта — только
слушатель, готовность не зависит от скан-инструментов; p0.i — ветвь (и) поднимает свой
прокси bind :0, фактический порт — из события, ловец — рантайм (исполнение ветви в
контролируемом окружении и сверка факта), не словарная проверка исходника; p0.noreport —
отказ «не репортит порт» именованный (литерал пинует проба — единый источник),
различим с таймаутом.

**Срез 5 — А-19 в раннере + честный комментарий (Q3, Q5).** release()
(scripts/verify_antiplacebo.sh:441-452) хранит $RUN при fails>0 (~3 строки): сообщение
«прогон оставлен в …» становится правдой, die-причина барьера сохраняется в
invocations.log; стартовая чистка раннера по-прежнему убирает мёртвые run-*; при rc=0
RUN убирается как раньше (течь каталогов не заводим — райдер (ii) контракта 012).
Комментарий scripts/check_metering.sh:97-100 («анти-плацебо крутит их параллельно
десятки» — ложь о последовательном раннере) переписать: дезинформация стоит на месте
будущей работы над флейком. Остальное А-33 — вне предмета (Q3).
