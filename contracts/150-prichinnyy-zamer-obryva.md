## Предмет и инварианты

**Предмет (один наблюдаемый результат):** в каждом красном экранном job Complior-mob, упавшем по канонической сигнатуре обрыва adb (141), CI публикует артефакт причинного замера — `sampler.tsv` таймлайн (PID/состояние эмулятора из `/proc`, `adb devices` состояние, boot_id/PID adbd гостя из живых проб, cgroup раннера memory.current/memory.events(high,max,oom)/cpu.stat(nr_throttled,throttled_usec)/PSI(cpu,memory avg10), host MemAvailable), системный снимок (UTC, run/attempt/job/runner, nproc/uptime/free, netns inode, PID adb-server), хвост журнала эмулятора (tail 200, ≤2 файла), ограниченный logcat (`-t 200` либо честный маркер недоступности), найденные сигнатуры file:line (≤20), itog, — снятый ДО остановки/повтора (сэмплер живёт весь экраной шаг), redacted, ограниченного объёма. Предмет НИЧЕГО не лечит: перезапуск/повтор/изоляция станции — другие предметы (995 v2 не трогать).

Инварианты:

- **И-1 (итог job неприкосновенен):** шаги обёртки никогда не меняют вывод экраного шага: старт подавляет собственные отказы, сбор всегда rc 0, артефакт `if: always()` с `if-no-files-found: ignore`; собственные отказы замера — именованные маркеры в логе (`ZAMER_*`), ловцы — батарея и пункт ревьюеру; `continue-on-error` запрещён у всех шагов работника.
- **И-2 (данные до остановки):** сэмплер стартует ДО экраного шага, частота не чаще 1 сэмпла в секунду (≤1 Гц) локальных чтений; живость PID — из `/proc`; недоступное на момент сбора (logcat/boot_id при offline) — маркер НЕДОСТУПНО, не пустота (Astra §10: «фиксировать, что logcat оборвался»).
- **И-3 (гейт публикации):** артефакт собирается ТОЛЬКО при сигнатуре в output_namespace РАБОТНИКА, взятом из карты (после wipe повторной попытки): зелёный, восстановленный-зелёный и продуктовый красный без обрыва не публикуют и не падают; grep шире ns — обманная широта (класс 141/Astra §9).
- **И-4 (лёгкость):** ≤1 сэмпл/с; проба гостя ≤1 в 15 с (timeout 3 с, только при state=device) — никаких bugreport/dumpsys/полных дампов и десятков параллельных adb-подключений; объём: сэмплер ≤2700 строк и ≤512 KiB, каждый файл артефакта ≤512 KiB, артефакт ≤2 MiB, logcat только `-t`.
- **И-5 (редакция):** `ghp_…`/`github_pat_…`/`AKIA…`/PRIVATE KEY/`Bearer …` вырезаются из ВСЕХ текстов артефакта; env не публикуется (в снимок идут только метки GITHUB_RUN_ID/GITHUB_RUN_ATTEMPT/GITHUB_JOB/RUNNER_NAME).
- **И-6 (канон байт-в-байт):** `mobile/scripts/zamer_obryva.sh` продукта == пин `source.json:.piny` батареи (модель `model/mobile/scripts/zamer_obryva.sh`); обёртка — три именованных шага с согласованными env (z02).
- **И-7 (чужое не трогает):** тела/пины/порядок чужих шагов не меняются; карта/селектор/агрегат/лекало — без правок; S (995) и его повтор — вне предмета.

## Модель угроз

ЗАЩИЩАЕТ (по свойству):

- публикацию причинного замера на красном с сигнатурой обрыва и ТОЛЬКО на нём: зелёный, восстановленный-зелёный и продуктовый красный без обрыва артефакт не получают и итога не меняют;
- данные момента обрыва, снятые до остановки/повтора эмулятора (PID-таймлайн живого процесса, cgroup/PSI-счётчики, boot_id/PID adbd живыми пробами, смена adb-server);
- границы объёма артефакта и редакцию секретов во всех его текстах;
- лёгкость замера (частота, отсутствие тяжёлых команд и лишних adb-подключений — сам не нагружает раннер);
- неизменность итога job обёрткой (отсутствие маскировки красного: запрет continue-on-error, гейт не шире ns работника).

НЕ ЗАЩИЩАЕТ (остаточные риски, имя ловца или владельца решения):

- код возврата qemu (exit status) недоступен вне родительской оболочки экраного шага: таймлайн фиксирует факт и момент смерти PID, не код; закрытие потребует правки экраных тел/лекала v+1 (владельцы 143/117/135/118/995) — не этот предмет;
- RECOVERED-обрыв (итог зелёный после восстановления) не публикуется: гейт судит финальный ns — по слову владельца «зелёный job замер не публикует»; расширение на восстановленные — отдельный предмет;
- станционные причины (kernel OOM/KVM/segfault за интервал) — чтение владельцем станции при доступе (Astra §10), батарея их не моделирует; отсутствие прав честно помечается;
- сэмплер умирает вместе с job при SIGKILL/аварии хоста — последняя строка таймлайна честно обрывается;
- поведение живого GitHub Actions (upload-artifact v7, реальный adb-транспорт) батарея моделирует подложками в замкнутом мире — живая проводка доказывается приёмками 7/8;
