## Предмет и инварианты

**Предмет (один наблюдаемый результат):** в каждом красном экранном job Complior-mob, упавшем по канонической сигнатуре обрыва adb (141), CI публикует артефакт причинного замера — `sampler.tsv` таймлайн (PID/состояние эмулятора из `/proc`, `adb devices` состояние, boot_id/PID adbd гостя из живых проб, cgroup раннера memory.current/memory.events(high,max,oom)/cpu.stat(nr_throttled,throttled_usec)/PSI(cpu,memory avg10), host MemAvailable), системный снимок (UTC, run/attempt/job/runner, nproc/uptime/free, netns inode, PID adb-server), хвост журнала эмулятора (tail 200, ≤2 файла), **`logcat-kolco.txt` — предостановочное кольцо logcat (`logcat -d -t 50`, пишется сэмплером В ПРОЦЕССЕ работы по живому транспорту, ≤1 чтения в 15 с, ≤96 KiB)**, **`emulator-exit.txt` — фиксация завершения эмулятора (исчезновение PID из /proc, последнее состояние процесса, дельта oom_kill cgroup, маркеры причины из хвоста журнала эмулятора)**, ограниченный logcat момента сбора (`-t 200` либо честный маркер недоступности), найденные сигнатуры file:line (≤20), itog, — снятый ДО остановки/повтора (сэмплер живёт весь экраной шаг), redacted, объём ограничен; зелёный/восстановленный-зелёный/продуктовый красный без обрыва не публикуют и не краснеют (И-3).

**РЕШЕНО ВЛАДЕЛЬЦЕМ 2026-10-31 (п.2 решения 26.10 «PID/exit эмулятора»):** слово владельца 31.10 ~11:55 UTC (через консультанта, дословно по пункту 150): «150 причинный замер обрыва — один дополнительный scoped-критик сверх капа на правки П1–П3 арбитража 150 (итог арбитража подтверждает Fable — Astra была консультантом предмета); суррогат кода выхода эмулятора (факт и момент смерти PID, дельта oom, маркеры журнала, статус NE_DOSTUPEN) принят вместо числового exit п.2 решения 2026-10-26, числовой exit — отдельным предметом позже». Почему суррогат, а не число: числовой wait-status надёжно недоступен этому непривилегированному наблюдателю ПОСЛЕ reap — сэмплер не родитель qemu; пока процесс zombie, Linux может отдать wait-status через поле 52 /proc/PID/stat при доступном procfs, но лёгкий sampler (И-4: ≤1 Гц) не гарантирует попадания в это окно; чтение журнала эмулятора после `trap cleanup EXIT` даёт лишь маркеры. Даже прочитанное значение поля 52 — ЗАКОДИРОВАННЫЙ wait-status (exitcode<<8 | signal), а не сам exit code: без декодирования числом выхода его не называть. Предмет реализует и судит ПРИНЯТУЮ владельцем часть: факт и момент смерти PID (таймлайн + `emulator-exit.txt`), последнее состояние процесса до смерти, дельту `memory.events oom_kill` cgroup раннера через момент смерти, маркеры причины из журнала эмулятора (signal/segfault/fatal/oom/crash/killed) и честный маркер `vyhod_status=NE_DOSTUPEN`. Числовой exit — ОТДЕЛЬНЫЙ предмет позже по слову того же владельца (не «отложено молча»): его реализация потребует правки побайтово замороженных экраных тел/лекала (выход владельцев 143/117/135/118/995) либо расширенных доступов наблюдателя.

## Модель угроз

ЗАЩИЩАЕТ:
- публикацию причинного замера на красном с сигнатурой обрыва в ТЕКУЩЕЙ попытке ns и ТОЛЬКО на нём: зелёный, восстановленный-зелёный (включая сохранённый архив `ns/diagnostics/attempt-N` 995) и продуктовый красный без обрыва артефакт не получают и итога не меняют;
- данные момента обрыва, снятые до остановки/повтора эмулятора: PID-таймлайн живого процесса, cgroup/PSI-счётчики, boot_id/PID adbd живыми пробами, смена adb-server, logcat-кольцо по живому транспорту, фиксацию завершения эмулятора (смерть PID, дельта oom_kill, причина по журналу);
- границы объёма артефакта (каждый файл и артефакт целиком — точно в потолке, маркер обрезки включён) и редакцию секретов во всех его текстах, включая многострочный PEM-блок целиком (тело и END — тоже секрет);
- лёгкость замера (частота ≤1 Гц, пробы гостя и чтения кольца ≤1 в 15 с, отсутствие тяжёлых команд — сам не нагружает раннер);
- неизменность итога job обёрткой (отсутствие маскировки красного: запрет continue-on-error, гейт не шире ns текущей попытки, путь upload согласован с ФАКТИЧЕСКИМ `--out` исполняемой команды сбора по каждому работнику);
- гигиену самоисполняемой батареи: каждый порождённый процесс-подделка мира остановлен и дождан, живых нонсов мира после суда нет (клетка b12).
НЕ ЗАЩИЩАЕТ:
- истинный числовой exit code qemu: числовой wait-status надёжно недоступен этому непривилегированному наблюдателю после reap (сэмплер — не родитель qemu); пока процесс zombie, Linux может отдать wait-status через поле 52 /proc/PID/stat при доступном procfs — лёгкий sampler (И-4) не гарантирует попадания в это окно; закодированный wait-status без декодирования exit code'ом не называется; суррогат `emulator-exit.txt` (смерть PID/ом-дельта/причина по журналу/маркер `vyhod_status=NE_DOSTUPEN`) ПРИНЯТ владельцем 2026-10-31 вместо числового exit п.2 решения 26.10 (см. §Предмет) — не «отложено молча»: числовой exit вынесен ОТДЕЛЬНЫМ предметом позже по слову того же владельца, его реализация потребует правки экраных тел/лекала либо расширенных доступов — за владельцами 143/117/135/118/995;
- обрыв без следа в текущей попытке ns (транспорт умер ДО записи сигнатуры в лог финальной попытки): гейт молчит — замер перестраховки не предусмотрен, слово владельца 26.10 «зелёный job замер не публикует»; расширение — отдельный предмет;
- станционные причины (kernel OOM/KVM/segfault за интервал) — чтение владельцем станции при доступе (Astra §10), батарея их не моделирует; отсутствие прав честно помечается;
- сэмплер умирает вместе с job при SIGKILL/аварии хоста — последняя строка таймлайна честно обрывается;
- поведение живого GitHub Actions (upload-artifact v7, реальный adb-транспорт) батарея моделирует подложками в замкнутом мире — живая проводка доказывается приёмками 7/8 исполняемой процедурой `zhivaja_priemka_150.sh` (каждая проверка — логическое сравнение с именованным отказом; ошибка gh/API не считается успехом; самопроверка на подложном gh — `--samoproverka`);
- полнота обёртки у экранов, вливаемых БЕЗ соблюдения нормы, ловится только постфактум красным `--repo` в CI харнесса (норма кусает после merge, не до) — признанное ограничение механики.
