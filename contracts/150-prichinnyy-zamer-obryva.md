## Предмет и инварианты

**Предмет (один наблюдаемый результат):** в каждом красном экранном job Complior-mob, упавшем по канонической сигнатуре обрыва adb (141), CI публикует артефакт причинного замера — `sampler.tsv` таймлайн (PID/состояние эмулятора из `/proc`, `adb devices` состояние, boot_id/PID adbd гостя из живых проб, cgroup раннера memory.current/memory.events(high,max,oom)/cpu.stat(nr_throttled,throttled_usec)/PSI(cpu,memory avg10), host MemAvailable), системный снимок (UTC, run/attempt/job/runner, nproc/uptime/free, netns inode, PID adb-server), хвост журнала эмулятора (tail 200, ≤2 файла), **`logcat-kolco.txt` — предостановочное кольцо logcat (`logcat -d -t 50`, пишется сэмплером В ПРОЦЕССЕ работы по живому транспорту, ≤1 чтения в 15 с, ≤96 KiB)**, **`emulator-exit.txt` — фиксация завершения эмулятора (исчезновение PID из /proc, последнее состояние процесса, дельта oom_kill cgroup, маркеры причины из хвоста журнала эмулятора)**, ограниченный logcat момента сбора (`-t 200` либо честный маркер недоступности), найденные сигнатуры file:line (≤20), itog, — снятый ДО остановки/повтора (сэмплер живёт весь экраной шаг; у матричного child — до повтора/finally), redacted, объём ограничен; зелёный/восстановленный-зелёный/продуктовый красный без обрыва не публикуют и не краснеют (И-3).

**РЕШЕНО ВЛАДЕЛЬЦЕМ 2026-10-31 (п.2 решения 26.10 «PID/exit эмулятора»):** слово владельца 31.10 ~11:55 UTC (через консультанта, дословно по пункту 150): «150 причинный замер обрыва — один дополнительный scoped-критик сверх капа на правки П1–П3 арбитража 150 (итог арбитража подтверждает Fable — Astra была консультантом предмета); суррогат кода выхода эмулятора (факт и момент смерти PID, дельта oom, маркеры журнала, статус NE_DOSTUPEN) принят вместо числового exit п.2 решения 2026-10-26, числовой exit — отдельным предметом позже». Почему суррогат, а не число: числовой wait-status надёжно недоступен этому непривилегированному наблюдателю ПОСЛЕ reap — сэмплер не родитель qemu; пока процесс zombie, Linux может отдать wait-status через поле 52 /proc/PID/stat при доступном procfs, но лёгкий sampler (И-4: ≤1 Гц) не гарантирует попадания в это окно; чтение журнала эмулятора после `trap cleanup EXIT` даёт лишь маркеры. Даже прочитанное значение поля 52 — ЗАКОДИРОВАННЫЙ wait-status (exitcode<<8 | signal), а не сам exit code: без декодирования числом выхода его не называть. Предмет реализует и судит ПРИНЯТУЮ владельцем часть: факт и момент смерти PID (таймлайн + `emulator-exit.txt`), последнее состояние процесса до смерти, дельту `memory.events oom_kill` cgroup раннера через момент смерти, маркеры причины из журнала эмулятора (signal/segfault/fatal/oom/crash/killed) и честный маркер `vyhod_status=NE_DOSTUPEN`. Числовой exit — ОТДЕЛЬНЫЙ предмет позже по слову того же владельца (не «отложено молча»): его реализация потребует правки побайтово замороженных экраных тел/лекала (выход владельцев 143/117/135/118/995) либо расширенных доступов наблюдателя.

Инварианты:

- **И-1 (итог job неприкосновенен):** шаги обёртки и дочерний хук никогда не меняют вывод экраного шага/child: старт подавляет собственные отказы, сбор всегда rc 0, rc хука maestro = rc обёрнутой команды, артефакт `if: always()` с `if-no-files-found: ignore`; собственные отказы замера — именованные маркеры в логе (`ZAMER_*`), ловцы — батарея и пункт ревьюеру; `continue-on-error` запрещён у всех шагов работника И на уровне job.
- **И-2 (данные до остановки):** сэмплер стартует ДО экраного исполнения (у child — до boot/maestro), частота не чаще 1 сэмпла в секунду (≤1 Гц) локальных чтений; живость PID — из `/proc`; завершение эмулятора фиксируется В МОМЕНТ события сэмплером (`emulator-exit.txt`: смерть PID, состояние до, дельта oom_kill, причина по журналу, честный маркер недоступности числового кода); logcat-кольцо пишется по живому транспорту ДО смерти (`-t 50`); недоступное на момент сбора (logcat/boot_id при offline) — маркер НЕДОСТУПНО, не пустота (Astra §10: «фиксировать, что logcat оборвался»); у child при отказе с сигнатурой — сбор ДО повтора (состояние первой неудачи не теряется).

- закрытость канона обёртки: каждый шаг замера КАЖДОЙ единицы покрытия байт-в-байт равен отрендеренному канону, отклонение — именованный отказ (никакая пере-сериализация, дубликат ключа, алиас/тег, лишний управляющий ключ, чужая форма run/shell/if/cwd/env не проходит); lane-форма — только при закрытой привязке к пиннованному скрипту;
- исполнительный результат по каждой единице: канонический сбор судится по реальным файлам (itog/signatury), событие запуска процесса или echo результатом не считается;
- границы объёма артефакта (каждый файл и артефакт целиком — точно в потолке, маркер обрезки включён) и редакцию секретов во всех его текстах, включая многострочный PEM-блок целиком (тело и END — тоже секрет);
- лёгкость замера (частота ≤1 Гц, пробы гостя и чтения кольца ≤1 в 15 с, отсутствие тяжёлых команд — сам не нагружает раннер);
- неизменность итога job обёрткой (отсутствие маскировки красного: запрет continue-on-error на шагах и job, гейт не шире ns текущей попытки; rc хука = rc обёрнутой команды child);
- гигиену самоисполняемой батареи: каждый порождённый процесс-подделка мира остановлен и дождан, живых нонсов мира после суда нет (клетка b12).

- станционные причины (kernel OOM/KVM/segfault за интервал) — чтение владельцем станции при доступе (Astra §10), батарея их не моделирует; отсутствие прав честно помечается;
- сэмплер умирает вместе с job при SIGKILL/аварии хоста — последняя строка таймлайна честно обрывается;
- поведение живого GitHub Actions (upload-artifact v7, реальный adb-транспорт, npm-рантайм lane) батарея моделирует подложками в замкнутом мире — живая проводка доказывается приёмками 7/8 исполняемой процедурой `zhivaja_priemka_150.sh` (каждая проверка — логическое сравнение с именованным отказом; ошибка gh/API не считается успехом; самопроверка на подложном gh — `--samoproverka`); исполнительные клетки применяют каноническую семантику `shell: bash` по БАЙТАМ канона, но сам npm в песочнице не исполняется (F2 проверяется статической привязкой lane — osi.md «границы честности»);
- ветвление проверяемого `run` по окружению песочницы/CI: произвольный run вне канона отвергается целиком (не исполняется), канонический — исполняется в канонической семантике; ветвление ВНУТРИ канонического run (кроме зафиксированных `|| echo` старта) невозможно байтами; cognitive-only остаток — живой CI и reviewer;
- подделку журнала проверяемым `run` через доступный путь/дескриптор двойника: диск проверяемого во время исполнения не является истиной ожиданий (правило 8); ловец — reviewer, отдельной механической гарантии нет;
- запуск скрипта сбора минуя двойник PATH (абсолютный путь к bash/скрипту) и обход канона правкой child-раннера ВНЕ канон-строк: батарея судит канон-строки хука и байты шагов, но не семантику остального кода раннера — его держат батареи 143 v3 и живые приёмки; 
- полнота обёртки у экранов, вливаемых БЕЗ соблюдения нормы, ловится только постфактум красным `--repo` в CI харнесса (норма кусает после merge, не до) — признанное ограничение механики.

## Демаркация

Конформные входы батареи — деревья продукта, где карта соответствует грамматике 143 (записи с job/id/output_namespace[, avd_port]), workflow — схеме GitHub Actions без дубликатов ключей/алиасов/тегов, а обёртка замера — отрендеренному канону; валидный контрпример = дерево, расходящееся с моделью ТОЛЬКО по замеру (байты канона обёртки/хука/скрипт/гейт/объём/редакция), при инвариантности к именам экранов/портам/флоу/форме (F1|F2|матричная) и к root/job defaults (шаги замера несут явные shell/working-directory). Батарея конечна против пространства workflow-грамматик: недостижимые состояния (кривой YAML, не-карта, нет скрипта, дубликат ключа) дают именованные отказы (rc 1/rc 2), никогда зелень; карта без матричных записей — законное состояние (z07 зелёна «детей нет»), карта отсутствует — зелень невозможна (SUBJECT_ABSENT красен во всех клетках).
