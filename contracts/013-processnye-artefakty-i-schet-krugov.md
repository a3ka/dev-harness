## Предмет

### А — Н-53/В1: фильтр процессных файлов в обходе коммитов check_zones

В `scripts/check_zones.sh` (обход коммитов, перед сопоставлением файла с зоной)
фильтруются ФАЙЛЫ — не коммиты — ровно трёх процессных видов:

| Путь | Вид |
|---|---|
| `verdicts/*` | каталог ЦЕЛИКОМ (critic/, adversary/, review/, arbitration/ — все четыре: приёмка параметризована по подкаталогам, находка 2 вердикта v1) |
| `NABLIUDENIA*.md` | глоб КОРНЕВОГО уровня |
| `HANDOFF.md` | точный файл |

Свойства (все — решения владельца и измеренные требования, не вкус):

- коммит из ТОЛЬКО процессных путей — вне суда целиком;
- смешанный коммит судится по предметным файлам (прецедент `e62bc2fe`: roles/ +
  NABLIUDENIA.md одним коммитом остаётся судимым по roles/-половине);
- СПАСЕНО-механика НЕ трогается — остаётся для предметных нарушений; отрицательная
  фикстура конечности `case_spaseno_ne_nazvannyj_hash.sh` в силе;
- сводная строка печатает счётчик «процессных вне суда: N», где N — число процессных
  ФАЙЛОВ, исключённых фильтром при обходе проверяемых коммитов (смешанный коммит
  отдаёт процессный файл счётчику, предметную половину — суду); единица ФАЙЛЫ
  ДИСКРИМИНИРОВАНА двумя точками ΔN=2 — чистой и смешанной (РЕШЕНИЕ арбитража
  kontrakt-013-edinitsa-scheta): коммит с двумя процессными файлами обязан дать
  прирост ровно +2 в каждой ветви — счёт коммитами, видами фильтра или префиксами
  путей даёт +1 и краснеет; молчаливый skip
  запрещён (зелёное называется; поимённые ok-строки на каждый вердикт — шум,
  отклонены развилкой 2);
- существующие ЗОНА-строки на процессные пути (замороженные 011/012) остаются
  валидными и становятся безвредными no-опами — новая запрещающая грамматика
  отвергла бы замороженные блобы (frontier В3, отклонён);
- комментарий в скрипте несёт причину: Н-53, рекурсия carve-out, ×1/×2.

НЕ входят в исключение (осознанно, боли не измерено): `plans/`, `contracts/`,
`roles/`, `.omp/`, `AGENTS.md`, `decisions/`, `ROADMAP.md`.

### Б — Н-57/Р1: circles по событиям смены первой строки вердикта

В `scripts/freeze_contract.sh` §6а счёт коммитов по глобу заменяется
реконструкцией таймлайна первых строк:

- вход — `git log --reverse -M --format=@%H --name-status -- "verdicts/critic/${dir}-${NNN}-v*.md"`;
- каждое **A/M** и **R со скором <100** даёт событие «первая строка файла» (у R —
  назначения) с нормировкой как у `first` в §6 (`tr -d '\r'`, trim; классы
  `accept|FAIL|ESCALATE`; прочее — свой класс, событие всё равно);
- **D и R100 событий не дают** — удаление и чистое переименование суть форма,
  не содержание (дискриминировано пятой ветвью probe_grammatika_sobytij: R100
  переносит файл с первой строкой, ОТЛИЧНОЙ от класса последнего события другого
  файла глоба, — ложно начисленный круг не сжимается и даёт кап; круг 2 вердикта);
- несколько файлов глоба в одном коммите — порядок по пути (детерминизм);
- подряд-одинаковые классы сжимаются; `circles` = длина сжатого; первое событие =
  круг 1 (появление вердикта есть круг);
- комментарий §6а переписать под эту грамматику (Н-57: три ложных капа на 011,
  012/1, 012/2); текст `die` НЕ меняется.

Контроль на живой истории 012 (замер frontier §0, воспроизведён при сдаче пачки):
события `[FAIL, accept, accept, accept, accept]` → сжатый `[FAIL, accept]` →
**circles=2** в точках обеих заморозок — не раздувает (шум не считается) и не слепит
(реальная серия FAIL→accept→FAIL растёт). Порог капа (≥3) и клапаны (арбитр /
слово владельца) — не меняются.

### Пробы перехода: красное сейчас — зелёное только у реализованного предмета

Находка 1: обе scoped-команды и smoke зелёны УЖЕ на нереализованном дереве — они
держат честность фикстур, но предмет не дискриминируют, а раннер судит фикстуру
повызовно и пофигурных ожиданий не держит. Дискриминацию несут пробы — файлы с
собственным кодом возврата, ветвями с ожидаемыми кодами и поимённой печатью
несовпадения (грамматика предполётного гейта: каждая обязана существовать, быть
исполняемой и быть красной на текущем дереве):

- `bash fixtures/check_zones/probe_protsessnye_vne_suda.sh`
- `bash fixtures/check_zones/probe_svod_protsessnyh.sh`
- `bash fixtures/freeze_contract/probe_012_dva_kruga.sh`
- `bash fixtures/freeze_contract/probe_grammatika_sobytij.sh`

Сейчас каждая → rc=1 (первая несовпавшая ветвь напечатана поимённо). После
реализации → rc=0, и РОВНО при честном предмете: частный фильтр `verdicts/critic/*`
(краснеет на adversary/review/arbitration), молчаливый или всегда-нулевой счётчик
(расходится с точным N), счёт КОММИТАМИ/ВИДАМИ/ПРЕФИКСАМИ вместо файлов — сверки
N=1/2 вырождены (по одному процессному файлу на коммит); РЕШЕНИЕ арбитража
kontrakt-013-edinitsa-scheta требует точку ΔN=2 в ОБЕИХ ветвях реализации, гибрид
«файлы в одной, коммиты в другой» краснеет хотя бы на одной из них: ЧИСТАЯ N=4 —
два файла ОДНОГО вида (оба в verdicts/critic/) одним коммитом, rc 0 (стабы
коммитов/видов/префиксов напечатают 3/2/2); СМЕШАННАЯ N=6 — два процессных
(HANDOFF.md + NABLIUDENIA_SUDJA.md) плюс предметный вне зоны, rc 1 по предметной
половине (коммитосчётчик напечатает 5); игнор шума (реплей 012 не
проходит обе точки), счёт R100 событием назначения (пятая ветвь грамматики:
чистое переименование файла глоба с первой строкой FAIL при хвосте accept —
событий [FAIL, FAIL, accept], сжатый [FAIL, accept] = 2, кап молчит; стаб «любое
R — событие» даст ложное FAIL: сжатый [FAIL, accept, FAIL] = 3 → кап), игнор
R<100, CR/trim или неизвестного класса, обход файлов одного коммита в произвольном
порядке — каждый оставляет свою ветвь красной, и проба остаётся rc=1.
Соответствие проб находкам: 1+2 → probe_protsessnye_vne_suda, 3 →
probe_svod_protsessnyh, 1(история 012) → probe_012_dva_kruga, 4 →
probe_grammatika_sobytij. Круг 2: единица счёта → две точки ΔN=2 (чистая N=4,
смешанная N=6) в probe_svod_protsessnyh по РЕШЕНИЮ арбитража
kontrakt-013-edinitsa-scheta; R100 → пятая ветвь probe_grammatika_sobytij
(кругов 2, rc 0).
