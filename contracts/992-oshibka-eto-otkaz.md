## Предмет

Один результат: сбой проверки не превращается в разрешение, пропуск проверки, выпуск версии или запись некорректной строки. Область — только перечисленные места семи существующих скриптов плюс регрессии пакета A. Нового гарда, нового парсера и новой грамматики нет.

1. Ошибки чтения области/дельты charter, списка worktree/тегов/диапазона preflight, существующего package.json дают rc1 с именованной причиной. Отсутствующий package.json и дерево без check-ключей сохраняют законный пропуск rc0; отказ show при существующей записи дерева — не отсутствие.
2. judge получает seq только после успешного чтения/разбора журнала; обе ветви verdict/policy отказывают до append на ошибке. Неудачный append в обоих писателях — rc1 и причина «журнал: … строка не записана», без success-баннера. Ожидаемая строка и исходные байты журнала снимаются проверяющим до вызова.
3. Названные пять jq-проверок не выпускают профиль при аварии jq; stderr называет jq и проверяемую ветвь, stdout пуст. Законное false/отсутствующее optional поле не становится отказом. Существующие P1…P7 для ошибок данных не ослабляются.
4. Обе выдачи max+1 сначала успешно читают полный список версий. Ошибка перечисления — rc1 с for-each-ref в причине, без тега, реестра и коммита. Не угадывать v1, не ждать случайного отказа tag -a.
5. Шесть исходных исправлений A закрепляются независимыми предъявлениями. Не удалять и не ослаблять их при реализации B.

НЕ предмет: другие похожие `|| true`, конкурентный append/локи, криптографическая целостность журнала, транспорт gitw, схема профилей, изменение полномочий/ролей. Новый класс вне названных мест — отдельная Н-запись/контракт, не расширение 992.

## Конструкция и демаркация

Батарея `fixtures/freeze_contract/fail_closed_992.py` запускает публичный CLI полного скрипта в одноразовом репозитории с собственной `.git`. Сеть заменена только на границах ls-remote/curl; git/jq-шим возвращает ненулевой rc на конкретном вызове, прочие вызовы делегирует реальному бинарю. Независимые prerequisite-гейты freeze/done и свидетельства судьи изолированы зелёными стабами — их корректность не предмет 992. На одном входе контроль без сбоя обязан дать rc0, на парном сбое — rc1 и предметную причину; в матрице старый скрипт обязан дать именно rc0, а не просто провалить произвольный assert. Исключение: две CI-append клетки различаются диагнозом при rc1 на обеих сторонах.

24 именованные клетки задаются единственным словарём CASES в батарее: восемь A (шесть исходных мест плюс отдельные ветви merge-base/verdict-append); charter diff/tree; preflight package/worktrees/tags; judge policy-seq/verdict-seq; profile defaults/keys/object/strings/array; freeze/done versions; CI ok/fail append. Каждая выполняется отдельно и имеет свой итог, объединённого зачёта по первой красной точке нет. Матрица сравнивает родителя A, живое дерево и кандидатную модель на скопированных субъектах. Исторический код — обманный стаб: сохранённый fail-open, не константный `exit 0`. `model_992.py` — исполняемое предложение для проверки конструкции, НЕ production-реализация и НЕ fallback при обычной приёмке.

Конформные входы: обычный Git-репозиторий с полным читаемым контролем; существующий JSON допустимой схемы; журнал с допустимой строкой либо явно предъявленным ошибочным seq; ошибки инструментов rc128 (git), rc7 (jq/подгейт); реально незаписываемый файл `/proc/version` вместо chmod-трюка, работающего иначе под root. Номер/путь/sha не являются причиной отказа. Валидный контрпример = сохранение класса входа при замене значений и различие наблюдаемого результата. Мера не претендует на доказательство против субъекта, который специально узнаёт фикстуру или атакует процесс проверяющего.
