**Ветвь A — `.githooks/pre-push`: scoped чартер-суд диапазона пуша.**
Сегодня (код): между рабочим деревом и origin нет НИ ОДНОГО механического судьи устава —
pre-commit судит staged, CI судит origin ПОСЛЕ пуша (необратимо); remote-side pre-receive
на plain GitHub недоступен (факт хостинга). Новый `.githooks/pre-push` (exec-паттерн
pre-commit, `core.hooksPath` уже коммичен установщиком package.json:37): git подаёт хуку
на stdin строки `<local_ref> <local_sha> <remote_ref> <remote_sha>` на каждый пушимый
ref; отказ хука валит ВЕСЬ пуш. Договор суда:

1. **Все remote**, не только origin: хук судит каждую строку stdin независимо от того,
   куда пушат (сегодня remote один — семантика «все» дешевле специального случая).
2. Аннотированные теги разыменовываются `^{commit}` до коммита.
3. **Диапазон**: валидный `remote_sha` → `$remote_sha..$local_sha` (пуш main судит ВСЁ
   новое на main, даже уже уехавшее бэкапом wip-ветки мимо хука); нулевой `remote_sha`
   (новый ref) → `$local_sha --not --remotes` — первая экспозиция линии. Пуш тега РАНЬШЕ
   его линии даёт непустой судимый диапазон и умирает на красном — origin больше не может
   стать «тегом без своей линии» (Н-78(3)).
4. **Судимое множество и вердикт — наследование scoped-семантики check_charter, кольцо
   ОДНО**: `is_charter_path`, `charter_diff_paths`, `razreshil` — ТОЛЬКО импортом
   `CHARTER_LIB=1` из `scripts/check_charter.sh` (прецедент потребителя
   check_staged.sh:72-76); вторая реализация кольца запрещена (прецедент
   lib_zones/lib_registry). Файл уставной с ПЕРВОЙ заморозки (`frozen/<dir>/<NNN>/1`,
   `ustav/1`) — коммиты ДО since вне суда; merge — по дельте к ПЕРВОМУ родителю
   (`charter_diff_paths`), веточные — по своей дельте; грамматика `razreshil`
   НЕИЗМЕННА (первая колонка, путь, непустая причина — check_charter.sh:23-35);
   добавление уставного файла свободно (`--diff-filter=MD`).
5. Красный (устав-дельта M/D без РАЗРЕШИЛ в ТОМ ЖЕ коммите) → пуш умирает целиком,
   rc≠0, именованная причина: ref, коммит, путь.

## Демаркация конформности (с первой редакции)

Конформный вход построен по документированной грамматике предмета: уставной путь —
`AGENTS.md`/`ROADMAP.md` при живом `ustav/1`, `plans/NNN-*.md`/`contracts/NNN-*.md` при

ПЕРВОЙ колонке тела ТОГО ЖЕ коммита; merge --no-ff; пути относительные. Обе грани класса
конформны: merge-грань — merge-коммит с уставной дельтой к `^1` при нейтральных
родителях (`7c90925`), веточная — не-merge коммит с дельтой M (`27d387b`). Конформное
лечение — reset + cherry-pick с корректной строкой в теле (`27e57db`). Валидный
контрпример = инвариантность к значениям (подстановка номеров/имён/содержимого дельты не
меняет исход; арбитраж ebc57db) ∧ расхождение честной реализации и слабой НА КОНФОРМНОМ
входе (арбитраж fa0d354). Стаб подставляется тому входу, где его дефект наблюдаем
(Н-39, NABLIUDENIA.md:688): «no-op» — на любом красном пуше, «только merge» — на пуше
ветки без merge в диапазоне, «полная история» — на лечении поверх повреждённого origin;
требовать красноты стаба там, где он ведёт себя честно, — требовать лжи в диагнозе.
