### Половина Б: инженерия раннера (ПИННОВАННЫЙ API)

`scripts/verify_antiplacebo.sh` — правки минимально-необходимые; scoped-фильтр, цикл
прогона, учёт вызовов и слепок НЕ трогаются (фрозены 006/007/008; регресс — приёмка 6).

1. **Scratch вне стерегомого дерева.** Все run-каталоги, логи и артефакты раннера —
   под `$VERIFY_ANTIPLACEBO_SCRATCH`; при пустой переменной — `mktemp -d` под
   `${TMPDIR:-/tmp}` (carve-out правила 16). Стерегомое дерево байт-в-байт неизменно
   на пишущем раннере — ни во время прогона, ни после (Н-48-2/5).
2. **Lock против параллельных прогонов.** Файл
   `$SCRATCH/verify_antiplacebo-<hash8>.lock`, где `hash8` — первые 8 hex sha256
   КАНОНИЧЕСКОГО пути проверяемого корня (разные деревья друг друга не блокируют:
   взаимная порча снапшотов измерена для одного дерева, Н-48-3). Содержимое:
   `<pid> <pgid> <epoch>`. Захват атомарен (`set -C`). Живой владелец → раннер
   отказывает: stderr `занят: …` (слово «занят» — пин, правило 7) и код 3; шапка
   раннера дополняется `3 — занят другим прогоном`. Существующий прогон НЕ убивается
   и не портится.
3. **Стартовая чистка** мусора убитых прогонов (Н-48-5): перед захватом lock удаляются
   lock-файлы и `run-<pid>` каталоги МЁРТВЫХ владельцев (по `kill -0`), а также файлы
   в scratch, не являющиеся ни lock, ни run-каталогом живого pid (base64-обрывки
   путей). Чужой live lock другого дерева и run-каталоги живых pid неприкосновенны.
4. **Дисциплина убийства.** Раннер убивает ТОЛЬКО собственных потомков по pgid
   (существующий `kill -- -<case_pid>`); `pkill`/`pgrep -f` по имени процесса
   запрещён (Н-48-4: так убивали чужие прогоны).

Зелёный образец API — `fixtures/check_runner_hygiene/_ref_runner.sh` (эталон вокруг
тривиальной работы; предмет исполняет ту же дисциплину вокруг полной пачки).
