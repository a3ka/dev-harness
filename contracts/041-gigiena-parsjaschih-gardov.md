## Модель угроз

ЗАЩИЩАЕТ:
- честный разбор произвольного содержимого буллетов и структурных полей независимо от того какие байты встречаются внутри данных
- различение отсутствия обязательной секции от присутствующей но структурно неполной секции именованной причиной первой красной проверки
- защиту меток и разделителей грамматики от подмены смысла через regex или glob инъекцию untrusted содержимого

НЕ ЗАЩИЩАЕТ:
- враждебное окружение вызывающего процесса за пределами базового экспорта PATH включая sourced исполнение и экспортированные функции это отдельный класс ENV-TRUST и SOURCED-EXEC контракта 038 и не входит в область этого контракта
- смысловую адекватность содержимого буллетов модели угроз это решает критик по прямому переносу oblast-i-porog.md §Вопрос2 а не механизм
- решение о том обязана ли конкретная секция существовать в конкретном будущем контракте это cognitive-only критика roles/critic.md а не автоматическая классификация

## Инварианты

Грамматики — ЕДИНЫЙ источник этот контракт; реализация несёт фразы ПОБАЙТОВО
(фикстуры сверяют дословно через `grep -Fq`). Каждый пункт §Приёмка —
исполняемая команда с известным rc (канон 008).

1. **Область применения нормы.** Пункты 2–6 этого раздела обязательны для
   ЛЮБОГО контракта, замороженного ПОСЛЕ 041, который вводит гард
   `scripts/<имя>.sh`, и этот гард парсит/исполняет текст, автором которого
   не является сам гард. **Момент определения новизны гарда — HEAD ТОГО
   КОММИТА, на который указывает тег минта номера ЭТОГО контракта
   `id/CONTRACT/<NNN>`** (выдача `next_id.sh CONTRACT`), **а НЕ HEAD в
   момент заморозки.** Тег минта структурно предшествует ЛЮБОМУ коммиту,
   зонально признанному частью этого контракта ДО его заморозки
   (`check_staged.sh` дверь 023 (iii) — файл самого контракта без живого
   тега не проходит; `check_zones.sh` «рука Б» — гард/фикстура в
   резервации до заморозки признаются частью контракта ТОЛЬКО если тег
   минта уже жив и является предком коммита): поэтому гард, отсутствовавший
   на HEAD в момент минта и введённый строго ДО заморозки — именно так,
   как того требует обязательный пред-фризовый self-application п.2(v), —
   ОСТАЁТСЯ НОВЫМ для этой нормы, даже если к моменту заморозки он уже на
   HEAD: штатное предъявление self-application-кода НЕ выводит гард из-под
   нормы, потому что минт всегда предшествует ему. Гард, уже существовавший
   на HEAD в момент минта по причине, НЕ связанной с этим контрактом, новым
   не считается (это и есть случай «контракт без нового гарда» ниже). НЕ
   входят в область: контракты, правящие УЖЕ существующий гард (038 и любой
   будущий — правки существующего гарда судит критик по существу правки, не
   по этой норме целиком); контракты без нового парсящего гарда вовсе.
   Критик — единственный судья применимости (roles/critic.md, норма-строка
   §ПРОВОДКА); механизм ничего не решает о применимости, только о форме уже
   признанного применимым случая.
2. **Пять свойств формата для СТРУКТУРНЫХ полей (Направление 3).**
   «Структурное поле» — путь, разделитель, маркер, quoted-токен: то, что гард
   использует ДЛЯ РАЗБОРА, а не свободная проза (буллеты, причины — для них
   действует порог формы п.4, не байтовый алфавит: замкнутый алфавит для
   естественного языка неприменим по конструкции предмета). Контракт,
   вводящий гард, ОБЯЗАН в своих §Инварианты объявить для каждого
   структурного поля:
   1. **Замкнутый положительный алфавит.** Грамматика перечисляет байты,
      которые поле МОЖЕТ содержать («только эти байты»), а не байты, которые
      оно НЕ может содержать («всё кроме X»). «Всё кроме» пропускает КЛАСС
      непредвиденных байтов целиком — ровно так round 2 / round 3.Б2 038
      прошли `roles/*.md` / `[^/]*.md` (glob принят за регулярное выражение,
      `*` матчит `/` и пустую строку).
   2. **Представление без переиспользования байта данных разделителем.**
      Внутреннее представление (после разбора, ДО употребления) — массивы
      либо параллельные переменные, НЕ single-string с join-делимитером, если
      этот же байт разрешён ВНУТРИ данных поля. Байт `|` был именно таким
      разделителем в 038 ДО круга 12 (channel-pipe-truncation) — норма-строка
      легально содержит `|`, и join+split молча усекал её.
   3. **Литеральное untrusted-untrusted сравнение.** Сравнение одного
      untrusted-текста (имя файла на диске, basename аргумента) с другим
      (текст из контракта, объявленное имя) — ТОЛЬКО через равенство строк
      (`[ = ]`, `case` литерал, `grep -F`) либо явное экранирование перед
      построением паттерна. НИКОГДА — интерпретация ОДНОЙ стороны как
      regex/glob чужой, построенного из ДРУГОЙ untrusted-стороны без
      экранирования: round 13 038 (guard-ere-metacharacters) интерполировал
      basename файла в `grep -E` без экранирования, и `a.b.sh` принимал
      `axb.sh`.
   4. **Точечный якорь терминатора структуры.** Заголовки, fence, разделители
      секций matched ТОЧНО (`^якорь$`, побайтовое равенство строки), и длина
      терминатора СЧИТАЕТСЯ по семантической единице (уровень заголовка, вид
      маркера) — НЕ по суммарной длине совпавшего текста регулярного
      выражения. Round 12 (charter-heading-level) 038 вычислял уровень
      заголовка из длины regex-матча, включавшей нерелевантные байты
      (пробелы-разделители).
   5. **ОБЯЗАТЕЛЬНАЯ self-application green-фикстура при самоприменении, ДО
      заморозки.** Если вводимый гард парсит поле, которое ВСТРЕЧАЕТСЯ В
      САМОМ КОНТРАКТЕ, вводящем этот гард (как поле ПРОВОДКА встречается в
      038, поле «## Модель угроз» встречается в 041) — контракт ОБЯЗАН нести
      фикстуру, прогоняющую гард на СОБСТВЕННОМ буквальном тексте своего
      контракта, зелёную (rc 0) ДО заморозки. Не опционально: без этой
      фикстуры контракт НЕ ПРОХОДИТ критика (Вопрос 2 роли критика — «готово,
      недоказуемое командой»: self-application недоказуема на несуществующем
      контракте постфактум). Отличие от общего порядка «архитектор пишет
      реды, implementer — реализацию»: ДЛЯ ЭТОГО КОНКРЕТНОГО класса риска,
      измеренного кругом 15 038 (038 заблокировал СОБСТВЕННЫЙ done-gate
      регрессией в ПРОВОДКА-парсинге на СВОЁМ ЖЕ тексте), пред-фризовое
      доказательство обязано быть живым прогоном РАБОТАЮЩЕГО кода — красная
      фикстура «гарда ещё нет» этот риск не ловит по построению.
