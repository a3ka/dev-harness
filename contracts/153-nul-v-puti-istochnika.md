# Контракт 153 — ложный отказ NUL в пути источника sourceCanon

КЛАСС ЗАДАЧИ: КОДОВЫЙ — контракт, красная батарея и ремонт существующего шлюза.
КЛАСС РИСКА: рисковый — безопасность: шлюз проверяет пути источников и симлинки за границей репозитория, ошибочное ослабление NUL/канонизации может открыть чтение внешнего файла или пропустить сверку перед done; прежние отказы сохраняются отдельными отрицательными входами.
КОНТЕКСТ: слово владельца 2026-11-01 ~11:20 «эту ошибку в механизме харнеса надо взять в починку прямо сейчас»; репро бэкенда Complior-back: sourceCanon.path `migrations/001_core.sql` ложно даёт `SOURCE_CANON_INVALID: NUL в пути` при pre_critic/done по 142/143/144. Это блокирует штатный done; ручные done-теги не доказывают починку шлюза.

## Существующее

Существующий публичный CLI `scripts/check_project_sources.sh --repo R --contract P --stage pre_critic|done` получает effective sourceCanon от `scripts/profile_resolver.sh`, после проверки источника вызывает объявленный gate. В проверке пути `case "$p" in *\0*)` bash читает `\0` как литерал цифры 0: путь `migrations/001_core.sql` отказывает как NUL. Переменная bash не может хранить байт NUL.

`scripts/profile_resolver.sh:scan_canon` уже проверяет JSON-строки path и gate на `contains("\u0000")` ДО извлечения путей через `jq -r`/`mapfile`; источник грамматики сохраняется единым. Его существующие отказы `SOURCE_CANON_INVALID` наблюдаемы отдельным входом с JSON `"source\u0000.md"`. Повторный NUL-предикат над переменной bash не чинить другим строковым шаблоном.

`scripts/pre_critic.sh` и `scripts/done_contract.sh` вызывают этот CLI; менять их не нужно. `fixtures/workshop_project/rezhim_996/probe.py` + `probe.sh` судят режим проекта и sourceCanon, но не предъявляют путь с цифрой 0; это замороженная батарея, остаётся зелёной. `contracts/996-rezhim-proekta-polnyj-cikl.md` §Lifecycle и `contracts/112-podklyuchenie-proekta.md` описывают существующий шлюз и миграции бэкенда; текст замороженного 996 не правится. `registry/plan.tsv` содержит строку 153 (PR #470 `owner/plan-153`, в main 33f3e80d7); план — отдельная раздача консультанта, не реализация шлюза и не зона этой пачки.

## Frontier и граница

Выбор: убрать неисполнимый NUL-case из `check_project_sources.sh` и оставить существующую проверку исходного JSON в `profile_resolver.sh`. Вариант «искать NUL в bash-переменной» отвергнут: байт теряется при командной подстановке; вариант «дублировать jq-парсер в consumer» отвергнут: две грамматики расходятся. Измеренная боль — ложный отказ пути с 0, не перепроектирование путей источников.

Соседний `*..*` отвергает также `a..b.md`; резолвер 996 запрещает подстроку `..` в исходном JSON (`contains("..")`). Изменение его замороженной грамматики — новый класс отказа и отдельный контракт; 153 сохраняет её без ослабления. Конформные пути этой пачки не содержат `..` даже как подстроку; отрицательный вход с компонентом `..` остаётся красным.

## Предмет и инварианты

Один результат: объявленный в sourceCanon относительный regular file с цифрой 0 проходит тот же публичный шлюз и запускает gate, а настоящий JSON NUL отказывает ДО преобразования пути в bash; остальные проверки остаются действующими.

- И-1. Для каждой строки длины 1..5 над Σ = `0 1 a / . - _ \`, которая не начинается с `/`, не содержит `..` и представляет существующий regular file внутри R, реальный CLI даёт rc 0, пустые stdout/stderr и запускает gate. Исходные восемь входов `migrations/001_core.sql`, `10.sql`, `a0b/0.md`, `0.md`, `v1.0`, `0`, `0/x.md`, `x/0` сохраняются отдельными клетками (из них `0` входит в этот домен); цифра 0 сама по себе не основание отказа.
- И-2. JSON path с `\u0000` в `harness.project.json` даёт rc 1 `SOURCE_CANON_INVALID` и причину `path NUL` до извлечения путей и до исполнения gate. Сравнение исходного JSON выполняет действующий resolver, не дублирующий парсер в consumer.
- И-3. Абсолютный path и path с компонентом `..` дают rc 1 `SOURCE_CANON_INVALID`; симлинк на существующий файл вне R даёт rc 1 `SOURCE_CANON_INVALID: источник вне репозитория`; каталог и FIFO вместо regular file дают rc 1 `SOURCE_CANON_INVALID: источник не regular file`. Отказы 996 о симлинках и каталогах не ослабляются.
- И-4. Шов `pre_critic|done`, режим отсутствующего канона, argv/cwd/HEAD и коды существующего gate не меняются. Аддитивная батарея 153 дополняет, но не правит frozen 996; его батарея остаётся зелёной на реализации.

## Приёмка

Команда `W` = `bash fixtures/workshop_project/nul_istochnika_153/probe.sh` из корня харнесса; все миры — независимые временные git-репозитории. Конформный положительный вход: JSON sourceCanon с существующим относительным regular file внутри R, приоритетом 0 и исполняемым argv gate; отрицательные входы нарушают ровно названное свойство (JSON NUL, абсолютный/`..`, каноническое положение вне R, не-regular файл). Контрпример стаба валиден, если его результат расходится с честным на указанном конформном входе, независимо от значения временного корня; JSON NUL — отрицательный грамматический вход с требуемым отказом, не файл с NUL на диске.

Исчерпывающий домен `sweep`: 37448 строк Σ^{1..5} = 26502 положительных + 6530 грамматических отказов (`/`-префикс либо `..`) + 4416 не-regular по построению (хвост `/` либо последний компонент `.`). Батарея сверяет эти четыре константы; положительные создаёт через `os.open` по сырой строке с realpath внутри R, при конфликте файл/каталог повторяет партию той же длины. Каждая партия — один sourceCanon через реальный CLI с проверкой rc 0, пустых stdout/stderr и `gate-observed`; при первом отказе печатает RED со stderr первого отвергнутого пути и останавливается. Остальные 14 клеток неизменны; `--seed` меняет только имя временного корня, не строки домена.

1. Дано дерево до реализации; когда `W`; тогда rc 1, `CELLS=15 GREEN=6`: восемь прежних путей с цифрой 0 красны каждый по собственному отказу `SOURCE_CANON_INVALID: NUL в пути`; `sweep` отдельно RED с первым отвергнутым путём `0`.
2. Дано модель честного ремонта (одна отмена ложного NUL-case, действующий resolver сохранён); когда `W --model`, `W --model --seed 1`, `W --model --seed 7`, `W --model --seed 42`; тогда каждый rc 0, `CELLS=15 GREEN=15`. Парный негатив: `W` до ремонта → rc 1 с девятью красными клетками; модель — доказательство до реализации, после ремонта равна ей.
3. Дано модель и обманные копии реальных скриптов; когда `W --stabs`; тогда rc 0, `SVJAZI=14 CAUGHT=14 LIVE=0`; шесть glob-обманок по цифре 0 пойманы именно клеткой `sweep`, остальные — своим входом по карте батареи. Четырнадцать связей соответствуют тринадцати различным изменениям: directory и fifo проверяют одну замену `-f` на `-e` на разных входах. Негатив: выжившая обманка → rc 1 `STAB_SURVIVED`.
4. Дано реализация в scripts/check_project_sources.sh; когда `W` и `W --stabs`; тогда оба rc 0, `CELLS=15 GREEN=15` и `SVJAZI=14 CAUGHT=14 LIVE=0` соответственно. `W --repo` — алиас безфлагового `W`, а не второе независимое доказательство. Парный негатив — отдельные клетки JSON NUL, absolute, dotdot, outside, directory, fifo по И-2/И-3: каждая rc 1 по именованной причине.
5. Правило совместимости: `bash fixtures/workshop_project/rezhim_996/probe.sh` на реализации → rc 0; отрицательные клетки источника 996 остаются красными внутри своей батареи (её общий итог rc 0).

Цена на этой станции: `W` до ремонта 3.26 с, `W --model` 45.35 с (ожидаемый `W` после ремонта ≈45 с), `W --stabs` 59.80 с; CI-проводка учитывает длительный честный sweep, но обманки останавливаются на первой красной партии.

## Модель угроз

ЗАЩИЩАЕТ:
- ложный отказ на любом пути домена Σ^{1..5}, являющемся существующим относительным regular file внутри R без `..`, и ложное принятие настоящего JSON NUL;
- ослабление прежних отказов по абсолютному/`..`/симлинку наружу/каталогу/FIFO;
- статический плацебо-тест: батарея исполняет шлюз в отдельных git-мирах, сравнивает код и структурную причину в stderr, oracle задан в памяти проверяющего до запуска.

НЕ ЗАЩИЩАЕТ:
- обманка, чей минимальный триггер требует символа вне Σ (`*2*`, `*0z0*`, `*0 0*`, кириллица, `*[[:cntrl:]]*`) либо длины > 5 (`*/00/*`, `*000000*`, `*0/0/0/*`) — выживает по построению; ловец — ревьюер по диффу (ПЕРЕСЕЧЕНИЕ implementer: удалить ровно одну строку). Мутант, выживающий только за счёт символа вне Σ или длины > 5, предъявляется этой границе, не новым кругом по той же причине;
- обманки вне класса «детерминированный отказ по строке пути» (зависимость от времени, окружения, номера источника, содержимого файла) — домен их не различает; ловец — тот же ревьюер;
- имена файлов с подстрокой `..` без компонента: существующая замороженная грамматика 996 запрещает их, соседний дефект — отдельный предмет;
- управляющие символы кроме NUL: resolver 996 сегодня запрещает NUL, но не все управляющие символы; JSON path `x\ny.md` при существующих файлах `x` и `y.md` и отсутствующем `x\ny.md` даёт rc 0 с gate=True (`mapfile` делит путь). Их новый запрет меняет frozen-грамматику источников. Формулировка `NUL/управляющем символе` в owner-plan PR #470 передана оркестратору на отдельное решение, не приписывается существующему отказу 996;
- версия jq 1.6 в CI: `contains("\u0000")` может считать любую JSON-строку содержащей NUL; на станции используется jaq 2.3.0, батареи 996 и 153 проверяют фактический раннер, а изменение resolver вне 153;
- семантика `./a`, `a//b`, `a/./b` (ОС разрешает, гейт принимает) — домен их принимает вместе с ОС; это существующее поведение 996, 153 его не меняет и не судит отдельно;
- непредусмотренные нестандартные файловые системы, изменяемый между readlink и gate файл (TOCTOU): отдельный класс отказа, не измерен этим предметом;
- поведение самого пользовательского sourceCanon.gate: 153 судит запуск и отказ уровня шлюза, не корректность содержимого проверки проекта.
