## Модель угроз

ЗАЩИЩАЕТ:
- от публикации тега заморозки раньше текста в любой форме `gitw push`: суд стоит перед каждым exec настоящего git при push, состав берётся у git по тому же argv, а не из разбора argv;
- от ложного «текст уже в main» по суррогату: имя файла без blob, локальный main, снимок `refs/remotes/origin/main` — суждение по blob в живом main цели;
- от тега поверх неразрешающего или отсутствующего вердикта: вердикты v1…v сверяются первой строкой в main цели;
- от молчаливого допуска при нечитаемом авторитете или составе: нет main цели, вершина не получена локально, dry-run не дал состава — именованный отказ;
- от тупика «тег блокирует ленд своего текста» без ослабления 071: удержание вне `refs/tags/`, публикация — через тот же суд, отказ публикации возвращает удержание;
- от расширения суда на чужие классы тегов: `done/`, `id/` проходят прежним путём.

НЕ ЗАЩИЩАЕТ:
- от обмена мимо подкоманды `push` gitw: сырой `git push`, алиас-подкоманда (`gitw -c alias.p=push p …` — gitw передаёт её прозрачно по 045 И-3), ручной `git update-ref` удержания — обход двери 045, норма-строка «git-обмены только через bash scripts/gitw» (role-канал 045), cognitive-only; ловец — CI `check:contract-frozen` на ближайшем PR (`--no-verify` обходит только hook-дверь .githooks/pre-push, не суд внутри gitw);
- от гонки: main цели сдвинулся назад (force-push) между суждением и обменом — вне модели 045 (TCB);
- от иных причин красного `check:contract-frozen`: пропуск версии, правка замороженного текста в main — их ловит сам читатель;
- от ручки `GIT_EXCHANGE_GUARD_CANONICAL`, выставленной агентом, и от удаления файлов scripts/ — TCB-класс 045 дословно;
- от повторной заморозки того же номера во время удержания: freeze считает версии по `refs/tags/frozen/*` и может выдать удержанную версию повторно — publish тогда откажет `удержание невозможно` (R-3).

## Демаркация

Конформный вход: мир, где `gitw push …` (подкоманда литерально `push` после глобальных флагов, принятых 045 И-2) отправляет на каноническую цель ссылки любых классов в любой форме argv и конфига, которую принимает `git push`; тег заморозки — аннотированный или лёгкий, имя приёмника в §Грамматика либо вне её; файлы контракта и вердиктов — по путям §Существующее п.1; удержание — только командами `hold`/`publish` гарда. Конформная реализация: на каждом таком входе даёт rc, класс отказа, состояние цели и локальных ссылок по §Инварианты. Валидный контрпример = реализация, чьё rc, класс или состояние расходится с оракулом на конформном входе, инвариантный к seed (воспроизводится при другом NNN/v того же класса входа).
