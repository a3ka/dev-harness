## Предмет и граница

Один наблюдаемый результат: **`bash scripts/gitw push …`, чей состав обмена создаёт или двигает на цели `refs/tags/frozen/*`, исполняется, только если для каждого такого тега текст под тегом (тот же blob по тому же пути) и вердикты критика v1…v (`accept`) уже лежат в main ЦЕЛИ; иначе — именованный отказ до обмена, тег остаётся локальным, а push main с лендом самого текста при таком теге проходит. Исполнимая форма — `bash fixtures/workshop_project/teg_posle_teksta_130/red_teg_posle_teksta_130.sh --candidate <клон>` → rc 0.**

НЕ в предмете: scripts/freeze_contract.sh (не пушит, §Существующее п.2); удаление тегов на цели (флаг `-`), лёгкие (неаннотированные) теги заморозки, пропуск версий v<k — иные причины красного `check:contract-frozen`, не порядок публикации; теги `done/`, `id/`, `refs/done-hold/`; поезд публикации и служебные коммиты (строка плана `poezd-bez-dogonyalok`, следующий номер); сырой `git push` мимо gitw (§Модель угроз).

## Инварианты

1. Состав обмена — то, что отправил бы настоящий git: `git push --dry-run --porcelain --no-verify` с тем же argv (те же глобальные флаги, цель, refspec, `--tags`, `--follow-tags`, `--mirror`, конфиг `push.followTags`/`remote.<r>.push`). Судятся строки с флагом создания/сдвига (`*`, ` `, `+`), чей приёмник начинается с `refs/tags/frozen/`. Ни одной ссылки в составе при rc dry-run ≠ 0 — отказ класса «состав обмена не читается».
2. main ЦЕЛИ — `git ls-remote <цель> refs/heads/main` на момент вызова (живой авторитет 045), не локальный `main` и не `refs/remotes/origin/main`. Обмен с main и тегом одним вызовом судится по main цели ДО обмена.
3. Тег допущен ⇔ имя в грамматике (§Грамматика) ∧ под коммитом тега ровно один файл `<dir>/<NNN>-*.md` ∧ его blob равен blob того же пути в main цели ∧ для каждого k = 1…v файл `verdicts/critic/<dir>-<NNN>-v<k>.md` в main цели первой строкой (без краевых пробелов и `\r`) равен `accept`. Иначе — отказ, обмен не исполняется ЦЕЛИКОМ (ни тег, ни прочие ссылки того же вызова), локальный тег не трогается.
4. Fail-closed: нет main на цели, вершины main цели нет в локальном хранилище объектов, коммит под тегом не разрешается — отказ своим классом, не допуск. Недоступная цель — прежний отказ 045 И-7 `gitw ОТКАЗ: авторитет недоступен`.
5. Теги вне `refs/tags/frozen/` (в т.ч. `done/`, `id/`) и обмены без тегов заморозки судом 130 не затрагиваются: поведение gitw/071 на них прежнее.
6. Терпимость чека (2) 071: локальный `refs/tags/frozen/*`, которого НЕТ на цели (не переприцеленный), и чей текст или вердикт по И-3 ещё не в main цели, не блокирует push main — печатается `gitw ПРЕДПОЛЁТ: тег в ожидании текста: <тег>`. Тот же тег, когда текст и вердикты уже в main цели, блокирует push main прежним отказом чека (2) — напоминание запушить тег. Суждение «в ожидании» — то же, что И-3 (один источник суждения у гарда и чека (2)); нечем судить → не в ожидании → прежний отказ.
7. Отказ не требует ручных обходов: порядок «push main с лендом → push тега» проходит двумя вызовами gitw без переименования тегов, `refs/*-hold/` и ручек окружения.

## Модель угроз

ЗАЩИЩАЕТ:
- от публикации тега заморозки раньше текста в любой форме вызова gitw: литерал, короткое имя, `--tags`, `--follow-tags`, обмен «main + тег» — состав берётся у git, не из argv;
- от ложного «текст уже в main» по суррогату: имя файла без blob, локальный main, снимок `refs/remotes/origin/main` — суждение по blob в живом main цели;
- от тега поверх неразрешающего или отсутствующего вердикта: вердикты v1…v сверяются первой строкой в main цели;
- от молчаливого допуска при нечитаемом авторитете: нет main цели, вершина не получена локально, источник тега не разрешается — именованный отказ;
- от тупика «тег блокирует ленд своего текста»: тег в ожидании не блокирует push main, а после ленда снова требует публикации;
- от расширения суда на чужие классы тегов: `done/`, `id/` проходят прежним путём.

НЕ ЗАЩИЩАЕТ:
- от сырого `git push` мимо gitw (и `--no-verify` где угодно): обход двери 045 — норма-строка «git-обмены только через bash scripts/gitw» (role-канал 045), cognitive-only; ловец — CI `check:contract-frozen` на ближайшем PR (симптом виден в минутах);
- от гонки: main цели сдвинулся назад (force-push) между суждением и обменом — вне модели 045 (TCB);
- от иных причин красного `check:contract-frozen`: лёгкий тег, пропуск версии, правка замороженного текста в main — их ловит сам читатель;
- от ручки `GIT_EXCHANGE_GUARD_CANONICAL`, выставленной агентом, — TCB-класс 045 дословно.

## Демаркация

Конформный вход: мир, где обмен gitw отправляет на каноническую цель ссылки любых классов в любой форме argv, которую принимает `git push`; тег заморозки — аннотированный, имя в §Грамматика либо вне её; файлы контракта и вердиктов — по путям §Существующее п.1. Конформная реализация: на каждом таком входе даёт rc, класс отказа и состояние цели по §Инварианты. Валидный контрпример = реализация, чьё rc, класс или состояние цели расходится с оракулом на конформном входе, инвариантный к seed (воспроизводится при другом NNN/v того же класса входа).
