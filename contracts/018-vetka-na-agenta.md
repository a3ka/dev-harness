## Предмет

Три среза; срез 1 ⊥ {2,3}. Срез 2 — НОРМА (владелец-канал), срез 3 — процедура над готовыми
инструментами 016.

**Срез 1 — страж «ветка, не main» (Q4): расширение `scripts/check_staged.sh`.**
Существующий барьер add-A судит staged-множество по зонам автора; сюда добавляется ветвь
«коммит мимо своего worktree». Автор и «не судится» — прежней мерой (`git var
GIT_AUTHOR_IDENT`; `my_count==0` → «не судится» rc 0: владелец и прошлые сессии не
проверяются, fail-open). НОВАЯ ветвь, ПОСЛЕ «не судится» и ДО суда путей:

- если у автора ЖИВА ветка `refs/heads/wip/<NNN>/<автор>` (его спавнили в worktree) И
  текущий чекаут судимого корня — НЕ его СОБСТВЕННАЯ `wip/<*>/<автор>` (основной чекаут main,
  иной branch, detached, ЛИБО ЧУЖАЯ `wip/<*>/<другой>`) → rc 1, именованный отказ с
  подстрокой-литералом `вне своей ветки wip/` (единый источник литерала — фикстуры, Н-39);
- текущий чекаут — СОБСТВЕННАЯ `wip/<*>/<автор>` (автор-компонент имени ветки == committer) →
  ветвь молчит, суд продолжается зонами (агент коммитит в свой worktree — норма);
- у автора НЕТ живой `wip/<*>/<автор>` → ветвь молчит: автор не спавнен в worktree, его
  main-коммит легитимен (судья main-direct по (Q2), оркестратор, владелец).

Определение «СВОЯ wip vs не-своя» — по КОДУ (решение по коду, а не по прозе): текущая ветка
чекаута = `git -C <корень> symbolic-ref --short HEAD`; «своя» ⟺ ветка матчит `wip/*/<автор>`,
т.е. имеет префикс `wip/` И последний компонент (после последнего `/`) == committer; всё иное
(main, detached, ЧУЖАЯ `wip/<*>/<другой>`) — не-своя. Спавн-состояние автора =
`git -C <корень> for-each-ref refs/heads/wip/` с матчем компонента `/<автор>` последним. Обе
меры — чтение, identity не трогают, канарейка И-5 016 их не судит (не commit/merge).

**Премиса (Q4) исправлена по коду.** (Q4) велит исключать судей как «автор без зон». По
факту дерева судьи ЗОНИРОВАНЫ (critic/adversary/reviewer несут `verdicts/*`, orchestrator —
`NABLIUDENIA.md`/`HANDOFF.md`/`roles/`), у них `my_count>0`. Исключение через «не судится»
их бы НЕ покрыло и заблокировало легальные main-коммиты вердиктов/устава — ровно коллизия,
названная в (Q4). Поэтому исключение судьи/оркестратора достигается СПАВН-СОСТОЯНИЕМ (нет
своей `wip/*`-ветки → main-direct легитимен), а владельца — «не судится» (не зонирован,
fail-open). Наблюдаемый вход стража — Р2b: единственное место, где cwd-промах спавненного
агента (забыл `cd $WORKTREE`) виден. Остаток cognitive-only, назван прямо: рабочий агент,
которого НЕ спавнили вовсе (нет `wip/*`-ветки), на main неотличим от легального main-direct —
у стража нет входа; ловец этого — норма среза 2 (оркестратор спавнит каждого рабочего
агента), не барьер.

**Срез 2 — норма проводки (Q1,Q2,Q3): `roles/orchestrator.md` — НОРМА, владелец-канал.**
Путей `roles/` нет ни в одной ЗОНА-строке этого контракта (уставный класс, отдельное слово
владельца — прецедент 016 §Зоны). Механизм среза 1 от текста роли НЕ зависит. Текст-кандидат
нормы (владелец вносит):
- оркестратор спавнит КАЖДОГО РАБОЧЕГО агента (architect, implementer) через
  `spawn_agent --author <роль> --nnn <NNN>` в его `wip/<NNN>/<автор>` worktree; WORKTREE/BRANCH
  из stdout-контракта — в задание субагента ДО спавна (016 §6.2а);
- агент ПЕРВЫМ действием `cd $WORKTREE` и коммитит в свою ветку (Р2b, cwd cognitive-only,
  ловец — страж среза 1);
- судьи (critic/adversary/reviewer) — main-direct + репро в ОДНОРАЗОВОМ клоне (Q2, вариант i
  frontier §3 Р3): судейские ветки не заводятся, вердикт коммитится в main напрямую. Причина
  по коду: `land_agent` И-9 (016 :130-151) требует committer ∈ реестр авторов ЗОНА-строк —
  этот путь для судей не используется; страж среза 1 их пропускает спавн-состоянием. ⚠️
  расхождение с буквой ROADMAP §9:178 («спавнит КАЖДОГО, включая судей») названо: (Q2)
  разводит судей на main-direct;
- (Q3) оркестратор ОБЯЗАН передавать `--nnn <NNN текущего контракта>` каждому спавну:
  авто-нумерация `spawn_agent` (016 :108-121) выдала бы агентам одного майлстоуна РАЗНЫЕ
  номера. Единый `wip/<NNN>` — см. §Незаполненные (Q3-решение: названный остаточный риск).

**Срез 3 — явный land/merge (полнота, требование владельца): процедура над `land_agent` /
`gc_agent_branches` (готовы 016, РАБОТА НЕ РАЗДАЁТСЯ).** По accept судей оркестратор сводит
`wip/<NNN>/<автор>` → main вызовом `scripts/land_agent.sh --branch wip/<NNN>/<автор>
--worktree <путь>`: merge --no-ff identity оркестратора (016 И-1), приземление ИЗ основного
чекаута, main^2 == tip ветки. Порядок: приземляются ветки принятых агентов; между
приземлениями основной чекаут держится чистым (правки HANDOFF — после, Р5). Close-out:
`scripts/gc_agent_branches.sh` сносит слитые `wip/*`, зависшие СОХРАНЯЕТ и печатает владельцу
(016 И-6). Нового кода срез 3 не вводит — предмет в ПРОВОДКЕ существующих инструментов как
штатного шага режима.
