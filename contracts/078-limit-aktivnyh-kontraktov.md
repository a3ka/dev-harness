## Инварианты

1. **И-1 Определение и единый источник.** N активен ⟺ (∃ `refs/tags/frozen/contracts/N/*`
   на origin ∨ ∃ `refs/heads/wip/N/*` на origin) ∧ ¬∃ `refs/tags/done/contracts/N/*` на
   origin. NNN — ровно три цифры. Активные — МНОЖЕСТВО NNN, не сумма частей: N, лежащий
   и в frozen, и в wip, активен ОДИН раз (обход double_namespace критика 078 к2 —
   «уникальные внутри частей, сумма без дедупликации» — запрещён; предъявлен клеткой
   л5в и стабом Ж). Счёт живёт ОДНОЙ функцией `active_contracts_list` в
   `scripts/lib_active_contracts.sh` (печать активных NNN по строке в stdout; rc 0), её
   импортируют все три скрипта; переизобретение разбора в скриптах запрещено.
2. **И-2 Счёт по origin, fail-closed.** Источник — живой `git ls-remote origin` (три
   паттерна: frozen, done, wip). Локальные refs, теги и дерево для счёта не читаются.
   remote origin не настроен ИЛИ ls-remote отказал → rc 1 `ОТКАЗ: лимит активных
   контрактов: авторитет недоступен (<деталь>), данные неизвестны — fail-closed`
   (прецедент 068: имя отдельно от «лимит превышен»; обрыв сети — не санкция; при
   недоступном origin число и список активных НЕ выдумываются — И-9).
3. **И-3 Порог ≥2 → отказ до мутации.** `next_id.sh` (режим issue, класс CONTRACT) и
   `mint_line.sh`: активных ≥2 → rc 1 `ОТКАЗ: лимит активных контрактов: активных <N> ≥ 2:
   <NNN-через-запятую>` ДО первой мутации: next_id — тег не создан, номер не напечатан;
   mint_line — строка не записана, HEAD не двинут, дерево чисто. У next_id лимит стоит до
   вычисления максимума; у mint_line — после dual-control тега (шаг 3), до проверки
   манифеста (шаг 4).
4. **И-4 freeze: ≥2 не считая замораживаемого.** `freeze_contract.sh` для `dir=contracts`:
   активных минус NNN замораживаемого ≥2 → rc 1 тем же именем ДО создания тега (реестр и
   тег не тронуты). Лимит стоит после §3 (грамматика NNN), до §4 (закоммиченность);
   `plans/NNN-*.md` лимитом не судится (поведение байт-в-байт как до 078).
5. **И-5 Исключение — только строка владельца.** Литеральная подстрока
   `РАЗРЕШИЛ-ВЛАДЕЛЕЦ: сверх лимита` в причине снимает отказ: freeze — в `$2`;
   next_id — новый необязательный флаг `--reason <строка>` (ровно один, позиция — после
   `<КЛАСС>`: `next_id.sh [КОРЕНЬ] <КЛАСС> [--reason <строка>]`; второй `--reason` или
   лишний аргумент — прежний die-отказ грамматики argv); mint_line — новый флаг
   `--reason <строка>` в существующем while-парсере (один). Снятие печатает именованную
   строку в stderr: `  ok   лимит активных контрактов: снято строкой владельца, активных
   <N> ≥ 2: <NNN-через-запятую>` — число И множество NNN (И-9), хвост байт-в-байт как
   у отказа И-3. Печатается только при активных ≥2; ниже порога причина не читается и
   строка не печатается. Любая иная причина — в т.ч. содержащая `РАЗРЕШИЛ-ВЛАДЕЛЕЦ:` БЕЗ
   ` сверх лимита` — ничего не снимает. Сравнение — литеральная подстрока
   (case/grep -F), никогда regex/glob из значения (норма 037).
6. **И-6 done закрывает, резерв и замораживаемый не активны для счёта входа.** Тег
   `done/contracts/N/*` на origin вычитает N из активных. Тег `id/CONTRACT/N` (резерв)
   активным НЕ является (слово владельца: «номер из резерва без заморозки до реализации
   не доходит» — путь резерва перекрыт самим лимитом на mint_line/freeze, а не счётом).
   freeze вычитает ТОЛЬКО NNN замораживаемого (И-4).
7. **И-7 Область действия.** Только CONTRACT-жизненный цикл: классы PLAN/VERDICT/ADR,
   `--backfill`, `freeze plans/…` — байт-в-байт как до 078. `mint_line.sh` судится всегда
   (его предмет — только контракты).
8. **И-8 Неослабление соседей.** Атомарность и max+1 next_id (007), dual-control и дверь
   031 mint_line (068), реестр/вердикт/кап/гейты 036/038/027/043 freeze — не ослабляются;
   их отказы первичны по своим предметам, порядок вклинивания назван в И-3/И-4.
9. **И-9 Молчание запрещено на трёх исходах.** Отказ (И-3/И-4) и снятие строкой
   владельца (И-5) печатают именованную строку в stderr с числом активных и ТОЧНЫМ
   множеством NNN; хвост обеих форм — `активных <N> ≥ 2: <NNN-через-запятую>`
   (приёмка сверяет множеством, не маркером, на всех 14 клетках отказа И снятия).
   Недоступность (И-2) печатает именованную строку со словами `данные неизвестны` —
   без числа и списка: при недоступном авторитете значения неизвестны, а не ноль и не
   пусто. Прохождение ниже порога не печатает ничего (выдача молчалива, как до 078).

## Гигиена полей (норма 041)

Новый ввод — `--reason` у next_id/mint_line и причина `$2` freeze — поле СВОБОДНОГО текста
(человеческая причина), в замкнутый алфавит не переводится: единственная операция над ним —
литеральное сравнение с константой `РАЗРЕШИЛ-ВЛАДЕЛЕЦ: сверх лимита` (case-подстрока /
grep -F), построение regex/glob из значения запрещено (норма 037). Байт значения не
переиспользуется как разделитель/якорь нигде. Структурных полей с разбором предмет не
вводит: NNN уже несёт грамматика `[0-9]{1,3}` (mint_line) / `NNN-<slug>.md` (freeze, разбор
из next_id.sh). Self-application green-фикстуры парсящего класса не требуется: нового
парсера нет.

## Модель угроз

ЗАЩИЩАЕТ:
- открытие третьего контракта при двух живых: каждый из трёх входов — своя ветвь отказа
  с числом и списком NNN активных, до первой мутации (тег/строка/HEAD не тронуты);
- расхождение локального дерева и origin: счёт только по живому ls-remote — новые
  frozen/wip/done на origin видны без fetch, отложенный fetch-отражение не прячет активность;
- обрыв сети/отсутствие remote как способ обойти лимит: fail-closed именованным отказом;
- обход «почти правильной» строкой: `РАЗРЕШИЛ-ВЛАДЕЛЕЦ:` без ` сверх лимита`, строка в
  другом аргументе, не в причине — отказ остаётся;
- ложный отказ на закрытом контракте: done-тег вычитает N; резерв (id-тег) не считается;
  freeze не считает сам замораживаемый (вторая версия заморозки не блокирует сама себя);
- задним числом 075–079: стоят — не судятся, не отменяются.
НЕ ЗАЩИЩАЕТ:
- злонамеренный оператор: правка scripts/*, снятие remote в живом дереве, подмена веток
  руками — ловец check_zones/check_charter/CI пост-фактум (прецедент 071);
- параллельные независимые клоны, выдающие номер до пуша тега (граница «гоночный клон»
  next_id, измерена адверсарием) — закрывается сверкой при слиянии, не лимитом;
- wip-ветки вне схемы `wip/NNN/*` (детектор 077-класса — вне объёма 078);
- потолок по ЗАДАЧАМ (не контрактам): 078 судит только контракты.
