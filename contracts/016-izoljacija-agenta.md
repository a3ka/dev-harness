## Предмет

Четыре среза; срез 1 ⊥ {2,3,4}, срез 3 — последним (ему нужны ветки среза 2).

**Срез 1 — барьер add-A (Q1): маски + pre-commit судья staged-путей.**
`scripts/check_staged.sh <корень>`: судит STAGED-множество ДО коммита. Автор —
локальный `user.name` коммитящего; зоны — объединение ЗОНА-строк автора из замороженных
контрактов, ЕДИНОЙ реализацией с `check_zones.sh` (чтение зон выносится в
`scripts/lib_zones.sh`; потребители импортируют ОДНУ функцию — второй список путей
запрещён; правка `check_zones.sh` — только эквивалентный рефакторинг, замороженные ветви
не меняются). Ветви:

- staged-путь вне зон автора → rc 1 «вне зоны: <путь>» — несущая проверка;
- control-символ (U+0000–U+001F, U+007F) в ИМЕНИ staged-пути → rc 1 «имя с
  control-символом: <путь>» — ловится и ВНУТРИ зоны (факт 0171f1b: имя-обрывок
  «открытые с адресами:\n»);
- staged пуст → rc 0 «нечего судить»; автор не объявлен ни в одной заморозке → rc 0
  «не судится» (семантика check_zones: владелец и прошлые сессии не проверяются);
- маски корневого скратча (`/out*.txt` у корня, факт 0171f1b) — слой `.gitignore`,
  НЕ ветвь судьи: различимого входа нет (корень — ничья зона, «вне зоны» ловит то же
  самое; Н-39 — ветвь без собственного входа не заводится).

Установка: `core.hooksPath` → коммиченный `.githooks/` — НЕ уставная правка (Q6),
приезжает норма-коммитом. `check:hooks` в CI проверяет МЕХАНИЗМ установки
(`scripts/check_hooks.sh <корень>`: .githooks/pre-commit коммичен и исполняем; ведёт к
судье scripts/check_staged.sh; установщик core.hooksPath коммичен в package.json), НЕ
рантайм-наличие. Пределы хука — cognitive-only остаток, назван дословно (Q1): `--no-verify`
обходит; «git commit -- <пути>» формально проходит; на неустановленном хуке защиты нет;
свежий worktree от коммита ДО появления .githooks — хука тихо нет. Хук — не жёсткий гейт:
несущая проверка — путь-против-зоны, маски — удобство.

**Срез 2 — спавн: `scripts/spawn_agent.sh`.** Ветка `wip/<NNN>/<автор>` от main +
`git worktree add` ВНЕ стерегомого дерева (checkout из git-объектов — reflink-walker omp

Cognitive-only, названо прямо: попадание агента в worktree — инструкция в задании,
omp-принуждения нет (ловцы — срез 3 и §6.5).

**Срез 3 — приземление: `scripts/land_agent.sh`.** Приёмка исполняется В worktree;
предмет обязан быть в HEAD worktree — иначе отказ (наблюдаемое отношение HEAD к базе
ветки, И-8). Грязный главный чекаут на приземлении → rc 1 «главное дерево загрязнено

**Срез 4 — GC: `scripts/gc_agent_branches.sh`.** Слитые `wip/*` — авто-снос; зависшие —

### Инварианты (каждый с rc-командой)

- **И-1** агентский коммит не достижим из main минуя merge-коммит; merge приземления
  исполняет САМ ВЫЗОВ `land_agent.sh` — наблюдается ПЕРЕХОД, не состояние журнала:
  зелёный case scope пинует ДО вызова `main_before` (rev-parse main) и `tip`
  (rev-parse ветки); заранее построенного merge в фикстуре НЕТ. После вызова с rc=0
  обязаны выполняться все четыре сверки: main != main_before (main сдвинут вызовом);
  main^1 == main_before (ровно один first-parent шаг); main^2 == tip (второй
  родитель — приземляемая ветка); `git log -1 --format=%cn main` == orchestrator
  (identity результата). Валидатор чужого merge попадает в вилку без выхода:
  заранее построенного merge нет — валидировать нечего (rc≠0 на зелёном case), либо
  он «проходит», не сдвинув main (main == main_before — сверка красная); создать
  merge может только сам вызов. Пределы (cognitive-only): провенанс ИСТОРИЧЕСКИХ
  merge живого журнала — committer подделываем `-c`, журналом не различим
  (ужесточение — подписи/серверный контроль — слово владельца, класс записан в
  шапке check_zones); внутренний способ построения merge скриптом не судится —
  судится эффект вызова. rc: `bash
  scripts/verify_antiplacebo.sh . --scope land_agent` (case_kommit_mimo_merge:
  агентский коммит прямо на main; case_merzh_ne_orkestrator: committer merge-коммита
  приземления — не orchestrator).
- **И-2** staged-множество вне зон / с control-символом в имени отвергается ДО коммита.
  rc: `bash fixtures/check_staged/probe_check_staged_krasnyj.sh` (сейчас rc=1) и scoped
  `--scope check_staged` (после реализации rc=0).
- **И-3** замороженные теги достижимы и неизменны по блобу после КАЖДОГО приземления.
  rc: scoped `--scope land_agent` + охрана `--scope check_contract_frozen` → rc=0.
- **И-4** после приземления веток `wip/<NNN>/<автор>` нет в `for-each-ref`. rc: scoped
  `--scope land_agent` (case_vetka_perezhila) и `--scope gc_agent_branches`.
- **И-5** grep-канарейка identity (образец CT-I-1 референса): вне комментариев — ни
  одного вызова `git … commit` / `git … merge …` в `scripts/` без `-c user.*=`/GIT_* в
  той же строке (merge-base — чтение, не судится; аннотированные теги next_id несут
  env-зависимость по контракту Н-61 — выдача зовётся с env-identity, канарейкой не
  судятся). Пустота меры доказывается КОДОМ ВОЗВРАТА: rc=0 когда пусто, rc≠0 когда
  найдено (нарушение печатается дословно):
  ```
  ! grep -rnE '\bgit\b[^|<>]*[[:space:]](commit|merge)[[:space:]]' scripts/ | grep -vE ':[0-9]+:[[:space:]]*#' | grep -v merge-base | grep -vE 'user\.(name|email)=|GIT_(AUTHOR|COMMITTER)_(NAME|EMAIL)' | grep .
  ```
  Замер этой пачки: живое дерево → rc=0 (мера пуста; найденные первой строкой
  вхождения несут явную identity и отфильтрованы). Красный вход меры — toy-дерево с
  `scripts/bypass.sh`, где есть буквальный вызов `git commit` без identity: команда
  обязана напечатать эту строку и вернуть rc≠0 (прогоны этой пачки — дословно в отчёте).
- **И-6** GC удаляет слитые; несбитые СОХРАННЫ наблюдаемо — ТОЖДЕСТВО ЦЕЛИ, не только
  имя: фикстура пинует `oid_before` каждой несбитой ветки ДО вызова GC, и после
  прогона `git rev-parse` обязан вернуть ТОТ ЖЕ OID — любая смена цели ref
  равносильна сносу и красна одной сверкой (результат-форма: способы смены цели не
  перечисляются). При наличии зависших веток каждая остаётся в `git for-each-ref` и
  поимённо названа в СПИСКЕ владельцу (симметрия Н-59: молчание ≠ разрешение);
  удаление зависшей — только слово владельца; sweep видит fifo (python-lstat).
  Пределы (cognitive-only): update-ref МИМО GC в живом репо git'ом не запрещён и
  этим инвариантом не судится (живая дисциплина — не предмет фикстурного критерия);
  прореживание объектов `git gc`/`prune` — не предмет 016. rc: scoped `--scope
  gc_agent_branches` (case_zavisshaja_snesena: несбитая ветка пропала из
  for-each-ref после прогона GC; case_zavisshaja_peredvinuta: имя живо — ветка
  напечатана в СПИСКЕ, — а OID сменился → сверка тождества красная).
- **И-7** грязный main на приземлении → rc 1 (§6.5-2). rc: scoped `--scope land_agent`
  (case_gryaznyj_main).
- **И-8** приёмка-OK-без-ветки красная: приземление отказывает, если приёмка зелёная, а
  предмета в HEAD worktree нет (§6.5-1). rc: scoped `--scope land_agent`
  (case_priyomka_bez_vetki).
- **И-9** identity (Q3): каждый агент коммитит `-c user.name=<роль>`; общий `.git/config`
  НЕ несёт дефолтного user.name (при пачке: пусто); worktree ШАРИТ общий конфиг — коммит
  без явной identity падает «empty ident» (§6.3-5, Н-56/Н-61-класс). Соответствие имени
  роли наблюдаемо СЦЕПКОЙ ПАРЫ ПОЛЕЙ на приземлении — приземление отказывает rc 1 ДО
  merge поимённо: (1) «identity расщеплена: <sha> author=<имя> committer=<имя>», если
  у какого-либо коммита приземляемого диапазона committer != author (`--no-verify` не
  помогает: проверка живёт в land_agent, не в хуке); (2) «имя вне реестра ролей:
  <имя>», если committer не входит в реестр авторов замороженных контрактов — тот же
  список, что собирает check_zones (единая реализация lib, второй реестр запрещён).
  Сцепка+реестр делают поле check_zones (author) тождественным полю И-9 (committer)
  по построению — расцепка «два судьи по разным полям одного коммита» закрыта;
  merge-коммит самого скрипта сцепку выполняет автоматически (обе identity — зашитый
  orchestrator). Риск назван: дефолт, однажды внесённый в общий конфиг, подписывает
  ВСЕ worktree одним именем (hft-провал «14 worktree все подписаны reviewer»).
  Предел (cognitive-only): ИСТИННАЯ роль процесса не судится — identity
  самообъявлена; назвавшийся чужой ролью ЦЕЛИКОМ (committer == author) ловится
  только пересечением путей с зонами; ужесточение — подписанные коммиты со сверкой
  ключа и имени — слово владельца (шапка check_zones). rc: `git config --local
  user.name` → пусто; scoped `--scope spawn_agent` (case_bez_identichnosti) и
  `--scope land_agent` (case_imja_vne_reestra; case_identity_rasscheplena: коммит
  диапазона с чужим `--author` — committer != author → rc 1 «identity расщеплена»).
