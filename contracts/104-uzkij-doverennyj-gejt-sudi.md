## Решения

1. **Пин установки — расположение расширения.** `spawn-guard.ts` читает `<dirname(import.meta.url)>/../../config/agent_models.json` (прецедент gate-draft/startup-digest). `process.cwd()`, `HARNESS_TOOLS_ROOT` и любой другой env/аргумент источником НЕ являются (cwd — проект; env — наследуется и подделывается ребёнком). Файла нет/не читается/без `roles` → `{block:true, reason:"ОТКАЗ: конфиг установленного харнеса не читается: <путь>"}` на КАЖДОМ `task`-вызове (fail-closed, не bootstrap-пропуск); чужие инструменты не трогаются. Остальная семантика хука — дословно 099 (замеры 1–3 арбитража; `task` вне алфавита; batch/flat; битый вход → «спавн-страж сломан (fail-closed, Н-270)»).
2. **Грамматика трассы с привязкой — проекция-надмножество единого источника.** `models_actual.sh --tsv --bind` печатает `роль TAB модель TAB allowed|denied TAB <session-id> TAB <object-sha|->`: первые три поля — байт-в-байт строки `--tsv` (095, make_task не трогается); `<session-id>` — basename JSONL сессии без `.jsonl` (тот же примитив, что в норме 037); `<object-sha>` — значение первой строки `^OBJECT=[0-9a-f]{40}$` (якорь `^…$`, флаг /m — грамматика пар 066) в тексте задания сессии, иначе `-`. Алфавиты (041): session-id — `[A-Za-z0-9._-]+`; object — ровно 40 hex или `-`; TAB внутри значений невозможен по построению (basename без TAB — иначе строка отбрасывается с rc 2).
3. **Нога `--verdict <роль> --trace <tsv> --object <sha> --session <id> [--root]`.** `--object`/`--session` ОБЯЗАТЕЛЬНЫ (без них — usage rc 2). Строки роли отсутствуют → rc 1 «ОТКАЗ: трасса без строки роли: <роль>»; строка роли без 4-го/5-го поля → rc 2 «трасса без привязки (нужно 5 полей)»; для КАЖДОЙ строки роли (литеральные сравнения, 041): `session ≠ --session` → rc 1 «ОТКАЗ: чужая трасса: сессия <s>, суд <id>»; `object ≠ --object` → rc 1 «ОТКАЗ: трасса не об объекте суда: <o>, суд <sha>»; `allowed` ∧ модель ≠ `models[tiers[roles[роль]].model]` → rc 1 «ОТКАЗ: вердикт не материализуется: судья <роль> на модели <m>, тир <t> (Н-270)»; `denied` ∧ модель ≠ `models[tiers[…].fallback]` (или fallback `null`) → rc 1 «ОТКАЗ: фолбэк вне списка тира: <роль> на <m>, тир <t> (Н-270)»; иначе rc 0 «СУДЬЯ СВОЕЙ МОДЕЛИ: вердикт <роль> материализуется». Ноги `--spawn`/`--frontmatter` — из 099 без изменений. Override модели закрыт: источник ожиданий — только `--root/config/agent_models.json` (по умолчанию установка = `SELF_DIR/..`), флага «ожидаемая модель» нет.
4. **Потребитель — `judge_gate.sh <sha> --verdict-row <задача> <object_id> <вердикт-файл> --sud <роль> <трасса> <session>`.** Перед записью строки зовёт соседний `check_sud_model.sh --verdict <роль> --trace <трасса> --object <sha> --session <session>` (порядок аргументов литерально этот); rc двери ≠ 0 → строка НЕ пишется, rc двери пробрасывается (1 → 1 с причиной двери на stderr, 2 → 2); тройка `--sud` отсутствует → rc 1 «ОТКАЗ: свидетельство судьи не передано (--sud <роль> <трасса> <session>)», строка не пишется. 5-аргументная форма 098 перестаёт быть зелёной: клетки `fixtures/dokazatelstva_098/` получают тройку `--sud` с честной toy-трассой одной правкой `_mir.sh` (ПЕРЕСЕЧЕНИЕ, §Зоны). Режимы `<sha>` (008) и `--policy-row` не трогаются.
5. **Поведенческие нормы — role-каналом** (`roles/orchestrator.md`): задание судьи несёт строку `OBJECT=<sha объекта суда>` (без неё трасса не привязывается — вердикт не материализуется); трасса для `--sud` строится `models_actual.sh --tsv --bind` ПОСЛЕ завершения судьи; подкладывать трассу другой сессии запрещено (механизм — И-4).

## Демаркация контрпримеров

Конформные входы: роли-судьи ∈ {critic, adversary, reviewer, arbiter}; модель — непустая строка алфавита латиница/цифры/`-._/`; трасса — строки `роль TAB модель TAB allowed|denied TAB session TAB object` (session `[A-Za-z0-9._-]+`, object 40 hex или `-`); sha — 40 hex; события хука — `{type:'tool_call', toolName, toolCallId, input}` с `input.tasks[]`-элементами `{name, agent, task}` или flat `{name, agent, task}`; установка — каталог с `.omp/extensions/spawn-guard.ts` и `config/agent_models.json` грамматики `models/tiers{model,fallback}/roles`. Валидный контрпример = реализация, инвариантная к значениям (любые имена ролей/моделей/сессий конформной грамматики), расходящаяся с инвариантом на КОНФОРМНОМ входе. Неконформное (TAB в значении, 39 hex, роль вне алфавита) — rc 2 fail-closed, контрпримером не является.

## Модель угроз

ЗАЩИЩАЕТ:
- подмену алфавита ролей проектом: источник — файл установки по расположению расширения, cwd и env не читаются (И-2, И-5);
- «тихий дефолт» судьи на `task`-тире (Н-270): резолвнутый `agent` ∉ алфавита без `task` → блок ДО исполнения (И-1);
- материализацию вердикта чужой сессии или о чужом объекте при верной модели: литеральная сверка session/object (И-4, И-3б);
- судью на модели не тира и на фолбэке вне объявленного владельцем списка `tiers.<тир>.fallback` (И-3б);
- запись verdict-строки без свидетельства или вопреки отказу двери (И-6).

НЕ ЗАЩИЩАЕТ:
- сессии проекта, в которые лаунчер не загрузил расширение (П-107), и `--no-extensions`;
- подделку JSONL сессии в зоне вне дерева (граница доверия 028: зона — доверенная сторона);
- компрометацию самой установки харнеса (кто правит `config/agent_models.json` установки — владеет алфавитом);
- содержательную силу вердикта: судится модель/сессия/объект, не качество суждения.
