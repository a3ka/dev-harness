security-кластер). Заморозка — после круга критика.

## Предмет — измеренная боль, а не пересказ

`scripts/check_protected.sh:81` ставит доверенный PATH (`export PATH=/usr/bin:/bin`, закрытие
PATH-spy адверсария круга 1 контракта 039), но PATH — НЕ единственный способ разрешения ИМЕНИ
команды: bash разрешает ФУНКЦИИ раньше `$PATH`, а экспортированная функция переживает старт
любого дочернего bash сериализацией `BASH_FUNC_<имя>%%=() {…}` (механизм Shellshock). Барьер
считает решающую разность ОДНОЙ строкой — `comm -23 "$TMP/existed" "$TMP/head"` — и его же шапка
называет `comm` прямо: «та самая утилита, чей подмен даёт зелёное без ALLOW».

Живой репродюсер этой пачки (`/tmp/dev-harness-verify/scratch/arch046/repro-n130-check-protected.sh`,
ожидания в ПАМЯТИ проверяющего, сверка по rc И по подстроке отказа), toy-дерево формы
`fixtures/check_protected/_repo.sh`, `plans/001-p.md` удалён коммитом БЕЗ строки
`ALLOW-ARTIFACT-DELETE`, барьер СЕГОДНЯШНИЙ:

```
A. чистое дерево, чистое окружение          rc=0  причина_напечатана=0
B. удаление, чистое окружение               rc=1  причина_напечатана=1
C. удаление + тень comm                     rc=0  причина_напечатана=0   ← ОБХОД
D. удаление + тени unset и comm             rc=0  причина_напечатана=0   ← ОБХОД
расхождений: 2
```

Цена в терминах предмета барьера: защищённый артефакт исчезает из истории БЕЗ единой строки
разрешения, а гейт отвечает `rc=0` и не печатает ни одной строки `FAIL` — без записи в
`/usr/bin:/bin`, без root, без подмены `/usr/bin/git`. Это ровно та категория обходов, которую
арбитраж 040-II оставил открытой для будущих кругов (категория (i)).

ВТОРОЙ, НЕОЧЕВИДНЫЙ УЩЕРБ, найден замером этой же пачки: лечение (re-exec через `env -i`) стирает
и ИЗМЕРИТЕЛЬНЫЕ переменные вызывающего, а постоянный CI-страж call-budget
`fixtures/check_protected/red_predel_git_vyzovov_ours.sh` (контракт 040, §Приёмка Р2) считал
git-вызовы через `SHELLOPTS=xtrace BASH_XTRACEFD=9`. Замер на живой паре (тот же toy, тот же
файл стража):

```
сегодняшний барьер:   git-подпроцессов LOW=29, HIGH=29 → "ПРЕДЕЛ ДЕРЖИТСЯ: LOW=29<=30", rc=0
пофикшенный барьер:   git-подпроцессов LOW=0,  HIGH=0  → "ПРЕДЕЛ ДЕРЖИТСЯ: LOW=0<=30",  rc=0
```

То есть без второй части предмета фикс превратил бы живого стража в молчаливо-зелёного: страж
перестал бы отличать предмет контракта 040 от его полного отсутствия. Поэтому предмет 046 — ДВЕ
неразделимые части: герметичное окружение барьера И перевод его измерительного канала на
внешнюю трассировку, переживающую `env -i`.

## Frontier: варианты и оправдание болью

- **В-1. `unset -f <перечень доверенных имён>` сразу после PATH-пина.** ОТВЕРГНУТ — не вкусом, а
  измерением на близнеце: эта редакция жила в `check_zones.sh` один круг и пала
  (`verdicts/adversary/contracts-040-v5-circle.md`, `d46a615`) от экспортированной функции
  `unset`, no-op'ящей ИМЕННО `-f`-форму. Сам `unset` в перечень войти не может: перечень есть
  то, ЧЕМ снимают. Перечисление структурно не сходится — следующее отравленное имя (`printf`,
  `[`) открывает ту же дыру заново. Предъявление живёт в дереве отдельной фикстурой
  (`case_ten_funkcii_unset_comm.sh`), чтобы В-1 нельзя было внести «как проще».
- **В-2. Абсолютные пути (`/usr/bin/git`, `/usr/bin/comm`, …) во всех вызовах.** ОТВЕРГНУТ:
  дороже (правка каждого call-сайта, вечный долг на каждую новую строку), хуже читается И НЕ
  закрывает класс — bash допускает функцию с ЛИТЕРАЛЬНЫМ слэшем в имени, объявляемую через
  сорсинг `BASH_ENV` (арбитраж 040-III, векторы D/E).
- **В-3. `env -i` re-exec ДО первой строки кода, со сверкой по `/proc/$$/environ`.** ПРИНЯТ —
  лечение по прецеденту, не изобретается заново: `scripts/check_zones.sh:119-207` (контракт 040,
  редакции v6/v7) и `scripts/check_provodka.sh` (контракт 038, круг 9, арбитраж
  `038-vrazhdebnaja-sreda-zapuska.md`) несут ровно эту форму, прожитую кругами адверсария.
  Закрывает ВЕСЬ класс «унаследованная экспортированная bash-функция с ЛЮБЫМ именем» без
  перечисления: дочернему bash нечего импортировать.
- **В-4. Ничего не менять в барьере, вызывать его доверенно (`env -i … bash check_protected.sh`).**
  ОТВЕРГНУТ как ЕДИНСТВЕННАЯ мера: перекладывает защиту на каждого вызывающего (CI-шаг, дрилл,
  `check_spec_ready`, человек), то есть держится памятью, а не механизмом. Как ДОПОЛНЕНИЕ к В-3
  остаётся честным усилением и названо в §Риски.
- **НЕ ВХОДИТ В ПРЕДМЕТ** (класс назван прямо, чтобы круги его не переоткрывали): «враждебное
  ОКРУЖЕНИЕ ВЫЗОВА» — `BASH_ENV`/`ENV`, slash-именованные функции, `SHELLOPTS`, сорсинг —
  структурно незакрываем изнутри скрипта (арбитраж 040-III
  `contracts-040-vrazhdebnoe-okruzhenie-predel.md`: `BASH_ENV` с `exit 0` даёт rc=0 на ВСЕХ
  формах гарда); подлинность вывода `git` при живом PATH (арбитраж 040-II, три замера);
  `user.name` как удостоверение; правка `scripts/check_zones.sh` (там класс уже закрыт).

## Инварианты (механизм: блок «ГЕРМЕТИЧНОЕ ОКРУЖЕНИЕ» в `scripts/check_protected.sh`)

Грамматика и числа — ЕДИНЫЙ источник этот контракт; реализация несёт названные литералы
ПОБАЙТОВО.

1. **Блок стоит ДО ЛЮБОЙ ДРУГОЙ СТРОКИ КОДА** — раньше `set -euo pipefail`, раньше
   `unset GIT_DIR …`, раньше `export PATH=…`. Любая строка кода выше блока исполняется в
   отравленном процессе.
2. **Решение о re-exec принимается по ФАКТИЧЕСКОМУ окружению процесса** (`/proc/$$/environ`,
   `tr '\0' '\n'`), а НЕ по флагу-часовому вида `[ -z "$REEXECED" ]`: часовой выставляется
   вызывающим заранее (класс закрыт на соседнем барьере — `check_no_leak.sh`, адверсарий к5,
   `4dfc0ff`).
3. **Allowlist — РОВНО две переменные, `PATH` и `LC_ALL`, в этом порядке**, и строка сравнения
   несёт ровно их: `$'PATH=/usr/bin:/bin\nLC_ALL=C.UTF-8'`. Порядок обязан совпадать с порядком
   аргументов `env -i` (иначе вечный re-exec). `HOME`/`TMPDIR` НЕ протаскиваются: ни одна строка
   барьера не читает `$HOME`, скратч — явный путь с каталогом (`$ROOT/tmp/protected.XXXXXX`).
4. **`POSIXLY_CORRECT=1` — отдельной строкой ВЫШЕ `exec`** (присваивание функцией не
   перехватывается и включает POSIX-режим, где `exec` — special builtin раньше пользовательской
   функции; арбитраж 040-III, вектор H). `env` и `bash` зовутся АБСОЛЮТНЫМИ путями.
5. **`export PATH=/usr/bin:/bin` остаётся на месте** (строка 81 сегодня) — вторичная защита и
   побайтовое diff-сравнение с прецедентом; `unset -f`-перечисления в файле не появляется НИ
   ОДНОГО (В-1 отвергнут).
6. **Решающая логика барьера не меняется ни байтом**: область из `roles/*.md`, `existed`/`head`,
   `comm -23`, `excuse_for`, оракул `merge-tree`, тексты `bad()`/`ok()` — байт-в-байт. Предмет
   046 — окружение процесса, а не семантика защиты.
7. **Измерительный канал стража call-budget переживает re-exec.** `run_trace` в
   `fixtures/check_protected/red_predel_git_vyzovov_ours.sh` — внешняя `strace -f -e trace=execve`
   (форма и счётная строка ПОБАЙТОВО с близнеца `fixtures/check_zones/red_predel_git_vyzovov.sh`,
   ревью-круг 040 `b38e78a`), плюс fail-closed проверка живости меры: `CALLS_LOW>0 ∧ CALLS_HIGH>0`,
   иначе именованный отказ. Ноль вызовов — КРАСНОЕ, а не зелёное. (Приземлено architect'ом ДО
   заморозки, см. §Зоны.)
8. **Ни одна из 25 существующих `case_*.sh` семьи не правится, не удаляется и не
   переименовывается** — добавление новых легально (§Приёмка Р3).

## Модель угроз

ЗАЩИЩАЕТ:
- унаследованная экспортированная bash-функция с ИМЕНЕМ ЛЮБОЙ утилиты, которую барьер зовёт
  голым именем (`comm`, `git`, `sort`, `awk`, `grep`, `mktemp`, `mkdir`, `rm`, `tr`, `sed`, `wc`,
  `dirname`) — структурно, без перечисления имён;
- рекурсивная тень самого средства нейтрализации (`unset`, `command`, `builtin`) — их таблица в
  дочернем процессе пуста по построению, снимать нечего;
- подделка часового re-exec заранее выставленной переменной окружения вызывающего;
- унаследованные `GIT_*` и конфиг вызывающего как канал подмены предмета (сохранено из 039 плюс
  стёрто целиком границей `env -i`);
- молчаливая смерть измерительного канала стража call-budget: ноль вызовов даёт именованный
  отказ, а не тривиально проходящую границу.

НЕ ЗАЩИЩАЕТ:
- вызывающего, управляющего интерпретатором ДО первой строки барьера (`BASH_ENV`/`ENV`,
  slash-именованная функция на `/usr/bin/env`, сорсинг барьера в отравленную оболочку) —
  структурно незакрываемый класс, решение арбитража 040-III, закрытие существует только в
  доверенном ВЫЗОВЕ барьера;
- подлинность вывода `git` и прочих утилит при живом доверенном PATH (подмена `/usr/bin/git`
  через root или скомпрометированный пакет) — граница доверия, а не арифметика вывода;
- `user.name` как удостоверение автора коммита (остаток, наследуемый из 039/040);
- отсутствие `procfs` (не-Linux): сверка окружения опирается на `/proc/$$/environ` — тот же
  принятый риск, что уже несут `check_zones.sh` и `check_provodka.sh`;
- старые `case_*.sh` семьи `check_protected` — их полярность этим контрактом не пересматривается.

## Риски (named residual)

1. **Класс «враждебное окружение ВЫЗОВА» остаётся открытым** (§Модель угроз, арбитраж 040-III):
   `BASH_ENV` с `exit 0` даёт rc=0 на ЛЮБОЙ форме внутрискриптового гарда. Закрытие существует
   ровно в одной точке — вызове барьера доверенной стороной как
   `env -i PATH=/usr/bin:/bin LC_ALL=C.UTF-8 bash scripts/check_protected.sh` — это цена и воля
   ВЛАДЕЛЬЦА, а не предмет кругов 046.
2. **`/proc/$$/environ` — Linux/procfs.** На не-Linux сверка окружения не работает; тот же
   принятый риск, что уже живёт в двух соседних барьерах. Ловец — не барьер, а среда проекта.
3. **Страж call-budget измеряется только в CI** (локально `rc=2`, strace нет). Локальный прогон
