## Инварианты (каждый — rc-командой; красное — §Приёмочный критерий)

**М1. Извлечение пина, новый CLI-режим.** `node path-guard.ts --extract-pin '<текст>'` →
одна строка JSON `{"worktree":"<абс>"|null}`, rc 0; rc 2 — сломанный вход. Пин извлекается
⟺ ОДНОВРЕМЕННО:

1. в тексте РОВНО ОДНА spawn-пара: токен `WORKTREE=<абс>` и токен
   `BRANCH=wip/<NNN>/<автор>` (токен начинается в начале строки или после `:`/`;`/`,`
   с возможным пробелом; значение WORKTREE — непробельный АБСОЛЮТНЫЙ путь, BRANCH — по
   грамматике ветки). Две и более пары → null: мульти-контрактный промт оркестратора
  (032+033 в одном тексте) НЕ пинится прозой — консервативный отказ;
2. spawn-форма согласована: `basename(<путь>) == wip-<NNN>-<автор>` (spawn_agent.sh:257);
3. путь — ЖИВОЙ linked worktree, ВСЕ три условия: `<путь>/.git` существует; это ФАЙЛ;
   его содержимое — строка формата `gitdir: <путь>`; ЦЕЛЬ gitdir существует на диске.
   Отсутствие `.git`, `.git`-каталог, мусорное содержимое `.git`-файла и несуществующая
   цель gitdir — четыре РАЗНЫХ отрицательных входа, каждый даёт null (п4, п4а, п4б, п4в).
   Привязка «worktree ЭТОГО репо» отвергнута сознательно: пин в чужой worktree
   не даёт сессии НИЧЕГО из нашего дерева (main-чекаут остаётся вне пина), а привязка по
   корню расширения ломает игрушечные репо фикстур — остаток назван в §Остаточный риск.

Нарушение любого → null → сессия unpinned, fail-closed 025 дословно.

**М2. Per-session пин фабрики.** `register()` на `session_start`/`session_branch`/
`session_tree` восстанавливает пин из ПЕРВОЙ user-записи `ctx.sessionManager.getBranch()`
(role == 'user') по грамматике М1; хранит ПО session_id (`ctx.sessionManager
.getSessionId()`; процесс держит несколько сессий — omp://extensions.md «registries are
process-wide», модульная переменная без ключа = перенос пина между сессиями, запрещено).
КАЖДОЕ из трёх lifecycle-событий — самостоятельный источник восстановления: пин обязан
подниматься и на session_branch, и на session_tree сессии, у которой НЕ БЫЛО
session_start (п12). `tool_call` судится с пином = `call.worktree` → `env.WORKTREE` →
пин-задания; приоритет наблюдаем на фабричных конфликтах источников, включая событие
против env (п13–п15). Только ПЕРВАЯ user-запись: поздний steering роли user НЕ
перепинивает (п9). Для пина-из-задания сверка с `actual` НЕ применяется (actual процесса

пина из события/env сверка 025 C-1 (realpath, «не существует», «не совпадает») — без

## Остаточный риск (назван прямо)

- **Main-сессия с РОВНО одной парой в промте** (оркестратор ведёт один контракт и цитирует
  пару дословно) может быть запинена в чужой wip: её прямые записи в main-чекаут краснеют
  (замечено немедленно), штатный выход — plumbing (уже норма дня). Ловец — живой прогон;
  альтернатива — маркерная строка задания (развилка 3).
- **Пин в чужой/сторонний worktree** (живой linked worktree чужого репо): сессия получает
  запись ТОЛЬКО туда, из нашего дерева — ничего; main-чекаут вне пина.
- **Symlink внутри пина/скратча** — как сегодня (угроза «спутанный агент», не adversary;
  plumbing-канал существует и гардом не судится — граница модели угроз 025 дословно).
- **Пин не аутентифицирует роль**, только путь; суд ролей — зоны/стражи, как сегодня.
- **Граница модели угроз (АРБИТРАЖ d2ffb8e)**: страж судит tool_call агента в среде,
  поднятой не им; старт процесса (PATH/бинарники/задание) — данность; страж НЕ песочница
  (замер 4).
