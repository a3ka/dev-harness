## Инварианты (кодовые)

- **И-1 (окно = своя ветка/ленды).** Судимое множество окна контракта NNN =
  прямые не-merge коммиты диапазона `frozen/contracts/<NNN>/<v>..HEAD`
  (последняя живая заморозка, прежний примимет п2) ∪ коммиты, принесённые
  merge'ями с первой строкой (`%s`) `land: wip/<NNN>/…`; коммиты, принесённые
  ЧУЖИМИ лендами (`land: wip/<OTHER>/…`), из окна ИСКЛЮЧАЮТСЯ
  (`rev-list <merge>^1..<merge> --no-merges` по каждому чужому merge — тот же
  родительский примитив, что check_zones); merge без маркера — внутренний,
  НЕ исключается.
- **И-2 (покоммитная тронутость, не диапазон и не конечный дифф).**
  Зарегистрированный писатель считается тронутым ⟺ хотя бы один коммит
  судимого множества менял блоб его пути (diff-tree по коммиту): правка
  писателя своим коммитом с последующим возвратом исходного содержимого другим
  своим коммитом окна — писатель ТРОНУТ, проба обязательна (окно — множество
  коммитов своей ветки, трогавших писателя, а не дифф endpoints). Непустота
  конечного диффа тег..HEAD в предикат не входит; линейный endpoint-diff
  диапазона больше не применяется ни к одному писателю.
- **И-3 (дверь не ослаблена).** Для тронутых по И-1/И-2 писателей п3 (пробы
  исполнения) и п1-b (замер-строка) неизменны, с дословными фразами отказов;
  vacuous-ветви (нет consumers.d / нет frozen-тега / нет тронутых писателей) —
  rc 0 как сегодня.
- **И-4 (именованные отказы, fail-closed окна; ошибка ≠ пустое множество).**
  Отказ git-инструмента добычи судимого множества (rev-list/log/diff-tree
  окна: ref-граница не разрешается в объекты, диапазон невалиден) — именованный
  отказ rc 1 дословной фразой «потребители 116: список судимых коммитов окна
  недоступен», не тихая пустота (Б2 038: отказавший инструмент не должен
  давать vacuous rc 0). Законно пустое множество — ДРУГОЙ исход: коммиты окна
  добыты успешно и писателей не трогали → vacuous rc 0 (И-3); отказу добычи
  запрещено маскироваться под этот исход.

## Модель угроз

ЗАЩИЩАЕТ:
- окно контракта NNN не приписывает контракту правки зарегистрированного писателя, принесённые ЧУЖИМИ лендами `land: wip/<OTHER>/…` — ложная атрибуция (боль 056/058/059) закрывается механизмом, не дисциплиной.
- собственные правки писателя (хребет, свой ленд) по-прежнему требуют замер-строку и зелёные пробы каждого потребителя — дверь не ослаблена (И-3).
- отказ инструмента добычи окна — именованный rc 1, не пусто-зелёный (И-4; класс Б2 038); законно пустое окно остаётся vacuous rc 0 (И-3) — исходы различены механизмом, не дисциплиной.
- грамматика маркера не расползается: одна форма, побайтово из check_zones (Граница-1).

НЕ ЗАЩИЩАЕТ:
- подмену git в доверенном PATH (TCB-класс 040-II/III — тот же остаток, что у check_zones; закрытие — вызов `env -i` доверенной стороной, не предмет 062).
- подлинность автора коммита (`user.name` — не удостоверение; остаток check_zones, там же лечение).
- ленд с ПОДДЕЛАННЫМ своим маркером `land: wip/<NNN>/<автор>` (чужая работа, замаскированная под свою ветку) — предмет ревью ленд-двери (accept_task_commit/land_agent), не гейта окна; гейт честно судит принесённое как своё.
- merge без маркера, принесший чужую работу, — судится как внутренний по грамматике check_zones (та же семантика, сознательно).

Самоприменение (норма 041): гард 062 чужой ввод заново не парсит — маркер
ленда читается из subject git `%s` тем же литеральным префикс-матчем, что в
check_zones (структурное поле одно, алфавит — первая строка коммита);
форма секции проверена живьём `bash scripts/check_threat_model.sh . <этот
контракт>` → «секция валидна».
