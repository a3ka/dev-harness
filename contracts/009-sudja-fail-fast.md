# Контракт 009 — судья fail-fast (поток A, срез Н-41)

Номер выдан механизмом: `next_id.sh CONTRACT` → 009, тег `id/CONTRACT/009`. Предмет — решение
владельца (2026-08-24): закрыть второй механизм Н-41. Срез 1 уже сделан (008 → `judge_gate.sh
<sha>` через CI-сигнал). Срез 2: судья НЕ ВИСИТ в bash-вызове при долгом CI.

Из NABLIUDENIA Н-41: лимит bash-вызова судьи 600с, а CI может длиться дольше. Bash-вызов
таймаутится на 600с, и `hub` для отмены внутрипроцессного субагента нет (Н-41). `fail-fast`
дополняет существующее API: при превышении тайм-бокса `judge_gate.sh` отказывает СРАЗУ (rc=1 + сообщение),
не дожидаясь bash-таймаута.

## §Предмет — что делаем

Расширить `scripts/judge_gate.sh` режимом `--fail-fast[=<N>]` (поток A, срез Н-41).
008-закреплённое API (`judge_gate.sh <sha>` без флага) сохраняется 1:1. Новое:
- `--fail-fast` без значения → тайм-бокс 540с по умолчанию (90% от 600с лимита bash-вызова судьи);
- `--fail-fast=N` → тайм-бокс N секунд (N — натуральное > 0; не-цело и N≤0 — отказ с названной причиной).

Реализация: `check_ci_gate.sh` запускается через `timeout --foreground TBOX`. При срабатывании
timeout (rc=124) `judge_gate.sh` печатает в stderr дословно `FAIL-FAST: превышен тайм-бокс N с`
и выходит RC=1. Прочие RC пробрасываются; маркер `OK` на rc=0.

Защиты (отказ с названной причиной, RC=1):
- `command -v timeout` пусто → дословно `FAIL-FAST: timeout не найден` (даже если --fail-fast запрошен);
- `--fail-fast=N` с N≤0 ИЛИ N не целое → дословно `FAIL-FAST: тайм-бокс должен быть > 0 (дано: <N>)`.

## §Что значит готово — критерий (красные предъявлены ДО круга критика)

Барьер `scripts/check_judge_gate.sh` имеет 10 ветвей (2 унаследованных от 008 + 8 новых).
Фикстуры в `fixtures/check_judge_gate/case_*.sh` — ОДИННАДЦАТЬ (3 унаследованных от 008 + 8 новых).
Каждая фикстура предъявляет барьер КРАСНЫМ против сломанного предмета и ЗЕЛЁНЫМ против
heredoc-эталона с правильной реализацией.

### 10 ветвей барьера

**(красный)** (008) — fake реагирует на sha; `judge_gate.sh <deadbeef>` обязан RC≠0 + маркер FAKE.

**(зелёный)** (008) — fake реагирует на `$PASS_SHA`; `judge_gate.sh <PASS_SHA>` обязан RC=0 +
«OK» + fake видит `sha=$PASS_SHA`.

**(фailfast-медленный)** (009) — fake спит `$SLEEP_FOR=3с` ПЕРЕД реакцией; `judge_gate.sh
--fail-fast=2 <SLOW_SHA>` обязан: RC≠0 + дословно «FAIL-FAST: превышен тайм-бокс 2 с» + **в
выводе НЕТ «rc=1»**. Конструкция: bash в script-режиме не пробрасывает SIGTERM в дочерний
sleep. С sleep-перед-реакцией fake становится «спящим», timeout SIGTERM убивает fake с
обрывом маркера «rc=» (без «rc=0»/«rc=1»). Подстрока `rc=1` в выводе означает, что fake
прожил (имитация без timeout).

**(фailfast-быстрый-ok)** (009) — fake отвечает мгновенно rc=0 на `$PASS_SHA`; `judge_gate.sh
--fail-fast=2 <PASS_SHA>` обязан: RC=0 + «OK» + fake видит `sha=$PASS_SHA`.

**(фailfast-дефолт)** (009) — fake отвечает мгновенно rc=0 на `$PASS_SHA`; `judge_gate.sh
--fail-fast <PASS_SHA>` (bare, без `=<N>`) обязан: RC=0 + «OK».

**(фailfast-дефолт-540)** (009) — доказательство, что bare-дефолт РЕАЛЬНО 540 (а не 0/1/2/3/...).
fake спит 2с ПЕРЕД реакцией. Без fake-timeout стаб с `TBOX=3` проходит как зелёный (fake
спит 2с, успевает за 3с). Закрытие: fake-timeout через изолированный PATH-minimal
`$WORK/nopath_540/timeout` — это скрипт, который пишет $@ в `$WORK/timeout_args.log` и затем exec
настоящего `/usr/bin/timeout`. Барьер проверяет, что в args.log содержится `--foreground 540`.

**(фailfast-произвольный-N)** (009) — `judge_gate.sh --fail-fast=<RANDOM_N> <PASS_SHA>`, где
`RANDOM_N` — случайное число из `[3..500]` на прогон (генерируется в барьере через
`$((RANDOM % 498 + 3))`, печатается в stderr для верификации). Обязан: RC=0 + «OK» + fake
видит `sha=$PASS_SHA`. Это закрывает стаб-whitelist `{2,7,...}`: при любом N вне whitelist
стаб даст RC≠0 (а не RC=0 + OK) → die. **Остаточный риск, cognitive-only**: домен
`N∈ℕ>0` бесконечен, проверка конечна. Стаб, принимающий ВСЕ натуральные N (без whitelist),
пройдёт как зелёный при любом N∈[3..500]. Это ограничение по построению (лимит bash-вызова
600с делает N≥600 бессмысленным).

**(фailfast-защита-N-невалидный)** (009) — `judge_gate.sh --fail-fast=0 <PASS_SHA>` обязан: RC≠0 +
дословно «тайм-бокс должен быть > 0».

**(фailfast-защита-N-нецелый)** (009) — `judge_gate.sh --fail-fast=abc <PASS_SHA>` обязан: RC≠0 +
дословно «тайм-бокс должен быть > 0».

**(фailfast-защита-timeout-отсутствует)** (009) — PATH без timeout (через **изолированный**
`$WORK/nopath_abs/` с симлинками на bash/sh/cat/date/echo/printf/sleep/dirname/pwd, БЕЗ timeout).
Каждая ветвь с PATH-манипуляцией использует **свой собственный** каталог
(`nopath_540` для дефолт-540, `nopath_abs` для timeout-отсутствует). НЕ используется
`rm -f` для чистки — это создаёт порядковую зависимость между ветвями. `judge_gate.sh
--fail-fast=2 <PASS_SHA>` обязан: RC≠0 + дословно «timeout не найден».

Старые ветви `(красный)` и `(зелёный)` (008) НЕ ТРОГАЕМ — обратная совместимость.

### Конструкция fake

Fake `check_ci_gate.sh`:
- `printf '${FAKE_MARK} sha=%s rc=' "$1" >&2` — печатает маркер с `$1`, **БЕЗ newline** (обрыв на `rc=`).
- `sleep ${eff_sleep}` — ПЕРЕД реакцией (см. комментарий в `check_judge_gate.sh` про bash+SIGTERM).
- Если `$1 = $PASS_SHA` → `printf '0\\n'; exit 0` (rc=0, без задержки — sleep уже выполнен).
- Иначе → `printf '1\\n'; exit 1` (rc=1 после sleep).

`eff_sleep = ${SLEEP_FOR:-0}` — задаётся на вызов через `SLEEP_FOR=N run_gate ...`. По умолчанию 0.

### Обязательный положительный контроль all

Прогон `bash scripts/check_judge_gate.sh <эталон>` (без указания ветви = `all`) на heredoc-эталоне
с правильной реализацией fail-fast обязан дать RC=0. Это закрывает утечку состояния между
ветвями (например, утёкший `$WORK/nopath_540/timeout` в ветку `timeout-отсутствует`). Каждая
фикстура с PATH-манипуляцией (`фailfast-дефолт-540` и `фailfast-защита-timeout-отсутствует`)
должна прогнать `all` на эталоне после проверки своей ветви.

## §Незаполненные требования

- Поведение при `--kill-after` для подвисших процессов (если SIGTERM игнорируется): контракт
  требует невисения, а не конкретного механизма. Деталь свободная.
- Контракт НЕ различает «CI не зелёный» и «превышен тайм-бокс» по RC — оба RC≠0. Различие в
  сообщении. Это сделано, чтобы стаб, возвращающий «CI не зелёный» на медленном входе, проваливал
  ветвь `(фailfast-медленный)` — что и требуется.
- **Домен N (cognitive-only, решение арбитра 2026-08-24):** проверка `(фailfast-произвольный-N)`
  подаёт один `RANDOM_N ∈ [3..500]`. Стаб-whitelist с малым множеством N провалится (при
  N вне множества отвергает вход → die). Стаб, принимающий ВСЕ натуральные N>0 без whitelist,
  пройдёт как зелёный. Это ограничение по построению (лимит bash-вызова 600с делает N≥600
  бессмысленным; область применения — все «практические» N).
- **Утечка состояния между ветвями (решение арбитра 2026-08-24):** изолированные каталоги
  `nopath_540` / `nopath_abs` на ветвь + обязательный положительный контроль all в фикстурах
  с PATH-манипуляцией.
