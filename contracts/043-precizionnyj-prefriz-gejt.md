# Контракт 043 — прецизионный пре-фриз гейт (Н-113/Н-115)

Статус: черновик v1. Основа — `agent://FrontierPrecisionGate` (полный frontier-разбор
трёх вариантов места/механизма) + решение владельца 2026-09-23 (дословно, приведено
целиком в §Инварианты и §Критик-надстройка ниже, не переоткрывается): рекомендация
принята — Вариант Б (новый sibling-скрипт на freeze-time хуке) + Вариант В (тот же
скрипт как обязательная bash-команда критика ДО accept) ВМЕСТЕ, НЕ порознь; Вариант А
(рост `check_spec_ready.sh`) НЕ принят.

## Предмет

Н-113/Н-115 — измеренный класс: критик-гейт перед заморозкой не сверяет (а) ЗОНА-
дельту черновика с union ЖИВЫХ заморозок (036 §В3 ловит только ВНУТРИ своего
контракта — intra-, не cross-контрактно), (б) достижимость приёмки семей case-файлов
НА ДЕРЕВЕ, куда ляжет заморозка (036 §В4 закрыл ТОЛЬКО ∃-квантор — один живой вызов
на семью; прецедент 031 требует ∀ — каждый case-файл), (в) совместимость чернoвика с
CI-паритетом (контракт 020, механизм есть и дёшев — `verify_ci_parity.sh`, 1.574с,
0 расхождений на здоровом HEAD, — но `freeze_contract.sh` его НИКОГДА не вызывает).
Каждое несоответствие исторически всплывало ПОСЛЕ подписи владельца на первой
заморозке → v+1 → новый круг критика → новая подпись (конкретика: контракт 031 —
ТРИ frozen-правки; 036 — ТРИ; 038/040 — по одной поздней; HANDOFF чекпойнт #11:
«038 на круге 16 + ревьюер FAIL: 37/67 красной пачки не подключены к CI»).

Носитель — ОДИН новый sibling-скрипт `scripts/check_precision_gate.sh <корень>
<отн-путь-контракта>`, решающий три независимые задачи:

1. **(а) Зона-коллизия.** Dry-run union: ЗОНА-пары черновика, которых ещё нет в живом
   union под ЭТИМ ЖЕ NNN («новые» пары), сверяются с живым union всех остальных
   замороженных контрактов (`lib_zones.sh:zones_load`, контракт 033). Путь, уже
   принадлежащий ДРУГОМУ NNN под ДРУГИМ автором, — БЛОКЕР fail-closed с ИМЕННОЙ
   причиной (путь + оба NNN + оба автора); единственный законный выход — явное
   union-объявление в тексте черновика новой строкой `ПЕРЕСЕЧЕНИЕ` (правило 7
   AGENTS.md — «неразобранное объявление отказывает с названным местом и выходом»;
   молчаливое сужение/приём по догадке запрещены нормой).
2. **(б) Живая полярность case-файлов.** Для КАЖДОГО (не только count — владелец
   Q2 явно отклонил глоб-счёт как placebo, прецедент Р2 038 — 37/67 фикстур красной
   пачки не были подключены к CI, счётный гейт этого не увидел) НОВОГО (не
   существовавшего на HEAD применимой базовой линии — §Инварианты п.2) case-файла
   затронутой семьи (`fixtures/check_<key>/`, объявленной в ЗОНА черновика):
   basename структурно заявляет полярность (`red_*`/`green_*`), барьер семьи
   (`scripts/check_<key>.sh`) подтверждённо исполнен ЖИВЬЁМ (внешний независимый
   трейс — bash `BASH_XTRACEFD`/`PS4`, НЕ текстовое совпадение в выводе самого
   case-файла — тот же независимый-от-предмета оракул «командная позиция в
   трассе», что 036 (`check_spec_ready.sh` В4-2/3) уже применяет для того же
   класса риска — довожен до произвольной глубины вложенности), и собственная
   самопроверка case-файла зелена. Семья, чей барьер правится ЭТИМ ЖЕ
   черновиком (живой случай — эта самая семья `check_precision_gate`), задачей
   (б) молча не судится (прецедент 036 В4-3 — «барьер, движущаяся цель
   драфта», см. §Инварианты п.3.0). Цена растёт линейно с числом case-файлов
   семьи — названо здесь честно, не скрыто;
   поэтому задача исполняется ПОСЛЕДНЕЙ (§Инварианты п.6).
3. **(в) Паритет CI.** `verify_ci_parity.sh <корень>` (контракт 020) — уже полный
   двунаправленный механизм (сирота-семья ∧ мёртвый ключ), дешёвый (~1.6с), просто
   никогда не вызывавшийся на freeze-хуке. Вызов добавлен без изменения самого
   `verify_ci_parity.sh`.

## Модель угроз

ЗАЩИЩАЕТ:
- честное обнаружение новых пар автор путь при пробном объединении зоны черновика с живым union без домысливания структуры чужих контрактов вне их объявленной ЗОНА
- различение полярно заявленного red или green case файла от файла без структурной декларации через замкнутый двухбуквенный префиксный алфавит имени вместо свободной прозы
- подтверждение живого вызова барьера семьи внешним независимым трейсом процесса на уровне командной позиции а не текстовым совпадением где либо внутри вывода самого case файла
- литеральное побайтовое сравнение пути автора и номера контракта между строкой ПЕРЕСЕЧЕНИЕ и объявлением ЗОНА без интерпретации любой стороны как регулярного выражения или глоба

НЕ ЗАЩИЩАЕТ:
- враждебное окружение вызывающего процесса за пределами базового PATH экспорта это отдельный класс ENV TRUST и SOURCED EXEC контракта 038 и не входит в область этого контракта
- смысловую адекватность причины строки ПЕРЕСЕЧЕНИЕ или причины красного case файла это решает критик а не механизм по прямому переносу oblast-i-porog.md Вопрос2
- ретроактивную полноту случаев когда путь барьера семьи оказывается данными аргумента постороннего вызова вместо позиции исполняемого слова трассы упрощённый якорь без полного командно-позиционного оракула 036 со списком обёрток это именованный остаточный риск страховка критик
- новизну case файлов семьи вне применимой базовой линии контракта то есть case файлы существовавшие до неё этим гейтом не пересматриваются задним числом

## Инварианты

Грамматики — ЕДИНЫЙ источник этот контракт; реализация несёт фразы ПОБАЙТОВО
(фикстуры сверяют дословно через `grep -Fq`/`grep -Fxq`). Каждый пункт §Приёмка —
исполняемая команда с известным rc (канон 008).

1. **`ПЕРЕСЕЧЕНИЕ`-строка (структурное поле, норма 041 самоприменена — поле
   встречается в ЭТОМ САМОМ контракте, см. §Приёмка Р-та self-application).**
   Грамматика, ровно: `ПЕРЕСЕЧЕНИЕ <автор>: <путь> — <NNN> <причина>` — построчный
   якорь `case "ПЕРЕСЕЧЕНИЕ "*`, разбор `sed -nE` анкерованным regex ОДНИМ
   выражением на все четыре группы (не пятью независимыми, чтобы частичное
   совпадение не давало частичной истины). Пять свойств формата (норма 041
   §Инварианты п.2):
   1. **Замкнутый алфавит.** `<автор>` — `[^:[:space:]]+` (тот же токен, что ЗОНА
      уже требует репозиторно, `lib_roles.sh` не расширяется); `<путь>` — токен без
      пробелов (пробел уже разделяет список путей ЗОНА, установлено
      `check_zones.sh`; путь легален с любым другим байтом, включая `-`/`:`);
      `<NNN>` — ровно три цифры `[0-9]{3}`.
   2. **Представление без переиспользования байта данных разделителем.**
      Реализация несёт параллельные bash-массивы (`X_AUTHOR[]`/`X_PATH[]`/
      `X_NNN[]`), НЕ join-строку: причина и путь легально содержат `-` и `:` —
      ровно те байты, которыми размечена сама грамматика поля (` — ` и `: `).
   3. **Литеральное untrusted-untrusted сравнение.** Привязка (п.1в ниже) и
      детект коллизии (п.3) — ТОЛЬКО `[ = ]`/`case`-литерал; НИКОГДА
      regex/glob, построенный из пути или автора черновика (Направление 3,
      041 — тот же класс риска, что закрывал 038-round-13 guard-ere-metachars).
   4. **Точечный якорь терминатора.** Строка `ПЕРЕСЕЧЕНИЕ …`/`ЗОНА …` matched
      ТОЧНЫМ префиксом в начале строки (`case "ЗОНА "*":"*`), построчный
      разбор — не regex по всему телу файла.
   5. **Обязательная self-application green-фикстура ДО заморозки** —
      `fixtures/check_precision_gate/green_09_self_application_043.sh` +
      `fixtures/parsing_hygiene_battery/profiles/check_precision_gate.sh`
      (функция `battery_self_application_green`) — обе прогоняют
      `scripts/check_precision_gate.sh` буквально на этом контракте
      (`contracts/043-*.md`), rc 0 обязателен (§Приёмка Р-та).
   Строка `ПЕРЕСЕЧЕНИЕ` без связной четвёрки (пропущен NNN, пропущен em-dash
   ` — `, пустая причина) — именованный отказ «ПЕРЕСЕЧЕНИЕ не по грамматике:
   <строка>» целиком, частичный разбор не принимается.
2. **Задача (а): зона-коллизия.**
   1. `registry_state "$ROOT" 'frozen/'` — `full`/`unknown-remote` проходят
      дальше, иначе именованный отказ «реестр заморозок не читается: <state>»
      (fail-closed, тот же приём, что 036/038).
   2. `zones_load "$ROOT"` (контракт 033) — читает union ЗОНА ВСЕХ живых
      замороженных контрактов (`author\tpath\tNNN`, высшая версия каждого NNN,
      диапазон 1..done). Отказ `zones_load` (rc 1) — именованный «union зон не
      читается (отказ реестра)»; rc 2 — `NOT_IMPLEMENTED`.
   3. Черновик разбирается на пары `(автор, путь)` по ВСЕМ строкам `ЗОНА <автор>:
      <путь>…` (та же построчная грамматика, что `check_spec_ready.sh` уже
      использует для В4 — не второй разбор одного формата).
   4. Для каждой пары `(a, p)`, отсортированной ЛЕКСИКОГРАФИЧЕСКИ по `(путь,
      автор)` (детерминированный порядок — «первая красная строка» обязана быть
      воспроизводима между прогонами, не зависеть от порядка bash-хэша):
      - **own** — пара уже присутствует в union ПОД ЭТИМ ЖЕ NNN (переиздание v2+
        строки — не новая пара, не судится этой задачей: это область 036 §В3);
        `own` пропускает пару без дальнейшего разбора;
      - иначе — **новая** пара. Ищется коллизия: любая строка union с ТЕМ ЖЕ
        путём `p`, ДРУГИМ NNN и ДРУГИМ автором (не `a`). Коллизия НЕ считается,
        если автор совпадает (повторное владение implementer/architect и т.п.
        через много контрактов — нормальный, ожидаемый паттерн union-семантики
        033, не предмет этой задачи).
      - Коллизия найдена, но черновик несёт строку `ПЕРЕСЕЧЕНИЕ <a>: <p> —
        <coll_NNN> <причина>` (привязанную — п.1 выше) → пара пропущена, зелёная.
      - Коллизия найдена, объявления нет → БЛОКЕР fail-closed, именованная
        причина: «зона-коллизия: `<p>` заявлен `<a>` (этот контракт, NNN
        `<NNN>`), уже в union под NNN `<coll_NNN>` для `<coll_author>` — нужна
        строка ПЕРЕСЕЧЕНИЕ `<a>`: `<p>` — `<coll_NNN>` `<причина>`».
3. **Задача (б): живая полярность case-файлов.**
   0. **Исключение «барьер правится этим же черновиком».** Семья `<key>`, чей
      барьер `scripts/check_<key>.sh` литерально присутствует СРЕДИ ЗОНА-путей
      этого же черновика (барьер вводится/правится ИМ), задачей (б) молча не
      судится — прецедент 036 §В4-3 («барьер — движущаяся цель драфта», задачу
      для неё решает критик), stderr-пометка «семья `<key>` — барьер правится
      этим же черновиком, задача (б) для неё пропущена». Живой случай — сам
      `check_precision_gate.sh`: без исключения его self-application case
      (задача (а), self-application §Приёмка Р9) рекурсивно тестировал бы
      СВОЮ ЖЕ семью неограниченно глубоко (измерено живьём при написании —
      без исключения прогон не завершался за 60с).
   1. **Затронутая семья** — любой путь `fixtures/check_<key>/…` среди ЗОНА-пар
      черновика (за вычетом п.3.0); `<key>` — та же экстракция, что
      `check_spec_ready.sh` (036, В4) уже применяет (`fixtures/check_` префикс,
      до следующего `/`). Семья без барьера (`scripts/check_<key>.sh` не
      существует) НЕ дублируется этой задачей — уже красна в
      `check_spec_ready.sh` §В4-1, который в пайплайне исполняется РАНЬШЕ (§6а).
   2. **Применимая базовая линия новизны** — ВЫСШИЙ уже живой
      `frozen/contracts/<NNN>/<v>` этого же NNN, если существует (норма 036 §В3
      — «новое» для v2+ значит «не было в предыдущей версии»; ДОБАВЛЕНИЕ красных
      тестов пост-заморозки легально, AGENTS §Воркфлоу п.3, и не пересматривается
      этой задачей задним числом); иначе (первая заморозка, `vmax=0`) — тег
      минта `id/CONTRACT/<NNN>` (тот же приём границы новизны, что норма 041
      §Инварианты п.1 применяет к гардам). Тег минта отсутствует, а затронутая
      семья есть → именованный отказ «тег минта `<tag>` не существует — новизна
      case-файлов не определима» (fail-closed: без базовой линии судить нечем).
   3. Для каждого `case_*.sh`/`red_*.sh`/`green_*.sh` затронутой семьи, НЕ
      присутствующего в дереве базовой линии по тому же относительному пути
      (`git cat-file -e <базовая-линия>:fixtures/check_<key>/<файл>`):
      - basename обязан начинаться `red_` либо `green_` — иначе именованный
        отказ «полярность не заявлена: `<файл>` (basename не начинается red_
        или green_)». Старые (пред-базовая-линия) case-файлы семьи, включая
        любые, не следующие этой конвенции исторически, — ВНЕ области (см. §Модель
        угроз НЕ ЗАЩИЩАЕТ), задним числом не пересматриваются.
      - Независимый трейс — bash `BASH_XTRACEFD`/`PS4` (прецедент 036
        `check_spec_ready.sh` В4-2/3, арбитраж 036d1f1): `<файл>` исполняется
        ВТОРЫМ прогоном под `env PS4='+ ' SHELLOPTS=xtrace BASH_XTRACEFD=<fd>`,
        где `<fd>` — приватный дескриптор гейта, физически отдельный от
        stdout/stderr пробы — проба владеет своими потоками, не каналом трассы;
        трасса наследуется КАЖДЫМ вложенным bash (та же гарантия, что 036
        документирует). Живость барьера засчитывается, если строка трассы,
        после снятия ведущего прогона `+` (глубина вложенности — функция/
        `$(…)` вокруг вызова, ≥1 систематически по конвенции `_toy.sh`) и ровно
        одного пробела, ПОБАЙТОВО равна канонический-абсолютному пути барьера
        либо начинается им и пробелом (командная позиция — барьер ПЕРВЫМ
        словом, не где-либо в трассе). Отсутствие → «`<файл>`: барьер `<key>`
        не вызван живьём (командная позиция не найдена в трассе)».
      - Живость подтверждена, но rc прямого (не-трейсового) прогона `bash
        <файл>` не 0 → «`<файл>`: самопроверка провалена (rc `<rc>`, ожидался
        0)».
4. **Задача (в): паритет CI.** `verify_ci_parity.sh <корень>` (контракт 020, БЕЗ
   изменения самого механизма) — rc≠0 → именованный отказ «паритет CI красен
   (verify_ci_parity.sh rc `<rc>`): `<первая строка вывода>`».
5. **Коды возврата носителя** `scripts/check_precision_gate.sh <корень>
   <отн-путь-контракта>`: 0 — все три задачи зелёные, последняя строка stdout
   `OK` (канон 008); 1 — отказ, именованная причина первой красной; 2 —
   `NOT_IMPLEMENTED` (нет git/контракта/NNN-грамматики/реестра/тега-минта-когда-
   нужен). rc 2 на freeze-хуке — fail-closed rc 1 (тот же приём, что 036/038).
6. **Порядок исполнения задач — а → б → в.** Задача (б) — самая дорогая, растёт
   линейно с числом case-файлов затронутых семей (владелец: «цена растёт с
   числом case-файлов — назови это честно») — исполняется ПОСЛЕДНЕЙ; (а) и (в)
   — cost-сопоставимы (union-чтение из тегов vs. ~1.6с сканирование `.github/**`
   + `package.json`), (а) первой как ядро предмета этого контракта.
7. **Проводка в `freeze_contract.sh` — шаг «6а-ter»** СРАЗУ ПОСЛЕ §6а-bis
   (consumers-gate 038) и ДО §6б (doc-preflight 027) — по паттерну, уже трижды
   применённому в файле (§6а/§6а-bis):
   ```
   if [ -f "$SELF_DIR/check_precision_gate.sh" ]; then
     pg_out=""; pg_rc=0
     pg_out="$(cd "$ROOT" && bash "$SELF_DIR/check_precision_gate.sh" "$ROOT" "$TARGET" 2>&1)" || pg_rc=$?
     if [ "$pg_rc" -ne 0 ]; then
       die "precision-гейт 043 красен: $(printf '%s' "$pg_out" | head -n 1)"
     fi
   fi
   ```
   Условный `if [ -f … ]` — та же bootstrap-защита, что консюмерс-гейт 038 несёт
   (окно между заморозкой ЭТОГО контракта и приземлением файла implementer'ом).

## Критик-надстройка

Решение владельца (дословно): «критик-надстройка (В): `roles/critic.md` получает
шестой обязательный пункт: прогнать этот скрипт баш-командой ДО accept, rc≠0
