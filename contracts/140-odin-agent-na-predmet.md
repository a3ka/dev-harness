## Демаркация

Конформные входы (грамматика батареи): события `{"tasks":[{agent,name,task}]}`/flat с полями из замкнутых алфавитов (агент — роли config + scout/task/sonic/arbiter/…; имя `[A-Za-z0-9._-]+`; строки SUBJECT/OBJECT/PIN по инварианту 2, допускается ЛЮБОЙ прочий текст задания вокруг них — ровно это и судится); журналы holder — построчные JSON записей рантайма omp (типы `custom`/`message`/`custom_message`/…; произвольные строковые поля — включая литералы маркера сдачи; структурные поля записи принадлежат рантайму), yield-литерал/без, mtime; git-миры кандидата — ДЕРЕВО OBJECT с `contracts/`-записями произвольного состава (blob-файлы, симлинки mode-120000, каталоги-записи `<NNN>-*.md`), tip меняется amend, рабочий каталог — грязный; занятия замка (holder/класс/object), учёт (START/RELEASE/SLOVO любых предметов и групп), репо реестра (контракты с/без строки риска, risk-legacy.tsv, pauzy.tsv, теги done). Валидный контрпример к инвариантам = инвариантность к значениям вне алфавитов ∧ расхождение на конформном входе; вход с SUBJECT/OBJECT вне грамматики или строка журнала вне JSON — НЕконформный, красен по построению. Неконформные стабы (мутации модели) обязаны краснеть ровно на своих привязках — и могут краснить шире (минимальная гарантированная краснота — привязка, не полный эффект; свидетель x01 по замеру v1 краснил 44 из 48, привязка — 12 клеток названных классов: дубль живого, рестарт, лимиты ×2, судья-до-yield, OBJECT ×4, порядок, пакет, гонка). Конформные входы СТАНЦИОННЫХ клеток: события — полные omp `tool_call` `{type, toolName:'task', toolCallId, input}` (input — batch/flat алфавитов инварианта 2), подложный ctx — файл сессии по грамматике инварианта 1, миры — те же комбинации, что у двери-CI; валидный контрпример к интеграции = инвариантность к значениям вне грамматик ∧ расхождение на конформном tool_call; слой субъекта в `--stabs` судит ТОЛЬКО существующую поставленную дверь (до ленда — опора над моделью, зелень предварительная, не приёмка). v5: поле `isolated` — часть грамматики события: у рабочего конформное значение — ровно булево true; отсутствие поля и ложь — КОНФОРМНЫЕ входы с именованным отказом `NE_IZOLIROVAN` (не «красное по построению»); слово isolated:true в тексте задания — произвольный прочий текст вокруг строк грамматики, источником не является; поле isolated у судьи — вне ТРЕБОВАНИЯ изолированности (пропуск судейских ворот прежний): значения true/false и отсутствие поля конформны, нормализованный факт (`"isolated":true`/`"isolated":false`) записывается в строку START судьи (s45/s46/s47).
