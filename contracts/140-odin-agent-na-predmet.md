## Демаркация

Конформные входы (грамматика батареи): события `{"tasks":[{agent,name,task}]}`/flat с полями из замкнутых алфавитов (агент — роли config + scout/task/sonic/arbiter/…; имя `[A-Za-z0-9._-]+`; строки SUBJECT/OBJECT/PIN по инварианту 2, допускается ЛЮБОЙ прочий текст задания вокруг них — ровно это и судится); миры — произвольные комбинации: журналы holder (yield-литерал/без, mtime), занятия замка (holder/класс/object), учёт (START/RELEASE/SLOVO любых предметов и групп), репо (контракты с/без строки риска, pauzy.tsv, теги done), git-ветки (tip меняется amend). Валидный контрпример к инвариантам = инвариантность к значениям вне алфавитов ∧ расхождение на конформном входе; вход с SUBJECT/OBJECT вне грамматики — НЕконформный, красен по построению. Неконформные стабы (мутации модели) обязаны краснеть ровно на своих привязках — и могут краснить шире (минимальная гарантированная краснота — привязка, не полный эффект; свидетель x01 по замеру краснит 44 из 48, привязка — 12 клеток названных классов: дубль живого, рестарт, лимиты ×2, судья-до-yield, OBJECT ×4, порядок, пакет, гонка). Конформные входы СТАНЦИОННЫХ клеток: события — полные omp `tool_call` `{type, toolName:'task', toolCallId, input}` (input — batch/flat алфавитов инварианта 2), подложный ctx — файл сессии по грамматике инварианта 1, миры — те же комбинации, что у двери-CI; валидный контрпример к интеграции = инвариантность к значениям вне грамматик ∧ расхождение на конформном tool_call; слой субъекта в `--stabs` судит ТОЛЬКО существующую поставленную дверь (до ленда — опора над моделью, зелень предварительная, не приёмка).
