## Инварианты

1. **Порядок диапазона (а)**: cherry-pick диапазона обязан идти ОТ СТАРШЕГО К
   МЛАДШЕМУ — `rev-list --reverse` в сборе RANGE_SHAS. Свойство: на ветке после
   приёма коммиты стоят в порядке источника (`git log --reverse` subjects
   старший→младший), содержимое файла = последовательное применение.
2. **М2 п.4 не ослаблен (а)**: литеральная сверка identity и мерж-политика 4а
   накрывают КАЖДЫЙ коммит диапазона и при новом порядке — негативные пары
   «старший чужой» и «младший чужой» обе красны до и после.
3. **Провенанс до записи (б)**: mint_line отказывает ДО правки дерева, если тег
   не жив локально / не аннотирован / не достижим на origin (self-mint) / sha
   локального тега ≠ sha тега на origin (переминт) / origin недоступен
   (fail-closed: обрыв сети НЕ пишет строку; имя отказа отдельное от «не выдан
   авторитетом»).
4. **Повторный минт (б)**: NNN уже в манифесте HEAD → именованный отказ скрипта
   («ОТКАЗ: номер … уже в манифесте»), дерево чисто, HEAD не двинулся.
5. **Дверь 031 — судья, неотвратимый для самого скрипта (б)**: скрипт коммитит
   строку штатным коммитом с identity orchestrator на main; дверь судит дельту
   на коммите; отказ двери = rc 1 + точечный откат пути к HEAD. Неотвратимость
   (Б2 к1): до записи скрипт проверяет эффективный hooks-каталог (core.hooksPath,
   при пустоте — <git-dir>/hooks) на исполняемый pre-commit — конфиг-дизарм =
   именованный отказ «дверь 031 отключена конфигом»; командная строка коммита
   НЕ несёт ни одного -c (identity — env GIT_AUTHOR_*/GIT_COMMITTER_*), и
   hooksPath-инъекция -c остаётся единственной чужеродной точкой — различима
   клеткой батареи по поведению. Скрипт не создаёт/не удаляет теги и не пушит.
6. **Атомарность (б)**: на любом отказе рабочее дерево чисто и HEAD не двинулся;
   при успехе — ровно один новый коммит на main, author=committer=orchestrator,
   stdout `MINTED nnn=<NNN> sha=<tag-object-sha> commit=<sha>`.
7. **Гигиена парсинга (041, новое поле `--nnn`)**: замкнутый алфавит `^[0-9]{1,3}$`
   с нормализацией %03d; строка реестра — единый источник грамматики 023/031
   («<NNN> → <40-hex>», U+2192, sha ОБЪЕКТА тега), собирается ОДНИМ printf;
   сравнения sha — литеральный `[ = ]`; peeled-строки `^{}` исключаются из
   ls-remote-вывода.

## Модель угроз

ЗАЩИЩАЕТ:
- многокоммитная пачка task-субагента принимается без ручного replay: порядок
  старший→младший устраняет конфликт применения, инварианты 037 (identity каждого
  коммита, мерж-политика, атомарный отказ) сохранены дословно (регресс 7/7)
- опечатку/подмену строки реестра: скрипт пишет только tag-object-sha ЖИВОГО
- опечатку/подмену строки реестра: скрипт пишет только tag-object-sha ЖИВОГО
  локального тега, сверённый с origin (self-mint, переминт, повторный минт, обрыв
  сети — именованные отказы до правки дерева); дверь 031 остаётся вторым
  независимым судьёй на коммите (м4 — живость, м5 — неотвратимость для самого
  скрипта)
- отключение двери для минта: конфиг-дизарм (эффективный hooks-каталог без
  живого pre-commit) — именованный отказ до записи; hooksPath-инъекция -c в
  командную строку коммита скрипта различима клеткой батареи поведенчески
  (коммит мимо двери на входе, где дверь обязана отказать)

НЕ ЗАЩИЩАЕТ:
- компрометацию самого авторитета (тег запушен на origin злоумышленником вместе со
  строкой в манифесте): dual-control судит СОГЛАСИЕ локального тега и origin, не
  честность владельца тега — граница 023/031, 068 её не двигает
- обход `--no-verify` при ручном коммите строки мимо скрипта — тот же
  когнитивный остаток 016/031, ловец — CI (check:zones/charter) и ревьюер по диффу
- гонку «строка появилась на origin/main между проверкой скрипта и коммитом» —
  закрывает ДВЕРЬ (условие 3 судит живую шапку origin/main на коммите), скрипт
  лишь откатывает путь при отказе
