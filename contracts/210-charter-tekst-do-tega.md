# Контракт 210 — check_charter не судит коммит, внёсший текст контракта до публикации его frozen-тега

СТАТУС: ЧЕРНОВИК-ЗАТРАВКА (bootstrap: `make_task --role architect` требует существующий `contracts/210-*.md`; текст контракта пишет architect по заданию станции — затравка не является ни спекой, ни критерием; заменяется целиком).

## Боль
Измерено 22.11: порядок «текст → тег после влива» (контракт 130 И-8) делает `contracts/NNN-*.md` уставным путём только ПОСЛЕ публикации `frozen/contracts/NNN/1`; после этого `scripts/check_charter.sh` судит задним числом коммит, который внёс текст ДО тега, как «M без РАЗРЕШИЛ-ВЛАДЕЛЕЦ». Случаи: merge PR #1240 `409836ed5d` (текст 204) — красный полный check_charter на main, отказ Д3 двери консультанта на #1243/#1241; синхронизация #1241 с main `66a37eff` (тот же текст 204, блоб `9288a6cd69` = frozen-тегу) — красный CI #1241 (run 45067553641). Закрыто разово grandfather-парами 70/71 (owner-PR #1244, `059cc95a`) по слову владельца; без механизма повторится на 205/206/207/208/209/210 и на каждой синхронизации ветки PR с main, принёсшей текст контракта.

## Решение
Слово владельца 22.11: «новая задача станции — не судить коммит, внёсший текст контракта до публикации frozen-тега». Направление (станция, `inbox-STANCIJA-GRANDFATHER-0035.txt` (б)): не судить коммит, чей вносимый блоб контракта побайтно равен блобу в frozen-теге и который является предком коммита тега (либо merge, второй родитель которого — предок frozen-тега). Изменение текста ПОСЛЕ тега по-прежнему требует РАЗРЕШИЛ-ВЛАДЕЛЕЦ. Нужное свойство формулирует architect.

КЛАСС ЗАДАЧИ: кодовый. КЛАСС РИСКА: рисковый (страж устава: ослабление суда уставных путей — права/устав; adversary → reviewer).
РАБОТА НЕ РАЗДАЁТСЯ: затравка; зоны и раздачу объявляет architect.

## Незаполненные требования:
- точные зоны (`scripts/check_charter.sh`, его `--incr`, грандфазер-список) и ПЕРЕСЕЧЕНИЕ с активными предметами;
- инварианты: освобождается только внесение блоба, побайтно равного frozen-тегу, до/в истории тега; любая иная правка уставного пути без РАЗРЕШИЛ — по-прежнему FAIL; синхронизация main→wip, приносящая уже-замороженный текст, не судится; пары 70/71 остаются валидными или поглощаются правилом;
- красные клетки (merge до тега с равным блобом — ок; sync-merge с равным блобом — ок; правка текста после тега без РАЗРЕШИЛ — FAIL; блоб ≠ тегу — FAIL; поддельный «тег» не на origin — FAIL) и стабы к ветвям — привязывает architect по коду.
