## Frontier (по коду)

- **В1 «норма без механизма»** — расширить прозу роли (чеклист перед
  touch). ОТВЕРГНУТ: дисциплина измерено мертва (Н-85), запрет «при живых
  субагентах» уже сегодня прозой и не работает.
- **В2 «проверяет orch-loop»** — обёртка сама валидирует состояние.
  ОТВЕРГНУТ: слово владельца — обёртка сведена к минимуму, механизмы — в
  харнес; плюс orch-loop не видит HANDOFF-авторство/детектор своими
  инструментами без дублирования логики.
- **В3 «дверь-гейт scripts/orch_restart.sh» (ВЫБРАН)** — один скрипт-гейт:
  пять именованных условий, делегирование удаления мусорных worktree
  расширению gc_agent_branches, маркер только на зелёном; строка роли
  заменяется на вызов двери. Оправдание болью: единственный вариант, где
  нарушение КАЖДОГО условия даёт именованный отказ ДО каскада рестарта.
- **В4 «маркер в дереве»** — tracked-файл-флаг. ОТВЕРГНУТ: маркер —
  межпроцессный сигнал вне репо; файл в дереве грязнит porcelain и красит
  собственный гейт по построению.
- **В5 «различимый признак границы сессии»** (условие (в), круг критика
  к1 Б2: равенство автора не отличает новую сессию S2 той же identity с
  несделанным HANDOFF). Кандидаты:
  (i) env-нонс сессии, сверяемый с нонсом в HANDOFF-коммите, — ОТВЕРГНУТ:
  требует конвенции коммит-трейлеров у КАЖДОЙ сессии (расширение предмета
  на прозу ролей и привычный коммит-поток) и новой записи в каждом
  HANDOFF-коммите;
  (ii) mtime маркера перезапуска как граница — ОТВЕРГНУТ: второй смысл у
  одного артефакта (правило «идентификатор с двумя смыслами нечем
  развести»), маркер потребляется обёрткой, его mtime не переживает
  перезапуск надёжно, состояние «перезапуск отложен» перегружается;
  (iii) **СТАРТОВЫЙ СЛЕД-ФАЙЛ, пишемый дверью при зелёном завершении**
  (граница текущей сессии = момент последнего зелёного завершения двери)
  — ВЫБРАН: self-contained в предмете (обёртка не растёт — слово
  владельца «обёртка сведена к минимуму» соблюдено), пишется тем же
  механизмом, что читается, закрывает обход S2 в обоих мирах — со следом
  (HANDOFF-коммит S1 старее следа) и без следа (инициализация не
  вакуумна); механизм — инвариант 11, ноги условия — инвариант 2(в).

- **В6 «порог ноги (в)»** (вторая дверь, слово владельца; критерий —
  «порог отсекает отметку от предложения, правило 8»): (i) ЗАПРЕТ всех
  совпадений словаря — ОТВЕРГНУТ: контракты обязаны ЦИТИРОВАТЬ красные
  входы (приёмки и фикстуры цитируют закавыченную строку-вход красной
  клетки целиком) — дверь делала бы черновики ненаписуемыми, ложные
  срабатывания чаще находок; (ii) кавычный порог (совпадение внутри
  «…»/„…“/"…"/`…` — отметка, голое — предложение) — ВЫБРАН: механически
  проверяемая форма, отражает различие цитаты и утверждения, ложные
  срабатывания лечатся правкой формулировки (слово владельца: «правка
  формулировки, не обход»); (iii) семантический разбор «настоящая ли
  это привязка» — ОТВЕРГНУТ: смысл порогом не меряют (правило 8),
  ловец перефразированных привязок — критик.

   перезапуска — прежним touch по чеклисту (слово владельца); строка роли
   меняется реализационной пачкой ДО проверки done (приёмка А6).
2. **Пять условий, каждое — именованный отказ rc 1, маркер НЕ ставится:**
   (а) `HEAD == origin/main` — маркер «HEAD расходится с origin/main»;
   (б) porcelain пуст — маркер «porcelain непуст»;
   (в) HANDOFF.md изменён коммитом ЭТОЙ сессии — ДВЕ ноги, порядок строго
   (в1)→(в2):
   (в1) автор ПОСЛЕДНЕГО коммита, тронувшего HANDOFF.md, равен
   `git config user.name` чекаута (identity — та же мерка, что
   check_zones) — маркер «HANDOFF.md изменён не этой сессией»;
   (в2) committer-дата (`git log -1 --format=%ct -- HANDOFF.md`) этого
   коммита СТРОГО больше стартового следа сессии (инвариант 11) —
   маркер «HANDOFF.md изменён до стартового следа сессии»; закрывает
   обход «новая сессия S2 той же identity с несделанным HANDOFF»:
   HANDOFF-коммит S1 старее следа, которым завершлась предыдущая
   door-сессия (а при отсутствии следа — старее свежей инициализации);
   (г) `check_no_leak.sh --check <абс-ROOT>` rc 0 — маркер «детектор …»;
   (д) нет мусорных worktree ПОСЛЕ делегирования GC (инвариант 4) —
   маркер «мусорный worktree: <путь>».
   Пиннуты: слово-маркер причины + канал stderr; полная фраза — свобода
   реализации (прецедент gc_agent_branches.sh:273-275).
3. **Маркер атомарен по порядку.** Ставится ПОСЛЕ всех зелёных проверок;
   при любом отказе маркер отсутствует (не создаётся). Уже стоящий
   (перезапуск отложен) маркер дверь не удаляет — не её состояние.
4. **Мусорный worktree** := запись `git worktree list --porcelain` НЕ
   основного чекаута, чья ветка НЕ `refs/heads/wip/[0-9]{3}/<автор>`
   (включая detached/bare). **Расширение GC**: `scripts/gc_agent_branches.sh`
   получает ветвь мусорных worktree — чистый (porcelain worktree пуст) ∧
   приземлённый (HEAD-коммит worktree достижим из HEAD) мусорный worktree
   УДАЛЯЕТСЯ самим GC (rc 0); неудаляемый мусор GC называет в stderr
   фразой «мусорный worktree: <путь>» и возвращает rc 1; легальные wip и
   реестр/reflog-грация/TMP-РЕАП/SWEEP не тронуты (их замороженные
   фикстуры зелёны, scoped-прогон — в приёмке). **Делегирование**: дверь
   запускает GC СВОЕГО корня ровно командой
   `bash scripts/gc_agent_branches.sh --root <абс-ROOT>` (существующая
   ручка --root, gc_agent_branches.sh:230-235), затем ПЕРЕСНИМАЕТ список worktree: оставшийся мусор

## Модель угроз

ЗАЩИЩАЕТ:
- маркер при HEAD ≠ origin/main / грязном porcelain / красном детекторе —
  именованный отказ с причиной, маркер отсутствует (клетки честной части
  батареи);
- маркер при чужом HANDOFF-авторе — нога (в1) identity;
- маркер при HANDOFF-коммите СТАРЕЕ стартового следа — нога (в2):
  вторая сессия той же identity с несделанным HANDOFF (обход критика к1
  Б2), включая первое использование двери (инициализация следа не
  вакуумна) и связку «след поставлен, сессия перезапущена, HANDOFF
  обновлён кем-то раньше границы»;
- рестарт при отказавшей двери (маркер до/вместо проверок) —
  маркер-отсутствие в каждом отказном предикате батареи;
- накопление мусорных worktree: чистые приземлённые удаляются РАСШИРЕНИЕМ
  GC — наблюдаемо ЗАПУСКОМ GC САМОГО ПО СЕБЕ на конформном мире (прямая
  клетка г1) и инструментированным прогоном двери (внешний лог вызова);
- удаление мусорного worktree ДВЕРЬЮ мимо GC — вызов GC фиксируется
  внешним логом батареи: удалённый каталог без записи вызова = красная
  клетка (критик к1 Б3);
- удаление легальных wip-worktree — ветвь жива после зелёного прогона
  (прямая клетка GC и клетка двери);
- подмену репозитория окружением — инвариант 10 (санитизация git-env).
- (дверь перед критиком) спавн критика на красном черновике — отказ
  двери rc 1 с маркером ноги («precision-gate»/«spec-ready»/«Н-39:
  привязка стаба в прозе, строка N»), клетки ч1..ч4 батареи;
- (дверь) пару «стаб ↔ ветвь» в прозе контракта — нога (в): голая строка
  «стаб + глагол привязки (умирает|ловится|краснеет|падает) +
  клетка/вход/кейс» даёт именованный отказ с номером строки; порог
  отсекает ЦИТИРОВАННУЮ отметку (кавычки «…» „…" "…" `…`) от
  предложения — правило 8; ложное срабатывание — правка формулировки,
  не обход (слово владельца);
- (дверь) npm-проброс ноги (а): вызов ключа с запечёнными аргументами
  судит умолчальный contracts/043, а не переданный черновик — клетка s6
  (стаб с ручкой WRONG_TARGET проходит красный вход rc 0 — пойман);
- (дверь) ложное срабатывание порога на честном черновике (цитата
  отмечена, но порог её режет неправильно) — клетка ч4/стаб s4: честный
  вход обязан rc 0, стаб-флаггер отказывает — пойман.

НЕ ЗАЩИЩАЕТ:
- подделку/удаление стартового следа руками сессии — тот же класс, что
  ручной touch маркера: за границами предмета, ловец — роль/владелец;
  след — память о границе, а не удостоверение;
- слово `user.name` — не удостоверение (остаток check_zones): identity-нога
  (в1) проверяет автора, граница сессии — только ногой (в2);
- живые умолчательные литералы маркера и следа при ОТСУТСТВИИ швов —
  батарея не читает и не пишет живые пути (гигиена маркера и следа);
  правильность литералов судит ревьюер по коду (cognitive-only,
  остаточный риск назван);
- параллельную постановку маркера мимо двери (ручной touch) — за
  границами предмета; ловец — роль/владелец;
- свежесть origin/main (дверь НЕ делает fetch — дёшево и локально; живой
  пуш-маршрут — предмет 071 пары).
- (дверь) спавн критика МИМО двери (оркестратор позвал до/без rc 0) —
  за границами предмета; ловец — строка роли «критик спавнится только
  после rc 0 scripts/pre_critic.sh» и судьи;
- (дверь) перефразированную привязку стаба (вне словаря токенов/глаголов
  слова владельца) — эвристика форменна (правило 8); ловец — критик;
  расширение словаря — воля владельца;
- (дверь) подделку САМИХ гейтов-ног (правка scripts/check_precision_gate.sh
  / check_spec_ready.sh проверяемым) — входы ног не правятся (зоны),

## Остаточный риск (назван прямо)

- Первое использование двери (следа нет: первый прогон после done 072 или
  стёртый /tmp) отказывает по (в2) даже сессии, только что закоммитившей
  HANDOFF: инициализация ставит след «сейчас», коммит секундами раньше
  старее. Самоисцеляется: повторный HANDOFF-коммит этой сессии и повтор
  двери. Плата — один лишний коммит на первое использование; направление
  отказа fail-closed (вакуумная инициализация открыла бы обход S2).
- Подделка/стирание следа руками сессии — за границами предмета (тот же
  класс, что ручной touch маркера); след — память о границе, не
  удостоверение; ловец — роль/владелец.
- Умолчательные литералы маркера и следа при живом прогоне батареей не
  наблюдаемы (гигиена: живые пути не читаются и не пишутся); их
  правильность — код-ревью реализационной пачки.
- Дверь не делает fetch: origin/main судится по локальному
  remote-tracking ref; гонка «origin ушёл» — за границей (живой пуш — 071).
- gc-делегация не атомарна с переснятием списка (между GC и списком может
  появиться новый worktree): новый мусор виден СЛЕДУЮЩЕМУ прогону; окно
  названо, закрывается повтором двери (idempotent).
- эвристика Н-39 ноги (в) — ФОРМЕННАЯ (правило 8: смысл порогом не меряют):
  ловит грамматическую форму «стаб + глагол привязки + клетка/вход/кейс» в
  одной строке, а не семантику утверждения; перефразированная привязка
  («s7 выкрашивается на к9») пройдёт — ловец критик, не дверь; список
  глаголов и токенов — дословно из слова владельца, расширение словаря —
  воля владельца;
- ложное срабатывание ноги (в) на честной прозе (непроцитированная
  оговорка о стабе) — по слову владельца правка формулировки, не обход:
  цитируй отметку кавычками; конформные контракты 072 прошли ногу (в)
  (приёмка А7-ч4);
- окно между rc 0 двери и спавном критика (оркестратор обязан позвать
  критика ПОСЛЕ двери, но дверь не держит замок на сам спавн) — ловец
  строка роли + судьями; тот же класс, что ручной touch маркера;
- npm-проброс: слово владельца «npm run check:precision-gate -- .
  <contract>» осмысленен только на БЕЗАРГУМЕНТНОМ npm-ключе (нынешний
  ключ несёт запечённые аргументы 043 — проброс судит 043, нога пуста);
  реализационная пачка делает ключ безаргументным и переносит аргументы
  в ci-вызовы явно; клетка s6 батареи ловит пропуск (инвариант 15).
