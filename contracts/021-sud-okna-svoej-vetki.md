## Предмет

**Ветвь А — семантика диапазона ОТКРЫТОГО окна (С2 «ветка-дифф»).**
Сегодня (код): диапазон контракта N = frozen/contracts/N/1..done/contracts/N/1, а при
отсутствии либо недостижимости done-тега — хвост frozen/contracts/N/1..HEAD
(lib_zones.sh:157-167); обход — линейный `rev-list --no-merges` диапазона
(check_zones.sh:265-267); merge-коммиты как единицы суда пропускаются (check_zones.sh:44).
Для ПОСЛЕДОВАТЕЛЬНЫХ контрактов хвост пуст либо свой; для ПАРАЛЛЕЛЬНЫХ открытых окон
хвост одного контракта накрывает чужие коммиты — измеренная боль Н-66 (013/014).

После 021 судимое множество ОТКРЫТОГО окна N:

1. **Свои ветки — по merge-дельтам.** Для каждого merge-коммита диапазона, тело которого
   несёт маркер «чей merge» — строку `land: wip/<N>/<автор>` (примитив уже живёт:
   land_agent.sh:175, `merge --no-ff -m "land: $branch_arg"`; stdout дублирует, :254) —
   окну N принадлежат принесённые коммиты `rev-list <merge>^1..<merge>` без merge-единиц
   (дельта к первому родителю — тот же родительский примитив, что charter И-7).
2. **Прямые коммиты.** Не-merge коммиты первого-родителя линии main в диапазоне от
   авторов, объявленных в N, — против зон автора в N; код-путь check_zones.sh:263-293
   (авторы → зоны → дельта путей коммита) не меняется.

Вердикт-функция НЕ меняется: единица суда — по-прежнему не-merge коммит со своим автором
(merge-коммит как единица пропускается, его содержимое судит ревьюер — как сегодня);
меняется ТОЛЬКО множество судимых коммитов открытого окна. Линейный хвост «все не-merge
до HEAD» уходит. Окно чужого контракта не судится ПО ПОСТРОЕНИЮ: чужие рабочие коммиты
приходят в main только merge'ями со своим маркером (§9 merge-only; обкатка 019 — ноль
прямых коммитов рабочих в main, 12 land-сведений). Cross-track касание файла чужой зоны
объявляется ЗОНА-строкой СВОЕГО контракта точным именем (глобы запрещены
path_prefix_valid, прецедент 010) — без СПАСЕНО-рекурсии: суд чужого окна на этот коммит
больше не смотрит.

**Ветвь Б — признание draft-коммитов (Н-77(б), поглощение).**
Не-merge коммит, несущий дельту по пути contracts/<NNN>-<slug>.md и отмеченный тегом
выдачи `id/CONTRACT/<NNN>` (тег на САМОМ коммите; ставит оркестратор при сверке реестра —
Н-76/Н-77(а)): дельта по этому пути из суда зон выводится — легальный draft-пуск, сигнал
легальности есть тег выдачи. Та же дельта без тега судится как обычное касание вне зон.
Прочие пути того же коммита судятся по общим правилам: тег — не индульгенция на весь
коммит. Одна семантика «что судится» для staged-суда и history-аудита: страж судит
draft-пуск по ветви 2 контракта 019 (architect + следующий свободный номер,
next_id_peek), history-аудит — по тегу выдачи; номер оба читают из next_id; check_staged
и next_id НЕ правятся — их семантика верна.

**Ветвь В — мера параллельности §10 (усиление 1 владельца).**
Новый скрипт `scripts/measure_parallel_windows.sh` (имя предложено архитектором; мера, а
не барьер: 0 — параллельность окон доказана, 1 — «не параллельно» либо нечем доказать, с
именованной причиной). Вход: корень репо и два номера контрактов A,B. Окна ПЕРЕКРЫЛИСЬ
⟺ frozen/contracts/A/1 раньше done/contracts/B/1 И frozen/contracts/B/1 раньше
done/contracts/A/1 (времена коммиттеров тегов; git-история окон — единственный источник:
заморозка первого ≠ done первого). Последовательный прогон (окно B открылось не раньше
done A) → rc 1 «не параллельно» с именами и временами. Недостающий тег → rc 1 с именем
недостающего тега — пустая выборка красная, не зелёная.

**Ветвь Г — инвариант регресса (усиление 2 владельца).**
Оконная модель — СТРОГОЕ обобщение линейной: на ПОСЛЕДОВАТЕЛЬНОЙ истории (done N
закрывает окно N до открытия N+1) множества судимых коммитов и вердикты оконной и
линейной моделей СОВПАДАЮТ — ни потерянных нарушений, ни добавленных. Совпадение держится
по построению: линейный rev-list диапазона — это в точности прямые первого-родителя плюс
коммиты, принесённые merge'ями диапазона; в последовательной истории все merge'и
диапазона — merge'и самого N. Суд 013–020 неизменен: done-ветка диапазона (Н-14,
lib_zones.sh:158-164) не трогается, вердикт-функция не меняется, меняется только
наполнение открытого окна.
