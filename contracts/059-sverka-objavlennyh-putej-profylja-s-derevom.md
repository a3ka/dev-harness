Один механизм: **резолвер** (`scripts/profile_resolver.sh`) после успешного
слияния (И-5/И-6, строка `MERGED=` :516) и ДО печати merged (:587) сверяет

(:154). Расхождение → именованный отказ P-фразой в stderr, rc 1. Workshop
правки НЕ требует: он зовёт резолвер первым шагом проектной ветви
(workshop:650, до PSTATE :673, mkdir :706 и шага шаринга 058 :759) и
проксирует отказ дословно (И-11 контракта 054) — отказ срабатывает ДО
создания какой-либо структуры. Резолвер — единственный читатель обоих слоёв;
сверка в нём = единый источник семантики (Граница-6 054: второй читатель
запрещён).

## Инварианты (кодовые)

- **И-1 (сверка эффективного значения).** Верифицируется `ci.workflow` из
  MERGED (происхождение repo ИЛИ project — безразлично; правила слияния И-6
  054 не меняются). Ни один слой не объявляет `ci` (merged-ветвь отсутствует)
  → сверки нет, rc 0 (не объявлено — не судимо).
- **И-2 (грамматика пути; порядок проверок различает литералы И-3).** Значение
  обязано: (а) быть ОТНОСИТЕЛЬНЫМ путём (ведущий `/` → отказ, тот же класс
  что profilePath Граница-2 054 — абсолютный путь в версионируемом файле
  машины-зависим и не сверяем с деревом); (б) разрешаться канонизацией
  `readlink -f "$REPO_ABS/$cw"` в СУЩЕСТВУЮЩИЙ объект (пустой результат /
  несуществующий объект → «отсутствует»); (в) канонизированный путь — ВНУТРИ
  `"$REPO_ABS"/*` (`../`-побег и симлинк наружу → «вне дерева»; прецедент
  канонизации profilePath :186-225); (г) быть ФАЙЛОМ (`-f`; каталог → «не
  файл»).
- **И-3 (именованные отказы, литералы байт-в-байт).** Все фразы начинаются
  `profile ОТКАЗ: ` (P-класс резолвера, проксируется И-11), по одной на
  строку stderr, rc 1, значение названо:
  - АБС: `ci.workflow обязан быть относительным путём от корня репо, получен абсолютный: <CW>`
  - ОТСУТСТВУЕТ: `объявленный путь отсутствует в дереве репо: ci.workflow=<CW> от корня <REPO_ABS>`
  - ВНЕ ДЕРЕВА: `ci.workflow выходит за корень репо после канонизации: <CW> -> <CANON> вне <REPO_ABS>`
  - НЕ ФАЙЛ: `объявленный путь не файл: ci.workflow=<CW> — каталог`
- **И-4 (точка в потоке).** Сверка стоит ПОСЛЕ `MERGED=` и ДО `printf '%s\n'
  "$MERGED"` — отказ атомарлен: stdout пуст, merged не напечатан. Ошибки
  схемы/пинов 054 срабатывают раньше и не меняются.
- **И-5 (probe = live).** Резолвер вызывается workshop в обоих режимах одним
  кодом (054 Граница-3): сверка работает и в `--probe` (дорогая проверка на
  дешёвом этапе — до раскладки ролей и omp).

## Frontier: границы и отвергнутые варианты

- **Граница-1 (верифицируемое множество = `ci.workflow`).** Единственный
  класс объявленных путей, утверждающий СУЩЕСТВУЮЩУЮ инфраструктуру проекта.
  ОТВЕРГНУТО сверять `workflowPaths.*`: это ЦЕЛЕВАЯ раскладка harness
  (создаётся автобутстрапом II-3, который в очереди ПОСЛЕ 059), в живом
  дереве odelix-stack `.harness/contracts|registry|fixtures` отсутствуют
  (проверено ls 2026-09-29) — сверка дедлокнула бы запуск пилота. Сверка
  целевой раскладки поедет вместе с её потребителями (II-2/II-3).
  ОТВЕРГНУТО сверять `git.canonicalRemote` (URL, не путь дерева) и
  `commands.*` (команды). Потребителей workflowPaths на HEAD нет —
  единственный потребитель merged сегодня projectId (workshop:663).
- **Граница-2 (резолвер, не workshop).** ОТВЕРГНУТА сверка в workshop по
  повторному чтению merged — второй источник истины (Граница-6 054).
- **Граница-3 (канонизация ДО принадлежности).** Симлинк внутри репо на цель
  вне репо — расхождение (канонизированный путь вне `REPO_ABS/*`); «существует
  по склейке» (`-e` без канонизации) недостаточно.
- **Граница-4 (файл, не каталог).** CI-workflow — файл; каталог на месте
  объявления = разрыв того же класса.

## Приёмка (сценарии; грамматика 050)

- дано: toy-репо+слой объявляют `ci.workflow=".github/workflows/ci.yml"`,
  файла нет; когда: `bash scripts/profile_resolver.sh --repo <repo>` (env
  `HARNESS_PROJECT_LAYER_ROOT`); тогда: rc 1, stderr содержит литерал И-3
  «объявленный путь отсутствует в дереве репо: ci.workflow=» (grep -F).
- дано: то же + файл создан; когда: та же команда; тогда: rc 0 и
  `jq -r '.ci.value.workflow'` stdout = объявленное значение дословно.
- дано: `ci.workflow="/etc/hostname"`; когда: та же команда; тогда: rc 1,
  stderr `grep -F 'обязан быть относительным'`.
- дано: `ci.workflow="../../escape.yml"`, файл вне репо существует; когда:
  та же команда; тогда: rc 1, stderr `grep -F 'выходит за корень репо'`.
- дано: объявленный путь — симлинк на файл вне репо; когда: та же команда;
  тогда: rc 1, stderr `grep -F 'выходит за корень репо'`.
- дано: объявленный путь — каталог; когда: та же команда; тогда: rc 1,
  stderr `grep -F 'не файл'`.
- дано: ci не объявлен ни репо, ни слоем; когда: та же команда; тогда: rc 0
  (в merged нет ветви ci).
- дано: toy-репо с git+pin+.env, ci объявлен, файла нет; когда:
  `env XDG_STATE_HOME=<base> HARNESS_PROJECT_LAYER_ROOT=<layer> bash workshop
  --probe <repo>`; тогда: rc 1, stderr несёт отказ резолвера (grep -F
  `ci.workflow`) И отсутствует `<base>/dev-harness-projects/<projectId>`
  (сверка в дешёвой фазе, структур нет).
- правило: `bash fixtures/check_judge_gate/red_sverka_puti_profylja.sh`;
  rc 0 после реализации (стаб-пак 6/6 + честные клетки зелёные); на HEAD
  rc 1 (красная).
- правило: после правки toy-миров `bash fixtures/_krasnye_058.sh` остаётся
  rc 0 (регресс соседней семьи закрыт созданием объявленных файлов).
