# Контракт 223 — ARCH_CI v2: `.review/` — служебный путь подъёма SHA* в двери done

СТАТУС: ЧЕРНОВИК-ЗАТРАВКА (bootstrap: `make_task --role architect` требует существующий `contracts/223-*.md`; текст контракта пишет architect по заданию станции — затравка не является ни спекой, ни критерием; заменяется целиком).

## Боль
Слово владельца 2026-11-24 ~22:00 UTC (через консультанта, дословно): «ARCH_CI v2 да».
Измерено 24.11: `done_contract.sh` (блок ARCH_CI, `:361–377`) поднимает SHA* по первому родителю только через merge с дельтой `.harness/*`. Вердикт-PR бэкенда несёт `.review/<дата>.md` (штатный артефакт ревьюера, `status: ready`) — merge считается продуктовым, SHA* остаётся на нём, check-run `arch` на push-прогоне такого merge отсутствует → отказ `ARCH_CI: … успешного check-run arch нет` (done 177/6 бэкенда, 24.11 ~17:55 UTC, main 09f8ba63; с тех пор ещё три merge — #1033, #1034, #1036 — отказ не сняли). Касается почти каждого done бэкенда с ревьюером.

## Решение
Кодовый контракт: в подъёме SHA* двери done служебными считаются пути `.harness/**` И `.review/**` (граница каталога: `.reviewx/…` — не служебный); остальное поведение ARCH_CI неизменно (чужой SHA, отсутствующий, красный, skipped — отказ). Реши: форма списка служебных путей (одна константа/функция), совместимость с 187а/201(г), ПРОВОДКА.
