# Контракт 001 — фикстурный контракт анти-плацебо

Номер выдан механизмом: `bash scripts/next_id.sh CONTRACT` → `001`, тег `id/CONTRACT/001`.

РАБОТА НЕ РАЗДАЁТСЯ: контракт кодифицирует уже действующее соглашение, по нему не раздаётся ни
одного задания.

Статуса задач в этом файле НЕТ и не будет: контракт заморожен ПОБАЙТОВО, поэтому изменяемого
состояния в нём быть не может — `check_contract_frozen.sh` отвергнет любую правку без новой
заморозки. Ход работ живёт в `HANDOFF.md`. Во внешнем проекте, откуда взят образец, dev правит
колонку Status прямо в milestone-файле; у нас это отказ барьера.

## Предмет

Соглашение о фикстуре анти-плацебо: что обязана делать фикстура, чтобы предъявление барьера
красным считалось состоявшимся. Сегодня это соглашение живёт ТОЛЬКО в шапке
`scripts/verify_antiplacebo.sh`, то есть в комментарии одного скрипта. Комментарий не является
контрактом: его читает тот, кто уже открыл файл, и он не переживает переписывание скрипта.

Взято первым предметом потому, что соглашение УСТОЯЛОСЬ: его переписывали трижды (подделка записи
о вызове, подделка окружения, схлопывание пустого аргумента), и последняя редакция держит 98
фикстур. Контракт, замороженный раньше, чем предмет устоялся, ломает процедуру на первом же
применении.

## Соглашение — дословно

Фикстура живёт в `fixtures/<ключ барьера>/case_*.sh`, где ключ есть путь внутри `scripts/` без
расширения, `/` → `.` (`lib/verify_x.sh` → `lib.verify_x`).

| элемент | смысл |
|---|---|
| `# ПРИЧИНА: <подстрока>` | что барьер печатает, КРАСНЕЯ, и чего НЕ печатает на зелёном |
| `# ОКРУЖЕНИЕ: NAME=VALUE` | необязательно, можно несколько; подстановка только `$WORK`, `$REPO`, `$PATH` |
| `$BARRIER` | клиент канала. Вызов барьера иным путём не считается вовсе |
| `$WORK` | пустой каталог фикстуры. Дерево репозитория трогать нельзя |
| `$REPO` | корень, откуда можно копировать |
| `BARRIER_ROOT=$WORK` | барьер, привязанный к своему каталогу: проверяющий положит туда его побайтовую копию и запустит её |

Роль файла в `scripts/` объявляет он сам ШАПКОЙ — первым непрерывным блоком комментариев:
`Коды возврата: 0 — …, 1 — …, 2 — …` означает барьер (нужна фикстура), `НЕ БАРЬЕР: <почему>` —
вне области явно и с записанной причиной. Неразобранное объявление — отказ кодом 1 с названным
местом.

Код 2 (`NOT_IMPLEMENTED`) красным НЕ считается и считается провалом фикстуры: «нечем проверить» не
равно «проверено», иначе внесённое нарушение прячется под нехватку инструмента.

## Критерий готовности

Соглашение считается соблюдённым, когда выполнены три условия, и каждое доказывается КОМАНДОЙ с
кодом возврата, а не чтением:

1. **Каждый барьер предъявлен красным.**
   `rm -rf tmp/antiplacebo && bash scripts/verify_antiplacebo.sh` → 0.
   Барьер без фикстуры, фикстура без барьера, барьер, оставшийся зелёным на обманном дереве, и
   фикстура без положительного контроля — всё это код 1 с названным местом.

2. **Красное предъявлено ПОВТОРНЫМ прогоном проверяющего**, а не записью фикстуры о себе. Это
   свойство самого проверяющего: он повторяет запомненные argv, каталог, подставной корень и
   объявленное окружение. Проверяется тем же прогоном пункта 1 — в его выводе у каждой фикстуры
   стоит «повторный прогон красный кодом N».

3. **Дерево вне `$WORK` не изменилось** за прогон. Слепок по содержимому и в памяти
   проверяющего; расхождение — код 1 со списком файлов. Проверяется тем же прогоном.

Чего этот критерий НЕ обещает, названо прямо: механизм не судит, ОТНОСИТСЯ ли обманное состояние к
предмету барьера — фикстура может ронять его посторонним. Против этого положительный контроль
(отсекает вечно-красное) и чтение кода двумя ролями. Помечено `cognitive-only`.

## Исполнители и зоны

`РАБОТА НЕ РАЗДАЁТСЯ` — см. первую строку файла. Соглашение действует для ВСЕХ, кто пишет
фикстуры: архитектора, исполнителя, адверсария. Зона появится в первом контракте, который
действительно раздаётся.

## Приёмка

Команды из `package.json`, каждая с кодом возврата:

- `npm run check:antiplacebo` → 0;
- `npm run check:ci-parity` → 0: барьер вне CI не барьер, и приёмка не имеет права быть богаче CI
  молча.

## Что этот контракт заменяет

Ничего не заменяет и ничего не добавляет к поведению: шапка `verify_antiplacebo.sh` остаётся
рабочим текстом механизма. Контракт даёт соглашению ДРУГОЕ качество — его нельзя изменить молча:
после заморозки правка требует нового вердикта критика и строки `РАЗРЕШИЛ-ВЛАДЕЛЕЦ:` в изменяющем
коммите.
