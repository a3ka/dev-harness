## Предмет и инварианты

Один результат: узкое исключение карты данными и обязательная та же дверь при материализации критика, в объёме R-0168. Production исполняет implementer после freeze; эта пачка — контракт, исполняемый эталон, оракул и красные предъявления.

1. Источник — **установка**: `registry/karta-exceptions.json`, версия 1; схема `registry/karta-exceptions.schema.json`. Код/реестр из проверяемого ROOT, env, staged или рабочего файла автора запасным источником не являются. CLI не получает флагов отключения карты. В установке deploy ревизии кода и данных един; изменения реестра проходят штатный review, не разрешаются автору проверяемого вердикта.
2. Формат — JSON-объект ровно `version`, `exceptions`; exceptions — массив записей ровно `blob`, `call`, `map`, `reason`, `author`, `date`, `owner_ref`. blob — полный lowercase `^[0-9a-f]{40}$`, без префиксов/масок/регистрового приведения. call — `^[1-9][0-9]*$`; map — 17 самостоятельных строк К-01…К-17 без CR/LF в элементе, в исходном порядке. reason/author непустые JSON-строки; date — YYYY-MM-DD; owner_ref — `^R-[0-9]{4}$`. Разделители JSON не переиспользуются как данные без штатного escaping; сравнения идентичности буквальные, не regex из входа. Лишние ключи, дубли JSON-ключей и blob запрещены. Канон схемы и первой записи — model/karta-exceptions.schema.json и model/karta-exceptions.json семьи.
3. Отсутствующий реестр либо валидный `{"version":1,"exceptions":[]}` — исключений нет. Пустой файл не равен пустому массиву. Нечитаемый/битый JSON, неверная версия/схема, отсутствующая/битая схема при наличии реестра, дубли, неконформная нормализация — rc 1 с `KARTA_REGISTRY_INVALID:` (через дверь — её штатное `ОТКАЗ:`). Проверка формата — JSON Schema через validate_std; уникальность ключей/blob и происхождение нормализации проверяются дополнительно. Нет fallback «принять всё».
4. При точном совпадении **исходного Git blob** карта для текущего HEAD-вердикта, индекса исторических вызовов и последнего FAIL берётся из map; её разбирает штатная `karta_stroki`, раскрытие — прежнее `karta_raskryt`. Хранится исходный blob для дедупликации/неоднозначности. Ни исходные байты Git, ни OBJECT, ни первая строка FAIL/accept не переписываются. Разные blob-ы одного номера остаются неоднозначностью. Не перечисленный blob использует прежнюю грамматику без нормализующего обхода.
5. Эквивалентность проверяется **побайтным равенством** map детерминированному результату извлечения исходных К-строк только из `## Карта классов` до следующего `## `. Разрешены только: у самостоятельной явной ссылки `без изменений с вызова N, кроме X` заменить `, ` на ` — `, сохранив `кроме X`; у `без изменений с вызова N; X` заменить `; ` на ` — `; у прямого `чисто в измеренных границах — X` удалить ровно ` в измеренных границах`. N, X и остальные строки остаются побайтно прежними. Прямые `блок|чисто|н/п`, ссылочность, класс, целевой номер, доказательный хвост и порядок не заменяются. Для К-15 получается `К-15: чисто — таблица счётных утверждений выше.`. Нормализованный результат дополнительно обязан быть штатной картой 193; правило не является грамматикой для незарегистрированных входов.
6. Первая живая запись — только blob 0c079b17b3d1a3fee5cf58c5daf19ea9c156d713, call 6, причина/автор/дата/R-0168 и литеральные 17 строк normalized178.json. Добавление другой допустимой записи меняет только конфиг; удаление записи возвращает прежний отказ. Изменение хоть одного байта образца (включая пустую строку вне карты) создаёт другой blob и не наследует исключение. Другой путь **с теми же байтами** имеет тот же Git blob и законно принимается; путь не часть content-addressed ключа. Другой путь с другим blob не принимается. Другой регистр/префикс ключа — ошибка схемы, не альтернативная идентичность.
7. `scripts/pre_judge.sh verdict --repo R --file V` после прежних границ и до успешного `VERDICT_BRANCH=` для critic-ветки **или critic-пути** вызывает установленный рядом `scripts/check_verdict_karta.sh R VREL`. Все решения (FAIL и accept) и все вызовы судятся одинаково. rc 0 карты → прежний успех. Любой ненулевой rc карты → rc 1 pre_judge, первая строка stderr ровно `ОТКАЗ: KARTA_NE_SHTATNA`, следующая содержит `карта не штатная` и причину двери; stdout пуст. Нет обхода через timeout, SDACHA_OKRUG, другую роль ветки при critic-пути или локальный fake в ROOT. Неизвестный `--skip-karta` отвергается прежним usage rc 2. Прочие роли без critic-пути и режимы prepare/sync-main/archive сохраняются.
8. HEAD-only обеих дверей, effective workflowPaths, прежние синтаксические отказы и фазовые/графовые свойства 193/204 сохраняются. Новые ссылки с запятой/точкой с запятой и квалифицированное `чисто` вне реестра по-прежнему красны. Статический census доказывает только пересечение зон; поведение/происхождение карты доказывают живые команды и полная литеральная карта в памяти до субъекта.

## Модель угроз

ЗАЩИЩАЕТ:
- от расширения исключения на другой blob: полный lowercase ключ, буквальное равенство, позитивная/негативная пара при конфиг-only изменении;
- от перекраски и произвольной нормализации: равенство детерминированному результату исходного blob плюс прежний валидатор, раскрытая карта целиком;
- от ранней материализации новой нештатной карты: обязательный реальный check_verdict_karta в pre_judge, до stdout успеха, без условности решения/вызова и без подмены кодом проекта;
- от конфигурационного fail-open: закрытая JSON Schema, уникальность, именованный отказ и отсутствие запасного источника.
НЕ ЗАЩИЩАЕТ:
- от ложного содержательного суждения критика; ловцы critic/reviewer;
- от злонамеренного изменения доверенной установки/реестра полномочным писателем; ловцы изоляция, review и обычный deployment;
- от иных исторических форматов вне реестра или отсутствующих исходных вызовов; прежняя дверь отказывает, новый предмет требует отдельной санкции.

## Не защищает

Не вводит свежесть done, новое имя/грамматику СУД для новых вердиктов, новую фазовую модель и проверку достаточности доказательств. Ловцы — 193/204/224 и судьи. Конечная батарея не доказывает все значения: валидный контрпример — конформный JSON/вердикт с инвариантностью к значениям и наблюдаемым расхождением; сломанный мир/инструмент не дефект продукта. Для исторического нечислового вызова доверяется адресной call-записи конфигурации, её историческую истинность судит reviewer, не расширенный regex СУД.
