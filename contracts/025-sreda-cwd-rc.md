### Пачка B — pipefail + маркер (Г4)

**B-1. Extension rc-prefix (.omp/extensions/rc-prefix.ts) — носитель env
PI_SHELL_PREFIX.** Схема настроек билда ключа prefix НЕ ИМЕЕТ (замер круга 2:
`omp config list --json` — 453 ключа, из «prefix» только нерелевантный
hindsight.bankIdPrefix; пробы `bash.prefix` / `prefix` / `shell.prefix` /
`bash.commandPrefix` → каждая rc 1 Unknown setting). Реальный носитель — env
`PI_SHELL_PREFIX` («Optional command prefix wrapper», omp://environment-variables.md):
executor харнеса оборачивает КАЖДУЮ bash-команду значением этой переменной — у
ГЛАВНОЙ и у ДОЧЕРНИХ сессий (B3: launch-env дошёл до ребёнка; D: extension-присвоение
дошло до ребёнка при снятом launch-env). **Кто выставляет: extension rc-prefix при
загрузке** — default-export factory присваивает `process.env.PI_SHELL_PREFIX`
(пруф D: носитель полностью в-деревен, работоспособен без launch-env). ЕДИНЫЙ
ИСТОЧНИК значения — ЭТА строка контракта; модуль несёт её ПОБАЙТОВО:

```
set -o pipefail; trap '[ "$?" -eq 141 ] && exit 0' EXIT;
```

Семантика (живые пробы A/C3/D круга 2, все исходы из прогонов): rc пайплайна = rc
ПЕРВОГО упавшего элемента (форма Н-84 `… | tail` умирает красным: `false | true` →
ОШИБКА у главной И у ребёнка); агрегат 141 (SIGPIPE-смерть продуцента при раннем
закрытии потребителя) маппится в 0 — Г4-кавер: `yes | head -1` → УСПЕХ у главной и
ребёнка, `grep -q <нашёл>` → 0, `git log | grep -q <ранний матч>` → 0; произвольные
коды не тронуты (`exit 7` → 7); голая смерть от SIGPIPE-сигнала остаётся 141.
Названный остаток маппинга (Р3): продуцент, УПАВШИЙ реальной ошибкой и ДОБИТЫЙ
SIGPIPE, агрегируется в 141 → 0 — ловец: маркер B-2 (судья видит [exit=141]) и
детектор 024. Префикс НЕ ставит `set -e`. Контроль: без носителя `false | true` →
УСПЕХ rc 0 (замер круга 2).

**B-2. Extension exit-marker (.omp/extensions/exit-marker.ts) — для всех сессий,
грузящих расширения (главные и дочерние — B3/B4).** tool_result-патчер: в КАЖДЫЙ
bash tool_result дописывает строку `[exit=N]` из details харнеса (details.exitCode —
независимая от эха агента мера; omp://bash-tool-runtime.md). rc=0 с лживым
`echo rc=1`/`echo rc=0` в выводе расходится с маркером — видимо судье по стенограмме.

**B-3. Г4-кавер (зонд-файл, запускаемая rc-форма).** Живые сессии MAIN и CHILD в
одноразовом клоне дерева-субъекта: `false | true` обязан умереть ОШИБКОЙ;
`yes | head -1` и чтение `grep -q` обязаны НЕ краснеть (ложная краснота легитимных
паттернов = БЛОКЕР, слово владельца). Носитель файла — И-6.

(Г1: страж целит вектор, не тотальность записи; относительная запись и в главной

## Демаркация конформности (с первой редакции — урок 019)

Конформный вход среды построен по документированной грамматике:

- пути записи: абсолютные, резолвящиеся ВНУТРИ пинна, либо в allowlist Г3
  (`${TMPDIR:-/tmp}/dev-harness-verify/**`, `artifact://` и внутренние URI);
- чтения: любые пути, любые формы, без cwd — свободны (Г3 «читать свободно»);
- bash: с cwd-параметром (абсолютным) ИЛИ с абсолютными операндами записи;
  пайпы любые, включая ранний выход потребителя (grep -q, | head — Г4-легитимны);
- edit/write: абсолютный путь; несуществующий файл в-пинне — конформен (создание).

НЕконформные (вектор утечки — предмет стража): edit/write с относительным path;
bash-запись с относительным операндом без cwd; запись в основной чекаут И чужие
worktree (в т.ч. абсолютным путём — следствие А-72); несуществующий пинн WORKTREE;
пинн, расходящийся с фактическим рабочим деревом сессии.

Валидный контрпример = инвариантность к значениям ∧ расхождение честной и слабой
реализации НА КОНФОРМНОМ входе (арбитражи ebc57db — значения, fa0d354 — грамматики).
Инвариантность к значениям — требование к red-входам КОДОМ: пути и имена — из
mktemp/$RANDOM, не константы; стаб, честный на входе ветви, красноты на нём не
требуется (Н-39: не требовать ЛЖИ в диагнозе). Слабые формы, которые серия обязана
убить (матрица прогнана кругом 2, дерево-декои в /tmp/dev-harness-verify/025/matrix/):
«process.exit(0) + мёртвый prefix: + deny-комментарии» (ТОЧНЫЙ обход критика —
умирает на всех пяти), «judge всегда pass» (умирает на блок-ветвях И-1/И-5), «judge
всегда block» (умирает на канарейках И-1 и границах пина И-5), «маркер лжёт
[exit=0]» (умирает на кодах 7/141/1 И-4), «пин лексический без realpath» (умирает
на ../ и симлинке И-5), «deny `*`» (умирает на канарейках чтения И-3), «три deny не
про ночь» (умирает на ночных формах И-3), «rc-prefix присваивает мёртвую строку»

- **Р1. Extension-недостижимость для дочерних — ЗАКРЫТО кругом 2** (B3/B4/D;
  А-112 исправлен). Остаток upstream: загрузка USER-каталога расширений у детей не

  из проектного config.yml дошло до ребёнка именованным отказом). Раскатка по
  сессиям — Р5.
- **Р3. 141-маппинг глотает реальную неудачу продуцента при раннем закрытии
  потребителя** (проверено кругом 1: класс входа существует; seq-продуцент ловит

  преднамеренно отвергнута: ложная краснота ВСЕХ ранних выходов (А-111: 200/200 на
  раннем матче) — блокер по слову владельца.
- **Р4. deny-паттерны — строковый матчинг,** не семантика путей: паттерн может
  пропустить обходную форму записи (heredoc-редирект, eval-обёртка) или
  ложноблокировать редкую легитимную форму. Граница меряется батареей реализации
  (ночные формы умирают, легитимные проходят); это ВТОРОЙ слой (первый —
  extension, третий — детектор 024).
- **Р5. Раскатка настроек — по сессиям:** deny-слой (A-2) оживает только у сессий,
  стартованных ПОСЛЕ приземления config.yml (снимок родителя). Зонд И-6 гоняют в
  свежей сессии; существующие долгие сессии не ретроактивны. На extension-слой
  (A-1/B/C) не распространяется — грузится из дерева на старте каждой сессии.
- **Р6. Подозрение: расширения 015 (gate-draft, startup-digest) — живые no-op.**

  билд не эхит команду первой строкой — молчаливый не-гейт). Предмет отдельного
  расследования (А-113); 025 НЕ чинит и НЕ полагается на эти модули.
- **Р7. Single-uid identity:** настройки и extension не различают авторов;
  страж судит по форме вызова, не по личности — тот же cognitive-only класс, что

- **Р8. eval-канал дочерних сессий.** Дети могут исполнять команды инструментом
