### Пачка A — страж вектора утечки (Г1, Г2)

**A-1. Extension path-guard (.omp/extensions/path-guard.ts) — для сессий, грузящих
расширения.** tool_call-перехват (omp://extensions.md: pre-exec, `{block:true,

вызов — fail-closed). ЦЕЛИТ ВЕКТОР УТЕЧКИ, НЕ «любой bash без cwd» (Г1 дословно):

- edit/write с ОТНОСИТЕЛЬНЫМ `path` → блок «относительный путь записи запрещён —
  Н-85: абсолютный путь или cwd»;
- bash-команда ФОРМЫ ЗАПИСИ (sed -i / >/>>/printf >>/tee/cp/mv/rm с файловым
  операндом) с ОТНОСИТЕЛЬНЫМ операндом И без cwd-параметра → блок «запись
  относительным путём без cwd запрещена — Н-85»;
- запись АБСОЛЮТНАЯ в-пинне → пропуск; вне пинна → пин-ветвь (пачка C);
- ЧТЕНИЯ (read/grep/glob/bash без формы записи) → ПРОПУСК ВСЕГДА, в т.ч. из корня

Модуль несёт `--selftest` (прецедент scripts/proxy/metering_proxy.ts --selftest):
синтетические tool_call-события против handler'а; грамматика событий и входы —
в шапке scripts/drill_path_guard.sh (Н-39: привязка стабов к ветвям — по коду
инструментов, НЕ проза контракта).

**A-2. Settings deny-паттерны (.omp/config.yml, bash.patterns) — единственный
носитель, досягаемый для ДОЧЕРНИХ сессий.** Правила deny на баш-запись с
ОТНОСИТЕЛЬНЫМ операндом — ночные формы: sed -i, перенаправление >/>>, printf >>,
tee. Точные паттерны — реализация с красно/зелёной батареей (ночные формы обязаны
умирать именованным отказом; легитимная запись АБСОЛЮТНЫМ путём в-пинне — проходить;
чтения — проходить). Секция маркирована строкой-комментарием
`# ── СТРАЖ ЗАПИСИ (контракт 025)` и несёт НЕ МЕНЕЕ ТРЁХ раздельных deny-правил
(по одному на класс операнда ночного канала). Досягаемость до детей — через
snapshot-цепь настроек (замер — И-6.2).

### Пачка B — pipefail + маркер (Г4)

**B-1. Settings pipefail-префикс (.omp/config.yml, ключ `prefix:` в bash-секции;
точное имя ключа этого билда — за реализацией, frontier-остаток).** ЕДИНЫЙ
ИСТОЧНИК — ЭТА строка контракта; config несёт её ПОБАЙТОВО:

```
set -o pipefail; trap '[ "$?" -eq 141 ] && exit 0' EXIT;
```

Семантика, проверенная живым прогоном этой пачки (все шесть входов): rc пайплайна =
rc ПЕРВОГО упавшего элемента (форма Н-84 `… | tail` умирает красным); агрегат 141
(SigPIPE-смерть продуцента при раннем выходе потребителя) маппится в 0 — Г4-кавер:
`seq 1 100000 | head -1` → 0, `git log | grep -q <ранний>` → 0, `grep -q <нашёл>` →
0; произвольные коды не тронуты (`exit 7` → 7); голая смерть от SIGPIPE-сигнала
остаётся 141 (не замаскирована). Названный остаток маппинга: продуцент, УПАВШИЙ
реальной ошибкой и ДОБИТЫЙ SIGPIPE при раннем закрытии потребителя, агрегируется
в 141 и уходит в 0 — ловец: маркер B-2 (судья видит [exit=141]) и детектор 024.
Префикс НЕ ставит `set -e` (легитимные ненулевые потоки не ломаются).

**B-2. Extension exit-marker (.omp/extensions/exit-marker.ts) — для сессий, грузящих
расширения.** tool_result-патчер: в КАЖДЫЙ bash tool_result дописывает строку
`[exit=N]` из details харнеса (details.exitCode — независимая от эха агента мера;
omp://bash-tool-runtime.md). rc=0 с лживым `echo rc=1`/`echo rc=0` в выводе
расходится с маркером — видимо судье по стенограмме. Несёт `--selftest`.

**B-3. Г4-кавер (зонд).** В свежей сессии (после приземления настроек) И в её
дочерней: `false | true` → ОШИБКА tool_result; `seq 1 100000 | head -1` → НЕ
ошибка; `git log --oneline | grep -q <ранний матч>` → НЕ ошибка; `… | grep -q
<мимо>` → ошибка. Ложная краснота легитимных паттернов = БЛОКЕР (слово владельца).

## Демаркация конформности (с первой редакции — урок 019)

Конформный вход среды построен по документированной грамматике:

- пути записи: абсолютные, resolвящиеся ВНУТРИ пинна, либо в allowlist Г3
  (`${TMPDIR:-/tmp}/dev-harness-verify/**`, `artifact://` и внутренние URI);
- чтения: любые пути, любые формы, без cwd — свободны (Г3 «читать свободно»);
- bash: с cwd-параметром (абсолютным) ИЛИ с абсолютными операндами записи;
  пайпы любые, включая ранний выход потребителя (grep -q, | head — Г4-легитимны);
- edit/write: абсолютный путь; несуществующий файл в-пинне — конформен (создание).

НЕконформные (вектор утечки — предмет стража): edit/write с относительным path;
bash-запись с относительным операндом без cwd; запись в основной чекаут И чужие
worktree (в т.ч. абсолютным путём — следствие А-72); несуществующий пинн WORKTREE.

Валидный контрпример = инвариантность к значениям ∧ расхождение честной и слабой
реализации НА КОНФОРМНОМ входе (арбитражи ebc57db — значения, fa0d354 — грамматики).
Инвариантность к значениям — требование к red-входам КОДОМ: пути и имена — из
mktemp/$RANDOM, не константы; стаб, честный на входе ветви, красноты на нём не
требуется (Н-39: не требовать ЛЖИ в диагнозе). Слабые формы, которые серия обязана

## Остаточные риски, названные прямо

- **Р1. Extension-носитель недостижим для дочерних task-сессий (з1-а, два раунда).**
  Аудитория ночных утечек прикрыта только A-2 (баш-вектор) + B-1 (rc) через
  snapshot-цепь; edit-вектор в детях (форма Impl022fix:228) механизмом НЕ
  прикрыт — ловится детектором 024 пост-фактум и интерим-дисциплиной. Закрытие
  upstream'ом (грузить расширения в дочерних) расширит coverage без переделки
  контракта — монитором И-6.3.
- **Р2. Snapshot-цепь настроек до детей — док-основание, не замер** (замер
  невозможен до существования настроек: снимок наследуется от родительской
  сессии, стартовавшей до правки). И-6.2 меряет её первым; недостижимость =
  доклад блокера (Г4-слово владельца про ложную красноту тут ни при чём — но
  без цепи B-1 в детях мёртв, останется маркер B-2 только для главных сессий).
- **Р3. 141-маппинг глотает реальную неудачу продуцента при раннем закрытии
  потребителя** (проверено: класс входа существует). Ловец: маркер [exit=141]
  судье по стенограмме + детектор 024. Альтернатива (не маппить) преднамеренно
  отвергнута: ложная краснота ВСЕХ ранних выходов (А-111: 200/200 на раннем
  матче) — блокер по слову владельца.
- **Р4. deny-паттерны — строковый матчинг,** не семантика путей: паттерн может
  пропустить обходную форму записи (heredoc-редирект, eval-обёртка) или
  ложноблокировать редкую легитимную форму. Граница меряется батареей реализации
  (ночные формы умирают, легитимные проходят); паттерны НЕ претендуют на
  полноту — это второй слой, не единственный (первый — extension в главных,
  третий — детектор 024).
- **Р5. Раскатка настроек — по сессиям:** цепь до детей оживает только у сессий,
  стартованных ПОСЛЕ приземления config.yml (снимок родителя). Зонд И-6.2 гоняют
  в свежей сессии; существующие долгие сессии не ретроактивны.
- **Р6. Подозрение: расширения 015 (gate-draft, startup-digest) — живые no-op.**
  Черновики отсутствуют вовсе при живых падающих гейтах в сессиях оркестратора
  (каталог /tmp/dev-harness-nabludenia не создан ни разу); конфаунд —
  payload-форма (gate-draft.ts:49-51 берёт команду из ПЕРВОЙ строки content
  tool_result; если билд не эхит команду первой строкой — молчаливый не-гейт).
  Предмет отдельного расследования (А-запись этой пачки); 025 НЕ чинит и НЕ
  полагается на эти модули.
- **Р7. Single-uid identity:** настройки и extension не различают авторов;
  страж судит по форме вызова, не по личности — тот же cognitive-only класс, что
  у всей системы (правило 11).
