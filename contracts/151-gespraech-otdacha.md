## Предмет и инварианты первой реализации

Один результат сейчас: `mobile/src/lib/otdacha/index.ts` экспортирует `patternFor(scene, at)` и асинхронный `playHaptic(scene, at, policy)`; `mobile/package.json` и lockfile содержат установленную совместимую с Expo зависимость `expo-haptics`. Входы `scene` и `at` — идентификатор и точный числовой момент из дизайнерского haptics.json, не порог прошедшего времени. Карта — внутри `mobile/src/lib/otdacha/`, без импорта файлов батареи; проба сверяет её с дизайнерским оракулом. `patternFor` возвращает `{ios, android}` из записи или `null` при отсутствующей паре; повторяющаяся сцена различается моментом. Это единственная точка тактильной отдачи для будущих экранов; без React-компонентов, подключения к меню или earcons в первой поставке. Файлы пробы лежат вне каталога субъекта под случайным именем, а модельный `oracle.json` в `--repo` отсутствует.

- И-1. Вся карта из оракула: основной набор GA-T содержит 16 разных сцен; эталонные GA-R2/R2-393/R3/R3-393 имеют свои моменты, а не перезаписывают предыдущие. Выбор платформы: iOS light/medium → `impactAsync(Light|Medium)`, selection → `selectionAsync()`, warning/success/error → `notificationAsync(Warning|Success|Error)`; Android VIRTUAL_KEY/CONTEXT_CLICK/LONG_PRESS/CLOCK_TICK/REJECT/CONFIRM → `performAndroidHapticsAsync` с одноимённым `AndroidHaptics` enum. Никаких `Vibration.vibrate()` и синтетических звуков. Для каждой сцены и платформы вне точного множества её моментов `patternFor` = `null` и вызовов SDK нет: проверяется каждая точка решётки — целые миллисекунды от −1 до последнего момента оракула +1 и четверти миллисекунды в диапазоне собственных моментов сцены ±1. Остаток вынесен в НЕ ЗАЩИЩАЕТ.
- И-2. `policy = { platform: 'ios'|'android', enabled: boolean, vibrationEnabled: boolean, quietMode: boolean }`; для каждой записи и обеих платформ SDK вызывается ровно один раз тогда и только тогда, когда `enabled === true && vibrationEnabled === true && quietMode === false`. Отсутствующий, `undefined` или `null` любого из трёх флагов подавляет эффект. Политика обязательна и поступает от вызывающего хоста; модуль не фабрикует «разрешено» при неизвестном флаге. Нативный SDK дополнительно подчиняется запрету Taptic Engine/vibration на устройстве, даже если прикладная политика разрешает; earcons модуль не воспроизводит.
- И-3. Модуль не строит таймер: GA-T35 испускается при вызове на `at=500` после распознанного удержания, не на touch-down; GA-T21/T22 и повторные эталоны — тот же принцип. Ранний `at=0` вместо 500 даёт `null`. Промис `playHaptic` остаётся pending, пока промис Expo удерживается `HOLD_MS=1000` мс реального времени, затем разрешается вслед за ним и передаёт его отказ хосту без проглатывания; проверяются все четыре метода SDK. Отключённое состояние завершается без SDK.
- И-4. Версия `expo-haptics` в package.json равна диапазону установленного Expo `bundledNativeModules.json`, версия в lockfile удовлетворяет диапазону и совпадает с установленным пакетом, запись lock имеет `resolved` и `integrity`. Продуктовый Jest-сьют с моком SDK проходит в измеренном Expo/Jest-пресете. Модель батареи не переносится в продукт: в `--repo` разрешение импорта идёт в продуктовой раскладке, без файлов оракула харнесса на пути импорта.

## Приёмка

`W` = `bash fixtures/workshop_project/gespraech_otdacha_151/red_gespraech_otdacha_151.sh`; `R` — продукт с установленным `mobile/node_modules` и designer-copy `docs/ux/04_Gespraech_D24/motion/haptics.json`. Для `--model`/`--stabs` требуется `--runtime R` либо `MOB_151_RUNTIME=R`. Проба исполняет Jest в одноразовом temp-проекте с реальными `jest.config.js`/`jest.setup.ts`/node_modules R; `EXPO_PUBLIC_API_MODE=production`. Ожидания и исчерпывающее множество имён клеток вычисляются в Python из оракула до импорта субъекта, независимы от его require-кэша; непрошедшая, пропущенная, лишняя или pending клетка делает rc≠0 в каждом режиме. В `--repo` копируется только каталог модуля в продуктовую раскладку; тест с матрицей ожиданий и результаты лежат вне каталога субъекта под случайным именем и недостижимы по предсказуемому относительному пути; модельный `oracle.json` доступен только `--model`/`--stabs`, в `--repo` отсутствует. Конформные входы: строки `haptics` с точным числовым scene+at и булевы флаги; отсутствующие/null флаги обязаны подавлять эффект, неконформные ключи/числовое время — тишина на названной решётке. Контрпример валиден, когда конформен этому домену, инвариантен к временным путям и расходится с честной моделью на собственном входе.

1. Дано: без реализации и без R; когда `W`; тогда rc 1 `SUBJECT_ABSENT`. Дано R до реализации; когда `W --repo R`; тогда rc 1 `SUBJECT_ABSENT`. Нет установленной Jest-среды для модели → rc 2 `INFRASTRUCTURE`, а не зелень или ложная краснота продукта.
2. Дано R с установленной средой; когда `W --model --runtime R`; тогда rc 0, `CASE 805 GREEN 805 RED 0` (~13 с); `W --stabs --runtime R` → rc 0, `SVJAZI 24 CASE 805` (~4.5 мин). Каждый стаб красен своей клеткой или именованным dependency preflight, в том числе подмена глобального test, разделённый oracle require-cache, ожидание/отказ SDK, продуктовый импорт модели и фиктивная версия зависимости. Негатив: порог `time <= at`, отсутствующий флаг, проглоченный отказ или несовпавшее множество имён → rc 1 с именованной клеткой; лишние и повторяющиеся имена → `KRASNO LISHNJAJA_<имя>`; пустая исходная матрица → rc 2.
3. Дано R с установленным `expo-haptics`, модулем и lockfile; когда `W --repo R`; тогда rc 0, `CASE 805 GREEN 805 RED 0`. Парные негативы: отсутствует либо несовместима/не установлена зависимость → rc 1 `DEPENDENCY_ABSENT`; отсутствует модуль → rc 1 `SUBJECT_ABSENT`; несовпадение дизайн-копии и оракула → rc 2 `ORACLE_DESIGN_DRIFT`; модель, читающая `../../../oracle.json`, → rc 1 `KRASNO PRODUCT_MODULE_RESOLUTION`. Ключ/момент вне карты на обеих платформах не испускает эффект на решётке И-1.
4. Правило ворот: `bash scripts/pre_critic.sh --repo . contracts/151-gespraech-otdacha.md`, `bash scripts/check_ceilings.sh`, `bash scripts/check_precision_gate.sh . contracts/151-gespraech-otdacha.md`, `bash scripts/check_zones.sh` → rc 0. `bash scripts/check_provodka.sh . contracts/151-gespraech-otdacha.md` → rc 0 при существующем guard и точной внешней оговорке 994; результат не свидетельствует о запуске CI продукта. Проводка считается исполненной только после продуктового diff с отдельным полным H-пином и живого quality на PR реализации: W --model --runtime R → rc 0, CASE 805 GREEN 805 RED 0; W --stabs --runtime R → rc 0, SVJAZI 24 CASE 805; W --repo R → rc 0, CASE 805 GREEN 805 RED 0.
