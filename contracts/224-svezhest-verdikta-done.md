# Контракт 224 — дверь done выбирает свежий вердикт ревьюера по порядку кругов, а не по предку коммита

СТАТУС: ЧЕРНОВИК-ЗАТРАВКА (bootstrap: `make_task --role architect` требует существующий `contracts/224-*.md`; текст контракта пишет architect по заданию, затравка — только боль, решение-рамка и ссылки).

## Боль
Бэкенд 25.11 (письма back 1700/1720, консультант m2373): `done_contract` для 179 и 181 отказывает «несколько вердиктов, свежий … не accept», хотя последний круг ревьюера — accept (impl-4), а FAIL — прошлого круга (impl-3).
Причина в коде (перепроверено консультантом чтением `scripts/done_contract.sh`, цикл после «Свежий по коммит-истории»): файлы `contracts-<NNN>-*.md` перебираются в `sort -V`, «свежий» сменяется, только если коммит прежнего свежего — ПРЕДОК коммита следующего (`git merge-base --is-ancestor`). Если вердикты круга impl-3 и impl-4 пришли параллельными ветками (служебные PR вердиктов), коммит impl-4 не потомок коммита impl-3 — свежим остаётся FAIL.
Цена: done 179 и 181 бэкенда стоят; тот же класс ждёт любой предмет с вердиктами разных кругов из разных веток. Обход «записать старый FAIL позже» запрещён консультантом (m2392): запись старого FAIL делает его «свежим».

## Решение (рамка)
Кодовый контракт: свежесть вердикта ревьюера для двери done определяется порядком кругов (номер круга в имени `contracts-<NNN>-impl-vN.md` / OBJECT-цепочка), а не предком коммита вердикта; неоднозначность (два вердикта одного круга, номер вне грамматики) — отказ с названием места, не молчаливый выбор.

## Существующее
`scripts/done_contract.sh` (выбор свежего вердикта и проверка OBJECT ревьюера); прецеденты аудита 2026-10-16 («ошибка git — отказ, а не пропуск»); контракт 167 (merge main→wip, вердикты по OBJECT); контракт 104 (OBJECT= в вердикте).

## Класс
Кодовый. КЛАСС РИСКА: рисковый (дверь done — страж принятия: нельзя пропустить свежий FAIL; adversary → reviewer).

## Не входит
Правка вердиктов бэкенда и проектных реестров; порядок вердиктов адверсария; done 179/181 — после ленда этого предмета, сессией бэкенда.

## Номер и реестр
Номер 224 выдан механизмом (`next_id.sh CONTRACT`, тег `id/CONTRACT/224` = `3683e56d…`; строка `registry/contracts.tsv` на main). Строка `registry/plan.tsv` — тем же owner-PR.

- красные клетки на настоящих Git-мирах: вердикты impl-3 FAIL и impl-4 accept из параллельных веток → done обязан пройти; impl-4 FAIL после impl-3 accept → отказ; два вердикта одного круга → отказ;
