владельца — mint-сообщение выдачи (6c4adc5): «раннер: probe-only каталоги для
предметов вне scripts/ — оба режима scoped+полный; аутентичность источника замера —

## Предмет

Две боли, обе доказаны исполнением, обе — корень в раннере анти-плацебо.

**Боль 1 — probe-only каталоги.** §2 verify_antiplacebo.sh («фикстура без барьера»)
судит КАЖДЫЙ каталог fixtures/ ДО scoped-фильтра. Предметы вне scripts/ (workshop,
.omp/extensions/path-guard.ts) не имеют барьерного ключа — их каталоги
fixtures/qa_kanal_xd + fixtures/workshop_inventory (030, пост-фриз bc68777) флажат
ВСЕ прогоны. Замер на живом HEAD 6c4adc5: `bash scripts/verify_antiplacebo.sh --scope
next_id` → rc 1, «расхождений: 2», обе строки «FAIL fixtures/<…>: фикстура без
барьера», при зелёной самой семье (1/1). CI красен с ec11c86, суды ВСЕХ контрактов
заблокированы check_ci_gate (033-к2 Б1: scoped rc 1 на da3f01e, 20/20 фикстур зелёные).
Класс каталога легитимен: red_* предъявления прямые, вне case_*-глоба, НЕ для батарей
раннера — прецеденты 024/025/026; в БАРЬЕРНЫХ каталогах red_* лежат массово (60+ файлов)
и раннером молча не исполняются. Решение-основа 8242f1e (исключён из сквоша 030, в
дереве отсутствует): cross-check scope-aware — лечит ТОЛЬКО scoped, полный прогон
остаётся красным (гвард SCOPE_MODE). 034 легализует класс в ОБОИХ режимах.

**Боль 2 — аутентичность источника замера.** Гвард-1 адверсария 033-к2 (348b108, Б2):
Непустота-выборки-033-проверка (frozen 033 :95) принимает ПОДСТАВНОЙ счётчик.
Исполненная подмена: ветка в check_zones.sh на аргумент '.' печатает константу
«…проверено по зонам: 1» и выходит rc 0 — все проверки 033-v2 зелёные при нулевой
фактической работе. Гвард сверяет regex и N>0, не связывая счётчик с исполнением;
фикстуры check_zones подмену не ловят (toy-репо зовут барьер абсолютным корнем —
348b108: 20/20 зелёных на подменённой копии).

## Frontier: решения и отвергнутые варианты

1. **КАК раннер узнаёт probe-only каталог — МАРКЕР-ФАЙЛ `fixtures/<key>/.probe-only`**
   (файл непуст: причина — для судей; пустой маркер = объявление без причины,
   прецедент check_zones «причина пуста — объявление без причины неотличимо из опечатки»).
   Отвергнуто: (в) авто-детект «нет case_*.sh ⇒ probe-only» — молчит при опечатке имени
   case (каталог с ОДНОЙ опечатанной case тихо легализуется, Н-99-класс); (б) реестр
   ключей в отдельном конфиге — второе место истины, разъезжается при переименовании
   каталога; шапка-комментарий в red_* — единица сверки §2 есть КАТАЛОГ, частичная
   разметка N файлов двусмысленна.
2. **Семантика §2 ЕДИНА в обоих режимах.** Легальность/нелегальность каталога не зависит
   от режима; scope-aware-обход 8242f1e замещается (сам коммит в дереве отсутствует —
   изымать нечего). Postоронний ЛЕГАЛЬНЫЙ probe-каталог не красит scoped-прогон чужой
   семьи (боль 1); НЕлегальный каталог красит ОБА режима (fail-closed).
3. **Аутентичность замера — ИЗВЕСТНЫЙ ОТВЕТ + живой запуск.** Гвард запускает предмет
   сам, на сконструированном входе, ответ K которого известен ПОСТРОЕНИЕМ (гвард сам
   создал K коммитов), и требует счётчик == K. Подмена-константа даёт N≠K — красное
   доказано исполнением. Отвергнуто: sha1-сверка git-объекта check_zones — не ловит
   ЗАКОММИЧЕННУЮ подмену (замер исполняет «этот файл», но «этот файл» и есть
   подменённый; ловит лишь грязное рабочее дерево — не исполненный 348b108);
   независимый rev-list-пересчёт живого дерева — вторая семантика зон рядом с
   единственным читателем lib_zones (анти-норма 016) и дрейф двух реализаций.
4. **Граница: red_* в барьерных каталогах — действующая конвенция прямых предъявлений**
   (check_judge_gate 22, check_hooks 10, check_runner_hygiene 13, …), раннером не
   исполняются и не флагаются. 034 её не меняет. Смешение case_*+red_* внутри
   БАРЬЕРНОГО каталога легально; смешение в probe-only каталоге — нет (роль одна).

## Инварианты

1. Каталог fixtures/<key>/ без барьерного ключа, с непустым маркером .probe-only и
   ≥1 red_*.sh — легален в ОБОИХ режимах: не флагается §2 полного, scoped и --changed
   прогона.
2. Не ослабление (все три — красные в обеих эрах, во ВСЕХ режимах раннера — полный,
   scoped И --changed): каталог без ключа БЕЗ маркера — флагается «фикстура без
   барьера»; probe-only каталог с case_*.sh — флагается (роль каталога одна: case-
   батарея живёт только у барьерного ключа); барьерный каталог с маркером .probe-only
   — флагается (противоречие ролей не молчит). Отказ §2 переживает нулевую changed-
   выборку: нелегальный каталог ВНЕ диффа + легальная probe-правка в диффе («нечего
   гонять») обязан давать итог rc 1 — ранний выход нулевой выборки НЕ легализует
   дерево с уже напечатанным FAIL (к1-Б1, контрпример A исполнен критиком).
3. Нуль выбора наблюдаем выводом, а не только rc 0: правка файлов probe-only каталога
   не выбирает НИ ОДНОГО барьера — селектор отвечает `MODE: needs-full` кодом 2 без
   единой `KEY:`-строки (консервативный `MODE: full` НЕ есть нуль выбора, к1-Б2,
   контрпример B исполнен критиком), раннер печатает `MODE: none` и не исполняет ни
   одного case. НЕмаркированный посторонний каталог в диффе — консервативно MODE: full;
   явный --scope <probe-ключ> остаётся «неизвестный ключ» rc 1 (не барьер — нечего
   гонять).
4. Замер-гвард, связывающий счётчик с прогоном, обязан держать известный ответ:
   исполнять предмет приёмочной формой вызова (та, что в приёмке — у 033 это '.'),
   на входе с ответом K по построению, и требовать равенства. Исполненная подмена
   348b108 (ветка на '.' с константой) на таком входе даёт N≠K — гвард красен; старый
   N>0-гвард ту же подмену принимает — плацебо показано исполнением, не пересказом.

## Остаточный риск (назван прямо)

- Подмена, обученная инструменту (знает форму toy/значение K заранее) — атака на
  инструмент предъявления, не на предмет; судом 034 не оценивается (прецедент границы
  030: чтение файлов инструмента ради вшитых значений — атака на инструмент). Дешёвое
  расширение ловли — второй toy с иным K — уже в предъявлении (K=3 и K=5).
- Содержимое .probe-only — свободный текст: судится чтением (cognitive-only), непустота
  механическа.
- Инвариант 3 (--changed) не покрыт статическими CI-шардами — держится предъявлением
  (ворота 3–5 red_katalog_ne_flagaetsa.sh) и судами.
- Граница red_* в барьерных каталогах остаётся вне механики раннера: конвенция имён,
  судится ревью (cognitive-only).
