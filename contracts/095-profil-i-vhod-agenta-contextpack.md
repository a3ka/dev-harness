## Предмет (дословно из докса владельца, строки 354–379)

**Состав:** 1.7; контекстная часть 2.1; 3.1–3.4, 3.6; минимум 3.5.

До пилота реализуется **узкая, но настоящая версия ContextPack**, а не ручная имитация:

- проектная карта, `rules:`, reuse, пути документов;
> - `orch_brief`;
> - `make_task`, манифест и происхождение фрагментов;
- зоны из frozen-блоба для исполнительских стадий;
- отдельный корректный режим архитектора/критика до заморозки;
- ADR и уроки по области;
> - `КОНТЕКСТ:`, `§Существующее`, карта кода зоны;
- видимость скилов;
- reviewer получает фактически выданное задание;
- роль/модель/разрешённый fallback подтверждаются трассой.

Историю решений всего харнеса и каталог всех языков здесь не достраивать. Для первого проекта размечаются действующие документы и области пилотной работы.

**Выход:**

- реальный запуск в репозитории проекта получает его правила, а не контекст харнеса;
- обязательные источники доступны и разрешаются по манифесту;
- потерянная обязательная ссылка даёт точную причину, а не молчаливое усечение;
- смена роли/зоны меняет релевантную выдачу;
- автор и судья независимы по фактическому прогону;
- отсутствие свидетельства модели не считается успехом;
- стартовый и задачный контекст укладываются в принятые бюджеты без потери обязательных норм.

## Решения

1. Субъект — ОДИН сборщик `scripts/make_task.sh`: `--repo R --role ROLE [--kind task|brief] [--contract NNN] [--task-file F] [--model-trace F]`. Грамматика CLI и все фразы закреплены честной моделью `fixtures/context_pack_095/model/dover.sh`: субъект обязан принимать её CLI и фразы дословно (детали реализации — implementer). Отказы rc 1 «ОТКАЗ: …» ДО выдачи пака — частичного stdout у отказа нет.
2. Пак (stdout, порядок под кэш 13.6-5 — устойчивое раньше, изменчивое позже): заголовок → TRACE → MAP/RULES/REUSE (по карте профиля, видимость по роли) → SKILLS (матрица 13.4) → CONTEXT (`КОНТЕКСТ:` строки + секция `## Существующее` контракта ДОСЛОВНО) → ZONES (ЗОНА-строки ДОСЛОВНО из frozen-блоба; до заморозки — из черновика, origin=draft) → LESSONS (по ОБЛАСТИ, кап 5) → TASK (только reviewer: sha256 + байты выданного дословно) → MANIFEST (TAB: kind, path, mandatory|optional, origin) → BUDGET (vklejka=N/40000).
3. Контекстные ключи — миграция схемы 054 (`contextPack` в repo-слой/слой проекта), грамматика значений замкнутыми алфавитами (041): kind ∈ {map,rules,reuse}; путь `[A-Za-z0-9._/-]+`; роли CSV из алфавита ролей харнеса; mandatory|optional; why без TAB/переводов строк.
4. Происхождение фрагментов: origin ∈ {profile,frozen,draft,taskfile,trace} — ЕДИНСТВЕННЫЙ источник значения — ветвление источник-пака (заморозка есть → frozen; черновик → draft); манифест без origin или origin вне алфавита — дефект, ловится клеткой И-11.
5. `spawn_agent.sh` получает новую ногу: отказ «нет манифеста make_task: <NNN>» при спавне исполнительской роли без построенного пака (II-3 дословно); брифинг — старт сессии оркестратора (роль): дельта роли `roles/orchestrator.md` — вызов make_task --kind brief вместо ручного чтения HANDOFF целиком.
6. `pre_critic.sh` получает ногу ФОРМЫ: контракт без строк `КОНТЕКСТ:` или без секции `## Существующее` — именованный отказ до критика (13.3 дословно: pre_critic судит форму, критик — полноту).
7. Миграция (Пять правил §2): ручная сборка задания/брифинга удаляется из роли оркестратора (свободный текст — ТОЛЬКО дельта круга, слой 5); статусная строка `roles/orchestrator.md:26` («до готовности генератора orch_brief…») заменяется вызовом двери; области пилотных зон размечаются НОВЫМ реестром `registry/lessons-harness.tsv` (id урока TAB ОБЛАСТЬ-глоб TAB выжимка) — исторический журнал NABLIUDENIA.md не переписывается (слово владельца: действующие документы и области пилотной работы, не бэкфилл); поведенческие нормы исполнителя/ревьюера/архитектора доставляются самим паком (CONTEXT/TASK секции), тексты этих ролей не правятся.
8. Реальный харнес — первый пользователь: `harness.project.json` харнеса получает `contextPack` с действующими документами (ARCHITECTURE.md, CODING-STANDARDS.md, consumers.d/, NABLIUDENIA*.md) и областями пилотных зон; внешний проект — слой проекта 054. Батарея судит грамматику/инварианты на toy-носителях, живой прогон на внешнем репо — этап 3 пути Г.
