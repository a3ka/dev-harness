## Предмет

Боль (docs/owner/2026-10-03-done-i-instrumenty.md §9.1, замер 7 дней / 405 прогонов CI):
199 cancelled / 104 failure / 100 success; из отменённых 192 — push в main (110 успели
отработать от половины окна и больше): каждый push в main отменяет предыдущий полный прогон
(concurrency по ref). Окно «судья → done» у 071–074 на треть — ожидание CI (слово владельца
2026-10-04, ROADMAP §11). Корень — скорость одного прогона: последовательная джоба `ci`.

Предмет (форма решена владельцем §9.2 дословно; инженерный выбор ниже — frontier этой пачки):

1. **Генератор шагов.** Шаги джобы `ci` и шарды джобы `antiplacebo` генерируются из единого
   реестра `registry/ci-steps.tsv` генератором `scripts/gen_ci_steps.sh`; джоба `ci`
   перестраивается в матрицу из 6–8 параллельных lane (прецедент — форма `antiplacebo`:
   matrix include `lane`/`keys`, lane-шаг исполняет ключи подряд через
   `scripts/run_ci_lane.sh <ключи…>` с остановкой на первом отказе именем ключа).
2. **Инкрементальные проверки истории.** `check_charter`, `check_zones`, `check_ids`,
   `check_protected` получают режим `--incr <кеш-файл>`: судится ТОЛЬКО окно от последнего
   проверенного sha до HEAD; полнота проверки та же (не ослабление, а кеширование/диффинг —
   инвариант И-7).

Frontier-выбор источника данных (моя зона решения, альтернативы рассмотрены и отклонены):
- (а) шапки `scripts/*` (`Коды возврата:` = барьер) — не покрывает НЕ-барьерные шаги джобы
  `ci` (drill-ы, семейные selftest-ы, npm-команды с аргументами) и не несёт весов/lane;
- (б) `package.json` как единственный источник — нет места для весов без порчи публичного
  интерфейса пакета, а lane-распределение в нём не выразить;
- (в) **выбрано**: отдельный TSV-реестр `registry/ci-steps.tsv` (команда шага сверяется с
  `package.json` инвариантом И-3 — реестр не плодит вторую копию команд, а ссылается на них;
  lane-распределение и ключи НУЖНЫ наблюдаемыми в сгенерированном блоке — их судит оракул
  батареи, а не доверие генератору).

НЕ предмет (границы): runtime-watchdog `verify_antiplacebo.sh` (082); classifier лёгкий/тяжёлый
и хеш кодового дерева (CI-Б, §9.3); выбор `ref:`/`fetch-*` строк чекаута (Б-5/Н-206 —
переносятся дословно); concurrency-политика и `timeout-minutes` джоб (контракт 020 —
поднимается отдельным словом, не этой пачкой).

## Решения

Действующих ADR области нет (decisions/001–007 — старый формат без ОБЛАСТЬ, механика ADR
из слова владельца §8 ещё не оживлена); существенный выбор — внутри контракта (frontier-выбор
источника выше). Решения: нет существенного выбора вне этого контракта.

## Инварианты

1. **Единый реестр.** `registry/ci-steps.tsv` — единственный источник шагов `ci` и шардов
   `antiplacebo`. Формат строки (TSV, закрытый алфавит): `lanes <K>` (ровно одна meta-строка,
   K — целое 6..8) · `step <key> <weight> <command...>` (key — `[a-z0-9][a-z0-9._:-]*`,
   уникален; weight — целое ≥0, секунды замера; command — `npm run <key> [-- args]` либо
   `bash <путь>`) · `shard <имя> <keys...>` (ключи через пробел). `ci.yml` несёт блоки между
   парами маркеров `# BEGIN GENERATED CI JOBS (083)` / `# END GENERATED CI JOBS (083)` и
   `# BEGIN GENERATED CI SHARDS (083)` / `# END GENERATED CI SHARDS (083)`, побайтово равные
   генерации; блок JOBS — matrix include `lane: <имя>` + `keys: <ключи…>` (по паре на каждую
   lane), блок SHARDS — `shard: <имя>` + `keys: <ключи…>`. `bash scripts/gen_ci_steps.sh
   --check [--root <dir>]` — rc 0 на совпадении, rc 1 с именованным расхождением на дрейфе
   (ручная правка внутри блока красна).
2. **Параллельность.** Генерация даёт РОВНО K lane-строк, K = meta-строке реестра, 6≤K≤8;
   имена lane различны, keys-строка у каждой непуста; каждый step-ключ попадает ровно в
   ОДНУ lane (сумма-инвариант по ключам); внутри lane шаги идут подряд, остановка на первом
   отказе с именем ключа в причине (`run_ci_lane.sh`). Статическая оболочка джобы (checkout
   c Н-206-строками, node 26, gate-шаг `check:ci-parity` до lane-шага) не генерируется и
   пишется один раз.
3. **Резолв команд.** Каждый `step`-ряд резолвится: `npm run <x>` — x обязан существовать в
   `package.json` scripts; `bash <путь>` — путь обязан существовать в дереве. Нерезолв —
   именованный отказ генератора (rc 1), файлы не трогаются. `verify_ci_parity.sh` после
   перестройки считает npm-ключ покрытым CI, если он потреблён реестром (площадь покрытия
   пере-выражена через реестр; правило 6 для статических шагов и сумма-инвариант шардов —
   без ослабления; легальные исключения — прежний `config/ci_parity_exceptions.txt`).
4. **Баланс.** Веса — из замеров владельца (§9.1) и живых прогонов; генератор распределяет
   ключи по K lane жадно (LPT: по убыванию веса, в наименее загруженную) и обязан держать
   `max(нагрузка lane) ≤ ceil(total/K) + max(вес одного шага)`; нарушение — именованный
   отказ (rc 1), а не «как получилось».
5. **Шарды.** Include-блок `antiplacebo` генерируется из `shard`-строк реестра побайтово;
   сумма-инвариант `verify_ci_parity.sh` по-прежнему судит СГЕНЕРИРОВАННЫЙ блок (набор
   ключей шардов ∕ именованные исключения — без ослабления против сегодняшнего).
6. **Инкрементальный CLI (единая грамматика — один источник).** Все четыре чека принимают
   `--incr <кеш-файл>`; грамматика живёт в `scripts/lib_incr.sh`, чеки несут её побайтово
   через вызов библиотеки (переизобретение в каждом чеке — провал). Кеш-файл — ровно одна
   строка `[0-9a-f]{40}` + перевод строки. Поведение:
   - (а) кеш валиден и его sha — предок HEAD → судится ТОЛЬКО окно `<base>..HEAD`; stderr
     несёт маркер `incr: <имя-чека> судит <base>..<head> (N коммитов)`, N — из rev-листа окна;
     зелёный вердикт атомарно записывает HEAD в кеш-файл;
   - (б) кеш-файл ОТСУТСТВУЕТ → полный прогон, НО не молча: stderr несёт маркер
     `incr: <имя-чека> полный прогон (кеш отсутствует)`; запись кеша после зелёного — та же;
   - (в) кеш-файл есть, но первая строка не `[0-9a-f]{40}` ЛИБО sha не предок HEAD →
     именованный отказ rc 1 с причиной, называющей кеш и base (подделка/повреждение не
     лечатся ни тихим успехом, ни незаметным полным прогоном);
   - (г) без `--incr` — прежний полный режим, побайтово; все сегодняшние вызывающие
     (CI-шаги, freeze_contract, судейские прогоны) не меняются.
7. **Полнота не ослаблена (демаркация контрпримера).** Конформная toy-история — коммиты,
   допустимые грамматикой предмета соответствующего чека (для `check_charter`: добавление
   AGENTS.md свободно; коммит, МОДИФИЦИРУЮЩИЙ AGENTS.md без строки `РАЗРЕШИЛ-ВЛАДЕЛЕЦ` —
   конформный ВХОД и красный ВЕРДИКТ). Свойство: на любой конформной истории verdict_full ==
   композиция verdict_incr по любому разбиению окна: (зелёный на A..B ∧ зелёный на B..C) ⇒
   зелёный full на A..C; красный в подокне ⇒ красный full. Судимое множество incr-прогона —
   окно, а не вся история: нарушение НИЖЕ базы невидимо для incr — и это НЕ ослабление:
   база попадает в кеш только зелёным прогоном (п. 6а), доверие к базе = доверие к прошлому
   зелёному, не к входу.
8. **Живые вердикты не меняются.** Полный режим четырёх чеков на живом дереве до и после
   реализации — одинаковые множества строк `  ok `/`  FAIL ` и rc (дифференциал, не «стало
   зелёным»); эталоны ДО снимает реализационная пачка на ветке предмета ДО правок и
   коммитит (прецедент 082 А2).

## Остаточный риск

- Кеш CI живёт в `actions/cache` — недетерминирован (restore может промахнуться): деградация
  СКОРОСТИ (явный полный прогон), не корректности. Ловец: тайминг-приёмка А3 на живом CI.
- PR-прогоны кеш не сохраняют (save только push): первый инкр-прогон PR чаще полного на
  словах «кеш отсутствует» — принятая цена (CI-Б снимет класс целиком).
- Баланс-веса дрейфуют вместе с реестром: инвариант И-4 судит ТЕКУЩИЕ веса; появление шага
  тяжелее границы — именованный отказ генератора, лечение — правка весов замером, не правка
  границы (порог не ослабляется ради результата).
- Lane-исполнитель `run_ci_lane.sh` останавливает lane на первом отказе: поздние шаги lane не исполняются до
  чинки раннего — то же поведение, что у последовательной джобы сегодня (не ослабление);
  fail-fast между lane не заводим (прецедент antiplacebo `fail-fast: false`).
- Инкрементальность `check_zones`/`check_ids`/`check_protected` поведенчески доказана в
  батарее клетками И0 (маркер + пустое окно + кеш) и — window-оракулом с нарушением — только
  для `check_charter` (его toy-мир минимален и конформен грамматике; миры остальных трёх
  требуют тяжёлой репликации реестров/тегов). Риск «incr судит не то окно» у трёх оставшихся
  держат маркер с числом коммитов (И-6а: N выводится из rev-листа окна и сверен с ожиданием
  клетки И0) + судейский круг адверсария на живом прогоне. cognitive-only остаток, ловец —
  адверсарий контракта (вправе потребовать toy-мир по прецеденту 073).
