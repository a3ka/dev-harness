# Контракт 051 — живой режим check_fork_route судит только открытые записи (Н-159)

Статус: черновик. Минт: тег `id/CONTRACT/051` (tag-object
`f3dc9a234290cd8c77778c47c4ccd528863daa2d`) + строка `051 → f3dc9a2…` в
`registry/contracts.tsv` на origin/main — dual-control исполнен ДО этой пачки (резерв 023).
Заморозка — после круга критика.

## Предмет — решение владельца дословно

> «Живой режим check_fork_route судит rc только по записям ОТВЕЧЕНО: нет; --schet считает
> все. Историю и запись mint-030-kanal не трогать. Красная фикстура: открытая передаточная
> запись → rc 1, отвеченная → rc 0.»

Измеренная боль (Н-159). Живой прогон `bash scripts/check_fork_route.sh --root .` красен на
main с 2026-09-19: легаси-ретро `forks/mint-030-kanal.md` (коммит владельца `850400f`,
`КЛАСС: инженерный` + `МАРШРУТ: батч`, `ОТВЕЧЕНО: да`) даёт «передаточное касание» — режим 4в
судит ВСЕ записи независимо от ОТВЕЧЕНО. Живое ДО (дерево `7680606`, измерено этой пачкой):
`rc=1`, отказ «передаточное касание: инженерный форк адресован владельцу: mint-030-kanal»;
`--schet` при этом зелён: «просмотрено 9 / передаточных 2». Цена: ~5 минут изоляционных проб
на каждый форк-цикл (замер на sankcija-v2-050-h5), CI живой каталог не гоняет (матричный ключ
`check_fork_route` — фикстурная семья, не `forks/`). Направление решения владельца: фильтр
закрытых записей в судах обычного режима, НЕ миграция легаси-записи (и4).

## Инварианты (механизм: `scripts/check_fork_route.sh` — суды обычного режима)

Определение (единый источник — действующая грамматика режима `--flush`, который скипает
только «да», строки 235/255; второй алфавит открытости не заводится): **закрытая запись** =
`ОТВЕЧЕНО: да`; **открытая запись** = поле `ОТВЕЧЕНО` отсутствует ИЛИ `ОТВЕЧЕНО: нет`.

1. **Обычный режим (вызов без `--flush`/`--schet`) судит rc только по открытым записям**
   (и1). Суды судьбы записи — 4а «двойная роль» (инв. 6 контракта 029) и 4в «маршруты
   (а)/(б)/(в), неизвестный класс» (инв. 1–3 контракта 029) — применяются только к открытым
   записям; закрытая запись не красит rc обычного режима ни одним исходом 4а/4в. Логика судов
   внутри области не меняется (и3: «судят по-старому, если применимо к открытым»): те же
   поля, те же поимённые отказы, те же пиннутые подстроки отказа.
2. **Грамматика журнала (секция 0: имя ASCII, `ФОРК:` = имени, дубликат `ФОРК`, кратность
   `КЛАСС`, ISO `ЗАВЕДЁН`) судит ВСЕ записи во ВСЕХ режимах без изменений.** Основания:
   (а) `--schet` считает все (инв. 3) и обязан разбирать закрытые; (б) обманный стаб (б)
   («грамматика полей не ослаблена») требует живых поимённых отказов — закрытость не становится
   лазейкой порчи журнала; (в) прецедент: грамматика стоит до разделения режимов. Протокол P4
   (§Красный протокол): закрытая запись с не-ISO `ЗАВЕДЁН` → `rc 1` «грамматика записи» и ДО,
   и ПОСЛЕ.
3. **`--schet` считает ВСЕ записи** (и2): «просмотрено N» — все файлы каталога `forks/`,
   «передаточных M» — все батч-записи без засвидетельствованной воли, независимо от
   `ОТВЕЧЕНО`. Числа фиксом не меняются: живое ДО «просмотрено 9 / передаточных 2», живое
   ПОСЛЕ — те же (подтверждено прототипом, §Красный протокол).
4. **`--flush` семантика не меняется** (и3): уже скипает закрытые (строки 235/255), не
   трогается.
5. **4б «деградация» не трогается** (и3 дословно): rc не красит (печать `ДЕГРАДАЦИЯ:` при
   rc 0), триггеры и порог те же.
6. **История git и файл `forks/mint-030-kanal.md` не тронуты** (и4): правка только в
   `scripts/check_fork_route.sh` + новые клетки; живой эффект — mint-030-kanal (`ОТВЕЧЕНО: да`)
   перестаёт красить живой прогон: `rc 1` → `rc 0`. На дереве `7680606` из 9 записей живого
   каталога 8 закрытых и 1 открытая (`spaseno-031-v4`: воля-владельца, батч, конформная —
   симуляция открытого подмножества дала `rc 0`), живое ПОСЛЕ `rc 0`.
7. **Прежние девять проб семьи не правятся, не удаляются и не переименовываются** (семь
   `red_*.sh` + две `case_*.sh`; каркас `_forks.sh` пробой не считается); три новые клетки —
   добавление.

Демаркация контрпримера. Конформный вход — игрушечный журнал грамматики 029: id ASCII
`[a-z0-9-]+`, `ФОРК:` = имени, поля «КЛЮЧ: значение» по одной на строку, `КЛАСС` не более
одного раза, `ЗАВЕДЁН` (если есть) — ISO `ГГГГ-ММ-ДДTчч:мм:ссZ`, `ОТВЕЧЕНО` ∈ {да, нет,
отсутствие}. Валидный контрпример к клеткам = инвариантность к значениям (id, время, прочие
поля) ∧ расхождение честной реализации инвариантов 1–7 с ожиданием клетки на конформном
входе.

## Риски (named residual)

1. **Грамматика-на-закрытых (инв. 2) — вывод архитектора, не дословная скобка и1.** Буквальное
   прочтение «ни один исход обычного режима не красит» охватывало бы и грамматику секции 0;
   выбрано «грамматика судит все», потому что (а) `--schet` считает все (и2) и обязан
   разбирать закрытые; (б) стаб (б) требует живых поимённых отказов — закрытость не лазейка
   порчи журнала; (в) грамматика стоит до разделения режимов (прецедент --flush). Живой
   легаси-случай Н-159 этим закрыт: mint-030-kanal грамматике конформна. Требует подтверждения
   владельца до заморозки.
2. **4б не тронута (инв. 5):** закрытая консультант-запись с `ВЫЗВАН` без вердикта печатает
   `ДЕГРАДАЦИЯ:` и ПОСЛЕ фикса (rc 0). Владелец этого не просил менять; красным не является.
3. **Живое ПОСЛЕ Р5 валидно для каталога дерева `7680606`** (8 закрытых + 1 открытая
   конформная). Новая открытая неконформная запись корректно красит живой прогон и ПОСЛЕ —
   это работа барьера, не дефект фикса.
4. **Красные клетки — прямые пробы `red_*.sh` (прецедент 029), в мета-прогон
   `verify_antiplacebo` не попадают** (батарея семьи — две `case_*.sh`, зона implementer по
   029). Регрессия фикса ловится: живым прогоном по роли (ПРОВОДКА), повторными прогонами
   Р1–Р3, судом критика/ревьюера. Case_*-дубль в CI-батарею — расширение отдельным словом
   владельца, в этот предмет не входит.
