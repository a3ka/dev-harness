# Контракт 211 — D52-bootstrap на reviewer/adversary: класс риска из дерева OBJECT при локальном frozen-теге с тем же tag-object

СТАТУС: ЧЕРНОВИК-ЗАТРАВКА (bootstrap: `make_task --role architect` требует существующий `contracts/211-*.md`; текст контракта пишет architect по заданию станции — затравка не является ни спекой, ни критерием; заменяется целиком).

## Боль
Измерено 22–23.11: у судей СТАДИИ РЕАЛИЗАЦИИ (reviewer, adversary) дверь `scripts/zamok_predmeta.sh` (`--sudit`, блок `[D42 frozen-risk]`, `frozen_predmeta()`) читает класс риска из ЗАКРЕПЛЁННОГО frozen — через строку `<NNN> → <tag-object>` в `registry/contracts.tsv` НА MAIN. Строка REPLACE (`<NNN> → tag-object frozen/contracts/<NNN>/1`) попадает на main только ПОСЛЕ ленда носителя заморозки и publish тега, а ленд следующего (реализующего) шага требует accept судьи реализации — круг: судья реализации не получает класс (`KLASS_RISKA_NET: закреплённый frozen недоступен`), пока строка не на main, а строка не на main, пока реализация не принята. Блок `[D52 bootstrap-kritika]` (строки ~1289–1316 двери) решает это ТОЛЬКО для роли `critic`/`critic-sol` при НУЛЕ frozen-тегов предмета; для reviewer/adversary — «как прежде» (отказ/предупреждение `KLASS_RISKA_NET`, предмет считается рисковым). Замеры: проект Complior-back (177: «закреплённый frozen недоступен» — реестр проекта лежит в `.harness/registry/`, а не `registry/`), Complior-agent 137/139 (`inbox-back-0125-177-spawn-klass-riska-net.txt`, `inbox-back-0215-185-critic-klass-riska-net.txt`), станция: Rev204 до влива REPLACE 204 (#1243).

## Решение
Слово владельца 22.11 (через консультанта 00:26 UTC): «ВАРИАНТ А — продолжение D52-bootstrap на reviewer/adversary (класс риска из дерева OBJECT при локальном frozen-теге с тем же tag-object)». Направление: для ролей reviewer/adversary, когда строки `<NNN> → …` на main ещё нет (или она хранит id-тег, а не frozen), но в репозитории носителя есть ЛОКАЛЬНЫЙ/достижимый `frozen/contracts/<NNN>/<v>` с тем же tag-object, который удостоверен для ветки OBJECT (коммит заморозки — предок OBJECT), — класс риска читается из ДЕРЕВА OBJECT (как у critic-bootstrap); иначе прежнее поведение (`KLASS_RISKA_NET`, предмет считается рисковым). Нужные свойства и границы формулирует architect: условия «тот же tag-object» (какого именно тега и откуда — tag-object локального frozen-тега == объект, на который указывает пин проекта/OBJECT-дерева), невозможность подмены класса автором (дерево OBJECT пишет автор ветки — ловец: коммит заморозки — предок OBJECT и текст контракта в OBJECT побайтно равен frozen-блобу), поведение при РАЗНЫХ версиях (`/1` vs `/2`), поведение для critic (не меняется), порядок судей (adversary → reviewer для рискового).

КЛАСС ЗАДАЧИ: кодовый. КЛАСС РИСКА: рисковый (замок допуска судей; независимость и порядок судей; adversary → reviewer).
РАБОТА НЕ РАЗДАЁТСЯ: затравка; зоны и раздачу объявляет architect.
