# Контракт 005 — автономия: свой прокси учёта

Номер выдан механизмом: `next_id.sh CONTRACT` → 005, тег `id/CONTRACT/005`. Предмет —
решение владельца 2026-08-19: «dev-harness полностью независим; фабрика контента —

## Предмет

Харнес поднимает **свой** прокси учёта трафика моделей: OpenAI-совместимый
ретранслятор с потолком расхода и журналом вызовов, без внешних зависимостей
(`node:` builtins только), со своей базой на файловой системе. Дом секретов уже
развязан с фабрикой (6a8480b); этот контракт закрывает вторую половину автономии —
учёт. Домены решений, найденные кругом 1 критика (01b4dc1), закрыты в тексте и
помечены [К1-N].

1. **Прокси-ретранслятор** `scripts/proxy/metering_proxy.ts` (запуск
   `node scripts/proxy/metering_proxy.ts`): OpenAI-совместимый; ЛЮБЫЕ пути
   провайдера (GET/POST), а не только `/v1/chat/completions` [К1-5]; ответ
   провайдера возвращается как есть (тело, статус, content-type). Конфиг —
   путь аргументом `--config <файл>`; фикстуры пишут свой конфиг с
   ПОРОЖДАЕМЫМИ при каждом прогоне значениями (токены, provider id, model id,
   upstream-путь) [К1-5].
2. **Приписывание роли токеном** [К1-1]: токены живут ТОЛЬКО в доме секретов
   (`~/.config/dev-harness/secrets.env`, строки `METERING_TOKEN_<ROLE>=…`);
   `config/metering.json` (репозиторий) перечисляет РОЛИ и провайдеров — без
   буквальных токенов; `.omp/models.yml` ссылается `${METERING_TOKEN_<ROLE>}`.
   Прокси строит карту токен→роль ЧТЕНИЕМ конфигурации НА КАЖДЫЙ запрос
   (кэширование на старте запрещено): смена файла секретов отзывает/выдаёт
   токен без перезапуска. Неизвестный токен — 401, строки журнала нет.
3. **Журнал** `data/metering/calls.jsonl` — append-only, строка на вызов:
   `ts, role, provider, model, path, tokens_in, tokens_out, usd, latency_ms,
   status`. Деньги — ЦЕЛЫЕ микро-доллары (int64 minor units, [К1-С2]); в
   `budget.json` те же целые. Пишется и для неуспешного вызова (обрыв:
   usage нет → tokens 0, usd 0 — записанная граница недоучёта в безопасную
   сторону для журнала и НЕ для бюджета: потолок не списывает то, чего не
   видел; граница наследует решение референса). Направление производности
   доказывается: `--rebuild-budget` пересобирает `budget.json` из журнала;
   барьер УДАЛЯЕТ budget.json, запускает пересборку и сверяет [К1-3].
   `data/metering/` — локальное состояние, в `.gitignore` [К1-С3].
4. **Модель без цены — ОТКАЗ ДО запроса** [К1-2]: 503 `model_unpriced`,
   upstream не вызван, строки журнала нет. Консервативный учёт: неоценённый
   платный вызов через прокси невозможен в принципе.
5. **Потолок ДО запроса, списание ПОСЛЕ** [К1-2, К1-8]: `ceilings:
   { "<provider>": { "usd_per_month": <int микро-доллары> } }`; период —
   КАЛЕНДАРНЫЙ МЕСЯЦ UTC, вычисляется функцией `periodAt(ts)` НА КАЖДОМ
   запросе (чистая функция UTC `YYYY-MM`; selftest проверяет её на стыке
   месяцев фиксированным временем) [К1-8]. Исчерпан — 402 с состоянием
   бюджета ДО запроса; перерасход на один вызов — записанная граница.
6. **Запуск лаунчером**: `workshop` перед сессией проверяет `GET /healthz`
   на порту из конфига (умолчание 8765); не отвечает — поднимает прокси
   фоновым процессом (pid-файл `~/.config/dev-harness/proxy.pid`), ждёт
   ≤ 5 с; не поднялся — отказ при запуске с причиной. Занятый порт чужим
   процессом — отказ с причиной (см. «Незаполненные требования»).
7. **Живой маршрут — механизмом** [К1-6]: `check_metering.sh --live` делает
   уникальный вызов (uuid в промпте) через ЖИВОЙ omp, затем проверяет, что в
   `calls.jsonl` появилась строка с ожидаемой ролью и `ts` позже старта
   пробы; прямой маршрут (мимо прокси) строки не рождает — код 1.

## Критерий готовности

1. `node scripts/proxy/metering_proxy.ts --selftest` → 0: `periodAt` на стыке
   месяцев, приписывание токена, свёртка журнала в бюджет (целые микро-USD),
   append-only запись.
2. `bash scripts/check_metering.sh` → 0 с подставным upstream. ВОСЕМЬ ветвей,
   КАЖДАЯ — отдельный красный вызов собственной фикстуры [К1-4], все
   порождаемые значения порождаются при каждом прогоне [К1-5]:
   - (а) прокси не поднят → код 2;
   - (б) неизвестный ПОРОЖДЁННЫЙ токен → 401, строки нет;
   - (в) валидный вызов (порождённые provider/model/путь ≠ chat/completions)
     → 200, строка с ролью по токену и usage из ответа;
   - (г) исчерпанный потолок → 402 ДО запроса (счётчик upstream не вырос);
   - (д) обрыв upstream → строка со статусом ошибки, tokens/usd = 0;
   - (е) маркер append-only: строка-маркер, записанная ДО прогона, жива ПОСЛЕ;
     удалённый budget.json пересобран `--rebuild-budget` и равен свёртке;
   - (ж) модель без цены → 503 ДО запроса, upstream не вызван;
   - (з) все токены конфигурации находятся в секрете, в репозитории буквальных
     нет: grep буквальных токенов по конфигам — пуст.
3. `bash scripts/check_metering.sh --live` → 0 на машине владельца [К1-6]:
   uuid-вызов через живой omp → строка в журнале с ролью и свежим ts;
   прямой маршрут (перемоделированный) → 1.
4. `npm run check:antiplacebo` → 0; `check:ci-parity`: в CI — только
   `--selftest` и ветвь (з) (CI без сети) — объявленное исключение с причиной.
5. Живой прогон владельца: `workshop` поднимает прокси, healthz в HANDOFF.
