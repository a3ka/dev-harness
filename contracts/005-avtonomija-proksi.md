# Контракт 005 — автономия: свой прокси учёта

Номер выдан механизмом: `next_id.sh CONTRACT` → 005, тег `id/CONTRACT/005`. Предмет —
решение владельца 2026-08-19: «dev-harness полностью независим; фабрика контента —
лишь один из будущих проектов; прокси запускается ЗДЕСЬ».

## Предмет

Харнес поднимает **свой** прокси учёта трафика моделей: OpenAI-совместимый
ретранслятор с потолком расхода и журналом вызовов, без внешних зависимостей
(философия репозитория: `node:` builtins только), со своей базой на файловой системе.
Дом секретов уже развязан с фабрикой (6a8480b); этот контракт закрывает вторую
половину автономии — учёт.

1. **Прокси-ретранслятор** `scripts/proxy/metering_proxy.ts`: принимает
   OpenAI-совместимые запросы (`/v1/chat/completions`, произвольные POST/GET пути
   провайдера), читает провайдера и РОЛЬ из заголовков, форвардит на `baseUrl`
   провайдера с ключом из дома секретов, возвращает ответ как есть.
2. **Приписывание роли токеном** — закрывает `role=unknown` из роадмапа: каждому
   вызывающему выдаётся свой токен прокси (`config/metering.json`:
   `roles: { architect: "<token>", implementer: "…", … }`); `.omp/models.yml`
   назначает каждому провайдеру-псевдониму свой `apiKey: "<токен роли>"`.
   Прокси приписывает вызов роли по токену; неизвестный токен — 401.
3. **Журнал** `data/metering/calls.jsonl` (append-only, строка на вызов):
   `ts, role, provider, model, tokens_in, tokens_out, usd, latency_ms, status`.
   Журнал пишется и для неуспешного вызова (провайдер берёт деньги за обрыв).
   Состояние бюджета `data/metering/budget.json` — производное, пересобираемое
   из журнала командой свёртки; расхождение — ошибка барьера.
4. **Потолок ДО запроса, списание ПОСЛЕ** (`config/metering.json`:
   `ceilings: { minimax: "50 USD/мес" }`): исчерпан — 402 с состоянием бюджета;
   перерасход на один вызов — записанная граница (наследие решения фабрики).
5. **Цены** — из `config/metering.json` (`per_m_tokens: { in, out }` в USD);
   модель без цены — вызов проходит, журнал пишет `usd: null`, барьер красит
   конфигурацию, а не журнал (цена не назначена — не молча ноль).
6. **Запуск лаунчером**: `workshop` перед сессией проверяет `GET /healthz`;
   не отвечает — поднимает прокси фоновым процессом (pid-файл в
   `~/.config/dev-harness/proxy.pid`, журнал процесса там же), ждёт готовности
   ≤ 5 с; не поднялся — отказ при запуске с названной причиной. Порт фиксирован
   в конфиге (по умолчанию 8765).

## Критерий готовности

1. `bash scripts/check_metering.sh` → 0 — барьер со ветвями:
   - (а) прокси не поднят → код 2 (`NOT_IMPLEMENTED`), не зелёное;
   - (б) неизвестный токен → 401, в журнале нет строки;
   - (в) валидный вызов через подставной upstream → 200, в журнале строка с
     ролью по токену, статусом и токенами из ответа;
   - (г) исчерпанный потолок → 402 ДО запроса (upstream не вызван — подставной
     upstream считает вызовы);
   - (д) неуспешный upstream (обрыв) → строка в журнале со статусом ошибки;
   - (е) журнал сходится с бюджетом: сумма `usd` строк периода = значение
     `budget.json` (свёртка);
   - (ж) модель без цены → 200, `usd: null`, отдельный отказ конфигурации.
2. `bash scripts/proxy/metering_proxy.ts --selftest` → 0 (единичные тесты
   свёртки журнала и приписывания токена — без сети).
3. `npm run check:antiplacebo` → 0; `check:ci-parity` (check:metering в CI —
   только `--selftest` и статические ветви: CI без сети, ветви (б)-(ж) —
   локальная приёмка, объявленное исключение с причиной).
4. Живой прогон: `workshop` поднимает прокси и сессия отвечает через него
   (замер владельца, запись в HANDOFF).
