# 997 — orch-loop: факт запуска переживает удаление метки

## Предмет

Н-304: после удаления `orch-restart.scoped` уже отработавшая в scope сессия была названа запуском без потолка; цикл остановился, станция простаивала ~10 ч (17.10 23:43 → 18.10 09:56). Результат 997: факт запуска в scope хранится вне удаляемого файлового имени, маркерный рестарт действительно запускает следующую сессию, отсутствие подтверждения не разрешает запуск без потолка, одновременно живёт один цикл. Чистый кодовый cutover, не новая политика рестартов.

КОНТЕКСТ: `docs/owner/2026-10-18-tri-slota.md` §1 — Н-304 первая задача слота харнесса; три слота разрешаются консультантом только после исправления в main и штатного рестарта станции.
КОНТЕКСТ: `docs/owner/2026-10-18-tri-slota.md` §3 — кап 3 круга; первый список блокеров полный, поздние новые требования — советы, нарушение принятого требования блокирует.
КОНТЕКСТ: `NABLIUDENIA.md` Н-304 — журнал scope доказал исполнение (1h23m CPU), удаливший метку не установлен; это не расследование виновника.

## Frontier и выбор

Н-304 (~10 ч простоя):

- `systemctl show/is-active SESSION_UNIT` после возврата — отклонён: завершённый transient scope мог уже исчезнуть.
- Перенос `.scoped` в state-dir — отклонён: меняет вероятность уборки, не зависимость от unlink.
- Файл + systemd + история — отклонён: добавляет ретенцию/гонку GC.
- **Выбран анонимный pipe → память родителя**: подтверждение внутри scope до exec, отдельно от stdout; unlink и GC не отзывают байты.
- Singleton: **flock**, не pgrep/PID-файл/check-then-start (гонка, stale PID). Требование владельца — без второго экземпляра; lock-inode вне verify, без unlink.
- Retry отказа scope — отклонён: **ноль повторов**, И-5. Н-189 (потеря сессии #11, ручное восстановление): сохранить общий EARLY_MAX=3, не бесконечный цикл.

Н-266 (~45 мин разбора 085/093): только частные PATH-подмены, без production test-mode. Н-211 (8 ч простоя): нормы слотов/кругов и другие двери вне предмета.

## Инварианты реализации

1. Каждый запуск по-прежнему проходит `systemd-run --user --scope` с `MemoryMax=$ORCH_MEM_MAX` и `MemorySwapMax=0`; ни одна ветка не запускает AGENT_CMD напрямую после отказа. Без подтверждения именно ЭТОГО запуска — rc 1 немедленно, без повторов. Значение по умолчанию 32G, нормализация user-bus, выбор uid, снятие credentials в опциональном режиме и reaping сохраняются.
2. Вместо RAN — отдельный одноразовый канал текущего запуска. Команда внутри scope пишет фиксированное `SCOPED\n` до exec агента; родитель получает подтверждение в память. Сравнение буквальное, токен не берётся из stdout агента/launcher, файла, rc агента или истории предыдущего запуска. Перед exec агента receipt/lock/вспомогательные fd закрываются. Ошибка подготовки/чтения канала — отказ, не fallback. Rc команды хранится отдельно: выход scoped-агента 1/137 не объявляется отказом создания scope. `.scoped` больше не создаётся/читается production-кодом; legacy alias не оставляется.
3. Stdout/stderr и stdin агента остаются исходными. `systemd-run` остаётся прямым ребёнком цикла: промежуточный процесс `$(…)` вокруг запуска не допускается; read-end анонимного канала открывается заранее, читается после возврата. Наблюдатель и reaping достигают агента; следующая сессия начинается после завершения предыдущей. Lock-fd наблюдатель закрывает ВНУТРИ тела, сохраняя строки снимка 085 р2. `model.sh` демонстрирует канал, не заменяет production-обвязку.
4. Подтверждённая сессия пишет payload `scope подтверждён (канал запуска); файловая метка не используется` с обычным префиксом номера сессии/времени. Без подтверждения — `запуск в scope не подтверждён — запуск без потолка запрещён (И-5, контракт 093)`: не утверждается, что юнит никогда не создавался. Диагноз «ресурсный предел не создан» удаляется из production, потребители 085/093 мигрируются.
5. Singleton — один цикл на HOME: `flock -n` на `$HOME/.local/state/dev-harness/orch-loop.lock`, ДО self-update, удаления MARK/GO/PGID, наблюдателя и сессии. Второй экземпляр: rc 1, payload `ОТКАЗ: orch-loop уже запущен`, без изменения состояния первого, вызова installer или второго агента. Lock держится во время сессии и перехода; собственный exec не принимается за конкурента. MARK и LOG по отдельности и вместе не меняют ключ. Env-флаг «lock уже взят» не свидетель. Невозможность открыть/взять lock — именованный отказ до сессии; после выхода новый запуск разрешён.
6. MARK/GO и отсутствие файлового свидетеля независимы. Само исчезновение файла — не приказ рестарта: `/exit` без MARK останавливает цикл. Ранний маркер и падение используют прежний общий счёт; смена причин его не обнуляет. EARLY_MAX=3 запрещает четвёртый ранний запуск; долгие штатные сессии сохраняют сброс счёта.

## Приёмочный критерий

Команды из корня принятого дерева. `probe.sh`: rc 0 — ожидания совпали, 1 — нарушение поведения, 2 — недоступный вход; печатает каждый сценарий, реальные rc/число запусков и непустой census. В этой пробе процессы настоящие, HOME/репо/состояние одноразовые, systemd-run/systemctl/sudo/omp — частные PATH-подмены, станция не участвует.

Дано до-997 субъект; когда указанная команда; тогда rc 1: удаление файлового свидетеля не даёт второй сессии, singleton не защищён. Это предъявление ДО реализации.

- Дано реализованный субъект; когда `probe.sh --cases`; тогда rc 0. Все сценарии исполняются для same/other uid (sudo-shim доказывает проводку, не ОС-изоляцию). `marker_removed`: удаление новых файлов во всём пространстве записи scope-команды W (HOME, каталог MARK, частный TMPDIR); вне W проба запрещает scope-команде запись механизмом Landlock; удаляется каждый новый объект W без исключений по имени, у канонического lock сохраняется inode и обнуляется содержимое. Затем MARK и сигнал наблюдателя; loop rc 0, два последовательных агента, без ложного отказа. `removed_crash`, `removed_crash_1`, `removed_crash_137`: то же удаление, первый агент заканчивает соответственно 7/1/137 без MARK; каждый вход даёт loop rc 0, два агента. Имена путей свежие в каждом прогоне.
- Дано отказ scope до команды; когда `probe.sh --case scope_refused` или `--case scope_refused_137`; тогда проба rc 0, loop rc 1 с payload инв.4, одна попытка scope, ноль агентов. Отказы launcher 1/137 и его stdout `SCOPED` не являются подтверждением. Положительная пара `--case clean_exit`: проба/loop rc 0, один scoped-агент, без рестарта.
- Дано успешный первый scope и отказ второго; когда `probe.sh --case second_refused`; тогда проба rc 0, loop rc 1, один агент, две попытки scope, без retry и переиспользования старого свидетельства.
- Дано живой первый цикл; когда `probe.sh --case duplicate`, `--case duplicate_mark`, `--case duplicate_log`; тогда каждая проба rc 0, второй loop rc 1 с singleton-payload, первый жив до release, всего один агент. Входы меняют соответственно оба шва, только MARK, только LOG; `marker_removed` — положительный контроль перехода владельца lock.

## Модель угроз

ЗАЩИЩАЕТ:
- От потери факта scoped-запуска при unlink файлового свидетеля независимо от его имени/каталога, от смешения rc/вывода агента или launcher с подтверждением и от повторного использования прошлого свидетельства.
- От второго обычного запуска с тем же HOME независимо от MARK/LOG и от порчи состояния первым действием конкурента; от retry отказа scope и сброса общего предела при смене ранних причин.

НЕ ЗАЩИЩАЕТ:
- От намеренно враждебного процесса того же uid, удаляющего канонический lock-inode, меняющего входной код/config или атакующего fd через procfs; от гибели host/tmux/user-manager. Lock — операционное состояние, не граница одинаковых uid.
- От удаления MARK/GO/PGID: последствия в их собственной семантике (приказ рестарта, reaping); подтверждение scope обязано переживать их удаление. Не меняет дверь 072/080 и не делает unlink самостоятельным restart-триггером.
- От недостаточности kernel MemoryMax, несовместимости передачи fd настоящим systemd-run или регрессии TUI: PATH-проба этого не воспроизводит. Это cognitive-only остаточный риск; ловец — консультант на шаге поставки с реальным cgroup, fd-подтверждением и терминалом.

Конформный вход: Linux/bash, flock/pgrep, штатные ORCH_* (абсолютные частные пути, положительный EARLY_MAX, числовые задержки), доверенный systemd-run, исполняющий команду только после создания scope. Валидный контрпример = расхождение на таком входе, инвариантное к замене путей/номеров сессии. Произвольный shell-код в конфиге/враждебный uid не являются Н-304. Проба ограничивает запись scope-команды механизмом Landlock: единый кортеж W в backend.py — HOME, каталог MARK, частный TMPDIR и control наблюдателя; для /dev разрешён только WRITE_FILE. Свип проходит W∖control, удаляет каждый новый объект без исключений по имени; канонический lock сохраняет inode, но его содержимое обнуляется перед свипом. Входные программы/config/git вне W недоступны scope-команде для записи; control не является конформным местом receipt (зависимость от TOY_* нарушает инвариантность к путям). Landlock недоступен → rc 2 (NOT_IMPLEMENTED), не пропуск. Ожидания — в памяти до запуска, журналы — наблюдения; payload сравнивается полем целиком. Нового production-парсера чужих структур нет: receipt — фиксированный литерал доверенной команды.
