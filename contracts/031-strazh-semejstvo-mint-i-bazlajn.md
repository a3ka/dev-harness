## Предмет

ОДНО семейство — «двери привилегированной дельты»: страж САМ доказывает легитимность
дельты, которая по зонам проходить не обязана (по образцу архитект-двери 023, ветвь iii:
грамматика → реестр → провенанс → ветка). Два механизма:

1. **Н-81, дверь оркестратора-минта.** frozen/contracts/023/1:355 уполномочивает
   оркестратора/владельца писать строку манифеста `registry/contracts.tsv`, но путь не
   находится НИ в одной зоне (dual-control исключительность, 023), поэтому каждый минт
   сегодня = касание владельца (замер 2026-09-19: f24033e, d769e11 — два касания за
   день; единственный оркестраторный минт d28c688 прошёл окном удачи, см. границу-2).
2. **Н-112, дверь переснятия базлайна.** `check_no_leak --check` трипперит на легитимной
   main-direct вердиктной дельте судьи (замер 2026-09-19: verdicts/review/contracts-029-k2.md
   при чистом porcelain; closeout каждого контракта упирается в СТОП). Переснятие базлайна
   разрешается ТОЛЬКО при доказуемо вердиктной дельте — механизмом, не ручной правкой.

Оба механизма делают минты и closeout автономными БЕЗ обхода стража (--no-verify —
bright line, слово владельца 2026-09-19: «не пересекаем даже под норму»).

## Инварианты

### Механизм-1: дверь минта (scripts/check_staged.sh + признание в scripts/check_zones.sh)

Дверь (check_staged): staged-путь `registry/contracts.tsv` под автором `orchestrator`
пропускается БЕЗ суда зон ⟺ ШЕСТЬ условий ВМЕСТЕ (порядок проверок — по образцу 023:
форма → грамматика → реестр → провенанс → ветка):

1. **Форма:** staged-дельта пути (git diff --cached -U0) — ТОЛЬКО добавления: N ≥ 1
   новых строк, ноль изменённых/удалённых. Прочие staged-пути того же коммита судятся
   обычным порядком (дверь — не индульгенция на весь коммит, инвариант 021 :337-339).
2. **Грамматика каждой добавленной строки:** `^[0-9]{3} → [0-9a-f]{40}$` — NNN ровно %03d,
   разделитель « → » (U+2192), 40 маленьких hex = ША ОБЪЕКТА аннотированного тега
   (грамматика 023:349-351 — единый источник, вторая реализация запрещена).
3. **Реестр:** NNN отсутствует в манифесте HEAD И в манифесте ЖИВОЙ шапки origin/main
   (механика чтения origin — та же, что у архитект-двери 3б: ls-remote шапки → fetch →
   cat-file; повторный минт запрещён).
4. **Провенанс-локально:** тег `id/CONTRACT/<NNN>` жив локально (show-ref --verify),
   объект — ANNOTATED TAG, tag-object-sha == sha строки.
5. **Провенанс-origin:** тот же тег достижим на origin (ls-remote точного имени), sha на
   origin == sha строки. Отказ сети (ls-remote/fetch) → fail-closed «авторитет
   недоступен» — имя ОТДЕЛЬНОЕ от «не выдан авторитетом» (023:289-290 дословно).
6. **Ветка:** текущая ветка = main (манифест — авторитет main; церемония-прецеденты
   d28c688/d769e11 — минт на main).

Нарушение любого → rc 1 с ИМЕНОВАННОЙ причиной (фразы — дословно, единый источник;
фикстуры сверяют по байтам):

- «дверь минта 031: дельта манифеста не только-добавление»
- «дверь минта 031: строка не по грамматике манифеста»
- «дверь минта 031: номер <NNN> уже в манифесте — повторный минт»
- «дверь минта 031: тег id/CONTRACT/<NNN> не жив локально»
- «дверь минта 031: sha строки ≠ tag-object-sha живого тега»
- «дверь минта 031: тег <NNN> не выдан авторитетом: тег не достижим на origin»
- «дверь минта 031: авторитет недоступен»
- «дверь минта 031: дверь не на main»

Пропуск печатает `judged: registry/contracts.tsv (дверь минта 031: +N строк ↔ живые
dual-control теги)`. Дверь действительна ТОЛЬКО для автора `orchestrator` (владелец
не зонирован — «не судится» как сегодня; implementer/прочие агенты → «вне зоны»).

Признание (check_zones): в суде коммитов путь `registry/contracts.tsv` под автором
`orchestrator` исключается ИЗ ЭТОГО ПУТИ (не из коммита) ⟺ дельта коммита по этому
пути — только-добавление строк грамматики манифеста ∧ для каждой строки тег
`id/CONTRACT/<NNN>` жив локально ∧ tag-object-sha == sha строки. Иначе — bad()
«коммит вне зоны» с теми же именами причин (минт-признание, локальный реестр;
провенанс не перепроверяется — дверь решила его на входе, прецедент 023 (iv)).

### Механизм-2: дверь переснятия (scripts/check_no_leak.sh, режим --retake)

`check_no_leak.sh --retake <абс-корень>` (абсолютность корня — как у обоих режимов;
снимок-целостность — те же защиты, что у --check: симлинки/mode/verify/двойное чтение
Б4). Переснятие базлайна ПРОИСХОДИТ ⟺ ШЕСТЬ условий ВМЕСТЕ:

1. Снимок существует и цел (защиты-снимка 024 дословно).
2. **Porcelain чист** (`git status --porcelain` пуст): дельта обязана быть ЗАКОММИЧЕНА.
3. **Дельта непуста** по семантике 024 (новые строки манифеста против базлайна).
4. **Ровно один путь** в дельте (все новые строки манифеста принадлежат одному пути).
5. **Путь — вердиктный:** путь покрыт ЗОНА-строкой какого-либо замороженного контракта,
   и эта зона начинается с `verdicts/` (zones_load — ЕДИНСТВЕННЫЙ читатель; отказ
   реестра зон → fail-closed «реестр зон недоступен»).
6. **Автор — судья:** автор последнего коммита, коснувшегося пути (%an `git log -1`),
   ∈ множества владельцев зон, покрывающих путь (те же зоны, что в проверке 5).

Успех: базлайн переснимается (формат снимка — тот же: root/verify/mode-lock), stdout
несёт стенограмму: «базлайн переснят: вердиктная дельта <путь> (автор <автор>, коммит
<sha>)»; rc 0. Последующий `--check` → rc 0 «основной чекаут чист».

Отказ — rc 1, ИМЕНОВАННОЙ причиной, СНИМОК НЕ ТРОНУТ (последующий --check обязан
остаться красным — «переснятие, прячущее НЕ-вердиктную дельту, краснеет», слово
владельца):

- «переснятие не доказано: дельта пуста — нечего переснимать»
- «переснятие не доказано: дельта не ровно-один-файл»
- «переснятие не доказано: путь не вердиктный (зона судьи не объявлена)»
- «переснятие не доказано: автор дельты не судья зоны»
- «переснятие не доказано: porcelain не чист — дельта обязана быть закоммичена»
- «реестр зон недоступен»

`--retake` НЕ меняет семантики `--snapshot`/`--check` (режимы 024 дословно; новая
утилита внешнего вызова, если появляется, — через тот же TRUSTED_PATH-пин, голое имя
после блока пина — дефект, шапка 024:83-87).
