## Боль (измеренная, CI 2026-09-02)

Разброс длительности CI на сопоставимом коде: **105 с** (`17bf21d`) ↔ **35–42 мин**
(`6a65236`, `8b9b4d9`, `1cc6b27`, `6b789b8`) ↔ **5 мин** (`b2c0343`). Доминирует шаг
«Анти-плацебо» (UI-номер 5 с учётом служебного «Set up job»;
`npm run check:antiplacebo -- --changed ${{ github.event.before }}`). Локально тот же

не симптомом (перепрогонами), а структурой шага.

Масштаб предмета по дереву: 36 каталогов `fixtures/<барьер>/`, 330 `case_*.sh`;
`verify_antiplacebo.sh` обходит барьеры последовательно, шардирования нет.

## Предмет

Шардирование шага «Анти-плацебо» в `.github/workflows/ci.yml`: matrix по барьерам
(ключ `fixtures/<барьер>/`) или иная нарезка — по коду `scripts/verify_antiplacebo.sh`
(обход барьеров, `--scope <ключ>`, `--changed <base>` через `scope_select.sh`) и
`.github/workflows/ci.yml`. Каждый шард прогоняет своё подмножество фикстур; критерий
нарезки и N шардов — развилка Р1 (владелец).

## Инварианты

1. **Правило 6 (гейт не зеленее CI):** каждая команда из `run:` каждого шарда имеет
   пункт в приёмке (`scripts` в `package.json` либо объявлена в
   `config/ci_parity_exceptions.txt` с причиной); `scripts/verify_ci_parity.sh` —
   зелёный на новой проводке.
2. **Scoped-режим для судей (Н-48) сохраняется:** `bash scripts/verify_antiplacebo.sh
   <корень> --scope <ключ>` работает дословно как сегодня — шардирование меняет ТОЛЬКО
   CI-проводку, не раннер и не CLI.
3. **Сумма шардов = полный набор фикстур:** ни одна `fixtures/<барьер>/case_*.sh` не
   выпадает из всех шардов и не попадает в два шарда; нарушение — красное (см.
   приёмку).

## Приёмочный критерий (КРАСНЫЕ ТЕСТЫ; текст уточняется грилингом Р1–Р4)

Приёмка через фикстуры/стабы несёт КРИТЕРИЙ ВАЛИДНОСТИ контрпримера (демаркацию) с
первой редакции (норма R1, roles/architect.md:92-97): какие входы КОНФОРМНЫ
(перечисление фикстур — по документированной грамматике раннера:
`fixtures/<ключ барьера>/case_*.sh`, ключ = путь в `scripts/` без расширения), и что
валидный контрпример = инвариантность к значениям ∧ расхождение на КОНФОРМНОМ входе.
Каждый обманный стаб — к тому входу, где его дефект НАБЛЮДАЕМ (Н-39 дословно,
NABLIUDENIA.md:688).

- **Красное на выпавшую:** из соответствия «шард → фикстуры» изымается одна конформная
  `case_*.sh` (не значением, а структурно — стаб/правка соответствия) → проверка
  полноты (инвариант 3) обязана дать rc≠0 с названной фикстурой.
- **Красное на задублированную:** одна конформная `case_*.sh` приписывается двум
  шардам → rc≠0 с названной фикстурой и шардами.
- **Красное scoped-режима:** стаб проводки, ломающий `--scope <ключ>` (раннер
  изменён/ограничен) → существующие scoped-фикстуры раннера красные.
- **Красное правила 6:** `run:`-команда шарда без пункта приёмки →
  `verify_ci_parity.sh` отказывает с текстом команды (прецедент: находка адверсария
  по `&&`-хвостам).
- Зелёное: полная сумма шардов на чистом чекауте эквивалентна сегодняшнему полному
  прогону (тот же набор барьеров/фикстур); `check:ci-parity` зелёный.

## Не-цели

- Покупка/настройка self-hosted-раннера ВНЕ репозитория (если Р2 выберет владельца —
  отдельное решение с деньгами, в этот контракт не входит; в репо попадает только
  проводка под выбранный раннер, если он выбран).
- Изменение семантики раннера `verify_antiplacebo.sh` (правила игры фикстур,
  память-проверяющего, протокол канала) — не трогается.
- Ускорение отдельных барьеров (профилирование/кэш) — отдельная работа, если вообще.
