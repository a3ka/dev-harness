## Нарезка / Frontier (различение «секретный ключ» ↔ «не-секрет»)

| Вариант | Суть | Цена/риск | Решение |
|---|---|---|---|
| А — белый список секретных суффиксов по букве слова владельца | судим только `*_API_KEY`/`*_TOKEN`/`*_SECRET`/пароли | неназванные секретные имена (DATABASE_URL, PRIVATE_KEY, STRIPE_KEY, `*_PASSPHRASE`, AUTH, COOKIE) ускользают — fail-open | **отклонён** (не проходит обязательную клетку fail-open) |

| **Г — сочетание (ВЫБРАН)** | значение судимо ⟺ имя несёт секретный МАРКЕР (токены по `_`, регистр нечувствителен) ∨ имя НЕ оканчивается адресным суффиксом ∨ значение несёт учётные данные (userinfo) | маркер сильнее суффикса; канон — три строки (И-1); сужение против текущего стража — только класс «адресный суффикс ∧ значение без userinfo» (И-4) | **выбран**: закрывает боль (METERING_PROXY_URL), сохраняет защиту всех неназванных секретов |

**Расхождение с буквой слова владельца (названо, не молча):** буква перечисляет секретные суффиксы («только `*_API_KEY`, `*_TOKEN`, `*_SECRET`, пароли»); Г судит БОЛЬШЕ буквы — любое имя без адресного суффикса считается секретным (fail-closed: LOG_LEVEL, REGION и прочие «прочие параметры» вне шести суффиксов продолжают давать ложный отказ, как сегодня). Направление расхождения — безопасное (защита не сужается против текущего стража); решение о воле (расширить адресный алфавит поимённо) — владельцу, строка-ЧЕРНОВИК для батча: `РАЗРЕШИЛ-ВЛАДЕЛЕЦ: страж sekret-v-dereve (зона 125/136) — предикат 142: секретный маркер имени (KEY TOKEN SECRET PASSWD PASSWORD PASSPHRASE PRIVATE AUTH COOKIE CREDENTIAL — токены по подчёркиванию, без регистра) сильнее адресного суффикса (_URL _HOST _PORT _ADDR _ENDPOINT _NAME и базовые имена); адресное имя со значением без учётных данных (фрагмент «user:pass@») не судится; всё прочее судится как прежде; слово владельца 2026-10-26 skaner-sekretov.`

Нарезка (050): 142 — один наблюдаемый результат «адрес/порт/имя дома секретов в индексируемом файле проекта не блокирует `connect_project.sh`; секретный ключ (названный или неназванный) и учётные данные в значении — блокируют по-прежнему». ## Предмет и инварианты

1. **И-1 канон.** Предикат секретности — ТРИ строки канона, единственный источник (`source.json:.kanon`, модель и субъект несут их байт в байт, клетка `r1-kanon-v-subekte`): `SEKRET_MARKERY="KEY TOKEN SECRET PASSWD PASSWORD PASSPHRASE PRIVATE AUTH COOKIE CREDENTIAL"`, `ADRES_SUFFIKSY="_URL _HOST _PORT _ADDR _ENDPOINT _NAME URL HOST PORT ADDR ENDPOINT NAME"`, `USERINFO_RE='[^/@[:space:]]*:[^/@[:space:]]*@'`. Маркеры и суффиксы сопоставляются по ТОКЕНАМ через подчёркивание (`OLD__API_KEY` содержит токен KEY), имя складывается к верхнему регистру ДО сопоставления.
2. **И-2 судимость.** Значение судимо ⟺ (имя несёт секретный маркер) ∨ НЕ (имя оканчивается адресным суффиксом И значение не содержит userinfo). Маркер сильнее суффикса (`API_KEY_URL` судимо). Userinfo — ЛЮБОЙ фрагмент `user:pass@`/`:pass@` в значении, без привязки к схеме (DSN без схемы и пустой пользователь ловятся).
3. **И-3 адреса и параметры не судятся — предикат по замкнутому алфавиту суффиксов, а не белый список имён.** Имя с адресным суффиксом и значение без учётных данных (`METERING_PROXY_URL=http://127.0.0.1:8787`, `*_HOST`, `*_PORT`, `*_NAME`, `*_ENDPOINT`) не попадает в список сканируемых значений — сессия поднимается (боль уходит). Свойство доказано на КАЖДОМ суффиксе замкнутого алфавита канона (`_URL _HOST _PORT _ADDR _ENDPOINT _NAME` + базовые `URL HOST PORT ADDR ENDPOINT NAME`) именами ВНЕ прежних позитивных клеток: k19–k30 (REPORTS_URL, CACHE_HOST, GRPC_PORT, PROXY_ADDR, METRICS_ENDPOINT, TENANT_NAME, SITEURL, DBHOST, HTTPPORT, NODEADDR, APIENDPOINT, CLUSTERNAME) — сессия; парные k31–k42 (те же имена + userinfo в значении) отказывают — учётные данные сильнее суффикса; стаб «whitelist пяти имён прежних позитивных клеток» (обход критика, вердикт contracts-142-v1) краснеет на k19–k30.
4. **И-4 монотонность (fail-closed).** Множество судимых значений после 142 — подмножество судимых текущим стражем; единственное разрешённое сужение — класс И-3. Неназванные секретные имена (DATABASE_URL с учёткой, PRIVATE_KEY, STRIPE_KEY, KEY_PASSPHRASE, AUTH, COOKIE), секретный маркер в нижнем регистре, короткие значения — судимы по-прежнему.
5. **И-5 страж 125 дословно.** Имя/текст/момент отказа `sekret-v-dereve` (rc 1 ДО сессии, в отказе — имя файла, не значение), fail-closed по инструментам, парсер KEY=VALUE (первый `=`, усечение пробела, `#`-комментарии, CRLF-снятие, идиома последней строки, пропуск пустых значений, обе формы значения), границы `git ls-files --cached --others --exclude-standard`, `grep -lsF` без порога длины — не меняются и не ослабляются.
