# Контракт 212 — REPLACE строки реестра после ленда PR: механизм станции (одноразовый клон, ветка main, дверь 031)

СТАТУС: ЧЕРНОВИК-ЗАТРАВКА (bootstrap: `make_task --role architect` требует существующий `contracts/212-*.md`; текст контракта пишет architect по заданию станции — затравка не является ни спекой, ни критерием; заменяется целиком).

## Боль
Измерено 22–23.11 (204, 205, 207, 206, 208): после ленда носителя заморозки и публикации тега `frozen/contracts/<N>/1` строку `registry/contracts.tsv` `<N> → <id-tag-object>` нужно ЗАМЕНИТЬ (REPLACE) на `<N> → <tag-object frozen/contracts/<N>/1>`. Дверь минта 031 (`scripts/check_staged.sh`, REPLACE-форма) судит коммит ТОЛЬКО на ветке `main` (`current_branch == main`) при живом локальном теге `refs/tags/frozen/contracts/<N>/<v>` и условии «коммит заморозки — предок origin/main»; `freeze_contract.sh` в int-worktree (ветка не `main`) → «ОТКАЗ: реестр не закоммичен: дверь минта 031: дверь не на main». Основной чекаут станции писать нельзя (Н-85/А-122: запись в чекаут из непиннованной сессии запрещена; null-allowlist `/tmp/dev-harness-verify/**`, `artifact://`), identity consultant на `registry/contracts.tsv` — «вне зоны», owner — «не судится». Следствие: REPLACE делается РУКАМИ в одноразовом клоне (`/tmp/dev-harness-verify/consultant/replace-consultant.sh`, `/tmp/dev-harness-verify/replace-orch.sh`: клон → локальная `main` = origin/main → `git fetch origin refs/tags/frozen/contracts/<N>/1:…` → замена строки → коммит (дверь 031 пускает identity orchestrator) → push `wip/<N>/replace` → PR → влив консультантом), каждый раз ~20–30 мин и отдельный PR; без строки на main у судей реализации `KLASS_RISKA_NET` (см. 211).

## Решение
Слово владельца 22.11 (через консультанта): «новая задача станции: REPLACE реестра после ленда PR — механизмом станции». Направление: скрипт станции `scripts/replace_line.sh --nnn <N> [--root …]` (по образцу `mint_line.sh`, контракт 068): проверяет dual-control провенанс (локальный тег `frozen/contracts/<N>/<v>` = тег на origin = объект, коммит заморозки — предок origin/main, старая строка = id-tag-object, повторный REPLACE отказ, чистое дерево, ветка main), заменяет РОВНО одну строку и коммитит identity orchestrator штатной дверью 031 (без обхода); место выполнения — одноразовый клон под null-allowlist либо иное разрешённое страж-слоем место (architect решает по коду: страж Н-85, `gitw`, 071) — с публикацией через штатный `gitw`/PR (push main — только через PR и CI, `gitw` предполёт «код-через-PR»). Нужные свойства и границы формулирует architect.

КЛАСС ЗАДАЧИ: кодовый. КЛАСС РИСКА: рисковый (запись в исключительную dual-control зону реестра контрактов; права/устав — ослабление двери минта недопустимо; adversary → reviewer).
РАБОТА НЕ РАЗДАЁТСЯ: затравка; зоны и раздачу объявляет architect.

## Незаполненные требования:
- точные зоны (`scripts/replace_line.sh` — новый; `scripts/check_staged.sh` дверь 031 — не ослабляется; `scripts/gitw*`; `scripts/freeze_contract.sh` — сообщение отказа/подсказка маршрута; `registry/contracts.tsv` — только строка) и ПЕРЕСЕЧЕНИЕ с активными предметами (031, 049, 068, 130 И-8, 140, 211);
- инварианты: REPLACE только при условиях двери 031 (ветка main, живой локальный frozen-тег = тег на origin, коммит заморозки — предок origin/main, старая строка = id-tag-object); одна строка; повтор отказ; дерево чисто; никакого обхода/`--no-verify`; identity orchestrator, без owner; публикация только через PR+CI;
- красные клетки (честный REPLACE проходит; тег не на origin / коммит заморозки не предок main / строка не та / повтор / грязное дерево / ветка не main / `--no-verify`-инъекция — отказ с именованной причиной) и стабы к ветвям — привязывает architect по коду.
