Orchestrator регистрирует шаг `check:replace-posle-lenda-212-family-selftest` и его замер: до ленда реализации — `--model`, `--stabs`, `--sintaksis`; после ленда — `--repo .`, `--stabs`, `--sintaksis`. ## Инварианты

1. CLI: N — одна строка из 1–3 ASCII-цифр, нормализуется до NNN; R — корень git-репозитория, умолчание cwd. Строка реестра строго `NNN → [0-9a-f]{40}` с U+2192; объект — annotated tag, не peeled commit. Сравнения tag-object и старой строки литеральные, не regex/glob из данных. Код возврата CLI — ОДИН договор в тексте, модели и клетках, по образцу `mint_line.sh` 068: отсутствие обязательного `--nnn` либо неизвестный аргумент — rc 1 с usage; N вне грамматики 1–3 цифр, R не каталог/не репозиторий либо недоступен git — rc 2 `NOT_IMPLEMENTED` (отсутствие аргумента и негодное значение различаются кодом).
2. До записи: HEAD — main, дерево и индекс чисты, локальная main равна **живой** `refs/heads/main` origin (не stale tracking-ref). Иначе именованный rc 1 без изменения HEAD/индекса/реестра. Место — основной чекаут станции по маршруту 068 либо иной разрешённый чистый чекаут через --root; чистоту и ветку скрипт проверяет сам, страж места не выключает.
3. До записи удостоверен локальный annotated `frozen/contracts/NNN/vmax`, равный по tag-object тому же ref на origin. `vmax` выбирается той же числовой мерой, что дверь 031, среди живых локальных версий `[0-9]+`. Сеть недоступна — отдельный отказ «авторитет недоступен»; отсутствующий origin-тег — «не выдан авторитетом»; разные объекты — «переминт заморозки».
4. Коммит, разыменованный из выбранной заморозки, — предок живой main origin. Одной публикации тега без ленда недостаточно: rc 1 «не предок origin/main», дерево не мутируется.
5. В HEAD реестра ровно одна строка NNN: ноль/дубль — именованный отказ. Грамматику проходит ВЕСЬ манифест HEAD единым шаблоном «NNN → 40-hex»: NUL-байт, CRLF-окончание строки, лишние поля после sha, пустая строка — каждый своим именованным отказом (NUL — с номером причины «реестр не текст», прочие — с номером первой неконформной строки) ДО записи и ДО любых command substitution над манифестом: `$()` молча выбрасывает NUL (с предупреждением в stderr) и все конечные LF и не может быть источником байтового суда. Незавершённая последняя строка — конформное состояние честного мира, не неконформный вход. Старая сторона — annotated id/CONTRACT/NNN либо frozen/NNN/(vmax−1), как у двери 049; новая — tag-object выбранной заморозки. Строка уже равна новой — rc 1 «повторный REPLACE», второго коммита нет. Последовательный догон предыдущей версии сохраняется; пропуск промежуточных версий не расширяется.
6. Замена — полное равенство старой строки: запись во временный файл и mv, одна строка изменена, прочие байты реестра сохранены ПОБАЙТНО, включая край файла: чужая последняя строка без завершающего LF не получает нового байта, завершённый манифест не теряет конечный LF (разделители печатает явный printf, не `print`). Один commit содержит только профильный реестр. Его author и committer — orchestrator, email orchestrator@dev-harness.local, переданные явным env на вызове commit.
7. Эффективный hooks-каталог до записи содержит исполняемый pre-commit; конфиг-дизарм — отказ. Commit проходит штатным хуком: ни `--no-verify`, ни `-c core.hooksPath`, ни других `-c` на его командной строке. Отказ хука не замалчивается: rc 1 с именем двери, точечное восстановление пути из HEAD. Другие identity и зоны не получают разрешений.
8. Успех: rc 0, stdout ровно `REPLACED nnn=<NNN> old=<40hex> new=<40hex> commit=<40hex>\n`. Stderr сохраняет вывод штатного хука, не подавляется. Отказ предмета — stderr `ОТКАЗ: <причина>\n`, rc 1; недоступность инструмента проверки — rc 2. Скрипт не пушит, не двигает теги, не создаёт PR, не ослабляет first-parent признание.

Все эти сценарии исполняются одной батареей на настоящем git и живом pre-commit → check_staged.sh в одноразовых репозиториях TMPDIR.

### Наблюдение и валидность контрпримера

Наблюдение — rc, **полные stdout и stderr bytes** без text-режима, декодирования, strip или преобразования CRLF/CR перед сравнением. Пред-состояние, исходные объекты тегов, ожидаемые строки и причины фиксируются в памяти проверяющего до запуска. Поле commit успеха сверяется с фактически созданным HEAD через git plumbing, затем отдельно проверяются один новый коммит, содержимое реестра, identity и чистота; оно не заменяет проверку эффекта. Ожидания не перечитываются из изменённого субъектом реестра. Байт-границы обеих труб включают CRLF, CR, пробел, двойной LF, BOM, NUL, не-UTF8, лишний вывод и перенос между трубами.

Демаркация: контрпример — расхождение на CLI/refs/манифесте объявленной грамматики при инвариантности к NNN, значениям объектов и путям. Умышленно неконформные CLI/реестры (NUL, CRLF, лишние поля, пустая строка) предъявляются как негативы со своим кодом, а не становятся новым разрешённым языком; отсутствие завершающего LF — конформное состояние, а не негатив. Миры несут разные номера, не только 212; константа номера имеет адресное предъявление. Живые ветка, hooksPath, local/origin теги и git DAG проверяются не двойником git, а настоящим инструментом.

## Модель угроз

ЗАЩИЩАЕТ:
- От REPLACE до ленда и self-freeze: локальная annotated заморозка равна опубликованной, её коммит — предок живой main origin; отсутствие сети, тега и расхождение объектов имеют разные именованные отказы.
- От обхода двери и расширения полномочий: чистая main, живой pre-commit до записи, commit без обходных флагов, фиксированная identity orchestrator; вывод двери наблюдается в stderr успеха, нарушение конфигурации даёт отказ.
- От порчи учёта: ровно одна адресная строка, старая сторона удостоверена, повтор не пишет второй коммит, чужие строки байт-в-байт сохраняются вместе с краем файла (незавершённая последняя строка не получает LF); грамматика всего манифеста и NUL-байт проверяются до записи по трубе plumbing, минуя молчаливые выбросы command substitution; отказ commit возвращает только реестр к HEAD. Ловец — клетки честных и неконформных миров и адресные обманные копии матрицы.
- От плацебо наблюдения: один путь запуска и полный байтовый предикат обоих потоков во всех режимах, пред-снимок в памяти, адресная матрица с уникальными якорями и проверкой каждой связи.

НЕ ЗАЩИЩАЕТ:
- Историческая пара 6eebe0302/registry/contracts.tsv не становится законной: grandfather требует отдельного слова владельца; ловец — владелец через консультанта и существующий check_zones. Это зависимость озеленения всей истории main, не повод расширять first-parent допуск.
- Гонка origin после снимка до отдельного push не исключается: non-fast-forward отказывает публикации; ловец — gitw/pre-push и CI. Теги и авторитет origin остаются доверенной зоной, их авторство дополнительно не аутентифицируется.
- Наличие исполняемого pre-commit не удостоверяет произвольное злонамеренное тело хука или подложный git в PATH; ловец — доверенная установка станции, review/adversary и CI. Новый инструмент не снимает остаток 016/068.
- Побайтовая форма сообщений check_staged может измениться отдельным контрактом: батарея намеренно фиксирует штатный вывод двери; ловец — красный model-контроль и суд совместимости такого изменения.
- Проектные варианты профиля используют существующий резолвер 996, но отдельная продуктовая интеграция не обещана этим станционным предметом; ловец — профильные батареи 996 и судьи проекта.
- Конечная батарея не доказывает эквивалентность произвольной программы; сверх объявленной грамматики и конечных предъявлений ловцы — adversary и reviewer реализации. Общий временной порядок между двумя раздельными трубами не наблюдается, порядок байтов внутри каждой наблюдается полностью.
