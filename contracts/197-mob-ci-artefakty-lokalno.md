2. **И-2 грамматика пути — один источник.** Путь `<koren>/<run_id>-<run_attempt>/<имя>/` строит ТОЛЬКО скрипт-канон `mobile/scripts/ci-artefakty.cjs` (байтовый пин, клетка e01); литерал корня в workflow не встречается (d01). Вызовы — однострочные `npm run ci:artefakt-zapis -- --imja M --chto P` / `npm run ci:artefakt-chtenie -- (--imja M | --shablon G) --kuda D [--run-id R --run-attempt T]` из замкнутого набора ключей (b01/c01), каждый — в одном из трёх контекстов И-8; значения lanes в package.json — канон (e02). Корень по умолчанию `/var/lib/ci-artifacts/Complior-mob`; env `CI_ARTEFAKTY_KOREN` (переопределение для replay батареи и станции) workflow НЕ задаёт.
3. **И-3 писатель — собственный run-контекст.** Шаг-писатель не передаёт `--run-id/--run-attempt` (b03); скрипт берёт `GITHUB_RUN_ID`/`GITHUB_RUN_ATTEMPT`, оба обязаны быть числовыми (r05); записи попыток лежат в разных каталогах (r09).
4. **И-4 APK — продюсерская попытка.** `build-apk` публикует output `run_attempt` (рядом с `apk_sha256`/`artifact_name`/`run_id`); читатели потребляемой категории APK (класс `--imja` покрывает `apk-*`) ОБЯЗАНЫ передавать пару `--run-id/--run-attempt` из `needs.build-apk.outputs`: отсутствие пары у APK-читателя → `CHITATEL_APK_BEZ_PARY` (c03; Frontier-строка «ищет в собственной попытке» судится и в нулевой форме), неполная пара → `NEPOLNAJA_IDENTIFIKACIJA_RUNA` (c01); ПРОИСХОЖДЕНИЕ значений после env-разрешения — только выражения `needs.build-apk.outputs.run_id`/`needs.build-apk.outputs.run_attempt` (c03: `RUN_PARA_NE_IZ_SBORKI`; литеральная пара чужого прогона красна по происхождению — запрещённая оболочка вызова, прячущая пару за кавычной охраной с оператором, отсекается грамматикой И-8 раньше); имя артефакта по-прежнему из outputs сборки (литерал env `IMJA_ARTEFAKTA` сохранён), digest сверяется до установки — сборка переживает выборочный повтор работника (r02), семантика И-4 frozen 143 сохранена.
5. **И-5 замыкание и fail-closed.** Каждый читаемый `--imja`/`--shablon` структурно совпадает с каким-то писателем того же workflow (c02: разрешение цепочек env→needs→steps и matrix-классов — структурная проверка, наличие писателя в workflow не зависит от того, исполнился ли он в прогоне); чтение отсутствующего ТОЧНОГО имени (`--imja`) и отсутствующего каталога run'а — именованный отказ rc 2, не пустой успех (r02/r11); пустой выбор ШАБЛОНА вынесен из fail-closed в И-7 (r10) — v+1, слово владельца 2026-11-16 «197 v+1 — да»: замороженная форма «отсутствующий шаблон — отказ» краснила каждый PR без новых экранов (mob#180: matrix пуста → `SOVPADENIJ_NET` rc 2 → required android-e2e красна), до 197 тот же шаг был `actions/download-artifact` с `pattern` и при отсутствии совпадений НЕ падал.
6. **И-6 алфавит имени и страж корня.** Имя `[A-Za-z0-9][A-Za-z0-9._-]*` без `/`, не `.`/`..`; шаблон того же алфавита с `*`; источники/назначения — относительные пути без сегмента `..` (d02); скрипт после сборки пути сверяет префикс корня — побег невозможен даже при пропуске алфавита (r03/r04).
7. **И-7 семантика переноса сохранена.** `<имя>/` — всегда каталог: файл кладётся внутрь под своим именем, каталог — содержимым (семантика upload/download-artifact); шаблонный сбор кладёт каждого ребёнка отдельным каталогом (эквивалент `merge-multiple: false`, r07); `if-no-files-found: error` эквивалентен отказу `ISTOCHNIK_OTSTUTSTVUET` (r08); шаблонное чтение без совпадений — семантика download-artifact с `pattern` (v+1): rc 0, именованная строка `CHTENIE_PUSTO: <шаблон>`, каталог `--kuda` создан ПУСТЫМ (r10); строгость по ожидаемому множеству сохраняет потребитель — `ci-aggregate.cjs` («Verify selected children», шаг сразу после читателя) сверяет ВЫБРАННЫЕ экраны с evidence-каталогом ровно: непустой выбор при пустом evidence — именованный отказ агрегата, ложной зелени нет; шаблонных чтений в каноне ровно два, оба `screen-evidence-*` (android-e2e, mobile-regression-signal).
8. **И-8 полная форма носителей, исполнимость и замкнутый инвентарь.** Run-текст носителя — ЗАМКНУТАЯ ГРАММАТИКА БЕЛОГО СПИСКА (арбитраж Arb197V1, РЕШЕНИЯ 1–2): кандидат обнаруживается по ЛИТЕРАЛЬНОМУ имени lane (`ci:artefakt-zapis`/`ci:artefakt-chtenie`) в run-тексте шага — ДО и БЕЗ какого-либо shell-разбора, неудача разбора не делает шаг «не-носителем»; весь текст кандидата обязан совпасть с одной из трёх измеренных форм (разложение 11+1+5 на модели): L — одна строка вызова; S+L — строка `set -euo pipefail`, затем L; P+L+Q — APK-блок: фиксированный префикс P (set, проверки IMJA_ARTEFAKTA/ZHELANYJ_DIGEST, подготовка apk-build), затем L, фиксированный суффикс Q (проверка файла, вычисление и сравнение digest, mkdir, cp) — управляющие конструкции допустимы только в фиксированных P/Q с этим содержимым. L — закрытая форма И-2 с ПОЛНЫМ потреблением аргументов: `npm run <lane> -- <ключ> <значение>…`, пары без хвостов и повторов, ключи из замкнутого набора `{--imja,--chto,--shablon,--kuda,--run-id,--run-attempt}`; значения — литерал, `'…'`, `"…"` из литеральных кусков, кавычных env-ссылок `$NAME` и подстановок `${{ … }}`; обратная косая черта и shell-метасимволы в алфавит не входят. Иное → `FORMA_NOSITELJA_VNE_GRAMMATIKI` (g01): композиция операторов у вызова (включая экранированную кавычку `test \" = x && npm run …` и перенос после оператора), субшелл/группа/if-обёртка/подстановка `$(…)`, фон `&`, инверсия `!`, вариант `set` без `-e`, посторонняя команда-спутник, lane-имя в echo/heredoc — исполненной операцией не считаются (fail-closed: семантические клетки такой шаг не видят, инвентарь i02 текстом-призраком не закрывается). Носитель не может быть тождественно неисполним и не может подавлять свой провал (i01): поле `if:` шага — замкнутый набор канона `{отсутствует, always(), success()}`; `if: false`/`${{ false }}` → `NOSITEL_NEISPOLNIM`, прочее условие → `USLOVIE_VNE_KANONA`; `continue-on-error` на шаге носителя, на его job'е и в его `strategy` → `PROVALY_PODAVLENY`; константная ложь в `if:` job'а носителя (Yaml-булево `false`, текстовые формы, замаскированная `${{ !always() }}`) → `JOB_NOSITELJA_OTKLJUCHEN` — структурные job-условия вне замкнутого списка константной лжи не судятся (канон needs/matrix — предмет 143). Инвентарь имён предмета замкнут (i02): пять категорий (APK сборки `apk-*`, selection.json `selection`, доказательства экранов `maestro*`, child-evidence `screen-evidence-*`, маркер полной регрессии `regression-marker`) обязаны иметь писателя (`KATEGORIJA_BEZ_PISATELJA`), посторонний писатель вне категорий красен (`POSTORONNIJ_PISATEL`), потребляемые категории (APK, child-evidence) обязаны иметь читателя в workflow (`KATEGORIJA_BEZ_CHITATELJA` — молчаливая потеря видима; терминальные читает ops/server, предмет 196). Клетка краснеет, когда операция ОТСУТСТВУЕТ или НЕИСПОЛНИМА, а не когда в файле есть текст.

## Модель угроз

ЗАЩИЩАЕТ:
- от возврата к квоте GitHub: закрытие канала upload/download/gh run download статически (a01–a03), включая «один забытый шаг»;
- от транспорта мимо канона: сырые пути и посторонние команды у писателей (b01/d01/d02), байтовый пин скрипта (e01), замкнутые lanes (e02);
- от потери сборки при повторе и от чтения чужой попытки: продюсерская пара run_id/run_attempt у каждого APK-читателя — наличие и ПРОИСХОЖДЕНИЕ значений судятся (только needs.build-apk.outputs; И-4, c01/c03), fail-closed чтение точного имени и каталога run'а (r02/r11);
- от неисполнимых носителей и молчаливой потери: замкнутые if/continue-on-error/job-условия носителей (шаг, job, матрица), полная форма run-текста носителя — ровно один самостоятельный foreground lane-вызов в одном из трёх измеренных контекстов L/S+L/P+L+Q; композиция операторов у вызова (включая экранированную кавычку B6 и перенос после оператора B14), субшеллы/группы/if-обёртки/подстановка `$(…)`, фон, инверсия, вариант `set` без `-e`, echo/heredoc-носитель — единый именованный отказ формы, замкнутый инвентарь пяти категорий с читателями потребляемых (g01/i01/i02, И-8);
- от слияния попыток и побега за корень: числовые контексты, изоляция каталогов (r05/r09), алфавит имени и страж префикса (r03/r04, d02).
- от ложной зелени пустого шаблонного сбора: пустой выбор — rc 0 с именованной строкой `CHTENIE_PUSTO` и ПУСТЫМ созданным `--kuda` (r10), а строгость ожидаемого множества держит потребитель ci-aggregate («Verify selected children») — непустой выбор при пустом evidence даёт именованный отказ агрегата; точное имя тихо прошедшим не бывает (r11);
- от слепоты носителей к рабочему каталогу: при `defaults.run.working-directory` ≠ корень каждый носитель несёт шаговый `working-directory: ${{ github.workspace }}` (g02) — lane не теряется в `mobile/package.json` (урок mob#180).

НЕ ЗАЩИЩАЕТ:
- физическое владение/права корня и очистку каталогов run'ов — предмет 196; ловец — живой прогон CI после ленда;
- поведение GitHub вне артефактного слоя (needs/агрегат/матрица/порядок шагов) — предметы 143/141/148, батарея целостность DAG не судит;
- произвольные замаскированные константно-ложные job-выражения ВНЕ замкнутого списка (`${{ false == true }}` и подобное) — статический вычислитель выражений GitHub вне предмета; ловец — живой прогон CI (fail-closed агрегат 143 требует доказательства невыполнившихся работников);
- `mobile-cloud-e2e.yml` (облачный раннер, 2 upload-шага по замеру) — вне предмета;
- снятие неиспользуемого `actions: read` у пяти работников — гигиена permissions, отдельное решение владельца;
- ретенцию доказательств после очистки таймером 196 — наблюдаемо только живой станцией.
- канал upload-artifact ВНЕ mobile.yml (локальные composite actions `.github/actions/**`, другие workflow продукта) — батарея осматривает только mobile.yml и package.json lanes; сегодня это ловит `verify_ci_parity.sh` (флаг «локальный composite action не обходится»), защита держится на пути-обходе паритета (Совет 4 вердикта).
- произвольный shell ВНЕ обнаруженных носителей: косвенный вызов lane через переменную, eval, функцию, другую программу или имя, составленное по частям, — белый список прямых носителей не доказывает отсутствия косвенных операций во всём workflow; ловец — reviewer реализации по полному diff mobile.yml/package.json и действующий verify_ci_parity (остаток арбитража 197, РЕШЕНИЕ 3);
- поштучную сохранность каждого maestro-писателя: инвентарь категорий закрывает категорию целиком, удаление одного писателя при наличии других категорию не роняет; ловец — reviewer по исходному инвентарю всех 17 операций и diff переноса, реальный мобильный прогон CI после ленда (остаток арбитража 197).
