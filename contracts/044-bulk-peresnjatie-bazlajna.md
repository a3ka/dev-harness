## Предмет

ВТОРАЯ дверь переснятия базлайна детектора утечек: режим `bash scripts/check_no_leak.sh
--retake-bulk <абс-корень>`. Существующая дверь 031 `--retake` (do_retake,
scripts/check_no_leak.sh:1213-1373) принимает ТОЛЬКО дельту РОВНО ОДНОГО пути (шаг 4:
`n_paths -ne 1` → отказ), покрытого ЗОНА-строкой с префиксом `verdicts/` (шаг 5), автор
последнего коммита которой — владелец этой зоны (шаг 6). Это узкий частный случай
«судья написал один вердикт между спавнами». Реальная боль — многочасовая ЛЕГИТИМНАЯ
многокоммитная работа с путями ВНЕ verdicts/:

- исходный Н-139: 17 путей на HEAD `765ec15463ff4ad5346e8c70882ed9c7eb0863db`
  (verdicts/critic/*, verdicts/arbitration/*, contracts/*, scripts/*, fixtures/*,
  HANDOFF.md, package.json, .github/workflows/ci.yml);
- рецидив на 043 (2026-09-24): 2 пути на HEAD `7d8d864b7b54668400f74c597a8dd96d91359e2d`
  (verdicts/adversary/* + fixtures/check_precision_gate/*).

Оба раза владелец/консультант становился РУЧНЫМ ОРАКУЛОМ ровно того факта, который git
уже несёт: `git status --porcelain` пусто; `git rev-list --left-right --count
origin/main...HEAD` → `0 0`; на каждый путь дельты `git log -1 --format=%H -- <путь>`
достижим на origin/main и его автор — владелец зоны, покрывающей путь. 044 делает этот
факт МЕХАНИЗМОМ: bulk-дельта принимается ⟺ «ровно ноль незакоммиченного/неслитого»
(не «ровно один путь»), с тройным замком на каждый путь: зона ∧ автор-владелец ∧
origin-достижимость.

Однопутевая вердиктная дельта остаётся предметом 031 `--retake` — 044 НЕ меняет ни его
семантику, ни текст 031, ни режимы `--snapshot`/`--check` (024).

## Инварианты (механизм: дверь bulk-переснятия, scripts/check_no_leak.sh, режим `--retake-bulk`)

Грамматика CLI сохранена: ровно два аргумента (режим + АБСОЛЮТНЫЙ корень); диспетчер
узнаёт новый режим, usage-строка перечисляет все четыре: «ОТКАЗ диспетчер:
использование: check_no_leak.sh --snapshot|--check|--retake|--retake-bulk <абс-корень>».
Переснятие bulk-дельты ПРОИСХОДИТ ⟺ ДЕВЯТЬ шагов ВМЕСТЕ (порядок: снимок → porcelain →
двойное чтение → дельта → реестр зон → origin → каждый путь → глобальная синхронизация →
снимка):

1. **Снимок существует и цел** — защиты-снимка 024 дословно (симлинки файла/каталога/
   промежуточного, регулярный файл, root-строка, mode 0444, verify-строка и сходимость
   sha) — те же имена ветвей отказа, что у `--retake` (031 §Механизм-2 п.1); НОВЫХ имён
   для наследуемых защит не заводится.
2. **Porcelain чист:** `git status --porcelain` пуст → иначе отказ
   «переснятие-bulk не доказано: porcelain не чист — дельта обязана быть закоммичена».
3. **Двойное чтение манифеста** (TOCTOU 024-Б4 дословно): расходление двух чтений →
   «основной чекаут мутировал во время сверки…» (имя 024, без изменений).
4. **Дельта непуста** (семантика 024: новые строки манифеста против базлайна) → иначе
   «переснятие-bulk не доказано: дельта пуста — нечего переснимать».
5. **Реестр зон жив:** zones_load rc ≠ 0 → «реестр зон недоступен»; rc 0, но в реестре
   НОЛЬ зон вовсе → «переснятие-bulk не доказано: реестр зон пуст — читатель ослеплён»
   (аналог ослеплённого читателя 031, обобщённый с «ни одной verdicts/-зоны» на «ни
   одной зоны»: bulk-дверь судит по полному реестру — пустой реестр для неё слеп
   целиком).
6. **origin/main разрешается** (`git rev-parse --verify --quiet origin/main`) → иначе
   «переснятие-bulk не доказано: origin/main недоступен» (fail-closed; имя ОТДЕЛЬНОЕ от
   «не достижим», прецедент «авторитет недоступен» 031-5).
7. **НА КАЖДЫЙ путь дельты** (лексикографический порядок; первый отказ останавливает
   дверь целиком — частичных переснятий нет):
   - а. **байты закоммичены:** sha256 рабочего файла == sha256 `git cat-file
     HEAD:<путь>` (обе стороны читаются напрямую, МИМО assume-unchanged/skip-worktree)
     → иначе «переснятие-bulk не доказано: байты дельта-пути не закоммичены (porcelain
     лжёт: assume-unchanged/skip-worktree)»;
   - б. **путь покрыт ≥ 1 зоной полного реестра** (литеральное покрытие: точное
     равенство пути ИЛИ префикс-каталога с завершающим `/` — та же семантика, что у
     zones_match_path в lib_zones.sh; НОВАЯ regex-ветка по байтам данных запрещена,
     норма парсящих гардов 041). При ПУСТОМ покрытии и пути, матчащем `contracts/<M>-*`,
     вступает ВТОРОЙ приём — двухрукое draft-признание И-3 (подраздел «Признание
     черновика в шаге 7б» ниже; семантика 023 дословно) → иначе «переснятие-bulk не
     доказано: путь <путь> не покрыт ни одной зоной»;
   - в. **слит:** sha последнего коммита, коснувшегося пути (`git log -1 --format=%H --
     <путь>`), — предок origin/main (`git merge-base --is-ancestor <sha> origin/main`)
     → иначе «переснятие-bulk не доказано: коммит <sha> пути <путь> не достижим на
     origin/main»;
   - г. **автор — владелец зоны:** %an того же коммита ∈ владельцы зон, покрывающих
     путь (сравнение литеральным равенством строк, как 031 п.6) → иначе
     «переснятие-bulk не доказано: автор <автор> пути <путь> не владелец зоны».
8. **Глобальная синхронизация:** `git rev-list --left-right --count origin/main...HEAD`
   == `0<TAB>0` → иначе «переснятие-bulk не доказано: история разошлась с origin/main
   (left-right ≠ 0 0)». ЭТА ЖЕ строка доказывает равенство HEAD == origin/main
   (граница-4).
9. **Успех:** базлайн переснимается ТЕМ ЖЕ форматом (root + sorted + verify, mode 0444 —
   переиспользуется do_snapshot), stdout несёт стенограмму — СТРОКА НА КАЖДЫЙ путь:
   «базлайн переснят: bulk-дельта <путь> (автор <автор>, коммит <sha>)», где <sha> — sha
   последнего коммита, коснувшегося пути (тот же вызов, что в 7в — единый источник
   факта), ЗАТЕМ итоговая строка «базлайн переснят: bulk-дельта — путей <N>,
   незакоммиченного/неслитого 0»; rc 0. Последующий `--check` → rc 0 «основной чекаут
   чист».

Отказ — rc 1, ИМЕНОВАННОЙ причиной (список выше — единый источник, фразы побайтово),
СНИМОК НЕ ТРОНУТ: последующий `--check` обязан остаться красным на той же дельте
(«переснятие, прячущее недоказанную дельту, краснеет» — слово владельца 2026-09-19,
наследовано из 031 дословно).

### Признание черновика в шаге 7б (Н-147: свой черновик — не «незонированный путь»)

Первое реальное применение двери отказало на СОБСТВЕННОМ черновике: путь
`contracts/044-*.md` не покрыт ни одной зоной — зоны читаются из замороженных
контрактов, а 044 до заморозки своей зоны в реестр не внёс. Без признания рецидив
гарантирован на КАЖДОМ следующем черновике-контракте (владелец, Н-147, дословно:
«draft-carve-out … по образцу 023 И-3 … — это завершение 044, не отдельный предмет»).

## Модель угроз

ЗАЩИЩАЕТ:
- многочасовая многокоммитная легитимная дельта судится механически: незакоммиченное
  (porcelain + побайтовое равенство), неслитое (per-path достижимость + глобальный
  left-right), чужая рука (автор ∈ владельцы зон пути), незонированный путь (именованный
  отказ с именем пути);
- черновик контракта до заморозки: судится как СВОЙ путь по резерву (И-3), но без
  ослабления честности — байты закоммичены, коммит слит на origin/main, автор объявлен
  (владелец какой-либо зоны реестра); чужой/неслитый/подменённый черновик красен теми
  же шагами 7а/7в/7г, что и любой путь;
- прячущее переснятие: отказ не трогает снимок, `--check` остаётся красным;
- пусто-зелёные оракулы: пустая дельта, пустой реестр, недоступный origin/main —
  именованные отказы, не молчаливый успех (пустая выборка красная).

НЕ ЗАЩИЩАЕТ:
- подлинность identity: коммит ОТ ИМЕНИ владельца зоны (остаточный риск check_zones
  `cognitive-only`, дословно); 044 наследует его без изменений;
- утечка, дошедшая до честного коммита и пуша правильным автором: Демаркация 024
  наследуется дословно — детектор судит состояние, не историю; 044 добавляет
  origin-достижимость, не ревью содержимого;
- исчезнувшие пути: дельта манифеста 024 — новые строки; deletions невидимы обеим дверям
  (наследовано от 024, не предмет 044);
- сговор/подмена локального git или PATH (TCB-арбитражи 040 дословно).
- self-mint локального тега id/CONTRACT/<M> объявленным владельцем зоны: признание
  читает локальный реестр, провенанс тега — предмет двери 023 (iii), не этой двери
