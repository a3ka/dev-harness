## Frontier

Потолок памяти. (А) оставить cgroup-сторож orch-memcap как есть и задокументировать —
отвергнут: три файла станции вне репо — ровно тот класс дрейфа, который закрывает 085.
(А′) внести orch-memcap в репо файлами 10-12 — отвергнут: узаконивает меру, которую
владелец назвал временной с названной заменой; голая cgroup мимо дерева systemd, окно до
60 с, только root, без проверки под harness. (Б) `systemd-run --user --scope` внутри
orch-loop — ВЫБРАН: потолок живёт в уже пиненном user-файле (инвентарь остаётся 9),
ставится без root, действует с первого байта, проверяется под harness шимом и живьём на
станции; семантика exec измерена — сторож и цикл находят omp прежним `pgrep -P`. Нет
scope (нет user-bus) — сессия стартует БЕЗ потолка с именованной строкой журнала, не
останов: правило самого цикла «ночью остановка = потерянные часы»; fail-closed повторил бы
цену инцидента 17:57 — работа стоит до ручного запуска.

Слияние. База — станционная версия (слово владельца), дельта 080 переносится в неё;
три конфликтных куска разрешаются объединением намерений (И-1), вне них — побайтно
вывод слияния. Механизм round-trip не вводится: перенос станция → репо исполняет этот
контракт, детектор дрейфа уже есть (`install.sh verify`, k5b 074).

## Демаркация контрпримеров

Конформные входы. orch-loop: швы `ORCH_*` шапки станционной версии и `ORCH_MEM_MAX`;
сессия — процесс `omp --profile …`, прямой потомок цикла; маркер и стоп-файл на локальной
ФС; systemd-run — опции до `--` (свойства формами `-p K=V`, `--property=K=V`,
`--property K=V`), команда после `--`. orch-peak: мир шва ORCH_PEAK_TEST по 080 (инв. 4,
16, 17) плюс `ORCH_LOOP_STOP`, журналы верхнего уровня с usage, toy-repo с bare origin,
`ORCH_USER` без живого дома (запись в пути станции невозможна). Валидный контрпример —
реализация, зелёная на всех клетках, но нарушающая инвариант на ДРУГОМ конформном входе
(тайминги, имена журналов, значения в пределах швов): инвариантность к значениям и
расхождение на конформном входе. Вход вне грамматики (systemd-run без `--`, сессия не
прямой потомок, запись в живые пути станции) контрпримером не является.

## Модель угроз

ЗАЩИЩАЕТ:
- потерю станционных починок при установке из репо — снимки станции в fixtures и сверка
  по диффу (И-1, И-2): пропавшая строка станции — красное с её текстом;
- откат дельты 080 станционной версией (Н-187: принудительный перезапуск без ожидания
  живых субагентов) — батарея 080 на слитом дереве (И-6);
- маркер против сменившейся сессии (Н-189), останов цикла единичным ранним маркером или
  падением, гонку снятия маркера — поведенческие клетки на перенесённых смоуках (И-3, И-4);
- принятие подписи сторожа за слово владельца (Н-200) — по доставленным сообщениям (И-4в);
- снос цикла OOM-ом omp (17:57) — scope с MemoryMax: ядро убивает только scope, цикл идёт
  веткой падения (И-5б; шимом и живьём);
- тихую работу без потолка — именованная строка журнала (И-5в);
- дрейф репо ↔ установленное после приёмки — новые пины k5/k5b 074 и `install.sh verify`.

НЕ ЗАЩИЩАЕТ:
- прямую правку станции между приёмками — детектор есть, периодического триггера на
  станции нет (отдельный предмет);
- глобальный OOM хоста от процессов вне scope — tmux-scope с циклом может пасть как 17:57;
- потерю user-менеджера harness посреди сессии — scope гибнет с ним, цикл видит падение;
- различение OOM и внешнего SIGKILL без маркера — оба дают строку И-5б;
- полноту README сверх чек-строк k6 — ловец ревьюер.
