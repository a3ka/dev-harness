## Frontier

Потолок памяти. (А) оставить cgroup-сторож orch-memcap как есть и задокументировать —
отвергнут: три файла станции вне репо — ровно тот класс дрейфа, который закрывает 085.
(А′) внести orch-memcap в репо файлами 10-12 — отвергнут: узаконивает меру, которую
владелец назвал временной с названной заменой; голая cgroup мимо дерева systemd, окно до
60 с, только root, без проверки под harness. (Б) `systemd-run --user --scope` внутри
orch-loop — ВЫБРАН: потолок живёт в уже пиненном user-файле (инвентарь остаётся 9),
ставится без root, действует с первого байта, проверяется под harness шимом и живьём на
станции; семантика exec измерена — сторож и цикл находят omp прежним `pgrep -P`. Нет
scope (нет user-bus) — сессия стартует БЕЗ потолка с именованной строкой журнала, не
останов: правило самого цикла «ночью остановка = потерянные часы»; fail-closed повторил бы
цену инцидента 17:57 — работа стоит до ручного запуска.

Отказ scope против падения сессии. rc отказа systemd-run (до исполнения команды) и rc
исполненной сессии совпадают (1); предварительная проба `-- true` запуск не страхует — шина
может отказать между вызовами. Различение — по факту исполнения команды, поэтому после `--`
допустим префикс, exec'ом в том же процессе приходящий к вызову workshop (например,
файл-свидетель, который пишет префикс); способ — за исполнителем.

Счёт «подряд». Шапка станции — «EARLY_MAX подряд ранних маркеров или падений»; код станции
копит счётчик каждого вида через событие другого вида (`ранний, ранний, падение, ранний` при
EARLY_MAX=3 — останов на четвёртой сессии). Выбран общий счёт нештатных завершений,
обнуляемый обычным перезапуском; раздельные счётчики со взаимным сбросом отвергнуты: не
останавливают чередование ранний/падение — ту петлю, ради которой предел.

Слияние. База — станционная версия (слово владельца), дельта 080 переносится в неё;
три конфликтных куска разрешаются объединением намерений (И-1), вне них — побайтно
вывод слияния. Механизм round-trip не вводится: перенос станция → репо исполняет этот
контракт, детектор дрейфа уже есть (`install.sh verify`, k5b 074).

## Демаркация контрпримеров

Конформные входы. orch-loop: швы `ORCH_*` шапки станционной версии и `ORCH_MEM_MAX`;
сессия — процесс `omp --profile …`, прямой потомок цикла, служебных файлов цикла, кроме
маркера и стоп-файла, не трогает; маркер и стоп-файл на локальной ФС; systemd-run — опции
до `--` (свойства формами `-p K=V`, `--property=K=V`, `--property K=V`), команда после
`--`; запуск сессии — вызов, чья команда кончается вызовом workshop (И-5а), иной вызов —
проба; каждый вызов либо исполняет команду exec'ом, либо отказывает rc≠0 до исполнения — в
любой последовательности (отказ запуска после успешной пробы, исполнение после отказа).
orch-peak: мир шва ORCH_PEAK_TEST по 080 (инв. 4, 16, 17) плюс `ORCH_LOOP_STOP`, журналы
верхнего уровня с usage, toy-repo с bare origin, `ORCH_USER` без живого дома (запись в пути
станции невозможна). Валидный контрпример — реализация, зелёная на всех клетках, но
нарушающая инвариант на ДРУГОМ конформном входе (тайминги, имена журналов, значения в
пределах швов, последовательность отказов systemd-run): инвариантность к значениям и
расхождение на конформном входе. Вход вне грамматики (systemd-run без `--`; команда,
кончающаяся вызовом workshop, но не приходящая к нему exec'ом; сессия не прямой потомок;
запись в живые пути станции) контрпримером не является.

v2 (И-10): предмет клетки т1 — ГРАММАТИКА строки MSG (замкнутый набор обязательных
ссылок, запрещённые литералы, одна строка, длина, равенство снимку), значение —
дословная строка инварианта; конформный вход — файл субъекта с любой строкой,
удовлетворяющей грамматике; вход вне грамматики (подстановка, две строки, чужой текст
без обязательных ссылок) красен по построению, контрпримером не является. Поведение
ЧИТАТЕЛЯ сообщения (возьмёт ли агент-модель в todo паузное) механически не наблюдаемо —
cognitive-only, ловец назван в модели угроз.
