### П1 (Н-217). orch-peak под root без HOME рушится на bootstrap

Живой код (HEAD `2e3f2c2`): `orch-peak:16` ставит `set -u`; `orch-peak:34` вычисляет
`SESS_GLOB="${ORCH_SESS_GLOB:-$UHOME/…}"` (UHOME — из getent, HOME НЕ нужен);
`orch-peak:165–168` источит `${REPO}/scripts/lib_session.sh` в root-контексте;
`lib_session.sh:18` — `: "${ORCH_SESS_GLOB:=$HOME/…}"`: при незаданной `ORCH_SESS_GLOB`
раскрывается `$HOME`, которого в systemd-окружении root нет → unbound variable валит
ВЕСЬ сторож (не только bootstrap). Воспроизведено живьём (PROVERKA.md §4).

**Латентный дефект того же корня [INFERERENCE по коду, живьём не измерялся]:** даже когда
HOME есть (интерактивный root с `HOME=/root`), bootstrap «успешен», но источённая
`current_session_dir` глобит `$HOME/…` = `/root/…` → пусто → CTX_HARD считает «живых
субагентов нет» и ставит принудительный маркер без опроса `ORCH_HARD_GRACE` — то же
повреждение, что и в Н-217, молча.

### П2 (Н-216). install.sh root: ложный отказ предусловий под root без safe.directory

Живой код: `install.sh:121` `hooks_path="$(git -C "$MAIN_DST" config --local --get
core.hooksPath …)"` и `install.sh:138` `auto_merge="$(git -C … --local --type=bool …)"` —
под root без `safe.directory` обе `--local`-читалки падают, `|| true` глушит, значения
становятся пустыми → ложные «core.hooksPath не установлен» / «не false (<пусто>)» ДО
chattr, при фактически выполненных предусловиях.

### П3 (Н-219, герметичность тест-инфраструктуры). Клетка глубокого сценария обязана

оставить `ORCH_SESS_GLOB` неустановленной (иначе не воспроизводит Н-217 крash вовсе — `:=`
в `lib_session.sh:18` не сработает), а единственный путь к НЕреальному home — подмена
САМОЙ `$UHOME`.

## Диагноз и выбор почина (по коду, прочитанному живьём; владелец назвал варианты как НАБЛЮДЕНИЕ)

### П1 — выбирать семейство «безопасный источник ДО source», конкретно: посев ORCH_SESS_GLOB
В `orch-peak` НЕПОСРЕДСТВЕННО ПЕРЕД блоком bootstrap (`if [ -f "${REPO}/scripts/lib_session.sh" ]…`,
после вычисления `SESS_GLOB` строкой 34) добавить:

```bash
ORCH_SESS_GLOB="$SESS_GLOB"
```

(без export: source — тот же шелл; переменная окружения не загрязняется). Обоснование
отказа от альтернатив:

- **Почему не `export HOME="$UHOME"` (вариант (а) владельца в лоб).** Работает для краша,
  но экспортирует ложный HOME в root-процесс и всех его детей, а семантика fix'а становится
  «подделать окружение», тогда как достаточно НЕ раскрывать `$HOME` вовсе: при
  предзаданной непустой `ORCH_SESS_GLOB` слово `:="${ORCH_SESS_GLOB:=$HOME/…}"` не
  вычисляется (семантика `:=` в bash). Посев лечит И латентный дефект (глоб всегда тот,
  что сам orch-peak считает правильным — `$UHOME`-based), и сохраняет тест-шов
  (`ORCH_SESS_GLOB` в окружении по-прежнему honoured — `SESS_GLOB` строки 34 уже
  наследует её; посев не перебивает, а нормализует: env-пустая строка → умолчание).
- **Почему не «не source'ить вовсе» (вариант (б) владельца).** Локальные fallback'и
  orch-peak семантически идентичны СЕГОДНЯ, но И-13 контракта 080 существует ровно против
  тихого расхождения двери и сторожа при будущей правке `lib_session.sh`; полное удаление
  source — легализация постоянного дублирования. Bootstrap остаётся единым источником,
  fallback — страховкой отсутствия файла.

### П3 — env-knob `ORCH_UHOME` для `UHOME` (ТРЕТЬЯ правка, обязательна вместе с П1)

В `orch-peak` (строка 18, ДО вычисления `SESS_GLOB`) заменить:

```bash
UHOME="${ORCH_UHOME:-$(getent passwd "$U" | cut -d: -f6)}"
```

Обоснование: ВСЕ остальные пути в этом файле уже переопределяемы через `ORCH_*` (`ORCH_REPO`,
`ORCH_STATE`, `ORCH_MARK`, `ORCH_LOG`, `ORCH_REPORT`, …) — `UHOME` единственное исключение
безо всякой заявленной причины. Без knob'а (пустой `ORCH_UHOME`) поведение ПОБАЙТОВО прежнее
(`getent` как раньше) — дефолтная ветка НЕ меняется, это чистое расширение поверхности
тестирования/диагностики, тот же паттерн, что остальные knob'ы файла. Без этой правки клетка
глубокого сценария (П1, латентный дефект) СТРУКТУРНО не может быть герметичной (Н-219) —
единственный путь посадить тест-сессию, не трогая реальный `~/.local/state/dev-harness-
sessions/**`, это подменить `$UHOME`, от которого вычисляется весь glob.

### П2 — чтение значений мимо ownership-guard: `--local` → `--file`

В `install.sh` (блок root, строки 121 и 138) заменить способ чтения:

```bash
hooks_path="$(git config --file "$CFG_MAIN" --get core.hooksPath 2>/dev/null || true)"
auto_merge="$(git config --file "$CFG_MAIN" --type=bool --get branch.autoSetupMerge 2>/dev/null || true)"
```

Обоснование по коду, не по названию: шаг — ЧИТАЮЩАЯ проверка уже провалидированного
файла (`CFG_MAIN` существует — гард строк 111–114); `--file` не делает repo-discovery и
не зависит от владельца каталога и `safe.directory`; вариант (а) владельца
(`--global --add safe.directory`) — постоянная мутация `/root/.gitconfig` побочным эффектом
установщика, порядок/отказ которой сам становится состоянием. Семантика И-2 не меняется:
пустое значение → тот же именованный отказ fail-closed (пин — кейс C клетки).

`scripts/lib_session.sh` предписанным фиксом НЕ правится (корень — место вызова под
root, не библиотека пользовательского контекста); зона оставлена для защитительных
правок, не меняющих грамматику строки 18 для пользовательских вызовов (`orch_restart.sh`
под harness с HOME не затрагивается).
