# Контракт 069 — PR-маршрут МИНИМАЛЬНЫЙ: CI-гейт по PR, слияние всегда land_agent

## Предмет

Боль сессии 2026-09-30, измерена владельцем: 8 из 10 CI-прогонов дня отменены —
все пуш-прогони конкурируют за ОДНУ concurrency-группу ci-<main-ref>, и каждый
новый пуш в main отменяет предыдущий прогон (ci.yml:26-28, группа по
github.ref); ждать чужой прогон под своим прогон-гейтом — прямой простой
судейского конвейера.

Предмет — норма роли orchestrator: кодовая пачка идёт «ветка wip/<NNN>/<автор>
→ PR → зелёный PR-CI → слияние ТОЛЬКО scripts/land_agent.sh локально → пуш main
через bash scripts/gitw БАТЧЕМ». PR — только CI-гейт по своему ref
(PR-прогон не отменяет main-прогон и наоборот); кнопка Merge в UI GitHub
запрещена: её merge даёт committer GitHub без маркера «land: wip/…».

Класс предмета: смешанный (норма-строка роли + probe-only красное предъявление
мутанта). НОВЫХ СКРИПТОВ не строить — слово владельца 2026-09-30 (HANDOFF п.2):
ci.yml уже несёт всё нужное, защита main — настройка GitHub, не код.

## Инварианты

1. **PR — ТОЛЬКО CI-гейт**: PR открывается на ветку пачки; зелёный PR-прогон по
   своему ref — единственное, что требует PR; ревью/апрувы GitHub в норму не
   входят. main-ref не занимается пачкой до ленда.
2. **Слияние — только land_agent**: кнопка Merge в UI GitHub запрещена; её
   merge-коммит (committer GitHub, subject «Merge pull request #N …», без
   маркера «land: wip/…») ловится живыми барьерами: пост-фактум вызов land_agent
   отказывает именованно «не несёт коммитов относительно main» (И-1) и main не
   двинут; GitHub-committer коммит в диапазоне ветки («Update branch» кнопкой)
   — именованный отказ «имя вне реестра ролей … (И-9)»; уставная дельта через
   merge без РАЗРЕШИЛ — красный check_charter (зло-ленд).
3. **Пуш main — отдельный шаг gitw, батчем**: PR-ref не отменяет main-ref
   (группа по ref), но дисциплина 2026-09-30 сохраняется: пока ждёшь
   прогон-гейт — в main не пушить.
4. **Защита main — предусловие done-шага, не код**: API ветки main/protection:
   200 → proceed; 404 → именованный отказ «предусловие: main не защищён —
   включи protection»; иной код → именованный отказ «предусловие: защита main
   не прочитана». Живой замер этой пачки: read-токен ODELIX_GITHUB_TOKEN не
   имеет scope на branch-protection (HTTP 403 «Resource not accessible by
   personal access token»); без токена — 401. Данные консультанта: защита
   выключена (Branch not protected). Включение защиты и токен со scope — шаг
   владельца, в дереве не решается.

## Модель угроз

ЗАЩИЩАЕТ:

- отмену рабочих CI-прогонов пачками друг друга: PR-прогон живёт по своему
  ref, main-группа остаётся за лендами; боль «8 из 10 отмен» уходит без правки
  workflow (С2 — живой grep триггера и группы);
- слияние мимо land_agent: кнопка GitHub → именованный отказ И-1 пост-фактум
  (main не двинут), именованный отказ И-9 на диапазон с GitHub-committer,
  зло-ленд устава красен check_charter; probe-only предъявление красное
  2 из 2 мутантов (С1, живой прогон пачки);
- дрейф нормы: генерат .omp/agents/orchestrator.md перегенерируется тем же
  коммитом пачки (gen --check rc 0), норм-строка сверяется г4 проводки
  побайтово (grep -Fxq).

НЕ ЗАЩИЩАЕТ:

- сам факт нажатия кнопки ДО любых проверок — событие вне дерева; ловится
  пост-фактум: журнал main несёт committer GitHub, последующие ленды отказывают
  И-1/И-9, уставная дельта красна; вычистка (revert) — операция владельца,
  069 её не автоматизирует;
- прямые пуши в main посторонними — закрытие ветки защитой GitHub есть
  предусловие done-шага (инвариант 4), не механизм этого контракта; живой
  замер 403 у read-токена — включение и читающий токен за владельцем;
- собственно merge-коммит кнопки в суде зон: check_zones судит только не-merge
  коммиты (rev-list --no-merges; живой замер пачки: кнопочный merge
  зонированного PR даёт rc 0) — ловец кнопки это land_agent (И-1/И-9) и устав;
  зоны судят принесённые коммиты как обычные прямые.
