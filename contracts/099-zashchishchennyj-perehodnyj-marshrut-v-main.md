## Предмет (дословно doc §2/§3 + Н-270)

Переходный маршрут: попадание в main ТОЛЬКО через PR со слиянием доверенным компонентом после допуска дверью. Узлы doc §2 (цитаты дословно):

- **land_agent**: «Сейчас делает локальный merge и удаляет рабочую ветку; push — отдельный шаг. Перенести подготовку в интеграционную ветку, не двигать локальный main и не удалять исходную ветку до принятия PR. Сохранить авторство, `land:`-семантику и дословные санкции. Не включать squash/rebase-merge без миграции исторических барьеров.»
- **gitw/предполёт 071**: «Гард канонического remote оставить. Предполёт публикации main при GitHub API merge не вызывается: его содержательные проверки перенести перед серверным слиянием. Удалить заменённую проверку "хотя бы один зелёный PR-workflow", не потерять контроль тегов и дерева.»
- **CI/check_ci_gate**: «PR workflow уже есть, но checkout берёт head PR, не результат слияния. Проверять интегрируемый результат, включая сообщение и identity финального merge: `check_charter` судит его дельту к первому родителю. Убрать требование `sha ∈ origin/main` из предсудейского CI-гейта; требовать конкретный обязательный набор для проверяемого объекта. `push: main` оставить как постконтроль, не условие допуска.»
- **check_no_leak**: «Это охрана основного чекаута, не серверной ветки. PR-работу вести в отдельном дереве; обновление основного чекаута — штатной доверенной операцией со сверкой/обновлением снимка. Не разрешать произвольный `retake` ради зелени.» — зазор измерен (см. §Существующее): ahead-режим без зонной ноги.
- **Служебные коммиты**: «Коммитить вне main, публиковать пакетными PR. Обновить роли и потребителей, предполагающих немедленное попадание записи в main.» — поведенческая норма, role-канал (ПРОВОДКА); механически наследуется PR-only маршрутом (прямых пушей в main нет после серверного правила §5.3, live-класс).
- **Канал owner**: «`fetch` остаётся; owner-коммиты поступают в PR без переавторства и потери санкций. `author=owner` не является аутентификацией. Полномочия создать/слить PR нужны доверенному компоненту, не общий административный токен агентам.» — норма роли + существующий 070 (токен read-only).
- **Теги и реестр**: «Защита main не защищает `frozen/*`, `done/*`, `id/*`. Ограничить их создание доверенным писателем, запретить изменение/удаление серверными правилами тегов. `freeze_contract` уже создаёт тег и отдельный коммит реестра: последовательность должна обеспечивать наличие тегов для PR-CI и целостность реестра.»

Секция 3 (дословно ключевые фразы): «Красный main сам по себе не блокирует исправляющий PR»; для промежутка «нужен обязательный доверенный гейт, допускающий только точно перечисленные существующие дефекты; остальные проверки l7/ap2 остаются обязательными по существу. Не сравнивать количество или текст красных строк: одинаковое число может скрывать новую поломку. Неизвестный отказ, отсутствие результата, сбой раннера — блокировка. База исключений кандидат менять не может. После исправления — все 12 обязательны, временный гейт удаляется.»; «обязательная проверка должна удостоверять фактическое выполнение, не просто наличие зелёной оболочки» (skipped/neutral — не успех).

Подпредмет Н-270 — дословно второе требование (шапка): механический отказ на спавн судьи без явного agent/не своего тира ДО учёта результата + сверка трассы после спавна + нематериализация вердикта при несовпадении.

1. **Дверь допуска — новый `scripts/pr_dopusk.sh`** (единый субъект перехода): `pr_dopusk.sh <корень> --pr <N>`; rc 0 «ДОПУСК: <pr> <объект>» / rc 1 именованный отказ / rc 2 fail-closed. Ручка API: `PR_DOPUSK_API` (base URL; без — api.github.com, конвенция 071/087). Судит: (а) merge-объект PR — `merge_commit_sha` из ответа API + локальная сверка дерева (расхождение/движение базы — отказ «база двинулась»); (б) сообщение и identity финального merge: land:-маркер в первой строке объекта, committer — доверенный компонент (orchestrator); чартер — инкремент по дельте к первому родителю существующим npm-ключом; (в) теги/реестр: каждый локальный `frozen/*|done/*|id/*` — на origin тем же объектом (отказ «локальный тег не на origin: <тег>»); каждая строка реестра «NNN → <sha>» — sha есть тег NNN на origin, membership как 023-2в (отказ «реестр: тег не выдан авторитетом: <NNN>»); (г) обязательный набор checks на PR — структурно per-name (098 дословно), событие pull_request, фактическое выполнение (skipped/neutral/отсутствие ≠ success, отказы «нет результата: <имя>»/«неизвестный отказ: <имя>»); переходный перечень l7/ap2 — точно перечисленные дефекты из `config/transition_defects_099.tsv`; (д) содержательные чеки дерева 071 — переиспользованием `gitw_preflight_071.sh` в режиме объекта (`--object <sha>`), где чек 3 (зелёный-PR-workflow) ЗАМЕНЁН серверными обязательными checks — «его содержательные проверки перенести перед серверным слиянием» (ПЕРЕСЕЧЕНИЕ implementer).
   (г2) доверенное происхождение проверок (граница арбитража 099 по З-5): обязательные проверки, результат которых судит pr_dopusk, исполняются кодом ПЕРВОГО РОДИТЕЛЯ `M^1` — все шаги workflow и всё, что они транзитивно исполняют (`scripts/*`, `fixtures/*`, npm-ключи `package.json`, `config/*`): workflow-шаг `M^1` материализует проверочное замыкание из `M^1` (`git checkout <M^1> -- scripts fixtures package.json config`) ДО запуска проверок. Байт-идентичность `M^1 ↔ M` сохраняется ТОЛЬКО для минимума, исполняемого платформой из объекта `M`, а не из `M^1` — `.github/workflows/` + `package.json`; `scripts/` и `fixtures/` из этого минимума ИСКЛЮЧЕНЫ (замер 5 арбитража: байт-заморозка поверхности отказывала 20/40 легитимных лендов, расширение на scripts/ — 23/40, делая PR-маршрут декорацией). Дельта минимума → отказ «проверки изменены кандидатом: <путь>» НЕЗАВИСИМО от имён/статусов; расширение списка путей байт-идентичности сверх минимума — отказ приёмки. Эволюция проверок — маршрут 071 (доверенная сторона) или ленд в main (движется `M^1`), не PR-кандидат.
2. **Реестр перехода — `config/transition_defects_099.tsv`: строки `<имя составляющей> TAB <sha256|->`** (блокер критика :49). Имена — СОСТАВЛЯЮЩИЕ обязательных проверок в шаг-гранулярности (check-run из ответа CI: l7a/l7b, не job-агрегат l7): раннее прерывание job оставляет составляющие без результата — реестр и дверь обязаны это видеть. `-` — составляющая обязана быть зелёной; sha256 — stdin из отсортированных (LC_ALL=C) строк отказа составляющей (каждая с завершающим \n), строки из ответа CI (output проверок), не из локальной доски (А-401). Дверь читает реестр по ПЕРВОМУ РОДИТЕЛЮ объекта (main-сторона слияния), не из объекта; дельта кандидатом → «база исключений изменена кандидатом». Допуск: КАЖДОЕ имя реестра присутствует в ответе со статусом completed (завершённость исполнения); conclusion success — зелено; conclusion failure — ТОЛЬКО при точном совпадении sha (иначе «неизвестный отказ: <имя>»); отсутствие/незавершённость любой составляющей → «нет результата: <имя>»: допуск известного дефекта одновременно удостоверяет полноту остальных обязательных результатов. После чинки l7/ap2 хеши заменяются на `-`, дверь и маршрут удаляются (doc §3). Производитель составляющих (совет критика круга 2 :51): `config/transition_producers_099.tsv` — ОДНА таблица `<check-run> TAB <шаг workflow M^1> TAB <исполняемая команда>`, читается дверью по `M^1`; КАЖДОЕ имя обязательного набора покрыто строкой, шаг существует в `.github/workflows/` дерева `M^1` и несёт команду дословно — имя check-run связывается с кодом `M^1`, его произведшим.

4. **Н-270, дверь сверки — новый `scripts/check_sud_model.sh`** (юнит; первая половина З-7 сохраняется): `--spawn <роль> [<модель>] [--root <кат>]` — модель ОБЯЗАТЕЛЬНА (нет → «ОТКАЗ: спавн судьи без явного agent: <роль>»), литеральная сверка с тиром роли из `config/agent_models.json` (roles→tiers→models, @семейство резолвится; 041: замкнутый алфавит ролей {critic, adversary, reviewer, arbiter}; значение модели — алфавит латиница/цифры/`-._/`, TAB/пробел вне алфавита); несовпадение → «ОТКАЗ: модель не тира роли: <роль> тир <expected> спавн <actual>». `--frontmatter <роль> [--root <кат>]` — статическая сверка модели спавна: frontmatter `.omp/agents/<роль>.md` (строка `model: ["@<тир>"]`) против тира роли из `config/agent_models.json`; несовпадение → «ОТКАЗ: frontmatter роли не тира роли: <роль> frontmatter <fm> тир <expected>»; файл/строка не читаются → rc 2 fail-closed «ОТКАЗ: frontmatter роли не читается: <роль>» (несовпадение frontmatter и источника назначений не молчит; динамический фолбэк модели — только трасса, З-8). `--verdict <роль> --trace <tsv>` — та же сверка по трассе (грамматика — ЕДИНЫЙ источник `роль TAB модель TAB allowed|denied` из make_task/models_actual --tsv): несовпадение → «ОТКАЗ: вердикт не материализуется: судья <роль> на модели <actual>, тир <expected> (Н-270)»; трасса без строки роли / битая грамматика → rc 2 fail-closed (= не материализуется).
   Точка перехвата РЕАЛЬНОГО запроса (граница арбитража 099 по З-7) — проектное расширение omp **`.omp/extensions/spawn-guard.ts`**: регистрирует обработчик хука `tool_call`; для `toolName === 'task'` судит КАЖДЫЙ элемент `input.tasks[]` (batch) и `input` целиком (flat, omp://tools/task.md:50) по РЕЗОЛВНУТОМУ `agent` (замер 3 арбитража: omp подставляет дефолт `agent:"task"` ДО хука — «опущен» и `agent:"task"` неразличимы; потому предикат один: резолвнутый агент ∈ замкнутого алфавита, `task` в алфавит НЕ входит — иначе Н-270-дефект не ловится вовсе). Алфавит — РОЛИ `config/agent_models.json` + явно перечисленный `scout` (AGENTS.md:71; замкнутый список в ОДНОМ месте кода расширения). Отказы: `agent:"task"` → `{block:true, reason:'ОТКАЗ: спавн без явного agent: task'}`; `agent` вне алфавита → `{block:true, reason:'ОТКАЗ: тип агента вне алфавита: <agent>'}`; валидная роль → undefined; batch с одним плохим элементом → block (один элемент заражает вызов — семантика первого блока); `toolName !== 'task'` → undefined; битый input / исключение в обработчике / нечитаемый алфавит → block fail-closed. ## Демаркация контрпримеров

Конформные входы: роли-судьи ∈ {critic, adversary, reviewer, arbiter}; модель — непустая строка в алфавите `config/agent_models.json` (латиница/цифры/`-._/`); трасса — строки `роль TAB модель TAB allowed|denied`; sha — 40/64 hex; имена checks — строки реестра перехода (составляющие в шаг-гранулярности, не job-агрегаты; в клетках записи подаются `|`-строкой — summary отказов содержит пробелы); события фабричного seam хука — `{type:'tool_call', toolName, toolCallId, input}` с `input.tasks[]`-элементами `{name, agent, task}` (agent — РЕЗОЛВНУТАЯ строка; алфавит — роли `config/agent_models.json` + scout, `task` не входит); frontmatter роли — строка `model: ["@<тир>"]`; refspec/теги/реестр — грамматики 071/023. Валидный контрпример = инвариантность к ЗНАЧЕНИЯМ конформных полей ∧ расхождение честной реализации и контрпримера на КОНФОРМНОМ входе клетки (sha/имена/порты случайны на прогон). Неконформные (битый sha, TAB в роли, неизвестный ключ check) — предмет именованных отказов двери, не контрпримеры.
