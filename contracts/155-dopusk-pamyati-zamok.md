## Frontier и выбор (с ценой и отказами)

- **А. Блокирующее ожидание в новой двери допуска (ВЫБРАНО).** Страж после алфавита вызывает `scripts/dopusk_pamyati.sh`; нехватка → запись в FIFO-очередь состояния и poll счётчиков до освобождения либо именованного таймаута. Цена: tool_call висит до таймаута (≤300 с; платформенный предел неизвестен — станционная проба p02), конкурентные ожидатели держат свои хуки. Порядок «допуск ДО замка»: замок занимается состоянием при успехе — отказ/ожидание допуска не оставляет ложного держателя и не держит предметный мьютекс (гонка судов 140).
- **Б. Именованный отказ + повтор вызывающим.** Дверь отказывает `DOPUSK_NET`, очередь — поведение агентов (оркестратор сам ждёт и ретраит). ОТКЛОНЕНО: очередь живёт в прозе заданий — замер 156: «прошлые нормы в задание не помогают»; порядок/голодание не механические; каждый повтор — новый круг модели.
- **В. Перенос бюджета на слой systemd (MemoryMax на каждый спавн).** ОТКЛОНЕНО: агенты — таски omp внутри уже запущенной сессии, не процессы orch-loop; обёртка каждого спавна в systemd-run — переделка пускача; OOM kill всё равно убивает работу, которой нужны ожидание и страховка, а не смерть.
- **Г. Только OOMPolicy=continue, без допуска.** ОТКЛОНЕНО: сессия жива, но работа одного процесса теряется (данные/время); владелец назвал continue «последней страховкой», не средством. Оставлен в объёме как И-8.

## Предмет и инварианты

Два наблюдаемых результата. (а) Gated спавн при остатке бюджета памяти ниже заявки не стартует «впритык» и не убивает чужую работу — он ждёт в FIFO-очереди до освобождения либо именованного отказа по таймауту. (б) Замок предмета, чей держатель завершил СОБСТВЕННУЮ сессию без сдачи, освобождается немедленно по факту session_exit — не по возрасту, не по смерти родителя, не по давлению памяти.

- **И-1 (место в цепочке).** Страж: алфавит 104 → допуск 155 → замок 140. Алфавит не прошёл — вызова допуска нет (семантика 104 дословно); допуск отказал/сломан — вызова замка нет и замок НЕ занимается (отказ допуска не оставляет ложного держателя); gated нет — ПУСК допуска без очереди, далее обычный суд замка. Событие двери несёт pid процесса стража (`{"tasks":[…],"pid":N}`).
- **И-2 (источник бюджета).** Остаток = `memory.max` − `memory.current` каталога cgroup v2, выведенного стражем из СВОЕГО `/proc/self/cgroup` (kernel-факт; env не источник). Значения — целые байты ≥0 либо литерал `max`; `current > max` → остаток 0; файл нечитаем/не число → rc 2 NOT_IMPLEMENTED (fail-closed: «страж допуска сломан», не молчаливый пропуск); `max`-без-потолка → именованный ПУСК `DOPUSK: BEZ_POTOLKA` (без конечного бюджета допуск не считается; страховка — И-8).
- **И-3 (заявка).** Заявка = `ZAJAVKA_BAJT` (4294967296) × число gated items; роли gated — те же замкнутые алфавиты, что у замка 140; gated нет → `PROPUST` rc 0 без очереди и записей.
- **И-4 (очередь).** Нехватка → запись в `$SOST/dopusk/ochered/` под мьютексом flock (имя `%010d-<pid>-<rand>` — seq монотонный; содержимое: заявка, deadline, pid). Пуск при: остаток ≥ своей заявки И (живой головы нет ИЛИ остаток ≥ заявки головы) — младший не перепрыгивает старшего. Записи с прошедшим deadline собираются любым прохожим. Ожидание ≤ `--timeout` (умолчание 300 с, poll 5 с, счётчики перечитываются); истечение → `ОТКАЗ: OCHERED_TAJMAUT` rc 1, своя запись убрана. Заявка — граница старта, не резерв: одновременный пуск нескольких ждущих на одном остатке возможен (НЕ ЗАЩИЩАЕТ).
- **И-5 (идентичность записи).** holder.json и строка START несут `sessionId` (=holder, имя файла журнала сессии) и `pid` процесса суда из события («-», если события без pid). pid — диагностика повторных занятий; физическую живость PID дверь не доказывает и по нему НЕ освобождает.
- **И-6 (факт смерти).** `stare_holder` возвращает `pogib` только если журнал САМОГО holder содержит литерал `"customType":"session_exit"` и НЕ содержит yield (приоритет yield — дословно 140). Возраст журнала, выход родителя (dispose/sigterm), маркер давления памяти — НЕ путь к pogib: живой замок = дубль. Ветки bezhit/broshen/net_fajla и причины 140 — дословно.
- **И-7 (выпуск).** В `--sudit` занятый погибшим замок снимается под мьютексом предмета (rm zanyat + RELEASE `prichina=pogib`), предмет свободен — обычные проверки дальше; `--osvobodit` на pogib — немедленно, `prichina=pogib`; гонка двух судов — ровно один START (мьютексы 140). D10 «судья после yield автора» не ослаблен: судья на погибшем без yield авторе — `AVTOR_ESHCHO_RABOTAET` (автор не сдал).
- **И-8 (страховка юнита).** `orch-loop` SCOPE несёт `-p OOMPolicy=continue` ПРИ сохранённых `-p "MemoryMax=$MEM_MAX" -p MemorySwapMax=0` (085/093 дословно): смерть ОДНОГО процесса по памяти (rc 137) не добивает сессию scope'ом (rc 143 всем).
- **И-9 (гигиена 041).** Дверь допуска — новый гард чужого ввода: замкнутые алфавиты (роли; счётчики — целые/max; записи очереди — целые тройки), представление без переиспользования байта данных разделителем, литеральные сравнения, профиль `fixtures/parsing_hygiene_battery/profiles/dopusk_pamyati.sh` с зелёным прогоном батареи гигиены — обязателен при реализации (зона implementer).

## Модель угроз

Субъект — три носителя (дверь допуска, дверь замка, юнит-эталон orch-loop) + интеграция стража; оракул в памяти проверяющего, пины SHA256 моделей, причины — буквальные строки.

ЗАЩИЩАЕТ:
- старт «впритык»: gated спавн при остатке ниже заявки ждёт в очереди либо отказывает именованной причиной OCHERED_TAJMAUT — не стартует и не убивает чужую работу; пакет судится заявкой на все gated items;
- очередь: младший не перепрыгивает живую голову (FIFO по seq под мьютексом), истёкшие записи собираются любым прохожим, ожидание ограничено таймаутом, своя запись убирается при любом исходе; счётчики перечитываются на каждом опросе — освобождение замечается;
- замок: единственный факт смерти — session_exit в журнале САМОГО holder без yield; авто-снятие немедленное под мьютексом предмета с RELEASE pogib; родительский dispose/sigterm при живом держателе и возраст журнала 10.5 мин — замок жив (RABOCHIJ_ZHIV), негативные образцы m1/m1b закрытого 152 переформулированы клетками b04/b03; тишина 70 мин — прежняя ветка Е 140 (только ручное снятие);
- идентичность: запись замка и START несут sessionId+pid — повторное занятие различимо, выпуск по pid НЕ производится;
- юнит-эталон: OOMPolicy=continue при сохранённых потолках MemoryMax/MemorySwapMax=0 — смерть одного процесса (rc 137) не добивает сессию;
- зелень без реализации невозможна: безфлаговый режим красен поимённо (SUBJECT_ABSENT/дельта отсутствует), порча трёх носителей ловится пинами до клеток, выживший обман — rc 1 STAB_ZHIV.

НЕ ЗАЩИЩАЕТ:
- одновременный пуск нескольких ждущих на одном остатке (заявка — граница старта, не резерв) и физическую нехватку памяти после пуска — страховка И-8, не гарантия;
- точность константы заявки вне измеренных инцидентов (6.7–11.1 ГиБ один процесс): настройка — v+1 по слову владельца, не эта пачка;
- платформенный предел блокирующего ожидания tool_call (omp может оборвать ход стража раньше таймаута двери): станционная проба p02; зависание сверх --timeout исключено собственным таймаутом двери;
- подмену счётчиков или журналов владельцем состояния (диск — территория проверяемого, правило 8): cgroup выводит страж из /proc/self/cgroup, гонка вооружений не ведётся; ловец — живая приёмка/ревью станции;
- смерть держателя БЕЗ записи session_exit (SIGKILL) и миллисекундное окно «запись есть, процесс ещё жив»: журнал не различает — ветка broshen 60 мин дословно;
- sudo-ветку orch-loop (uid агента ≠ владельца): свойство scope действует одинаково, живой пробой не мерилась (p03 мерит same-user ветку);
- поведение живой станции (реальный cgroup, systemd, интеграция стража, порядок алфавит→допуск→замок в живом вызове) до фазы живой приёмки — станционные клетки p01–p03 командой приёмки.
