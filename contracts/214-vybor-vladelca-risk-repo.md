Это существующий корень доверия. `proverit_peredachu` D35–D39 связывает внешний продукт с опубликованным свидетельством станции, исходным START и точным tag-object/frozenCommit; одного origin/basename недостаточно. `profile_paths` повторно использует `next_id.sh`/`project_paths_resolve`, который вызывает существующий двухслойный resolver, включая канонизацию файлов профиля. `probe211.py` даёт независимые Git-миры станции/автора, frozen/OBJECT, START/yield и legacy; новая семья повторяет шесть входов арбитража. ## Боль и frontier

Арбитраж измерил: при отсутствующем/ином origin правило `risk_repo=r_wt` доверяет авторскому репозиторию. Поддельные frozen и закрепляющая строка автора плюс незакоммиченный legacy «обычный» дают reviewer rc 0 уже через D42. Чтение только HEAD автора не решает дефект: автор способен закоммитить подмену.

| Вариант | Решение по измеренной боли |
|---|---|
| Сравнить origin или запретить клон без origin | Отклонён: строка origin подконтрольна автору; запрет ломает штатную станционную изоляцию. |
| Читать HEAD выбранного носителя | Отклонён: устраняет грязь, но не подложный закоммиченный источник и локальный frozen. |
| Новый сетевой реестр владельцев по id-тегам | Отклонён: дублирует runtime-корень и D35–D39, добавляет сетевую зависимость каждому суду без необходимости. |
| Доверенный runtime `--repo` + уже удостоверенная передача, неизменяемый снимок | Выбран: авторский origin вообще не участвует в выборе; станционные isolated-клоны работают без origin; внешний источник допускается только по существующему свидетельству. |

## Предмет и инварианты

1. В обычном станционном/прямом проектном вызове владелец — ровно `--repo`, доверенный параметр запуска из runtime. `r_wt`, его origin, локальные id/frozen-теги, contracts.tsv, профиль и legacy не могут переопределить владельца. Никаких литералов имён/путей проектов, env-выбора владельца или fallback на автора. Репозиторий `--repo` не обязан иметь origin: изолированность автора не является ошибкой источника.
2. До чтения источников риска фиксируется полный commit `--repo HEAD^{commit}`. Профиль, его слой, пути contracts/registry и legacy берутся только из этого согласованного закоммиченного снимка; последующее движение HEAD, грязь, удаление и неотслеживаемые файлы владельца не меняют решение. Допустима существующая материализация Git-снимка с вызовом штатного resolver; профиль не разбирается второй реализацией. Источник слоя профиля — тот же доверенный снимок, не внешний env-root. Legacy читается по Git-объекту, не по цели симлинка рабочего файла.
3. Внешний продукт выбирается только после D35–D39 действующей проверяемой передачи. Класс берётся из точного `P_FROZEN`, удостоверенного станционным свидетельством; профиль/legacy — из того же immutable frozenCommit продукта. HEAD/грязь продукта и его более новые теги доверенным источником не становятся. Неудостоверенный источник передачи не превращается в обычный класс; прежние проверки свидетельства и адресные overrides не расширяются. Отсутствие удостоверенного frozen не является разрешением доверять авторскому HEAD.
4. Все D30/D42/D52/D64 используют один выбранный снимок метаданных. D42 читает декларацию из закреплённого frozen владельца. D52 читает декларацию из OBJECT носителя только при нуле frozen у доверенного владельца; профиль/legacy всё равно принадлежат владельцу. D64 сохраняет numeric-latest, annotated tag, предковость, непустое побайтное равенство состава/блобов; теги берёт только у доверенного владельца. Имена и mode контрактов, алфавит класса и порядок неоднозначности прежние.
5. Нет доступного доверенного commit/снимка → rc 1 `ISTOCHNIK_RISKA_NEDOSTUPEN`, без START/изменения ledger. Нет/неоднозначен класс в доступном снимке → прежнее `KLASS_RISKA_NET`, класс рисковый, reviewer без завершённого adversary получает rc 1 `ADVERSARIJ_DO_REVJUERA`; adversary допускается и reviewer после adversary допускается по прежнему порядку. «Не удалось прочесть» никогда не означает «обычный».
6. Фиксация метаданных не сдвигает HEAD/ветку владельца или автора, не добавляет им теги/коммиты и убирает собственные временные снимки при любом выходе. Git-снимок/его зависимости не исполняют checkout hooks. Область ответственности runtime защищает `--repo` и дерево установленного guard от записи автора; это не новая авторизация по самозаявленной строке задания.

## Модель угроз

ЗАЩИЩАЕТ:
- Авторский носитель (включая полные права на его commits/refs/config/грязь и удаление/подмену origin) не назначает доверенного владельца; незакоммиченные профиль/legacy владельца и движение его HEAD после фиксации не меняют класс; неизвестность не открывает reviewer без adversary.

НЕ ЗАЩИЩАЕТ:
- От записи в runtime `--repo`, установленный guard или уже удостоверенное станционное свидетельство; ловцы — существующая изоляция/path-guard и reviewer по источнику вызова. `--repo` из произвольного ручного shell не удостоверяет runtime сам себя.
- От согласованно ошибочных доверенных данных, подмены Git/ядра/общего UID, параллельной враждебной записи в собственный временный снимок, а также от переопределения происхождения через правомерное действие владельца. Ловцы — adversary/reviewer рисковой реализации и действующие guard-правила; это остаточный риск, не машинное доказательство происхождения runtime.
- От иных дефектов D9/передачи/бюджета, разрабатываемых 229/154; ловцы — их собственные батареи и суды. Тесты происхождения не заменяют факт модели судьи или принятие юридически значимого owner-решения.

Контрпример валиден на существующей грамматике Git/профиля/событий: тот же доверенный снимок и условия суда, меняются только авторский источник/грязь либо момент движения HEAD после фиксации. Расхождение требует наблюдаемой смены rc/труб/START; произвольное имя проекта/предмета не является разрешением константного решения. Неконформный профиль не обязывает выдавать обычный класс.
