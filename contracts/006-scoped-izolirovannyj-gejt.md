# Контракт 006 — быстрый изолированный гейт (поток A)

Номер выдан механизмом: `next_id.sh CONTRACT` → 006, тег `id/CONTRACT/006`. Предмет —
решение владельца (HANDOFF «ГДЕ МЫ», поток A): закрыть налог Н-41 — полный гейт
`verify_antiplacebo.sh` идёт 11–23 мин и прогоняется ~4 раза за контракт. Проект конструкции
решён советом fable (Anthropic) + terra (OpenAI) за 2 круга — `history://CouncilFable`,
`history://CouncilTerra`, `history://CouncilFable2`, `history://CouncilTerra2`. D1 (worktree) и
D2 (граница) — решения архитектора; замороженный слепок контракта 001
(`frozen/contracts/001/1`) НЕ трогается.

Гейт получает **scoped-режимы**: прогонять только ЗАДЕТЫЕ барьеры вместо всех. Три части:

- `scripts/scope_select.sh` — **юнит-селектор** (объявляет `НЕ БАРЬЕР:`, тестируется через
  `check_scope_select.sh`, как `metering_proxy.ts` через `check_metering.sh`): состояние дерева
  + флаги → множество ключей + режим + код;
- `scripts/check_scope_select.sh` — **барьер приёмки**: гоняет `scope_select.sh` по сценариям и
  УТВЕРЖДАЕТ выбор/режим/код/причину (по образцу `check_metering.sh`);
- интеграция в `scripts/verify_antiplacebo.sh`: scoped-режим реализуется как ФИЛЬТР над
  СУЩЕСТВУЮЩИМ циклом барьеров (селектор даёт ключи → сузить список барьеров → ТОТ ЖЕ цикл, тот же
  учёт и слепок), НЕ отдельным кодовым путём. Конструкция остаётся ДИЗАЙН-требованием, и приёмка
  обязана исполняемо различать минимум одного представителя КАЖДОГО обещанного класса отказа:
  м1 (красное не предъявлено, код 1), м2 (барьер выходит кодом 2), м3 (необъявленный код),
  н (запись вне $WORK, расхождение слепка). «По построению» в приёмке допустимо только когда само
  построение проверяется механизмом — иначе это cognitive-only. **Гарантией объявляется ПРОБА**
  (исполняемо различает классы отказа), конструкционное ограничение — обоснование дизайна.

1. **Интерфейс.** `scope_select.sh <корень> --changed <база>` — выводит задетое из
   `git diff --name-status -z <база>`, исследуя ОБА конца диффа. `scope_select.sh <корень>
   --scope <ключ>[/<case>]…` — явные ключи барьеров, опционально case-уровень. `verify_antiplacebo.sh`
   без флага — ПОЛНЫЙ прогон (умолчание, поведение не меняется ни на байт); с `--changed`/`--scope`
   — потребляет селектор и фильтрует цикл.
2. **Отображение (консервативный откат, fail-closed, ВЫВЕДЕНО из шапок).** Барьер = файл
   `scripts/`, чья первая непрерывная шапка объявляет `Коды возврата:`; библиотека/support =
   объявляет `НЕ БАРЬЕР:`. Сужение до ключа только если файл присутствует ТЕМ ЖЕ барьером в
   ОБОИХ концах диффа, роль/коды/шапка не менялись, нет динамического `source`, его не сорсит
   другой eligible-барьер. Любое add/delete/rename, смена роли, неизвестный/неклассифицированный
   файл, правка библиотеки/раннера/самого `scope_select.sh` → ПОЛНАЯ выборка. Скан
   классификации всего `scripts/` и сверка «барьер↔фикстура» — полнодеревные в ЛЮБОМ режиме.
3. **Коды и маркировка неавторитетности.** Пустая выборка (дифф вне барьеров/фикстур) → код 2 +
   строка «0 задетых — scoped ничего не доказал, полный гейт в CI». Инструмент недоступен (нет
   `git`, база не резолвится) → 2 (fail-closed), НЕ «0 задетых успех». Неизвестный ключ/case → 1
   с названным ключом; пустой явный `--scope` → 1. Scoped-режим печатает машинно-отличимый
   маркер (`MODE: scoped|needs-full` + строку `SCOPED: … — не для приёмки`), отличный от полного
   прогона, и НЕ содержит пути публикации CI-статуса. Требование потребителя проверять ИМЕННО
   полный контекст `antiplacebo-full` — следующий пункт потока A (см. «Незаполненные требования»).
4. **Узкая изоляция ресурсов.** Порты/HOME/TMPDIR per-fixture (`env -i`, свой `TMPDIR`, ретраи
   EADDRINUSE — большей частью уже есть; предмет — аудит и добор недостающего). Замороженный
   слепок (исключения контракта 001) НЕ трогается. Конкурентный локальный гейт даёт ИСТИННОЕ
   громкое красное «прогон недостоверен целиком» (не false-green) — сохранённая ветвь.

## Критерий готовности

Приёмка — ДВА барьера, оба предъявлены КРАСНЫМИ против обманных стабов ДО круга критика (краснота
засчитана ПОВТОРНЫМ прогоном): `check_scope_select.sh` (тир 1, селектор) и `check_scoped_run.sh`
(тир 2, интеграция scoped-режима в раннер). Реальные `scope_select.sh` и `verify_antiplacebo.sh
--changed` (зона исполнителя) обязаны пройти оба.

**Тир 1 — `fixtures/check_scope_select/case_*.sh`** (предъявлены КРАСНЫМИ ДО критика): барьер
`check_scope_select.sh` ловит обманный `scope_select` на каждой ветви. Ветвь (м) закреплена за
тиром 2 и здесь не повторяется.
- (а) `--scope` неизвестный ключ → 1, названный ключ;
- (б) `--scope` пустой явный список → 1;
- (в) `--scope <ключ>/<неизвестный_case>` → 1, названный case;
- (г) `--changed` дифф только по докам → 2 + строка «0 задетых…» + машинный маркер `SCOPED:`, НЕ 0;
- (д) `--changed` при нерезолвимой базе ЛИБО не-git дереве → 2 (fail-closed), НЕ «0 задетых успех»;
- (е) `--changed` правит барьер `b` (тот же барьер в обоих концах, роль не менялась) → `MODE: scoped`,
  выбран РОВНО ключ `b` (не `a`);
- (ж) `--changed` правит библиотеку (`НЕ БАРЬЕР`, сорсится барьером) → `MODE: full`;
- (з) `--changed` add / delete / rename / смена роли шапки — КАЖДЫЙ → `MODE: full` (или 2), НЕ
  частичный scoped;
- (и) case-уровень: `--scope <ключ>/<case>` → выбран РОВНО этот case;
- (к) scoped/needs-full печатает машинно-отличимый маркер (`MODE:` + строка `SCOPED: …`) — ОБА
  режима, не только scoped; иначе отличим от полного НЕ по маркеру;
- (л) git-отсутствие: игрушка строится при доступном git (для setup), а ВЫЗОВ селектора — с PATH без
  `git` → код 2 (fail-closed), НЕ «0 задетых успех». Это ИСПОЛНЯЕМЫЙ тест против подмены PATH,
  смена claim «нет git → 2» — на усмотрение владельца. Неавторитетность обеспечивает ПОТРЕБИТЕЛЬ
  (точный контекст `antiplacebo-full` — следующий пункт потока A), НЕ статический разбор исходника
  селектора.

ДИСПЕТЧЕР ВЕТВЕЙ ОБОИХ барьеров — fail-closed: неизвестное имя ветви (`WANT` ∉ известного
множества и не `all`) → код 1 с названным WANT. Без этого названная ветвь может стать
фантомом молча (см. находку 3 арбитража).

**Тир 2 — `fixtures/check_scoped_run/case_*.sh`** (второй барьер `check_scoped_run.sh`, интеграция
scoped-режима в раннер; предъявлены КРАСНЫМИ ДО критика против обманного стаб-раннера — симметрично
тиру 1, БЕЗ отсрочки): барьер гоняет `<корень>/scripts/verify_antiplacebo.sh` на игрушечных
деревьях и утверждает:
- (л) ФИЛЬТР + RC: при правке одного барьера `b` прогнан ТОЛЬКО он («барьеров: 1», фикстуры `b`
  запускались, `a` — нет) И итоговый RC==0 — ловит фильтр, выронивший выбранный барьер либо не
  сузивший выборку, ИЛИ вернувший не-ноль не по предмету;
- (м1) СОХРАНЕНИЕ ОТКАЗА (класс «красное не предъявлено»): scoped_rc == full_rc И scoped-вывод
  содержит подстроку диагноза «красное не предъявлено»;
- (м2) СОХРАНЕНИЕ ОТКАЗА (класс «код 2 — нечем проверить»): scoped_rc == full_rc И диагноз
  «нечем проверить» присутствует в scoped-выводе;
- (м3) СОХРАНЕНИЕ ОТКАЗА (класс «необъявленный код 7»): scoped_rc == full_rc И диагноз
  «которого не объявлял» присутствует в scoped-выводе;
- (н) СОХРАНЕНИЕ ОТКАЗА (запись вне $WORK): scoped_rc == full_rc И диагноз «дерево изменилось»
  присутствует в scoped-выводе — слепок брекетит цикл неизменным кодом;
- (case) CASE-ФИЛЬТР: `--scope <ключ>/<case>` прогоняет РОВНО этот case (на дереве с 2 case для b
  под `KEY: b/case_b_1` прогон ровно 1 case), несуществующий case → fail-closed (не-ноль).
