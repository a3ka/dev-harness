## Frontier: границы и отвергнутые варианты

- **Граница-1 (место суждения — вариант А frontier: обёртка на PATH, НЕ вариант Б).**
  Взвешены оба варианта явно:
  - (а) обёртка `scripts/gitw`, вызываемая путём/PATH-пином: суждение НА execve-уровне —
    независимо от формы tool-call (прямой bash, скрипт, python3-subprocess — А-229 ловится,
    любой execve `git`-обмена через обёртку видим ей самой); потребители пинают её точечно
    (норма-строки: обмены — только через `bash scripts/gitw …`).
  - (б) расширение path-guard.ts: API расширения — block-only (возвращает {block, reason}),
    env вызова не переписывает; судит СТРОКУ команды — слепота к формам ИЗМЕРЕНА живьём в
    том же расследовании (cd-цепочки, $ПЕРЕМЕННЫЕ в путях, `2>&1`, редиректы — шесть отбитов
    за одну пачку проб, классы А-214/А-250/А-255/А-257); плюс вторая реализация URL-грамматики
    в TypeScript = второй читатель одного инварианта (класс дрейфа, прецедент lib_zones).
  - Решение: (а). Вариант (б) отвергнут — не «дёшево»: block-only + слепота форм + дрейф.
- **Граница-2 (судятся ТОЛЬКО обмены push/fetch/pull; запись конфига НЕ судится).**
  `remote set-url`/`config --local`/правка файла проходят мимо обёртки БЕЗ отказа —
  сознательно: путей записи .git/config легион, единственная точка, где подмена СТАНОВИТСЯ
  вредом — исполнение обмена. Обёртка делает подмену БЕЗВРЕДНОЙ (обмен откажет по литералу)
  и ДЕТЕКТИРУЕМОЙ (DOTGIT-нога 024 ловит дельту конфига за минуты — так был пойман Н-148),
  но не запрещённой. Clone с локальным путём также не судится: вред материализуется в
  обмене/слиянии (все — под гардом) либо в утечке путей (детектор 024, вне предмета).
- **Граница-3 (двухступенчатая сверка: литерал → живость).** Первая ступень — буквальное
  равенство цели каноническому URL (истина); вторая — `ls-remote <цель> HEAD` fail-closed:
  недостижимый авторитет = именованный отказ, не молчание (прецеденты: pre-push 022 п.4,
  spawn 023 «авторитет недоступен»). Успех самого обмена сигналом НЕ является (А-259).
- **Граница-4 (ровно ОДНА обходная ручка).** `GIT_EXCHANGE_GUARD_CANONICAL` переопределяет
  канонический URL ЦЕЛИКОМ (для toy-реп и фикстур). Полный EXEMPT-байпас отвергнут: каждая
  ручка — обходная поверхность; одной достаточно. Ручка объявлена в модели угроз.
- **Граница-5 (проводка по грамматике 038).** Поведенческие нормы (цикл синхронизации
  оркестратора с DOTGIT-детекцией; STOP-и-доклад implementer/architect) — role-каналом;

- **Граница-6 (отвергнуто: deny-глобы `.omp/config.yml` bash.patterns на сырые формы

## Инварианты (механизм: `scripts/gitw` — обёртка обмена)

- **И-1 (разрешение настоящего git).** Первый `git` в PATH, чей realpath ≠ realpath самой
  обёртки; не найден → rc 2 `gitw NOT_IMPLEMENTED: настоящий git не найден`. Граница: клеткой
  батареи не накрыта (окружение батареи всегда имеет /usr/bin/git) — названа прямо.
- **И-2 (разбор argv, fail-closed).** Ведущие глобальные флаги потребляются по arity:
  `-C <путь>`, `-c <к=v>`, `--git-dir[=]<x>`, `--work-tree[=]<x>`, `--namespace[=]<x>`,
  `--bare`, `--no-pager`, `--paginate`, `--no-replace-objects`, `--literal-pathspecs`,
  `--exec-path[=]<x>`, `--no-optional-locks`. Первый не-флаг токен = подкоманда.
  НЕраспознанный ведущий флаг → rc 1, фраза F3: у неизвестного флага неизвестна арность,
  подкоманда не может быть определена надёжно, а несудимый обмен запрещен классом предмета.
- **И-3 (судимые подкоманды).** Ровно `push`, `fetch`, `pull`. Всё прочее — прозрачная
  передача (И-8) без суждения.
- **И-4 (цель обмена).** (а) первый не-опциональный аргумент после подкоманды, если он
  URL-подобен (содержит `://` или начинается с `/`, `./`, `../`) — цель = он; ИНАЧЕ
  (б) сконфигурированный origin — ДВОЙНОЙ сверкой, обе литерально каноничны:
  `$REAL <контекст> config --get remote.origin.url` (видит `-c`-перекрытия вызова —
  живой замер этой пачки: `remote get-url` при `-c` возвращает ФАЙЛОВОЕ значение) И
  `$REAL <контекст> remote get-url origin` (видит insteadOf-переписывание, которое
  `config --get` не раскрывает); `<контекст>` = сохранённые `-C`/`-c`/`--git-dir`/
  `--work-tree` глобальные флаги ОБЯЗАТЕЛЬНО те же, что у исполняемого вызова (инвариант
  единства разрешения: запрос и исполнение обязаны разрешаться в ОДНО репо). Нет ключа
  конфига и нет get-url → нет origin → передача: git откажется сам, обёртка чужие отказы
  не присваивает (канарейка г7).
- **И-5 (сравнение — ТОЛЬКО буквальное равенство целых строк).** `[ "$url" = "$canonical" ]`;
  никогда подстрока/префикс/regex/glob, построенные из untrusted-значения (норма-класс 037
  accept_task_commit). Канонический URL — ЕДИНСТВЕННАЯ константа
  `ssh://git@github.com/a3ka/dev-harness.git` в коде обёртки; ручка
  `GIT_EXCHANGE_GUARD_CANONICAL` заменяет её целиком, той же literal-семантикой.
- **И-6 (несовпадение).** rc 1, ровно ОДНА строка stderr: `gitw ОТКАЗ: URL origin не
  канонический: <цель-санитизированная>`; обмен НЕ исполняется — refs/FETCH_HEAD получателя
  не тронуты. Санитизация печати: каждый байт <0x20 или =0x7F → `?` (подделка строк отказа
  переносом строки внутри URL невозможна).
- **И-7 (живость авторитета).** `$REAL <контекст> ls-remote <цель> HEAD`; rc≠0 → rc 1,
  `gitw ОТКАЗ: авторитет недоступен: ls-remote <цель> rc=<код>` — fail-closed: сетевой сбой
  не есть санкция.
- **И-8 (прозрачная передача).** Прошедшее суждение (или несудимая подкоманда) → `exec
  "$REAL" "$@"` — argv побайтово тот же, код возврата реального git, stdout/stderr не
  перехватываются, обёртка молчит.
- **И-9 (среда не санируется).** `GIT_DIR`/`GIT_WORK_TREE` и прочие git-переменные действуют
  на запрос (И-4б) и исполнение (И-8) ОДИНАКОВО — снятие переменных разорвало бы единство
  разрешения из И-4. Фикстура обязана снимать их сама для своего toy-мира (её герметичность,
  не предмета).

Фразы — единый список (фикстуры сверяют дословно, grep -F):
F1 = `gitw ОТКАЗ: URL origin не канонический: ` + санитизированная цель;
F2 = `gitw ОТКАЗ: авторитет недоступен: ls-remote ` + цель + ` rc=` + код;
F3 = `gitw ОТКАЗ: неизвестный глобальный флаг: ` + флаг;
N  = `gitw NOT_IMPLEMENTED: настоящий git не найден`.

## Единый источник семантик

- Канонический URL: константа в `scripts/gitw`; контракт и фикстура несут её побайтово.
- Фразы F1/F2/F3/N: список §Инварианты; код несёт дословно; фикстуры grep -F.
- Судимость подкоманд и arity-таблица флагов: ОДИН case в `scripts/gitw` (И-2/И-3); вторая
  реализация запрещена (прецедент lib_zones/lib_registry).
- Гигиена парсящего гварда (норма 041): структурные поля и их замкнутые алфавиты —
  подкоманда ∈ {push, fetch, pull}; глобальные флаги — таблица И-2; цель-URL — произвольная
  строка БЕЗ управляющих байтов на печати (санитизация И-6); разделители не переиспользуют
  байты данных (argv — execve-нули, сравнения целых строк, без join/split); терминатор
  разбора — первый не-флаговый токен (точечный якорь); сравнение untrusted-к-константе —
  только литеральное. Self-application: `bash scripts/check_threat_model.sh .` на самом
  контракте → rc 0 (форма секции модели угроз — прогон до заморозки).

## Модель угроз

ЗАЩИЩАЕТ:
- исполнение обмена (push/fetch/pull) с неканонической целью в ЛЮБОЙ форме вызова: прямой,
  `-C`/`-c`/`--git-dir` контекст, явный URL-аргумент — именованный отказ до исполнения,
  получатель не тронут;
- тихий маскарад self-referential URL (А-259): суждение вынесено ДО обмена и по литералу
  конфига, успех обмена больше не участник доказательства;
- ослепление/недостижимость авторитета: fail-closed именованным отказом, а не молчаливым
  «Everything up-to-date» при расходящемся апстриме;
- probe C локального вектора: инжект `wip/*`-рефов в живую репо из клона с локальным
  origin умирает на URL-сверке до касания цели (клетка г1в).

НЕ ЗАЩИЩАЕТ:
- саму запись в .git/config (`remote set-url`, `config --local`, правка файла): проходит —
  подмена делается безвредной (обмен откажет) и детектируемой (DOTGIT 024), не запрещённой
  (граница-2);
- выставление ручки `GIT_EXCHANGE_GUARD_CANONICAL` самим агентом: TCB-класс (040 дословно) —
  ручка видна в командной строке транскрипта, злонамеренный обход вне модели (Г4 опровергнут
  мотивом, инциденты — растерянность, не атака);
- необменные операции: clone с локальным путём (вред материализуется в обмене/слиянии — под
  гардом; утечка путей — детектор 024, вне предмета), сырые add/commit/reset в чужом чекауте,
  config-записи — STOP-норма ролей + детектор, не обёртка;
- инжект рефов через КАНОНИЧЕСКИЙ origin (wip-ветки на GitHub) — предмет устава/pre-push 022,
  не 045;
- подмену PATH до обёртки, злонамеренный TCB, сговор (040 дословно).

## Демаркация контрпримера (сходимость серии)

- ПОЛОЖИТЕЛЬНАЯ ОБЛАСТЬ (конформные входы): `gitw [<глобальные флаги из таблицы И-2>]
  <push|fetch|pull> [...]` в репозитории с настроенным origin ЛИБО с явным URL-аргументом,
  цель — строка без ограничения алфавита (управляющие байты допустимы во ВХОДЕ, гасятся на
  ПЕЧАТИ). Все инварианты И-1..И-9 → ровно один из исходов: rc1 с F1/F2/F3 (обмен не
  исполнен, побочных эффектов нет) ЛИБО прозрачный exec (И-8).
- ОТРИЦАТЕЛЬНЫЕ ВХОДЫ СЕРИИ: та же форма, нарушен РОВНО ОДИН инвариант → именованная клетка
  батареи (г1–г10, по одной причине на клетку; обманный стаб расходится с честной реализацией
  ровно на своей клетке смерти — Н-39: стаб привязан к входу, где его дефект наблюдаем).
- Валидный контрпример против сходимости = инвариантность к значениям (случайные toy-пути на
  каждом прогоне; подстановка значений не меняет вердикт клетки) ∧ расхождение на КОНФОРМНОМ
  входе. Расхождение, зависящее от конкретных значений, — дефект фикстуры, не предмета.
- Вне формы (не-обменные подкоманды, argv без подкоманды, вызов не обёрткой) — НЕ
  контрпримеры: инварианты 045 о них не заявляют ничего.
