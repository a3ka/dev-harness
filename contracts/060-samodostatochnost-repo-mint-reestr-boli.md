## Модель угроз

ЗАЩИЩАЕТ:
- номер контрактного артефакта проектной сессии резервируется тегом в `.git` ПРОЕКТНОГО репо, очередь харнесса (id/-теги, registry/contracts.tsv) не трогается — пилотная боль (д) закрыта механизмом, не дисциплиной.
- реестр заморозок проектных контрактов живёт в дереве проекта (е), самокоммит реестра — в истории проекта; реестр харнесса байт-в-байт неизменен.
- черновики болей проектной сессии не попадают в общий машинный пул харнесса (ж); строка записи несёт HEAD именно проектного репо, а не чекаута харнесса.
- относительное значение руки даёт именованный отказ N1 rc 1 ДО любого письма у всех трёх потребителей, когда рука оперативна — явного корня нет (Граница-3; при валидном явном корне отказа нет, Граница-2; path-injection: значение вставляется в пути git-операций).
- доставка руки сессии — экспортом в окружение потомка лаунчера, а не печатной строкой: потребитель, запущенный через границу лаунчера, видит корень без ручной установки (наблюдается окружением стаб-omp, прецедент 055).

НЕ ЗАЩИЩАЕТ:
- подмену env владельцем окружения сессии (TCB-класс 040 — локальное окружение под контролем исполняющего).
- гонку двух независимых клонов одного проекта (граница «гоночный клон» next_id — без изменения, дубль ловит check_ids при слиянии).
- запись болей мимо draft-инструмента напрямую в файлы харнесса по абсолютному пути — cognitive-only остаток, ловец — ревьюер сессии + норма R1 в промпте (промпт — носитель, не гейт).
- потребление недефолтных workflowPaths (Граница-5) и домен почты самокоммита реестра в проекте (Граница-6).
- содержание workflow-файла проекта и сетевые эффекты реального omp (клетка к8 использует стаб-omp, пишущий только факт окружения).

## Демаркация контрпримера (сходимость серии)

- ПОЛОЖИТЕЛЬНАЯ ОБЛАСТЬ (конформные входы): git-репо с хотя бы одним коммитом +
