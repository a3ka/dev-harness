# Контракт 213 — дверь сдаточного листа: «последний FAIL» судится ТОЛЬКО в предъявляемой фазе (check_sdacha / karta_poslednij_fail)

СТАТУС: ЧЕРНОВИК-ЗАТРАВКА (bootstrap: `make_task --role architect` требует существующий `contracts/213-*.md`; текст контракта пишет architect по заданию станции — затравка не является ни спекой, ни критерием; заменяется целиком).

## Боль
Измерено 23–24.11 (147 v6): `bash scripts/pre_critic.sh contracts/147-gespraech-vhod-menu.md` на OBJECT `dde53fe039b7947b42a715b12f8ad6855a7c4306` (`wip/147/orch-lin`) → rc 1 «сдаточный лист красен: последний FAIL 2: карта 0 строк». Причина: `scripts/check_sdacha.sh` (строки ~262–265) зовёт `karta_poslednij_fail "$ROOT" "$PRED_VERDIKT" "$telo"` (`scripts/lib_karta_sdachi.sh`) и судит как «последний FAIL» вердикт ПРОШЛОЙ фазы v5 — FAIL v5b `704a6ccfc` (12.11, `contracts-147-v5-vyzov2-fail.md`) без секции карты, хотя фаза v5 ЗАКРЫТА accept `e1f71fd1c` (18.11, карта 17 строк). Предъявляется новая фаза v6, у неё FAIL-вердиктов НЕТ; прошлый FAIL закрытой фазы не должен красить сдачу. Эксперимент консультанта: `check_sdacha --run` с выключенной ТОЛЬКО этой проверкой → «СДАЧА: лист зелёный (двери=9 карта=17/17 дельта=1)» rc 0. Цена: слово владельца 23.11 на разовый запуск критика 147 v6 при красном pre_critic («147: разово разрешаю запуск критика 147 v6 при красном pre_critic по причине «последний FAIL — прошлой фазы v5, закрытой accept»; запись причины и остаточного риска в HANDOFF; параллельно предмет 213 — исправление двери.»).

## Решение
Слово владельца 23.11: «параллельно предмет 213 — исправление двери». Направление: `karta_poslednij_fail` (и вызывающий код двери) выбирает «последний FAIL» ТОЛЬКО среди вердиктов ПРЕДЪЯВЛЯЕМОЙ фазы предмета (фаза = версия заморозки/вызов по имени `contracts-<N>-v<V>*.md` и строке `фаза=` в `СУД:`); FAIL фазы, закрытой более поздним accept той же фазы, либо принадлежащий другой (предыдущей) фазе, не судится; FAIL предъявляемой фазы по-прежнему обязан иметь валидную карту и блок-закрытие в «## Дельта». Реши: как определяется фаза и «закрытость» (по имени файла, по строке `СУД:`, по accept позже по истории); как сохранить уже работающие защиты (FAIL без карты в той же фазе — отказ; подмена фазы — отказ «неизвестность ≠ чисто»); граница с 192/193/204 (карта вызовов по фазе — `karta_index`).

КЛАСС ЗАДАЧИ: кодовый. КЛАСС РИСКА: рисковый (ослабление двери сдачи — допуск судейского входа; adversary → reviewer): ослабление допуска требует доказательства, что FAIL ТЕКУЩЕЙ фазы по-прежнему судится.
РАБОТА НЕ РАЗДАЁТСЯ: затравка; зоны и раздачу объявляет architect.

## Незаполненные требования:
- точные зоны (`scripts/check_sdacha.sh`, `scripts/lib_karta_sdachi.sh` — зона 193/204 и пересечения; `fixtures/workshop_project/sdacha_193/`, `karta_vyzova_204/`; CI-учёт) и ПЕРЕСЕЧЕНИЕ с активными предметами (193, 204, 192, 147, 148, 197);
- инварианты: FAIL предъявляемой фазы без карты/без блок-закрытия — отказ (как сейчас); FAIL прошлой закрытой фазы — не судится; фаза не определилась — отказ с именованной причиной (не молчаливое допущение); регресс 193/204 зелёный;
- красные клетки (мир: FAIL v5b без карты + accept v5 + предъявляется v6 → лист зелёный; FAIL текущей фазы без карты → отказ; accept ДО FAIL (порядок) → судится; неопределённая фаза → отказ) и стабы к ветвям — привязывает architect по коду, НЕ проза контракта.
