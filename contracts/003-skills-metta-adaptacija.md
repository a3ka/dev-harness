## Критерий готовности

1. **Состав и подлинность.** `skills/` содержит РОВНО каталоги `grilling`,
   `writing-for-agents`, `tdd`, `diagnosing-bugs` — множество проверяется барьером дословно.
   Тела — английские оригиналы снимка `9c9f36c`; шапка-адаптация на русском несет ИМЕННО этот
   hash. `bash scripts/check_skills.sh` → 0 — НОВЫЙ барьер, ВОСЕМЬ ветвей отказа:
   (а) скил не обнаружен omp — захват запуска с подставным omp, ответ называет слово из тела;
   (б) имя каталога ≠ имени фронтматтера;
   (в) hash шапки ≠ значению из блоба высшей заморозки ЭТОГО контракта (не зашит в барьер);
   (г) каталог вне объявленного множества четырёх;
   (д) профиль не совпадает с репозиторием ПОСЛЕ overlay ИЗ ПУСТОГО состояния: барьер сам
   создаёт пустой временный HOME, запускает НАСТОЯЩИЙ overlay (не его эхо), затем `cmp`
   каждого `SKILL.md` в РЕАЛЬНОМ профиле запуска (тот HOME, куда overlay положил) с
   репозиторным — приёмка 4 не может подменить прогон печатанием ok-строки: ветвь проверяет
   ПОСТУСЛОВИЕ действия, а не сообщения;
   (е) тело не совпадает со снимком upstream: `cmp` репозиторного `skills/<имя>/SKILL.md`
   с raw.githubusercontent.com/mattpocock/skills/<hash>/skills/<категория>/<имя>/SKILL.md,
   где <категория> — productivity для grilling и writing-for-agents, engineering для tdd и
   diagnosing-bugs (пути upstream с категориями — замер арбитража 5: путь без категории даёт
   404); <hash> — из блоба высшей заморозки контракта, как в ветви (в). Сверяется ТЕЛО ПОСЛЕ
   шапки-адаптации: граница — первая строка фронтматтера upstream `---`, всё от неё —
   байт-в-байт; шапка-адаптация и её русский текст во владении адаптации. Сеть есть локально
   и в CI; недоступность — код 2 с причиной, не зелёное;
   (ж) псевдоним `grill-me` не документирован в шапке `grilling` (grep по «grill-me»);
   (з) полнота красных фикстур: на РОДИТЕЛЕ первого коммита по `skills/` и
   `scripts/check_skills.sh` каталог `fixtures/check_skills/` уже содержит фикстуры ВСЕХ
   объявленных ветвей — мера полноты, а не только первенства (одна ранняя фикстура и шесть
   поздних не проходят).
2. **Указатели в ролях — гибрид, мерой поимённо.** Для КАЖДОЙ пары из таблицы ниже
   соответствующий файл роли обязан содержать строку, где `skills/<имя>/SKILL.md` и ведущее
   английское слово из скобок стоят ВМЕСТЕ; посторонних `skills/`-строк в ролях нет. Проверка
   командой на пару: `grep -cE "skills/<имя>.*<слово>|<слово>.*skills/<имя>" <файл роли>` →
   ровно 1, иначе код 1. Русское условие строки — `cognitive-only`, ловец ревьюер.

   | роль | скил (leading word) |
   |---|---|
   | architect | grilling (frontier), writing-for-agents (context pointer), tdd (tautological), diagnosing-bugs (tight loop) |
   | implementer | tdd (red → green), diagnosing-bugs (tight loop) |

   Качество русских условий — `cognitive-only`, ловец ревьюер.
3. **Красные фикстуры ВСЕХ ВОСЬМИ ветвей (а)-(з) — архитектор ДО раздачи, порядком коммитов.**
   Фикстуры ВСЕХ восьми ветвей (а)-(з) лежат в коммитах архитектора, и ПЕРВЫЙ коммит по
   `fixtures/check_skills/` старше ПЕРВОГО коммита по `scripts/check_skills.sh` и `skills/`.
   Мера: `git log --reverse --format=%an -- fixtures/check_skills/ | sed -n 1p` → `architect`
   и `git log --reverse --format=%h -- fixtures/check_skills/ skills/ scripts/check_skills.sh |
   sed -n 1p` указывает на фикстурный коммит — раньше ЛЮБОГО коммита по скилам и барьеру →
   иначе код 1. Ветви, найденные при реализации,
   исполнитель ПОДАЁТ заявкой; красную фикстуру к ней пишет архитектор в своей зоне —
   исполнитель в `fixtures/` не пишет вовсе (zone-согласовано, см. ниже).
4. **Overlay кладёт, барьер проверяет.** `npm run overlay` копирует `skills/` в профиль omp
   (цель — `.omp/agent/skills/` в HOME профиля, замер шага плана 008) и печатает ok-строку;
   постусловие держит ветвь (д) барьера. `check:skills` в приёмке и CI.
