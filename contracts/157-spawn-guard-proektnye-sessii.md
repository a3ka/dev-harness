## Инварианты и границы

1. Источник — только `ctx.sessionManager.getSessionFile()` после алфавита 104. Грамматика — СТРУКТУРНЫЕ сегментные позиции маркеров, не подстрока: единый источник — две регулярки `fixtures/workshop_project/spawn_guard_157/model/stateRoots.ts`, реализация несёт их побайтово. Станция `^(.+)/zones/([^/]+)/\.omp/profiles/([^/]+)/agent/sessions/(.+)$` → `--sostojanie <S>/zamok`, `--zhurnaly <S>/zones/<zone>/.omp/profiles/<profile>/agent/sessions`; проект `^(.+)/home/\.omp/profiles/([^/]+)/agent/sessions/(.+)$` → `--sostojanie <P>/state/zamok`, `--zhurnaly <P>/home/.omp/profiles/<profile>/agent/sessions`. Корень журналов — `agent/sessions` СРАЗУ за `profiles/<profile>/`, не последнее совпадение `agent/sessions` в хвосте пути. Станция проверяется первой; при значении `<S>`, само содержащее `/zones/`, регулярка детерминирована жадным префиксом (крайнее правое вхождение). Значения `<S>`, `<zone>`, `<profile>`, `<P>` и хвоста имени — не политика: любой допустимый `<P>` (включая `dev-harness-projects/shadow`) доходит до двери; подстрока `/zones/` в хвосте имени сессии, `/home/` внутри значения `<P>` и вложенный `agent/sessions` в хвосте принадлежность НЕ меняют — её определяют только сегментные позиции маркеров. Всё, что не совпало ни с одной регуляркой, — прежний именованный fail-closed ДО двери: без вызова двери и без записи состояния. `--repo` остаётся cwd; ни cwd, ни `HARNESS_SESSION_HOME`, ни другой env корнем не являются.
2. На каждой распознанной раскладке вычисленный корень не есть разрешение на спавн: реальная дверь вызывается для **каждого** валидного task, и все три ветви её статуса дают одинаковые решения на ОБЕИХ раскладках: rc 0 — пропуск; rc 1 — блок с первой непустой строкой stderr как именованной причиной; rc 2 — fail-closed БЛОК `ОТКАЗ: страж замка сломан (fail-closed)`, не пропуск (140 инв. 1). Отказ алфавита 104 — до двери; чужие инструменты без изменений. Временный event удалён после суда, существующие замки станции не перемещаются.
3. Конформные входы батареи — абсолютные пути к jsonl, совпавшие с одной из двух регулярок п. 1 (значения компонентов произвольны, включая вложенный `agent/sessions` в хвосте), и события `task` с валидным agent установки и синтетическим живым ctx. Валидный контрпример = инвариантность к значениям компонентов ∧ расхождение с инвариантом на конформном входе, не произвольный синтаксически битый путь. Чужая форма — путь без обеих структурных форм: маркеры-подстроки в хвосте имени её не легализуют, отказ до двери без записи состояния. Раскладка с обоими маркерами структурно, симлинки и спор о доверии к самому ctx — вне этого адресного изменения; замороженные обязательства не ослабляются.

## Красное предъявление и приёмка

`W = python3 fixtures/workshop_project/spawn_guard_157/probe.py`. Батарея копирует **поставленный** `.omp/extensions/spawn-guard.ts` в установку с конфигом и испытательной дверью, вызывает настоящий `tool_call` через драйвер Node. Испытательная дверь пишет argv и возвращает независимые rc 0, rc 1 с первой строкой stderr `DOOR_DENY_157` либо rc 2 — все три ветви исполняются на обеих раскладках; для чужих форм сверяется неизменность всего дерева случая (замок не создаётся нигде).
