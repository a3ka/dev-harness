**Ветвь 1 — делегирование устава → check_charter (Н-72, решение (б); реализация (i)

делегируется уставному судье. Предикат уставного класса — ТА КОЛЬЦО области, что у

**Кольцо доказано входами на ОБЕИХ половинах области** (блокер 2 критика :123),
серийными входами одного case (А-32):

- ПОЛОЖИТЕЛЬНЫЙ frozen: замороженный `contracts/NNN-*` и замороженный `plans/NNN-*`
  (живой тег первой заморозки) с разрешённой правкой в истории (строка РАЗРЕШИЛ) →
  делегирование rc 0. Сегодня оба входа красны «вне зоны» — измерено прогоном пачки.
- ОТРИЦАТЕЛЬНЫЙ frozen: `contracts/NNN-*`/`plans/NNN-*` БЕЗ тега первой заморозки
  (и не следующий свободный номер) → НЕ уставного класса → прежний зонный суд:
  для автора вне зоны пути — отказ «вне зоны» ДО и ПОСЛЕ 019 (охрана от переусердия
  предиката). Обход «предикат только для AGENTS/ROADMAP» краснит scoped: обе
  положительные половины уходят в «вне зоны» → «нет положительного контроля».

Репо без соответствующего тега → путь НЕ уставного класса → прежний зонный суд (новой
ветки без наблюдаемого входа не заводится, Н-39). Делегирование: `check_staged`
запускает `check_charter <ROOT>` (судья — из своего SELF_DIR, не из предмета) и
наследует rc И вывод: rc 0 → путь пропущен (ок-строки check_charter с числом
просмотренных проходят наверх — зелёное называется, шапка check_charter:184-189);
любой ненулевой rc → отказ rc 1 с наследованным текстом (именованные причины
«изменён без разрешения владельца», «не назвала путь», «без причины» — единый
источник грамматики razreshil() в check_charter.sh). Свидетель `judged: <путь>`
сохраняется (со-локализация F-4: напечатано ⟺ судимо).

**ИЗМЕРЕННАЯ ГРАНИЦА (названа прямо, прогон 2026-09-01):** pre-commit НЕ видит тела
коммитящегося коммита — `COMMIT_EDITMSG` отсутствует на входе хука при `git commit
-m`. Поэтому ключ РАЗРЕШИЛ ТЕКУЩЕГО коммита судится check_charter ПО ИСТОРИИ: CI
`check:charter` (уже в проводке, ci.yml:154) краснеет на запушенном нарушении — после
019 ВКЛЮЧАЯ уставную дельту merge-коммитов (И-7), — и каждое следующее делегирование
при staged уставного пути отказывает на нём же. Блок ДО создания коммита невозможен
без нового хука (commit-msg) — вне предмета (Не-цели). Норма строки не меняется:
строку пишет владелец либо сессия по его прямому слову (правило 11); механика лишь
перестаёт отбивать легальный коммит до создания. Остаток вне предмета, назван:
`check_zones.sh:267` читает историю зон тем же `rev-list --no-merges` — ЗОНАЛЬНАЯ
дельта merge-коммитов не судится; предмет 019 — устав (файл вне зоны implementer
019, потребность не измерена).

**Ветвь 2 — draft-контракт следующего номера → автор architect (Н-72, расширение).**
Staged-путь `contracts/<NNN>-<slug>.md` (разбор rc 0), где NNN — СЛЕДУЮЩИЙ свободный
номер класса CONTRACT, И автор РОВНО `architect` → путь пропущен (не судится зонами):
зоны нового контракта живут в его собственном файле и неактивны до заморозки
(самоссылка), авторство пачки — architect. Следующий свободный номер читается
БЕЗОПАСНО ДЛЯ ПРЕДМЕТА: новая библиотечная функция `next_id_peek <корень> <класс>` в
`next_id.sh` (импорт по образцу NEXT_ID_LIB) — те же четыре источника max+1 (теги
`id/CONTRACT/*`, имена ссылок, HEAD, история), НО без создания тега-резерва: резервация
— побочный эффект ВЫДАЧИ, судья не занимает номера и не меняет предмет. Peek судит по
тегам/веткам/HEAD/истории, НЕ по индексу: staged draft — сам себе следующий номер.
Всё иное — чужой автор на draft-пути, не-следующий номер, иное расширение — прежний
зонный суд (отказ «вне зоны» и до, и после 019). Планы plans/ в draft-пуск не входят.
**Названное окно гонки (совет критика :50):** peek без резервации не сериализует
читателей — два architect-клона от одной вершины одновременно читают один и тот же
следующий NNN и оба проходят суд. Сериализация в 019 НЕ заводится (§10 параллельные —
отдельный предмет); ловец downstream — существующий `check_ids`: слитые разные slug
с одним NNN краснеют на done-коммите, поэтому обход критерия «CI зелёный на
done-коммите» через гонку не предъявлен. Точка сериализации — предмет §10.

**Ветвь 3 — octal-фикс спавна (живая находка обкатки 018-среза-2).**
`spawn_agent.sh:122`: `printf '%03d' "$nnn"` парсит аргумент с ведущим нулём как
ОКТАЛ. Измерено живым прогоном (2026-09-01): `--nnn 042` → rc 0 и
`BRANCH=wip/034/architect` (042-октал = 34) — тихая съезжка значения; `--nnn 019` →
rc 1 `printf: 019: invalid octal number`, спавн мёртв до создания ветки (живой случай
обкатки). Фикс по образцу строки 117: `nnn_padded="$(printf '%03d' "$((10#$nnn))")"`.
На диске основного дерева лежит незакоммиченный локальный фикс этой же формы — 019
фиксирует его первым пост-заморозочным коммитом (прецедент 5f5446e).
Двунаправленность паддинга пинуется ЗНАЧЕНИЕМ (блокер 1 критика :119): `--nnn 042` →
`BRANCH=wip/042/architect` ДОСЛОВНО, `--nnn 19` → `BRANCH=wip/019/…`. Повторный спавн
того же номера → rc 1 «уже существует» (существующее поведение сохраняется).
