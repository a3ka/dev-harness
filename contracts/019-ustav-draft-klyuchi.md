Источники: Н-72 (NABLIUDENIA.md) — решение владельца 2026-08-31 ~13:30 вариант (б) +
расширение ~14:00 (единый гейт на два класса законных коммитов); живая находка обкатки
среза 2 контракта 018 (2026-09-01): `spawn_agent.sh:122` падает на `--nnn 019`.
Прецеденты боли: текст 018 коммитил владелец с пометкой «Н-72» (534507b); контракт-файл
017 сажал владелец-канал с авторством «Alex K» (0e6b5f7).

**ЗАКРЫВАЕТ Н-72.** Цена (измерена): один отбитый коммит устава + каждый новый контракт
сериализуется на вручную коммитящего владельца; цена растёт с каждым контрактом.

## Предмет

Три ветви; 1 и 2 живут в одном цикле `scripts/check_staged.sh`, ветвь 3 отдельна.

**Ветвь 1 — делегирование устава → check_charter (Н-72, решение (б); реализация (i)
«исключение+делегирование» — выбор архитектора по коду, предпочтение владельца).**
Staged-путь УСТАВНОГО класса у зонированного автора перестаёт судиться зонами и
делегируется уставному судье. Предикат уставного класса — ТА КОЛЬЦО области, что у
check_charter (единый источник, вторая реализация запрещена — прецедент lib_zones):

- `AGENTS.md`, `ROADMAP.md` — точное имя в корне, при живом теге `ustav/1`;
- `plans/NNN-*.md`, `contracts/NNN-*.md` — разбор `parse_artifact_basename` (rc 0),
  при живом теге первой заморозки `refs/tags/frozen/{plans,contracts}/NNN/1`.

Репо без соответствующего тега → путь НЕ уставного класса → прежний зонный суд (новой
ветки без наблюдаемого входа не заводится, Н-39). Делегирование: `check_staged`
запускает `check_charter <ROOT>` (судья — из своего SELF_DIR, не из предмета) и
наследует rc И вывод: rc 0 → путь пропущен (ок-строки check_charter с числом
просмотренных проходят наверх — зелёное называется, шапка check_charter:184-189);
любой ненулевой rc → отказ rc 1 с наследованным текстом (именованные причины
«изменён без разрешения владельца», «не назвала путь», «без причины» — единый
источник грамматики razreshil() в check_charter.sh). Свидетель `judged: <путь>`
сохраняется (со-локализация F-4: напечатано ⟺ судимо).

**ИЗМЕРЕННАЯ ГРАНИЦА (названа прямо, прогон 2026-09-01):** pre-commit НЕ видит тела
коммитящегося коммита — `COMMIT_EDITMSG` отсутствует на входе хука при `git commit
-m`. Поэтому ключ РАЗРЕШИЛ ТЕКУЩЕГО коммита судится check_charter ПО ИСТОРИИ: CI
`check:charter` (уже в проводке, ci.yml:154) краснеет на запушенном нарушении, и
каждое следующее делегирование при staged уставного пути отказывает на нём же.
Блок ДО создания коммита невозможен без нового хука (commit-msg) — вне предмета
(Не-цели). Норма строки не меняется: строку пишет владелец либо сессия по его прямому
слову (правило 11); механика лишь перестаёт отбивать легальный коммит до создания.

**Ветвь 2 — draft-контракт следующего номера → автор architect (Н-72, расширение).**
Staged-путь `contracts/<NNN>-<slug>.md` (разбор rc 0), где NNN — СЛЕДУЮЩИЙ свободный
номер класса CONTRACT, И автор РОВНО `architect` → путь пропущен (не судится зонами):
зоны нового контракта живут в его собственном файле и неактивны до заморозки
(самоссылка), авторство пачки — architect. Следующий свободный номер читается
БЕЗОПАСНО ДЛЯ ПРЕДМЕТА: новая библиотечная функция `next_id_peek <корень> <класс>` в
`next_id.sh` (импорт по образцу NEXT_ID_LIB) — те же четыре источника max+1 (теги
`id/CONTRACT/*`, имена ссылок, HEAD, история), НО без создания тега-резерва: резервация
— побочный эффект ВЫДАЧИ, судья не занимает номера и не меняет предмет. Peek судит по
тегам/веткам/HEAD/истории, НЕ по индексу: staged draft — сам себе следующий номер.
Всё иное — чужой автор на draft-пути, не-следующий номер, иное расширение — прежний
зонный суд (отказ «вне зоны» и до, и после 019). Планы plans/ в draft-пуск не входят.

**Ветвь 3 — octal-фикс спавна (живая находка обкатки 018-среза-2).**
`spawn_agent.sh:122`: `printf '%03d' "$nnn"` падает на `--nnn 019` (ведущий ноль =
invalid octal, rc 1, спавн мёртв до создания ветки). Фикс по образцу строки 117:
`nnn_padded="$(printf '%03d' "$((10#$nnn))")"`. На диске основного дерева лежит
незакоммиченный локальный фикс этой же формы — 019 фиксирует его первым
пост-заморозочным коммитом (прецедент 5f5446e). Двунаправленность паддинга
сохраняется: `--nnn 042` → `wip/042/…`, `--nnn 19` → `wip/019/…`.

**Порядок ветвей в главном цикле check_staged:** грамматика имени (как была) →
уставной класс (делегирование) → draft next-id (architect) → зоны (как было).

## Не-цели

- Commit-msg хук (блок устава ДО создания коммита) — отдельный предмет: новая проводка
  хуков + правка check_hooks; названный остаток И-границы.
- Draft-пуск plans/, VERDICT, ADR — вне (потребность не измерена).
- Норма строки РАЗРЕШИЛ (правило 11), роли, ROADMAP — устав, владелец-канал.
- Раннер verify_antiplacebo, multi-NNN/§10, omp-btrfs — вне.

## Незаполненные требования

- Точная ok-строка делегированного пути (лгать «в зоне автора» нельзя; формулировка —
  деталь реализации, свидетель `judged:` обязателен).
- Место предиката уставного класса: библиотечный импорт из check_charter.sh либо
  отдельная библиотека — деталь; контракт пинует единый источник и запрет второй
  реализации.
- Делегирование один раз на коммит при нескольких уставных staged-путях — деталь.
- Текст отказа draft-ветки чужому автору: наследуется действующий зонный «вне зоны».
