## Предмет

Слово владельца (§9.3 от 2026-10-03; заметка — слово 2026-10-06, передано консультантом): push в
main без кода (verdicts/, HANDOFF.md, NABLIUDENIA*, docs/, строки registry/) → лёгкое задание
(устав, зоны, ids, protected, грамматика 015 — инкрементально, ≤ 2 мин); код в main — только через
PR; хеш кодового дерева (дерево без учётных путей) — check_ci_gate (4б) и ворота принимают зелёный
результат с тем же хешем; приёмка — отменённых тяжёлых ≈ 0 в неделю, учётный push проверяется
≤ 2 мин; заметка — общие самотесты из каждой lane в одну джобу, веса реестра по замерам.

Один результат — ноль выброшенных тяжёлых прогонов — проводится через пять частей:
1. **Хеш кодового дерева и класс изменения** — `scripts/ci_klass.sh hash|klass`, строки `uchet`.
2. **Доказательство тяжёлого прогона по хешу** — артефакт `tyazhelyj-<H>`; `dokaz`, `reshenie`,
   `strip` того же скрипта.
3. **Проводка CI** — джобы klass, legkij, vorota, obshchij, tyazhelyj-itog; тяжёлые джобы условны и
   исполняются на дереве без учётных путей; отмены concurrency нет.
4. **Ворота** — check_ci_gate (4б) и чек 5 предполёта gitw принимают тяжёлое по кодовому хешу;
   push кода без доказательства — отказ «код в main только через PR».
5. **Веса по замерам** — строки замера `run_ci_lane.sh`, инструмент `scripts/ci_vesa.sh`.

## Frontier

- Хранилище доказательства. (а) actions/cache по ключу H — кеш PR-прогона невидим push-прогону
  main: приземление перезапускало бы тяжёлое — отвергнуто. (б) Обход предков с равным H по
  check-runs — запрос на коммит, лимит 60/ч без токена — отвергнуто. (в) **Выбрано:** артефакт
  `tyazhelyj-<H>` джобы tyazhelyj-itog; один запрос списка артефактов по имени на весь репозиторий;
  имя — индекс, не доверие: H(head_sha) пересчитывается локально.
- Формула хеша: id git-дерева через временный индекс (пишет объекты) против sha256 фильтрованного
  `ls-tree -r -z` (чистое чтение) — выбрано второе.
- Честность «результата по хешу»: тяжёлые шаги исполняются на рабочем дереве без учётных путей
  (strip) — вердикт тяжёлого есть функция кодового дерева по построению; шаг, читающий учётный
  путь, обнаруживается красным тяжёлым и переносится в legkij. Список «доверенных» шагов отвергнут.
- Состав U: список владельца плюс forks/ и .review/ (записи консультанта и ревьюера) и ROADMAP.md
  (блок плана генерируется из строк registry/plan.tsv — учётного источника, 084). contracts/, plans/,
  AGENTS.md, roles/, .omp/ — код: их читают тяжёлые шаги (spec-ready-036, precision-gate-043, skills,
  ceilings, gen); правки — через PR, процедура прямого коммита уставных правок (Н-186) для них
  заменяется FF-ландом PR.

## Инварианты

1. **И-1 Учётные пути и хеш.** U — строки `uchet<TAB><значение>` реестра `registry/ci-steps.tsv`.
   Значение: каталог `<сег>/…/` (покрывает пути с этим префиксом), точный путь `<сег>/…/<сег>`,
   корневой префикс `[A-Z][A-Z0-9_]{3,}*` (только файлы корня без «/»); сегмент `[A-Za-z0-9._-]+`,
   кроме `.` и `..`. Строка, чьё первое слово `uchet`, вне грамматики (пробел вместо TAB, CR, пусто,
   `//`, ведущий `/`) — отказ rc 1 с именем реестра; значение, покрывающее `registry/ci-steps.tsv`,
   `scripts/ci_klass.sh` или `.github/workflows/ci.yml`, — отказ rc 1. U контракта (как множество):
   verdicts/, docs/, forks/, .review/, HANDOFF.md, ROADMAP.md, NABLIUDENIA*, registry/contracts.tsv,
   registry/closed-without-done.tsv, registry/plan.tsv. H(c) — sha256 (64 hex) потока, где по
   порядку `git ls-tree -r -z --full-tree c` идёт каждая запись `<режим> <тип> <объект>\t<путь>\0`,
   чей путь не покрыт U(c). Реестр — код: его правка меняет H. `ci_klass.sh hash <rev>` печатает H;
   `klass <old> <new>` печатает `uchet` при равных H по U(old), иначе `kod`.
2. **И-2 Реестр (дельта 083 И-1).** Новые виды строк: `uchet` (И-1) и `legkij` — поля через TAB:
   вид, ключ, вес, команда (грамматика ключа, веса и команды — как у step 083). Ключи уникальны по
   step ∪ legkij; `run_ci_lane.sh` исполняет ключи обоих видов; ключи legkij ⊇ {check:charter,
   check:zones, check:ids, check:protected — командами `--incr` 083, check:nabludenia,
   check:contract-frozen} и не входят в lane-матрицу.
3. **И-3 Доказательство.** `dokaz <rev>`: один запрос списка артефактов
   `GET <API>/actions/artifacts?name=tyazhelyj-<H>&per_page=100`; доказательство — элемент списка
   (любой позиции) с name, литерально равным
   `tyazhelyj-<H>`, `expired == false`, `workflow_run.repository_id == head_repository_id`, head_sha
   из 40 hex, коммит есть локально и H по U(rev) от head_sha равен H. Найдено — stdout
   `dokaz <head_sha>`, rc 0; нет — rc 1, stdout пуст; отказ curl или не JSON — rc 2. База API —
   `CI_KLASS_API`, иначе `GITHUB_REPOSITORY` (+`GITHUB_API_URL`), иначе origin github-формы;
   `GITHUB_TOKEN`, если задан, — заголовком.
4. **И-4 Ворота.** `vorota <old> <new>`: на old нет строк uchet — rc 0 «неприменим» (переход и
   деревья без реестра); `uchet` — rc 0 без запроса к API; `kod` и `dokaz new` rc 0 — rc 0; `kod`
   без доказательства — rc 1, stderr несёт фразу «код в main только через PR»; отказ API на `kod` —
   rc 2.
5. **И-5 Предполёт gitw.** `scripts/gitw_preflight_071.sh` несёт чек 5 — `ci_klass.sh vorota
   <вершина main цели> <отправляемый tip>` после чека (3) и до чека (1); rc ≠ 0 — отказ
   «gitw ПРЕДПОЛЁТ-ОТКАЗ: …» с фразой И-4, обмен не идёт; вершина main цели не в локальной
   истории — отказ с «сделай fetch». Чеки 071 (1)–(4) не меняются.
6. **И-6 check_ci_gate (4б).** Шаги 1–3 прежние. Без skipped среди чек-ранов sha — прежнее правило
   (все success). При ≥ 1 skipped: чек-ран вне {success, skipped} — отказ; чек-раны `legkij` и

   «тяжёл…», rc 2 — отказ «CI не ответил».
7. **И-7 strip и reshenie.** `strip <H>` до удаления сверяет H(HEAD) == `<H>` (иначе rc 1

8. **И-8 Проводка ci.yml** (формы литеральны — грамматика клеток К батареи): джобы klass, legkij,

   `npm run check:ci-parity` и сам-тесты раннера анти-плацебо — только в не-матричной obshchij;

9. **И-9 Замеры и веса.** `run_ci_lane.sh` после каждого исполненного ключа печатает отдельной

## Демаркация контрпримеров

Конформные входы: деревья git с путями любых байтов, кроме NUL (TAB и перевод строки внутри имени
допустимы); реестр по грамматике И-1/И-2 и 083; ответ API — JSON схемы GitHub (artifacts[].name,
.expired, .workflow_run.{repository_id, head_repository_id, head_sha}; check_runs[].{name,
conclusion}) с любым порядком и числом элементов в пределах страницы; ci.yml блочного стиля без якорей,
алиасов и flow-отображений, со скалярами шагов И-8 в одну строку. Валидный контрпример — реализация,
зелёная на всех клетках батареи и расходящаяся с инвариантом на ДРУГОМ конформном входе
(инвариантность к значениям путей, хешей, порядков и имён в пределах грамматики). Вход вне
грамматики (строка uchet с пробелом, JSON вне схемы, ci.yml с якорями) контрпримером не является:
на нём обязателен именованный отказ, а не конкретный вердикт.

## Модель угроз

Разбираемый чужой ввод: строки uchet реестра, пути дерева из `git ls-tree`, JSON артефактов и
check-runs GitHub API, строки замера в логах прогонов.

ЗАЩИЩАЕТ:
- пропуск тяжёлого прогона для кода, выданного за учётное: граница U сверяется литерально и по сегментам, точка — литерал, каталог — с «/», корневой префикс не проходит сквозь «/»;
- подложное доказательство: имя артефакта не принимается на веру — хеш дерева head_sha пересчитывается локально, истёкший и форк-артефакт не засчитываются, имя сверяется литерально;
- тихое ослабление классификатора через реестр: правка U меняет хеш и сама требует PR, значение, покрывающее реестр, скрипт классификатора или workflow, отвергается;
- тяжёлый вердикт, зависящий от учётных путей: тяжёлые шаги исполняются на дереве без учётных путей, несовпадение хеша рабочего дерева — отказ до удаления;
- код в main мимо PR: предполёт gitw и джоба vorota отвергают push, чей кодовый хеш не доказан тяжёлым прогоном, учётный push от API не зависит;
- потерю данных разбора: последняя строка реестра без перевода строки, доказательство последним элементом списка и TAB или перевод строки в имени пути не теряются молча.

НЕ ЗАЩИЩАЕТ:
- подделку артефакта или чек-рана участником с правом записи в репозиторий и workflow — доверенная граница контракта;
- устаревание тяжёлого вердикта по причинам вне кодового дерева: сеть, образ раннера, теги и история git, читаемые тяжёлыми шагами, — ловец следующий кодовый PR и CI-В;
- чтение учётного содержимого тяжёлым шагом через объекты git (`git show HEAD:<учётный путь>`) в обход strip — ловец ревьюер;
- пропуск доказательства при списке артефактов длиннее одной страницы на сто элементов — деградация скорости, не корректности.
