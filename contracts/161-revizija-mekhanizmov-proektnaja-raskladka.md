## Предмет и инварианты

1. Корень предмета определяется корнем project git-worktree и профилем этого проекта, а не `HARNESS_PROJECT_LAYER_ROOT` основной сессии; профильный `workflowPaths` через действующий resolver един для `done_contract`, `pre_critic`, `make_task`, `spawn_agent`, freeze/тега/паузы. При противоречивом layer-root — именованный отказ либо нормализация к layer-root ТОГО ЖЕ проекта, не чужая зона. Настоящий worktree с `-c user.name=architect` и пустым file-config проходит, неверный автор не проходит. На станции прежняя раскладка остаётся зелёной.
2. Цикл проекта: номер резервируется в проекте; task pack собирается из профильного контекста проекта с обязательными секциями MAP/RULES/REUSE/ZONES и записями реальных файлов; манифест становится доступным spawn_agent ДО создания worktree, без коммита временного черновика в main и без записи в основной чекаут (допустим внешний state). Отсутствие любой строки профиля, включая optional, — именованный отказ с путём. Spawn рабочего агента без пакета И манифеста — отказ ДО worktree; владелец hook-пути 157, в 161 только дверь/интеграция с 157. Контекст агенту экрана, стартующему со станции, принадлежит ЦЕЛЕВОМУ проекту; подмена AGENTS.md станции проектному — отказ.
3. Паритет каждого конформного CI шага решается из его working-directory и эффективного package.json, а не из корня по умолчанию; отсутствие корневого package.json не означает пропуск обязательства. Оpaque команды (`$(...)`, heredoc, backticks) выносятся владельцем CI проекта в прозрачные исполняемые скрипты (163 моб; бэкенд — своя сессия), не исполняются парсером; после прозрачного cutover `verify_ci_parity.sh`, `check_precision_gate.sh`, `pre_critic.sh` на мобильной раскладке дают rc 0. Проверка продолжает отвергать непокрытый шаг и лишний ключ; корневой делегатор запрещён как условие успешного контроля.
4. Временная льгота долга PR #503 (если присутствует на интеграционной базе) и `.harness/registry/ci_parity_debt.txt` моба удаляются после зелёного паритета по сути, НЕ ПОЗЖЕ 2026-11-18. После этой даты никакой долг не делает красную проверку зелёной. Снятие файла проекта — в проектном владении 163, не правка чужого репо исполнителем 161. Миграция батарей, читающих `mobile.yml`, — только v+1 с вердиктом и разрешением владельца на пересечение.
5. Служебное состояние подключения/контекста порождается в согласованном проектном state или явно отслеживаемом проектном файле без загрязнения главного дерева перед mint; существующие непустые состояние/пины/трасса сохраняются; секретный `.env` не оказывается в индексе. `.omp/` проектного рантайма игнорируется/не загрязняет main и при этом обязательный пакет остаётся проверяем до spawn; `land_agent` реально принимает чистое дерево и отказывает грязному.
6. Развёрнутый оверлей моделей именуется по идентичности проекта/сессии в каталоге вне чужого проекта: две одновременно открытые сессии моба и бэкенда не пишут один файл; изменение одного не меняет байты оверлея другого. Профиль харнеса ссылается только на существующие файлы; краткое адресное руководство `ARCHITECTURE.md` поставляется отдельным owner-коммитом по слову владельца/консультанта, не этим коммитом architect (bootstrap `check_staged` не допускает этот путь). Исправления шаблона требуют КОНТЕКСТ, ПРЕДПОСЫЛКИ в ПРОВОДКА при CI-изменении и конкретные пути ЗОНА orchestrator.
7. PR #500/#504/#509 сохранены в парной проверке: на проекте `.harness/contracts` класс риска замка читается, запись в `.harness/registry/pauzy.tsv` переводит не-паузный 148 в паузу, tag frozen после текста/вердиктов уходит штатно; на станции корневые контракты и пауза 097 ведут себя как прежде. Запись учёта проекта идёт в проектный state/агрегатор и реально видна учёту SLOVO, не считается увиденной по одному отсутствию файла в харнесе.
