# Контракт 004 — потолки документов скилом, а не советом

Номер выдан механизмом: `next_id.sh CONTRACT` → 004, тег `id/CONTRACT/004`. Предмет —
остаток шага 6 ROADMAP: «скил письма проверяет потолки скриптом, а не советом» и
«grill-me не пускает к спеке, пока незаполненное требование не названо».

## Предмет

Шаг 6 роадмапа наполовину исполнен майлстоином 003 (четыре адаптации лежат, роли несут
указатели). Остаток — два предмета:

1. **Числовые потолки длины — текстом скила И барьером.** У источника (Мэтт) ноль
   ограничений длины; наша норма, ЧИСЛОМ В БАЙТАХ (арбитраж `potolki-granica-pokrytie`):
   **персона ≤ 51200 байт, файл-правило ≤ 30720 байт** (30/50 КиБ по роадмапу; иные
   значения — воля владельца, счётчик байтов — норма). «Персона» — каждый файл `roles/`.
   «Файл-правило» — `AGENTS.md` и каждый файл `.omp/rules/`. СЧЁТЧИК — байты (`wc -c`),
   не символы: замер арбитража воспроизвёл `roles/critic.md` — 16919 байт против 9864
   символов (кириллица 1.7×). Потолки вписываются в шапку-адаптацию
   `skills/writing-for-agents` (строка «Потолки: …») и держатся барьером
   `scripts/check_ceilings.sh`: превышение → код 1 с именем файла и фактом.
   Замер на 2026-08-19: крупнейшая персона — `roles/critic.md`, 16919 байт; всё зелёное
   до правки (барьер создаётся КРАСНЫМ против раздутого файла).
2. **Гриль перед спекой — процедурно.** `grill-me` не пускает к спеке, пока
   незаполненное требование не названо. Семантика «незаполненности» механизмом не
   измеряется — гейт формальный: ОБЛАСТЬ механическая — каждый НЕЗАМОРОЖЕННЫЙ черновик
   `contracts/NNN-*.md` (нет тега `frozen/contracts/<NNN>/*`) обязан нести раздел
   «Незаполненные требования:»; ГРАММАТИКА ТЕЛА механическая (арбитраж): без пустых
   строк — либо ровно слово `нет`, либо непусто и КАЖДАЯ строка начинается с `- `;
   отсутствует, пуст, либо иное тело → код 1 с именем файла. Замороженные контракты
   вне суда: их текст неизменен побайтово. Честность содержания списка —
   `cognitive-only`, ловец критик.

## Критерий готовности

1. `bash scripts/check_ceilings.sh` → 0. КРИТЕРИЙ НЕСЁТ СВОЙСТВА МАТРИЦЫ вход→код, а не
   перечень исходов (арбитраж `potolki-granica-pokrytie`: злонамеренный барьер
   `wc -m` с избирательными порогами прошёл семь поимённых фикстур буквы и провалил
   семь проб предмета). Обязательные свойства матрицы, фикстуры в
   `fixtures/check_ceilings/`:
   - пара «РОВНО потолок → 0, потолок+1 байт → 1» в КАЖДОЙ ветви: `roles/`,
     `AGENTS.md`, `.omp/rules/` — шесть граничных исходов (пара зажимает `≤`);
   - различающая КИРИЛЛИЧЕСКАЯ фикстура: символов меньше потолка, байтов больше → 1
     (ловит `wc -m`);
   - НЕЗАВИСИМОСТЬ ОТ ИМЁН: красная проба каждого класса с именем, ПОРОЖДАЕМЫМ фикстурой
     при каждом прогоне (случайный компонент); фиксированные «неочевидные» имена
     запрещены (ловит барьер, зашитый на известные пути);
   - раздел «Незаполненные требования:» — ПОЛНАЯ матрица исходов: тело «нет» → 0;
     валидный список (каждая строка `- …`) → 0; отсутствует → 1; пустое тело → 1;
     тело вне грамматики → 1;
   - зелёная проба ЗАМОРОЖЕННОГО контракта с телом вне новой грамматики → 0: барьер
     обязан читать теги `frozen/contracts/<NNN>/*`, а не исключать известные номера —
     фикстура ставит ПОДСТАВНОЙ замороженный тег в своём дереве;
   - красное: черновик без раздела → 1; раздел с телом вне грамматики (например,
     произвольная строка) → 1.
2. Шапка `skills/writing-for-agents` несёт строку потолков; ЗЕРКАЛО
   `.agents/skills/writing-for-agents/` синхронно (вечной обязанностью держит ветвь (д)
   контракта 003 — правка скила без зеркала красит `check:skills`).
3. `npm run check:antiplacebo` → 0; `check:ci-parity` с новым `check:ceilings` в CI;
   `check:gen`, `check:zones`, `check:contract-frozen` → 0.
