# Контракт 218 — окно PR-проверок `check:contract-frozen` / `check_charter` судит коммиты ВЕТКИ PR (от merge-base с main), а не чужие merge main и не ветку позади main

СТАТУС: ЧЕРНОВИК-ЗАТРАВКА (bootstrap: `make_task --role architect` требует существующий `contracts/218-*.md`; текст контракта пишет architect по заданию станции — затравка не является ни спекой, ни критерием; заменяется целиком).

Цена: ≈15 пересборок носителей и ≈10 повторных CI-прогонов за сутки; каждый влив ломает остальные открытые PR (Д4/окно); синхронизации main→wip запрещены (167).
Измерено 24.11 (owner-PR, `gh pr list --search "owner in:title"`): 1–22.11 — 0–3 закрытых-без-влива в сутки; 23.11 — 6; 24.11 — 15 закрытых при 5 влитых (модели судей #1336→#1352→#1357→пачка #1362, затравка 219 #1335→#1353→#1358). Причина в каждом закрытии — «пересборка на main без merge-синхронизации (окно check_charter)»: `update-branch` вносит merge-коммит main в ветку, и `check:charter` на PR судит коммиты main (24.11 21:50, run 45488202769: FAIL по 1fb51dc3, c25196f6, 78579513, 71384784, a1654418, 11e4aaad, 1c2d1c1e, ef7ce55f, 3e8db265, 90365f10 — все коммиты main, не PR).

## Решение
Кодовый контракт: окно PR-проверки = коммиты ВЕТКИ PR относительно merge-base с main (как `check_zones --incr` по 207 «один суд окна»), а не first-parent цепочка merge-ref; контракты/теги, не затронутые изменениями ветки, в окно не входят; для `push` в main окно прежнее. Реши: (а) определение окна в `check:contract-frozen` и `check_charter` (merge-base против `origin/main`, `pull_request` vs `push` — по событию CI/аргументу); (б) защита от сужения (подмена базы; ветка, меняющая frozen-контракт задним числом, не должна уходить из окна при чужом merge main; «неизвестность ≠ чисто»); (в) связь с 200 (окно заморозки), 207 (check_zones incr), 195 (потребители 116, окно PR-слияний), 210 (публикация frozen), 217 (`--incr` пустого окна), 071 (предполёт gitw push main), 167 (merge main→wip запрещён) — окно должно делать синхронизацию/пересборку ненужной; (г) Д4/sync-door консультанта.
