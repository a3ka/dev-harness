# Контракт 071 — предполёт gitw push в main: именованные отказы ДО отправки

## Предмет

Боль дня 2026-10-01, измерена владельцем: **4+ потерянных CI-прогона** (грамматика
015 ×3, parity ×2, ceilings от задержанного frozen-тега) — все пушатся в main и
красятся уже НА GitHub, где rerun недоступен (403 без Actions:write), а новый
законный прогон = следующий пуш. Трижды пуш проходил при красном pre-check из-за
`;`-цепочек (самонарушение дня, HANDOFF день-3). До сих пор все предполётные чеки
— руками по чеклисту; руки ошибаются, Prologue-дисциплина «строгие &&-цепочки»
не механизм.

Предмет — крюк предполёта в scripts/gitw: любой push, покрывающий refs/heads/main
на канонической цели, ДО исполнения обмена проходит четыре именованных отказа
(слово владельца 2026-10-01 дословно):

1. **чеки дерева**: check:nabludenia, check:ci-parity, check:ceilings, check:ids
   на ОТПРАВЛЯЕМОМ дереве (~3 с; живой замер пачки на полном дереве: 2.8 с);
2. **локальные frozen/*|done/* теги** обязаны быть на origin тем же объектом
   (боль: задержанный frozen-тег красит ceilings уже на CI);
3. **каждый merge «land: wip/<NNN>/<автор>»** в отправляемом диапазоне — второй
   родитель обязан иметь зелёный прогон CI event=pull_request conclusion=success
   (норма 069: слияние только после зелёного PR);
4. **worktree**-кладбище: кроме основного worktree разрешены только ветки
   wip/<NNN>/<автор> под ${TMPDIR:-/tmp}/dev-harness-worktrees/<hash8>/
   (hash8 = 8 hex); прочие — именованный отказ с путём и веткой.

Каждый отказ — rc 1 ДО отправки, получатель не тронут; все мёртвые ветви
(сеть, npm, API) — тоже отказ (fail-closed), не пропуск.

Класс задачи: КОДОВЫЙ (поведение scripts/gitw судится прогонами; проза роли
ролью не трогается — roles/ в зоне 072).

## Инварианты

1. **Крюк**: push с покрытием refs/heads/main на канонической цели → предполёт
   ДО exec; rc 1 «gitw ПРЕДПОЛЁТ-ОТКАЗ: <именованная причина>», получатель не
   двинут; успех и каждый пропуск (пуши не-main, дерево без чек-ключей)
   печатаются именованной строкой «gitw ПРЕДПОЛЁТ: …» — молчания нет; push
   без покрытия — обмен прозрачен, семантика 045 неизменна.
2. **Грамматика покрытия main**: refspec с dst == main|refs/heads/main (включая
   удаление `:main`, `HEAD:main`, `src:main`); --all|--mirror; отсутствие
   refspec при текущей ветке main. Refspec с глобом (*) или неразбираемый
   флаг push → именованный отказ (fail-closed: несудимое покрытие = запрет).
3. **Чек (1)**: четыре npm-ключа исполняются на ОТПРАВЛЯЕМОМ дереве —
   временный detached worktree на tip отправляемого src под
   ${TMPDIR:-/tmp}/dev-harness-worktrees/<hash8>/, удаление до exec (порядок:
   worktree-чек (4) исполняется раньше создания собственного). rc≠0 любого
   чека → отказ с именем ключа и хвостом вывода чека. Дерево с 1–3 ключами из
   четырёх → отказ «чек-ключи не полностью»; 0 ключей → именованная строка
   пропуска (молчание запрещено), обмен продолжается. npm отсутствует →
   отказ «чек-раннер недоступен».
4. **Чек (2)**: каждый локальный тег frozen/*|done/* обязан существовать на
   цели обмена тем же объектом; отсутствует или иной sha → отказ с именем
   тега и обоими sha. ls-remote --tags не прошёл → отказ (сеть — не санкция).
5. **Чек (3)**: каждый merge subject «land: wip/<NNN>/<автор>» в диапазоне
   (вершина main на цели ls-remote … отправляемый tip): второй родитель
   обязан иметь ≥1 прогон event=pull_request, conclusion=success (GitHub API);
   прогонов нет / не success / API недоступен / цель не github без ручки →
   отказ с именем ветки и sha. Subject «land: …» вне грамматики
   wip/[0-9]{3}/ → отказ «land-субъект не разбирается».
6. **Чек (4)**: git worktree list --porcelain репозитория вызова: разрешены
   основной worktree и worktree ветки refs/heads/wip/<NNN>/<автор> под
   ${TMPDIR:-/tmp}/dev-harness-worktrees/<hash8>/; прочие → отказ с путём
   и веткой (detached называется detached).
7. **Порядок**: (4) → (2) → (3) → (1), всё до exec; собственный временный
   worktree создаётся после (4), удаляется до exec (остаток на упавшем
   cleanup именован следующим пушем — остаточный риск).
8. **Ровно одна ручка тестов**: GITW_PREFLIGHT_071_API — полный base API
   включая owner/repo (фикстуры направляют её на локальный стаб-сервер);
   без ручки: https://api.github.com + repo из эффективной цели (конвенция
   check_ci_gate:56-62). Никаких других обходных ручек нет.
9. **Неослабление 045**: предполёт после И-5/И-7; отказы 045 (канон/живость)
   первичны; fetch/pull предполёта не несут.

## Модель угроз

ЗАЩИЩАЕТ:
- пуш красного дерева (1): каждый из четырёх чеков — своя ветвь отказа с
  именем ключа; стабы s1/s2/s10 умирают на своих клетках;
- задержанный/переписанный frozen|done тег (2): отсутствует на цели или иной
  sha → отказ ДО отправки; стабы s3/s4;
- land без зелёного PR (3): нет прогона, не-success, мёртвый API, не-github
  цель без ручки → отказ; стабы s5/s6/s7;
- мусорный worktree (4): путь+ветка названы; стабы s8;
- «;»-цепочки и забытый чеклист: отказ механический, до exec;
- деградацию чек-ключей в дереве: 1–3 из 4 → отказ «не полностью»;
- разбор refspec: глоб/неизвестный флаг → fail-closed отказ (стаб s9 —
  только литерал «main» — умирает на полной форме refs/heads/main).

НЕ ЗАЩИЩАЕТ:

- злонамеренный оператор: правка scripts/gitw, подмена env-ручек, удаление
  package.json из дерева (0 ключей = именованный пропуск) — вне угрозы
  «руки ошиблись»; ловец — check_zones/check_charter/CI пост-фактум;
- push.default=upstream/matching, загоняющий main без явного refspec при
  чужой текущей ветке — грамматика крюка судит явные refspec/--all и текущую
  ветку main; остаток назван, ловец — дисциплина роли;
- теги вне пространств frozen/*|done/* (id/*, иные) — вне слова владельца;
- push НЕ в main (ветки, теги): предполёт не несётся — 045-семантика;
- зелёность PR-прогона по ЧУЖОМУ коммиту (подмена head_sha невозможна —
  спрашивается sha второго родителя из истории самого репо).

четыре npm-ключа дословно из package.json); конформный refspec — по
git-push(1) (src[:dst], dst main|refs/heads/main); конформные теги —
refs/tags/(frozen|done)/** с sha из toy-истории; конформный worktree — ветка
wip/[0-9]{3}/[^/]+ под /dev-harness-worktrees/[0-9a-f]{8}/. Значения (имена
веток, sha, порты) случайны на прогон — инвариантность к значениям: стаб с
зашитым литералом пройти клетку не может. Валидный контрпример =
инвариантность к значениям ∧ расхождение честного и стаба на конформном входе.

  «dev-harness-worktrees…» вне корня → rc 1 (стаб s8 умирает).
- **А7 (сценарий; свойство: грамматика покрытия и мёртвые ветви).** дано:
  `push origin refs/heads/main` при мусорном worktree → rc 1 (стаб s9 —
  только литерал main — умирает); `push origin main:refs/heads/wip/x` → rc 0
  и строк ПРЕДПОЛЁТ нет; refspec с глобом → rc 1 «refspec не разбирается»;
  npm вне PATH → rc 1 «чек-раннер недоступен: npm» (symlink-ферма); дерево с
  2 ключами из 4 → rc 1 «чек-ключи не полностью».
- **А8 (правило; свойство: пачка архитектора на своих гейтах).** дано:
  дерево пачки; когда: npm run check:ceilings, check:ids, check:ci-parity,
  check:nabludenia; тогда: все rc 0 (контракт — черновик с разделом
  «Незаполненные требования», npm-ключей/шагов пачка не добавляет, А-запись
  несёт адрес).

## Остаточный риск (назван прямо)

- push.default=upstream/matching может загнать main без явного refspec при
  чужой текущей ветке — крюк судит явные refspec/--all/--mirror и текущую
  ветку main; ловец — дисциплина роли (строгие команды пуша), механизм
  очередь живого укуса.
- Упавший cleanup временного worktree оставляет каталог под санкционированным
  корнем с detached-веткой — следующий push откажет именованно (ветка не
  wip) и назовёт путь; авто-чистка не заводится (tmp-reap по возрасту).
- 0 ключей check:* в дереве = именованный пропуск (045-toy-миры); злонамеренно
  деградировавшее дерево предполёт не судит — ловец check_zones/CI.
- Ручка GITW_PREFLIGHT_071_API — тестовый шов: оператор, подменивший её на
  свой «зелёный» сервер, обходит чек (3); вне угрозы «руки ошиблись», ловец —
  владелец (та же цена, что у GIT_EXCHANGE_GUARD_CANONICAL, граница-4 из 045).
