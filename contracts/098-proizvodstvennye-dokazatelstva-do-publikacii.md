## Решения

1. **M доносится до CI нецелевой ссылкой**: обвязка публикует подготовленный merge под короткоживущим ref вида `refs/heads/cand/<object_id>` (gitw-канал 045, БЕЗ credential целевой ветки); CI исполняет полный применимый перечень на дереве этого ref; ref убирается после записи доказательств. Требование «sha на origin/main» из check-контура УДАЛЯЕТСЯ (замена, не наслаивание — Пять правил §2).
2. **check-писатель** (`check_ci_gate.sh <корень> <M-sha> --check-row <object_id> <ключ>`): сопоставление СТРУКТУРНОЕ — по ключу обязательной проверки из политики (per-name), запуск (run id) и дерево фиксируются полями строки; tree sha — литерально `M^{tree}`; wfsha — принятая версия определения, ДОКАЗАННАЯ прогоном: исполнитель прогона (поле app.slug ответа CI) сверяется литерально с пином `ciApp=` принятой политики, sha256 ИСПОЛНЕННОГО определения (поле wfsha ответа CI) — с sha256 принятого файла определения; отбор — последний одноимённый прогон на M, неподходящее происхождение — именованный отказ («проверка чужой обвязки: <имя>» / «проверка не доверенной версии: <имя>»), не перебор до подходящего; локально вычисленный хеш источником строки не является. Частичный прогон ≠ вердикт (Н-204): непокрытый обязательный ключ — `fail` строки либо её отсутствие, не молчание.
3. **verdict-писатель** (`judge_gate.sh --verdict-row <задача> <object_id> <вердикт-файл>`): читает СОБЫТИЕ решения (первая строка вердикт-файла круга: accept|FAIL|ESCALATE), пишет строку `verdict` с object_id; зелёный CI не превращается в accept.
4. **policy-писатель — вызов и носитель названы** (совет критика :29): штатный вызов `judge_gate.sh <sha> --policy-row <object_id> <старая-policyVersion> <новая-policyVersion> <файл-санкции>`; носитель — `scripts/judge_gate.sh` (implementer-зона 008/098, новый скрипт не заводится); первая строка файла-санкции — событие `accept`, иначе именованный отказ rc 1; строка `policy` судейского канала, кандидат и ленд её не пишут. Клетка Б-1 ведёт эту строку штатным вызовом.
5. **Журнал вне проверяемой ветки**: `registry/candidates.tsv` на принятой стороне (чек-аут оркестратора), append-only; запись строки доказательства не меняет B/C/M (объект — git-объекты по sha).
6. **Репетиция публикации**: изолированная копия реального репозитория (`/tmp/dev-harness-verify/dokazatelstva-098-**`), полный контур object→prepare→писатели→publish; целевая ветка КОПИИ; credential публикации не задействованы.
