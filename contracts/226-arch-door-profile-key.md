СТАТУС: ЧЕРНОВИК-ЗАТРАВКА (bootstrap: `make_task --role architect` требует существующий `contracts/226-*.md`; текст контракта пишет architect по заданию станции — затравка не является ни спекой, ни критерием; заменяется целиком).

## Боль
Слово владельца R-0103 (25.11): «Л10: станция берёт новым номером сразу после done 203 — дверь архитектуры включается ключом профиля проекта вместо литерала Complior-back (часть Ш-5 hooks.archBrief); остальной Ш-5 — не сейчас». Норма владельца R-0102 (25.11): «хардкодить ничего не надо, все надо выносить в конфиги».

## Решение (рамка)
Кодовый контракт: включение двери архитектуры и репозиторий продукта — ключом профиля проекта (`harness.project.json`, образец ключа — Б-4 `pack.maxBytes`, М-0, контракт 203); нет ключа → дверь выключена (поведение для проектов без архитектуры не меняется). Критерий плана (`plans/ARH-RAB.md` Л10): игрушечный проект с иным repoId и пином — кодовое задание без `--arch-component` → rc 1 `ARCH_COMPONENT_NET`; `git grep -n 'Complior-back' main -- scripts/check_architecture_*.sh` вне комментариев → пусто; бэкенд после переключения ключа ведёт себя как сейчас (его профиль получает ключ тем же PR или отдельным PR бэкенда — решает architect по зонам). Остальные ключи Ш-5 (`ci.requiredChecks`, `hooks.judgeSetup`, вынос моб-UI) — НЕ брать.
