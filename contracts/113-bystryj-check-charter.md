## Рассмотренные варианты

- **(а) общий кеш `--incr` в `.git` (не в worktree) + инкремент от последнего проверенного
  коммита.** Не лечит СВЕЖИЙ worktree/clone (кеша нет — боль та же 28–35 мин); добавляет класс
  риска «протухший/чужой кеш» (частично закрыт ветвью (в′) lib_incr). Отклонён как основа.
- **(б) scoped pre-commit: судить только затронутые staged-пути.** Ломает инвариант: нарушение
  в другом уставном файле/старом коммите уходит из-под суда; эквивалентность для диапазона не
  доказуема дешевле самого полного обхода. Отклонён; класс лжи представлен стабом s6/s1.
- **(в) одиночный проход «коммит → пути» одним `git log --name-only` + матчинг против
  уставного множества + per-match проверка принадлежности диапазону (`merge-base
  --is-ancestor`) и `razreshil`.** O(коммиты + матчи) вместо O(пары × коммиты): 309 546
  diff-tree → 1 log + 170 матчей. Вердики эквивалентны ПОСТРОЕНИЕМ (тот же предикат на том же
  множестве: судится (f, c) ⟺ f жив в HEAD ∧ тег первой заморозки жив ∧ c достижим из HEAD ∧
  ¬(c предок-или-сам since) ∧ f ∈ charter_diff_paths(c) ∧ ¬razreshil(c, f)). **ВЫБРАН.**
- **(г) индекс «путь → коммиты» предвычислением.** Частный случай (в) с состоянием на диске —
  отказ: свежесть индекса = новый класс отказов; (в) не несёт состояния.

`--incr` сохраняется как есть (грамматика 083 не меняется, окно сужает проход — вердикт тот же
по построению 083; с (в) окно лишь ускоряет уже-секундный проход). `--oracle` = старый обход,
сохранён навсегда как эталон дифференциала (инструмент приёмки В2 и судов).

## Инварианты

1. Дифференциал: на любом дереве `--oracle` и умолчание дают ОДИНАКОВЫЙ вердикт — rc и
   сортированное множество строк `  ok `/`  FAIL ` (компаратор —
   `fixtures/ci_gen_083/diff_verdicts_083.sh`, переиспользование, не копия). Для `--incr`-окон —
   равенство rc и множества `  FAIL ` (счётчики диапазонов легитимно сужаются; прецедент
   нормализации — вердикт ревью 083, С-5).
2. Semantics матчей: `charter_diff_paths` по определению — дельта к первому родителю для merge
   (`--diff-merges=first-parent`), дельта к родителю для обычных, `--no-renames`,
   `--diff-filter=MD`. Корневые/добавления не судятся (статус A).
3. Диапазон: судится (f, c) ⟺ c достижим из HEAD ∧ ¬(c — предок-или-сам тега первой заморозки
   f) — направление аргументов `merge-base --is-ancestor` проверено живьём (инверсия ловится
   контролем честности s7/d8 батареи). В `--incr`-окне — зеркало lib_incr ПО ДОКУМЕНТУ:
   окно кеша подменяет since ТОЛЬКО тем документам, чей since — предок-или-сам кеша
   (since → INCR_BASE); кеш сторонней линии (в′) → полный проход. ГЛОБАЛЬНАЯ обрезка
   прохода кешем (`git log cache..HEAD` для всех документов сразу) ЗАПРЕЩЕНА: она не
   зеркало прежнего per-document диапазона — при боковой заморозке ПОСЛЕ кеша (тег
   первой заморозки не предок кеша; вливание merge с пустой дельтой к первому
   родителю) судимый диапазон документа остаётся `since..HEAD` и включает коммиты
   ДО кеша, в том числе сам коммит-кеш (обход круга 2 критика, корпус d9): быстрый
   режим обязан дать вердикт старого барьера на той же паре (кеш, дерево) при ЛЮБОЙ
   топологии кеш/тег/merge — эквивалентность по диапазону, не по счётчику. Проход
   «коммит → пути» строится по ВСЕЙ достижимой истории (0,07 с — замер Боли), кеш
   сужает только судимость матча. Грамматика кеша — из lib_incr без упрощений:
   повреждённый кеш (первая строка не sha) → rc 1, как у оригинала (совет критика
   круг 1: упрощённая грамматика каркаса её не наследует).
3а. Запись кеша (арбитраж круга 3, `verdicts/arbitration/contracts-113-gonka-kesha.md`):
   на rc 0 в кеш пишется ТОЛЬКО HEAD, зафиксированный до любого чтения истории
   прогона (`INCR_HEAD` из `incr_parse`), через `incr_finish` lib_incr; собственная
   запись кеша в быстром пути (перечитывание HEAD в конце) ЗАПРЕЩЕНА. Достоверность
   кеша: записанная отметка ≤ проверенный объём — после любого прогона следующий
   `--incr`-прогон даёт вердикт `--oracle` на том же дереве (rc и множество FAIL).
   Прецедент — И15 батареи 083 (`fixtures/ci_gen_083/red_ci_a_083.sh`).
4. Бюджет: умолчание на живом дереве при ХОЛОДНОМ старте ≤ 60 с — свежий ЛОКАЛЬНЫЙ КЛОН
   (свой git-каталог целиком: кеша нет НИ в worktree, НИ в `git rev-parse
   --git-common-dir`; worktree делит общий git-каталог с хозяином, и прогретый
   хозяином кеш маскирует холодную меру — обход круга 2 критика), rc равен
   записанному CI-зелёному (0), зелёное НЕМОЛЧАЛИВОЕ (ok-строки с числом
   просмотренного); прогретый повторный прогон — отдельная справочная метка
   клетки В, не критерий.
5. Барьер остаётся работоспособным в полном режиме без lib_incr (дриллы копируют его в
   $WORK/scripts/) — прецедент 083, инв. 6, не ломать.

## Модель угроз

ЗАЩИЩАЕТ:
- от пропуска нарушения устава: старый коммит вне окна, merge-дельта по первому родителю,
  откат (состояние ≠ история) — диф-клетки Д на герметичных корпусах сверяют умолчание
  с оракулом побайтово (компаратор 083);
- от потери чувствительности к структуре диффа: удаление и переименование уставного пути
  (корпуса d4/d5) и ложные красные на черновиках вне диапазона — строгая сверка множеств;
- от доверия чужому кешу: кеш сторонней линии (в′) уводит на полный проход, валидный кеш
  окна не меняет вердикта (диф-клетки d7/d8 + обманка s7);
- от молчаливо-зелёного прогона: пустая выборка — именованный отказ, зелёное обязано нести
  ok-строки с числом просмотренного (В-клетка + обманка s8);
- от тихого расхождения режимов: rc и сортированное множество строк `  ok `/`  FAIL `
  совпадают на любом дереве (инвариант 1, тот же компаратор);
- от регресса бюджета на холодном старте: В-клетка — 60 с на свежем ЛОКАЛЬНОМ КЛОНЕ
  живого дерева (кеша нет ни в worktree, ни в git-common-dir); кандидат, быстрый только
  при живом прогретом кеше, красен на холодной мере, прогретый повтор — метка;
- от подмены per-document окна глобальным: боковая заморозка ПОСЛЕ кеша (тег не предок
  кеша, merge с пустой дельтой к первому родителю) сохраняет документу диапазон
  `since..HEAD` с коммитами до кеша — сужение судимости кешем только per-document
  (диф-клетка d9; проверенный кеш сеется самим старым барьером в корпусе).
- от обгона кеша: «конкурентный коммит после снимка истории не попадает в кеш непроверенным»
  (диф-клетка гонки + стаб; формулировка арбитража круга 3 дословно);

НЕ ЗАЩИЩАЕТ:
- от подмены самого `scripts/check_charter.sh` в момент коммита (класс `--no-verify`,
  вне метода — прецедент границы канарейки check_staged 016);
- от одновременной лжи оракула и умолчания одним автором: обе половины живут в одном файле,
  ловится только судом замороженного main (cognitive-only остаток, тот же класс, что 019
  «подлинность строки при одном uid»);
- от выхода за пределы git-грамматики имён (control-символы уже запрещены самим git и
  `check_staged`);
- от расхождения на shallow-клоне: эталон отказывает по неполному реестру (rc 1), каркас
  умолчания на достижимом подмножестве дал rc 0 (замер критика круг 1, дважды) — инвариант 1
  заявлен на дереве с полной историей, оговорка в Остаточных рисках.

## Остаточные риски

- cognitive-only: одновременная ложь `--oracle` и умолчания одним автором (см. модель угроз);
  ловец — судьи на замороженном main + В2 приёмка.
- Shallow-клон (глубина 1 + выборочный fetch): реестр неполон → эталон отказывает rc 1,
  быстрый режим каркаса на достижимом подмножестве дал rc 0 (замер критика круг 1 на корпусе
  d8_kesh_valid, воспроизведён дважды). Инвариант 1 заявлен на дереве с полной историей;
  оговорка-ограничение реализационной пачке: на shallow-клоне умолчание отказывает как
  оригинал; отдельная клетка не заводится (совет критика круг 1, предмет не расширяется).
- Режим `--oracle` на живой истории стоит ~20–35 мин: В2 запускать фоном с timeout ≥ 3600
  (Н-380 остаётся ценой ЭТАЛОНА, но перестаёт быть ценой каждого коммита).
- Смешанный снимок внутри одного прогона (ls-tree HEAD / merge-base HEAD / log HEAD читаются
  в разные моменты; коммит между ними): вердикт одного прогона может не соответствовать ни
  одному дереву; так же ведёт себя прежний барьер (символический HEAD в rev-list по каждому
  документу). При отметке = HEAD начала это только расширяет объём суда; ловец — следующий
  прогон на устоявшемся дереве (кеш ≤ проверенного гарантирует, что несудимое попадает в
  окно) и `--oracle` при В2. Вне предмета 113: предмет — стоимость обхода, не изменение
  снимочной семантики 083 (арбитраж круга 3, «передаётся»).
- Два параллельных `--incr`-прогона на одном кеш-файле: `incr_finish` атомарен (tmp+mv),
  побеждает последний писатель; обе отметки — HEAD начала своего прогона, поэтому любая из
  них ≤ проверенного объёма того прогона; худший исход — лишний суд, не пропуск. Ловец тот
  же; клетка не заводится (Н-39: ветвь без входа).
- Коммит, совершаемый самим хуком (check_staged → барьер до появления HEAD) — существующая
  семантика 016/083, не предмет 113 (арбитраж круга 3).
