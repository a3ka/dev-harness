## Решения

- **Р1 Статусы в блоке ROADMAP — нет.** ROADMAP.md — уставной документ (`check_charter.sh:132`):
  статус в блоке менялся бы каждым тегом freeze/done, и перегенерация требовала бы строки
  владельца — main красен до подписи, а самокоммит реестра `freeze_contract.sh` упирался бы в
  pre-commit. Отвергнуто: статусы с равенством (неисполнимо без владельца), изъятие блока из
  устава (правка правила 11 — воля владельца), статусы «на момент правки плана» (отставание —
  та самая боль). Статусы живут в блоке HANDOFF и выводе `track_digest.sh`.
- **Р2 Один разбор.** Грамматика, статусы, пары и рендер — `scripts/lib_plan.sh`; его импортируют
  `gen_plan.sh`, `check_plan.sh`, `track_digest.sh`, `freeze_contract.sh` от своего каталога.
  Отвергнуто: разбор в каждом скрипте (класс расхождения `parse_artifact_basename`).
- **Р3 Freeze читает план из HEAD.** Незакоммиченная правка плана заморозку не открывает.
- **Р4 Freeze без плана — пропуск с именованной строкой; битый план — отказ.** Fail-closed на
  отсутствии сломал бы toy-миры потребителей freeze (`fixtures/freeze_contract/`,
  `fixtures/check_check_contract_ready/`, consumers.d) — цена, измеренная на 078. Отсутствие
  плана в живом дереве держат `check_plan` (fail-closed) и уставное кольцо.
- **Р5 Блок HANDOFF пишет вызов оркестратора, отсутствующий блок дописывается в конец** —
  против класса Н-209 (ротация теряет статические строки).
- **Р6 Активный = `заморожен` по локальным тегам.** Минтованные резервы (075–077, 079) активными
  не считаются (078 И-6); wip-ветки без заморозки не считаются — генератор вывода, не гейт.
- **Р7 Блок HANDOFF на равенство генерации не сверяется** — только «done-пункт не стоит
  следующим» и наличие блока (§10.4; устаревание — сигнал сторожа здоровья, §10.4 п.3).
- **Р8 «Одна строка §Предмет» дайджеста = заголовок H1 файла контракта** (первая строка
  `contracts/<id>-*.md` без `# `): первая строка раздела «Предмет» у живых контрактов — цитатная
  подводка, не предмет.
- **Р9 Проводка в CI и устав — пачка Б после done 083**: `registry/ci-steps.tsv`, `ci.yml` и
  `check_charter.sh` сейчас в работе 083.
- **Р10 pre-commit судит HANDOFF только при его правке.** Теги общие для всех worktree, а
  HANDOFF.md ветки — на момент её развилки: тег done сделал бы красным каждый коммит чужой
  ветки, которой HANDOFF не в зоне. Полная проверка — CI (main и merge-ref PR несут HANDOFF main).

## Инварианты

1. **И-1 Грамматика plan.tsv.** UTF-8, LF. Строка 1 — побайтово `id⇥пара⇥этап⇥зависит⇥источник⇥трек`
   (⇥ — TAB). Далее — ≥1 строка, ровно 6 полей через TAB; пустых строк и комментариев нет.
   Замкнутые алфавиты (TAB — ни в одно значение, `,` — только разделитель списка «зависит», `|` — ни в одно поле):
   id — `[0-9]{3}` (номер контракта) либо `[A-Za-zА-ЯЁа-яё][A-Za-zА-ЯЁа-яё0-9.-]*` (пункт без
   номера; в `CI-А`/`CI-Б`/`CI-В` последняя буква кириллическая), уникален в файле;
   пара — `[1-9][0-9]*`; этап — ровно `до V-2` либо `параллельно с V-2`; зависит — `-` либо
   id(`,`id)*; источник — `docs/owner/<путь>.md#<раздел>` либо `[0-9a-f]{7,40}`; трек —
   `[A-Za-z][A-Za-z0-9-]*`. Сравнения id, зависимостей и номеров — литеральные (`==`, `grep -Fx`),
   никогда regex/glob из значения (норма 037). Разбор — только `lib_plan.sh`.
2. **И-2 Статус вычисляется.** Для id-номера N первым совпавшим: `done` (∃
   `refs/tags/done/contracts/N/*`) → `закрыт без done` (первое поле строки
   `registry/closed-without-done.tsv` до TAB == N) → `заморожен` (∃ `refs/tags/frozen/contracts/N/*`)
   → `номер выдан`. Символьный id — `не начат`. Закрытые = {done, закрыт без done}; активные =
   {заморожен}; открытые = незакрытые. Теги — refs репозитория запуска.
3. **И-3 Пары.** P0 — наименьшая пара открытых строк; P1 — наименьшая пара открытых строк,
   большая P0 (может отсутствовать).
4. **И-4 Блок ROADMAP — функция plan.tsv.** ROADMAP.md содержит ровно одну строку
   `<!-- BEGIN GENERATED PLAN -->` и ровно одну `<!-- END GENERATED PLAN -->` (целыми строками,
   BEGIN выше END). Строки между ними — побайтово:
   ```
   **Итоговый порядок** (генерируется из registry/plan.tsv: bash scripts/gen_plan.sh --write; правка — строкой плана)

   | пара | id | этап | трек | зависит | источник |
   |---|---|---|---|---|---|
   | <пара> | <id> | <этап> | <трек> | <зависит> | <источник> |
   ```
   — по строке таблицы на строку плана: пара по возрастанию числом, внутри пары — порядок файла
   (отступ списка в этом тексте блоку не принадлежит; так же в И-5 и И-9). Статусов в блоке нет
   (Р1). Подстрока `Итоговый порядок` вне блока в ROADMAP.md не встречается.
5. **И-5 Блок HANDOFF.** Маркеры `<!-- BEGIN GENERATED NEXT SESSION -->` /
   `<!-- END GENERATED NEXT SESSION -->`; между ними побайтово:
   ```
   ## Следующая сессия (генерируется: bash scripts/gen_plan.sh --write)

   - <id> · пара <пара> · <статус> · трек <трек>
   ```
   Выбор: A — активные строки; k = max(0, 2 − |A|); E — первые k строк со статусом `номер выдан`
   или `не начат`, у которых каждая зависимость закрыта; A и E — в порядке (пара, файл); вывод
   A, затем E. A и E пусты — единственная строка `- нет пунктов: всё закрыто или зависимости открыты`.
6. **И-6 Генератор.** `bash scripts/gen_plan.sh --write [--root <dir>]` рендерит оба блока
   функциями `lib_plan.sh` и пишет только строки между маркерами (маркеры и всё вне их —
   побайтово прежние). В HANDOFF.md без маркеров блок дописывается в конец (прежние байты —
   префикс). Отказы rc 1, ни один файл не тронут: `план недоступен: registry/plan.tsv отсутствует`,
   любой отказ разбора И-1, `в ROADMAP.md нет блока плана`, `блок плана в ROADMAP.md не один`,
   `блок «Следующая сессия» в HANDOFF.md не один`.
7. **И-7 check_plan.** `bash scripts/check_plan.sh [--root <dir>] [--pre-commit]` судит рабочее
   дерево корня; `--pre-commit` исполняет группу (7) только если `HANDOFF.md` литерально есть в
   `git diff --cached --name-only` (Р10), остальные группы — всегда;
   rc 0 — всё сошлось; rc 1 — ПЕРВАЯ красная в порядке:
   (1) `план недоступен: registry/plan.tsv отсутствует`;
   (2) построчно по файлу: `план не разбирается: строка <N>: <поле>` (N — номер строки файла с 1;
   значение одного поля вне алфавита И-1 — <поле> = имя его столбца из строки 1),
   `нет источника: <id>` (5-е поле пусто), `нет трека: <id>` (6-е поле пусто); затем `план пуст`;
   (3) `источник не резолвится: <id>: <источник>` — нет файла `docs/owner/<путь>.md` в дереве, либо
   нет в нём строки-заголовка (`#`+, пробел), чей текст начинается с <раздел> и за ним пробел,
   `.` или конец строки; sha — `git cat-file -e <sha>^{commit}` неуспешен;
   (4) `номер вне реестра: <id>` — нет строки `registry/contracts.tsv`, чьё поле до ` → ` == id;
   (5) `зависимость на несуществующий id: <id> → <dep>`;
   (6) `в ROADMAP.md нет блока плана` | `блок плана в ROADMAP.md не один` |
   `блок ROADMAP расходится с генерацией` | `«Итоговый порядок» вне блока плана: ROADMAP.md:<строка>`;
   (7) `в HANDOFF.md нет блока «Следующая сессия»` | `блок «Следующая сессия» в HANDOFF.md не один` |
   `done-пункт стоит следующим: <id>` — строка блока `- <id> · …` с закрытым <id>.
   Для (6) и (7): `не один` — любая маркерная строка встречается больше одного раза; неполная
   или перевёрнутая пара — `нет блока`. rc 2 `NOT_IMPLEMENTED` — корень не git-репозиторий.
   Равенство блока ROADMAP — побайтово против той же функции рендера, что пишет `gen_plan.sh`.
8. **И-8 Отказ freeze.** `freeze_contract.sh`, только `dir=contracts`, после §3 и до §4: план и
   `closed-without-done.tsv` — блобы HEAD, разбор и статусы — `lib_plan.sh`. На HEAD нет
   `registry/plan.tsv` → stderr `  ok   план не заведён: проверка «вне плана» не применяется`,
   далее прежний путь; не разбирается → rc 1 `ОТКАЗ: план недоступен: <причина И-1>`; NNN не id
   строки с парой ∈ {P0, P1} → rc 1 `ОТКАЗ: контракт вне плана: <NNN> — не в текущей/следующей
   паре registry/plan.tsv (P0 <a>, P1 <b|нет>)` (открытых строк нет — `P0 нет, P1 нет`, отказ тем
   же именем). Отказ до первой мутации: тега `frozen/contracts/<NNN>/*` нет,
   `registry/contracts.tsv` побайтово, HEAD не сдвинут, дерево чисто. `plans/` — путь прежний.
   Выхода строкой причины нет: рычаг владельца — строка плана.
9. **И-9 Дайджест трека.** `bash scripts/track_digest.sh <трек> [--root <dir>]` печатает по строкам
   плана с этим треком, каждый раздел в порядке (пара, файл):
   ```
   # трек <трек>
   ## done
   - <id> — <заголовок H1 без «# »>
   ## заморожено, не done
   - <id> — заморожен
   - <id> — закрыт без done: <второе поле closed-without-done.tsv>
   ## в работе
   - <id>
   ## запланировано, не начато
   - <id>
   ```
   «в работе» = `номер выдан`, «запланировано» = `не начат`; пустой раздел — строка `- нет`; у
   done-id без файла `contracts/<id>-*.md` — `- <id> — файл контракта отсутствует`. Трек вне
   плана → rc 1 `трек не найден: <трек>`.
10. **И-10 Устав (пачка Б).** `registry/plan.tsv` входит в уставной класс `check_charter.sh`
    рядом с AGENTS.md/ROADMAP.md (якорь `ustav/1`): коммит, меняющий файл без
    `РАЗРЕШИЛ-ВЛАДЕЛЕЦ: registry/plan.tsv <причина>`, — красный check_charter с путём в причине;
    иные ветви check_charter не меняются.
11. **И-11 Проводка.** pre-commit (пачка А): `.githooks/pre-commit` до `exec … check_staged.sh`
    исполняет `bash "$ROOT/scripts/check_plan.sh" --root "$ROOT" --pre-commit` при существующем
    `$ROOT/registry/plan.tsv` и отказывает коммиту на rc≠0; без файла — прежнее поведение.
    CI (пачка Б): строки `registry/ci-steps.tsv` `step check:plan <вес> bash scripts/check_plan.sh`
    и `step plan-family-084 <вес> bash fixtures/_krasnye_084.sh`, блоки ci.yml — `gen_ci_steps.sh --write`.
12. **И-12 Перенос.** Первый коммит пачки А: `registry/plan.tsv` = таблица §Перенос (TAB между
    полями, порядок строк таблицы; символьный id, чей пункт до переноса получил номер строкой
    `registry/contracts.tsv`, пишется номером); ROADMAP.md — блок И-4 в §11 перед первым
    прозаическим пунктом порядка, в заголовках пяти прозаических пунктов `Итоговый порядок Odelix`
    → `Обоснование порядка Odelix`, остальной текст побайтово. Строки `РАЗРЕШИЛ-ВЛАДЕЛЕЦ:
    registry/plan.tsv …` и `РАЗРЕШИЛ-ВЛАДЕЛЕЦ: ROADMAP.md …` несёт лэнд-коммит оркестратора по
    слову владельца (065); исполнитель их не пишет. Тем же лэндом оркестратор исполняет
    `bash scripts/gen_plan.sh --write` — блок И-5 появляется в HANDOFF.md до проводки CI (пачка Б).
