## Предмет

Боль пилота Б-2 (odelix-stack ODX-STK-001, 2026-09-29): у проектной сессии
нет GitHub API — токен не передаётся, приёмка STK-001 непроверяема живьём

module_confirmation). Цена: 4 из 5 критериев приёмки с NOT_RUN-компонентами;
работа item 4 (M-87, 14 пунктов) закрыта ссылкой на реестр, а не сверкой.
Обход пилота (offline-сверка issue-map ↔ ISSUES.json, git ls-remote)
сработал, но RECONCILE_EXISTING_FIRST-задачи без GET issues/project items
остаются слепыми.

Решение владельца уже есть (чекпойнт #61, правка (3)): fine-grained PAT
odelixhq ТОЛЬКО ЧТЕНИЕ; лаунчер передаёт токен в сессию; ПЕРВЫЙ ШАГ —
ТОЛЬКО ЧТЕНИЕ. Токен живёт в доме вне репозиториев:
~/.config/odelix/github.env (на машине владельца —
/home/harness/.config/odelix/github.env), переменная ODELIX_GITHUB_TOKEN,
жив до 2026-10-29. Пароль/токен в репо и логах ЗАПРЕЩЕНЫ.

Предмет — шаг лаунчера workshop: чтение токена из дома вне репозитория
(по HOME лаунчера ДО подмены), передача в сессию (экспорт до exec omp в
ОБОИХ входах — одна функция, прецедент «окружение и учёт» workshop:102),
явная разметка режима (HARNESS_GITHUB_MODE=read|offline + баннерная строка
`GITHUB: read|offline` в probe и живом запуске), нуль копий значения в
файлы, значение не печатается. Деградация без токена — явная (offline),
не фатальная.

Класс задачи: КОДОВЫЙ (подтверждено по коду: предмет — поведенческий шаг

## Frontier (по коду workshop)

Сегодня сессии получают env так: load_env($PROJECT/.env) → bootstrap_env
(дом секретов по whitelist) → экспорты до exec omp (METERING_PROJECT/ROLE,
workshop:834-835). Варианты доведения токена:

- **В1 «проектный .env»** — ODELIX_GITHUB_TOKEN в .env проекта; load_env уже
  передаёт, ноль нового кода. ОТВЕРГНУТ: копия секрета в каждом проектном
  чекауте (умирает при переклоне — та же болезнь, которую закрывал
  bootstrap_env), против решения владельца (токен лежит вне репо), и
  деградация без пометки остаётся молчаливой — фиксируемый болью дефект.
- **В2 «whitelist bootstrap_env»** — добавить ключ в существующий дом
  ~/.config/dev-harness/secrets.env. ОТВЕРГНУТ: файл владельца лежит в
  ДРУГОМ доме (~/.config/odelix/), whitelist его не достигает; а само
  значение bootstrap_env дописывает в .env мастерской (:134) — копия в
  дереве, запрещено предметом.
- **В3 «шаг GitHub-токена» (ВЫБРАН)** — отдельная функция лаунчера: чтение
  ${HOME-до-подмены}/.config/odelix/github.env (дом решения владельца),
  семантика «уже заданное не затирается», экспорт ODELIX_GITHUB_TOKEN +
  HARNESS_GITHUB_MODE в обоих входах (одна реализация), баннер
  `GITHUB: read|offline`, деградация явная и не фатальная, нуль копий
  значения, значение не печатается.
- **В4 «offline-only разметка профилей»** (вторая половина якоря боли) —
  не передавать ничего, только помечать. ОТВЕРГНУТА как основная: владелец
  уже решил передать токен (чекпойнт #61); В4 выживает как явная offline-
  деградация В3 (баннер + HARNESS_GITHUB_MODE).

Оправдание болью Б-2: В3 — единственный вариант, дающий сессии GET
issues/project items (боль) и явную offline-разметку отсутствия (якорь
боли), не размножая секрет по деревьям (запрет владельца). Переиспользованы
конвенции: дом секретов вне репо, «уже заданное не затирается», баннерные
строки grep -Fx, грамматика KEY=VALUE; вторая конвенция не строится.

## Инварианты

1. **Токен доходит до сессии**: при непустом значении (файл дома ИЛИ уже
   заданный env) ODELIX_GITHUB_TOKEN экспортирован в окружение ребёнка
   exec omp в ОБОИХ входах (проектный и дев); судится env-дампом стаб-omp.
2. **Только чтение — первый шаг**: лаунчер не строит write-маршрутов и не
   расширяет применение токена; scope контролируется выдачей токена
   (GitHub-side, владелец), лаунчер передаёт значение как есть.
3. **Нуль копий**: значение не дописывается ни в один файл — ни .env
   мастерской, ни .env проекта, ни PSTATE, ни промпт; после живого запуска
   grep значения по toy-репо, PSTATE и дереву мастерской пуст.
4. **Нуль в логах**: значение не печатается ни в баннере, ни в probe, ни в
   stderr; баннер несёт только режим.
5. **Деградация явная, не фатальная**: нет дома или пустое значение →
   HARNESS_GITHUB_MODE=offline + строка `GITHUB: offline`, переменной
   ODELIX_GITHUB_TOKEN в окружении сессии нет (unset, не пусто), запуск не
   отказывает. Токен есть → HARNESS_GITHUB_MODE=read + `GITHUB: read`.
6. **Уже заданное НЕ затирается**: непустой внешний ODELIX_GITHUB_TOKEN
   (CI/фикстуры) побеждает файл; файл не перезаписывает env.

## Модель угроз

ЗАЩИЩАЕТ:
- молчаливую деградацию (боль Б-2: NOT_RUN без пометки) — offline виден
  баннером и env-режимом; стаб s3 ловится клеткой с3, честная клетка к3;
- утечку значения в логи — стаб s1 ловится клеткой с1 (значение в выводе),
  честные клетки к1/к2 судят вывод probe и живого запуска;
- утечку значения в файлы деревьев — стаб s2 ловится клеткой с2 (копия
  .env-строки), честная клетка к5 — grep по toy-репо, PSTATE, дереву;
- фатальность без токена — стаб s5 ловится клеткой с5 (отказ вместо
  деградации), честные клетки к3/к6;
- неподачу в сессию (сама боль Б-2) — стаб s6 ловится клеткой с6, честная
  клетка к2 судит env-дамп ребёнка за границей exec;
- неявный режим — стаб s7 ловится клеткой с7, честные клетки к2/к3;
- затирание внешнего значения (CI/фикстуры) — стаб s4 ловится клеткой с4,
  честная клетка к4.

НЕ ЗАЩИЩАЕТ:
- scope самого токена — свойство выдачи GitHub (владелец); лаунчер не
  понижает и не повышает привилегии значения;
- печать значения самим потребителем внутри сессии (env-команды агента) —
  за границей exec; ловец — дисциплина роли и владелец, отдельного
  механизма предмет не вводит;
- живой файл владельца вне дерева (формат, ротация до 2026-10-29) — шаг
  владельца; барьер работает на toy-доме и живой файл не читает.

## Красные предъявления

Носитель — fixtures/workshop_project/red_github_token_070.sh (прямое
предъявление; имя вне case_*-глоба раннера — семья probe-only 034,
прецедент 058), раннер — fixtures/_krasnye_070.sh. Привязки стабов к входам
(ручка → дефект → вход, где дефект наблюдаем) живут ТОЛЬКО в коде батареи
fixtures/workshop_project/red_github_token_070.sh (Н-39); контракт несёт
инварианты и rc-команды. Состав обманок — стабы s1..s7 с ручками STUB_*;
счёт предъявлений (стаб-пак 7/7 + диффпроба 7/7) живёт прогоном батареи.

Красное ДО реализации — г0, ПОВЕДЕНЧЕСКИЙ fail-fast (не греп исходника):
живой workshop --probe на toy-проекте с токеном в toy-доме не печатает
`GITHUB: read` → батарея rc 1 «предмет отсутствует», честные клетки к1..к7
не исполняются; стаб-пак 7/7 + диффпроба 7/7 зелёны в том же прогоне —
различимость батареи не зависит от честного кода. ДО-мера пачки: на 2bbe8a2
workshop не содержит обработки ODELIX_GITHUB_TOKEN/HARNESS_GITHUB_MODE
(grep -c по workshop = 0).

Демаркация контрпримеров: конформные входы — по грамматике bootstrap_env
(строки KEY=VALUE, разрез по первому «=», срез парных кавычек; ключ
ODELIX_GITHUB_TOKEN, значение непустое), а также отсутствие файла, пустое
значение, непустой внешний env-токен. Значения toy-токенов случайны на
каждый прогон — инвариантность к значениям: стаб с зашитым литералом
значения пройти клетку не может. Валидный контрпример = инвариантность к
значениям ∧ расхождение честного и стаба на конформном входе.

## Остаточный риск (назван прямо)

- Scope токена — GitHub-side: read-only держится выдачей fine-grained PAT
  (владелец, до 2026-10-29); лаунчер и барьер понижать привилегии не могут.
  Ловец дрейфа scope — владелец на выдаче.
- Печать значения потребителем внутри сессии (env-команды агента) — за
  границей exec; механизма нет, ловец — дисциплина роли/владелец.
- Токен истекает 2026-10-29: режим определяется НАЛИЧИЕМ непустого значения
  (инварианты 1/5), не его живостью — истёкший непустой PAT оставляет режим
  read (ошибки API — на стороне потребителя), offline наступает только когда
  владелец убирает/очищает значение или файл; фатального отказа не появится;
  продление/ротация значения — шаг владельца.
