## Предмет — ровно три механизма

### Механизм 1: `scripts/check_nabludenia.sh` — грамматика «ОТКРЫТО несёт адрес»

Судится СОСТОЯНИЕ файлов, не история (без git; скелет по образцу `check_ceilings.sh`).
Инварианты:

1. **Файлы.** Судятся оба — `NABLIUDENIA.md` (записи `### Н-NN. …`) и
   `NABLIUDENIA_ARCHITECT.md` (записи `### А-NN. …`) — корневого уровня
   каталога-аргумента (по умолчанию — корень скрипта), одной и той же мерой (развилка 6).
   Отсутствующий файл пропускается с именованной строкой; оба отсутствуют → rc=0 с печатью
   «неприменимо: …» (молчания нет — прецедент check_ceilings).
2. **Запись и статус.** Запись = строка `^### (Н|А)-\d+\.`. Статусный маркер = ПОСЛЕДНЯЯ
   группа в бэктиках той же строки заголовка. Заголовок записи без единой бэктик-группы —
   отказ «статус не объявлен» с именем записи (fail-closed: незакрытое = ОТКРЫТО — шапка
   файла; живой прецедент — А-16/А-17).
3. **Адрес.** Маркер, начинающийся со слова «ОТКРЫТО» (включая «ОТКРЫТО (кандидат)»,
   «ОТКРЫТО до …»), обязан нести `адрес:` с НЕПУСТЫМ хвостом внутри того же маркера:
   `` … `ОТКРЫТО — адрес: <непустое>` ``. Маркер «адрес:» с пустым хвостом — то же
   нарушение, формулировка «адрес пуст» (отделяет «слово есть» от «адрес назван» — урок
   charter). Адрес = где назначена починка: контракт, очередь, ROADMAP-шаг, правило роли
   или явная пометка «историческое, не чинить» (пометка тоже адрес — снимает ложное
   обещание). Маркер НЕ-ОТКРЫТО (ЗАКРЫТО…, ЧАСТИЧНО…, СПАСЕНО…) за адрес не судится —
   правило не обратной силы. **Только заголовок** (развилка 2): `адрес:` в теле записи не
   считается; блок-поиск по телу запрещён (ловит цитаты-стабы — ложно-зелёное).
4. **Отказ.** Каждое нарушение называет ИМЯ записи (Н-NN/А-NN) и причину ветви строкой
   вида `FAIL <имя>: <причина>`; причины ветвей: «открыта без адреса», «адрес пуст»,
   «статус не объявлен». Коды возврата: 0 — нарушений нет либо неприменимо; 1 — есть
   именованные нарушители; 2 — нечем проверить (файл существует, но не читается).
5. **Один источник грамматики.** Скрипт несёт строку `# ГРАММАТИКА: <regex записи,
   маркера и адреса>`; `nabludenia_digest.sh` (механизм 3) несёт побайтово ту же строку —
   сверка есть красная ветвь дрилла механизма 3 (класс «два источника истины»).

### Механизм 2: отказ гейта → авто-черновик наблюдения

**`scripts/draft_nabludenia.sh "<команда>" "<голова FAIL-строк>"`** (НЕ БАРЬЕР: логика
черновиков, судится дриллом `drill_gate_draft.sh`; прецедент — утилиты без фикстур).
Инварианты:

1. **Гейт-паттерн — в скрипте, единственный источник.** Гейт = локальный bash-вызов
   `scripts/{check_,verify_,drill_}*.sh`, `scripts/{freeze_contract,judge_gate,ci_diag}.sh`
   либо любой `npm run` из приёмки package.json. Команда не из списка → черновика нет,
   rc=0 (не-гейт не порождает записей — иначе спам-генератор).
2. **Черновик** пишется в `${TMPDIR}/dev-harness-nabludenia/drafts/` (развилка 3) — ВНЕ
   стерегомого дерева по построению 014.TMPDIR, канонически равный стерегомому корню
   скрипта или лежащий внутри него (любой лексический вид; путь может не существовать —
   каноникализация спуском до существующего предка), — именованный отказ код 1 ДО
   создания чего-либо. При создании каталога кладётся шапка README: «ЧЕРНОВИКИ, не
   записи: записать в NABLIUDENIA с адресом (механизм 1 красен без него) ИЛИ отвергнуть.
   Поднимаются дайджестом старта сессии».
3. **Формат.** Одна строка на отказ: `ДАТА · ГЕЙТ <имя> · HEAD <hash8|-> · FAIL: <первые
   ≤3 строки> · повторов: N`. HEAD — короткий хеш репозитория скрипта, вне git-репозитория
   — прочерк.
4. **Анти-спам = дедуп по ключу** (команда + первая FAIL-строка): повтор того же отказа —
   РОВНО ОДИН файл, счётчик повторов растёт, дата последнего обновляется; другой отказ —
   другой файл (детерминированная функция ключа: одинаковый ключ → один и тот же путь).
5. **Коды.** 0 — черновик записан/дедупнут либо не-гейт пропущен; 1 — именованный отказ
   (база внутри стерегомого дерева); внутренние ошибки — печать причины в stderr и rc=0
   (fail-open: черновик не пишется, сессия не падает).

**`.omp/extensions/gate-draft.ts`** — тонкая обёртка (авто-дискавери omp, своё не
проектируем): регистрирует РОВНО ОДИН handler на `tool_result`; для bash-результата с
isError=true вызывает скрипт (путь — относительно своего файла, `../../scripts/…`);
isError=false → вызова нет; фильтр гейт-паттерна скриптом (инвариант 1), расширение его
НЕ дублирует; падение/отказ скрипта handler проглатывает (fail-open — расширение в общем
процессе, не имеет права ломать работу).

### Механизм 3: session_start → дайджест старта сессии (пункт 006-A)

**`scripts/nabludenia_digest.sh --for-session [--root <корень>]`** (НЕ БАРЬЕР: судится
дриллом `drill_startup_digest.sh`; `--root` — для дрилла, по умолчанию корень скрипта).
Собирает и печатает секции, суммарно ≤40 строк:

1. **открытые записи с адресами** — id + адрес-строка той же грамматикой, что механизм 1
   (строка `# ГРАММАТИКА:` побайтово та же — инвариант 1.5); оба файла; запись без адреса
   тоже называется, с пометкой «(без адреса)»;
2. **дерево**: HEAD vs origin (ahead/behind), непушенные теги поимённо (`git tag -l` минус
   `git ls-remote --tags`; remote недоступен → строка «remote недоступен», не падает),
   аномалии `git status --short` (пусто → «чисто»);
3. **черновики механизма 2** — поимённо из `${TMPDIR}/dev-harness-nabludenia/drafts/`;
   пусто → «черновиков: 0»;
4. **указатель** на HANDOFF.md §«ГДЕ МЫ» — имя раздела, не текст.

Пустая секция печатается нулём, а не молчит; превышение потолка — хвост списка схлопывается
строкой «…и ещё N»; любая внутренняя ошибка — одна строка «дайджест не собран: <причина>»,
rc=0 (fail-open: старт сессии не имеет права упасть).

**`.omp/extensions/startup-digest.ts`**: на `session_start` → вызов скрипта (путь —
относительно своего файла) → РОВНО ОДИН `sendMessage` (`deliverAs: "nextTurn"`) с выводом;
скрипт упал → sendMessage с одной строкой «дайджест не собран» — процесс жив.

### Стабы и их входы (Н-39: каждый стаб — к входу, где его дефект НАБЛЮДАЕМ)

- «тихий отказ» (черновик не пишется) → вход: отказ гейта — черновика нет против
  написанного (case_chernovik_ne_pishetsja);
- «новый файл на вызов» → вход: повтор отказа — два файла против одного (case_dedup_spamit);
- «пишу на любую команду» → вход: не-гейт `ls /nonexistent` — черновик есть против нет
  (case_ne_gejt_pishetsja);
- «пишу куда сказали» → вход: TMPDIR внутри стерегомого — rc=0 против именованного
  отказа 1 (case_vnutri_dereva_molvit);
- «фабрика без подписки» → вход: fake-pi synthetic tool_result — 0 handler'ов против
  ровно одного (case_rasshirenie_ne_podnjato, case_rasshirenie_fail_open);
- «grep ОТКРЫТО по всему файлу» → вход: закрытая запись с цитатой в теле — названа
  против не названа (case_grep_otkryto_lovit_tela);
- «тегов: 0 всегда» → вход: непушенный тег — не назван против назван (case_tegi_ne_nazvany);
- «печатаю всё» → вход: 60 записей — 60+ строк против ≤40 с «…и ещё N»
  (case_potolok_prevyshaetsja);
- «пропускаю пустые секции» → вход: пустые черновики — строки нет против «черновиков: 0»
  (case_pustye_sekcii_molvhat);
- «другая ГРАММАТИКА» → вход: сверка маркеров — разошлись против побайтово равны

Мутации check_nabludenia (не стабы, обманное состояние дерева): ОТКРЫТО-без-адреса,
пустой хвост адреса, закрытые-без-адреса (зелёная охрана), цитата чужого адреса в теле,
А-запись без адреса, заголовок без статуса, каталог без файлов.

## Не-цели

- Единый ID-реестр Н через next_id.sh — отдельный предмет (рамка владельца; в нарезке
  Н-62 — «снижение дублей»).
- Семантическая дедупликация записей — cognitive-остаток, правило 8; помечается риском,
  не строится.
- Периодический полный CI (Н-63-2, «scoped 0 задетых → ложно-зелёное») — не ловится
  отказом гейта; отдельный предмет.
- CI-коллектор — ОТДЕЛЬНЫЙ предмет после ядра (развилка 4 дословно: «CI-коллектор —
  ОТДЕЛЬНЫЙ предмет после ядра»); шаг `if: failure()` + issue через GITHUB_TOKEN — по
  слову владельца, с permissions.
- Впрыск дайджеста в каждый task-вызов — отклонён (развилка 5 дословно: «Субагенты —
  дайджест оркестратору + норма роли; впрыск в task отклонён (ломает Н-39-дословность)»).
- Паритет локальных/remote тегов как ГЕЙТ (Н-65-механизм) — дайджест лишь ПОКАЗЫВАЕТ
  непушенные теги (наблюдаемость, не запрет).
- Н-61 (аудит git-вызовов), Н-66-б (семантика диапазона), «суд по своим коммитам»,
  один-файл-vs-два наблюдений, Н-60 (полная изоляция) — очередь автономности вне ядра.
- Четвёртый механизм — не предлагается и не заводится.
- Правка `scripts/verify_antiplacebo.sh` и существующих барьеров — не трогаются: три
  именованных FAIL «фикстура без барьера» на промежутке до реализации — по умыслу,
  уходят вместе с предметом.

## Незаполненные требования:

- Конкретный вид regex в строке `# ГРАММАТИКА:` — деталь реализации; контракт пинует
  побайтовое совпадение двух маркеров и семантику инвариантов 1–3 (механизм 1).
- Имя файла черновика из ключа дедупа — деталь реализации; пинуются инварианты 2.4
  (одинаковый ключ → один путь; разные ключи → разные пути).
- Формулировки адресов в миграционной пачке — образцы §Материал; неизменным остаётся
  назначение (куда/мёртвая), не дословный текст.
