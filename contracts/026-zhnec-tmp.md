## Предмет (инварианты)

Расширение `scripts/gc_agent_branches.sh` ветвью TMP-РЕАП. Существующие ветви (снос
слитых wip/*, СПИСОК зависших, `--expect-kept`, sweep остатков worktrees) не меняются.

1. **Источник кандидатов — только untracked**: `git ls-files --others -z -- tmp/` БЕЗ
   `--exclude-standard` — тот же источник, что нога-2 детектора 024. `tmp/` сидит в
   `.gitignore` — источник с `--exclude-standard` слеп по построению. Кандидат —
   ВЕРХНЕУРОВНЕВАЯ запись: путь сворачивается до первого компонента после `tmp/`
   (клон из 3947 файлов — один юнит удаления; само `tmp/` никогда не удаляется).
2. **tracked не трогается НИКОГДА**, двумя мерами: (а) источник не перечисляет tracked;
   (б) перед каждым удалением контроль `git ls-files -- tmp/<запись>` ПУСТ (tracked =
   запись индекса, включая staged-новые). Непустой контроль при untracked-кандидате под
   той же записью = СМЕШАННЫЙ вход: реап останавливается (уже удалённое остаётся
   удалённым), именованный отказ rc 1 «смешанный вход tmp/<запись>: tracked+untracked —
   владельцу», запись ЦЕЛА (fail-closed). Порядок задан явно: контроль (б) выполняется
   для кандидата, УЖЕ квалифицированного правилом 3, — перед его удалением;
   неквалифицированная запись (свежий аноним, активный номер) не судится смешанностью
   и не трогается (проба 3(б) кладёт смешанную запись с mtime −40д — квалификацию
   даёт возраст).
3. **Критерий реапа кандидата** (дизъюнкция):
   - **(а) done-тег**: имя записи содержит NNN из `0[0-9][0-9]` И в репозитории есть тег
     `done/contracts/NNN/*` → реап независимо от возраста;
   - **(б) возраст**: запись не несёт РАСПОЗНАННОГО NNN И mtime записи старше N дней
     (по умолчанию 7; замер: 219/227 git-видимых записей старше 7 дней, свежие анонимы
     1–7 дней — 5 записей — выживают, пауза выходных покрыта; флаг `--tmp-reap-age`).
   Распознанный NNN = есть `contracts/NNN-*.md` в дереве (NNN = `0[0-9][0-9]`) ИЛИ
   done-тег NNN. Запись несёт распознанный NNN без done-тега = АКТИВНЫЙ контекст →
   ВЫЖИВАЕТ независимо от возраста (скратч активного майлстоуна; долгий контракт не
   гибнет от возраста). Активный и done NNN в одном имени → выживает: приоритет
   активного номера над done (различающий вход `tmp/arch026-from021/` — проба 2).
   NNN без файла контракта и без тега — аноним, правило возраста.
4. **Dry-run по умолчанию**: каждый прогон gc печатает в stderr TMP-РЕАП список
   кандидатов (путь + причина: `done NNN` / `возраст Xd`) и счёт. Удаление — ТОЛЬКО
   явным флагом `--tmp-reap-apply` (Н-59: молчание ≠ разрешение; симметрия СПИСКА
   зависших); приёмка перехода — проба 1: dry-run сохраняет запись (файл существует,
   sha256 равен снятому ДО вызова), apply на ТОМ ЖЕ входе удаляет её. Остаточные риски
   названы: done-тег предполагает закрытие сессий контракта до close-out — та же норма,
   что у gc для worktrees («после того как НИ ОДИН спавн жив»); NNN в имени —
   эвристика принадлежности, не гарантия: случайный done-номер в чужом свежем имени
   даёт раннее удаление, старый безномерный активный контекст защиты возрастом не
   получает.
5. **mtime — lstat самой записи, python3** (Н-60: GNU find слеп к fifo/симлинкам; та же
   мера, что sweep остатков worktrees). Нет python3 → rc 2 NOT_IMPLEMENTED.
6. **Коды возврата**: 0 — порядок (сухой список напечатан / применено всё); 1 —
   смешанный вход, не удалось удалить кандидата, плюс прежние причины (заявленная
   зависшая, смена OID); 2 — нечем проверить. Пустой tmp/ и сухой список — rc 0.
7. **REGRESS-024** (критическая приёмка владельца): реап НЕ ослабляет ногу-2. Свежая
   (≤ N дней, без done-имени) утечка в `tmp/` остаётся ловимой `check_no_leak.sh
   --check` rc 1 после применения реапа; реап стейла между `--snapshot` и `--check` —
   только исчезновение строк манифеста, ложного rc 1 не даёт (дельта 024 судит новые
   строки, исчезновение — чистка).
