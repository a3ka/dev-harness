# Исключения паритета: скрипты `scripts` в package.json, которые НЕ входят в CI,
# и команды `run:` в `.github/workflows/ci.yml`, которые НЕ покрываются правилом 6
# (точное значение скрипта, `npm run X`, или 5-я форма `bash scripts/run_ci_lane.sh`).
#
# Формат: `<имя скрипта> = <причина>` или `команда: <текст команды> = <причина>` —
# пробелы вокруг `=` произвольные, пустое поле причины — отказ (молчаливая дыра).
# Этот файл читает САМ барьер, и любая правка проявляется в `npm run check:ci-parity`
# без перекомпиляции.
#
# Каждая запись ОБЯЗАНА иметь причину, потому что правило паритета из AGENTS.md
# сформулировано так: «приёмка не имеет права быть богаче CI молча». Необъявленный
# избыток приёмки — ложь, и записать «почему» обязательно: иначе через полгода
# никто не вспомнит, чем выбор был мотивирован.
#
# ──────────────────────────────────────────────────────────────────────────────
# Запись vs проверка. CI прогоняет ЧЕКУ на чистом дереве, а не ЗАПИСЬ: запись на
# каждом push'е — побочный эффект, который оседает в коммитах непонятно откуда.
gen:harness = команда записи: порождает .omp/agents/ из roles/, в CI прогонять запись неправильно — для сверки есть check:gen
overlay = команда записи: накладывает слой поверх omp, в CI прогонять запись неправильно — для сверки есть check:overlay
#
# ──────────────────────────────────────────────────────────────────────────────
# Местное основание контура. omp 185 МБ и его пин живут на машине разработчика,
# в CI их нет. check:overlay вернул бы 2 NOT_IMPLEMENTED — прогон бесполезен, а
# «проверено» в CI ложное.
check:overlay = предмет локальный: сверяет sha256 бинаря omp 185 МБ с пином, в CI бинаря и пина нет — прогон вернул бы NOT_IMPLEMENTED
check:skills-live = предмет локальный: требует бинаря omp (sha256 по пину), в CI бинаря и пина нет — прогон вернул бы NOT_IMPLEMENTED; для структуры есть check:skills
#
# ──────────────────────────────────────────────────────────────────────────────
# Сессионный трейс. Заявленная и фактическая модель сверяются по последнему трейсу
# в .zones/dev/, а в CI трейса нет — прогон бесполезен.
models:actual = требует трейс последней сессии в HARNESS_SESSION_HOME (по умолчанию — ${XDG_STATE_HOME:-$HOME/.local/state}/dev-harness-sessions/<hash8-канон-корня>/zones/dev, контракт 028), в CI трейса и его разрешения нет — прогон вернул бы NOT_IMPLEMENTED
#
# ──────────────────────────────────────────────────────────────────────────────
# Выдача номера. `next:id` печатает номер артефакта в stdout; это ЗАПИСЬ числа в имя файла,
# а не проверка, и в CI прогонять её неправильно — для проверки уникальности есть check:ids.
next:id = команда выдачи: печатает следующий номер артефакта в stdout, в CI прогонять неправильно — для проверки уникальности есть check:ids
#
# ──────────────────────────────────────────────────────────────────────────────
# Лаунчер сессии. `workshop` поднимает ИНТЕРАКТИВНУЮ сессию с моделью: в CI её некому вести, а
# запуск без терминала повис бы до таймаута. Это вход в работу, а не проверка.
workshop = интерактивный лаунчер: поднимает сессию роли в терминале, в CI вести её некому — для сверки слоя есть check:overlay и check:gen
#
# ──────────────────────────────────────────────────────────────────────────────
# Команда записи. freeze:contract СТАВИТ ТЕГ заморозки — это изменение реестра, а не проверка:
# запись на каждом push'е — побочный эффект, оседающий в истории непонятно откуда. Для сверки
# того, что тег поставлен правильно, есть check:contract-frozen: он читает реестр и отказывает,
# если заморозка лежит поверх невердикта или блоб разошёлся.
freeze:contract = команда записи: создаёт тег заморозки, в CI прогонять запись неправильно — для сверки есть check:contract-frozen

# ──────────────────────────────────────────────────────────────────────────────
# Прогон барьера проверки прокси учёта (контракт 005). Три режима --check-metering
# требуют подставного upstream и сети: фикстуры поднимают stub_upstream на свободном
# порту и посылают вызовы через живой процесс. В CI прокси не поднимается, и
# прогон вернул бы NOT_IMPLEMENTED, а зелёное CI при непроверенной приёмке есть
# тот самый гейт, что зеленее CI, против которого заведён сам check:ci-parity.
# metering:selftest — сетевой smoke прокси, в CI прогоняется без сети невозможно;
# оставлен под собственным шагом CI для архитектора, когда он дойдёт.
check:metering = требует подставного upstream и сети: фикстуры поднимают stub_upstream на свободном порту и посылают вызовы через живой процесс, в CI прокси не поднимается
check:metering:cold = требует подставного upstream и живой работник workshop: фикстура убивает прокси по pid-файлу и стартует workshop --check-metering, в CI pid-файла и подъёма нет
check:metering:live = требует живой omp: фикстура посылает uuid-вызов через живой канал и сверяет коррелятор в calls.jsonl, в CI omp не поднимается

# ──────────────────────────────────────────────────────────────────────────────
# Срез 1-4 контракта 016 (изоляция агента). Пять ключей — операционные команды
# либо предмет живого коммиттера; на CI чистого чекаута гонять их неправильно:
# запись мутирует состояние (хук, ветки, worktree, main), а судья staged пуст
# по построению. Паритетный гейт проверяет, что пункт приёмки ОБЪЯВЛЕН с причиной,
# а не молчаливо пропущен — это и есть запись ниже.
# Механизмы, ради которых команды заведены, покрыты так:
#   * check:hooks (в CI) — коммит .githooks/pre-commit + установщик core.hooksPath;
#   * fixtures/check_staged/case_* и probe_check_staged — scoped-прогон судьи
#     через scoped-барьер verify_antiplacebo (фикстура каталога);
#   * fixtures/spawn_agent/case_* — scoped-прогон спавна (ветка+worktree+identity);
#   * fixtures/land_agent/case_* — scoped-прогон приземления (identity, merge --no-ff, реестр);
#   * fixtures/gc_agent_branches/case_* — scoped-прогон GC (снос слитых, сохранение зависших).
hooks:install = команда записи: ставит core.hooksPath в локальный git config, в CI прогонять запись неправильно — для сверки механизма есть check:hooks
check:staged = предмет — staged живого коммиттера: на чистом CI-чекауте staged пуст по построению, rc=0 тавтологией; для сверки механизма есть check:hooks, для раннерных инвариантов — scoped-прогон фикстур check_staged
spawn:agent = команда записи: создаёт ветку wip/<NNN>/<автор> и worktree вне стерегомого дерева, в CI прогонять запись неправильно — для сверки изоляции есть fixtures/spawn_agent/case_*
land:agent = команда записи: мерджит --no-ff в main с identity оркестратора и мутирует коммитера, в CI прогонять запись неправильно — для сверки приземления есть fixtures/land_agent/case_*
gc:agent-branches = команда записи: сносит слитые wip/* ветки и связанные worktree, в CI прогонять запись неправильно — для сверки механизма GC есть fixtures/gc_agent_branches/case_*

# Сам-тесты раннера анти-плацебо (арбитраж 020 c8aaa67, замер 5). Отдельный шаг
# в джобе `obshchij` (вне matrix-джобы `antiplacebo`, контракт 087 И-8) собирает
# mktemp-корень из копии `scripts/verify_antiplacebo.sh` и `fixtures/verify_antiplacebo/`
# и гоняет там `npm run check:antiplacebo -- "$TMP_ROOT"` — 23 фикстуры на минимальном
# корне, 52 с стены (измерено в замере 5). Каждая команда шага оплачена своей записью
# команда: с настоящей причиной — канал тот же, что у residual-оплат инварианта 4;
# правило 6 (шишка барьера :37-39) предписывает объявлять причину для каждой
# команды `run:`, а не молча вычитать её из области. Прямой вызов
# `bash scripts/verify_antiplacebo.sh …` в workflow НЕ пишется — это красный флаг
# residual (замер 6: ветвь «барьер остался зелёным на обманном дереве»).
# Имя переменной `TMP_ROOT` зафиксировано контрактом 020 v2 (дословно).
команда: TMP_ROOT="/tmp/dev-harness-antiplacebo-selftest-$$" = уникальный корень сам-тестов раннера анти-плацебо (арбитраж 020 c8aaa67, замер 5): $$ — PID shell-а шага, уникален в пределах одного прогона CI; 23 фикстуры на минимальном корне — рецепт CI-шага, 52 с стены. `$()` в `run:` запрещена барьером как «форма вне разбираемого подмножества» (`form_outside_subset` :621), поэтому использован `$$` вместо `mktemp` — атомарность не страдает, в одном шаге один shell
команда: trap 'rm -rf "$TMP_ROOT"' EXIT = съём mktemp-корня сам-тестов раннера анти-плацебо при любом rc (арбитраж 020 c8aaa67, замер 5): корень не должен оставаться в /tmp при красном или зелёном прогоне
команда: mkdir -p "$TMP_ROOT/scripts" "$TMP_ROOT/fixtures/verify_antiplacebo" = создание scripts/ и fixtures/verify_antiplacebo/ внутри mktemp-корня сам-тестов раннера анти-плацебо (арбитраж 020 c8aaa67, замер 5): раннер гоняет ТОЛЬКО фикстуры из этого каталога, рецепт замера 5; команды склеены в одну строку (контракт 087: общие шаги obshchij)
команда: cp scripts/verify_antiplacebo.sh "$TMP_ROOT/scripts/verify_antiplacebo.sh" = копия раннера анти-плацебо в mktemp-корень сам-тестов (арбитраж 020 c8aaa67, замер 5): раннер ЗАМОРОЖЕН в этом круге — копия, не правка; рецепт замера 5
команда: cp -r fixtures/verify_antiplacebo/. "$TMP_ROOT/fixtures/verify_antiplacebo/" = копия 23 фикстур сам-тестов раннера в mktemp-корень (арбитраж 020 c8aaa67, замер 5): раннер гоняет ТОЛЬКО фикстуры из корня — `fixtures/verify_antiplacebo/case_*.sh`; рецепт замера 5
команда: npm run check:antiplacebo -- "$TMP_ROOT" = сам-тесты раннера анти-плацебо на минимальном mktemp-корне, аргумент — путь корня; оплата предписана арбитражем c8aaa67
