# Наблюдения архитектора: дефекты воркфлоу, которые замечены изнутри конструкции

Файл заведён 2026-08-25 по слову владельца. Симметричен `NABLIUDENIA.md` (там —
дефекты РАБОТЫ оркестратора и процесса в целом; здесь — дефекты, замеченные
архитектором-субагентом во время написания пачки: контракт, барьер, фикстуры,
процедуры регламента).

Префикс записей: `А-NN` (от Architect). Правила ведения — копия правил
`NABLIUDENIA.md` (запись обязана называть цену и чем закрыто; незакрытое
помечается `ОТКРЫТО`; повтор причины дважды — дополнение, не дубль).

## Отличие от NABLIUDENIA.md

- **NABLIUDENIA.md** — дефекты оркестратора/процесса/внешних ролей. Ведёт
  оркестратор (или владелец по прямому слову).
- **NABLIUDENIA_ARCHITECT.md** — дефекты, которые видит только тот, кто пишет
  конструкцию (контракт, барьер, фикстуры). Примеры: «ветвь X не доказывает
  свойство Y», «процедура Z описана вне последовательности исполнителей»,
  «red-тест прошёл бы стабом, потому что критерий слабее предмета».

## Когда писать

Архитектор заводит запись **в конце каждого вызова** (после сдачи пачки или
правок), если заметил хотя бы один дефект. Не накапливать «до лучших времён» —
наблюдение, не сделанное в момент замечания, теряется. Цена, как правило,
называется «из дерева» (номер строки, имя файла) или «из лога субагента».

## Формат записи

```
### А-NN. <название> `СТАТУС`

**Что произошло:** <наблюдение, не интерпретация>.
**Цена:** <минуты/круги/файлы>.
**Источник:** <файл:строка ИЛИ лог субагента ИЛИ явное "вывод">.
**Класс:** <тип — какой раздел нормы/роли нарушен>.
**ЧЕМ ЗАКРЫТЬ:** <правило в роли ИЛИ механизм ИЛИ "ОТКРЫТО">.
```

## Что НЕ сюда

- Дефекты продукта (кода, фикстур) — это для `verdicts/critic/` и
  `verdicts/adversary/`.
- Дефекты ролей critic/adversary/reviewer — это для `verdicts/arbitration/`.
- Стратегические наблюдения («предмет 011 был не нужен») — это для грилинга
  владельца, не для журнала.

## Записи

### А-1. Норма-предмет пинована маркерами, а не текстом `ЗАКРЫТО в 011 (fe6dbdf)`

**Что произошло:** ветвь `norma` пачки 011-v1 проверяла в AGENTS.md две подстроки —
`ПРИЁМКА-СУДЬИ (v2` и `полный прогон — только CI` (блоб 65ca8f9, строки 221–224).
Обе подстроки проносила норма, ПРОТИВОПОЛОЖНАЯ по смыслу («утверждение „полный прогон —
только CI“ неверно; судья обязан гонять полный прогон»), а полный текст нормы был
оставлен кругу критика (contracts/011-v1, строка 128).
**Цена:** 1 из 4 блокирующих находок круга 1 критика (6bffd2d); правка — дословный пин
трёх строк в контракте, перезапись ветви, +1 фикстура противоположной нормы.
**Источник:** verdicts/critic/contracts-011-v1.md:12-22; закрытие —
contracts/011-prijomka-sudi-i-gigiiena-rannera.md:21-29, scripts/check_runner_hygiene.sh:267-282,
fixtures/check_runner_hygiene/case_norma_protivopolozhnaya.sh.
**Класс:** ПРОЦЕДУРЫ — нарушены правила 1 и 8 (AGENTS.md:200, 219-222): смысл объявлен
механически доказанным маркером, без `cognitive-only` и названного ловца; решение «какой
текст» молча передано судье вместо автора контракта.
**ЧЕМ ЗАКРЫТЬ:** в 011 — дословный пин полного текста + красная фикстура противоположной
нормы (fe6dbdf). Для класса — кандидат правила в роль architect: «норма-предмет пинуется
полным дословным текстом; маркеры — только для охранных ветвей»; до внесения ловец — круг
критика (измерено: поймал, но ценой круга).

### А-2. Пин API без наблюдающей ветви: default-scratch не наблюдаем `ЗАКРЫТО в 011 (fe6dbdf)`

**Что произошло:** контракт 011-v1 пиновал «при ПУСТОЙ `VERIFY_ANTIPLACEBO_SCRATCH` —
`mktemp -d` под `${TMPDIR:-/tmp}`», но все ветви барьера, запускающие раннер, передавали
непустую переменную; поведение по умолчанию не наблюдалось ни одной командой приёмки
(обход: оставить in-tree `./tmp` при пустой переменной — все ветви зеленеют).
**Цена:** 1 из 4 блокирующих круга 1; правка — новая ветвь scratchdef + 1 фикстура +
правка контракта; счёт фикстур 12 → 17.
**Источник:** verdicts/critic/contracts-011-v1.md:24-32; закрытие —
contracts/011-prijomka-sudi-i-gigiiena-rannera.md:125-127, scripts/check_runner_hygiene.sh:201-220,
fixtures/check_runner_hygiene/case_scratchdef_v_dereve.sh.
**Класс:** КОНСТРУКЦИИ — приёмка слабее предмета: строка пинованного API без наблюдающей
её ветви барьера.
**ЧЕМ ЗАКРЫТЬ:** в 011 — ветвь scratchdef (пустая переменная, подставной TMPDIR, скратч
обязан появиться под ним и НЕ в дереве). Для класса — кандидат правила в роль: «каждая
строка пинованного API ↔ наблюдающая ветвь барьера; сверка до сдачи судье».

### А-3. Lock-ветвь доказывала существование файла, а не API `ЗАКРЫТО в 011 (fe6dbdf)`

**Что произошло:** ветвь `lock` 011-v1 проверяла существование lock-файла, сохранность
первого прогона, любой ненулевой код второго и подстроку «занят»; три пинованных свойства
— формат `<pid> <pgid> <epoch>`, атомарность захвата, ровно код 3 — не проверялись
(обход: неатомарный `printf` только pid + код 1 — критерий зелёный).
**Цена:** 1 из 4 блокирующих круга 1; правка — перезапись lock-ветви (~35 строк барьера),
3 новые фикстуры + расширение четвёртой.
**Источник:** verdicts/critic/contracts-011-v1.md:34-43; закрытие —
scripts/check_runner_hygiene.sh:136-173, fixtures/check_runner_hygiene/
case_lock_format_broken.sh, case_lock_rc_ne3.sh, case_lock_neatomarnyj.sh.
**Класс:** КОНСТРУКЦИИ — ветвь барьера слабее пина: проверяла соседнее (существование,
подстроку), а не пинованное свойство.
**ЧЕМ ЗАКРЫТЬ:** в 011 — ветвь пинует весь lock-API: трёхпольный формат, pid = владельцу,
pgid = его группе, ровно код 3, слово «занят», чужой lock байт-в-байт до/после; неатомарная
запись и неверный код предъявлены красным фикстурами. Для класса — тот же кандидат, что А-2.

### А-4. Вердикт «в тот же круг» судил будущий блоб `ЗАКРЫТО в 011 (fe6dbdf)`

**Что произошло:** процедура v+1 в 011-v1 требовала от круга критика вердикт
`contracts-010-v2` «в тот же круг» — когда правка 010 ещё не закоммичена: accept по
будущему блобу. Обязательные шаги процедуры (`check:charter`, `check:contract-frozen`,
перезаморозка) не были проводками приёмки; совет критика — два шага описаны «вне
последовательности исполнителей».
**Цена:** 1 блокирующая находка + 1 совет круга 1; правка — процедура переформулирована
последовательностью (i)–(iii), в §Зоны добавлена последовательность исполнителей 1–6,
приёмка дополнена пунктами 7–8.
**Источник:** verdicts/critic/contracts-011-v1.md:45-61; правила 9–11 — AGENTS.md:223-231;
закрытие — contracts/011-prijomka-sudi-i-gigiiena-rannera.md:43-52, 90-106, 146-154.
**Класс:** ПРОЦЕДУРЫ — нарушены правила 9–11 (вердикт — закоммиченный артефакт; заморозка
требует accept); многошаговая процедура описана вне последовательности исполнителей.
**ЧЕМ ЗАКРЫТЬ:** в 011 — каждый круг судит ЗАКОММИЧЕННЫЙ блоб (прецедент 008: судья
подтверждает запушенный sha через `judge_gate`), шаги разведены по исполнителям с указанием
«после какого блоба», промежуточный красный `check:contract-frozen` объявлен механизмом,
принуждающим v+1. Кандидат правила в роль: «многошаговая процедура в контракте —
последовательность исполнителей; вердикт всегда судит уже закоммиченный блоб».

### А-5. Обманка умерла от trap раньше окна наблюдения `ЗАКРЫТО (fe6dbdf)`

**Что произошло:** при сборке правок фикстура case_lock_format_broken краснела НЕ той
причиной: обманка писала однопольный lock и удаляла его в trap при выходе (sleep 6),
а барьерный опрос длится 8с — файл исчезал до конца опроса, и красное уходило в
«lock-файл не появился за 8с» вместо «три числовых поля».
**Цена:** один цикл диагностики-правки в замере сборки (~1 мин: rerun.out → гипотеза →
фикс); без правки фикстура провалила бы собственное предъявление (повторный прогон красный
не по объявленной ПРИЧИНЕ).
**Источник:** лог ArchitectFix011 (09:16 UTC, rerun.out: «не появился за 8с»); окно
опроса — scripts/check_runner_hygiene.sh:143-156; закрытие —
fixtures/check_runner_hygiene/case_lock_format_broken.sh:5-6,27 (lock НЕ удаляется в trap,
sleep 9 > 8).
**Класс:** КОНСТРУКЦИИ — фикстура с само-подметающей обманкой: окно наблюдаемости дефекта
меньше окна наблюдения барьера; красное по чужой причине — ложный диагноз (родня правила 7).
**ЧЕМ ЗАКРЫТЬ:** в 011 — обманка живёт дольше окна опроса и не подметает свой дефект
(зафиксировано комментарием в шапке фикстуры). Кандидат правила в роль (красные фикстуры):
«дефект обманки обязан наблюдаться всё окно наблюдения барьера; trap убирает артефакты,
не предмет предъявления».

### А-6. Пачка сдана с красным check:ceilings; предполётный гейт слеп к грамматике `ЧАСТИЧНО ЗАКРЫТО`

**Цена:** скрытый красный на сданной пачке (всплыл бы на регламентном пуше 4б);
диагностика ~1 мин (git show + stash-проба подтвердили красноту на HEAD: grep -c → 0).
**Источник:** scripts/check_ceilings.sh:81-83 (грамматика); лог ArchitectFix011 (09:24 UTC:
READY_RC=0 при CEIL_RC=1; FAIL «нет раздела» на stashed HEAD); закрытие —

**ЧЕМ ЗАКРЫТЬ:** заголовок — ЗАКРЫТО (fe6dbdf). Слепота гейта — ОТКРЫТО: кандидаты:

(правка замороженного 008 — слово владельца).

### А-7. Слепок раннера аннулирует прогон правками соседа в общем дереве `ОТКРЫТО`

**Что произошло:** scoped-прогон `verify_antiplacebo --scope check_runner_hygiene`
(09:14:11–09:16:43 UTC, круг правок 011) аннулирован отказом «дерево изменилось вне
$WORK»: за время прогона сосед (оркестратор) правил `roles/architect.md`,

локального — середина прогона). Слепок — на ВЕСЬ прогон: правка любого файла аннулирует
все результаты, сам инструмент печатает «прогон недостоверен целиком».
**Цена:** ~2.5 мин аннулированного прогона + ~1 мин диагностики (чьи правки: stat mtime,
список пиров); прогон перегнан после успокоения дерева.
**Источник:** scripts/verify_antiplacebo.sh:298-311 (слепок всего дерева на прогон),
:508-510 (отказ и «недостоверен целиком»); лог ArchitectFix011 09:14–09:18 UTC.
**Класс:** ИНСТРУМЕНТА — Н-48-2 в новом виде: скратч 011 (§Предмет Б.1) уводит из дерева
СОБСТВЕННЫЕ артефакты раннера, но правки соседа остаются ложным красным; lock (Б.2) разводит
параллельные ПРОГОНЫ, а не правки в общем дереве.
**ЧЕМ ЗАКРЫТЬ:** ОТКРЫТО. Кандидаты: 013 (изоляция прогонов — Н-45/Н-36; прогон вне общего
дерева), scoped-слепок (сравнивать только пути затронутых барьеров — правка замороженного
раннера, слово владельца); до механизма — правило для ОРКЕСТРАТОРА «не править дерево во
время чужого прогона» (журнал — NABLIUDENIA.md, не этот).
