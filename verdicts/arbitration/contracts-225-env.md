## Решение

1. **Критик прав по Б-2 / К-03.** Непустая строка REPOS, состоящая из bash-разделителей space/tab/LF, не означает ни конфигурационное умолчание, ни ошибку пустого списка. В 196 она означает ноль выбранных репозиториев. При исправных зависимостях, корректном сроке и существующем допустимом ROOT результат — **rc 0, stdout=b'', stderr=b'', никаких удалений**. Это распространяется на любую непустую смесь этих трёх разделителей, а не только один пробел.
2. **Автор прав в необходимости перенести умолчания в конфиг и сохранить `${VAR:-default}`; неправ в достаточности исправления только `''`.** Удалить один отказ `список репо пуст` недостаточно: Python `str.split()` делит больше символов, чем bash, а общий `directory()` сужает прежний ROOT-интерфейс. Ниже есть независимые измерения обеих соседних причин. Закрывать класс способом **канон/инструмент**, а не очередным специальным случаем.
3. **Вариант «заменить-поведение» не разрешён этим арбитражем.** 196 не обещает непустоту ENV-списка; 225 явно обещает сохранение старого интерфейса. Пустой JSON-массив конфигурации запрещён схемой 225 — это другой вход. Отказ вместо no-op не повышает безопасность удаления: оба ничего не удаляют; отказ лишь меняет операторский сигнал. Fallback на реальные репозитории для непустого whitespace, напротив, расширяет удаление и недопустим.
4. **К-01 остаётся обязательным механическим исполнением**, не остаточным риском: перенести четыре мутации v1 и собственную мутацию v2 в адресные стабы. Ранее закрытый cgroup-блок не открывается заново настоящим решением.
5. **Новый арбитраж перед третьим critic-вызовом не нужен, но автоматического разрешения третьего вызова нет.** После исполнения этого решения и дельта-листа по всем открытым блокам техническое условие `канон/инструмент` + формальный К-01 выполнено. Отдельная явная санкция владельца именно на дополнительный вызов и штатные двери остаются обязательными; этот файл её не заменяет. До санкции — не вызывать и не морозить. Третий вызов — scoped: закрытие Б-2, К-01 и последствия изменённой семантики, не новый полный поиск. Подробность бюджета — в разделе «Границы».

## Что делать автору

### Точная формула совместимости

Пусть C — корректный конфиг 225, E — значения трёх ENV, F — стабильный доверенный FS-мир старого cleaner, X — одинаковые bash/GNU-зависимости, cwd, locale, shell options и момент отсечения возраста. `B196[C]` — закреплённый выше исходник 196, у которого **только значения трёх defaults** приведены к C; оператор `${VAR:-...}`, порядок проверок и алгоритм не изменены. Конфигурационная валидация/новые зависимости 225 остаются самостоятельным явно изменённым предусловием.

Для каждого из трёх ключей k:

- `effective(k) = C[k]`, если k не задан или его значение имеет длину ноль;
- иначе `effective(k) = E[k]` **без trim, Unicode whitespace-normalization, канонизации или подстановки default после разбора**.

После успешного чтения C обязательство артефактного входа:

**Obs(225(C,E,F,X)) = Obs(B196[C](E,F,X)).**

`Obs` — точный rc, stdout как bytes, stderr как bytes и логический FS-эффект: те же удалённые/сохранённые пути, содержимое/тип/режим/владелец/цель ссылки сохранённых объектов, нет записей/удалений снаружи и нет systemctl/freeze/thaw. Неповреждение сравнивается со снимком до запуска. Это не обещание одинаковых syscall, wall time, atime от чтения или автоматически обновляемого времени родительского каталога после удаления. Возрастные миры используют одинаковую границу либо явный запас от неё, не два случайно разных «сейчас». Порядок и число строк, в том числе повторный репозиторий, значимы.

Формула применяется не только к конечному списку тестовых строк, но ко всем передаваемым ENV-значениям в прежней области 196, включая отказные. NUL не передаётся в POSIX ENV; враждебные FS/гонки не вводятся этим решением. При невалидном C действует собственный отказ 225, а не попытка сначала исполнить 196. Непустая ENV не отменяет обязательную валидацию C.

Для REPOS существенны **bash-разделители `0x20,0x09,0x0a`**, не класс Python `isspace()`. CR/VT/FF/NBSP не становятся разделителями и должны доходить до прежней проверки имён. Ведущие/замыкающие bash-разделители вокруг валидных имён не создают пустых репозиториев. Непустая строка только из этих разделителей даёт ноль выбранных репо, без fallback; при неверном сроке или ROOT сохраняется соответствующий отказ 196. Все имена проверяются до удаления, в том числе неверное после верного. ROOT — литеральное значение старого шва, а не текст для `.strip()` или `Path`-нормализации. Каноничность **JSON-корней и tmp** не переносится молча на унаследованную ENV артефактов.

**Рекомендуемый конечный инженерный способ:** сохранить единый проверенный bash-алгоритм артефактов 196, снабдив его проверенными default-значениями из общего конфига; убрать конкурирующую Python-реализацию артефактной семантики. Канон конфигурации и tmp-протокол остаются 225. Путь передачи трёх значений обязан сохранять байты, не использовать `eval` и не терять завершающие LF. Это решение не требует конкретного IPC/расположения функции; автор отвечает за рабочий публичный вход, установочный инвентарь и чистый cutover. Если оставлять порт алгоритма, он обязан выполнить ту же формулу, включая shell expansion, числовые отказы, пути и порядок вывода, а не только выбранные примеры. Сохранение алгоритма снимает целый класс расхождений дешевле такого порта.

### Конечная порождающая сетка и наблюдения

Не требовать бесконечного перебора и полного произведения всех ENV × FS. Генерировать перечисленные ниже конечные семейства по независимым осям; сохранить нынешние клетки и регресс 196. `A=Repo-A`, `B=Repo-B`, `P` — игрушечный ROOT. Ожидания и исходные деревья готовятся до вызова. Для old/new — два идентичных мира либо полное восстановление одного пути; нельзя давать модели уже очищенный old-мир.

1. **Defaults:** все 8 комбинаций unset/`''` трёх ключей, затем каждый непустой override отдельно и все три вместе. Конфиг брать с двумя отличающимися политиками/корнями, чтобы literal-старый default был различим. Сохранять отсутствие HOME.
2. **Ноль токенов:** все слова длины 1–3 над `{space, tab, LF}` (39 значений), плюс пустая строка отдельной default-клеткой. Для каждого непустого слова — корректные срок/ROOT, существующие старые и молодые прогоны A/B, а также внешний sentinel: rc 0, оба потока пусты, весь мир сохранён. Два дополнительных отрицательных предъявления — неверный срок и отсутствующий ROOT при непустом whitespace REPOS; не превращать их в ранний успех.
3. **Позиции разделителей:** `D={'', ' ', '\t', '\n', ' \t\n'}`; `p+A+q` для всех `p,q∈D`; `A+s+B` для каждого непустого `s∈D`; повтор имени `A+s+A` и обратный порядок `B+s+A` для тех же s. В этих мирах репо действительно существуют, есть old/young и необъявленное репо; сверять удаление, точные строки/порядок/счётчики, не только rc на отсутствующих каталогах.
4. **Не-bash whitespace и неверные имена:** каждый `c∈{CR,VT,FF,NBSP}` отдельно и в `A+c+B`; `'.'`, `'..'`, `'../escape'`, `'/absolute'`, `'-A'`, `A+' '+неверное` и обратный порядок. Проверять точный первый отказ и отсутствие удаления даже валидного старого прогона. Для `*`, `?`, `[AB]*` — две фиксированные cwd (совпадений нет / есть безопасные совпадения); дифференциально сохранить существующую bash-expansion, не выдавать самописный split за её эквивалент.
5. **Срок:** unset/`''` из п.1; непустые `1`, `4`, `8`, `01`, `000`, `0`, `-1`, `+1`, `1.0`, `abc`, одна Unicode-цифра; отдельно для `s∈{' ', '\t', '\n', ' \t\n'}` значения `s`, `s+'4'`, `'4'+s`. Не обрезать пробелы и не принимать Unicode-цифры. Эффект положительных значений различим по возрасту.
6. **ROOT:** unset/`''`; корректный P, существующий путь с внутренним/концевым пробелом, P с завершающим `/`, относительный путь к тому же каталогу, путь с существующим компонентом `x/../`; отсутствующий путь, обычный файл и ссылка вместо ROOT; whitespace-only и обрамление `s+P`/`P+s` для space/tab/LF. Проверять точные литеральные пути в сообщениях и отсутствие trim. Все пути, включая относительные и контрольные символы, находятся внутри одноразового мира. JSON C при этом корректен.

Это конечная **область доказательства**, а не сужение обещанного интерфейса до этих строк. Неиспытанная условная реализация не становится разрешённой. Новая конкретная находка по формуле остаётся дефектом, но произвольная новая специальная мутация сама по себе не требует полного нового суда.

В каждой клетке сравнивать rc/сырые bytes/FS-эффект old↔new; дополнительно literal-опоры по классам: whitespace no-op, отказ недопустимого имени/срока/ROOT, old удалён/young сохранён/внешнее сохранено, непустой override не берёт default. Проверять происхождение blob оракула и ровно три замены defaults. Не подменять в оракуле split, проверки или вывод. Не сравнивать `.strip()` потоков, unordered-множества строк или только наличие слова `ОТКАЗ`. Нормализация случайного префикса разных игрушечных миров допустима только явным взаимно-однозначным отображением корней; не удалять из наблюдения реальные пробелы/слеши/CR/LF ENV.
