# Арбитраж: способен ли bash-скрипт защитить себя от враждебного BASH_ENV (контракт 024)

Прочитаны все три первоисточника + контракт целиком. Спорные утверждения проверены

## Замеры (мои, не пересказ сторон)

- **З1 — решающий.** bash РАЗРЕШАЕТ функцию с именем-абсолютным-путём:
  `function /bin/echo { ... }; /bin/echo real` → напечатано `HIJACKED-FN`. Значит вызов
  пиннутым абсолютным путём НЕ иммунен к подмене функцией. Это снимает единственного
  кандидата на bash-only доверенный бутстрап. (Для сравнения: alias с `/` bash отвергает —
  `invalid alias name`; функции — нет.)
- **З2.** Маршрут «posix-режим возвращает приоритет special builtins» недостижим: `set`
  сам есть командное слово. Прогон дал `FN-SET-RAN FN-UNSET-RAN still-fn=[unset]` — и
  переход в posix-режим, и последующий `unset -f` исполнили функции атакующего.
- **З3.** `env -i` действительно срезает весь функциональный класс: дочерний bash видит
  `child-sees=[command]` без санитизации и `child-sees=[]` через `/usr/bin/env -i`. То есть
  re-exec ЛЕЧИТ класс — если до него дошли; «дойти» и есть непокрываемый шаг (З1).
- **З4.** Расширения предела нет там, где его можно было ждать: `extdebug`+DEBUG-trap из
  BASH_ENV не работает — bash отказывает (`cannot start debugger; debugging mode disabled`),
  rc подопытного скрипта совпал с чистым прогоном (7 и 7). Предел ровно один и назван точно:
  **командное слово**.
- **З5 — факты к6 верны.** По судимому HEAD: `scripts/check_no_leak.sh:187` —
  `unset -f command`, `:345` — `cd "$ROOT_ARG"`, `:453` — `[ -L "$entry" ] && continue`.
  Адверсарий не ошибся ни в одной строке.

## РЕШЕНИЕ

**1. Класс BASH_ENV — предел, принимается вариант (а).** Всё, что скрипт может ИСПОЛНИТЬ,
есть командное слово; функция перехватывает любое командное слово — включая абсолютный путь
(З1) и префиксы `builtin`/`command`, которые сами суть командные слова (к4, блокер 1).
Непереопределяемы только ключевые слова и раскрытия: ими можно СРАВНИВАТЬ и честно вернуть
rc, но нельзя УЗНАТЬ истину — для истины нужны `git` и `sha256sum`, то есть командные слова.
Структурного bash-only закрытия класса не существует; это свойство интерпретатора, а не
недоделанный фикс. Прав здесь автор конструкции: продолжать правки по этому классу — платить
без закрытия.

**Строка в Демаркацию 024 (зона architect, дословно):**

> (в) детектор ДОВЕРЯЕТ ОКРУЖЕНИЮ ВЫЗОВА: код, которому позволено исполниться в том же bash
> ДО первой строки скрипта (`BASH_ENV`/`ENV`, экспортированные функции), может подменить
> функцией любое командное слово — включая вызов по абсолютному пути и префиксы
> `builtin`/`command` — и получить ложный rc 0; закрытия в bash нет (замер: функция с
> именем-абсолютным-путём легальна, `verdicts/arbitration/bash-env-predel-024.md` З1).
> Гигиена вызывающей стороны ВНЕ зоны 024 — тот же характер сужения, что у принятых
> «TMPDIR-redirect» и «mv+replace с валидным verify»: детектор ловит СЛУЧАЙНУЮ утечку
> субагента, а не враждебного владельца вызывающего процесса.

**2. Да, это треадмилл — по признаку перемещения точки инъекции.** к4 → к5 → к6 меняли ИМЯ
перехваченного слова, а не наличие перехвата. После приземления строки (1) адверсарий ОБЯЗАН
применять кап «ПОВТОР КЛАССА» к любому вектору, предпосылка которого — исполнение кода
атакующего в том же bash до первой строки. Честная оговорка в пользу адверсария: треадмиллом
НЕ были ни к5 блокер 1 (часовой санитизации — обычная env-переменная: настоящий структурный
дефект, законно закрыт), ни к5 блокеры 2–3 (`HOME` в whitelist — проектное решение, законно
оспорено). Кап адресован только к6 блокерам 1–2 и их будущим переименованиям.

**3. Вариант (б) отвергнут, и это решение о ПРАВОТЕ, а не о цене.** Выход за bash не закрывает
класс, а переносит его (для бинаря — предзагрузка библиотек, для другого интерпретатора — его
собственные pre-execution хуки). Норма ветви B фиксирует вызов как `bash scripts/check_no_leak.sh`
— первый интерпретатор выбирает ВЫЗЫВАЮЩИЙ, значит доверие к вызывающему лежит в фундаменте
механизма и наружу не выносится. Вопрос «нужен ли проекту доверенный бутстраповый носитель
вообще» — воля и цена, то есть **владелец**, и для 024 он не нужен: угроза, породившая
контракт, — случайная утечка субагента (Н-85), не враждебный оркестратор.

**4. Разрешено как bar-raise, НЕ условие done** (implementer вправе не делать; отсутствие —
не блокер ни для одного судьи): (а) вернуть `env -i` re-exec с часовым **по argv, не по env**
(argv задаёт норма-строка церемонии, атакующий модели к6 владеет только окружением) — по З3
это срезает функциональный класс целиком при достижении re-exec; (б) убрать `cd` из
канонизации корня (`:345`): контракт и так требует `git -C <канон>` для всех вызовов, так что
`cd` — лишняя поверхность.

**5. Блокер 3 к6 (S-dotgit-hook-symlink) СТОИТ.** Он вне предела и закрывается структурно:
внутри `.git/hooks/` симлинк есть активная подмена хука, а не «отсутствие утечки», и это ровно
тот артефакт, ради которого находка 5 к5 переносилась в manifest. Как именно (снять пропуск
симлинков для путей внутри `.git/hooks/`, хешировать цель либо сам факт симлинка) — суждение
architect/implementer, не моё. Это НЕ часть треадмилла и не повтор класса.

**6. Статус 024: остаётся в правке-круге** — ровно по двум пунктам: блокер 3 к6 (п. 5) и
приземление строки Демаркации (п. 1). Вердикт к6 FAIL признаётся законным по факту блокера 3;
его блокеры 1–2 переклассифицированы в названный остаточный риск и блокерами более не
являются.
