# Арбитраж 040-II: достаточность оракула для класса «успешный rc batched-вызова не доказывает честность его вывода»

Созван автоматически по правилу AGENTS.md «3 круга по одному предмету без разрешения —
созывает арбитра»: три подряд адверсарных круга на реализации A2-батчинга
`scripts/check_zones.sh` (`verdicts/adversary/contracts-040-oracle-a2-diff-tree.md`,
`62fe511` → `-v2.md`, `16f8f0f` → `-v3.md`, `d5f3cc3`). Оба на своих третьих кругах
стороны сами назвали следующий шаг арбитражем, не четвёртой правкой.

Стороны: адверсарий (`openai-codex`), вердикты кругов 1–3; автор конструкции
(`anthropic`, роль architect), фиксы `dd2befe` (круг 1, fail-closed rc), `5f9c9d8`
(круг 2, сверка множеств author_map). Асимметрия семейств (арбитр — семейство автора,
адверсарий — вне его) записана; каждый спорный пункт решён прогоном, не вкусом.
Скрипты замеров — одноразовые, `/tmp/dev-harness-verify/arb040bat/`; единственный
постоянный артефакт — этот файл.

Предмет — дословно из задания: существует ли для ЭТОГО класса риска («что batched-вызов
git действительно вернул бы без батчинга») авторитетный источник/оракул, аналогичный
`git merge-tree --write-tree` арбитража 042; если нет либо непропорционально дорого —

## Замеры арбитра

Собственные toy-репозитории с нуля (хелперы `fixtures/check_zones/_repo.sh`, та же
топология, что у адверсария: зона `agent-x: scripts/`, легитимный коммит в `scripts/`,
нарушающий — в `plans/`). «Новый» = `HEAD` (`f721333`, с фиксами кругов 1–2);
«старый» = `bd2f906:scripts/check_zones.sh` — последняя per-commit форма ДО A2
(`:333` `git log -1 --format='%an' "$c"`, `:472` per-commit `diff-tree`). Git 2.55.

Фактические утверждения адверсария круга 3 подтверждены независимо: 2 из 2 (обе

— оконный rev-list ДО СИХ ПОР глотает rc≠0 в пустое окно (тот же класс, что находка
круга 1, маскирующее направление). Соседние глотания `:313`/`:315`/`:318` при отказе
дают БОЛЬШЕ судимых коммитов, не меньше — немаскирующее направление, не предмет.

## Решение по существу

**Класс «успешный rc не доказывает честность вывода» расщепляется на два подкласса, и
это расщепление — само решение. Оракула в смысле 042 у класса НЕТ и быть не может; у
каждого подкласса есть СВОЁ закрытие, и оба уже существуют в дереве как техника.**

### Подкласс 1 — полнота ДОСТАВКИ (закрывается структурным инвариантом, не оракулом)

Что старый per-commit цикл гарантировал самой формой: каждый судимый ключ получает
ровно один ответ, и ответ атрибутирован этому ключу (вызов именует коммит). Ровно это
— и НИЧЕГО сверх этого — batched-форма обязана доказывать явно (дословно класс А-223).
Это не аппроксимация, которой нужен внешний вычислитель (случай 042): входное множество
материализовано (`$TMP/commits`, `$TMP/matched_commits`), выходной поток несёт ключи —
соответствие множеств проверяет сам потребитель. Для author_map это сделано кругом 2.

Для `paths_raw` блокером была неоднозначность А-223: «SHA без заголовка» неразличимо
между честным пустым/root-коммитом и обрывом. Замер З-A снимает блокер: **`--always`**
печатает заголовок для КАЖДОГО входного SHA, включая root и `--allow-empty`, при этом
пути root-коммита без `--root` не листятся — per-commit семантика «0 путей» сохранена
байт-в-байт, ложных красных на честных пустых коммитах нет. После `--always` рецепт
круга 2 переносится дословно: каждый SHA из `$TMP/matched_commits` обязан иметь РОВНО
ОДИН заголовок в `$TMP/paths_raw` (нехватка, задвоение, лишний — один именованный
fail-closed класс). Судимое множество merge-коммитов не содержит (окно строится
`--no-merges`), поэтому «ровно один» корректно определён. Любая префиксная обрезка
любого из двух batched-потоков после этого красна ПО ПОСТРОЕНИЮ. Находка (б) круга 3 —
в этом подклассе; закрытие обязательно (см. v4-1 ниже).

### Подкласс 2 — ПОДЛИННОСТЬ содержимого (в предмете вывода-арифметики не закрывается вовсе)

Находка (а) круга 3 — из этого подкласса, и по трём независимым замерам он не
закрывается никакой проверкой внутри барьера:

1. **Это не регресс батчинга.** З-B: тот же фальсификатор с константным автором даёт
   то же ложное зелёное против per-commit формы `bd2f906`. Гарантии подлинности полей
   per-commit цикл НИКОГДА не имел — батчинг её не терял, и по определению класса
   А-223 («новую гарантию… которую гарантировал старый per-commit цикл») восстанавливать
   здесь нечего. Находка (а) — факт о барьере при лживом git вообще, не о A2.
2. **Фальсифицируемо само входное множество.** З-D: спай, отфильтровавший нарушающий
   SHA из `rev-list`, даёт rc=0 на ОБЕИХ формах, и сверка множеств круга 2 проходит
   вакуумно — вход и выход лгут согласованно. Любая «проверка полноты вывода» стоит
   НИЖЕ по течению от фальсифицируемого источника; предъявленный round-3a спай — лишь
   один член семейства, у которого есть заведомо более простые члены.
3. **Проверяющий живёт в TCB атакующего.** Сверка множеств — awk/grep/wc, разрешаемые
   из того же враждебного PATH, что и подменённый git (в `check_zones.sh` PATH не
   пиннован — грепом подтверждено, единственные упоминания PATH — в текстах сообщений).
   Спай, подменяющий git, подменяет и awk; доказательство честности инструмента
   инструментами с PATH атакующего циркулярно.

Кандидаты из задания, отклонённые ПО ЗАМЕРУ, а не вкусом:

- **Хеш-/содержимое-адресуемая сверка.** Объектные SHA в выводе печатает тот же бинарь;
  пересчёт требует `cat-file`/`hash-object` (тот же бинарь) либо шелл-реимплементации
  объектной базы (zlib, pack, дельты) — непропорционально и само неаудируемо. И даже
  идеальный сверщик пары `SHA → поля` слеп к З-D: фальсификация происходит во входном
  множестве, где сверять ещё нечего.
- **Перекрёстная выборка случайного подмножества per-commit.** Контрольный per-commit
  вызов уходит в тот же бинарь: спаи З-B и З-C — это ДВЕ половины одного шестистрочного
  спая, фальсифицирующего обе формы согласованно; выборка увидит равенство. Плюс
  недетерминизм в барьере — собственный дефект (невоспроизводимые красные). Отклонено.
- **Частичный возврат к per-commit «для доказательства»** — возврат Н-126 по частям и
  доказательство лжеца лжецом. Отклонено.

**Где закрытие подкласса 2 существует:** не в арифметике вывода, а в границе доверия к
инструменту — и проект эту границу УЖЕ купил один раз: 039 круг 1 (фейковый `comm`) →
доверенный PATH, `check_protected.sh:81` (`export PATH=/usr/bin:/bin` + именные rc=2
пробы утилит). З-E показывает цену и эффект прямо: под тотальным саботажником
check_protected работает как ни в чём не бывало (ноль вызовов спая), check_zones —
падает. **Асимметрия двух барьеров-соседей и есть корень трёхкругового спора: все три
круга (и обе находки круга 3) ездили на PATH-spy — векторе, который у соседнего барьера
мёртв одной строкой с осени 039.** Ответ «принять недоказуемость fail-closed'ом на
подозрении» не принимается в предложенной форме: «подозрение» подкласса 2 внутри
барьера невыразимо (З-D), fail-closed на нём не повесить; вместо этого подкласс целиком
выносится за границу доверия, где он уже решён принятой доктриной.

## Граница v4 (что обязан внести architect, механически)

1. **Доверенный PATH в `check_zones.sh`** — тем же блоком и с той же доктриной, что
   `check_protected.sh:66-95`: `export PATH=/usr/bin:/bin` до первой внешней команды,
   именные rc=2 пробы наличия употребляемых утилит. Санкция на дельту сверх «только
   батчинг» §Инвариантов п.1 — этим решением (прецедент: reglament-krug-4 санкционировал
   правку роли). Это закрывает подкласс 2 и обесточивает PATH-spy как вектор для ВСЕХ
   будущих кругов по этому барьеру.
2. **`paths_raw`: `--always` + сверка множеств заголовков.** Batched-вызов получает флаг
   `--always`; после разбора — сверка: каждый SHA из `$TMP/matched_commits` имеет ровно
   один заголовок в `$TMP/paths_raw`; нехватка/задвоение/лишний SHA — именованный
   fail-closed exit 1 того же класса и той же формы диагностики, что author-guard круга 2.
   Разбор блоков (`/^[0-9a-f]{40}$/`) не меняется — З-A подтверждает формат заголовка.
3. **`:306` — fail-closed.** `|| : > "$TMP/commits"` у оконного rev-list заменяется на
   именованный отказ того же класса, что фикс круга 1 (отказ команды → exit 1 с
   диагностикой, не пусто-зелёное окно). Соседние `:313`/`:315`/`:318` — немаскирующее
   направление, обязательной правки нет; строка комментария о направлении уместна.
4. **Гарды кругов 1–2 остаются** как защита от честных отказов (rc≠0, аварийная
   доставка) — они восстановление per-commit-гарантии, не эпицикл.
5. **Реворк двух spy-фикстур** (`case_batch_avtorov_otkaz.sh`,
   `case_batch_avtorov_obrezka.sh`): после пина их механизм инъекции мёртв, а
   verify_antiplacebo сверяет ПРИЧИНУ красного — в нынешнем виде они сломаются.
   Направление репурпоза — в СТРАЖЕЙ ПИНА, полярность переворачивается: spy присутствует
   в PATH, барьер ОБЯЗАН выдать rc=1 «коммит вне зоны» (спай инертен); мутант, потерявший
   пин, оживляет спая, нарушитель исчезает, красный прогон фикстуры пропадает — ловится
   антиплацебо-протоколом. Тем же паттерном — НОВАЯ фикстура на находку (б): спай
   усечения `diff-tree --stdin` (З-F) + обязательный красный «коммит вне зоны». Оба файла
   — пост-пиновые (`f0b6de6`-пин Р3/Р4 их не держит), правка легальна. Механика — свобода
   architect; требование — красная ветвь называет свою причину правдиво.
6. **Текст остаточного риска.** В шапку `check_zones.sh` — рядом с существующим
   `cognitive-only` риском `user.name` — записывается: подлинность вывода git за границей
   доверенного PATH (подмена `/usr/bin/git`, root-атаки, подпись коммитов) барьером не
   проверяется по построению; ужесточение (signed commits) — словом владельца, как уже
   записано там же. Чек-лист А-223 дополняется: «rc + сверка множеств ключей, И НЕ
   БОЛЬШЕ — подлинность содержимого не предмет вывода-арифметики, предмет границы
   доверия (доверенный PATH)».

Цена решения, названная прямо: пин меняет поведение на машинах с git вне
`/usr/bin:/bin` — та же цена, что уже уплачена check_protected.sh тем же CI (именной
rc=2, не молчание); `--always` — один флаг и ~десяток строк awk, per-commit семантика
не сдвигается ни на путь (З-A); выигрыш батчинга (Н-126) сохраняется целиком — ни
одного per-commit git-вызова не возвращается.

## Счёт сторон

Фактические утверждения адверсария круга 3 подтверждены независимым воспроизведением
2 из 2 (З-C, З-F). Находка (б) — целиком адверсарию: в предмете, закрывается п.2.
Находка (а) — факт адверсария верен, но квалификация «дефект A2-реализации» не
подтверждена замером (З-B: per-commit форма падает так же; З-D: класс не закрывается
внутри барьера вовсе) — закрытие назначено не четвёртой правкой вывода-арифметики, а
переносом границы доверия (п.1), то есть НИ одна из сторон не получила своей формы:
адверсарий — не «доказать полноту сильнее», автор — не «ещё один точечный гард».
Паттерн трёх кругов (каждый фикс закрывает предъявленный вход и оставляет соседа по
классу) подтверждён как epicycle в смысле 042 — и разорван он сменой ВОПРОСА: с «как
доказать, что лжец сказал правду» на «почему лжец вообще отвечает за барьер».
Дополнительный дефект `:306` — арбитра, вне вердиктов сторон. Для контроля асимметрии
семейств: счёт прежних арбитражей 040 — 4/4, 042 — 3/3 не в пользу автора; здесь —
(б) не в пользу автора, (а) — расщеплено по замеру.

Арбитр кода не писал, фикстур не писал, предмет спора не переписывал. Разрешил спор —
дальше работает автор.
