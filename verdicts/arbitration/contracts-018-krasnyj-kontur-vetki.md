## Решение испытанием

### 1. Ядро: два литеральных входа не удерживают объявленный класс — прав критик

И-1 объявляет предикат («последний компонент == committer»), а красным
предъявляет два литерала. Замер 1 показывает: реализация из двух захардкоженных
чекаутов проходит приёмку целиком. Критерий, который зелен у литералов и у
предиката одинаково, предметом не управляет. Красный контур ОБЯЗАН нести
независимые границы предиката.

### 2. Обязательный набор входов (исполнять архитектору)

Правило отбора — по одному красному свидетелю на каждую ВЕТВЬ РЕШЕНИЯ
запинованного предиката плюс по одному на каждый ИЗМЕРЕННЫЙ класс срезания:

| Вход (своя `wip/018/implementer` жива, автор implementer) | Ветвь предиката / класс срезания | Статус |
|---|---|---|
| Р1: чекаут `main` | именованная ветка БЕЗ префикса `wip/` | есть (`case_vetka_rabochij_na_main`) |
| Р2: чекаут чужой точной `wip/018/architect` | `wip/`-ветка, последний компонент != committer | есть (`case_vetka_chuzhaja_wip`) |
| Р3: detached HEAD (`symbolic-ref` отказывает) | ветки НЕТ вовсе — отдельный путь кода | ДОБАВИТЬ: новый case, красный вход — detached при живой своей wip |
| Р4: чекаут чужой `wip/018/implementerXyz` (имя committer — СОБСТВЕННАЯ подстрока последнего компонента) | срезание операции сравнения: подстрока/глоб вместо равенства компонента (замер 4) | ДОБАВИТЬ: новый case |
| З1: СВОЯ `wip/<другой NNN>/implementer` (напр. `wip/019/implementer`) | зелёная граница: «своя» при ЛЮБОМ NNN (замер 5) | ДОБАВИТЬ зелёным контролем |

Р3 и Р4 взаимно НЕ заменимы: плацебо-подстрока (замер 4) переживает
detached-вход и гибнет только на Р4; плацебо-литерал (замер 1) гибнет на любом
из них, но выживание №4 доказывает, что «третьей точки вообще» недостаточно —
нужна именно граница операции сравнения.

### 3. Упаковка — по измеренной семантике раннера (замер 3)

- Каждый из Р3 и Р4 — ЕДИНСТВЕННЫЙ красный вход СВОЕГО case-файла
  (`case_vetka_*.sh`, имена — архитектора). Дописывать их красными в
  существующие case ЗАПРЕЩЕНО: раннер энфорсит один красный кандидат на case, а
  промахнувшийся красный молча идёт в зелёные контроли — замер 3 показал rc 0
  такой упаковки при живом плацебо.
- З1 — ЕДИНСТВЕННЫЙ положительный контроль ХОТЯ БЫ ОДНОГО из новых case (напр.
  зелёный контроль case Р3). Причина той же семантикой: ложно-красный зелёный
  вход неотличим для раннера от легитимного красного кандидата, и лишь когда он
  один, его гибель валит case «нет положительного контроля». В case, где З1 —
  единственный зелёный, плацебо-NNN (замер 5) гибнет именно так.
- Оба новых case — той же дисциплиной «красное сейчас»: до реализации стража
  scoped-команда обязана давать rc 1 «красное не предъявлено» (страж отсутствует
  → красный вход зелен), после — rc 0.

### 4. Носитель критерия: фикстуры И текст И-1 — обе зоны architect

Привязка входов к стабам остаётся по коду фикстур (Н-39, :127-128), но И-1
называет rc-команды по-стабно — значит текст И-1 (и разделы «Красное сейчас» /
«После реализации») ДОПОЛНЯЕТСЯ двумя scoped-командами новых case тем же
форматом, что существующие две. Красный контур без rc-команды в инварианте —
невидим приёмке; rc-команда без фикстуры — пустая проза. Носят оба артефакта,
оба в зоне architect (`contracts/018-vetka-na-agenta.md`,
`fixtures/check_staged/`).

### 5. Формула стража — архитектора; реализация — implementer

Прототипы этого арбитража (вставки в `check_staged.sh` клона) — измерительные
стенды, НЕ предписанный код. Предикат запинован текстом v2 (:46-52) и не
меняется; место ветви, текст отказа (кроме подстроки-литерала `вне своей ветки
wip/`) и способ чтения ветки — детали реализации implementer после заморозки,
как и записано в §Незаполненные. Замер 2 удостоверяет: требуемые исходы
достижимы одной ветвью без изменения остального судьи.

## Границы (что НЕ требуется — standard-A)

- **Полнота «всех мыслимых веток» НЕ требуется.** Любой конечный набор фикстур
  проходим перечислением его точек — расширение набора не рождает интенсионал.
  Правило остановки: по одному свидетелю на ветвь решения предиката и на
  измеренный класс срезания. При четырёх красных точках честный предикат уже
  строго дешевле перечисления (замер 2: одна `case`-ветвь против растущего
  списка литералов); дальнейшие точки покупают только цену, не класс.
- `feature/x` («иной branch») отдельным case НЕ обязателен: его ветвь решения —
  «именованная ветка без `wip/`» — уже несёт свидетеля `main`, и честный
  предикат замера 2 краснит его тем же путём кода. МОЖНО добавить, требовать —
  нельзя (расширение без нового класса срезания).
- Плацебо, перечисляющее ВСЕ входы всех фикстур, остаётся проходимым по
  построению — класс cognitive-only, держится чтением закоммиченного кода двумя
  ролями (та же граница, что у канарейки 016, РЕШЕНИЕ 67fb3b1 §(а)).
- Не требуются: красные нескольких NNN сразу, юникод/омоглифы имён веток за
  пределами класса подстроки, различение worktree-чекаутов при равной ветке,
  кросс-NNN энфорсмент (закрыт §Незаполненные (Q3) как спавн-время).
