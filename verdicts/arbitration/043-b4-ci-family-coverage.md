## Решение по существу

**Прав критик. CI-self-gate НЕ достаточен вместо семейной CI-приёмки Р10/Р11 — не
частично, а структурно.** Три основания, каждое измерено:

1. **Исключение п.3.0 гарантирует, что self-application НИКОГДА не исполнит
   задачу (б) для собственной семьи** — это не случайный пробел покрытия, а
   постоянное свойство конструкции, названное самим контрактом и подтверждённое
   stderr шага (З3). Единственный precision-шаг CI исполняет только зелёные пути
   задач (а)/(в) на реальном дереве; ни один из девяти красных путей гейта CI не
   проходит никогда.
2. **З4 предъявляет ровно то, что критерий обязан отличать: CI как проведён сейчас
   остаётся зелёным на дереве, где замыкания Б2/Б3 круга 1 удалены.** Оплаченная
   двумя кругами работа регрессирует молча. Комментарий CI-шага (:211-212 —
   «фикстуры contracts/043-* (Р10/Р11) уже доказывают самодостаточность гейта»)
   апеллирует к командам, которые CI не исполняет: заявление без исполнителя.
   Правило 6 AGENTS.md, заглавие: «Гейт, который зеленее CI, — не гейт».
3. **Прецедент решён репозиторием дважды в этом же архитектурном классе.**
   038: раннер `_krasnye_038.sh` «жив и зелен, но не подключён» (ревьюер, Р2) →
   отдельный прямой шаг «Сам-тесты семьи ПРОВОДКА» вне case_*-глоба. 041: прямой
   шаг «Сам-тесты барьера check_threat_model» (`npm run check:threat-model-selftest`).
   Контракт 043 сам цитирует в §Предмет чекпойнт #11 («37/67 красной пачки не
   подключены к CI») как мотивирующую историю — оставить красную пачку СОБСТВЕННОГО
   гейта неподключённой значит воспроизвести дефект-класс, ради убийства которого
   контракт написан.

## Техническое решение (обязательное, форма — по живому прецеденту 038/041)

1. **`package.json`** — два новых статичных ключа, значения ПОБАЙТОВО равны
   командам Р10/Р11:
   - `"check:precision-family-selftest": "bash fixtures/_krasnye_043.sh"`
   - `"check:precision-battery": "bash fixtures/parsing_hygiene_battery/run_battery.sh check_precision_gate"`
   (точные имена — широта implementer'а; статичность имени и побайтовое равенство
   значения команде приёмки — обязательны, правило 6 / :1062 verify_ci_parity.sh).
2. **`.github/workflows/ci.yml`, job `ci`** — прямой шаг (или два) ВНЕ
   антиплацебо-матрицы, рядом с существующим «Пре-фриз precision-гейт (контракт
   043)», по образцу «Сам-тесты семьи ПРОВОДКА (контракт 038)»:
   `run: npm run check:precision-family-selftest` и
   `run: npm run check:precision-battery`. Ключ `check_precision_gate` в `keys:`
   шардов НЕ вносится (`.probe-only`-семья без `case_*` сломала бы ап-шаг —
   verify_ci_parity.sh:1145-1147). Запись в `config/ci_parity_exceptions.txt` не
   нужна: `npm run <имя>` покрыт правилом 6, тот же случай, что
   `check:provodka-family-selftest`. Цена измерена: 8.5 с + 4.6 с — дешевле
   соседнего шага сам-тестов антиплацебо (52 с).
3. **Контракт** — §Приёмка получает пункт (следующий свободный Р-номер),
   исполняемой командой доказывающий проводку: `grep -Fq` обеих строк
   `npm run check:precision-…` в `.github/workflows/ci.yml` И обоих ключей со
   значениями в `package.json` (та же дисциплина дословности, что Р12/038/041
   несут для своих ПРОВОДКА-строк). После приземления пары ключей паритет 020
   сам начинает стеречь их живость в CI («приёмка не богаче CI» — мёртвый ключ
   красен), то есть связка самоподдерживающаяся.
4. **Комментарий CI-шага :203-212** приводится в соответствие: ссылка «Р10/Р11 уже
   доказывают» либо заменяется ссылкой на новые шаги, либо убирается — комментарий
   не имеет права утверждать исполнение команд, которых workflow не содержит.

Сам шаг `npm run check:precision-gate` ПРАВИЛЕН и остаётся: это непрерывная форма
Р13 (self-application на живом дереве), критик его и не оспаривал. Решение —
дополнение, не замена.
