## Решение по существу: поканальный патчинг ПРЕКРАТИТЬ, недоверие окружению — ЦЕЛИКОМ

**Кто прав.** Адверсарий прав по всем четырём векторам круга 4 фактически
(замер 1, все живые до done-тега) и прав методологически ВТОРОЙ РАЗ: круги 5–8
закрывали предъявленный канал (парсер, TOCTOU, PATH-каталог, FIFO), а класс —
«унаследованное окружение процесса» — оставался открыт соседним каналом.
`export PATH=...` автора корректен против своего вектора, но PATH — лишь один
из каналов окружения; экспортированные функции, IFS, локаль, BASH_ENV — другие
каналы ТОГО ЖЕ класса. Кандидат оркестратора отклонён замером 2: очистка
функций инструментами, которые сами перекрываемы функциями, циклична.
Закрывается класс только тем, что скрипт НЕ ДОВЕРЯЕТ унаследованному environ
НИ В ЧЁМ и строит себе канонический environ сам, пользуясь до этого момента
ТОЛЬКО неперекрываемыми примитивами bash.

**Механизм (обязательная формулировка).** ПЕРВЫМИ исполняемыми строками
`scripts/check_provodka.sh` (ДО `set -uo pipefail`, до определения любых
функций — гард обязан исполниться раньше всего, что атакующий может затенить)
вставить дословно:

```bash
if [[ "$(/usr/bin/tr '\0' '\n' < /proc/$$/environ)" != $'PATH=/usr/bin:/bin\nLC_ALL=C.UTF-8' ]]; then
  POSIXLY_CORRECT=1
  exec /usr/bin/env -i PATH=/usr/bin:/bin LC_ALL=C.UTF-8 /usr/bin/bash "$0" "$@"
fi
```

Каждый токен несёт нагрузку; при реализации НЕ заменять:

- **Точное равенство environ, не маркер и не скан-блэклист.** Маркер-переменную
  («я уже чистый») атакующий подделает ВМЕСТЕ с атакой; перечисление опасных
  переменных (`BASH_FUNC_*`, `BASH_ENV`, `SHELLOPTS`, …) — тот же несходящийся
  блэклист, уже дважды похороненный на этом файле. Совпадение environ с
  каноном байт-в-байт означает: постороннего входа НЕТ, атаковать нечем;
  несовпадение — re-exec с каноном. Третьего состояния нет.
- **`/proc/$$/environ`** — первичный environ процесса на момент exec (ядро),
  не изменяемое представление шелла; читается редиректом (неперекрываем) и
  `/usr/bin/tr` по slash-пути.
- **Slash-пути `/usr/bin/tr`, `/usr/bin/env`, `/usr/bin/bash`** — имя команды
  со слешем НЕ проходит function lookup вообще (семантика bash): поддельные
  функции `tr`/`env` невызываемы (замер 3).
- **`POSIXLY_CORRECT=1` отдельным присваиванием СТРОКОЙ ВЫШЕ `exec`.**
  Присваивание неперекрываемо; оно немедленно включает POSIX-режим, в котором
  special builtins (в т.ч. `exec`) ищутся РАНЬШЕ функций — иначе
  экспортированная `exec() { return 0; }` съедает re-exec и скрипт продолжает
  жить во враждебной среде (замеры micro1 и V5). POSIX-режим живёт только в
  заменяемом образе: `env -i` не передаёт переменную в чистый образ, семантика
  остального файла не меняется.
- **`env -i`** — replace, не append: `BASH_FUNC_*%%` умирают ВСЕ разом,
  поимённо никто не перечисляется; вместе с ними PATH, CDPATH, GLOBIGNORE,
  IFS, BASH_ENV/ENV, SHELLOPTS/BASHOPTS, локаль, GIT_* — весь класс одним
  свойством. Re-exec без `-i` недостаточен (замер: `exit` остаётся функцией).
- **Порядок `PATH=… LC_ALL=…` в `env -i` обязан совпадать с порядком в
  сравниваемом литерале** — иначе вечный re-exec. Замер: ровно один re-exec,
  затем прямой прогон; при точном чистом запуске — ноль.
- **`LC_ALL=C.UTF-8`** — детерминизм инструментов вместо локали вызывающего
  (враждебная локаль — тот же класс); на glibc без C.UTF-8 деградирует в C,
  байтовое сравнение литералов «»/§ (`grep -F`, `sed`, `awk ==`) не меняется —
  фикстуры 31/31 зелёные под этим значением (замер 4).
- **Условие в `[[ … ]]`** — reserved word, неперекрываемо; внутри `[[` нет
  word splitting — враждебный IFS бессилен (замер V7).

**Сопутствующее (право, не обязанность).** Блок `export PATH=/usr/bin:/bin`
круга 8 после гарда избыточен (PATH уже канонический в обоих исходах гарда):
реализатор ВПРАВЕ снять его, перенеся ссылку на прецедент
`check_consumers.sh:41`/`check_protected.sh:81` в комментарий гарда, ЛИБО
оставить — но тогда комментарий обязан отражать, что первичная защита — гард.
Строки git-гигиены шапки не трогать (вне предмета). Существующая инвокация
всех вызывающих (`bash scripts/check_provodka.sh <корень> <контракт>` /
`bash "$REPO/scripts/check_provodka.sh" …` — фикстуры, done_contract, CI)
совместима: `$0` — путь к файлу, cwd сохраняется exec'ом, rc пробрасывается
заменой образа (батарея V8–V10).

**Семантические следствия (решены, не переоткрываются):**

1. Маскирование `exit` внутри `die()` закрыто ТЕМ ЖЕ механизмом (V4) —
   отдельного фикса `die()` не требуется и НЕ вносить (поканальность).
2. Отсутствие `/usr/bin/env`, `/usr/bin/bash` или `/usr/bin/tr` → гард
   отказывает, bash выходит с rc ≠ 0 (127) — fail-closed вне контракта 0/1/2
   ровно в том случае, когда отсутствует сам доверенный тулчейн; это ТО ЖЕ
   допущение, что уже несут PATH-пиннинг круга 8 и `/proc`-зависимость
   атомарного fd круга 6. Новым допущением не является.
3. Запуск канонический — по пути файла (`bash scripts/check_provodka.sh …`);
   запуск телом через stdin (`bash < script`) не поддержан, в дереве не
   используется, поддержки не добавлять.
4. Точный повтор канонического environ атакующим — НЕ обход: в таком environ
   нет носителя атаки по построению (V8: красный вход → rc 1).

## Граница модели угроз (обязательная; останавливает регресс)

Симметрично §5 первого арбитража. Барьер защищается от всего, что действует
ЧЕРЕЗ исполнение его собственного текста. Барьер НЕ защищается — и дальнейшее
харднение этого файла НЕ ТРЕБУЕТСЯ и не принимается как FAIL предмета — от
атак, отменяющих честное исполнение его текста ДО первой строки или подменяющих
сам субстрат исполнения:

- `SHELLOPTS=noexec` (замер 5: rc 0, тело не исполняется вообще);
- `BASH_ENV`/`ENV` с кодом, выходящим/саботирующим шелл до тела скрипта
  (замер 5: rc 0; вариант с `enable -n exec` — произвольный код в процессе
  до гарда, та же категория);
- подмена `/usr/bin/bash`, `/usr/bin/env`, `/usr/bin/tr`, содержимого
  `/usr/bin`,`/bin`, `/proc`; LD_PRELOAD на сам вызывающий процесс; ptrace;
  namespaces/chroot вокруг запуска; ядро; подмена самого файла скрипта.

Основание: текст внутри файла по определению не может защитить от рантайма,
который отказывается этот текст исполнять; атакующий с довыполненческим кодом
от имени вызывающего пользователя равно может не запускать барьер или
сфабриковать его rc. Единственное место, где этот остаток закрывается, —
сторона ВЫЗЫВАЮЩЕГО (инвокация барьеров через
`/usr/bin/env -i PATH=/usr/bin:/bin LC_ALL=C.UTF-8 /usr/bin/bash scripts/…`
в `.githooks/`/CI); делать ли это — отдельный предмет и приоритет владельца,
НЕ контракт 038 и НЕ основание для круга 5 по этому файлу. Адверсарские
находки внутри очерченного остатка по этому предмету не принимаются;
предъявление — ссылкой на этот раздел.
