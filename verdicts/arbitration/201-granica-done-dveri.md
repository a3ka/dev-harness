## РЕШЕНИЕ 1 — связь OBJECT с реализацией при F==CID

**Критик прав; исправить способом канон/инструмент.** Один предок F может быть состоянием до реализации. Именование этого известного обхода в НЕ ЗАЩИЩАЕТ не исполняет обязательство владельца. Автор прав только в требовании не отвергать честное равенство F==CID автоматически.

Конечный достаточный критерий для локального OBJECT:

- Оставить выбор vmax, чтение peeled F, грамматику OBJECT и обязательную свежесть F ⊆ CID.
- Для F строго раньше CID сохранить F ⊆ OBJECT. Это связь с версией; содержательную полноту реализации всё равно удостоверяет reviewer, а не ancestry.
- Для F==CID вместо одного OBJECT ⊆ F требовать одновременно OBJECT ⊆ F **и тождество Git-деревьев OBJECT и F за вычетом только точных файлов судебных свидетельств этого предмета**. Минимальный вычет — выбранный reviewer-файл; для рискового предмета допустим также выбранный, уже проверенный accept-файл adversary на тот же OBJECT. Не весь verdicts/, не все Markdown, не ЗОНА, не произвольный список от вызывающего. Пути берутся через workflowPaths и действующий выбор вердиктов; вычитаются именно файлы свидетельств, не каталоги и не symlink-переходы.
- Тождество означает те же пути, типы/mode и Git object IDs всего остального дерева, включая контракт, исполняемые файлы, удаление файлов и gitlinks. Канон — Git tree/diff plumbing с отключёнными external diff/textconv и без rename-эвристики, не содержательный парсер исходников. Нечитаемый объект/сравнение не даёт rc 0.
- Нарушение связи или непроверяемое свидетельство — именованный отказ до done-тега. Для расхождения содержимого годится уже введённая причина «OBJECT … не связан с последней заморозкой …»; ошибку Git нельзя назвать доказанным равенством.

Почему этого достаточно: [INFERENCE] при тождестве проекции всё несвидетельское содержимое F уже имеется в судимом OBJECT. В мире B→I→F код I отсутствует в B, поэтому сравнение не пусто. В честном I→F с добавлением review сравнение пусто; F==CID само по себе не отказ. Историческое наличие I без сохранения его содержимого не является доказательством реализации: сравнивается состояние, а не имя коммита.

Если **сам F добавляет реализацию**, которой нет в OBJECT, старый OBJECT не судил эти байты. Принимать такой вердикт нельзя: нужен суд на объекте, уже несущем реализацию, и последующая запись его вердикта. Требование записать собственный будущий SHA в тот же коммит не вводится. Если вместе с вердиктом изменены иные файлы, эта короткая форма доказательства неприменима; законный путь — свежий вердикт на полном объекте после F, не расширяемый список игнорируемых файлов. Это консервативная проверка доказательства, а не разрешение урезать обязательства.

Архитектор закрепляет положительную клетку равенства, отрицательную с OBJECT до I и отрицательную с изменением реализации непосредственно в F. Батарея должна отличать настоящий tree-критерий от прежнего ancestry-only и проверять rc/причину/отсутствие тега. Привязки стабов к ветвям — исключительно в коде architect, не в тексте контракта и не этим вердиктом.

## Остаточный риск с ловцом

Готовые строки для модели угроз после исправления:

- НЕ ЗАЩИЩАЕТ: Git-достижимость и тождество дерева не доказывают семантическую полноту реализации требований последней заморозки; ложный accept этапа вместо целого предмета ловят reviewer и, для рискового предмета, adversary на том же OBJECT, с предметными проверками CI.

## Заморозка

**201 остаётся незамороженным.** Требуются исполнение решений, отдельная санкция владельца на третий узкий вызов, accept критика на исправленный OBJECT, закоммиченный арбитраж и все штатные гейты/проводка. Отсутствие санкции нельзя заменить resolved, ссылкой на общий кап или истечением времени. Арбитр не ставит frozen/done-теги и не публикует ветку.
