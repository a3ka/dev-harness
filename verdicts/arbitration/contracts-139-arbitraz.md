## Решение по вопросу 2 — оси замыкания и «закрыто по построению»

**(а) Оси.**

- **СТРУКТУРА — канон скрипта (главная ось, закрывает класс по построению).** Новая ось статики `skript`: нормализованное тело `run:` субъекта (разобранное YAML-значение; строки `strip()`; пустые и начинающиеся с `#` выброшены) равно построчно нормализованному телу модели. Отказ именованный с адресом: `SKRIPT_RASHOZHDENIE: строка N: <строка субъекта>` (либо `…: строк M, в каноне K`). Канон скрипта делает класс «скрытый путь внутри шага» пустым множеством: любая ветвь, любая конкатенация, любой тэлл песочницы — чужая строка кода. Прежний `os_rerun` ОСТАЁТСЯ как дешёвая ступень с именованными диагнозами (`RERUN_RASHOZHDENIE`/`SKRITYJ_VYZOV`/`SETEVOJ_VYZOV` объясняют, ЧТО не так, тогда как `SKRIPT_RASHOZHDENIE` говорит только ГДЕ), но перестаёт быть единственной. Инвариант «ровно один `gh run rerun --failed "$RUN_ID"`» — следствие канона, не самостоятельная защита.
- **ОКРУЖЕНИЕ — replay в двух окружениях.** Каждый replay-вход прогоняется дважды: `CHISTYJ` (как сейчас) и `ACTIONS` — поверх текущего env: `GITHUB_ACTIONS=true`, `CI=true`, `GITHUB_RUN_ID`, `GITHUB_RUN_ATTEMPT=1`, `GITHUB_RUN_NUMBER`, `GITHUB_WORKFLOW=mobile-e2e-retry`, `GITHUB_JOB=retry`, `GITHUB_EVENT_NAME=workflow_run`, `GITHUB_EVENT_PATH` (файл с JSON события кейса), `GITHUB_SHA`, `GITHUB_REF`, `GITHUB_ACTOR`, `GITHUB_API_URL=https://api.github.com`, `GITHUB_SERVER_URL`, `GITHUB_WORKSPACE`, `GITHUB_TOKEN` (= тот же тест-токен, что `GH_TOKEN`), `RUNNER_OS=Linux`, `RUNNER_ARCH=X64`, `RUNNER_NAME`, `RUNNER_TEMP`, `ACTIONS_RUNTIME_TOKEN`. Оракул кейса один для обоих окружений; расхождение — обычные `RC/STDOUT/VYZOVY_RASHOZHDENIE` с префиксом окружения в строке CASE (`CASE <вход>@ACTIONS …`) либо отдельный диагноз `OKRUZHENIE_RASHOZHDENIE`. Назначение оси — честно названное: (i) доказывает env-инвариантность САМОЙ МОДЕЛИ (канон, который implementer скопирует, проверен в окружении, где будет жить); (ii) даёт ПОВЕДЕНЧЕСКИЙ красный свидетель для свидетеля критика (стаб со скрытой env-ветвью красен не только статикой, но и `VYZOVY_RASHOZHDENIE`/rc 127 в `@ACTIONS`). Ось окружения — НЕ замыкание класса (замер 4–6) и в контракте так и называется.
- **ВЫЗОВЫ — закрытый алфавит argv подложного `gh` и утилит PATH.** SHIM_PY принимает ровно три формы argv и ничего сверх: `api repos/<o>/<r>/actions/runs/<id>/jobs --jq <фильтр из алфавита>`, `api repos/<o>/<r>/actions/jobs/<id>/logs`, `run rerun --failed <id>`; любой лишний/иной аргумент (`-X`, `--method`, `-f/-F/--field/--raw-field/--input/-H/--hostname/--paginate`, лишние позиционные, `rerun` без `--failed`) — `VNE_ALFAVITA` rc 127 (замер `shim_f.py`: `api …/jobs -f x=1 --jq …` сейчас записывается как `API_JOBS` и получает ответ GET — алфавит не замкнут по argv). PATH replay — ТОЛЬКО каталог шима, в котором лежат симлинки на утилиты алфавита скрипта `{bash, sed, grep, tr, mktemp, rm}` (printf/echo/trap/test — builtins); `curl`, `wget`, `python3`, `node`, `env`, `xargs`, `sh` недоступны → `command not found` rc 127 → `RC_RASHOZHDENIE`. Это измеренный факт «закрытого алфавита утилит» вместо прозы. Утечку `SCENARIJ_*` в env скрипта устранять НЕ требуется — при каноне скрипта тэллы песочницы бессмысленны; факт утечки записать в §НЕ ЗАЩИЩАЕТ как пример, почему ось окружения не замыкает.

Мой вердикт accept не даёт и не заменяет; при FAIL вызова 3 по пунктам (i)–(vi) — не круг 4, а возврат к арбитру с конкретной строкой перечня (невыполнение решения, не новый спор); при FAIL по новому основанию вне перечня — К ВЛАДЕЛЬЦУ (бюджет исчерпан, второй арбитраж на предмет уставом не предусмотрен).
4. Затем implementer (файл в репо продукта), reviewer один вызов, merge, живой ловец.

## Формулировка для §НЕ ЗАЩИЩАЕТ (дословно)

> - исполнение открытого языка: replay судит скрипт на конечном множестве входов и в двух окружениях (`CHISTYJ`, `ACTIONS`) — ветвь, различающая песочницу и живой раннер (переменные Actions, утечка `SCENARIJ_*` в env скрипта, run_id вне оракула, природа бинаря `gh`, время), по построению может не исполниться в replay; замер арбитража 139: 3 из 6 таких форм зелёные в обоих окружениях. Класс закрыт не наблюдением, а грамматикой — канон скрипта (`struktura-skript`: тело `run:` построчно равно модели, комментарии/формат свободны); ось окружения доказывает env-инвариантность самой модели и даёт поведенческий свидетель, замыканием класса не является;
> - живой `gh`/GitHub API: подложный `gh` моделирует ответы и записывает argv; реальный исход `rerun-failed-jobs` не измерен; ловец — первый реальный инфра-флейк после merge: в истории run-а ровно один rerun failed jobs и строка `POVTOR:` в логе job-а `retry`; чистый провал — `SKIP:` без rerun; наличие `gh` на раннере и политика прав — ПРЕДПОСЫЛКИ.

## Решение по вопросу 4 — что владельцу, что инженерно

Инженерно, решено этим вердиктом и исполняется сторонами: блокер 2/2 настоящий, класс тот же, что А; конечная граница класса — канон скрипта (грамматика), оси окружения/вызовов — ступени наблюдаемости, не замыкание; перечень A–G закрыт; предмет исправительного вызова ограничен (i)–(vi). Основание — замер 1–6 и `kanon.py`, воля владельца о форме («форма — отдельный workflow … `gh run rerun --failed`», код шага у implementer собственной ценности не имеет), метод арбитражей 116 v3/136 v2/138 (сверх-приближение открытого языка + наблюдаемость + остаток с ловцом; здесь остаток класса сведён к нулю, потому что грамматика замыкается, — в 138 она не замыкалась).

Владельцу (не решается здесь):
1. **Цена**: один вызов критика сверх бюджета 2/2 — уже разрешён словом 25.10; дополнительных вызовов решение не требует. Правка автора — в своей зоне, своим бюджетом.
2. **Принятие остатка живого API** (§НЕ ЗАЩИЩАЕТ): первый реальный флейк после merge в main продукта — единственный свидетель фактического `rerun-failed-jobs`; до него корректность повтора доказана только подложным `gh`. Инженерная оценка: риск низкий — ветвь детерминирована, канон скрипта исключает иные пути, худший исход — один лишний повтор на self-hosted раннере либо отсутствие повтора с именованным `command not found` в логе `retry`.
3. **Независимость по трейсу**: оба критика отметили — фактическая модель автора (`history://Architect139`) не выведена; до спавна вызова 3 оркестратор обязан сверить фактический трейс автора (autoFallback на Sol делает critic-sol недопустимым судьёй) — это устав, не воля, но назначение модели судьи при коллизии — решение владельца/оркестратора, не арбитра.
4. **Класс риска «обычный»** подтверждаю инженерно; если владелец хочет adversary на реализацию одного файла workflow — это его деньги, инженерного основания нет.
