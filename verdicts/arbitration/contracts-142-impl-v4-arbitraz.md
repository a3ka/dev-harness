usp  LC_ALL=C            rc=1 calls=0             usp  LC_ALL=en_US.UTF-8  rc=0 calls=1

## Решение по Q1

**Достаточно ОДНОЙ клетки на форму адреса с ПОЛНЫМ классом в одном токене; развёртка «по байту на клетку» (≈232 запуска двери, +~75 с CI) не нужна — она не ловит ничего сверх и платит за каждый байт отдельным миром.** Закрывающее свойство формулируется так: *токен authority, составленный из ВСЕХ байтов канон-класса (порождён в раннере как дополнение запрещённого множества, не набран перечнем), под порождённым адресным именем, значение в индексируемом файле → rc 1 `sekret-v-dereve`, 0 запусков workshop, значение в отказе не печатается; в обеих URL-формах.* Мутант «исполняемый класс уже канона на любом байте/подклассе» при этом красен по построению; серия «ещё один символ» закрыта, потому что множество конечно (116 инвариантных байтов) и ВСЁ оно в одном значении.

Состав развёртки (ЗАМКНУТЫЙ перечень клеток; ожидание — из канона/модели, проверено `--model` в C и en_US.UTF-8: 158/158 оба):

|---|---|---|---|
| k121-token-ves-klass | `https://T@host.test/p`, T = все байты 0x01..0x7F ∖ {09 0A 0B 0C 0D 20 23 2F 3F 3A 40} (116) + `éЖ中😀`; значение в leak.txt | token (rc 1, calls 0, TOKZN не в отказе) | исключение любого байта/подкласса в токен-ветви, форма со схемой |

Почему именно так (каждый пункт — замер или вывод из канона):
- `:` исключён из T: для ЛЮБОГО класса токен-ветви значение `https://tok:x@host` судится двоеточие-ветвью (`[^/@[:space:]]*:[^/@[:space:]]*@` матчит `tok:x@`; замер: мутант-класс без `:` → rc 0 матча), т.е. исключение `:` из класса токена не fail-open и мутантом неразличимо; `@` — терминатор. Из U исключён `:`, чтобы единственное двоеточие было разделителем: иначе узкий мутант класса pass/user мог бы выбрать внутреннее `:` и матчить хвост без «запрещённого» байта — цель клетки (все байты в user И в pass) потерялась бы; исключение `:` из классов двоеточие-ветви тоже не fail-open (`a:b:c@` матчится при любом выборе двоеточия).
- T/U порождаются в раннере циклом по 0x01..0x7F с `case`-исключением запрещённого множества (прототип: `ves_klass_tok`, `ves_klass_dvoet`) — тогда «класс» определён каноном (дополнение `/ ? # [:space:]` + терминатор `@` + нейтральный `:`), а не рукой, и адверсарию нечего предъявить «ещё один символ»: его там нет по построению. Многобайтные UTF-8 — четыре представителя длин 2/3/4 байт; одиночные байты 0x80..0xFF и Unicode-пробелы НЕ входят (замер 1: ожидание канона локале-зависимо).
- Двоеточие-ветвь со схемой (`https://U:U@…`) не нужна: ветвь не зависит от `//`/схемы (мутант «только после схемы» — существующий стаб `dvoetochie-posle-shemy`, пойман на z6/k32…); проверено матрицей: `colon-https` ведёт себя как `colon` на всех дверях.
- Границы `/ ? #` уже закрыты k102 (`/`), k104 (`?`), k105 (`#`) и якорь — k108–k110 (стабы `token-gde-ugodno`, `token-bez-granicy`, `token-bez-yakorya`); пробельные — нет (мутант `[^/?#]+` проходил все 154 клетки: матрица, `granica` до правки нечем ловить). Пять строк в одном доме достаточно: ожидание «сессия» композитно (любая судимая строка → отказ → красна).
- Q1(в) имя ключа/маркеры/суффиксы — ВНЕ класса B2/B3 («исполняемый предикат ЗНАЧЕНИЯ при канон-литерале»): имена k19–k98 порождаются (закрыто арбитражем `contracts-142-arbitraz.md`), алфавиты маркеров и суффиксов конечны и покрыты по элементу (k1–k18, k19–k30). Изменений не требуется — принятый остаток не возникает.

Стоимость: +4 клетки ≈ +1.5 с на прогон (замер прототипа: `--model` 158 клеток — та же ~50 с).

# Принятые остатки (названы честно; в доклад architect)

- **Локале-зависимые байты канона**: одиночные 0x80..0xFF и Unicode-пробелы (U+2003, U+3000…) в токене/user/pass — под en_US.UTF-8 (станция) честная модель НЕ судит (сессия при утечке), под C — судит. Замер 1 и пробы `hi`/`usp`. Не предмет 142 (текст локаль не задаёт; канон — ERE в локали процесса); реальные учётные данные таких байтов не содержат. **К ВЛАДЕЛЬЦУ** (черновик): пин `LC_ALL=C` для grep предиката — правка зоны implementer и модели (v+1), либо запись остатка.
- Позиционные предикаты (ограничение ПЕРВОГО/ПОСЛЕДНЕГО байта токена, напр. `[A-Za-z][^…]*`): T начинается с 0x01 и кончается 4-байтным UTF-8 — мутант «первый байт — буква» ловится, но «первый байт ≠ `"`» — нет; семейство бесконечно (позиции × байты), развёртка по байту на клетку его тоже не закрывает.
- Верхняя граница длины токена (`{1,N}`, N ≥ 128): T — 127 байтов; ловится при N < 127.
- Контекстные предикаты (запрет пар байтов), сужение класса СХЕМЫ (`[^/?#[:space:]]*:` → `[a-z]+:`): для реальных схем не fail-open.
- Конструкция `! printf | grep -Eq`: ошибка grep (rc 2, напр. невалидный диапазон в локали) = «не userinfo» = fail-open; на канон-строке недостижимо, проявляется только у мутантов (замер `mut-ascii`/UTF-8).
- Неполнота привязок существующих стабов (напр. `token-tolko-https` красен на k114/k118/k120, привязан к k101): раннер не проверяет «ровно»; не предмет спора — замечание architect.
