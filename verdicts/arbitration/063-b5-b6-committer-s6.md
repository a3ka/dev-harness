## Замеры

1. **Б5: обход воспроизведён настоящей клеткой к8 (замер A).** Одноразовый скрипт
   источает декларации батареи `:1-446` без изменений (тот же `mkt` с
   `user.name=Fixture`, тот же `k8`, `chk_rc0`, `run_land`) и подставляет в `$LAND`
   стаб: гейт, скопированный из s3 батареи, + `git merge --no-ff -m "land: $BR" "$BR"`
   без `-c user.name`. Вывод:
   `ok к8: ленд зелёного входа rc 0` /
   `ЗАМЕР A … клетка rc=0; committer(HEAD)=Fixture; полей родителя=3`.
   Утверждение критика верно: все предикаты к8 удовлетворены при committer ≠ orchestrator.
   Это не «часть» обхода, а весь обход по клетке: остальные клетки land (к9) и стаб s3
   identity не наблюдают вовсе (s3 сам ставит identity оркестратора, `:542`, и ловится
   только счётом родителей — замер D ниже).
2. **Б5: предлагаемый предикат различает (замеры B/C/D).** Та же к8 + одна строка
   `[ "$(git log -1 --format=%cn HEAD)" = orchestrator ]`: против стаба без identity —
   `FAIL к8: committer merge-коммита «Fixture» ≠ «orchestrator» (И-7)`, rc 1 (B); против
   честного минимума (identity литералом + `--no-ff`) — rc 0, `committer(HEAD)=orchestrator`
   (C); против ff-обходчика с identity — rc 1 на счёте родителей, как и раньше (D): новый
   предикат ничего существующего не ломает.
3. **Б5: дублирования И-9 `land_agent.sh` НЕТ — по коду.** `scripts/land_agent.sh`
   работает на `--root` (репо харнесса), проверяет диапазон `main..<tip>` ЭТОГО репо

   репо через `zones_load` (`:141-161`), затем сверяет committer merge-коммита с

   ПРОЕКТА, где ни диапазона wip-ветки харнесса, ни реестра ЗОНА-строк нет; `land_agent.sh`
   на land проекта не вызывается никем. Единственная проверка identity на land проекта —
   та, которую И-7 предписывает самому `land_project.sh` («сверка после merge»); приёмка

   rc-предикатом в клетке land проекта. Прецедент формы — контракт 016 И-1 (`:83`:

4. **Б6: X-064 по всему контракту.** Механический проход по идентификаторам обманок

## Решение

**Б5 — прав критик целиком.** Committer-инвариант в приёмке 063 обязателен и И-9
`land_agent.sh` НЕ дублирует (замер 3: другой репо, нет реестра, скрипт не вызывается).
Инвариант И-7 не меняется — он уже верен; меняется приёмка и клетка к8, чтобы предикат
И-7 «committer == orchestrator» наблюдался командой на входе, где дефолт репо даёт ДРУГОЕ
имя (иначе предикат vacuous). Форма — замер 2:

- честная клетка к8: к трём предикатам добавляется четвёртый —
  `git log -1 --format=%cn HEAD` == `orchestrator`; вход к8 уже несёт чужую identity
  (`mkt`: `user.name=Fixture`) — это условие входа, и оно называется в «дано»;
- стаб-пак: седьмая ручка обмана «identity-обходчик» — ленд с честным гейтом и `--no-ff`,
  но merge без identity оркестратора (committer — из конфига репо). Это тот же обход, что
  предъявил критик; без стаба различимость нового предиката доказывается только после
  реализации. Привязка к клетке смерти и контрольному входу — код батареи;
- полярности odelix-workstation: зелёный ленд → два родителя И committer `orchestrator`.

Чего решение НЕ требует: проверки канареечной формы «identity в одной строке с `git merge`»
rc-командой приёмки 063 — эффект (committer) наблюдается напрямую, форма источника — предмет
check_charter/016, не спора.

**Б6 — прав критик целиком; канона достаточно, нового разбора класса нет.** Применяется
`8123bf3` (а)–(б) как есть: `:339-345` сокращается до ручки обмана без клеток и входов, в
форме соседних пяти. Несогласования `dea4268` с каноном нет (замер 5): предписание
вердикта остаётся в силе для кода, прозе контракта оно не разрешает пары.

**Форма исполнения.** Автор правит контракт (§Красные предъявления, §Приёмка, §Демаркация) и
батарею (к8, s7/s7_diff, шапка, счёт «Красное сейчас» после живого прогона). Критик — один
MICRO-круг: только (1) пять правок ниже, (2) X-064 по контракту после правки, (3) счётные
строки батареи по трём режимам stdin (rc-команды приёмки уже есть). Б4, И-9, И-10, к14 и
всё, признанное «да» в к3, не переоткрываются. Этот заход — не круг сверх регламента, а
условие механизма (`freeze_contract.sh` требует `accept` на HEAD — прецеденты
`kontrakt-002-reestr.md`, `oblast-slepka.md`, `reglament-krug-4.md`); повторный FAIL по
причинам Б5/Б6 после этого вердикта — владелец (`AGENTS.md`, правило 12).

## Готовые правки (дословные строки; переносы — по ширине соседей)

**П1. `:429-432` — сценарий land зелёного входа (заменить целиком):**

```

  (`user.name=Fixture`); ветка `feat-x` с коммитом отведена от main; когда:
  `bash scripts/land_project.sh --repo <игрушка> --branch feat-x`; тогда:
  rc 0, `git rev-list --parents -n1 HEAD` даёт ДВА родителя, subject
  `land: feat-x`, `git log -1 --format=%cn HEAD` == `orchestrator`
  (committer merge-коммита — И-7; при чужой identity в конфиге совпадение —
  эффект скрипта, не дефолта).
```

**П2. `:316-317` — к8 в перечне честных клеток (заменить фрагмент от «к8 (» до «)»):**

```
merge-коммита == `orchestrator`)
```

**П3. `:331-345` — стаб-пак (заменить от «Стаб-пак (зелёный» до закрывающей скобки
«выключателя контура» включительно):**

```
Стаб-пак (зелёный ДО и ПОСЛЕ реализации — различимость не зависит от
честного кода): семь обманных стабов, по одной ручке обмана каждый —
«гейт-слепец к ready-файлам» (гейт, игнорирующий `.review/` целиком),
«генератор-заглушка без команд профиля» (шаблон джобы без шагов
```

Хвост абзаца («Каждому стабу — диффпроба на контрольном входе. Привязка стабов … rc батареи
