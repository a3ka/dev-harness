## Решение по спорным пунктам

1. **Класс — (а).** Инвариант §Предмет сформулирован верно и остаётся; неполон КРИТЕРИЙ, которым контракт сам определяет его наблюдение: А-8 ограничивает наблюдение парой (имя, OID) и успешным вызовом, А-6 обещает «ДО любых refs», но сверяет один main, п.4 закрепляет формат без `%(symref)`. Чинить только клетки означало бы, что клетки проверяют строже, чем написано в контракте, — расхождение текста и кода, которое следующий судья законно предъявит. Текст правится; контракт не заморожен, поэтому это правка черновика, а не v+1 заморозки.

2. **Смысл «не трогает» — отсутствие операций, не равенство конечного состояния.** Основание инженерное, не дипломатическое: конструкция 094 отвергла промежуточное движение refs именно из-за «окна расхождения», видимого другим читателям; временная ref внутри prepare — ровно такое окно. Сильное чтение измеримо стандартным механизмом git (замеры 2–3), значит выбирать слабое нет причины. Граница сильного чтения задаётся ЯВНО (п. 5а), чтобы класс закрылся определением, а не следующим «а reflog?».

3. **Три обхода + два члена арбитра = один класс; закрывается двумя наблюдателями, не пятью заплатками.** Снимок с `%(symref)` и HEAD ловит перезаписи, невидимые хуку (symref на git 2.43; отсоединение HEAD — обоим); хук ловит операции, невидимые снимку (временная ref, перезапись на тот же OID). Применение к отказному вызову закрывает путь отказа. Любой новый обход того же класса после правки = дефект определения п. 5а, предъявляется ссылкой на этот файл, не новым кругом.

4. **Что остаётся автору.** Обещание «ни одной ref» не ослабляется до текста владельца «не двигает целевую ветку» (критик сам требовал не ослаблять молча; конструкция 094 требует строже). Снимок refs А-8 — правильный наблюдатель, он дополняется, не заменяется. Стаб-привязки — в коде (Н-39).
