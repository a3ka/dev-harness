### 2. Закрыть грамматику по конечной порождающей сетке

Формула канона выводится из инварианта 1, а не извлекается из resolver/model/build:

```text
A = ASCII буквы A..Z, a..z и цифры 0..9
B = A ∪ {_, ., -}
P(v) = (тип(v)=JSON boolean и v=false)
       ИЛИ (тип(v)=JSON string, v=u+'/'+r,
            ровно один '/', |u|≥1, |r|≥1,
            u[0],r[0]∈A; все последующие символы u,r∈B).
```

Это полное совпадение строки, без trim/casefold и лимита длины. Тип проверяется точно: число 0 не false. Отсутствие листа — отдельное разрешённое состояние, не значение P. Эквивалентный эталон — `fullmatch([A-Za-z0-9][A-Za-z0-9_.-]*/[A-Za-z0-9][A-Za-z0-9_.-]*)` плюс отдельный JSON false. Предпочтителен простой посимвольный оракул по A/B, чтобы не повторить jq-якорь production. Он живёт только в батарее: production по-прежнему имеет один resolver.

Расширить существующий probe/CASES генерацией стабильных именованных входов; отдельную конкурирующую батарею не создавать. Ожидания вычисляются до запуска субъекта из этой формулы, не из его ответа/регекса/носителя. Обязательные оси конечного набора:

| Ось | Входы и положительная противоположность |
| --- | --- |
| Тип и false | JSON false; null, 0, 1, true, [], {}, прежние непустые массив/объект; все 32 комбинации регистра пяти букв строки `false`, включая FALSE, False, fAlSe; отдельно ` false` и `false ` — все строки отвергаются |
| Разделитель и пустота | `''`, `/`, `/r`, `u/`, `ur`, `u//r`, `u/r/s`; положительные `a/b`, `0/9` |
| Первый символ обеих половин | Независимо заменить первый символ owner и repo каждым ASCII-символом 0..127; допускается только A. Остальная половина и соседняя половина валидны |
| Последующие символы обеих половин | Независимо вставить каждый ASCII-символ 0..127 в середину и в конец каждой половины; допускается только B. В частности `_`, `-`, `.` здесь честно разрешены, а в начале запрещены |
| Точное начало/конец, нормализация | SP, TAB, CR, LF, NUL по одному перед/после валидного значения и внутри обеих половин; односторонние входы, не только комбинированный ` a/b `. Валидная строка без добавки остаётся принятой побайтно |
| Unicode | `ǹ`, `١`, `Ａ`, `１` независимо на первом/последующем месте обеих половин, полноширинный `／` вместо разделителя; все отвергаются. ASCII-соседи и смешанный регистр принимаются неизменёнными |
| Длина | Минимальные половины длиной 1, длина 2; сохранить прежний длинный мир и добавить owner длиной 1024 с `/R` (полная длина 1026), симметричный repo и обе длинные половины. Они принимаются; нулевая половина отвергается. Это контроль отсутствия лимита, не обещание перебрать все длины |

Разворачивать оси по одной на валидном основании, не декартово произведение всех ошибок: иначе один отказ скроет другой. Дубликаты входов разрешено устранить, но каталог должен показывать все оси, размер непустой выборки и стабильные связи. Ожидание отказа: rc 1, пустой stdout, предметная причина hooks.archBrief; позитив: rc 0 и полное неизменённое значение/тип с origin=repo в merged. Ошибка среды — rc 2, не пойманная обманка. Существующие интеграционные миры отсутствия/false, смены ключа, пина, слоя и публичных дверей сохраняются.

Адресный перечень семейств мутаций: (а) оба исходных свидетеля Adv226 — разрешение конечного SP и `_` первым в owner; (б) дословный мутант Adv226b FALSE/False; (в) ослабление проверки типа/false; (г) первые алфавиты owner и repo отдельно; (д) последующие алфавиты обеих половин; (е) якоря начала/точного конца и trim; (ж) пустая половина/лишний slash; (з) замена ASCII-класса Unicode-классом; (и) нормализация регистра валидного адреса; (к) имеющийся st11-length-cap с длинным честным контролем. ## Границы

**К ВЛАДЕЛЬЦУ — именно вариант «reviewer без третьего adversary».** Готовый один вопрос: «Разрешаете по 226 после исправления К-01 и грамматической сетки этого арбитража перейти к одному reviewer без третьего adversary, с ручной независимой проверкой оставшихся К-08/К-09 и последующим owner-аттестатом adversary на том же OBJECT, как адресно разрешалось 219/224; до аттестата done не ставить?» **Рекомендованный ответ сейчас — нет: сначала использовать один узкий adversary по делегированному праву консультанта, если оно доступно.** Не требуется будить владельца ради самой инженерной правки. Если владелец всё же выбирает экономию вызова, нужны его адресное решение о риске и явный законный способ материализации обязательной подписи; этот арбитраж их не создаёт. Самому писать owner-аттестат или разрешающую строку запрещено.
