## Решение по вопросу 1: критерии закрытия

По обоим пунктам прав критик; его критерии принимаются с уточнениями ниже.
Обе находки — дефекты ПРЕДЪЯВЛЕНИЙ, не инвариантов: инварианты контракта уже
говорят правильные вещи, ворота их не различают.

**Б1 — обязательный критерий закрытия.** Ворота в11/в12 судят коммиты с
фактическим автором orchestrator, и это проверяет само предъявление:

1. судимый коммит создаётся автором orchestrator (как — выбор архитектора:
   починка вызова, отдельный помощник, amend; способ не навязывается);
2. ворота ПЕРЕД вызовом check_zones ассертят
   `git log -1 --format=%an` == `orchestrator` на судимом toy — самопроверка
   предъявления, чтобы класс «фикстурный помощник молча подменил автора»
   умирал в самих воротах, а не в следующем круге критика;
3. в11: СЕГОДНЯ rc 1 с «коммит вне зоны» и именем пути
   `registry/contracts.tsv` (замер 1 подтверждает: именно это даёт настоящий
   автор); ПОСЛЕ реализации rc 0;
4. в12: rc 1 с «вне зоны» и именем пути — ДО и ПОСЛЕ.

Граница точна и не расширяется: в1–в10 и в13 судят staged-множество по
effective identity локального конфига, туда `set_author` доносит автора
корректно — их не трогать (закрытый Б2 не переоткрывается).

**Б4 — обязательный критерий закрытия.** Отдельное ворота (р10 либо иное имя)
для ветви `zones_load rc ≠ 0` НАСТОЯЩЕГО читателя:

1. построение, в котором `zones_load` на toy-корне возвращает ненулевой rc,
   а механика дельты манифеста жива; существование доказано замером 2-B
   (origin с frozen-тегом, отсутствующим локально → rc 2 «missing-remote»);
   архитектор волен взять другое построение того же класса, но ворота обязаны
   звать живой читатель через субъект — мок/подмена zones_load предъявлением
   не считается;
2. `--retake` → rc 1 с побайтовым именем «реестр зон недоступен»;
3. байты снимка до == после;
4. последующий `--check` остаётся rc 1.

Р9 сохраняется как ворота второй ветви (rc 0 + пусто) — он полезен и не
плацебо. Одного ненулевого построения достаточно: инвариант 5 ключует ветвь
на класс `rc ≠ 0`, второй ненулевой вход был бы набивкой. Утверждение :241
о том, какой стаб где умирает, привести в соответствие с фактом (стаб
запасного пути умирает на новом воротах, не на р9).

Сопутствующее, в рамках того же фикса: формулировки :213–214 («СЕГОДНЯ rc 1»)
обязаны стать истинными через починку ворот, не через переписывание ожидания.

## Решение по вопросу 2: форма третьего круга

Обычный фикс-цикл архитектора под этим вердиктом. Respec не нужен: инварианты
обоих механизмов спор пережили, чинятся два предъявления и абзац приёмки
(:212–214, :237–241) плюс ложное утверждение :241. Новых предметов воли
владельца не возникло — обе правки инженерные. Заморозка результата третьего
круга разрешается только по вердикту судьи третьего круга, вынесенному в
границах вопроса 3; настоящий вердикт — её процедурное основание по правилу 15.

## Решение по вопросу 3: границы третьего круга

Третий круг — SCOPED. Судья третьего круга выносит FAIL только по двум
основаниям:

- (а) критерии этого вердикта по Б1/Б4 не применены либо применены с
  расхождением по названным rc/именам/наблюдениям;
- (б) новый дефект, внесённый самой дельтой фикса (диф от 538c829),
  в изменённых строках.

Закрытые Б2/Б3, решённые границы 2/5 и советы прежних кругов не
переоткрываются. Находки вне (а)/(б) записываются советами, основанием FAIL
не являются. Полный пересмотр предмета третьим кругом запрещён — иначе цикл
не сходится. При FAIL третьего круга по основаниям (а)/(б) новый арбитраж не
требуется: судья ссылается на этот вердикт.
