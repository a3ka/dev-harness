# Арбитраж 023: достаточность негативных входов dual-control (источник манифеста и сверка sha)

Предмет спора: `wip/023/architect` @ `afe6fe2feb6b310a2a35dbca992572bf4318578a`,
`contracts/023-rezervacija-nomera-dver-po-tegu.md`. Круг 1 — `57c8141` (блокер 1:
достижимость тега на origin не различает пуш оркестратора и пуш агента). Круг 2 —
`64da71b` (повтор причины: rc-критерий не имеет негативных входов для «манифест —
с ЖИВОЙ origin/main» и «sha-origin == sha-строки»). Созыв — по правилу «два отказа
по одной причине». Стороны обозначены ролями: автор конструкции и критик.

## Факты (замеры этого арбитража)

Все прогоны — в одноразовых клонах ветки `wip/023/architect` (tip `afe6fe2`);
основной чекаут не мутировался. Инструменты замера: `/tmp/arb023/patch.py`
(параметризованная дверь/гейт), `/tmp/arb023/probe.sh` (кандидатные входы).

**Замер 1 — честная реализация проходит red.** В клоне `/tmp/arb023/clone`
реализованы дверь (iii) в `check_staged.sh` и гейт (ii) в `spawn_agent.sh` по
букве контракта (тег локально → ls-remote тега на origin → манифест по шапке
`refs/heads/main` НА origin через ls-remote→fetch→show → сверка sha → ветка →
приземление; отказы именованные). `cwd=/tmp/arb023/clone`:
`bash fixtures/check_staged/red_dver_po_tegu.sh` → rc 0;
`bash fixtures/spawn_agent/red_gejt_javnogo_nomera.sh` → rc 0.

**Замер 2 — слабая форма (а) «манифест с ЛОКАЛЬНОГО main» проходит оба red.**
Та же реализация с единственной заменой: манифест читается из локального
`refs/heads/main` (`git show refs/heads/main:registry/contracts.tsv`), сверка sha
честная. `cwd=/tmp/arb023/clone`, по ДВА прогона (случайные входы):
`red_dver_po_tegu.sh` → rc 0, rc 0; `red_gejt_javnogo_nomera.sh` → rc 0, rc 0.

**Замер 3 — слабая форма (б) «sha не сверяется» проходит оба red.** Та же
реализация, манифест честно с origin/main, но строка `<NNN> → <40-hex>`
принимается без сравнения с sha тега на origin. `cwd=/tmp/arb023/clone`, по ДВА
прогона: `red_dver_po_tegu.sh` → rc 0, rc 0; `red_gejt_javnogo_nomera.sh` →
rc 0, rc 0.

Причина проходимости обеих слабых форм — по построению входов: в8 red_dver / в7
red_gejt предъявляют тег на origin при строке манифеста, отсутствующей ВЕЗДЕ
(и локально, и на origin), а оба положительных входа (`mint_rezerv`) несут
правильную строку И локально, И на origin. Ни один вход не расщепляет «локальный
main» от «origin/main» и ни один не несёт строку с чужим sha — утверждение
вердикта круга 2 подтверждено прогоном.

**Замер 4 — кандидатные негативные входы расщепляют формы диагонально.**
Вход А: тег заминчен и запушен на origin, строка манифеста закоммичена ТОЛЬКО на
локальный main (main не запушен). Вход Б: полный резерв `mint_rezerv`, затем
повторный минт тега поверх (`tag -d` + `tag -a` + `push -f` тега) — sha тега на
origin ≠ sha строки манифеста origin/main. `cwd=/tmp/arb023/clone`, дверь и гейт:

| Форма \ Вход | А (строка только локально) | Б (чужой sha на origin/main) |
|---|---|---|
| честная | rc 1 «тег N не выдан авторитетом» (дверь и гейт) | rc 1 «тег N не выдан авторитетом» (дверь и гейт) |
| слабая (а) локальный main | **rc 0 — ПРОХОДИТ** (дверь и гейт) | rc 1 «не выдан авторитетом» |
| слабая (б) без сверки sha | rc 1 «не выдан авторитетом» | **rc 0 — ПРОХОДИТ** (дверь и гейт) |

**Замер 5 — оба входа красны СЕГОДНЯ тем же классом, что в6–в8.** Чистый клон
`/tmp/arb023/pristine` (код tip, без реализации), `cwd=/tmp/arb023/pristine`:
вход А и вход Б — дверь rc 1 «вне зоны» (отказ БЕЗ имени «не выдан авторитетом»),
гейт rc 0 (спавн проходит). То есть ворота на этих входах строятся в ту же фазу
«красное сейчас → зелёное после», что существующие в6/в7/в8, — замысел трёх
якорей не меняется.

## Решение по спорным пунктам

1. **Критик прав по существу блокера круга 2.** Приёмочный критерий afe6fe2 не
   различает три якоря dual-control от «origin-тег + строка где угодно без
   сверки»: обе слабые формы прошли оба профильных red по два прогона (замеры
   2–3). Требования «по ЖИВОЙ шапке origin/main» и «sha-origin == sha-строки»
   записаны в прозе контракта, но не предъявлены исполнимым входом — для
   rc-критерия это норма без ловца.
2. **Повтор причины констатирован обоснованно.** Круг 1 требовал «минтер вне
   контроля агента»; правка afe6fe2 добавила манифест и входы в8/в7, но оба
   новых входа отрицают только СУЩЕСТВОВАНИЕ строки, не её ИСТОЧНИК и не
   РАВЕНСТВО sha — класс дефекта тот же, созыв арбитража правомерен.
3. **Форма недостающих входов — установлена замером 4 (обязательна к
   исполнению):**
   - **вход «строка манифеста только на локальном main»** (в red_dver и
     red_gejt): тег заминчен и запушен на origin от лица агента; строка
     `<NNN> → <tag-object-sha>` закоммичена в `registry/contracts.tsv` ЛОКАЛЬНОГО
     main; main НЕ запушен. Ожидание: rc 1, grep «не выдан авторитетом».
     Убивает слабую форму (а); честная жива;
   - **вход «повторный минт поверх резерва — sha разошёлся»** (в red_dver и
     red_gejt): полный резерв `mint_rezerv`, затем агент переминчивает тег
     (новый tag-object) и force-пушит его на origin; строка манифеста
     origin/main несёт прежний sha. Ожидание: rc 1, grep «не выдан
     авторитетом». Убивает слабую форму (б); честная жива. Эта форма
     предпочтительна перед «рукописным чужим 40-hex в строке»: она моделирует
     агентское действие (манифест остаётся продуктом авторитета) и уже названа
     в шапке в8 red_dver («минт поверх с расходящимся sha — 3в») — вход лишь
     доводит названное до исполнимого;
   - размещение: те же два файла (red_dver — два новых ворота после в8;
     red_gejt — два после в7), NNN из новых непересекающихся поддиапазонов,
     та же параметризация случайными входами, тот же две-прогонная приёмка.
     Оба входа строятся СУЩЕСТВУЮЩИМИ помощниками `_repo.sh`
     (make_repo/make_repo_archzone, toy_origin, mint_rezerv, g) — замер 4
     исполнен ровно ими; новый помощник допустим, но не обязателен;
   - изменение замысла трёх якорей НЕ требуется: замер 5 показал, что оба
     входа сегодня красны тем же классом, что существующие в6–в8 (дверь —
     отказ чужим именем, гейт — спавн проходит).
4. **Дополнительных негативных входов сверх этих двух арбитраж НЕ предписывает.**
   Комбинаторика прочих расщеплений (peeled-sha вместо tag-object-sha, чтение
   remote-tracking вместо живой шапки и т.п.) отсекается теми же двумя входами
   либо уже покрыта (в6/в7/в8); требовать её — раздувание критерия без
   измеренной слабой формы. Появится измеренная — появится и вход.

  вердиктом круга 2 и здесь не пересматривались.
