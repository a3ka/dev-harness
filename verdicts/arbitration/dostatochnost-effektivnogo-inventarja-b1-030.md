## Решение по спорным пунктам

1. **Критик прав в обоих кругах: причина одна, и она не в составе списка.** Оба
   обхода — частные случаи одного дефекта: проба судит ТЕКСТ присваиваний, а инвариант
   :21–22 говорит о СОСТОЯНИИ `$TOOLS` в точке `exec` (:516/:597). Обход к2
   воспроизведён мной независимо: две последовательные базовые строки → проба rc 0,
   живой `./workshop` отдаёт `--tools` без `hub` (таблица ниже, дерево k2).

2. **Предложенное автором определение «эффективный инвентарь = ПОСЛЕДНЕЕ безусловное
   присваивание вне блока FABLE + S-last-wins» НЕДОСТАТОЧНО.** Оно закрывает ровно
   обход к2 (замер: страв-реализация определения даёт rc 1 на k2) — и пропускает три
   новых ИСПОЛНЕННЫХ варианта того же дефекта, где определение текстово выполнено,
   а живой инвентарь ведущей сессии — без `hub`:

   - **v1 — условная ветвь вне FABLE.** Базовая строка :473 с `hub` цела; внутри УЖЕ
     СУЩЕСТВУЮЩЕГО блока `if [ -z "$PROJECT" ]; then` (:476), ДО блока FABLE, добавлено
     присваивание без `hub`. Оно «условное» по тексту — и БЕЗУСЛОВНО исполняется на
     пути ведущей сессии, потому что ВЕСЬ exec-путь тул-режима живёт внутри этого
     блока. Предикат «безусловное присваивание» опирается на различие, которого на
     этом пути не существует.
   - **v2 — затирание после `fi` блока FABLE**, с отступом, до exec: действует в обоих
     режимах; по положению проба сочла бы его «FABLE-присваиванием», по колонке — оно
     не «безусловное», определение его игнорирует.
   - **v3 — сорс файла.** После строки с `hub` добавлено
     `. "$HERE/scripts/session_tools.sh"`, файл переприсваивает `TOOLS` без `hub`.
     Сканер присваиваний сорса не видит.

   Замер (проба = скратч-проба критика к2; страв = моя дословная реализация авторского
   определения; рантайм = живой запуск `./workshop` со стабом `omp` на PATH,
   печатающим операнд `--tools`; `F=0`/`F=1` — без/с `--fable`):

   ```text
   дерево | проба rc | страв rc | F=0 hub | F=1 hub | истина инв.1/2
   ------ | -------- | -------- | ------- | ------- | --------------
   head   | 1        | 1        | НЕТ     | НЕТ     | нарушена (красный контроль)
   pos    | 0        | 0        | ЕСТЬ    | НЕТ     | выполнена (позитив-контроль)
   k2     | 0        | 1        | НЕТ     | НЕТ     | нарушена — обход к2, воспроизведён
   v1     | 0        | 0        | НЕТ     | НЕТ     | НАРУШЕНА — определение лжёт
   v2     | 0        | 0        | НЕТ     | НЕТ     | НАРУШЕНА — определение лжёт
   v3     | 0        | 0        | НЕТ     | НЕТ     | НАРУШЕНА — определение лжёт
   v4     | 1        | 1        | ЕСТЬ    | НЕТ     | выполнена — ЛОЖНЫЙ ОТКАЗ
   v5     | 0        | 1        | тул ЕСТЬ / проект НЕТ — см. пункт 4
   ```

   Полные операнды зафиксированы: на v1–v3 живой exec получает
   `read,edit,write,bash,grep,glob,lsp,web_search,task,todo` (без `hub`) при пробе и
   страве rc 0. На pos — тот же список с `,hub`, FABLE-запуск — без `hub`.

3. **Определение к тому же чрезмерно строго.** v4 — легальное дерево: базовое
   присваивание вынесено в сорсимый файл С `hub`; живой инвентарь инвариант выполняет
   (`hub` ЕСТЬ при F=0, НЕТ при F=1), а определение отказывает («безусловного
   присваивания нет»). Для критерия приёмки ложный отказ дешевле ложного пропуска, но
   он пиннит форму реализации, которую контракт пиннить не обещал.

4. **Второй exec-путь не покрыт ни пробой, ни узким прочтением определения.** v5:
   базовая строка с `hub` цела, но перед `require_metering "$PROJECT"` (:551, проектная
   ветвь) `TOOLS` переприсвоен без `hub`. Проба к2 — rc 0; живой тул-режим — `hub`
   ЕСТЬ, живой проектный запуск — `hub` НЕТ. Преамбула части 1 контракта прямо
   называет ОБА exec-пути питаемыми одним присваиванием. Литеральное прочтение
   авторского определения («последнее безусловное по всему файлу») этот вариант
   ловит (страв rc 1), прочтение «до строки FABLE» — нет; двусмысленность обязана
   быть снята фиксом в пользу покрытия обоих путей.

## Корень и требование к фиксу

Корень один: инвариант сформулирован о ДИНАМИЧЕСКОМ состоянии (`$TOOLS` в точке exec),
а проба судит СТАТИЧЕСКИЙ текст. Всякий текстовый суррогат — позиция, колонка,
последняя строка — аппроксимирует исполнение и лжёт при первой же условной ветви,
затирании после блока или сорсе; чинить перечислением суррогатов — треадмилл (класс
Н-89). Различимость предъявленных состояний, которую требует критик, здесь даёт только
НАБЛЮДЕНИЕ исполнения: операнд `--tools`, каким его получает exec, — для обоих режимов
(FABLE=0/1) и обоих exec-путей. Это измеримо дёшево: мой стенд (стаб `omp` на PATH,
перехват операнда) правильно классифицировал ВСЕ восемь деревьев таблицы — включая
принятие легального v4, на котором текстовые проверки ложно краснеют. Текстовым
проверкам остаётся грамматика (инв. 3) и негативные стабы.

Конкретный механизм пробы — за архитектором (Н-39 сохранена; арбитр оракулов не
пишет). Критерий достаточности фикса задаю наблюдаемо: проба круга 3 обязана краснеть
на классах v1 (условная ветвь вне FABLE на пути ведущей сессии), v2 (затирание после
блока FABLE), v3 (сорс), v5 (второй exec-путь) и зеленеть на pos и на классе v4
(легальная форма с тем же эффективным инвентарём) — вдобавок к уже закрытым k1/k2 и
позитивам W4–W6 действующей пробы.
