## Замеры

Все прогоны — точная scoped-батарея `red_sharing_agentdb.sh` с `WORKSHOP=<стаб>`
и корнем клона; конформный toy-вход `p2` — собственный скрипт по строителям
батареи (полный профиль 054/055, живой маркерный DEVDB по формуле hash8 корня клона).

- **З1 (репро к3 на HEAD, батарея неизменённая).** Стаб `case p1|rnd*) exec
  честного; *) A2, exit 0` (dev-вход без слоя делегируется): `стаб-пак 9/9 …
  к15: случайный projectId=rnd278071370737 … честная часть: 16/16 зелёная, rc=0`.
  На toy-входе `p2` тот же стаб: `rc=0`, `AGENTDB: изолирована`, PROJDB не создан
  при живом DEVDB — нарушение И-1 C1. Честный `workshop` на том же входе: `rc=0`,
  `AGENTDB: <DEVDB>`, `PROJDB — симлинк на DEVDB` (3 прогона из 3). Факты v3
  воспроизведены 2/2.
- **З2 (чтение честной реализации — вторая половина пары гарантий 041 п.2.1).**
  `PROJECT_ID_VAL` в `workshop` после санитизации :663-669 участвует ТОЛЬКО в
  сборке пути `PSTATE` (:692), экспорте `METERING_PROJECT` (:800) и баннере
  `METERING:` (:802). Блок шаринга :814-868 ветвится исключительно по состоянию
  `$AGENTDB_PROJDB`/`$AGENTDB_DEVDB` (`-L`, `-e`, `-f`, `-s`, `readlink`) — ни
  одного сравнения со значением `projectId`, ни одной константы-идентификатора.
  Честный код вычисляет правило ОБЩЕ, как требует И-1; условие (α) правила
  остановки 041 («честный гард сам неверен на входе») НЕ выполнено.
- **З3 (закрываемость дыры к3 структурно, без новой константы).** Прототип
  генератора: первый символ равномерно из `[a-z0-9]`, остальные из `[a-z0-9_-]`,
  длина равномерно 1..16, литерала нет, `p1` перегенерируется, результат
  fail-closed сверяется тем же regex (`die_pack` при выходе за грамматику).
  Батарея с этим генератором (вместо :101) против стаба З1 — ДВА прогона:
  `к15 красная, projectId=ertkmb44l, честная часть: 15 из 16, rc=1` и
  `projectId=75xrlfqs3v17n0_m, 15 из 16, rc=1` (З5). Аналитически: вероятность попасть в `rnd*` при такой
  выборке — `(1/36)·(1/38)²·(14/16) ≈ 1.7·10⁻⁵` на прогон; совпадение с любым
  литералом длины L ≤ `38^-(L-1)/36`. Класс «whitelist по литералу, подсмотренному
  в файле батареи» закрывается одним структурным ходом — выборкой из ПОЛНОЙ
  грамматики поля (single source — сама грамматика 055), а не очередной константой.
- **З4 (предел класса — стаб БЕЗ единой константы из батареи).** Стаб-«чёрный
  список»: `case p2) A2, exit 0; *) exec честного`. Против прототипа З3:
  `к15: projectId=7i8f … честная часть: 16/16 зелёная, rc=0`. На toy-входе `p2`:
  `rc=0`, `AGENTDB: изолирована`, PROJDB нет — нарушение И-1. Вероятность, что
  случайная выборка вообще выберет `p2`, — `≈4.6·10⁻⁵`. То же верно для любого
  стаба, чей предикат покрывает распределение выборки, но не всю грамматику
  («длина ≤ 16», «есть цифра», «всё, кроме одного id»): диапазон и алфавит
  выборки видны в файле батареи, и стаб-«whitelist по распределению» либо
  «blacklist на одно значение» проходит любую конечную выборку с вероятностью
  ≈1. Это ровно З2 арбитража 041: чёрноящичная батарея против white-box стаба
  невыигрышна для ЛЮБОГО числа случайных id за прогон; несколько id за прогон
  меняют константу в показателе, не класс.
- **З5 (положительный контроль прототипа + второй прогон стаба к3).** Честный
  `workshop` против батареи с генератором З3: `к15: projectId=w … честная часть:
  16/16 зелёная, rc=0` — id длины 1 (нижняя граница грамматики) честным кодом
  принят. Второй прогон стаба З1 против того же прототипа: `к15 красная,
  projectId=75xrlfqs3v17n0_m, 15 из 16, rc=1`. Обе полярности воспроизведены:
  честный — зелёный, стаб-литерал — красный 2/2.

## Решение по существу

### Пункт 1. Кто прав

- **Адверсарий прав фактически (З1, 2/2)** и прав в том, что фикс круга 2
  повторил болезнь круга 1: `rnd$RANDOM$$` — это константа `rnd` плюс шум, и
  константа снова подсмотрена стабом. Требование v2 «лучше генерируемым
  значением» автор исполнил в форме, где генерируемая часть не несёт различающей
  силы против литерала. Дыра к3 — член подкласса (β) правила остановки 041:
  закрывается структурно, без новой ручной константы (З3) — и это ещё не сделано.
- **Адверсарий НЕ прав в формулировке требования «батарея обязана сама доказать
  универсальность правила»** (v3: «конечный набор тестовых ID не может сам
  доказать универсальность контрактного правила») — как факт это верно, как
  требование к батарее — невыполнимо по построению (З4) и уже решено
  арбитражем 041 п.2: доказательство против намеренно нечестной реализации —
  ЧТЕНИЕ исходника, обязательная секция вердикта судьи. В v3 такой секции нет;
  здесь она предъявлена арбитром (З2) и закрывает вопрос по N1 на текущем
  `workshop`.
- **Автор прав в том, что честный код общий (З2), и не прав в форме к15 дважды**:
  «константа → константа + случайность» — не структурный фикс. Третья итерация
  обязана быть последней в этом классе именно потому, что после неё остаток
  доказуемо неустраним батареей (З4), а не потому, что стороны устали.

### Пункт 2. Семантика к15 — как правильно (обязательно к исполнению автором)

1. `projectId` для к15 берётся **из полной грамматики поля без какого-либо
   фиксированного литерала**: первый символ равномерно из `[a-z0-9]`, остальные
   равномерно из `[a-z0-9_-]`, длина случайная в диапазоне не уже 1..16 (верхняя
   граница — любая разумная; она видна в файле и входит в именованный остаток
   п.4). Алфавит в генераторе — единственный носитель (та же грамматика, что
   `workshop:665`, комментарий ссылается на неё), `p1` перегенерируется.
2. **Fail-closed самопроверка генератора**: результат сверяется тем же regex
   `^[a-z0-9][a-z0-9_-]*$` и неравенством `p1`; несоответствие — `die_pack`
   (ОТКАЗ батареи), а не красная клетка на счёт субъекта. Это удерживает
   дискретность: красная к15 всегда означает субъект, не генератор.
3. Один id за прогон достаточен (З3/З4: число выборок не меняет класс);
   несколько id НЕ требуются и не запрещаются.
4. Id печатается в строке отчёта (:635 — уже есть) на любом исходе; текст
   строки и комментарии :21-24, :94-100, :573-580 приводятся к классу: «мутант с
   любым зашитым ЛИТЕРАЛОМ/набором id краснеет; предикат, подогнанный под
   распределение выборки, — именованный остаток, закрывается чтением исходника
   (арбитраж 058/N1)». Слова «префикс rnd гарантирует…» уходят.
5. Структурная/статическая проверка вычисления (grep `workshop` на сравнения с
   `PROJECT_ID_VAL`) как МЕХАНИЗМ батареи — отклонена (041 п.2.4: сам становится
   парсящим гардом, тривиально обфусцируется). Чтение исходника остаётся
   когнитивной обязанностью судьи и обязательной секцией адверсарного вердикта
   по этому предмету (образец — З2).
6. Правится ТОЛЬКО `fixtures/workshop_project/red_sharing_agentdb.sh` (зона
   architect). Frozen-барьеры 058 (`NABLIUDENIA*.md`, `HANDOFF.md`, `AGENTS.md`,
   батареи соседей) не трогаются; носитель нормы — этот файл. Это исполнение
   решения, не новый круг.

### Пункт 3. Границы — стабильность и дискретность батареи

- Честная реализация инвариантна к значению (Демаркация 058; З2 — значение не
  участвует в ветвлении), поэтому зелёное честного детерминировано при любой
  выборке; измерено З5. Красное для стабов-литералов детерминировано с точностью
  до `≤ 2·10⁻⁵` на прогон (З3) — на порядок ниже фонового шума таймаутов к11
  (65 с + 91 с раннеры 054/055). Недетерминированный исход возможен ТОЛЬКО у
  стаба, подогнанного под распределение (например «длина ≥ 2» краснеет в 1/16
  прогонов) — это нестабильность стаба, не батареи, и именованный остаток п.4.
- Дискретность: счёт клеток 16 не меняется, клетка бинарна, генератор
  fail-closed (п.2.2). Новых файлов, ручек STUB_* и стабов в стаб-пак не
  добавляется: стаб-пак судит ветви И-1, а не значения id.
- Время прогона не меняется (генератор — микросекунды).

### Пункт 4. Масштаб — к15 или класс

- **Норма — классу**, носитель — этот файл: случайное значение, назначение
  которого — ловить зашитую константу СУБЪЕКТА (не уникальность имени temp-файла),
  не несёт фиксированного литерала и выбирается из полной грамматики поля;
  остаток «предикат по распределению» закрывается чтением исходника, круг не
  порождает (041 п.2.3).
- **Ретрофит — только к15.** Замер по дереву: `f_$RANDOM.txt`, `z$RANDOM.txt`,
  `r$RANDOM$RANDOM`, `${RUN}$RANDOM$$` и т.п. в `fixtures/check_runner_hygiene/`,
  `check_hooks/`, `check_no_leak/`, `check_metering/_repo.sh:18`,
  `check_ceilings/_gen.sh:22-26` — та же форма «литерал + шум». Все они в
  замороженных зонах чужих контрактов, живого стаба против них не предъявлено, а
  правило триажа владельца (`roles/orchestrator.md:302-306`) запрещает чинить
  до реального укуса. Применение нормы к ним — при первом же живом стабе в
  собственном круге того контракта либо при авторской правке этих файлов по
  другой причине; никаких кругов этот вердикт по ним не открывает.

### Пункт 5. Правило остановки и следующие круги

- После додела п.2 и зелёного `bash fixtures/_krasnye_058.sh` плюс красного
  прогона стаба З1 (`WORKSHOP=<стаб p1|rnd*>` → к15 красная) вопрос N1 **закрыт**;
  круг 4 адверсария по N1 НЕ созывается (чтение исходника предъявлено — З2).
  Проверка додела — оркестратор, механически: две команды выше.
- Любой будущий стаб класса З4 (blacklist, предикат по длине/алфавиту/
  распределению, различение harness от боевого окружения) по 058 — именованный
  non-blocking остаток в вердикте с секцией чтения исходника; правку батареи и
  арбитраж не порождает. Находки ВНЕ стаб-игры (честный код неверен на
  конформном входе, дыра грамматики 055, новые ветви И-1) этим не ограничены.
- Несоответствие додела этому файлу — дефект исполнения, чинится правкой по
  ссылке сюда, не спором.

## Цена решения, названная прямо

1. Батарея признаётся НЕ самодостаточным доказательством общности вычисления;
   вторая половина — чтение (З2), качество зависит от судьи. Митигация: секция
   чтения обязательна и предметна (строки, ветвления), не фраза.
2. Верхняя граница длины и алфавит видны в файле — остаток (З4) принят как
   неустранимый, а не как долг.
3. Три круга на одну клетку — цена двух неструктурных фиксов; правило п.5
   останавливает четвёртый.

## Счёт сторон

- Факты к3, повтор корня, «константа + шум ≠ структурный фикс», обязательность
  додела: адверсарию (З1, З3).
- «Батарея обязана сама доказать универсальность» как требование, круг 4 по
  тому же корню: отклонено (З4) — не в пользу автора, в пользу факта; общность
  честного кода: автору по замеру З2, не по слову.
- Рандомизация как выход: принята в единственной структурной форме (полная
  грамматика, без литерала) и ограничена именованным остатком — по замеру, не
  по вкусу. Прецедент 041 применён, не пересмотрен.

Арбитр код батареи не писал и не пишет: прототип генератора и стабы — одноразовые
замеры закрываемости в scratch-каталоге; канонический додел — работа автора.
Единственный постоянный артефакт — этот файл.
