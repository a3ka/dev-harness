## Решение по спорным пунктам

1. **Критерий реализации.** Позитивная сверка `status == "completed"` — единственное допустимое решение. Чёрный список — обход по построению при любой длине (замер 3): пространство строк бесконечно, терминальное значение одно. Модель автора (:143) верна и НЕ меняется. — автор прав по реализации.
2. **Критерий достаточности предъявления.** Example-based перечисление незавершённых значений НЕ замыкает класс никогда: каждое n-значное предъявление проходит (n+1)-значный чёрный список (v3 → v4 — ровно это). Замыкание достигается свидетелем, которого конечный чёрный список предвидеть не может, — nonce времени исполнения — плюс структурным свидетелем «поля нет». — критик прав по существу и по счёту: «ещё один статус» — не исправление.
3. **Ответственность за v3.** «Достаточное исправление: предъявить также на queued» (v3) — слабая формулировка достаточности самого критика; автор исполнил её буквально. Повтор причины — не непослушание автора; критик это записал сам, подтверждаю. Но и А-410 автора утверждает различающую силу, которой нет (замер 2): запись подлежит исправлению автором.
4. **Предпосылка созыва (Main).** «Замкнутый алфавит из трёх, waiting — legacy» — неверна (замер 1). Оба варианта вопроса созыва («позитивная сверка» ИЛИ «исчерпывающий чёрный список») — ложная дихотомия: позитивная сверка — критерий РЕАЛИЗАЦИИ (уже есть), а вопрос спора — критерий ПРЕДЪЯВЛЕНИЯ; исчерпывающий чёрный список отвергнут замером 3.
5. **Текст заморозки.** Правки не требует: строка 39 уже требует завершённость и отказ без строки; усиление клетки/стаба — AGENTS.md §Воркфлоу шаг 3 (как в v3/v4 критика). Владельцу — ничего: ни воли, ни денег, ни риска публикации.
