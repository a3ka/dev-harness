# Арбитраж 022: аннотированный push-тег и полный диагноз (блокер 4, круги 1–2)

Созыв: два FAIL по одной причине (вердикты `2f11b53` круг 1, блокер 4; `0838862`
круг 2, оба оставшихся блокера — повтор той же причины). Предмет: достаточно ли
(1) одного красного tag-входа без зелёного tag-контроля для договора scoped-суда
тегов (И-8) и (2) единственного merge-входа с тройкой `ref, коммит, путь` для
общего требования полного диагноза (предмет A, п. 5). Стороны: автор конструкции
(architect, контракт `53a74a5`) и критик. Кап 30 мин соблюдён; терминология
нейтральная (Н-73).

## Воспроизведённые факты

Все замеры — одноразовый клон `wip/022/architect` (`53a74a5`) в
`/tmp/arb022.7P8P9N/repo`; pwd-эхо печаталось перед каждым замером (А-95);
основной чекаут не мутирован (Н-74). Обе слабые формы построены исполняемыми
хуками и прогнаны против семи hook-red фикстур ветви A.

**Слабая форма (а) «отвергать ВСЕ теги»** (ветки судятся честно с полным
диагнозом; любая строка `refs/tags/*` отвергается без суда РАЗРЕШИЛ, найденный
путь печатается):

- `red_push_teg_annotirovannyj_suditsja.sh` → rc 0 — красный tag-вход слабую
  форму НЕ отличает;
- остальные шесть hook-red → rc 0 (см. оговорку про toy-дефект ниже); ни одна
  из названных rc-команд контракта тегов, кроме красного, не пушит — слабость
  структурно ненаблюдаема.

**Слабая форма (б) «полный диагноз только для merge»** (суд честный везде,
включая разыменование тега; `ref`+`sha` печатаются только когда красный
коммит — merge, иначе только путь):

- ВСЕ семь hook-red → rc 0, включая `red_push_merge_gran_bez_stroki.sh`
  (единственный, ассертящий тройку) — merge-вход квантор «для красного вообще»
  не держит.

Статическая сверка ассертов подтверждает механизм: тройку
(`contracts/001-x.md` ∧ полный sha ∧ `refs/heads/main`) грепает только
merge-red (`red_push_merge_gran_bez_stroki.sh:144-152`); все прочие честные
красные фазы грепают только путь.

**Различающие входы, убивающие слабые формы** (тот же клон, скрипт-канарейка):

- легитимный аннотированный тег `v-ok` на коммит с уставной дельтой M и
  корректной строкой `РАЗРЕШИЛ-ВЛАДЕЛЕЦ:` — честный суд тегов: rc 0, тег въехал
  на origin; форма (а): rc 1, тег не въехал. Канарейка различает;
- не-merge красный пуш ветки, сверка вывода отказа: честная печать — путь=да,
  sha=да, ref=да; форма (б) — путь=да, sha=НЕТ, ref=НЕТ. Греп тройки различает.

## Решение по существу

**Оба спорных пункта — за критиком.** Замер показал: обе слабые формы проходят
весь названный критерий; различающие входы существуют, дёшевы и исполнимы в
красных фикстурах без изменения замысла A+C.

**1. И-8 обязан получить Вход-2 — зелёную канарейку легитимного тега.**
Требование: аннотированный тег на коммит, чья судимая линия несёт уставную
дельту M с корректной строкой РАЗРЕШИЛ в том же коммите; честная ПРОПУСКАЕТ —
rc 0 ∧ тег въехал на origin. Фаза живёт в том же red-файле после красной фазы
(стаб «отвергать все теги» умирает именно на этом входе — привязка кодом, Н-39).
Именно РАЗРЕШИЛ-несущая канарейка, а не тег на уже публичный коммит: у
последнего судимое множество пусто, и форму «отвергать тег при любой уставной
дельте независимо от РАЗРЕШИЛ» он бы не отличил; выбранный вход прогоняет
зелёный путь самого суда. Отсылка к будущему «≥1 зелёный контроль» конверсии
недостаточна: морозится пред-заморозочный критерий, контроль должен быть назван
тегом до заморозки.

**2. Диагноз-требование — равномерно по всем классам отказов.** Каждая честная
красная фаза каждой hook-red фикстуры ассертит все три поля: полное имя ref
(`refs/heads/…` либо `refs/tags/…`), полный sha красного коммита (для тега —
разыменованного), путь. Push-проба check_hooks (ветвь Проба, фаза 2) — тоже все
три, не «путь и sha». Обоснованного отказа от равномерности нет: квантор п. 5
универсален («красный → … ПОЛНЫЙ диагноз»), точка отказа реализации может
ветвиться по классу коммита/ref (замер (б) это показал), каждая фикстура уже
захватывает вывод отказа и знает sha и ref — цена равномерности два грепа на
фазу.

## Побочный дефект, найденный замером (не предмет спора, но блокирует обещание)

`red_push_merge_gran_bez_stroki.sh` и `red_push_lechenie_ne_blokiruetsja.sh` в
текущем виде НЕ могут перейти red→green ни при какой реализации: toy-коммиты
делают `add -A` при установленном хуке и затягивают неотслеживаемый
`$T/.githooks/pre-push` в историю toy; последующий `reset --hard "$BASE"`
удаляет файл и каталог. В merge-red `cp` честного хука падает под `set -e`
(наблюдено: «cannot create regular file …/toy/.githooks/pre-push»); в
lechenie-red фаза 4 бежит вовсе без хука — красный force-push «проходит»
(наблюдено rc 1 с этой причиной при честном по веткам хуке). Для замера дефект
нейтрализован только в клоне (каталог хуков вынесен из рабочего дерева toy;
ассерты не тронуты) — после чего обе фикстуры дали ожидаемые rc. Автору —
починить toys в своей зоне (хуки вне рабочего дерева либо исключение
`.githooks` из `add`), иначе «ПОСЛЕ: → 0» невыполнимо.
