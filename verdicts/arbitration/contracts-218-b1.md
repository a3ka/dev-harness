### Implementer — формула выбора свидетельства

В PR-ветке для каждой уже выбранной версии:

1. По зафиксированному `PR_HEAD`, а не вновь разрешаемому символическому HEAD, успешно прочитать точную запись пути вердикта из дерева Git. Канонический способ — `ls-tree -r -z --full-tree` с literal-pathspec; разобрать запись NUL, сохранить тип и OID. Ошибка чтения дерева/разбора → `PR_WINDOW_TAG_UNREADABLE`, rc 1. Ненулевой rc не является отсутствием пути.
2. Запись существует: читать её blob по полученному OID, проверить статус чтения. Ошибка или непригодный тип → тот же именованный отказ rc 1; историческое тело не читать. Успешно прочитанное пустое тело — неразрешающий вердикт (rc 1), а не отсутствие записи. Непустое тело проверяется прежней грамматикой accept; существующий FAIL никогда не заменяется.
3. Только успешное чтение дерева без записи допускает прежний fallback: разрешить тег в commit с проверкой ошибки; подтвердить принадлежность основания `PR_COMMITS`. Если основание чужое — исторический accept не использовать, прежний отказ отсутствующего вердикта.
4. Для собственного основания тем же различением прочитать запись и blob. Ошибка → `PR_WINDOW_TAG_UNREADABLE`, rc 1; доказанное отсутствие или пустой вердикт → отказ без accept; прочитанный FAIL → прежняя предметная причина; прочитанный accept → продолжить остальные проверки без их амнистии.

Эквивалентная реализация допустима, если сохраняет эти состояния. Не вводить разбор локализованного stderr Git, особый «rc отсутствия cat-file», повторные попытки, общий fsck всего репозитория или новый инфраструктурный слой. Нужна локальная обработка выбранного свидетельства. Non-PR ветка остаётся прежней.
