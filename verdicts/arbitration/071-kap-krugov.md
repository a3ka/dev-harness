## Решение по вопросам

### П1. Кап — ДА, набран; и набран одной причиной

Три круга по одному предмету — кап по букве роли арбитра. Но важнее второй критерий: «два отказа
по одной причине». Причина одна во всех трёх: **граница argv между крюком и предполётом**.
r1 Р-1/Р-7 — крюк отдал предполёту весь argv (`push`/`origin` стали refspec-токенами); r2 Р-13 —
крюк отдал хвост `orig[@]:i` и потерял опции до remote; r3 F-1/F-2 — крюк отдал два хвоста
скаляром без кавычек и с дублем arity. Три разных среза одной и той же границы. Стороны три
круга правят симптом среза, а не определяют, КТО владеет грамматикой и в КАКОЙ форме argv
пересекает границу. Правило «не жди третьего» должно было сработать после r2 — не сработало;
это решение закрывает дыру.

Что меняется:
1. **Форма закрытия задаётся свойствами, не очередным срезом** (П3): до написания кода автор
   фиксирует в задании (а) владельца грамматики — предполёт, (б) форму передачи — массив
   `"${…[@]}"`, (в) таблицу флагов push со значением и правило §2 «неразбираемый флаг → отказ».
2. **Красное — первым**: клетки architect на каждый класс (состав ниже) пишутся и предъявляются
   красными на c963c73 ДО слияния impl-правки — как сам контракт требует для своих красных
   («красные предъявлены прогоном на нечиненом дереве»). Это и есть гейт против четвёртого
   FAIL по той же причине: у клетки есть мир с совпадающими путями в cwd, с push-options на bare,
   с `-c`/`-C` — то, чего п6в/п6г не имели.
3. **Гейт r4**: ревьюер судит по списку форм этого решения (П4). Формы с ранним exec 045
   (замер 2, «крюк не вызван») — не основание FAIL по 071.
4. **Счёт**: r4 — четвёртый судейский круг ревьюера по 071 (критик к1 до заморозки — отдельно).
   Кап оркестратора «>5 кругов → СТОП + пере-скоуп + владелец» (roles/orchestrator.md:274)
   не превышен, запас — один круг. Повторный FAIL r4 по той же причине (граница argv) →
   владелец немедленно (лестница architect.md:149-151), не арбитр.

### П2. Форма закрытия: ОДНА пачка fixr5 для достижимого крюком; недостижимое — к владельцу

Разбиение «F-6/F-7 отдельно, потому что они про чтение конфига/цели, а не про хвост» —
ОТКЛОНЕНО. Корень у них тот же, что у F-1/F-2: крюк НЕ передаёт предполёту контекст вызова
(`ctx[]` = -C/--git-dir, `cfg[]` = -c), которым сам 045 пользуется в каждом своём `git config`
(«единство разрешения», `scripts/gitw:410-411`). Предполёт судит cwd и голый конфиг — тот же
дефект интерфейса крюк→предполёт, другое поле. Делить одну границу на две пачки = два круга
ревьюера на одну причину при запасе в один круг.

Разбиение проходит по другой линии — **достижимо ли крюком** (замер 2):

- **Пачка fixr5 (impl + arch, один круг r4):** F-1; F-2/F-4/F-5 в формах со значением ПОСЛЕ
  remote (c20, c34, c35, c39, c42, c43) и через `=`; F-3; F-6 (все три формы); F-7.
- **Предел предмета → владельцу:** F-2/F-4/F-5 в формах со значением ДО remote (c19, c21, c36,
  c40): крюк не исполняется — exec канарейки 045 раньше. См. П4 и «Вопрос владельцу».

Порядок внутри пачки — по общему корню, затем по частоте укуса:
1. impl-1: argv крюк→предполёт массивом в кавычках + передача ctx/cfg (закрывает F-1, основа
   F-6/F-7);
2. impl-2: таблица флагов push в предполёте (arity 0/1, `=`-формы; `--repo` в ней же; неизвестный
   флаг → «несудимая конфигурация refspec: неразбираемый флаг <f>» по §2) — F-2/F-4/F-5
   (post-remote);
3. impl-3: нормализация refspec (ведущий `+` сбрасывается; `@` ≡ HEAD) — F-3;
4. impl-4: охват конфига в ветви «без refspec при ветке ≠ main»: `push.default` и
   `remote.<r>.push` читаются в контексте ctx/cfg; `remote.<r>.push` с dst main — покрытие; иной
   `remote.<r>.push` — несудимая конфигурация (§2 fail-closed) — F-6; текущая ветка / конфиг /
   worktree list — репозитория из ctx — F-7.
Коммиты атомарны по классам, но лендятся ОДНИМ слиянием и судятся ОДНИМ кругом.

### П3. __scan_tail: форма ревьюера НЕ обязательна; обязательны свойства

Форма ревьюера «в цикле цели копить индексы опций-значений в bash-массив» ОТКЛОНЕНА как
обязательная: «цикл цели» — это И-4а 045, а ПЕРЕСЕЧЕНИЕ 071 запрещает трогать разборы 045
(замер 4: четыре строки туда уже просочились — углублять нельзя). Автор прав в том, что форму
выбирает он. Ревьюер прав в диагнозе: ACCIDENTAL, дубль грамматики, неявное состояние (замер 5).
Поэтому для fixr5 обязательны СВОЙСТВА; нарушение любого — блокер r4:

- **С1. Ни одной неквоченной скалярной подстановки argv** на пути крюк→предполёт: передача
  только элементами массива (`"${arr[@]}"`). Токены доходят побайтово (глоб, пробел, пустая
  строка).
- **С2. Грамматика опций push со значением — ровно в ОДНОМ месте**, и это место — предполёт
  (cutover r2 Р-7 уже назначил его единственным парсером). В крюке — ни `--repo`, ни иной
  arity; в цикле И-4а 045 — ни одной новой строки.
- **С3. Неизвестный флаг push → именованный отказ** (§2 дословно: «неразбираемый флаг push →
  rc 1 «…несудимая конфигурация refspec: <деталь>»»). Текущее `-*) continue` (preflight `:67`)
  §2 нарушает. Таблица известных флагов — явный список; флаги, меняющие семантику refspec
  (`--delete`/`-d`, `--all`, `--mirror`, `--tags`, `--prune`), в ней же.
- **С4. Контекст вызова (ctx/cfg) доходит до предполёта** и применяется к КАЖДОМУ его `git`:
  symbolic-ref, config, rev-parse, worktree list, show-ref.

Простейшая форма, удовлетворяющая С1–С4: крюк отдаёт предполёту `"$target"` + ctx/cfg + ВЕСЬ
argv после подкоманды элементами массива, а предполёт сам по таблице флагов находит первый
позиционный токен (= repository по git-push(1)) и исключает его; тогда `__scan_tail`,
`pre_tail`/`post_tail` и `__target_in_argv` не нужны вовсе. Арбитр её НЕ предписывает —
записывает как ориентир; автор волен выбрать иную, если С1–С4 держатся. Шапка крюка
(С-2 ревьюера, `:596-603`) обязана описывать то, что делает код.
