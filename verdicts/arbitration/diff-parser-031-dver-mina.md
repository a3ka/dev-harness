# Арбитраж 031: перечисление строк unified diff в двери минта (3-й круг класса all-lines/only-additions)

Стороны: автор конструкции (фиксы 5700400+37ac33b «valid_count==add_count», db3936c «([^+]|$)») и адверсарий (вердикты к1 57bb16a, к2 64b0ae9, к3 05b07e9). Судья к3 направил в арбитраж: три круга подряд находят строки, невидимые предикату — смешанная невалидная (к1), пустая bare «+» (к2), содержимое с ведущим +/− (к3: дифф-строки «++garbage»/«--garbage» неотличимы от мета-заголовков «+++»/«---» по второму байту).

## Решение по существу

**Прав адверсарий к3 по обоим обходам, прав судья к3 по способу лечения.** Принят кандидат (а) — хунк-контекстный парсер: строки дельты перечисляются ТОЛЬКО внутри тел hunk'ов (после каждой строки `^@@` до конца диффа одного пути); строка тела с ведущим «+» — добавка, содержимое = всё после РОВНО одного ведущего «+» (включая «+x» из дифф-строки «++x»); с ведущим «-» — удаление; маркер «\ No newline at end of file» не судится. Заголовки `diff --git`/`index`/`---`/`+++` при диффе одного пути существуют только ДО первого `@@` и в перечисление не попадают — класс «второй байт решает» закрыт по построению, а не очередной заплаткой на regex.

Кандидат (б) — plumbing без текстового парсинга (сравнение блобов HEAD/staged) — ОТКЛОНЁН: чтобы доказать «только-добавления» без диффа, нужно либо заново реализовать LCS (диффом и является), либо ужесточить семантику до append-only (запретить вставку в середину), что меняет условие 1 механизма 1 замороженного 031/4 («staged-дельта пути (git diff --cached -U0) — ТОЛЬКО добавления» — дифф-семантика, вставка в середину есть добавление) и команду, названную замороженным текстом. Это территория v5 без выигрыша в силе.

Кандидат (в) — мультимножество строк — ОТКЛОНЁН как ОСЛАБЛЕНИЕ: перестановка существующих строк рядом с валидной добавкой у мультимножества невидима (0 удалений), а дифф-семантика её отвергает как не-только-добавление. Дифф ≠ множество; дверь обязана оставаться строже.

## Cognitive-only (не пробуется)

- Гард `/^diff /{h=0}` — оборонительный для гипотетического многофайлового диффа; при диффе одного пути (`-- registry/contracts.tsv`) недостижим, ворот не получает.
- Поведение на маркере «\ No newline at end of file» — не судится, семантика не изменена относительно текущего кода (замер 2, строка 16); отдельные ворота не заводятся.
- Довод «строка тела hunk'а при -U0 начинается только с +, − или \» — свойство формата git, держится замером 2 (строки-мимики), отдельной вечной пробы не требует.

Счёт по сторонам: обходы к3 — адверсарию целиком (оба подтверждены замером); способ лечения — по указанию судьи к3, принят с доказательством полной батареей; кандидаты (б)/(в) автору и не предлагались как позиция — отклонены арбитром по существу.
