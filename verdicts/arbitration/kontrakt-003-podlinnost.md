# Арбитраж 5: подлинность скилов и граница cognitive-only — контракт 003

Созван критиком по механическому триггеру: повтор причин блокировок в двух кругах по
`contracts/003-skills-metta-adaptacija.md` (вердикты `932f292` круг 1, `7891530` круг 2).
После созыва автор принял все пять обходов круга 2 и закрыл их коммитом `5242be3`, сняв два
своих cognitive-only. Судится контракт на HEAD (`5242be3`) как спецификация барьера: механизмов
в дереве ещё нет.

Предмет спора дословно: достаточно ли декларации/cognitive-only и проверки конечного состояния
там, где предмет требует механически отличить заимствованный оригинал и действие механизма от
имитации.

Решение обязательно к исполнению обеими сторонами. Решённое здесь в новых кругах не
переоткрывается — несоответствие предъявляется ссылкой на этот файл.

## Решение по предмету спора — принцип

Критик прав по принципу, автор прав по направлению закрытия. Формула, по которой разведены все
ветви ниже:

- **cognitive-only не принимается там, где механизация достижима ценой одного прогона.**
  Правило 1 нормы даёт выбор «механизм ИЛИ cognitive-only», но выбор не свободный:
  cognitive-only — это записанная НЕДОСТИЖИМОСТЬ механизма, а не жест по умолчанию. Оба снятых
  автором cognitive-only (тела, условие указателя) были механизируемы — автор сам это доказал,
  сняв их за один коммит.
- **проверка конечного состояния достаточна тогда и только тогда, когда конечное состояние
  логически влечёт действие.** Ветвь (д) из пустого HOME — достаточна: равенство после старта
  с нуля влечёт копирование. Приёмка 4 на реальном профиле — недостаточна: её конечное
  состояние наблюдается только ok-строкой (замер-заглушка ниже).

## Замеры

Свежий контекст, первоисточники, прогоны — не пересказ сторон.

1. **Снимок существует, но объявленный URL мёртв.** `api.github.com/...commits/9c9f36c…` → 200;
   `raw.githubusercontent.com/mattpocock/skills/9c9f36c…/skills/grilling/SKILL.md` → **404**.
   Дерево снимка (`git/trees?recursive=1`): пути несут промежуточную категорию —
   `skills/productivity/grilling/`, `skills/productivity/writing-for-agents/`,
   `skills/engineering/tdd/`, `skills/engineering/diagnosing-bugs/`. Ветвь (е) как написана не
   может стать зелёной НИКОГДА: все четыре cmp получают 404.
2. **`grill-me` в снимке — отдельный каталог `skills/productivity/grill-me/`**, тело — ровно
   роутер «Call the Skill tool with "grilling".» (7 строк с фронтматтером). Утверждение
   предмета контракта фактически верно.
3. **Обход критерия 3 построен и прогнан** (tmp/arbiter/demo3): архитектор коммитит ОДНУ
   фикстуру → исполнитель коммитит `skills/` → архитектор докладывает шесть фикстур → барьер.
   Обе меры критерия 3 зелёные: первая даёт `architect`, вторая — ранний фикстурный хеш. Шесть
   из семи фикстур написаны ПОСЛЕ реализации — предмет Q8-C не сделан.
4. **Обход приёмки 4 построен и прогнан** (tmp/arbiter/demo4): overlay-заглушка копирует
   ТОЛЬКО когда `$HOME` похож на временный каталог, иначе no-op с ok-строкой. Ветвь (д)
   (пустой временный HOME, cmp) — зелёная; реальный профиль после `npm run overlay` — пуст.
   Вся приёмка зелёная, встройка в воркфлоу не состоялась.
5. **Заморозка на HEAD механически невозможна:** `freeze_contract.sh` вычисляет v1 и требует
   на HEAD `verdicts/critic/contracts-003-v1.md` с первой строкой `accept`; первая строка
   сейчас — `FAIL`.
6. **Счёт ветвей в тексте ложен:** заголовок критерия 1 объявляет «ШЕСТЬ ветвей отказа»,
   перечислено семь — (а)…(ж); критерий 3 требует «фикстуры ПЯТИ ветвей» без называния,
   каких пяти из семи.

## Вопрос 1 — закрытие по существу, поветвенно

- **(а), (б), (г)** — обходов нет. Закрыто.
- **(в)** — hash шапки из блоба высшей заморозки, не зашит в барьер. Закрыто верно.
- **(д)** — на уровне барьера закрыто верно: пустой HOME снимает и предзаполненный профиль,
  и no-op (обход круга 2 мёртв). Остаточный обход живёт в СВЯЗКЕ с приёмкой 4 — замер 4.
- **(е)** — направление верное (cmp с неизменяемым raw по закреплённому коммиту), снятие
  cognitive-only правильное. Но ветвь не готова трижды:
  1. фактическая ошибка пути (замер 1) — критерий в нынешней букве невыполним;
  2. hash в URL не привязан к блобу заморозки. Обход: исполнитель правит hash в барьере
     (его зона) на снимок X и кладёт тела из X; (в) зелёная — шапка по-прежнему несёт
     9c9f36c и совпадает с заморозкой, (е) зелёная против X; в дереве тела чужого снимка
     под лгущей шапкой. Закрыть: (е) строит URL из ТОГО ЖЕ значения блоба заморозки, что
     и (в), — либо из шапки, уже сверенной ветвью (в);
  3. байт-граница «шапка/тело» не задана. Наш `SKILL.md` несёт русскую шапку-адаптацию,
     upstream её не несёт — cmp целых файлов красен всегда; какие именно байты есть «тело»
     (и входит ли английский фронтматтер upstream), спека обязана назвать, иначе извлечение
     остаётся на усмотрение проверяемого — территория подгонки.
- **(ж)** — закрыто на честном полу: grep по «grill-me» в шапке `grilling`. Остаток («слово
  есть, но в отрицающем контексте») — смысл; по правилу 8 смысл механизмом не измеряется.
  Не блокирует.
- **Критерий 2 (указатели)** — обход круга 2 (путь без слова) мёртв: пара «путь + ведущее
  слово в одной строке, ровно 1, посторонних нет» механически наблюдаема. Закрыто.
- **Критерий 3 (порядок Q8-C)** — обход круга 2 (skills/ вне меры) мёртв, но мера закрепляет
  только ПЕРВЫЙ фикстурный коммит — замер 3. Закрыть мерой полноты: на РОДИТЕЛЕ первого
  коммита по `skills/ scripts/check_skills.sh` дерево `fixtures/check_skills/` уже содержит
  фикстуры ВСЕХ объявленных ветвей (счётно — по именованию фикстур поветвенно). Поздние
  фикстуры по заявкам законны по самому контракту и порядковой мерой не ловятся — это
  остаётся процессным риском заявочного пути, его назвать в тексте.

## Вопрос 2 — граница cognitive-only в критерии 2

**Честная.** Механический пол выбран максимальным из разумных: путь и ведущее английское слово
в одной строке, счёт ровно 1 на пару, запрет посторонних `skills/`-строк. Остаток — качество
русского условия — есть чистый смысл; по правилу 8 порог отсекает отметку от предложения и этим
исчерпывается. Дальнейшая механизация русского текста была бы grep-плацебо: проверкой формы,
выдающей себя за проверку смысла. Ловец назван (ревьюер). Подмены нет.

Различие с двумя снятыми cognitive-only именно здесь: там механическая мера была достижима
(cmp, ведущее слово), тут достижимой меры нет — есть только плацебо.

## Вопрос 3 — годность к заморозке

**НЕ годен на текущем HEAD.** Пять точечных дефектов, все закрываются одной правкой текста:

1. (е): полные upstream-пути снимка поимённо — `productivity/grilling`,
   `productivity/writing-for-agents`, `engineering/tdd`, `engineering/diagnosing-bugs`
   (замер 1);
2. (е): hash URL — из блоба высшей заморозки, как в (в);
3. (е): байт-граница «шапка/тело» задана в спеке;
4. приёмка 4: после реального прогона overlay наблюдается РЕАЛЬНЫЙ профиль (cmp каждого
   `SKILL.md` профиля с репозиторным) — закрывает заглушку замера 4;
5. критерий 3: мера полноты фикстур на родителе первого коммита реализации — закрывает
   заглушку замера 3; счёт ветвей выправлен («семь», не «шесть»; фикстуры каких ветвей —
   поимённо, не «пяти»).

После правки — вердикт критика с первой строкой `accept` на HEAD, затем заморозка. Это не круг
сверх регламента и не назначение арбитра: `accept` на HEAD — механическое условие самого
`freeze_contract.sh` (замер 5), без него тег не встанет физически.

## Вопрос 4 — класс для NABLIUDENIA

**Да, и он двойной.** Рекомендация архитектору (файл в его зоне, я его не правлю):

- **«cognitive-only по умолчанию».** Дважды за два круга автор пометил cognitive-only то, что
  механизируется одним коммитом (тела → cmp; условие указателя → ведущее слово), и дважды снял
  пометку, когда критик показал достижимость. Цена: минимум один круг критика и созыв этого
  арбитража. Закрытие: пометка cognitive-only действительна только со строкой-причиной
  «механизация неисполнима, потому что <замер либо цена>»; пометку без причины судья блокирует.
  Симметрия с порогом критика из Н-1: автор, требующий от судьи предъявления, предъявляет сам.
- **Соседний рецидив класса Н-17 («со слов, а не из каталога»), найденный этим арбитражем:**
  механическая ветвь (е) написана против внешнего ресурса БЕЗ единого прогона — URL мёртв
  (замер 1, 404). Цена прогона — секунды; цена ошибки — невыполнимый критерий в замороженном
  контракте и круг правки vN. Закрытие то же по духу: команда, вписанная в контракт как мера,
  прогоняется один раз до коммита.
