## Решение

### (а) Семантика значения — байтовая строка без обрезки

1. **Значение `ci.workflow`** = байты UTF-8-вывода `jq -j '.ci.value.workflow'` из MERGED,
   ВСЕ, включая NUL, LF, CR, TAB, любые управляющие. Ни одна переменная, полученная через
   `$(…)`, `read -d ''`, `cat` или иной срезающий канал, значением НЕ является и для
   суждения не используется. Ревьюер прав по Н1 целиком.
2. **NUL внутри алфавита 054** («непустая строка», P6 не расширяется — 054 заморожен). Следствие
   по И-2(б): байт NUL не может быть частью пути ни в одной POSIX-ФС и не может быть передан
   `readlink`; «пустой результат / несуществующий объект» → фраза **ОТСУТСТВУЕТ**, rc 1,
   stdout пуст. Наличие NUL судится **счётом байтов** (число NUL в байтовом значении > 0
   или `jq … | contains("\u0000")` по MERGED), не сравнением bash-строк. Порядок И-2
   сохраняется: сначала (а) АБС по первому байту (`/\0x` → АБС; префикс до NUL начинается с
   `/` ⟺ значение начинается с `/`), затем NUL → ОТСУТСТВУЕТ, затем канонизация.
3. Предупреждения bash о NUL из 054-гейтов :361/:391 обязаны исчезнуть: непустота проверяется
   без подстановки байтов значения (например `jq -e '… | type == "string" and length > 0'`).
   **Семантика 054 не меняется**: фразы P6 байт-в-байт прежние (эталон `empty_cw` выше:
   `profile ОТКАЗ: значение вне алфавита: ci.workflow: пусто`), батареи 054/055/057 rc 0.
   Это в зоне implementer (`scripts/profile_resolver.sh`) и необходимо для И-3 059 («по одной
   на строку stderr») на NUL-входе; текст 054 не трогается.

### (б) Существование — точное байтовое

4. **LF (как и CR, TAB, пробел, `'`, UTF-8) — законный байт имени файла.** Ветвь :631-637
   («файл с LF в имени существовать не может → ОТСУТСТВУЕТ») опирается на ложную посылку и
   **удаляется**. Ревьюер прав по Н2 целиком. Существование судится ТОЛЬКО канонизацией
   полного байтового значения: `readlink -f -- "$REPO_ABS/<значение>"` → `-e` → принадлежность
   `"$REPO_ABS"/*` → `-f`.
5. **CANON захватывается байт-точно** (З-А): `readlink -f -z … | IFS= read -r -d ''`, либо
   сентинел `$(readlink -f …; printf x)` со срезом `x` и ровно одного завершающего LF, либо
   иная форма с тем же свойством. Замер: `-z/read` даёт 32/32 байта и `-f=yes`.
6. Итог для к3 контракта: файл `ci/a<LF>b.yml` существует и объявлен `"ci/a\nb.yml"` →
   rc 0, stderr пуст, merged `.ci.value.workflow` = `"ci/a\nb.yml"` дословно. Файл
   `ci/ok.yml<LF>` существует (а `ci/ok.yml` — нет), объявлено `"ci/ok.yml\n"` → rc 0.

### (в) Форма печати `<CW>` и `<CANON>` — сырьё, если можно; `$'…'` с фиксированной таблицей, если нельзя

7. Н3 решается текстом заморозки без владельца. И-3 требует одновременно (i) «литералы
   байт-в-байт», (ii) «значение названо», (iii) «по одной на строку stderr». Единственное
   прочтение, удовлетворяющее всем трём: **значение печатается сырьём (байт-в-байт), кроме
   случаев, когда сырьё ломает однострочность или однозначность** — тогда в экранированной
   форме. «Всегда %q» ломает (ii) на обычных значениях (`ci/my\ file.yml`, `ci/\'q\'.yml`) и
   зависит от локали (`$'ci/\303\274…'` под `LC_ALL=C` — ubuntu-latest CI локаль не
   выставляет, `ci.yml` без `LANG`/`LC_ALL`); «всегда сырьём» ломает (iii) (Р2). Ревьюер прав
   по существу Н3 (сырьё — база; локаль — дефект); implementer прав в том, что управляющие
   байты требуют экранирования. Прецедент прочтения: проба литералов к1
   (`r059-literals.sh`, 5/5 байт-в-байт при `<CW>` = сырое значение) принята adversary к2.
8. **Правило формы** (единое для `<CW>` и `<CANON>`; `<REPO_ABS>` — аргумент лаунчера, не
   данные профиля, печатается как сейчас):
   - **Сырьём**, если значение не содержит ни одного байта из C = {0x00–0x1F, 0x7F} И не
     начинается с двух байтов `$'` (З-В: иначе сырое имя `$'…'` неотличимо от экранированного).
   - Иначе — **`$'…'`-нотация с фиксированной, независимой от локали таблицей**:
     `\` → `\\`; `'` → `\'`; LF → `\n`; CR → `\r`; TAB → `\t`; любой другой байт из C
     (включая NUL и DEL) → `\xHH` (две строчные hex-цифры: NUL → `\x00`, DEL → `\x7f`);
     все прочие байты, включая UTF-8 ≥ 0x80, — сырьём. `printf %q` НЕ используется
     (локаль; неспособность нести NUL).
   - Отображение инъективно: сырая форма никогда не начинается с `$'`, экранированная —
     всегда; декодирование однозначно.
   - Наблюдаемые следствия: к18/к19 печатают то же, что сейчас (`$'ci/ok.yml\n'`,
     `$'ci/a\nb.yml'`); `ci/my file.yml`, `ci/'q'.yml`, `ci/ü-нет.yml`, `/abs/my file.yml`
     — сырьём в любой локали; NUL-значение — `$'ci/ok.yml\x00x'`.
   - Реализация формы свободна; рекомендуемая — один jq-фильтр по MERGED (jq несёт U+0000,
     не зависит от локали, вывод после экранирования безопасен для `$(…)`); bash-цикл по
     байтам допустим. 050-совет ревьюера (сентинел вместо временного файла + trap) —
     совет, не критерий; NUL-детекция через jq делает временный файл ненужным.
   - Экранирование `\\`/`\'` клетками не пинуется — закрывается чтением исходника судьёй
     (прецедент socket/device, арбитраж 059-к3 п.3.4).
