## Решение по пунктам

**Блокер круга 3 — ИСПРАВИТЬ (дефект эталона, зона architect; реализация — дословный порт, различий нет). Прав адверсарий по факту и по квалификации.** И-4 на OBJECT: «`priemka.sverka` — … rc 0 И stdout дословно равен сверке-образцу раннера 123 по манифесту пачки»; §З: «сверка — запуск раннера 123 по манифесту кадров пачки»; ЗАЩИЩАЕТ: «раннер 123 вызывается по коду». Вызов с посторонним манифестом — не вызов «по манифесту пачки», стандарт сильнее кода; stdout-равенство этого не ловит по построению (копия отвечает на тот же вопрос, а подставить можно и другой допустимый манифест с тем же выводом). Довод консультанта (малая правка модели + клетка + стаб + синхронизация + один scoped-микро-круг) — верен; арбитр добавляет к нему ДВА уточнения, без которых правка либо ложно-красная, либо дырявая:

1. **Связь `--manifest` — по байтам, не по пути.** Замер 4: честная форма батареи (и, по комментарию `build_repo`, продуктовая конвенция «пин механизма 123 внутри репо») зовёт `.harness123/kadry.json` — байт-копию `pack/kadry.json` с иным realpath. Правило: `sha256(repo / sv_manifest) == sha256(pack / f['kadry'])` (тот же файл по realpath — частный случай, покрыт). Это тот же принцип, что уже принят для раннера в круге 2 (идентичность по байтам, имя/путь — не дискриминатор). Вход адверсария (изменён `_comment`) — байты иные → `SAMODELNAYA_SVERKA`; это принято сознательно: копия с правкой комментария — не манифест пачки, честной форме править копию незачем. Альтернатива «перевести честную форму на путь пачки и связывать realpath» отклонена: меняет конвенцию продукта и форму `source.json` без нужды, а пачка вне repo (как в батарее: `tmp/pack` ↔ `tmp/repo`) не имеет устойчивого относительного пути от cwd = repo.
2. **Связь `--kadry` и `--repo` — по realpath:** `realpath(repo / sv_kadry) == realpath(repo / f['kadry_dir'])`, `realpath(repo / sv_repo) == realpath(repo)` (`--repo .` от cwd = repo — зелёный; абсолютные пути — зелёные; симлинк — зелёный). Замер 2: без связи `--kadry` свежесть судится по одному каталогу, сверка — по другому; это ТОТ ЖЕ дефект (вердикт круга 3 называет все три флага), а не новый класс, потому входит в перечень.

Порядок проверок (до или после исполнения команды) — за architect; судится только исход. Сравнение путей — по `os.path.realpath` (не по строке и не по `Path.resolve(strict)`), несуществующий путь — отказ `SAMODELNAYA_SVERKA`, не исключение.
