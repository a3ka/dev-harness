# Арбитраж 074-к1b — предел проверки перечитывания (где кончается ловец)

Созван по триггеру «три круга по одному предмету»: адверсарий дал FAIL на
к1, к2, к3 (`verdicts/adversary/contracts-074-r1.md`, `-r2.md`, `-r3.md`),
причина каждый раз одна по классу — субъект, пишущий адресат механизмом вне
множества, которое умеет портить клетка к1b, проходит батарею с rc 0 без
перечитывания sha256. Ловец трижды расширяли (cp-шина → cp/cat/install-шины
→ LD_PRELOAD-interposer + 6 канальных проб), и трижды следующий круг находил
следующий механизм (cat/install → tee → python3 `os.pwritev`/`os.splice`/
`mmap.flush`).

Судимое дерево: main `0d2cd8d`, клон `/tmp/dev-harness-verify/arb074k1b2/repo`,
прогоны последовательны, ничего не пушилось. Первоисточники прочитаны
целиком: контракт (§Модель угроз, §Остаточный риск, инвариант 3, А3), три
вердикта адверсария, `fixtures/ops_server/korrupt_write_074.c`,
`fixtures/ops_server/red_server_obvjazka_074.sh` (клетка `cell_k1b` :336-402,
канальные пробы :600-640), субъект `ops/server/install.sh`.

Стороны:
- (А) адверсарий: живой обход = блокер; python3 штатно обязателен для раннера,
  к3-входы реальны и дёшевы;
- (Б) автор конструкции: предмет — шелл-скрипт штатными утилитами; модель
  угроз называет предел (сговор/адаптивный противник); расширение ловца
  порождает следующий обход — гонка без конца за счёт проекта.

## Замеры

З1. Честный субъект (main) на штатном прогоне: rc 0; к1b печатает
`субъект отказался на испорченной записи (interposer испортил записей: 1)`,
`к1b-каналы: честные 6/6, ленивые пойманы 6/6`. Канал на честном субъекте
неинертен.

З2. Воспроизведён вход к3 адверсария (мир `pw`: `git archive` main, в
`install.sh` user-копирование заменено на `python3 -c` с `os.pwritev`
блоками по 4096, `check_one` после записи удалён, прочее дерево целое):

```
REPO_ROOT=<клон> OPS_ROOT=<pw> bash fixtures/_krasnye_074.sh
  k1b: все каналы порчи инертны (субъект не пишет байты — rename-класс,
       остаточный предел) — проба не судит, перечитывание судится стабом s7
       и канальными пробами
честная часть: 7/7 зелёная
итог 074: красных клеток=0 стабы=7/7
rc=0
```

Факт адверсария подтверждён: ленивый субъект принят, и принят именно веткой
`cell_k1b` :389-395 — «хэш адресата == пин и журнал порчи пуст → return 0».

З3. Где в коде рождается обход. `cell_k1b` различает три исхода: (а) порча
дошла, субъект отказал с «расхождение»+имя — зелёное; (б) порча дошла,
rc 0 — красное; (в) порча НЕ дошла (журнал пуст, байты целы) — **зелёное с
пометкой**. Исход (в) — это «нечем судить», и батарея сама в :97 постулирует
для того же канала: «канал «любой механизм» мёртв, это НЕ зелёное: rc 2
NOT_IMPLEMENTED» (нет cc → rc 2). Канальные пробы :620 тоже считают
инертность честной вариации ДЕФЕКТОМ (`grep -q 'инертн'` → красное). Только
главный вызов на субъекте :674 трактует «не смог судить» как «судил и
доволен». Все три круга обхода — ровно эта ветка; ни один из найденных входов
не обходил interposer «с порчей» (исход б) — все уходили в (в).

З4. Что даёт замена исхода (в) на красное. В throwaway-копии дерева
(`fc`, не коммитилась) :394-395 заменены на
`printf 'k1b: канал порчи инертен … перечитывание НЕ ДОКАЗАНО (fail-closed)'; return 1`.
Последовательно:

| прогон | rc | строки |
|---|---|---|
| штатный (честный main) | 0 | честная 7/7, каналы 6/6+6/6, красных 0 |
| `FIXSIM=1` | 0 | то же |
| `LANDSIM=1` | 0 | то же |
| мир `pw` (pwritev без перечитывания) | **1** | `КРАСНО: cell_k1b`, красных 1 |

Один флип ветки закрывает к3-вход, не трогая ни одного зелёного контроля.
По построению он закрывает КЛАСС, а не экземпляр: любой субъект, чья запись
ненаблюдаема корруптором (pwritev/pwritev2/splice/mmap+msync/mv-класс/
статический syscall), не получает порчи → байты целы, журнал пуст → красное
«не доказано». Остаются ровно два пути к зелёному: отказать с «расхождение» на
испорченных байтах (= перечитать) или различить окружение батареи и
подстроиться (= сговор, названный предел модели угроз, не этого спора).

З5. Цена расширения interposer на к3-входы (по коду `korrupt_write_074.c`):
`pwritev/pwritev2` — ~20 строк, тот же приём, что `writev`, надёжно;
`splice` pipe→файл — эмуляция чтением pipe и pwrite, ~40 строк, хрупко
(семантика смещений/частичных переносов); `mmap`+`msync` — страницы пачкает
не вызов, а память: PLT-перехват принципиально не видит записи, возможна
только подмена `mmap` на анонимную область с копированием на `msync/munmap`
— по сути второй корруптор. Статический бинарник и `mv` недостижимы вовсе.
Перечисление НЕ сходится — это измерено тремя кругами и подтверждено
структурно: класс «ненаблюдаемая запись» непуст при любой длине списка.

## Решение по спорным пунктам

П1. **Есть ли блокер.** Прав (А): ленивый субъект принят батареей с rc 0 —
это дефект различимости батареи (замер З2), а не «названный предел». Довод (Б)
«контракт защиты от сознательно написанного обхода не обещал» неточен в этом
пункте: к3-субъект не сговаривается с батареей (не знает её путей и
окружения), он просто не перечитывает — ровно то, что инвариант 3 и А3
обязывают батарею отличать. Ссылка (Б) на «cp-шина инертна … печатает
пометку» в §Остаточный риск описывает дефект, а не оправдывает его: пометка
«не судит» + rc 0 = зелёное без суда, что противоречит принципу самой батареи
(:97) и правилу 2 Frontier контракта («скрипт не имеет права печатать PASS»).

П2. **Какой ловец.** Прав (Б) в том, что гонка перечислений бесконечна и
платит за неё проект (З5). Предписание «расширить interposer на pwritev/
splice/mmap» ОТКЛОНЯЕТСЯ как форма закрытия: mmap закрыть PLT-перехватом
нельзя, mv/статику — тем более; четвёртый круг нашёл бы четвёртый механизм.
Предписание (А) «либо ограничит допустимый механизм нормативно и проверяемо»
(r3, последний абзац) — ПРИНИМАЕТСЯ: это и есть форма.

П3. **Форма (вариант 3).** Клетка к1b становится fail-closed:
- исход (в) «порча не дошла, байты целы, журнал пуст» на ГЛАВНОМ субъекте —
  красное с именованной причиной вида «к1b: канал порчи инертен для механизма
  записи субъекта — перечитывание НЕ ДОКАЗАНО»; `return 0` и пометка
  «проба не судит» удаляются;
- норма субъекта (контракт, инвариант 3 или А3, формулировка автора):
  user-часть пишет адресат механизмом, наблюдаемым каналом порчи к1b
  (write-класс libc: write/pwrite/writev/fwrite/copy_file_range/sendfile —
  штатные cp/cat/install/tee/dd/shutil); субъект с ненаблюдаемой записью
  не «риск», а красный к1b по построению. Это норма с механизмом (правило 1
  Frontier), а не проза;
- §Остаточный риск: пункт «cp-шина клетки к1b инертна … проба печатает
  пометку и не судит такой субъект» ЗАМЕНЯЕТСЯ на: «ненаблюдаемая запись
  (pwritev/splice/mmap/mv/статический syscall) не покрывается корруптором и
  судится fail-closed: к1b красна, субъект обязан перейти на наблюдаемый
  механизм или расширить корруптор вместе с субъектом. Остаточным остаётся
  только сговор субъекта с окружением батареи (общий класс семьи 058-073)»;
- комментарии `korrupt_write_074.c` (:27-29) и `red_server_obvjazka_074.sh`
  (:21-25, :349-352): «остаточный предел (назван, не расширяется)»
  переформулируется в «граница наблюдаемости; ненаблюдаемое — красное, не
  зелёное»; список механизмов остаётся как документация границы;
- канальные пробы :600-640 и стаб s7 не трогаются (они уже fail-closed);
  строку `grep -q 'инертн'` :620 автор вправе упростить, раз инертность
  теперь даёт rc≠0 сама.

Расширение interposer на `pwritev/pwritev2` (~20 строк, З5) — МОЖЕТ, не
ОБЯЗАН: при fail-closed оно не меняет ни одного вердикта на нынешнем субъекте
(cp) и нужно только если автор сам захочет такой механизм в субъекте.
splice/mmap не расширять.

П4. **Кап кругов.** Круг к4 адверсария — ОДИН, на новом дереве, предмет круга
ограничен: (i) мир `pw`-класса (любой ненаблюдаемый механизм без
перечитывания) даёт rc 1 с именованной причиной к1b; (ii) штатный/FIXSIM/
LANDSIM — rc 0 (З4 показывает, что оба достижимы одной правкой). Новый
механизм записи, уходящий в красное «не доказано», — НЕ блокер: это
предписанное поведение. Блокером в к4 считается только ленивый субъект,
получивший rc 0 без сговора с окружением батареи (сговор — предел модели
угроз, вне спора).

## Счёт по сторонам

П1 — адверсарию (блокер есть, факт подтверждён замером). П2 — автору (гонка
перечислений отклонена). П3 — форма адверсария из r3 («нормативно и
проверяемо»), механизм — из собственной конструкции батареи (:97, :620).
Независимость: каждое спорное утверждение решено прогоном (З1-З4), не
доверием.
