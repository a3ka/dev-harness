## Q1. Как доказать конечной батареей обещание на всём классе точек смерти — что закрывает по построению, что лишь повышает цену

1. **Факт спора — за критиком, целиком, и шире, чем он измерил.** Обязательство инв. 8/10 (контракт :47, :49) — универсальное по точке смерти: «мёртвый owned PID при отвечающем serial … готовность/установка/набор по нему не выполняются». Батарея OBJECT предъявляет три ТОЧКИ (сразу после EMULATOR_START, на boot-диагностике перед набором, после старта набора) и принимает контрмодель, устанавливающую APK на чужой serial (замер 2, 5). Это «ложная достаточность критерия» §Порог `roles/critic.md`, класс тот же, что в круге 1 (доверие отвечающему serial вместо жизни owned PID). Свип (замер 4) показал больше: **сама модель S OBJECT после смерти owned PID на `wait-for-device`/`getprop`/первых `settings put` исполняет оставшиеся `settings put global … 0` на чужом serial** — четыре точки из 18. Это тот же класс, не найденный ни одной стороной: «готовность по нему не выполняется» нарушено текстом собственной модели автора, а не только контрмоделью критика. Формулировка Q1 задания (от оркестратора, автор её не оспорил) называет настройки состояние-меняющим действием; текст инв. 8 «готовность … по нему не выполняется» — тем более: спорить с классификацией нечем.

2. **Почему метод сторон не сходится — урок 136/142 буквально.** Класс оси «владение инкарнацией» — «смерть owned PID в ЛЮБОЙ точке между вызовами инкарнации». Точка в клетке представляет класс одной точкой; конечное множество точек — список, и субъект с проверками ровно в этих точках зелен по построению (Н-408: «клетка на мутант» не сходится). Критик 2/2 в ЗАКРЫВАЮЩЕМ СВОЙСТВЕ снова предложил точку («смерть после ранней проверки, но до install») — третья точка породила бы четвёртый круг (проверка перед install, но не перед третьим `settings put` — замер 4 показывает, что такая модель уже существует: это OBJECT). Таблица осей у автора верная (кто умирает: новый owned PID; когда: до/в/после набора); неверна подстановка фиксированных моментов вместо порождения всех точек раннером.

3. **Что закрывает класс ПО ПОСТРОЕНИЮ — вариант (а), СВИП смерти, с уточнениями прототипа.** Механизм тот же, которым батарея уже защищает журнал вызовов: PATH замкнут (всё вне алфавита шимов — 127), поэтому множество точек, где субъект отдаёт управление наружу, — это ровно множество вызовов шимов, и оно ВЫВОДИТСЯ чистым replay, не фиксируется константой. Свойства по построению:
   - (i) точка смерти k = k-й вызов замкнутого алфавита внутри второй инкарнации (счёт раннера; N из чистого прогона; замер 6: N детерминирован сценарием, три прогона одинаковы); смерть назначается ПОСЛЕ эффекта вызова k — то есть «между вызовами k и k+1»; смерть «во время» утилит PATH (`date`, `cat`, `cp` …) эквивалентна смерти после предыдущего вызова шима: субъект между вызовами наружу ничего о устройстве узнать не может, кроме как самим `kill -0`;
   - (ii) алфавит состояние-меняющих вызовов замкнут и равен тексту инвариантa: `adb … install -r`, `adb … shell settings put`, `maestro`; любой новый вызов наружу — 127 и красный журнал;
   - (iii) ожидание одно на все k, вычислено до вызова субъекта: rc 1, нет `MAESTRO 2`, нет `RECOVERED`, есть `ОТКАЗ: owned PID`, публикация попытки 1, и после строки смерти — ни одного вызова из (ii). Субъект проходит все k тогда и только тогда, когда между каждым вызовом наружу и следующим состояние-меняющим вызовом стоит `kill -0` owned PID — это и есть проверяемая форма «непосредственно перед»;
   - (iv) тело каждого цикла инкарнации проходится (boot-цикл — входом `pozdno`, замер 7; стабилизация — тремя итерациями уже в сцене), поэтому каждое статическое место вызова пути готовности и перед-набора попадает в трассу хотя бы раз, а продолжение после любой итерации — тот же код;
   - (v) цена: одна строка модели (замер 6, 8), ~100 строк раннера (трасса вызовов отдельным файлом — прежние 29 ожиданий `zapisi` байт-неизменны), одна клетка, два стаба, ≈13 с на прогон.
   Свип с N = 0 (субъект без второй инкарнации — старый S) обязан быть красным, не пусто-зелёным.

4. **Что НЕ закрывает, а лишь повышает цену (отклонено как закрытие):**

   - (в) «(а)+(б)» — (б) ничего не добавляет к (а) при наличии пина; не вводить.
