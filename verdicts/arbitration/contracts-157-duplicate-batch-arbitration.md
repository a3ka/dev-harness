## Решение по каждому спорному пункту

1. **Допустимость повторной роли — adversary прав.** Исполнение немодифицированного хука доказывает: оба architect проходят алфавит и доходят до двери целиком. Уникальность agent не является условием этого шва. Принятие алфавитом не означает обход двери: честный кандидат соблюдает её rc 0/1/2.
2. **Мутант проходит 25 клеток и пропускает duplicate без двери — adversary прав по измеренному факту.** Это настоящий runtime обход искусственно изменённого хука. Нельзя приписывать его самому OBJECT: на том же входе OBJECT вызывает дверь и соблюдает отказ.
3. **Восемь принятых остаточных рисков не включают duplicate batch — adversary прав.** Это риски форм пути, а здесь меняется вход tasks. Решение НЕ расширяет остаточный риск, НЕ исключает duplicates из области и НЕ ослабляет обязательство каждого task пройти дверь.
4. **Обязательное расширение W именно из этого мутанта — adversary не доказал.** Действующий уже на OBJECT `roles/critic.md §Порог` требует не только источник входа, но и источник ошибочного механизма: замена/удаление существующей предметной операции или воспроизведение документированного прежнего дефекта. Там прямо сказано: «ссылка только на место вставки новой ветви таким основанием не является». Предъявленный мутант добавляет новый Set-предикат кратности и новый ранний return после stateRoots; никакую уже существующую duplicate-ветвь он не изменяет. В коде предмета такой ветви нет; runtime честного кандидата не показывает такого дефекта. Первые два adversary-вердикта документируют другие искусственные мутации, не исторический duplicate-дефект поставленного хука. Ссылка v3 на точку вставки до spawnSync не закрывает второй обязательный источник. Следовательно, на предъявленном доказательстве это СОВЕТ усилить W, а не блок и не обязательная правка architect.

Конечная инженерная граница: обязательство проверять дверь для каждого допустимого task сохраняется, включая повтор роли. Обязательное расширение батареи определяется доказанным механизмом по §Порог, а не возможностью бесконечно добавлять новые селективные ранние return. По данному duplicate-only механизму обязательной авторской правки не назначаю. Это не утверждение полноты W для всех будущих ошибок и не пересмотр закрытых v1/v2.
