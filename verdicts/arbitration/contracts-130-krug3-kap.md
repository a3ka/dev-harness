## Решение по существу

Чёрный список недостаточен **как класс**, а не как недоделанный перечень. Его корректность равна утверждению «перечислены ВСЕ принимаемые git написания опасных опций», а множество принимаемых написаний — это множество однозначных префиксов, которое есть функция таблицы опций установленной версии git (появление или исчезновение любой опции `--no-d…`/`--no-p…` сдвигает границу однозначности). Такой перечень уже разошёлся с git трижды в одной конструкции: круг 2 (полные формы), круг 3 (`--no-dr`), замер арбитра (`--no-po`). Белый список точного совпадения замыкает класс по построению: до пробы доходят только токены, про каждый из которых измерено, что он не отменяет `--dry-run` и не глушит porcelain; любой иной dash-токен — отказ до какого-либо вызова git. Цена — отказ на сокращениях и неизвестных опциях (включая безвредные `--atom`, `--dr`), что для двери обменов харнесса является fail-closed-нормой, а не регрессией: оператор пишет полную форму.

Это не «второй разборщик» в смысле РЕШЕНИЯ 1: refspec, remote и значения не разбираются; классифицируются только dash-токены до `--`, и для этого НЕ нужна арность (п.5 замера: без знания арности гард может только отказать лишний раз — `-o --weird` — но никогда не пропустить лишнего, потому что dash-значение, которое прошло бы как значение, либо в таблице, либо отказано).

**Обязательный перечень для architect (каждый пункт проверяем прогоном; правка без нового круга критика; затем — машинная приёмка по П-7 и ленд обычным порядком).**

- **П-1. Белый список.** В `sostav()` (модель; implementer повторяет в `scripts/gitw_teg_130.sh`) до разделителя `--` каждый токен argv после подкоманды классифицируется: не начинается с `-` (или равен `-`) → проходит как есть; `--` → проходит, дальше ничего не судится; иначе имя = токен до первого `=`, и имя ищется **точным совпадением** в закрытой таблице: действие PASS (токен проходит целиком, включая `=значение`), REPLACE (токен заменяется литералом `--no-verify`), нет в таблице → отказ (П-3) **до вызова git**. Батчинг коротких флагов (`-qn`, `-fu`) в таблице отсутствует → отказ. Сокращения в таблице отсутствуют → отказ. Арность не отслеживается (допустимо отслеживать — это только ослабляет ложные отказы, не меняет безопасность). Проба остаётся `<git> <argv[0..i)> --dry-run --porcelain --no-verify <sanitized>`; правило «ноль строк ⇒ отказ при любом rc» остаётся как второй рубеж.
- **П-2. Таблица — закрытый перечень в контракте (И-2) и побайтно в модели.** REPLACE: `-q --quiet --no-quiet -v --verbose --no-verbose --porcelain --no-porcelain -n --dry-run --no-dry-run` (обе полярности четырёх семейств: тихость, подробность, porcelain, сухой прогон). PASS — опции `git push -h` 2.43 вне этих семейств, в полной форме, обе полярности где git их даёт: `--all --no-all --branches --no-branches --mirror --no-mirror --tags --no-tags --follow-tags --no-follow-tags --atomic --no-atomic --thin --no-thin --progress --no-progress --prune --no-prune --signed --no-signed --force-with-lease --no-force-with-lease --force-if-includes --no-force-if-includes --recurse-submodules --no-recurse-submodules -f --force --no-force -d --delete --no-delete -u --set-upstream --no-set-upstream -o --push-option --receive-pack --exec --repo --verify --no-verify -4 --ipv4 -6 --ipv6`. Architect вправе сузить PASS (сужение всегда fail-closed), но не расширить без замера; критерий допуска записи в PASS — замер: опция, добавленная к пробе, не создаёт/не двигает ссылок на цели и не меняет число porcelain-строк. Формы `--no-repo/--no-exec/--no-receive-pack/--no-push-option` можно не включать.
- **П-3. Класс отказа.** Седьмой класс грамматики: `опция не распознана`; строка — прежний формат `gitw ТЕГ-ОТКАЗ: (обмен): опция не распознана: <токен> — гард 130 принимает опции push только в полной форме из перечня И-2`; rc 1; никакой вызов git (ни проба, ни ls-remote) до этого отказа не делается; состояние цели и локальных ссылок не меняется. §Грамматика: «ровно семь».
- **П-4. Клетки (минимум; имена и мир — architect).** Все — мир wip_teg (текст только на wip), ожидание «тег НЕ на цели» плюс класс:
  (а) `push --no-dr origin <тег>` → `опция не распознана`, тег не на цели — решающая клетка этого круга;
  (б) `push --no-po origin <тег>` → `опция не распознана` (второй пропуск перечня);
  (в) `push --no-d origin <тег>` → `опция не распознана` (гард отказывает раньше, чем git успел бы сказать «ambiguous»);
  (г) `push --dry origin <тег>` → `опция не распознана` (безвредное сокращение тоже отказано — демаркационная клетка);
  (д) `push --frobnicate origin <тег>` → `опция не распознана` (неизвестная опция отказана гардом, не пробой);
  (е) `push --push-option=--no-dr origin <тег>` на цели с `receive.advertisePushOptions=true` → проба суха, обычный суд → `текст не в main цели`, тега нет (`=`-форма не отказывается ложно и не отменяет пробу);

## Кто прав

- По предмету спора (достаточность санитайзера): **критик** — факт п.1 верен, конструкция пропускает преждевременную публикацию обычным argv; класс решения меняется (П-1).
- По частным утверждениям автора: `--no-d` неоднозначно (п.3) — верно; «замена, не удаление, не перестановка» и «без второго разборщика refspec» — верно и сохранено. Ошибка автора — фактическая: сокращение `--no-dr` однозначно, а «ноль строк» не ловит отменённую пробу.
- Предложение оркестратора: П-1 принято; П-2 клетки приняты с уточнением (`--no-po` добавлена; `--dr`/`--dry`/`--qui` — одна демаркационная клетка достаточна, остальное — переожидание c40); П-3 стабы приняты и расширены до пяти.

Владельцу вопрос не передаётся: цена решения — отказ на сокращениях опций push через gitw, что не меняет ни воли, ни денег, ни риска публикации; наоборот, сужает вход двери.
