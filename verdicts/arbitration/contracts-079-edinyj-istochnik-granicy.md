## Замеры

1. **Состав библиотеки.** `grep -n '^[a-zA-Z_][a-zA-Z0-9_]*() *{' scripts/lib_incr.sh` →
   ровно 4 функции: `_incr_plural` (:54), `incr_parse` (:72), `incr_fail` (:175),
   `incr_finish` (:196). Клетка Р3 судит следование 2 из 4 (`incr_parse` через маркер окна,
   `incr_finish` через кеш-запись). Не судимы: `incr_fail` (печать итога отказа при
   невалидном кеше — живая ветвь каждого чека: `[ "$INCR_RC" -eq 0 ] || { incr_fail; exit 1; }`,
   check_charter:323 / check_zones:283 / check_ids:171 / check_protected:184) и
   `_incr_plural` (вызывается ИЗНУТРИ `incr_parse` при печати маркера).

2. **Факт критика подтверждён.** Копия `check_ids.sh` с побайтовой вставкой `incr_fail()`
   из библиотеки сразу после source-строки (рецепт критика, построен независимо) через
   штатный шов `--check-sub` на всей семье Р3:
   `bash fixtures/pokrytie_083_088_079/red_istochnik_incr_079.sh . --check-sub <каталог>` →
   rc 0, `зелёных 8, красных 0`, 1,15 с. Частная исполняемая копия функции библиотеки
   принята приёмкой, объявившей переизобретение провалом. Критик прав по факту.

3. **Дешёвый общий носитель существует (ключевой замер).** Проба `probe.py` строит тою-миры
   по рецепту самой клетки (те же зависимости, тот же замороженный тою-контракт для
   check_zones, тот же тег `ustav/1` для check_charter) и мутирует копию `lib_incr.sh` ОДНИМ
   родовым правилом: в каждую строку `^<имя>() {` дописывается
   `printf "%s\n" "${FUNCNAME[0]}" >> <файл-след>`. Список имён берётся из библиотеки
   регулярным выражением, не рукой. Два входа на чек: кеш = HEAD (путь `incr_parse` →
   `_incr_plural` → … → `incr_finish 0`) и кеш = `invalid` (путь `incr_parse` → `incr_fail`
   → exit 1). Ожидание: след содержит ВСЕ имена из библиотеки. Результат:
   - честные 4 чека: след = все 4 имени, rc(valid)=0, rc(invalid)=1 — вход действителен;
   - 16 мутантов (4 чека × частная побайтовая копия каждой из 4 функций поверх source):
     в следе отсутствует РОВНО подменённая функция — поймано 16/16, включая оба
     контрпримера критика и `_incr_plural`, которую никто ещё не предъявлял;
   - стоимость: 20 миров, 2,13 с wall; одна мутация вместо двух ручных, ноль
     ad-hoc-мутантов на функцию.
   Ограничения, найденные пробой (автору знать): (i) check_zones и check_protected
   re-exec'ятся через `env -i` (check_zones.sh:119) — путь файла-следа через переменную
   окружения НЕ доходит (`ZOND079: unbound variable`, честный rc 1); путь обязан быть
   вшит литералом в мутированную копию библиотеки; (ii) функция библиотеки, недостижимая
   обоими входами, даст «нет в следе» и у честного чека — это должно быть rc 2 / именованный
   отказ клетки (как §Остаточный риск :236–239 уже трактует поломку мира), не тихое зелёное;
   сегодня все 4 достижимы.

4. **Что остаётся вне класса и почему это честно.** Частная копия, определённая ДО
   source-строки, перекрывается библиотекой и не исполняется — это мёртвый текст, не
   «исполняемая частная копия грамматики». Критик свой класс сформулировал как
   «исполняемый частный фрагмент той же библиотеки» (v2, блокер, абзац ОБХОД) — граница
   совпадает. Контракт вправе записать её одной строкой в §Демаркация.
