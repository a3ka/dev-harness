## Замер 2 — фильтр не только не помогает: он ломает честные среды (дефект, не найденный ни одной стороной)

`shim2.sh`: легитимная обёртка `git` (shell-скрипт `exec /usr/bin/git "$@"` — ровно форма
шимов asdf/mise/nix/direnv/Homebrew) — ЕДИНСТВЕННЫЙ `git` в PATH.

```
шим как git: git -C <wt> rev-parse --absolute-git-dir → /…/.git/worktrees/wip-101-aa, rc 0
предмет 773d761: rc 2 «NOT_IMPLEMENTED: git отсутствует»
```

То есть на машине, где git установлен шимом, страж объявляет git отсутствующим → все пины
`null` → каждая запись в чекаут блокируется, харнес неработоспособен. Это fail-closed в
сторону отказа в обслуживании, вызванный ИСКЛЮЧИТЕЛЬНО защитой, которая ничего не защищает
(замер 1). Снятие одной строки `if (isShellScript(candidate)) continue;` (копия предмета
`patched.ts`) даёт на том же входе `{"worktree":"…/wip-101-aa"}` rc 0, честные контроли
остаются зелёными, `PATH=/nonexistent` остаётся rc 2 NOT_IMPLEMENTED.

## Замер 3 — кандидат (к) «точный порт read_gitfile» убит собственным измерением

Git-исходников локально нет; правило выведено ИЗМЕРЕНИЕМ (`gitfile-matrix.mjs`, 18 форм через
настоящий git). **Дискретное правило git:** префикс РОВНО `gitdir: ` (8 байт, один ASCII-пробел)
→ остаток → срезаются ТОЛЬКО хвостовые `\r`/`\n` (пробел и таб НЕ срезаются) → результат обязан
быть ВАЛИДНЫМ gitdir, а не просто существующим путём.

В том же прогоне рядом с git судился кандидат точного порта, написанный здесь и сейчас
(8-байтный префикс + срез хвостовых пробельных + `stat` цели):

| форма | git | порт | расхождение |
|---|---|---|---|
| `gitdir: P \n` (хвостовой пробел) | reject | accept | **порт МЯГЧЕ** |
| `gitdir: P\t\n` (хвостовой TAB) | reject | accept | **порт МЯГЧЕ** |
| `gitdir: /tmp\n` (цель существует, но не gitdir) | reject | accept | **порт МЯГЧЕ** |
| остальные 15 форм (канон, CRLF, lone-CR, без EOL, `P\n\n`, BOM, NBSP, без пробела, 2 пробела, TAB после `:`, GITDIR, вторая строка, мусор+gitdir, мёртвая цель, ведущий пробел) | — | — | совпало |

Первая же попытка «точного порта», сделанная не в спешке и с таблицей к2 перед глазами, дала
3 промаха из 18, и ВСЕ ТРИ — в сторону fail-open. Третья строка убивает кандидата
окончательно: чтобы сравняться с git на ней, порт обязан реализовать проверку валидности
gitdir (HEAD/objects/refs/commondir), то есть переписать git. А именно эта форма — forged
`.git`, указывающий на существующий чужой каталог, — и есть вход зондов к3/к4.

**РЕШЕНИЕ `0c98913` в части «третьей формулы этого класса не будет» ОСТАЕТСЯ В СИЛЕ и
распространяется на «точный порт»: порт — та же формула, просто с обещанием точности,
которое измерение не подтверждает.** Кандидат (к) отвергнут.

## Замер 4 — граница: даёт ли обход оракула НОВУЮ способность

`probe2.mjs`, блок C, пиннованная сессия (`worktree` = честный linked worktree), цель записи —
каталог ВНЕ пина:

| tool_call bash | вердикт стража | факт |
|---|---|---|
| `cc -o <T>/writer <T>/writer.c` | **pass** | скомпилирован |
| `<T>/writer` (ELF, пишет `<T>/main-checkout/pwned.txt`) | **pass** | файл вне пина СОЗДАН |
| `python3 <T>/w.py` (скрипт, не `-c`) | **pass** | файл вне пина СОЗДАН |

`isWriteCommand` (:378-413) — allowlist ключевых слов формы записи; непрозрачное исполнение
(свой бинарник, скрипт-файл интерпретатора) в него не входит и входить не может. Значит агент,
способный поставить фейковый `git` (то есть записать исполняемый файл в скратч и запустить
его), УЖЕ обладает неограниченной записью мимо пина — более коротким путём и без всякого git.

Больше того: зонды к3/к4 требуют строго БОЛЬШЕГО, чем «запустить программу» — они требуют
задать `PATH` ПРОЦЕССУ СТРАЖА. Судимый агент этого не может: среда его процесса фиксируется
при старте тем, кто его спавнит. Тот же спавнящий задаёт и ТЕКСТ ЗАДАНИЯ, из которого берётся
пин (и только из первой user-записи — п9). Кто контролирует старт процесса, тот назначает и
оракула, и пин, и интерпретатор — аутентифицировать его изнутри процесса невозможно в принципе.

## Кто прав по каждому спорному пункту

1. **S-elf-git-first — критик прав.** Воспроизведён мной независимо (замер 1). Утверждение
   автора «доверенный якорь» неверно; shebang-фильтр аутентификацией не является.
2. **S-cache-path-replace — критик прав.** Воспроизведён (замер 1). Кэш имени ≠ удержание
   объекта.
3. **Требуемый к4 маршрут («сделать происхождение бинарника действительно доверенным» +
   две красные ветви приёмки) — ОТВЕРГНУТ.** Требование неисполнимо изнутри процесса
   (замер 4, абзац про среду) и не относится к способности, которой судимый агент не имеет.
   Красные ветви на ELF-фейк и swap кэша были бы вечно-красными — а это прямо запрещённая
   конструкция приёмки в этом харнесе.
4. **Норма «обход с исполнением = блокер» — не нарушена, а уточнена.** Норма судит обходы
   ВНУТРИ объявленной модели угроз. Настоящий корень четырёх кругов в том, что модель угроз
   032/025 НИГДЕ НЕ ЗАПИСАНА: каждый круг критик законно предъявлял всё более сильного
   противника, автор законно латал форму последнего зонда, и так до бесконечности. Граница
   объявляется здесь, ниже, и становится законом предмета.
5. **Кандидат (и) «якорь из лаунчера» — ОТВЕРГНУТ**, четыре независимых основания:
   (а) `GIT_PATH` в среде — ТА ЖЕ поверхность, что и `PATH`: кто ставит одну, ставит и другую;
   выигрыша в доверии нуль, а поверхность конфигурации новая;
   (б) `workshop` НЕ в зонах frozen 032/1 (`ЗОНА architect: contracts/032-…md
   fixtures/check_runner_hygiene/red_pin_spawn_zadanie.sh NABLIUDENIA_ARCHITECT.md`,
   `ЗОНА implementer: .omp/extensions/path-guard.ts`) — он в зоне frozen 030; правка требует
   изменения заморозки, то есть подписи владельца, ради нулевого выигрыша (а);
   (в) приёмке пришлось бы САМОЙ выставлять `GIT_PATH` в каждом CLI-прогоне — ровно класс
   А-162 «контроль, подставляющий env за предмет, проверяет свою подстановку»;
   (г) измеренная реальность харнеса против наследования среды: Н-111 (`_task`-субагенты не
   получают даже `WORKTREE`, который в норме ставит `spawn_agent.sh`) и Н-108 (второй живой
   omp над тем же чекаутом, поднятый мимо обычного пути) — якорь «из лаунчера» отсутствовал бы
   именно там, где страж нужен.
6. **Кандидат (л) верен по существу, но недостаточен как «ничего не делаем».** Объявить

## РЕШЕНИЕ — (м): граница объявлена + ложное доверие удалено

### Граница (закон предмета 032/025, дословно)

> Страж `path-guard.ts` судит tool_call агента, чей ПРОЦЕСС поднят не им. Доверенными входами
> объявлены: среда процесса на момент старта (в т.ч. `PATH`), исполняемые файлы, найденные в
> ней, и текст задания (первая user-запись). Противник модели — агент, уже запущенный внутри
> этой среды: он может писать файлы и вызывать инструменты, но НЕ может изменить среду
> собственного процесса и НЕ может переписать своё задание. Подмена бинарника в `PATH` процесса
> стража, подмена интерпретатора (`node`), подмена самого расширения и подделка текста задания
> — один класс «компрометация старта процесса», ВНЕ модели: он эквивалентен компрометации
> владельца/оркестратора и не закрывается изнутри процесса.
> Отдельно и прямо: страж — НЕ песочница. Непрозрачное исполнение (свой бинарник, скрипт-файл
> интерпретатора) пишет мимо пина и судьёй не ловится — измерено (замер 4). Страж держит
> непреднамеренный снос чужого дерева и класс «непиннованная запись», а не враждебный код.

### Дизайн, который исполняется

**Имя: «оракул без претензии на аутентификацию».** Git-оракул (РЕШЕНИЕ `0c98913`) остаётся —
он единственный, кто судит форму gitfile правильно (замер 3). Меняется ровно то, что лгало:

1. `isShellScript` и вызов `if (isShellScript(candidate)) continue;` — **удаляются целиком**
   (замеры 1+2: не аутентифицирует, ломает шим-среды).
2. Разрешение `git` при загрузке модуля **остаётся** — но переименовано по смыслу: это
   МЕМОИЗАЦИЯ (один резолв на процесс, абсолютный путь вместо голого имени, без повторного
   поиска), а не якорь доверия. Комментарии :31-45 и :248-252 переписываются под границу выше;
   слово «доверенный» из файла уходит.
3. Поведение `no-git` (пустой резолв → CLI rc 2 `NOT_IMPLEMENTED`, фабрика `null`/block)
   **не меняется** — проверено на копии предмета после снятия строки.

Живой набросок исполнен и измерен: `patched.ts` = предмет минус одна строка →
шим-среда даёт пин rc 0 (было rc 2), честный worktree даёт пин, `PATH=/nonexistent` даёт
rc 2 NOT_IMPLEMENTED, ELF-фейк по-прежнему проходит — и это ОБЪЯВЛЕННОЕ поведение границы,
а не дефект.

## Остаточный риск (записан прямо)

1. **Страж не песочница** — замер 4, три pass и два реально созданных файла вне пина. Это не
   дефект 032 и не закрывается в нём: закрытие требует ОС-механизма (bubblewrap/namespaces/
   seccomp) либо инвентаря без исполнения. Владельцу — ВОПРОС ВОЛИ, не инженерный спор, и не
   блокер: хотим ли мы вообще сандбокс, или страж остаётся барьером против непреднамеренного
   сноса. Подпись ЗДЕСЬ НЕ ТРЕБУЕТСЯ — круг идёт без неё.
2. **Зависимость от внешнего git на пути пина остаётся** (spawn на согласованную пару,
   мемоизация на сессию). Цена — миллисекунды; отказ любого рода = отказ пина (fail-closed).
3. **Мемоизация pathname по-прежнему не удерживает объект** (S-cache). Внутри объявленной
   границы это не обход: подменить файл по абсолютному пути в системном каталоге может лишь
   тот, кто и так контролирует среду старта.
4. Асимметрия арбитра (одно семейство с автором) — названа в роли и действует. Все четыре
   спорных пункта решены прогонами, у которых семейства нет; два решены ПРОТИВ автора
   (замеры 1 и 2, причём замер 2 — дефект в коде автора, не найденный ни одной стороной),
   один — против критика (замер 4/пункт 3), один — против моего же прежнего РЕШЕНИЯ в части
   формулировки границы (замер 3 подтвердил его суть).
