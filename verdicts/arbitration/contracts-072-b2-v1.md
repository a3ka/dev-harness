# Арбитраж 072-Б2 — граница сессии, записанная самой дверью (повтор Б2, круг 2)

Созван по правилу «два отказа по одной причине»: Б2 к1 (`verdicts/critic/contracts-072-v1.md`
— «эта сессия» подменена на «тот же автор») и Б2 к2 (вердикт `Krit072c2`, не закоммичен
по ограничению изолята — «приёмка не доказывает, что сама дверь оставляет правильную границу
для следующей сессии»). Судимый HEAD `915305d` (origin/main; правка архитектора `e728166`),
клон `/tmp/dev-harness-verify/arb072b2/repo`. Код и контракт не правились; замеры — в
отдельной копии `scripts/` + `fixtures/` вне клона (`…/arb072b2/mut`), мутант и проба
переходов — одноразовые, в клон не попали.

## Суть

Слово владельца: гейт «HANDOFF.md изменён коммитом ЭТОЙ сессии». Контракт исполняет его
ногой (в2): committer-дата HANDOFF-коммита строго больше стартового следа; след —
`ORCH_SESSION_START`, который ДВЕРЬ САМА перезаписывает «текущим моментом» при зелёном
завершении (инвариант 11, contracts/072:174-177; А4, :372-374). Батарея различает
ВХОДНУЮ сторону следа (к9 — след искусственно в будущем, к10 — следа нет, стаб s8), а
ВЫХОДНУЮ судит одним утверждением `p_A`
(fixtures/perezapusk_sessii/red_dver_perezapuska_072.sh:431-432): содержимое следа после
прогона ≠ содержимому до.

Спор: достаточно ли этого для заморозки, когда дверь может записать на выходе ЛЮБУЮ
отличающуюся дату.

## Позиции

- **Критик (к2):** предъявлен мутант — честная дверь во всём, кроме записи следа при
  успехе: `ct(последний HANDOFF-коммит) − 1 с` вместо «сейчас». `p_A` зелёный (байты
  отличаются), к9/к10 зелёные (входную проверку мутант не пропускает); следующая сессия
  S2 той же identity БЕЗ нового HANDOFF проходит гейт. Помечено `[INFERENCE]`: прогон
  мутанта критику был запрещён политикой записи. Кандидаты: (i) переход S1→S2 с
  потреблением маркера без нового HANDOFF — второй вызов обязан отказать; (ii)
  независимая проверка времени записанного следа.
- **Автор (architect):** инвариант 11 и А4 уже ТРЕБУЮТ «след перезаписан моментом
  завершения»; к9/к10 различают входную сторону; свойство выходной стороны — норма,
  которую исполняет реализатор.

## Замеры

1. **Утверждение критика ВЕРНО по коду — прогоном, не выводом.** Мутант собран из
   стаб-двери самой батареи (:162-242, без ручек; единственная правка — финальный
   `trace_write` → запись `date -Is -d "@$((ct−1))"`) и подложен как
   `scripts/orch_restart.sh` копии дерева. `bash red_dver_perezapuska_072.sh <копия>`:
   стаб-пак 9/9, дифф 9/9; красны ТОЛЬКО г1, г2, к7 («чистый приземлённый мусорный
   worktree не удалён самим GC» — расширения GC в дереве нет, к следу отношения не
   имеет); `честная часть: 9/12`. **к1 (p_A), к9, к10 — зелёные на мутанте.** Будь
   расширение GC реализовано, батарея на этом мутанте дала бы rc 0 — заморозка
   пропустила бы предмет, в котором условие владельца не выполняется.
2. **Обход реален, не гипотетичен.** Одноразовая проба переходов (toy-мир по строителю
   батареи: след «час назад», HANDOFF authored той же identity; дверь → маркер снят
   пробой = потреблён обёрткой → дверь ещё раз БЕЗ нового HANDOFF-коммита):
   ```text
   [честный] S1: rc=0 след=…T19:14:31 (ct HANDOFF=…T19:14:31)
   [честный] S2 без нового HANDOFF: rc=1 маркер=нет stderr=ОТКАЗ: HANDOFF.md изменён до стартового следа сессии
   [честный] S2 с новым HANDOFF: rc=0 маркер=СТОИТ
   [мутант]  S1: rc=0 след=…T19:14:32 (ct HANDOFF=…T19:14:33)
   [мутант]  S2 без нового HANDOFF: rc=0 маркер=СТОИТ
   [мутант]  S2 с новым HANDOFF: rc=0 маркер=СТОИТ
   ```
   Мутант разрешает маркер сессии, которая HANDOFF не трогала, — ровно обход Б2 к1,
   открытый заново с выходной стороны. Честный стаб на том же входе отказывает
   (в том числе при следе, равном секунде ct, — строгое `-gt` держит), а после нового
   HANDOFF-коммита пропускает: вход (i) различает честного и мутанта и не ломает
   честного.
3. **Довод автора «к9/к10 различают входную сторону» — верен и к спору не относится.**
   к9 (`trace_future`, :326/:398) и к10 (`trace_absent`, :327/:402) кладут след РУКАМИ
   батареи; ни одна клетка не подаёт двери след, который записала ОНА САМА. Замер 1
   это показывает: s8 пойман 9/9, к9/к10 зелёные — и мутант проходит.
4. **Довод автора «выходная сторона — норма, которую исполняет реализатор» противоречит
   самому контракту.** Frontier В1 (:68-71) отвергает «норму без механизма» с ссылкой на
   Н-85 («дисциплина измерено мертва»); инвариант 2 требует для КАЖДОЙ ноги красную
   клетку (А3). Выходная запись следа — часть механизма ноги (в2): без неё (в2) судит
   границу, которую никто не проверял. Текст :176-177 и :374 обязывает, команда А4 этого
   не доказывает (замер 1). Это тот же класс дефекта, что Б3 к1 (проверялся конечный
   эффект, а не обещанный механизм) — автор там принял и закрыл инструментированием.
5. **Представление vs поведение.** `p_A` судит байты следа; владелец говорит о
   поведении («коммит ЭТОЙ сессии»). Единственный субъект, для которого след имеет
   смысл, — СЛЕДУЮЩИЙ вызов двери; значит свойство выходной стороны наблюдаемо только
   через него. Проверка «след в окне часов оракула» (ii) этот же мутант поймала бы
   (ct−1 < момент до прогона — детерминированно, секунды), но она пиннует
   представление (одна ISO-строка = «сейчас» с точностью до секунды), а не предмет;
   она не ловит дверь, которая пишет верный след, но ломает связку иначе, и не
   доказывает, что честный переход вообще зелёный.

## Решение

**(а) По спорному вопросу прав критик.** Отдельные входы с заранее заданным следом
(к9/к10) + требование «текущий момент» в прозе НЕ достаточны для заморозки: приёмка
пропускает дверь, при которой гейт владельца не исполняется (замеры 1–2). Текстовая
норма без клетки — В1, отвергнутый самим контрактом (замер 4). Это не «подделка следа
руками» из НЕ ЗАЩИЩАЕТ (:214-219): след портит сам проверяемый предмет.

**(б) Правильный различающий вход — (i): переход S1→S2 в одной клетке.** Форма
(не побайтовое предписание):

- дано: конформный мир, след в прошлом, последний HANDOFF-коммит authored той же
  identity; когда: дверь (S1); тогда: rc 0, «ПЕРЕЗАПУСК», маркер стоит;
- затем батарея СНИМАЕТ маркер (потребление обёрткой — память батареи, субъекту не
  сообщается), HANDOFF.md НЕ меняется; когда: дверь (S2); тогда: rc 1, stderr
  «HANDOFF.md изменён до стартового следа сессии», маркера нет;
- затем новый HANDOFF-коммит той же identity с committer-датой СТРОГО позже секунды
  следа (достаточно `sleep 1` перед коммитом — детерминированно при секундной
  гранулярности `date -Is`/`%ct`); когда: дверь (S3); тогда: rc 0, маркер стоит.
  Эта положительная сторона обязательна: без неё клетку проходит дверь, пишущая след в
  далёком будущем (вечный отказ — fail-closed, но предмет мёртв).

Это зелёная пара А4 в её настоящем виде: «след перезаписан моментом завершения»
становится наблюдаемым поведением следующего вызова, а не байтами. Проверка
неравенства в `p_A` может остаться или уйти — она поглощена; автору решать.

**(в) (ii) не требуется и не заменяет (i).** Оракул «часы вне субъекта» существует
(собственное чтение `date +%s` батареей до и после прогона независимо от вывода
субъекта, та же системная шкала — не изъян), но судит представление, а не свойство
(замер 5). Добавлять — по желанию автора, в заморозку не входит.

**(г) Что делать в v3 (автор; батарея + проза контракта, не реализация):**

1. Батарея: клетка перехода (к11) по (б); стаб с ручкой выходной стороны (например
   «при зелёном завершении след = ct(HANDOFF)−1») — пойман на этой клетке, диффпроба
   без ручки зелёная. Привязка стаб→вход — только код батареи (Н-39, канон 064).
   Счёт: стаб-пак 10/10, дифф 10/10, честные 13/13 — согласовать строки А1/А2
   контракта, шапку батареи и шапку раннера `fixtures/_krasnye_072.sh:5-6` (там до
   сих пор «7 стабов / 7/7» — совет критика к2, закрыть той же правкой).
2. Контракт А4: зелёную пару переписать как переход S1→S2(→S3) по (б) — подлежащее
   честная дверь, без имён стабов (канон 064).
3. Инвариант 11 не менять: «текущий момент» остаётся нормой представления; её
   поведенческое следствие теперь имеет клетку.

Критик: один MICRO-круг — только к11/стаб/А4/счётчики; Б1, Б3, Б4 и советы не
переоткрываются. Повторный FAIL по той же причине после этого вердикта — владелец
(`AGENTS.md`, шаг 2).

## Границы

- РЕШЕНИЕ, не К ВЛАДЕЛЬЦУ: спор об инженерной достаточности критерия для слова
  владельца, которое никто не оспаривает; воля/деньги/публикация не затронуты.
  Предмет (дверь, след, ноги (в1)/(в2)) не меняется — только приёмка.
- Не судилось: равенство секунды ct == след (строгое `-gt` держит честного — замер 2,
  честный S1; отдельной клетки на границу равенства стороны не просили); остальные
  находки к2 закрыты критиком сам.
- Побочные артефакты: `…/arb072b2/mut` (копия scripts/fixtures + мутант + проба
  переходов) — вне клона, в репозиторий не попадают; клон чист.
- Счёт по сторонам: пункт (а) — критику целиком (третий арбитраж, третий раз
  спорный пункт решён прогоном); довод автора о к9/к10 верен как факт и не относится к
  спорному свойству. Арбитр делит семейство модели с автором; каждый пункт решён
  замером (1–5), у замера семейства нет. Факт критика, помеченный им `[INFERENCE]`,
  подтверждён прогоном — на этот раз сторона в факте не ошиблась.
- Файл не закоммичен: изолят арбитра write-пинен (ограничение задания); полный текст
