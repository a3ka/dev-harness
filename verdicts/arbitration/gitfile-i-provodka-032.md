## Замер 1 — таблица B1 к2 воспроизведена на текущем коде: к2 прав 5/5

Построен настоящий репозиторий + настоящий linked worktree; цель `gitdir` живая. Для каждой
формы: `git -C <кандидат> rev-parse --git-dir` (независимый оракул), CLI

с заданием первой user-записью → `tool_call write` в кандидат):

| форма `.git` | git | CLI | factory |
|---|---|---|---|
| `gitdir:<path>\n` (без пробела) | reject 128 `invalid gitfile format` | rc 0, непустой пин | **pass** |
| `\uFEFFgitdir: <path>\n` (BOM) | reject 128 | rc 0, непустой пин | **pass** |
| `gitdir:\u00A0<path>\n` (NBSP) | reject 128 | rc 0, непустой пин | **pass** |
| ` gitdir: <path>\n` (ведущий пробел) | reject 128 | rc 0, непустой пин | **pass** |
| `gitdir:  <path>\r` (2 пробела+CR) | reject 128 `not a git repository: (null)` | rc 0, непустой пин | **pass** |
| `gitdir: <path>\n` (канон) | accept | пин | pass — честный контроль |
| `gitdir: <path>\r\n` (CRLF) | accept | пин | pass — честный контроль |
| `gitdir: <path>\r` (CR) | accept | пин | pass — честный контроль |

## Вопрос 1 (валидация `.git`) — РЕШЕНИЕ: git-оракул, в зонах, без правки заморозки

1. **Frozen М1 п.3 НЕ пиннит ручную проверку.** Дословно: «`<путь>/.git` существует; это
   ФАЙЛ; его содержимое — строка формата `gitdir: <путь>`; ЦЕЛЬ gitdir существует на
   диске». Это четыре наблюдаемых условия, не предписание реализации: ни регэксп, ни запрет
   спрашивать git в тексте отсутствуют. Авторитет «формата gitdir» — сам git; оракул судит
   ровно этот формат. Ветви п4/п4а/п4б/п4в остаются наблюдаемыми и проходят (замер 2).
2. **Единственная дельта строже буквы**: git требует, чтобы цель была живым gitdir, а не
   просто «существовала на диске». Направление fail-closed; ни одна замороженная
   положительная ветвь (п1, п9, п11–п15 — все на настоящих worktree) не требует pass на
   существующей-но-невалидной цели. Правка frozen-текста НЕ нужна; дельта записана здесь
   как остаточная строгость.
3. **«Привязка к worktree ЭТОГО репо отвергнута»** — оракул не привязывает: судит любой
   репозиторий, toy-репо фикстур проходят (замер: REAL-linked-wt — toy-репо в /tmp).
4. **Гигиена спавна процесса из расширения — допустима на обязательных условиях**:
   - оракул вызывается ТОЛЬКО после структурных условий и полной грамматики пары (ровно
     одна пара + согласованный basename); успешный пин мемоизируется — спавна git на
     каждый tool_call нет;
   - санированное окружение: unset `GIT_DIR GIT_WORK_TREE GIT_INDEX_FILE
     GIT_OBJECT_DIRECTORY GIT_ALTERNATE_OBJECT_DIRECTORIES GIT_CEILING_DIRECTORIES(вход)`,
     `GIT_CONFIG_GLOBAL=/dev/null GIT_CONFIG_SYSTEM=/dev/null` — прецедент шапки
     spawn_agent.sh — плюс `GIT_CEILING_DIRECTORIES=<родитель кандидата>` против
     восхождения к чужому родительскому репо;
   - fail-closed: git отсутствует / spawn-ошибка → фабрика `null`→block, НИКОГДА pass;
     CLI `--extract-pin` при отсутствии git → rc 2 `NOT_IMPLEMENTED: нет git` (конвенция
     Н-85, измерена к1 на фикстуре с `PATH=/nonexistent`);
   - ручная грамматика (`/^gitdir:\s*(\S+)$/` + trim) УДАЛЯЕТСЯ целиком. Третьего
     регэкспа этого класса не будет: два круга подряд ручная грамматика оказалась мягче
     git — класс закрывается заменой судьи, не заплаткой.
5. **Маршрут — один круг в существующих зонах frozen 032/1**: architect
   (`fixtures/check_runner_hygiene/red_pin_spawn_zadanie.sh` — его зона) добавляет
   отрицательные ветви: пять форм B1 из таблицы, каждая через CLI И фабрику, ожидание
   `null`/block; положительные CRLF/CR-контроли; ветвь `PATH` без git → rc 2 именованный.
   Implementer (`path-guard.ts` — его зона) меняет `isLiveLinkedWorktree` на оракул по
   условиям п.4. Судьи по регламенту (адверсарий к3 этого предмета). Подписи владельца
   этот круг НЕ требует — начинать немедленно.
