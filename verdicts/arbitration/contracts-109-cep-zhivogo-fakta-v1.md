## Решение 2 — правило Ц и ЗАКРЫТЫЙ перечень (порог заморозки)

**Правило Ц (цепь) — на ВСЕ живые факты батареи.** Живой факт зелен только если измерены все три звена: (1) **вызов** — субъект запущен командой/точкой входа, которую ПОСТАВКА объявляет (скрипт package.json, вызов из harness/теста), а не файлом, который батарея нашла сама; (2) **запись** — субъект сам создал артефакт в sink (файл evidence), батарея его не подменяет; (3) **чтение** — ожидания сравниваются со значениями, ПРОЧИТАННЫМИ из sink, по независимым литералам батареи; возвращённое значение / stdout — дополнительный, не замещающий источник. Вход факта обязан ПРОХОДИТЬ по заявленному пути (сентинел — в сериализуемом поле; каждое объявленное значение конечной оси — отдельное наблюдение). `EGRESS_GUARD` правилу уже соответствует (вызов `docker compose config` по файлу поставки → разрешённая конфигурация → чтение сетей); `DRILL_EVIDENCE_GUARD` нарушает звено 1; `HARNESS_TUPLE_GUARD` — звено 3.

**К1 — HARNESS_TUPLE_GUARD читает sink (Б1).** Для каждого наблюдения оси `http_request, http_response, sql_before, sql_after, runtime_role, provider_calls`, `input_hashes[name]` и `mode` сравниваются из СОДЕРЖИМОГО сохранённого файла (JSON), сопоставленного наблюдению (по возвращённому имени файла либо по порядку создания); сравнение по return остаётся допустимым дополнением. Счёт файлов/неизменность первого/`wx` — как на OBJECT. Мутант `harness_sink_decoy` — дельта критика байт-в-байт (`writeSync(fd, '{}')`) → REJECTED_EXACT; привязка к ветви — по коду (Н-39).

**К2 — DRILL_EVIDENCE_GUARD исполняет точку входа поставки (Б2).** Грамматика докстринга объявляет точку входа: скрипт `backend/package.json` `scripts.<имя>` (имя — единый источник в докстринге; на модели — `drill:evidence`), команда которого вызывает коллектор `backend/scripts/*.js`. Факт берёт команду ИЗ скрипта (а не первый файл каталога), проверяет, что она указывает на коллектор, и исполняет её с грамматикой CLI (`--out DIR [--input FILE]`) в disposable-копии; три прогона (NOT_RUN, два входа) — как на OBJECT. Структурная причина `DRILL_MEASUREMENTS_ABSENT` судит наличие ЭТОГО скрипта и коллектора, на который он указывает, а не подстроку basename в сыром package.json (упоминание в `description`/комментарии не считается). Ссылка из harness.js/теста — допустимое ДОПОЛНЕНИЕ, не замена скрипта. Мутант `drill_unwired` — дельта критика (достаточно узкой формы З-3: скрипт удалён, `description` = basename) → REJECTED_EXACT.

**К3 — три режима в живом факте (Б3).** `HARNESS_OBS` содержит по одному наблюдению на каждый литерал `FIXTURE_5_8_2`, `SYNTHETIC`, `RUNTIME` (три записи; append-only — ровно три файла, прежние неизменны); `mode` — седьмое сравниваемое поле из sink (К1). Мутант `harness_mode_collapse` — дельта критика байт-в-байт (`mode: 'RUNTIME'`) → REJECTED_EXACT. Структурный `harness_no_mode_label` остаётся.

**К4 — сентинел внутри сериализуемой оси (суждение; совет критика).** Хотя бы один sentinel из `observation.secrets` помещается в значение сериализуемой оси наблюдения (например, заголовок/тело `http_request`); ожидание из sink: sentinel отсутствует в файле И поле присутствует (сравнение этого поля — «равно наблюдению с вырезанным сентинелом» либо «не равно сентинелу и не пусто» — форма по выбору автора); прочие оси — exact. Мутант `harness_scrubber_identity` — дельта критика байт-в-байт → REJECTED_EXACT. Литерал `[REDACTED]` грамматикой НЕ навязывается.

**К5 — NEEDS_ENV не зелен (суждение; совет критика).** Полный прогон и `--case`: факт `None` ⇒ rc ≠ 0 с текстом `NEEDS_ENV: <граница>` (rc 2 UNMEASURABLE предпочтителен — честно «не измерено»); `control_green` только при всех пяти `True`. Строка 1 (B) не меняется: rc 1 контролем. Докстринг «Выход:» и :46/:100 — одно утверждение.

**К6 — текст контракта.** Раздел «Закрытие обходов круга 2» вида БN → клетки, без стаб-пар в прозе (Н-39; образец :111–118); правило Ц одним абзацем в §Приёмочный критерий (:43) и в докстринге (единый источник: грамматика точки входа drill, режимы, сентинел); §Модель угроз :89 и :94 — фактические звенья («из сохранённого файла», «командой поставки»); :46–47 и §Замер — фактические числа (25 + 4 мутанта = 29 кейсов, число для сверки, авторитет — `cases()`), замер заново на новом коммите: B → rc 1 именованно, модель → rc 0 все факты `True`, 29/29, три прогона; деревья критика круга 2 → rc 1 именованно.

**Что НЕ блокирует круг 3** (переоткрывается только ссылкой на этот файл): происхождение наблюдений на реальном TCP/PG18 (связь «настоящий запрос → recordInteraction») — судится scoped-прогоном строки 5 adversary/reviewer, не батареей; положительный контроль wget/маршрута в строке 4; относительные зависимости harness в disposable-каталоге (автор вправе копировать `backend/`); integration-файл с `require` без единого `test(` (замечено в З-1 на `drill-unwired`; строка 5 судится живьём); private object-storage profile, TLS verify-full ingress, шесть identities issue #5 (граница предмета — владелец); YAML-валидность compose вне якорей; любые новые мутанты вне К1–К5; стиль/гранулярность кода батареи.
