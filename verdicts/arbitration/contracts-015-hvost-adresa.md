РЕШЕНИЕ (контракт 015): regex-якорь остаётся — подход robust; хвост после разделителя ЛЕГАЛЕН, дефект — в мере назначения пробы (потребляющая граница + want−have вместо равенства наборов); из трёх кандидатов обход один — «контракт 015 контракт 016» (реестр 9→10), два других объявляются В ЯЗЫКЕ и пинуются зелёными контролями.

# Арбитраж: граница хвоста адреса — robust ли regex-якорь (СТОП круга 5)

Созыв: вердикт критика v5 (`verdicts/critic/contracts-015-v1.md`) — accept с
СТОП-строкой по границе владельца 2026-08-27 («круги = сигнал о подходе, не
реализации»): при реестре 9/9 красных стабов ТРИ новых кандидата прошли rc=0.
Предмет спора принципиальный: допустим ли после структурного якоря произвольный,
в том числе пустой или похожий на второй адрес, хвост — или regex-подход хрупок
и нужен структурный парсер.

Дерево: HEAD `4c58712`. Все спорные утверждения проверены замером; команды и
rc — ниже.

## Замер 1: воспроизведение трёх кандидатов (утверждение критика подтверждено)

`build_root.py "$T" "<значение>"` + `probe_migracija_adresov.sh "$T"` на HEAD:

## Замер 2: три кандидата — НЕ unicode-класс

Все три значения — чистая кириллица + ASCII. Тезис «regex принципиально хрупок
против unicode/mixed-script» кандидатами НЕ подтверждается: unicode-класс закрыт
структурной позицией круга 5 и красен в реестре (входы 7–9: «αконтракт 015»,
«контракт 015β», «контракт 01p» — rc=1, перепроверено здесь). Кандидаты — вопрос
ПОЛИТИКИ ХВОСТА, разрешимый в закрытой форме, а не выразимости языка.

## Замер 3: хвост — несущая конструкция, а не люфт

Барьерный запрет «второй якорь в хвосте» (и тем более запрет хвоста целиком)
ломал бы собственную таблицу контракта: §Материал ЯВНО строит многоякорные
назначения — А-30 «очередь автономности: … — пачка Н-60 (…)» несёт {Q, P:Н-60},
А-31 — {Q, P:Н-61} (стем `пачк[а-яё]* (Н|А)-[0-9]+` матчится в хвосте — прогнано).
Контракт: «столбец … несёт ≥1 якорь»; хвосты несут и различающую семантику
очередных записей («очередь автономности: <какой пункт>») — дайджест механизма 3
печатает «id + адрес-строка»: без хвостов десять записей печатались бы
неразличимым «очередь автономности». Запрет хвоста = потеря наблюдаемости,
против цели самого контракта.

## Замер 4: настоящий дефект — мера назначения отстала от буквы контракта

Контракт (§Материал): «перефразирование сохраняет НАБОР якорей строки, и
миграционная проба сверяет набор записи с набором её строки». Набор = равенство.
Проба же (а) проверяет только `want - have` — лишний ключ легален; (б) строит
границы ПОТРЕБЛЯЮЩИМ классом: в «контракт 015 контракт 016» первый матч съедает
разделительный пробел, второй ключ не извлекается вовсе (прогнано: потребляющая
граница даёт `['контракт 015 ']`, lookaround-граница — оба ключа K:015, K:016).
Проба слабее собственного текста контракта — это дефект РЕАЛИЗАЦИИ МЕРЫ, не
подхода.

## Замер 5: прописываемая правка — полная матрица

Правка (две точки, ТОЛЬКО в мере ключей пробы, ERE не тронут):
1. границы стемов в `CATS` — несъедающие lookaround: `(?:^|(?<=SEP))стем(?=$|SEP)`
   (для K, Q, P, R, RR, Z; PATH/H/C по-прежнему съедают хвост как идентификатор);
2. ветвь «ОТКРЫТО с валидной формой»: `have = keys(<значение адреса>)` (значение
   после `адрес:`, не весь маркер) и `have != want` → «назначение изменено»
   (равенство наборов); ветвь закрытых записей остаётся `want - have` (титульный
   текст заголовка легально несёт посторонние ключи).

## Вопрос 1: подход. Regex ОСТАЁТСЯ, структурный парсер ОТКЛОНЁН

Язык адреса регулярен ПО ПОСТРОЕНИЮ: однострочное значение, закрытый список из
9 категорий, закрытый класс разделителей. Все дефекты пяти кругов — дефекты
МЕРЫ (круг 3: граница-токен; круг 4: отрицательный класс против не-ASCII;
круг 5→СТОП: потребляющая граница и want−have), ни один — дефект выразимости
regex. Структурный парсер унаследовал бы те же вопросы политики хвоста, стоил бы
второй источник истины против пина арбитража 3 (побайтовое совпадение ERE у трёх
потребителей) и против «узкого ядра». Минимальная правка — по замеру 5: ERE
`# ГРАММАТИКА:` НЕ меняется (пин арбитража 3 цел, SHA сохраняется), правится
мера ключей пробы — прецедент уже в контракте («усиление меры, НЕ изменение
формы», круг 5). Вариант «хвост запрещён целиком» отклонён замером 3; вариант
«хвост без букв-цифр» отклонён им же (хвосты несут семантику и легальные якори).

## Вопрос 2: судьба трёх кандидатов

- **«контракт 015 контракт 016» — обход, критик прав.** Значение меняет набор
  назначения (лишний K:016), что контракт запрещает буквой. После правки красен
  ветвью «назначение изменено». По требованию владельца 2026-08-27 (пойманный
  обход = постоянный стаб): реестр красных 9→10, собственный case класса
  «лишнее назначение» (образец — case_unicode_sklejka.sh: адаптер-барьер,
  красные ветви `|| true`).
- **«контракт 015 — примечание» — НЕ обход, в языке.** Голова называет цель,
  набор ключей равен табличному ({K:015}); комментарий без адресатных ключей
  назначения не меняет по построению. Механическая граница «пояснение vs
  злоупотребление», которой требовал критик, ЕСТЬ: злоупотребление = хвост,
  меняющий набор ключей; всё остальное — шум без назначающей силы.
- **«контракт 015 —» — НЕ обход, в языке.** Разделитель с пустым хвостом =
  пустой комментарий; голова называет цель. Косметика, не дефект.

Два легальных кандидата закрепляются ЗЕЛЁНЫМИ контролями в зелёной мере
сходимости контракта (§Красное сейчас, блок зелёной меры) — чтобы v6 судил
исполнение, а не переоткрывал их. Реестр 9→12 не нужен: красный стаб один.

## Вопрос 3: итоговая грамматика — закрытая форма

Значение V (текст после `адрес:` в ПОСЛЕДНЕЙ бэктик-группе заголовка, после
strip) принадлежит языку ⇔

1. **Форма** (барьер, дайджест, проба — побайтово один ERE, SHA `f8e5cb23…`):
   `V = ГОЛОВА · ХВОСТ?` fullmatch; ГОЛОВА — одна из 9 альтернатив
   (категория + обязательный идентификатор) С ПОЗИЦИИ 0; ХВОСТ отсутствует либо
   начинается символом закрытого класса SEP
   `[] ,.;:!?()«»„“”‘’"'…—–/*+&%#@~=<>^$|{}]` и далее произволен.
2. **Назначение** (только миграционная проба, только ветвь «ОТКРЫТО с валидной
   формой», умирает вместе с таблицей в коммите введения): множество адресатных
   ключей V (границы — lookaround по SEP/краям, без потребления) РАВНО множеству
   ключей строки §Материал.

**Классы вне языка** (исчерпывающе; каждый пункт — красная ветвь):
- (a) V не начинается стемом с позиции 0: чужие слова («неконтракт 015»),
  приклеенный слева символ ЛЮБОГО алфавита («αконтракт 015»), заглушки («.»),
  пустое V;
- (b) категория без завершённого идентификатора: «очередь», «правило роли»,
  «контракт 01p» (не-цифра рвёт `0[0-9][0-9]`);
- (c) склейка справа к идентификатору буквой/цифрой любого алфавита, дефисом,
  подчёркиванием («контракт 015β», «под-контракт»): не-SEP символ после головы
  рвёт fullmatch;
- (d) непустой хвост, начинающийся не-SEP символом;
- (e) для H — пустое обоснование после «не чинить:», для C — без «риск»;
- (f) мерой назначения: набор ключей V ≠ набору строки — недостающий ключ,
  чужой ключ («контракт 014»), ЛИШНИЙ ключ («контракт 015 контракт 016»).

**Классы в языке** (объявлены решением; не обходы, не предмет кругов):
- хвост-комментарий после SEP без адресатных ключей («контракт 015 —
  примечание», «контракт 015 (частично: …); …»);
- хвост из одних SEP-символов («контракт 015 —»);
- многоякорные значения с набором, равным табличному (А-30: {Q, P:Н-60}).

Пост-миграционная граница: после коммита введения таблица мертва, барьер судит
только форму (1); многоякорность и комментарии новых записей — авторские.
Это не дыра: инвариант механизма 1 — «адрес называет цель», и любое значение
языка называет ≥1 цель головой. «Нет четвёртого unicode-круга» означает: вход,
попадающий в классы (a)–(f), — исполнение уже вынесенного решения (судится
существующими ветвями), а не новый спор о подходе; новым спором был бы только
вход ВНЕ перечисленных классов, проходящий при верной по этому вердикту мере.
