### F2 — НЕ закрыт в обоих судьях

Оба исправленных фрагмента имеют форму:

```bash
OKNO_N=$(g rev-list --count "$OKNO_BASE..HEAD" 2>/dev/null); rc=$?
```

Но оба скрипта исполняются с `set -e`. Поэтому при отказе `rev-list --count`
оболочка завершает работу **на присваивании**, до `rc=$?`, именованного
`ОТКАЗ 086` и rc=2.

Живая проба `check_charter`: честный toy с одной обычной `src/`-дельтой даёт
`rc=0` и один маркер окна. Делегирующий `git`, возвращающий `127` только для
`git -C <toy> rev-list --count …`, дал:

```text
charter_control rc=0 marker=1
charter_count_spy rc=127 named=0 output=<empty>
```

Живая проба `check_zones` не опиралась на PATH (он намеренно перепускается с
`/usr/bin:/bin`). В toy оставлены валидными HEAD и база, но удалён объект
среднего из двух обычных коммитов: настоящий `git rev-list --count
<base>..HEAD` дал rc=128 (`Could not read …; revision walk setup failed`).
Судья дал тот же сырой rc=128, без именованного отказа, вместо rc=2:

```text
zones_raw_count rc=128
zones_count_corruption rc=128 named=0 output=<empty>
```

Это именно требуемый класс «отказ команды выглядит успехом/обработан не
fail-closed»: ошибка не нормализуется в обязательный исход И-5 и не сообщает
«нечем проверить». П5 требует rc=2 в обоих судьях, поэтому F2 остаётся FAIL.
