## БЛОКЕР S-nested-dotgit-blind — рекурсия среза зовёт ДВЕ ноги из трёх

**Что сломано.** `manifest()` (`scripts/check_no_leak.sh:880-897`) сшивает три ноги только для
корня: `emit_dotgit_manifest "$1"` вызывается ровно один раз, БЕЗ префикса и без рекурсии.
Обе рекурсивные точки спускаются в вложенный репозиторий ДВУМЯ ногами:

* gitlink/submodule, `emit_tracked_manifest:472-479` → `emit_tracked_manifest` + `emit_untracked_manifest`;
* untracked-вложенное репо, `emit_untracked_manifest:641-650` → те же две ноги.

Нога-3 (`emit_dotgit_manifest`, обход `hooks|info|config`) в рекурсию НЕ входит. Между тем
замороженный текст называет ногу-1 как «@head + **рекурсия манифеста** внутрь с префиксом»
(:224-226 контракта, дословно повторено в шапке кода :409-411), а «манифест» по тому же тексту —
ОБЪЕДИНЕНИЕ трёх ног. И основание ноги-3 в замороженном тексте — «исходный инцидент 024
(подмена pre-push) закрывается **только** этой ногой» (:236-238). Ровно этот инцидент
воспроизводится одним уровнем глубже и не ловится ничем.

**Следствие — не «хук в чужом репо», а произвольный тайник.** Любой байт под
`<вложенное-репо>/.git/` невидим ВСЕМ трём ногам: нога-2 корня отдаёт только сам каталог
(`UNTRACKED-REPO:<sha HEAD>\t<путь>`), рекурсивные `ls-files`/`ls-files --others` внутри
вложенного репо не видят его `.git`, а нога-3 туда не заходит. `UNTRACKED-REPO:<sha HEAD>`
не меняется — HEAD не трогали. Размер и содержимое тайника не ограничены.

**Воспроизведение** (`/tmp/dev-harness-verify/adversary024k12-nested-dotgit-bypass.sh`, вывод дословно):
