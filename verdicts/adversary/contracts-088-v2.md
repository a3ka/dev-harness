## 1. Б: незастейдженная порча k7 меняет решение о staged HANDOFF.md

В toy-репозитории обычный `.githooks/pre-commit` включён. В индекс помещён
корневой `HANDOFF.md` варианта B1 (в первой секции `## ГДЕ МЫ` есть только
`текст без указателя`). Затем **только рабочая копия**
`fixtures/ops_server/red_server_obvjazka_074.sh` изменена так, что её
`HANDOFF_PTR` равен `текст без указателя`; этот файл не staged. До коммита
staged-набор — только `HANDOFF.md`.

```text
B_WORKING_K7 rc=0 head_advanced=yes staged_before=HANDOFF.md unstaged_k7=fixtures/ops_server/red_server_obvjazka_074.sh,
```

Это fail-open И-5: `scripts/check_staged.sh` получает обязательный указатель
из рабочей копии `_handoff_src`, а не из зафиксированного объекта. Поэтому
коммит с невалидным индексным HANDOFF.md создаётся, если коммитёр меняет
лишь незастейдженную k7-фикстуру. B1 фиксирует источник только в чистом
мире и не проверяет конфликт staged-объекта с незастейдженной рабочей
копией k7.

## 2. D1: путь passwd-дома с пробелом скрывает живых субагентов

Шим `getent passwd "$(id -un)"` вернул конформный дом с пробелом:
`$SCR/passwd home with spaces`. В нём создана свежая текущая сессия с
`ZhivojA.jsonl`, `ZhivojB.jsonl` и старым `Staryj.jsonl`; HOME двери —
другая пустая директория, как в D1. Дверь должна была отказать до остальных
ног сообщением `ОТКАЗ: живые субагенты: ZhivojA,ZhivojB`. Вместо этого она
прошла ногу живых и дошла до следующей двери:

```text
D_PASSWD_SPACE rc=1 stderr=ОТКАЗ: HEAD расходится с origin/main
```

Причина — `scripts/lib_session.sh` выполняет `ls -t $ORCH_SESS_GLOB` с
нецитированным глобом. После того как 088 формирует глоб от passwd-дома,
пробел делит его на слова и `current_session_dir` возвращает пустоту. D1
проверяет значение дома, но не конформный путь с пробелом; поэтому
штатная батарея зелёная против реализации, которая пропускает этот вход.

## 3. Б: коммитёр подменяет обязательный текст отказа через OTKAZ_088

Вновь staged B1 без строки-указателя, без иных изменений. Коммит выполнен
с `OTKAZ_088=ATTACKER-CONTROLLED-REFUSAL`:

```text
B_OTKAZ_ENV rc=1 head_advanced=no stderr=ATTACKER-CONTROLLED-REFUSAL
```

Отказ по существу есть, но И-7 требует ровно:

```text
ОТКАЗ: HANDOFF.md — в первой секции «## ГДЕ МЫ» нет строки-указателя (контракт 088)
```

`check_staged.sh` по-прежнему читает `${OTKAZ_088:-...}` из окружения
коммитёра. B1 сверяет правильный текст только при обычном окружении;
конформный коммитёрский environment подменяет обязательную грамматику.

## Вывод

Положительный контроль и 17 штатных стабов прошли, однако приведённые
обманные реализации/входы не пойманы. Нужны клетки, соответственно:
(1) B1 с невалидным index-HANDOFF и конфликтующей незастейдженной k7;
(2) D1 с passwd-домом, содержащим пробел; (3) B1 с заданным
`OTKAZ_088`, требующая неизменный текст И-7. До этого контракт 088 — FAIL.
