## Находка — путь, равный SHA уже поглощённого коммита, ложно становится дублем заголовка

v8 заменил regex-классификацию заголовка сравнением со **следующим** ожидаемым SHA. Это верно различает 40-hex путь, равный следующему заголовку, но текущий `awk` затем всё ещё делает:

```awk
if ($0 in want) { seen[$0]++ }
```

для каждой записи, не равной следующему ожидаемому SHA. Поэтому честный путь, равный SHA **раньше поглощённого** судимого коммита, учитывается и как путь текущего блока, и как второй заголовок прежнего блока.

Минимальный честный toy строится штатным `fixtures/check_zones/_repo.sh`:

1. Заморозка v1 объявляет `ЗОНА agent-x: scripts/`.
2. `agent-x` честно коммитит `scripts/inside.sh`; его SHA обозначим `C`. Положительный контроль сразу после этого даёт `check_zones` rc=0.
3. Штатная заморозка v2 добавляет точную законную зону `ЗОНА agent-x: C`. Диапазон суда остаётся `frozen/contracts/001/1..HEAD`, то есть `C` остаётся в `$TMP/matched_commits`.
4. `agent-x` честно создаёт top-level файл с именем ровно `C`. Он лежит в буквально объявленной зоне.

Полный воспроизводимый контроль был запущен как:

```text
bash /tmp/dev-harness-verify/adversary040-v8-prior-sha-control.sh .
```

Он подтвердил:

```text
per-commit C path=scripts/inside.sh
per-commit D path=<C>
batched-check-rc=1
ОТКАЗ: batched git diff-tree --stdin вернул неполный/искажённый поток ...
  0 SHA без заголовка путей, 1 SHA с более чем одной заголовочной записью ...
```

Per-commit форма передаёт оба пути обычному точному сравнению зон и принимает их. У `git diff-tree --stdin -z` поток честный: после заголовка `D` запись `<C>` — данные пути D. Но v8 уже поглотил заголовок `C`; `<C>` не равен следующему ожидаемому заголовку D, правильно остаётся путём, а лишний подсчёт `$0 in want` ложно увеличивает `seen[C]` до двух. Это категория (ii) — ложный красный на честном git/Linux имени — и (iii) — batched расходится с per-commit.

В отличие от прежнего случая «путь равен следующему SHA», этот вход достижим без криптографического fixed point: SHA C известен до следующей версии заморозки, а зоны всех версий объединяются, тогда как диапазон начинается от первой заморозки. Лечение за автором: после строгой проверки на следующий ожидаемый заголовок запись должна быть данными; нельзя дополнительно трактовать совпадение с любым уже ожидаемым SHA как заголовок. Если нужна защита от искажённого потока, её нельзя строить на форме данных, которая легальна как pathname.
