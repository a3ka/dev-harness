## Находка 1 — заглавное эхо argv выдаёт себя за вызов скила

Построен `omp`, который не читает скил и не выполняет модельный вызов. На
`--skills ... -p ...` он лишь печатает **весь argv**, переведённый в верхний
регистр, и завершает работу кодом 0. Для `--version` он правдиво отдаёт
`omp/17.2.10`; для `models list` — минимальную строку с
`MiniMax-M3` и `yes`. В изолированном клоне пин намеренно перепривязан к sha256
этого подставного исполняемого, чтобы независимый пин overlay не заслонил
пробу. Сам overlay в этой пробе выполнил полное копирование и был затем
сверен барьером.

`PATH=bin:$PATH bash scripts/check_skills.sh` вернул **0**. Финальный вывод:

```text
  ok   скил «grilling» отвечает omp словом из тела
  ok   скил «writing-for-agents» отвечает omp словом из тела
  ok   скил «tdd» отвечает omp словом из тела
  ok   скил «diagnosing-bugs» отвечает omp словом из тела
  ok   профиль совпадает с репозиторием (полное дерево каждого скила)
  ok   фикстуры полны: 8 на родителе, все авторы коммитов по fixtures/ — architect
барьер зелёный: 8 ветвей пройдены
```

Причина: запрос барьера сам содержит требуемое слово (`Interview`) в argv,
а проверка ищет лишь наличие его верхнерегистровой формы (`INTERVIEW`) где-либо
в ответе. Заглушка получает доказательство из запроса, а не из тела скила, и
удовлетворяет проверке преобразованием регистра. Код 0 и честная полная ветвь
overlay показывают, что это не маскировка отказа `omp` или overlay.

## Решение

Три буквально предписанные прежние пробы закрыты: 127 отклонён, неполное или
искажённое дерево отклонено, любой поздний не-architect автор отклонён;
положительные контроли зелёные. Но новый вариант того же класса §1 проходит:
барьер принимает эхо собственного prompt вместо доказательства загрузки
скила. Поэтому закрытие не принимать. Нужна проверка ответа, не допускающая
получить ожидаемый маркер простым воспроизведением или преобразованием текста
самого запроса; затем повторить данную заглавную эхо-пробу вместе с
положительным контролем.
