# Контракт 040, adversary круг 9 — v9 `87e48b8`

Проверен предмет в границе арбитража 040-III (`verdicts/arbitration/contracts-040-vrazhdebnoe-okruzhenie-predel.md`, прочитан целиком до испытаний): только (ii) ложные красные на честном git, (iii) расхождения batched/per-commit на честном git и допустимый (i) без управления процессом запуска, подмены git или записи в `/usr/bin:/bin`. Векторы `BASH_ENV`/PATH-spy и иная отрава вызывающего намеренно не повторялись: арбитраж вывел их из предмета.

## Новые adversary-toy

1. Честный toy построил три ранее потенциально неоднозначных имени в одном batched-окне: top-level файл, равный SHA уже поглощённого коммита; легальный top-level `:within`; и `scripts/`-путь с лидирующим невалидным UTF-8 байтом `0xff`. Все приняты (`rc=0`). После этого отдельный top-level `:outside`, не входящий ни в одну зону, дал именованный `rc=1`. Тем самым `:` в path-токене после raw-метаданных не принят за следующий metadata-токен, а прежняя граница old-SHA не регрессировала.
2. Точный автомат `awk` при `LC_ALL=C.UTF-8` получил NUL-разделённые токены с невалидным лидирующим `0xff`, metadata и путём `:filename-leading-colon`. Несмотря на предупреждение gawk о невалидном multibyte, `substr($0,1,1)` не классифицировал `0xff` как `:`, а токен с лидирующим `:` после metadata остался путём. Нулевой байт в filename недостижим и при обходе index: OS отклонила `os.open(b"a\\0b", ...)`, а `git mktree -z` трактовал NUL как конец записи и отверг остаток как `input format error`; в корректном raw Git tree этот байт — структурный terminator имени.
3. Отдельный минимальный repository положительным контролем принял zoned change и именованно отверг реальный `plans/hidden-by-injected-stream.md`. Затем я подал четырём одноразовым копиям v9 искусственные malformed `paths_raw` (это проверка fail-closed ветвей, не finding и не допустимый обход): missing headers, duplicate expected header, extra header и metadata без path. Каждый прогон завершился `rc=1`, и сообщение назвало ровно соответствующий ненулевой счётчик из `missing/dup/extra/orphan`; остальные три были нулевыми. Значит новые extra-header и EOF-orphan ветви не молчат и не превращаются в `rc=0`.

Не найдено реализации, неверной в разрешённой границе и проходящей проверку. Конечный автомат использует форматный `:` только в верхнем состоянии; после metadata следующий NUL-токен безусловно сохраняется как путь. Это устраняет класс сравнения значения пути с SHA, включая путь с тем же лидирующим байтом, что и raw metadata.
