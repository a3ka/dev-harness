## Принятые проверкой неверные реализации

### 1. (е) `--rebuild-budget` может писать константу вместо свёртки

В копии прокси `tmp/adv005/e-constant/repo/` в начало `rebuildBudget` внесена
ровно одна неверная ветка:

```ts
if (!cfg.data_dir.includes('tmp-selftest-')) {
  writeBudget(cfg.data_dir, {})
  return 0
}
```

Это сохраняет самопроверку честной, но для каждого рабочего каталога стирает
сводный бюджет и объявляет операцию успешной. Проба
`bash tmp/adv005/probe_e_constant_budget.sh` дала одновременно:

```text
selftest=selftest OK
barrier_rc=0
ok   е: budget.json после rebuild равен свёртке calls.jsonl
rebuilt_budget={}
expected_fold_contains=7
```

То есть журнал из одной корректной строки с `usd: "7"` пересобран в `{}`.
Это нарушает направление производности из предмета и буквально требование
ветви (е) сравнить `budget.json` со свёрткой `calls.jsonl`.

Причина установлена исполнением: в `branch_е` вычисляются `expected` и
`actual`, но после их вычисления нет ни одного условия сравнения; сразу
вызывается `ok`.

Это не только брешь прямого барьера. Полная отдельная проба
`bash tmp/adv005/probe_e_antiplacebo.sh` положила ту же неверную реализацию
в изолированное дерево вместе со всеми 17 фикстурами учёта и запустила
неизменённый `scripts/verify_antiplacebo.sh` против него. Код был **0**:

```text
check_metering/case_e_marker_appendonly.sh: зелёный контроль есть,
  повторный прогон красный кодом 1 — «маркер мёртв»
барьеров: 1 · фикстур: 17 · предъявлено красным повторным прогоном: 17
```

Существующая фикстура (е) держит только truncate/append-only, а не неверную
свёртку. Поэтому анти-плацебо также принимает константный rebuild.

### 2. (к1) динамический импорт не-node модуля не наблюдается

Проба `bash tmp/adv005/probe_k1_dynamic_import.sh` добавила в копию прокси
выполняемое на запросе:

```ts
await import('file://' + '<абсолютный путь к outside-node.mjs>')
```

`outside-node.mjs` при загрузке дописывает маркер. Это импорт внешнего для
`node:` URL и нарушает builtins-only, однако неизменённый барьер вернул **0**.
Его существенные последние строки:

```text
ok   к1: импортов вне node: ... нет
barrier_rc=0
marker=111111
```

Проверка к1 ищет только статическую форму `import ... from "..."`; `import()`
в область поиска не входит. Маркер доказывает, что не-node модуль был реально
загружен, а не только присутствовал текстом.

### 3. (к2) внешний процесс скрывается динамическим доступом к builtin

Проба `bash tmp/adv005/probe_k2_dynamic_process.sh` добавила в обработчик
запроса:

```ts
const runner = process.getBuiltinModule('node:' + 'child_process')
runner?.['exec' + 'FileSync']('/bin/' + 'sh', ['-c', 'printf 1 >> <маркер>'])
```

Это создаёт внешний `/bin/sh` на каждом запросе. Но барьер снова вернул **0**:

```text
ok   к2: exec/spawn вызовов вне node: ... нет
barrier_rc=0
marker=11111111111111111111111
```

Regex к2 требует буквальный вызов `exec...(` или `spawn...(`; вычисляемое
свойство `['exec' + 'FileSync']` ему невидимо. Ненулевой маркер — наблюдение
реального выполнения внешнего процесса.

### 4. (л.i) один фиксированный вектор допускает зашитую константу

Проба `bash tmp/adv005/probe_li_constant.sh` заменила расчёт стоимости на
`Number`/`Math.ceil`, но вернула точное значение только для единственного
вектора, который проверяют и `selftest`, и барьер:

```ts
if (tokensIn === 1_000_000_000 && tokensOut === 0
    && inRateMicro === 9007199254740993n && outRateMicro === 0n) {
  return 9007199254740993000n
}
```

Барьер остался зелёным, в том числе сообщил точное ожидаемое значение:

```text
barrier_rc=0
ok   л.i: usd=9007199254740993000 — совпало с точным И отличимо от double
```

После этого та же экспортированная `computeUsd` была исполнена на соседнем
допустимом int64-векторе `(tokens_in=1000000000,
rate_in=9007199254740995)`. Наблюдение пробы:

```text
alternative_usd=9007199254740996096
expected_usd=9007199254740995000
```

Следовательно, проверка не доказывает int64-вычисление: она доказывает лишь
одну публичную константу. Контракт требует порождённые usage и тариф, а л.i
фиксирует оба. Нужны хотя бы два независимо порождённых точных вектора выше
`2^53` и сверка с отдельным целочисленным оракулом.

## Вердикт

FAIL. Барьер и анти-плацебо пропускают константный `--rebuild-budget`, хотя
это прямо разрушает производность бюджета. Дополнительно обе статические
проверки builtins-only обходятся реально исполняемыми динамическими формами,
а л.i допускает константу вместо общей int64-арифметики. Исправление за
автором: в (е) сравнить `expected` и `actual` с отказом и добавить к этому
отдельную красную фикстуру; к1/к2 проверять все формы загрузки и обращения к
`child_process`; л.i снабдить независимыми порождёнными векторами.
