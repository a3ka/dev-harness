Контрреализация сохраняет `hub` только для этих профилей, но безусловный инвариант нарушает:

  ```bash
  TOOL_NAME=h$(printf ub)
  ```

  В тексте нет литерала `hub` в условии, нет `${TOOLS…hub…}`; статический суд чист. Три предъявленных класса проходят: `bash fixtures/workshop_inventory/red_inventar_hub.sh` вернул **rc 0** со всеми обычными строками батареи зелёными. Но вне профилей пробы настоящий операнд неверен:

  ```text

  read,edit,write,bash,grep,glob,lsp,web_search,task,todo

  ```

  `hub` отсутствует. Это именно обход «косвенно построенное имя тула / форма-угадывание всех конечных динамических классов»: ни три значения, ни текущий статический текстовый шаблон не доказывают безусловность.

* **A-030-7 — таблица QA не полна по явно названным внутренним URI.** Из 15 строк отсутствует `skill://` (так же отсутствуют отдельные предъявления `agent://`, `history://`, `mcp://`), хотя контракт 030.2.3 требует block для каждого из них у непиннованной сессии. Контрреализация разрешает только `skill://` в обоих реальных потребителях, оставляя весь набор из 15 строк неизменным:

  ```ts

  // judgeBash:
  ```

  Дифференциальный оракул прошёл на этой неверной реализации: `bash fixtures/qa_kanal_xd/red_kanal_qa_report_issue.sh` → **rc 0**. Прямой живой CLI этой контрреализации дал:

  ```text

  rc=0
  ```

  На честном guard тот же вход корректно даёт `{"decision":"block",…}`. Следовательно, ответ таблицы верен не на тот вопрос: она доказывает `local://`, но не запрещённый контрактом `skill://`.

## Дополнительные обязательные классы

* **Отказ, выглядящий успехом:** PATH-stub `node`, завершающийся кодом 1, дал QA-пробе **rc 1**, не зелёный. Отказ именован верхним оракулом CLI↔factory.
* **Инструмент мимо PATH:** PATH без `node` дал **rc 2** и `NOT_IMPLEMENTED: нет node`; отсутствие инструмента не признано успехом. Перед этим shell также честно назвал недоступный `dirname`; итоговый именованный status пробы — отсутствие node.
* **Пустой вход:** прямой `--judge` с write и `path:""` возвращает pass. Это не нарушение части 030.2: у входа отсутствует URI/путь, а контракт судит разрешение внутренних URI. Он не маскирует A-030-7: непустой `skill://…` у неверной реализации был разрешён.
* **Нейтрализация:** A-030-6 нейтрализует только обязательность hub вне профилей пробы, сохраняя FABLE и все предъявленные A/B/C-пути; A-030-7 нейтрализует только запрет `skill://`, сохраняя каждую строку таблицы. Поэтому зелёный результат — дефект проверки, не «всегда-красный» стаб.
