## F1 — `check_charter --okno` превращает отказ построения списка в пустое зелёное окно

**Нарушено:** Frontier 2 и инварианты И-1/И-2: accept и land обязаны отвергать
правку уставного пути без `РАЗРЕШИЛ-ВЛАДЕЛЕЦ` через существующего судью в
окне. Вместо отказа общий гейт принимает её, если `check_charter` не сумел
прочитать свой список коммитов.

В `scripts/check_charter.sh:448` список прежнего уставного окна строится так:

```bash
g rev-list "$since..HEAD" > "$TMP/commits" 2>/dev/null || : > "$TMP/commits"
```

А в `:456-459` результат нового пересечения строится так:

```bash
g rev-list "$OKNO_BASE..HEAD" > "$TMP/commits_okno" 2>/dev/null || : > "$TMP/commits_okno"
grep -Fxf "$TMP/commits_okno" "$TMP/commits" > "$TMP/commits_isect" 2>/dev/null || : > "$TMP/commits_isect"
```

Каждый ненулевой rc — в том числе `127` — подменяется пустым файлом. Поэтому
нет различия между штатным пустым пересечением (`grep` возвращает 1) и
невозможностью исполнить `git`/`grep`; далее цикл не видит коммит и судья
завершается `0`. В отличие от него `check_zones.sh` канонизирует окружение и
явно отказывает при неудаче своего `rev-list`; именно `check_charter` остаётся
живым путём обхода общего гейта.

### Живой контрпример

В toy-репозитории есть `ustav/1`, `frozen/contracts/900/1` и зона `architect`
для `ROADMAP.md`. В `wip/900/architect` создан один коммит architect, меняющий
`ROADMAP.md` без строки разрешения. Нормальный запуск общего гейта даёт `rc=1`.
Затем впереди `PATH` поставлена только обманная команда `git`: она делегирует
`/usr/bin/git` всё, кроме `rev-list <что-либо>..HEAD`, для которого возвращает
`127`. Это ровно отказ инструмента, не изменение предмета или входной истории.

```
honest: rc=1
poisoned: rc=0
```

То же нарушение достигнуто через обе точки, а не только прямой вызов общего
скрипта:

```
# scripts/land_agent.sh; до/после проверен ref main
honest: rc=1 main_unchanged=yes
poisoned: rc=0 main_changed=yes

# scripts/accept_task_commit.sh; до/после проверена wip-ветка
honest: rc=1 branch_unchanged=yes
poisoned: rc=0 branch_changed=yes
```

Вторая независимая подмена оставляет настоящий `git`, но возвращает `127` лишь
для `grep -Fxf` — новой операции пересечения. Для того же неразрешённого
уставного коммита общий гейт опять дал:

```
honest: rc=1
poisoned: rc=0
```

Таким образом, классы «отказ, который выглядит успехом» и «инструмент мимо
PATH» не пойманы; через F1 запрещённая уставная правка принимается и на accept,
и на land.

### Граница проверки пересечения

Сам `grep -Fxf` в нормальном случае сохраняет порядок входного первого списка
и не дедуплицирует его: на первом списке `c,b,a,b`, шаблонах `a,b,b` получено
`b,a,b`; пустой список шаблонов дал rc `1`. Следовательно, порядок и
дубликаты не являются найденным дефектом: `rev-list` сам выдаёт множество.
Дефект — именно маскирование любого rc этой команды как штатной пустоты.

### Что обязано быть исправлено автором

`check_charter --okno` обязан различать ровно штатный rc `1` `grep` для пустого
пересечения и ошибку исполнения (`>1`, в том числе 127); отказ `git rev-list`
тоже обязан быть fail-closed. При ошибке судья должен завершиться не `0`, чтобы
`gejt_svedenija.sh` передал `rc=2` либо именованный отказ, но не принял окно.
Нужны регрессионные прогоны через **обе** точки: честная уставная правка без
разрешения красна; при делегирующем `git`-wrapper, который роняет только
`rev-list ...HEAD`, и при `grep`-wrapper, который роняет только `-Fxf`, accept
не сдвигает wip-ветку, land не меняет `main`.
