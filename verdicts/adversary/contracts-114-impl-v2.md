## Б1 — ceil медианы ломается на допустимом чётном входе выше 2^53

Канон требует `ceil(медиана ВСЕХ наблюдений окна)`; грамматика TSV допускает вес как неограниченный `[0-9]+`, верхней границы секунд нет. Обе реализации меры вычисляют чётную медиану как `math.ceil(statistics.median(o))`. `statistics.median` делит два Python `int` оператором `/`, то есть превращает результат в `float`; соседние целые выше 2^53 этим float уже не различаются.

Минимальный корпус в одноразовом клоне:

```
registry/ci-steps.tsv:
step\tcheck:huge\t1\tcmd

logs/01.log: замер: check:huge 9007199254740992
logs/02.log: замер: check:huge 9007199254740993
```

Прогон предмета:

```
bash scripts/measure_ci_weights.sh \
  --root /tmp/dev-harness-verify/Adv114r2/cases/huge/root \
  --logs /tmp/dev-harness-verify/Adv114r2/cases/huge/logs \
  --min-obs 2 --out /tmp/dev-harness-verify/Adv114r2/cases/huge/out.tsv
# rc 0
# check:huge\t9007199254740992\t2\t0
```

Независимое целочисленное вычисление `(a+b+1)//2` даёт `9007199254740993`. Значит мера тихо занижает вес на единицу на валидных наблюдениях. Это не только наблюдение TSV: после записи ложного веса `9007199254740992` в реестр и TSV в отдельном toy-git мире `bash scripts/check_ci_weights.sh --root . --migrate` вернул `rc 0`, `ok: веса по замеру (миграция): 1 ключей`.

Батарея не ловит этот класс: `bash fixtures/_krasnye_114.sh` вернул `rc 0`, `40/40`; положительный контроль честной модели тоже `rc 0`, `40/40`. Модель повторяет ту же `float`-арифметику, поэтому это не независимый оракул для граничных целых. Исправление: считать медиану целочисленно (для чётного `ceil((lo+hi)/2) == (lo+hi+1)//2`), без перехода через `float`, и добавить красную клетку с соседними числами выше 2^53.
