## Блокер I1: канарейка `grep -P` не судила рабочий Unicode-предикат

На судимом HEAD `orch_restart.sh` проверял канарейкой только
`grep -P '\p{Z}'`: положительный вход `a b` и отрицательный `ok`. Реальная
грамматика проверялась другим, более широким выражением
`\p{Z}|\p{Cc}|\p{Cf}`. Поэтому PATH-shim мог корректно делегировать
канарейку системному `grep`, а для рабочего составного выражения вернуть
`1` («совпадения нет»).

В toy-мире все остальные ноги были зелёными: `HEAD == origin/main`, чистый
porcelain, `HANDOFF.md` создан автором `evil identity`, след старше
коммита, сессия без журналов и `check_no_leak` зелёный. Shim возвращал `1`
только при аргументах `-P -q '\p{Z}|\p{Cc}|\p{Cf}'`; всё иное передавал
`/usr/bin/grep`. Несмотря на ASCII-space в запрещённом имени, дверь
поставила marker:

```text
selector-shim rc=0 marker=yes stderr= stdout=ПЕРЕЗАПУСК: маркер поставлен
```

Это селективная заглушка «правильная проверка не того предиката»: прежние
v4 клетки ловят отсутствие `grep -P` и shim, лгущий на *каждом* `-P`, но
не shim, сохраняющий старую узкую канарейку и лгущий только на исполнении
рабочего предиката.

**Исправление в `22c39a9`:** канарейка теперь вызывает ровно рабочий
предикат на трёх положительных представителях `Z`, `Cc`, `Cf` и чистом
отрицательном входе. Результат проверки самого `--as` разбирается явно:
`0` — отказ как запрещённое имя, `1` — чистое имя, любой иной rc —
fail-closed. Тот же shim после правки получает rc 1 с pinned diagnostic и
не создаёт marker.

## Блокер I2: rc 1 чтения shared config отождествлялся с отсутствием ключа

Нога (д') использовала rc `git config --file "$SHARED_CFG" --get
user.{name,email}` как бит наличия. Для честного `git` rc 1 означает
«ключ отсутствует», но исходник не доказывал, что именно этот смысл был
получен. Обманный `git` из PATH делегировал все команды `/usr/bin/git`,
кроме `config --file ... --get`, для которых возвращал rc 1. В sandbox
общий `.git/config` действительно содержал `user.name=leaked`, staged
файл был непуст, identity была `GIT_AUTHOR_NAME=env-bot`; субъект вернул
успех:

```text
git-config-shim rc=0 stderr= stdout=не судится: автор «env-bot» не объявлен ни в одной заморозке
```

Таким образом, отказ инструмента, выглядящий как «ключа нет», пропускает
ровно обязательную проверку общего file-config. Это не закрытая v1
проверка пустого/повторного ключа: там честный `git` возвращает rc 0 для
имеющегося ключа; здесь селективный инструмент подменяет сам результат
его чтения.

**Исправление в `22c39a9`:** после разрешения общего git-dir добавлена
контролируемая канарейка: временный config с `user.name=check-staged-probe`
обязан читаться `git config --file --get` с rc 0 и точным значением. Ошибка
разрешения common-dir или неподтверждённая канарейка даёт rc 2
`NOT_IMPLEMENTED`, а не проход. После фикса тот же shim останавливается
перед путевым/зонным судом с rc 2 и именованной причиной. Честные clean,
name/email и linked-worktree клетки батареи остаются зелёными.
