## Блокеры

### I1. Отсутствующий/сломанный `grep -P` считается валидной грамматикой `--as`

Инвариант 1 требует отвергать `--as`, содержащий пробелы, непечатные либо
Unicode-format/space code point. Реализация проверяет это так:

```bash
if printf '%s' "$AS_VAL" | grep -P -q '\p{Z}|\p{Cf}|[\x00-\x1f\x7f]' 2>/dev/null; then
  … отказ …
fi
```

Проверки статуса инструмента нет. В toy-репозитории со всеми прочими
зелёными ногами (HEAD==origin/main, чистый porcelain, HANDOFF от
`evil identity`, старый след, чистый config и снимок `check_no_leak`) в
`PATH` был подставлен только `grep`, возвращающий 127 **лишь** для первого
аргумента `-P`, а для всех прочих запусков делегирующий `/usr/bin/grep`.

```text
I1 grep-P-127: rc=0 marker=yes stderr=
```

Команда двери была `bash scripts/orch_restart.sh --as 'evil identity'`.
То есть недопустимое имя прошло все реальные ноги и поставило маркер;
отказ инструмента прочитан как «запрещённых code point нет». Это требуемый
класс «инструмент мимо PATH/отказ, выглядящий успехом». Текущие a6/a7/a8
проверяют лишь исправный системный `grep`, поэтому 24/24 не различают
такую заглушку от правильной проверки.

**Требуемая правка:** явно потребовать доступный `grep -P`, выполнить
детерминированную канарейку на запрещённом и чистом Unicode-входе и
fail-closed отказать rc 1, если любой запуск дал не ожидаемые rc/вывод.
Добавить клетку с `grep -P` rc 127 (и, как отдельную частичную заглушку,
rc 1/пустым выводом): `--as 'evil identity'` обязан дать pinned
`identity двери не определена` и не поставить маркер. Корректное
кириллическое `--as` должно оставаться зелёным.

### I2. Неудача `touch` маркера всё равно фиксирует `state=hard`, выключая retry

Инвариант жёсткой ноги требует `state=hard` **только после маркера** и
повтор после временного сбоя. В конце hard-ветки код сейчас делает:

```bash
if [ "$report_ok" -eq 1 ]; then
  as_u touch "$MARK" && log "…"
  echo hard > "$st"
fi
```

`echo hard` не зависит от статуса `touch`. В мире `ORCH_PEAK_TEST` с
usage 600000, без свежих субагентов, доступным `$REPORT`, короткими
GRACE/POLL и `ORCH_MARK=$world/no-such-parent/mark` первый `ctx` получил:

```text
I2 marker-write-failure: first_rc=0 first_state=hard marker=no second_rc=0 second_say_lines=1
```

Второй `ctx` той же сессии завершился до polling/попытки маркера: строка
в `say.log` осталась одна. Так нейтрализация ровно одного действия
(невозможная запись маркера) не вызывает повтор, а превращает сторож в
вечный ложный успех для данного session journal. Нормальные г6–г8 не
попадают в эту ветвь, так как их `$ORCH_MARK` доступен.

**Требуемая правка:** считать `touch` частью транзакции: при его ошибке
вернуть именованный отказ без `state=hard`; писать `hard` лишь после
подтверждённого существования маркера. Добавить поведенческую клетку:
первый `ctx` с отсутствующим родителем `$ORCH_MARK` не ставит marker и не
пишет hard; после создания родителя второй `ctx` снова выполняет hard-путь
и ставит marker. Отдельно сохранить уже закрытый случай неудачи `$REPORT`.

### I3. CTX_SOFT принимает неверный текст вместо pinned фразы контракта

Инварианты 7/15 требуют одной физической строки:

```text
новых спавнов не начинай, дождись завершения текущих субагентов, затем перезапуск дверью
```

В реальном `orch-peak` написано `текущей субагентов`. Поэтому точный
поиск обязательной frozen-фразы возвращает 1, а сообщение, которое
доставляется в `say.log`, содержит грамматически неверный вариант.

Батарея сама определяет `PHRASE_OK` с тем же неверным `текущей` и
принимает этот вариант; именно поэтому её структурная клетка в1,
поведенческая в3, стаб s6 и итог 24/24 остаются зелёными. Это
«правильный ответ не на тот вопрос»: тест проверяет литерал, отличный от
замороженного инварианта.

**Требуемая правка:** заменить слово в subject на `текущих` и вернуть
`PHRASE_OK`/s6/в1/в3 батареи к дословному pinned-литералу frozen-контракта.
Не ослаблять контракт.
