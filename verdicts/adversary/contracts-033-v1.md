## Проверка union-семантики и различающей фикстуры

Код `scripts/check_zones.sh` в суде путей использует:

```sh
awk -F'\t' -v a="$an" '$1 == a { print $2 }' "$TMP/zones_scoped" | sort -u > "$TMP/mine"
```

То есть union всех замороженных зон автора, без `$3 == n`.

`case_union_zon_vseh_zamorozok.sh` действительно различающая, не формальная:

- строит contract 001 с зоной `scripts/` и contract 002 с зоной `fixtures/b/` для одного `agent-x`;
- коммитит `fixtures/b/union.md`, который находится в диапазонах обоих окон;
- честный union-барьер обязан быть зелёным;
- затем fixture копирует субъект и нейтрализует ровно union-ветвь, возвращая per-contract фильтр `$1 == a && $3 == n`;
- этот стаб обязан вернуть rc 1 и назвать `fixtures/b/union.md`.

Факт исполнения подтверждён run `verify_antiplacebo`: у этой fixture есть зелёный контроль и красный повторный прогон проверяющего.

## Решение

**FAIL.** Done-токен Н-100 не сажать по контракту 033 в текущем виде. Нужна коррекция предмета/критерия через авторский круг: либо реальное fail-closed поведение на пустой судимой выборке, либо честно изменённая норма без ложного утверждения о красном нуле.
