## Новый обход: тот же корень N1, сигнал арбитру, не новый авторский круг

Найден ложнозелёный субъект, который делегирует `p1` и **любой** ID с
фиксированным префиксом `rnd`, но не вычисляет правило для всей грамматики
`^[a-z0-9][a-z0-9_-]*$`:

```bash
case "$project_id" in
  p1|rnd*) exec "$real_workshop" "$@" ;;
  *) printf 'AGENTDB: изолирована\n'; exit 0 ;;
esac
```

Его полный scoped-прогон остаётся зелёным, потому что все проектные входы
058 — `p1` либо случайный, но всегда `rnd$RANDOM$$`:

```text

    bash fixtures/workshop_project/red_sharing_agentdb.sh

к15: случайный projectId=rnd159601216037 — зашитый набор p1|p2 краснеет (N1)
честная часть: 16/16 зелёная; предъявлений: стабы 9/9 + дифф 9/9 + честные 16/16
rc=0
```

Но на конформном toy-входе с другим допустимым `projectId=p2`, живым
DEVDB и тем же мутантом получается ложный A2/rc=0 без симлинка PROJDB:

```text
$ XDG_STATE_HOME=…/p2-state HARNESS_PROJECT_LAYER_ROOT=…/p2-layer \
    bash .adversary058-mutants/n1-rndprefix-workshop --probe …/p2-repo
AGENTDB: изолирована
patterned-N1 breach: p2 live DEVDB but no PROJDB symlink
rc=0
```

Это **тот же корень**, что F1/N1: зашитый предикат вместо общего
вычисления для любого `projectId`. К15 закрыла конкретный набор `p1|p2`,
но её предсказуемая форма `rnd*` сама стала новой константой мутанта.
Согласно назначению, это явный **сигнал арбитру, а не новый круг автора**:
конечный набор тестовых ID не может сам доказать универсальность
контрактного правила, и очередное расширение перечня префиксов не устраняет
корень.
