# FAIL — fail-closed по rc закрыл круг-1, но неполный успешный author stream всё ещё делает нарушителя невидимым

Проверен HEAD с фиксом `dd2befe`. Круг-1 топология действительно закрыта: в
живом toy-репозитории с замороженной зоной `agent-x: scripts/`, легальным
коммитом в `scripts/` и следующим нарушающим коммитом в `plans/` PATH-spy
делегировал все вызовы реальному git, кроме `git log ... --no-walk`, который
возвращал `127`. Честный запуск дал `rc=1` и `коммит вне зоны`; spy дал
`rc=1` и ровно именованное:

```text
ОТКАЗ: batched git log --no-walk --stdin отказал ... список авторов окна недоступен.
```

Это именно нужная fail-closed реакция на круг-1, а не ложный успех.

## Новый обход: частичный, но успешный stdout

Тот же PATH-spy вместо отказа выполнил настоящий `git log` и отдал только
первые 50 байт stdout — одну полную NUL-запись `SHA\0agent-x\0\n` первого,
легального коммита — затем завершился `rc=0`. Второй, нарушающий коммит не
попал в `author_nul`. Реальный результат:

```text
partial-rc0 rc=0

замороженных контрактов: 1 · объявленных авторов: 1 · коммитов в диапазонах: 2 · проверено по зонам: 1
```

То есть `if ! g log ...` различает лишь статус процесса, но не полноту и
соответствие `author_nul` входному `$TMP/commits`. Разбор спокойно строит
частичный map; отсутствующий SHA в горячем цикле трактуется тем же образом,
что автор вне объявленных зон (`[ -n "$an" ] || continue`). Поэтому незаконный
коммит исчезает из суда. Это воспроизводимое ложное зелёное, не
постоянно-зелёная заглушка: без spy тот же предмет красный, а первый коммит
действительно проверен.

Лекарство остаётся за автором: после успешного batched lookup нужно
fail-closed сверять, что map содержит ровно по одной корректной записи для
каждого SHA из `$TMP/commits` (и не принимать усечённые/битые пары). Простая
проверка rc этого не доказывает.

## Прочие независимые пробы

* **Положительный контроль:** честный toy с той же замороженной зоной и без
  коммитов после freeze дал `rc=0`; полный `verify_antiplacebo` ниже также
  подтвердил зелёные контроли всех case-файлов. Следовательно новый `if !`
  не сделал обычный легитимный вход постоянно красным.
* **Кодировка авторского имени:** зона и commit author `агент`, с локальным
  `i18n.logOutputEncoding=ISO-8859-1`, всё ещё дали `rc=1` и `коммит вне
  зоны` для запрещённого пути. Эта проба не обнаружила обхода NUL-разбора.
* **Таймаут вместо rc:** PATH-spy, который на `--no-walk` спит 5 секунд,
  был запущен как `timeout 2 ...`; получен `rc=124` без ложного `rc=0` и без
  диагностического текста из ветви отказа. Это fail-closed на уровне
  вызывающего CI, но не именованная обработка зависшего git внутри барьера.
  Кратковременный отказ git/CI теперь также блокирует freeze/done `rc=1`;
  это намеренный и явно названный fail-closed trade-off, не обход и не
  легитимный здоровый вход. Я не считаю его причиной ложной красноты для
  честного доступного git.
