## Границы `in_enf`

Отдельный toy-драйвер прогнал один и тот же настоящий барьер на шести входах:

| Вход | Наблюдение |
|---|---|
| пустое тело контракта | `rc=2`, `NOT_IMPLEMENTED: тело контракта пусто` — пустой ввод не стал успехом |
| `ПРОВОДКА:` без каналов | `rc=1`, `проводка: поле пусто` |
| честный marker + три непустых continuation-строки | `rc=0` (положительный контроль) |
| continuation, затем пустая строка, затем голая «вторая часть» | `rc=1`, на самой второй части |
| marker, сразу пустая строка, затем голая `role=roles/missing.md …` | `rc=1`, `проводка: строка вне грамматики: role=roles/missing.md «Missing role norm.»` |
| marker/continuation, затем сразу `#` без blank, затем обычная проза | `rc=0` |

Тем самым пустая строка действительно выключает `in_enf`: в том числе в
сценарии «два логических абзаца» вторая голая половина НЕ теряется молча, а
краснеет своей строкой. Это соответствует предмету круга 16, где первая
пустая строка прямо названа терминатором markdown-абзаца. В сценарии из
пункта (2) новой фикстуры флаг также уже выключен до голой строки. Заголовок
без промежуточной пустой строки корректно завершает сбор поля; последующая
проза больше не интерпретируется как канал.

## Обманные реализации и нейтрализация

Каждая подмена запускалась против того же отдельного входа; её выход из
проверяющего драйвера — намеренный `rc=1`, то есть тест поймал плохую
реализацию, а не объявил её зелёной.

| Подмена | Дискриминирующий результат |
|---|---|
| `exit 0` (отказ выглядит успехом / константа) | после положительного контроля пропустила вариант с blank внутри ЭНФОРСМЕНТ: ожидался `rc=1`, получен `rc=0`; драйвер красный |
| `exit 1` (вечный отказ) | честный многострочный ЭНФОРСМЕНТ ожидал `rc=0`, получен `rc=1`; драйвер красный |
| убран reset `in_enf=0` на blank (нейтрализация ровно одной проверяемой вещи) | постоянная `red_R16_bare_line_after_enf_paragraph.sh` прошла свой positive-control и упала ТОЛЬКО на negative-control: ожидала `rc=1` для голого role после blank, получила `rc=0` |
| `#` заменён с `break` на `in_enf=0; continue` (ответ на соседнюю строку вместо окончания поля) | вариант без blank перед заголовком дал `rc=1` на последующей прозе вместо честного `rc=0`; драйвер красный |
| канонический PATH заменён на несуществующий | честный положительный вход дал `rc=2`; наблюдались `dirname: command not found`, `sed: command not found`, затем `NOT_IMPLEMENTED`; отсутствие инструмента не маскируется успехом |

Таким образом проверка различает работающую ветвь и плохие ветви, а не только
«всегда красное» и «всегда зелёное». Нового живого обхода на переходах
`in_enf` не найдено.
