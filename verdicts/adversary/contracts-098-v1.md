## Блокер A-098-1 — ответ CI от другого коммита выдаётся за M

Решение 2 и Б-5 требуют структурно связать обязательный ключ с конкретным запуском и **исполненным деревом M**. Честная модель `fixtures/dokazatelstva_098/model/check_ci_gate.sh` это делает: читает `head_sha` из ответа CI и отказывает, когда он не равен аргументу M. Однако ни одна из 14 клеток не предъявляет ответ CI, где одноимённый доверенный зелёный запуск имеет `head_sha != M`; стаб-пак также не портит эту сверку.

Я построил внешний обманный субъект: его `scripts/check_ci_gate.sh` подменяет результат разбора поля `head_sha` значением аргумента M, а остальные ветви делегирует честной модели. `scripts/judge_gate.sh` и `scripts/accept_publish.sh` — честные модели. Тем самым он принимает в ответе CI зелёный запуск для B как доказательство для M и записывает строку `check` с деревом M, хотя `head_sha` ответа равен B.

### Исполнение

1. Позитивный контроль честной модели:

   ```text
   bash fixtures/_krasnye_098.sh --model
   # все 14 клеток rc=0; стаб-пак s1…s17 rc=0; ИТОГ 098: rc=0
   ```

2. Отдельно живой раннер на ветке без реализации ожидаемо красный и не маскирует отсутствие субъекта:

   ```text
   bash fixtures/_krasnye_098.sh
   # rc=1; все клетки называют отсутствующий scripts/accept_publish.sh
   ```

3. Обманный субъект прошёл ПОЛНЫЙ реальный режим того же раннера:

   ```text
   bash fixtures/_krasnye_098.sh
   # стаб-пак s1…s17 rc=0; все 14 red_*.sh rc=0; ИТОГ 098: rc=0
   ```

   Значит батарея не ловит именно этот обман: она проверяет 17 своих мутаций модели, но не проверяет принятие ответа с чужим `head_sha` реализацией-писателем.

4. Специальная живая проба создала B, C, M, получила корректный зелёный `ci-a` для B, поместила этот JSON под ответ CI для M и вызвала обманный `--check-row` с M. Наблюдение:

   ```text
   BYPASS: CI run head_sha=cc270c59808ac52d376af275bdd55afe44815338 accepted as M=5e4cc624c36f69d23762c3228c0672f4158ad012
   ```

   То есть строка журнала утверждает дерево M, хотя предъявленный CI запуск исполнил B. Это ровно «правильный ответ не на тот вопрос» и ломает инвариант происхождения Б-5; при дописывании остальных честных строк дверь примет такую подменённую `ci-a` как доказательство M.

## Обязательные дополнительные пробы

- Пустой ответ CI (`total_count=0`, `check_runs=[]`) честная модель отвергает: `EMPTY-INPUT-REFUSED` (rc 1, `нет обязательной проверки: ci-a`, журнал пуст).
- Запуск модели с `PATH=/nonexistent` не выдаёт успех: rc 2, `NOT_IMPLEMENTED: нет git — историю прочитать нечем`.
- Нейтрализации verdict/check/policy, константы/подстрочные имена, чужое дерево и определение, поздние fail/success и смешанная история уже исполнялись встроенным стаб-паком s1…s17; позитивный контроль выше подтвердил, что эти клетки не вечно красные.

Нужна авторская правка проверки: отдельная клетка должна поместить для M одноимённый доверенный зелёный запуск с `head_sha` другого существующего коммита, требовать rc 1 с именованным отказом и отсутствия check-строки; парный контроль с `head_sha == M` должен записывать строку и проходить публикацию. До этого критерий пропускает реализацию, нарушающую решение 2/Б-5.
