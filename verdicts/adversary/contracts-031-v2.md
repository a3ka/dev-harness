# Adversary 031 / круг 2 — суд all-lines фикса двери минта

**Вердикт: FAIL.** Фикс `valid_count == add_count` закрывает смешение валидной строки с *непустой* неграмматичной строкой, но не считает пустую добавленную строку вообще. Поэтому манифест с честной строкой и отдельной пустой `+`-строкой проходит и staged-дверь, и историческое mint-признание.

## Именованный обход — пустая добавленная строка манифеста

Замороженный 031/4, механизм 1, условие 2 требует грамматику от **каждой добавленной строки**. Git показывает добавление пустой строки в `git diff -U0` как единственный байт `+`. Оба потребителя считают добавки только предикатом `^\+[^+]`, который требует символ после `+`:

- `scripts/check_staged.sh:435`: `add_count=… awk '/^\+[^+]/ …'`;
- `scripts/check_zones.sh:405`: `mint_add=… awk '/^\+[^+]/ …'`.

Пустая `+`-строка не входит ни в счётчик добавок, ни в `added_lines`, отфильтрованный `sed`. При одной корректной строке оба значения равны 1, так что сравнение `valid_count == add_count` на строках 450–452 / 417–419 ложно доказывает all-lines predicate.

### Выполненное воспроизведение

Для каждого пути создан свежий toy-репозиторий: frozen `001/1` объявляет зону `orchestrator: HANDOFF.md`, ветка `main`, файловый bare `origin`, два живых аннотированных и запушенных `id/CONTRACT`-тега. Предметная дельта содержит одну действительную строку

```text
700 → <tag-object-sha id/CONTRACT/700>

```

то есть за ней добавлена пустая физическая строка.

**Staged-дверь:** `bash <copied scripts>/check_staged.sh <toy>` вернул **rc 0**:

```text
judged: registry/contracts.tsv (дверь минта 031: +1 строк ↔ живые dual-control теги)
ok: staged в зоне автора orchestrator (1 путь/путей)
```

Это должно быть `rc 1` с `дверь минта 031: строка не по грамматике манифеста`.

**Hook-bypass / историческое признание:** та же дельта закоммичена фактическим автором `orchestrator` через `git -c core.hooksPath=/dev/null commit`, затем проверена копией `check_zones.sh`. Она вернула **rc 0**:

```text
процессных вне суда:

замороженных контрактов: 1 · объявленных авторов: 2 · коммитов в диапазонах: 1 · проверено по зонам: 1
```

Ни `коммит вне зоны`, ни именованная ошибка грамматики не напечатаны. Это должно быть `rc 1`; commit-time hook обходится, а CI-признание повторяет ту же дыру.

### Требуемый ремонт

Оба пути должны считать **все** строки добавления из unified diff, включая bare `+`, и до построения пар отвергать любую строку, не соответствующую полной грамматике. Исправлять только `check_staged` недостаточно: commit с отключённым hook обязан быть пойман `check_zones`. Нужна постоянная проба `валидная + пустая` для обоих путей, с честным позитивным контролем.
