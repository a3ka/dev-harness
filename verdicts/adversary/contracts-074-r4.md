# Адверсарий 074-к4 — предел перечитывания к1b

Предмет: `a1957624004ec18025f3c681e5ece505a7e01288`.
Рамка вердикта — строго П4 `verdicts/arbitration/074-k1b-predel.md`: блокером был бы только ленивый субъект без перечитывания, которому батарея даёт `rc 0` без сговора с окружением батареи. Такого субъекта не найдено.

## Последовательные прогоны

1. Мой вход к3 `pw`: из `git archive HEAD` построен отдельный мир; user-ветвь записывает исходник блоками 4096 байт через Python `os.pwritev`, затем ставит режим, но **не** вызывает `check_one`. Батарея запускалась без изменения батареи, интерпозера либо `PATH`:

   ```sh
   REPO_ROOT=/tmp/dev-harness-verify/adv074k4/repo \
   OPS_ROOT=/tmp/dev-harness-verify/adv074k4/pw \
   bash fixtures/_krasnye_074.sh
   ```

   Результат: `rc 1`; единственная красная клетка — `cell_k1b`; диагностическая причина дословно содержит `канал порчи инертен … перечитывание НЕ ДОКАЗАНО (fail-closed, арбитраж 074-k1b П3)`. Честная часть остаётся `7/7`, стаб-пак `7/7`, диффпроба `7/7`, каналы `честные 6/6, ленивые пойманы 6/6`. Это предписанный fail-closed-класс, не блокер П4.

2. Штатный предмет:

   ```sh
   bash fixtures/_krasnye_074.sh
   ```

   `rc 0`: честная часть `7/7`; `s1`–`s7` пойманы `7/7`; диффпроба `7/7`; к1b-каналы `6/6 + 6/6`; к1b сообщает отказ субъекта на испорченной записи, interposer испортил 1 запись.

3. Позитивные контроли:

   ```sh
   FIXSIM=1 bash fixtures/_krasnye_074.sh
   LANDSIM=1 bash fixtures/_krasnye_074.sh
   ```

   Каждый дал `rc 0`, честная часть `7/7`, стаб-пак/диффпроба `7/7`, каналы `6/6 + 6/6`.

4. Прежние наблюдаемые ленивые миры `cat`, `install`, `tee`: каждый построен из независимого `git archive HEAD`; user-ветвь использует соответственно этот механизм, но не перечитывает sha256. Каждый запуск с `OPS_ROOT=<мир>` дал `rc 1`, `КРАСНО: cell_k1b`, с прежней именованной причиной `rc=0 на испорченной записи … user-часть не перечитывает sha256`; interposer учёл 1 порчу. Батарея не приняла ни один из этих наблюдаемых ленивых субъектов.

5. Охота на ленивый `rc 0` без сговора: дополнительно проверен независимый rename-класс. Он копирует в скрытый временный файл, делает `chmod`, затем `mv` в `orch-loop`, без `check_one`; батарея, интерпозер и `PATH` не подменялись. Результат `rc 1` и тот же именованный fail-closed `перечитывание НЕ ДОКАЗАНО`; `cell_k1b` — единственная красная клетка, остальные показатели `7/7`, `7/7`, `7/7`, `6/6 + 6/6`. Это второй ненаблюдаемый класс, который уходит в предписанное красное, а не в ложное зелёное.

## Вердикт

Клетки к1–к7, стабы s1–s7 и канальные пробы живы по фактическим прогонам выше.
