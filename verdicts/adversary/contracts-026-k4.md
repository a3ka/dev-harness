# Адверсарий контракта 026, круг k4 — fail-closed TMP-РЕАП

Судимый фикс — `58c746a818a16ef552b5509a996ad264166a962e`
(`fix(026): fail-closed tracked-guard per git-call + always-validate
--tmp-reap-age (k3)`) на базе `5fa3895900a53609a4df74646dd28e53ff254ebc`.
Предмет в изолированном клоне не менялся; игрушечные репозитории, PATH-подмены
`git`/`rm` и harness находились вне клона.

## Закрытые атаки k3

Обе причины k3 закрыты исполнением.

1. В игрушке `tmp/mix/` одновременно содержались staged tracked `y` и untracked
   `z`; верхняя запись была старше 40 суток. Подставной `git` делегировал
   источник `ls-files --others`, но вернул `1` ровно на завершающем
   tracked-контроле `git ls-files -- tmp/mix`. Фикс завершился `rc=2` с
   `NOT_IMPLEMENTED: git ls-files (tracked-контроль) отказал ... (rc=1)`;
   `y` и `z` остались. Отказ больше не интерпретирован как пустой ответ.
2. При существующем, но пустом `tmp/`, все `--tmp-reap-age NaN`, `inf` и `-1`
   дали `rc=2` и `NOT_IMPLEMENTED` до чтения источника кандидатов.

## Новые атаки фикса

### Терминальный git-вызов и частичный источник закрыты

* Для старой анонимной `tmp/anon/` подставной `git` вернул `127` ровно на
  третьем и последнем git-вызове TMP-пути — `git ls-files -- tmp/anon`.
  Получены `rc=2`; запись осталась на месте.
* Подставной источник `git ls-files --others -z -- tmp/` вывел строгий префикс
  корректного NUL-потока, затем завершился `rc=1` (модель обрыва канала).
  Получены `rc=2`; обе старые записи `tmp/one/` и `tmp/two/` остались. Частичный
  stdout не был использован как список кандидатов.

### FAIL 1 — «безусловная» валидация не выполняется без `tmp/`

В корректном git-репозитории с `contracts/026-live.md`, но без каталога
`tmp/`, запуск

```text
bash scripts/gc_agent_branches.sh --root <toy> --tmp-reap-age NaN
```

вернул `rc=0` и итог `TMP-РЕАП кандидатов 0`, без `NOT_IMPLEMENTED`.
Валидация по-прежнему находится внутри `if [ -d "$ROOT/tmp" ]; then`
(`scripts/gc_agent_branches.sh:285-304`). Поэтому публичный параметр зависит
от случайного наличия каталога, несмотря на заявленную безусловность. Ожидался
`rc=2` независимо от существования `tmp/`.

Дополнительно граница заявленного «положительного конечного числа» неверна:
при пустом существующем `tmp/` значения `0`, `0.0` и `-0.0` каждое дали
`rc=0`. Обе проверки используют `v < 0` (`:299`, `:394`) вместо строгого
`v <= 0`; нулевой порог не положителен.

### FAIL 2 — названный TOCTOU-carve-out допускает удаление tracked

Комментарий перед `rm -rf` на `:503-510` называет окно check-then-act
приемлемым как «вне слоя 1». Это ложно для собственного инварианта TMP-РЕАП:
tracked «не кандидат НИКОГДА».

В игрушке исходная старая `tmp/anon/` была честно untracked. Подставной `rm`
сработал только для точного argv удаления `tmp/anon`: после успешных источника
и tracked-контроля он заменил запись каталогом с `tmp/anon/tracked`, добавил
его в индекс через настоящий `git add -f`, затем делегировал настоящий `rm`.

Фактический результат — `rc=0`, строка `TMP-РЕАП: tmp/anon возраст 40.0d` и
отсутствующий tracked-файл. Значит проверенный untracked объект подменяется
tracked объектом по тому же имени и удаляется. Это не только смена свежести:
теряются байты, которые инвариант прямо запрещает трогать. Комментарий честно
описывает риск, но его архитектурное оправдание не сохраняет контракт; фикс
предмета остаётся за автором.

`rc=0`: 7/7 case-фикстур имеют зелёный контроль и именованный красный повтор.
Тем самым это не вечно-красная проверка.


## Вердикт

`FAIL`: k3-регрессии и два новых отказа git закрыты, но два независимых
