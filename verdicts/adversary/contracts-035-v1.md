**Предмет:** post-close-out дерево из отдельного клона `HEAD 6f37b4365def82cc9ec6d2f976ac0cfb55347d16`; закон — `frozen/contracts/035/1` (`a2eadc2`). Клон не менялся (`git status --porcelain` пуст). Вердикт должен приземлить оркестратор с `author=adversary` в `verdicts/adversary/contracts-035-v1.md`.

## Именованный обход: «census-декларация без живого дерева»

Заключительная исполнимая проверка из § «Приёмочный критерий» проверяет только три текстовые формы: маркер Н-97, отсутствие старого маркера и регулярное выражение строки HANDOFF. Она не получает корень жнеца, не запускает `gc_agent_branches --tmp-reap-apply`, не перечисляет `tmp/` и не сопоставляет числа census с деревом.

В отдельной временной копии только `NABLIUDENIA.md` и `HANDOFF.md` была подменена уже конформная census-строка на заведомо ложную:

```
035 close-out: census ./tmp: 999 верхнеуровневых (0 непустых, 999 пустых), draft020 ×2 снесены
```

Затем дословно запущена заключительная команда контракта. Она завершилась `rc 0`; проба напечатала `falsified census accepted`.

Отдельное наблюдение на самом клоне: в нём нет `tmp/` (untracked-содержимое не переносится клоном), однако

```
bash scripts/gc_agent_branches.sh --root /tmp/dev-harness-verify/adv-035/repo --tmp-reap-apply
```

завершилась `rc 0` с `TMP-РЕАП кандидатов 0`; заключительная текстовая проверка после этого всё равно даёт `rc 0` для заявления о `10 верхнеуровневых (3 непустых, 7 пустых)`. Следовательно, закрытие можно оформить маркером и синтаксически годной, но не соответствующей дереву census-строкой, не предъявив реальный apply/снос `draft020 ×2`.

Это прямо пробивает поставленный вопрос close-out: проверка судит «маркер+census», но не файлы. До исполнимого связывания результата с указанным живым корнем и наблюдаемым apply/census Н-97 нельзя признать закрытым.
