# Адверсарий 054f — живая реализация 4850085

Проверка зелёная, но не различает несколько нарушений замороженного контракта 054.
Поэтому гейт не может быть принят: ниже приведены исполнения, в которых субъект
возвращает `rc=0` там, где контракт требует именованный отказ.

## Позитивный контроль и неизменность

В одноразовом SSH-клоне выполнены:

- `bash fixtures/_krasnye_054.sh` — `rc=0`: стаб-пак поймал 9/9 своих стабов,
  честные к1–к14 зелёные;
- `bash fixtures/parsing_hygiene_battery/run_battery.sh profile_resolver` —
  `rc=0`, 4/4 класса закрыты;
- `git diff --exit-code frozen/contracts/054/1 -- contracts/054-profil-dva-sloja-launcher-proekta.md`
  — `rc=0`.

Это не вечно-красная батарея. Её зелёный результат и есть наблюдаемая
неразличимость перечисленных контрмоделей.

## Обманная заглушка, пережившая батарею

Построена заглушка резолвера: на всех обычных входах она делегирует живому
`profile_resolver.sh`, но для `projectLayer.profilePath='../…'` возвращает успех
вместо отказа. Запуск

```sh
PROFILE_RESOLVER="$PWD/.adversary-profile-mutant.sh" bash fixtures/_krasnye_054.sh
```

дал `rc=0`, включая 9/9 стабов и к1–к14. Отдельный позитивный контроль этой
заглушки на валидном JSON за пределом корня слоя дал
`MUTANT BYPASS profile-path-traversal: rc=0`.

Следовательно, штатная батарея не ловит обход корня слоя. Это не только свойство
заглушки: живая реализация принимает тот же вход.

## Непойманные нарушения, исполненные против живого кода

Скрипт `.adversary-054-probes.sh` построил изолированные toy-репо/слои и выполнил
живые `profile_resolver.sh`, `workshop --probe` и `gen-harness.ts`. Все следующие
строки были наблюдаемы с `rc=0`:

1. `BYPASS nested-defaults-unknown: rc=0` — ключ
   `defaults.workflowPaths.unseen` слоя проекта не дал P4. И-3 требует отказ на
   ключ вне алфавита любого уровня. Причина в коде: обход вложенных defaults
   проверяет `has("defaults.workflowPaths")` на корне JSON, а не путь
   `.defaults.workflowPaths`, поэтому такие ветви вообще не сканируются.
2. `BYPASS empty-command-value: rc=0` — `commands.test: ""` репо-слоя принят и
   выдан. И-4 требует непустую строку для каждого `commands.*` (P6).
3. `BYPASS profile-path-traversal: rc=0` — `profilePath: "../escaped.json"`
   читает sibling-файл вне `${HARNESS_PROJECT_LAYER_ROOT}`. В2/граница-2 задают
   файл слоя как `<корень>/<profilePath>` и binding вне Git; относительность не
   должна быть путём выхода из корня. Проверка отсекает только ведущий `/`.
4. `BYPASS empty-rules-section: rc=0` — файл из единственной строки литерального
   заголовка секции принят `node scripts/gen-harness.ts --agents-rules`. И-9
   прямо устанавливает: «вывеска без тела правил правилом не является»; G1
   должен fail-closed также на пустой секции. К10 проверяет только отсутствие
   заголовка, не пустое тело.
5. `BYPASS global-only-4.3: rc=0` — у toy-репо локальный
   `receive.denyCurrentBranch` отсутствовал, но `HOME/.gitconfig` содержал
   глобальный `receive.denyCurrentBranch=refuse`; `workshop --probe` стартовал.
   И-10 требует явную настройку **в репо проекта / каждом клоне**. Текущий
   `git -C "$PROJECT" config --get …` читает global config и тем самым принимает
   подмену, не локальную 4.3-настройку.
6. `BYPASS numeric-bootstrap-pin: rc=0` —
   `config/harness_pin.json = {"version":7}` принят probe. И-13 требует
   непустую строку `.version`; нарушение формы обязано дать P6 с полем.

Для обязательных классов отрицательных контролей также исполнено:

- ключ с Unicode-гомоглифом `lаnguage` был пойман (`rc=1`, «неизвестный ключ»);
- при `PATH=/nonexistent` (jq недоступен) резолвер завершился неуспешно
  (`rc=1`), то есть отсутствие инструмента не было объявлено успехом.

## Вердикт

**FAIL.** Нужны правки автора в механизмах и расширение батареи отдельными
клетками для каждого приведённого обхода; особенно для вложенных `defaults.*`,
выхода `profilePath` из корня, локальности 4.3, пустой секции G1 и типов/пустых
значений профиля. Этот вердикт не меняет frozen-контракт.
