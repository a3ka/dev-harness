## Б5 (БЛОКЕР) — `.git/index` не входит ни в porcelain-манифест, ни в dot-git-обход: `assume-unchanged` даёт ложное «чисто» на живой правке tracked-файла

Механика. `emit_manifest` судит СОДЕРЖИМОЕ только тех путей, которые вернул
`git status --porcelain`. `emit_dotgit_manifest` покрывает `.git/hooks/**`,
`.git/info/**` и `.git/config` — и НЕ покрывает `.git/index`. Бит
`assume-unchanged` (равно `skip-worktree`) в индексе заставляет git не
сравнивать рабочий файл с индексом: porcelain становится пуст, хотя байты
файла в дереве изменены. Ни одна из двух половин манифеста этого не видит,
и двойное чтение Б4 не помогает — состояние СТАБИЛЬНО, гонки нет вовсе.

Это ровно тот класс, который уже признан предметом 024 блокером Б1 ревью v1
(«правка `.git/info/exclude` ослепляет источник манифеста»): здесь ослепление
идёт через штатный git-плюмбинг `git update-index --assume-unchanged` — одну
обычную команду, без враждебного окружения, без подмены PATH, без BASH_ENV
(кап тредмилла не задет), без симлинков и без гонок. Демаркация не укрывает:
путь НЕ ignored (porcelain показывает его в позитивном контроле), коммита нет,
история не трогается — судится ровно «состояние рабочего дерева», и оно лжёт.

Воспроизведено на ИГРУШЕЧНОМ чекауте:

```text
$ python3 /tmp/dev-harness-verify/k9_blind_porcelain.py
=== A. assume-unchanged blinds porcelain, index is not in manifest ===
snapshot: (0, '')
positive-control modify: (1, 'ОТКАЗ: основной чекаут загрязнён: tracked.txt')
restored check: (0, 'основной чекаут чист')
attack assume-unchanged: porcelain='' check-rc=0 out='основной чекаут чист' disk='LEAKED BY SUBAGENT'
FINDING A: tracked-file modification invisible via .git/index assume-unchanged
```

И на САМОМ судимом клоне (реальный чекаут dev-harness, tracked `ROADMAP.md`):

```text
$ python3 /tmp/dev-harness-verify/k9_final.py
=== J. assume-unchanged against the REAL judged clone ===
clone porcelain before: ''
snapshot: (0, '')
positive-control (plain tracked edit): (1, 'ОТКАЗ: основной чекаут загрязнён: ROADMAP.md')
restored: (0, 'основной чекаут чист')
ATTACK assume-unchanged: porcelain='' rc=0 out='основной чекаут чист' disk_differs=True

```

`disk_differs=True` замерено ПОСЛЕ завершения сверки: детектор сказал «основной
чекаут чист», а в дереве лежит tracked-файл с дописанной строкой утечки. Клон
возвращён в исходное состояние тем же прогоном (`ls-files -v` → `H`, porcelain
пуст, финальная сверка rc=0) — судимое дерево не испорчено.

Направление фикса — за автором; отмечу лишь, что побайтовый хеш `.git/index`
непригоден (индекс легитимно переписывается самим `git status` при refresh
stat-кэша), а наблюдаемая величина того же смысла — флаги
`git ls-files -v` (`H`/`h`/`S`), они меняются РОВНО при постановке/снятии бита.

  Направление безопасное (ложное «загрязнён», не ложное «чисто»), поэтому не
  блокер; но имя отказа вводит в заблуждение — чистка объявлена загрязнением.
* **Н-2 (слепое пятно глоба).** `for entry in "$dir"/*` не матчит dot-файлы:
  мутация `.git/info/.hidden-rules` даёт `rc=0 'основной чекаут чист'`.
  Эксплуатируемости не нашёл (git читает `.git/info/exclude` по имени, а
  перенаправление через `core.excludesFile` ловится хешем `.git/config`) —
  поэтому наблюдение, не блокер. Заткнуть — одна строка (`shopt -s dotglob`
  локально в обходе) и одно ворот-условие.
* **Н-3 (живучесть, не безопасность).** Если `.git/info/exclude` — симлинк на
  FIFO, `git status` блокируется на открытии, и детектор вместе с ним:
  `git status with fifo exclude: <git status TIMEOUT>`, `snapshot (10s cap):
  TIMEOUT`. Ложного «чисто» нет, но у сверки нет таймаута — церемония повиснет
  без rc. Тот же класс, что «нет rc» — назван, адрес на усмотрение автора.
