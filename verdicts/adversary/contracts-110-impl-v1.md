## 4. Советы (не блокируют)

- A5: принимаемый HEAD не фиксируется в начале. Если e2e делает коммит, тег уходит на новый
  коммит (HEAD до вызова 13c8f737, peeled тега c5a868a0, ветка main сдвинулась). Источники,
  прочитанные после e2e (review/otkat), тоже берутся с нового HEAD. Модель угроз исключает
  злонамеренный манифест, но лечится дёшево: снять sha в начале, читать `<sha>:path`, ставить
  `git tag -a … <sha>`.
- A6: статус берётся из первой строки `^status:` в любом месте файла. Находка без status во
  frontmatter (`Status: ready`) с цитатой `status: done` в теле → rc 0.
- A7: строка закрытия без причины (`sim-a` без TAB) засчитывается как закрытие.
- A8: строки манифеста на `#` молча пропускаются. Это расширение закрытого алфавита И-3, и
  закомментированная `#review` открытой находки → rc 0 (модель делает так же).
- A9: существующий тег `done/waves/3/08` даёт аварию bash (`08: value too great for base`,
  `v: unbound variable`, rc 1) вместо именованного отказа. refs не меняются.
- A10/A11: без jq и при не-git корне — rc 2 (NOT_IMPLEMENTED). У модели при отсутствии jq — rc 1.
  Это смешение «не реализовано» с отказом среды.
- A12: захват `.` проходит проверку «число» и сравнивается строкой → rc 0 (грамматика вне перечня).
- Автор тега в продуктовой двери — `Fixture <fixture@local>`, перенесён из эталона.
  `GIT_CONFIG_GLOBAL/SYSTEM=/dev/null` наследуются командами e2e/NFR (подтверждено `attack3.sh`).
- Н-363: побайтовой копии нет, но это транслитерация эталона — те же сообщения, те же ветви, те же
  regex/awk; отличаются массивы вместо строк и комментарии. Отсюда общие слепые зоны (A1–A9,
  A12 совпадают с моделью). Независимости оракула реализация не добавляет.
