## Четыре повторённые пробы

### 1. Битая ссылка: поведение HEAD исправлено, но не удержано матрицей

На дереве с единственной `roles/dangling.md -> absent.md` настоящий барьер вернул
**1**:

```text
scripts/check_ceilings.sh: line 41: .../roles/dangling.md: No such file or directory
  FAIL персона .../roles/dangling.md: размер нечитаем — битая ссылка или права
  ok   персоны: 1 файл(ов), потолок 51200 байт
превышений/нарушений: 1
```

То есть непосредственный дефект `rc=0` в HEAD действительно исправлен.

Однако построена точная регрессия этого класса: только в копии барьера заменена
ветвь ошибки размера персоны

```bash
size=$(wc -c < "$f" 2>/dev/null) || { bad "персона $f: размер нечитаем — битая ссылка или права"; continue; }
```

на старое успешное значение:

```bash
size=$(wc -c < "$f" 2>/dev/null) || size=0
```

Прямой прогон этой заглушки на той же битой ссылке вернул **0** и напечатал
`потолки в порядке` (перед этим shell сообщил `No such file or directory`). Это
ровно прежняя ошибочная семантика: файл посчитан персоной, но не измерен и не
стал отказом.

Критически, неизменённая проверка её приняла:

```text
$ bash scripts/verify_antiplacebo.sh tmp/adversary004-zakrytie/ignore-unreadable
барьеров: 1 · фикстур: 6 · предъявлено красным повторным прогоном: 6
# код 0
```

Ни одна из шести фикстур не создаёт битую ссылку либо иной нечитаемый файл.
Поэтому антизаглушечная матрица не удерживает находку 1 от возврата. Это не новый
класс: это не закрытая находка круга 1 («нечитаемый размер не может выглядеть
успехом»).
