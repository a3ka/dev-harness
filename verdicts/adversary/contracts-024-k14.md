## Блокер S-symlink-target-row-injection (атака (а): точка вывода МИМО enc_path)

**Причина.** `enc_path` применён к ПОЛЮ ПУТИ, но не к ПОЛЯМ-ЗНАЧЕНИЯМ, которые
сами суть путь. В `emit_dotgit_manifest_walk`:

```
printf 'DOTGIT:SYMLINK:%s\t%s\n'  "$target"   "$(enc_path "${pre}/${entry##*/}")"
printf 'DOTGIT:DANGLING:%s\t%s\n' "$resolved" "$(enc_path "${pre}/${entry##*/}")"
```

`$target` (`readlink`) и `$resolved` (`readlink -f`) идут в манифест СЫРЫМИ.
Цель симлинка — произвольная последовательность байт, LF в ней законен. Значит
ровно тот же контрпример к13 воспроизводится не по имени файла, а по ЦЕЛИ
симлинка: одна строка манифеста разрывается на несколько, и фрагмент становится
самостоятельной строкой, побайтово равной будущей строке РЕАЛЬНОГО носителя.
`root %s` (do_snapshot) — третья некодированная точка; она fail-closed, см. выше.

**Воспроизводимый контрпример** (`/tmp/dev-harness-verify/adversary024k14_symlink_target_injection.sh`,
два запуска подряд — идентичный результат):

```
BASE_FORGED_ROWS=2
LIVE_HOOK=239f59ed55e737c77147cf55ad0c1b030b6d7ee748a7426952f9b852d5a935e5
SYMLINK_TARGET_INJECTION rc=0 output=основной чекаут чист
BYPASS: raw symlink target row replaces deleted carrier row with live nested pre-push row
```

Конструкция, пять шагов:

1. Корневой репозиторий; внутри него неотслеживаемый `nested` — существует В
   БАЗЕ, поэтому его появление позже утечкой не считается.
2. Считается `sha256` будущих байт `nested/.git/hooks/pre-push`.
3. В `.git/hooks/` кладётся симлинк `carrier` с целью
   `carrier\nDOTGIT:<sha>\tnested/.git/hooks/pre-push\nx` (первый LF открывает
   подложную запись, второй закрывает её ДО того, как emit допишет свой `\t` и
   закодированный путь carrier'а). Промежуточные компоненты цели создаются.
4. `--snapshot`: в базе появляются ДВЕ подложные строки
   `DOTGIT:<sha>\tnested/.git/hooks/pre-push` — из SYMLINK-поля и из
   DANGLING-поля (`BASE_FORGED_ROWS=2`).
5. Симлинк удаляется (исчезновение по семантике `comm -23` не краснеет), а в
   `nested/.git/hooks/pre-push` кладутся ровно те байты из шага 2 и ставится
   `+x`. `--check` печатает «основной чекаут чист» и возвращает 0 при ЖИВОМ
   исполняемом hook'е — `LIVE_HOOK` совпадает с подделанным sha.

Два элемента конструкции проверены снятием, и оба несущие: без созданных
промежуточных каталогов цели `readlink -f` отказывает — честный fail-closed
`rc 2` («readlink -f отказал»), обхода нет; без ЗАКРЫВАЮЩЕГО LF
(цель `carrier\nDOTGIT:<sha>\tnested/.git/hooks/pre-push`) подделанная строка
склеивается с хвостом emit'а и база её не содержит — `--check` даёт `rc=1` с
именем `nested/.git/hooks/pre-push`. То есть детектор ловит носитель, когда
подделка не завершена, и именно поэтому завершённая подделка есть обход.

Что это НЕ: не косметика вывода и не форма имени в диагностике. Совпадает
полноценная строка манифеста ДО передачи в `comm`, то есть подделка поглощает
настоящую новую запись — тот же исход, что в к13, тем же механизмом, через
непокрытую точку вывода.

**Направление исправления (форму выбирает architect, Н-39).** Кодировать не
«путь в поле пути», а КАЖДОЕ поле строки манифеста, содержимое которого
приходит извне: `SYMLINK:<target>`, `DANGLING:<resolved>` и `root <канон>`.
Грамматика строки обязана быть однозначной по построению, а не по перечислению
полей, которые кто-то вспомнил: пока хоть одно поле печатается сырым, класс
к13 переезжает в него — к13 был про имя файла, к14 про цель симлинка, третьим
будет любое следующее сырое поле.
