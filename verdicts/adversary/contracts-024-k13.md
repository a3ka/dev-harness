## Блокер S-newline-tab-manifest-key-collision

**Причина.** Манифест остаётся текстом с неэкранированными `\n` в путях и
табуляцией как разделителем. В `emit_*` путь без кодирования кладётся после
`\t`; `manifest()` передаёт строки в line-oriented `sort`; `do_check()` судит
line-oriented `comm -23`. Поэтому один DOTGIT-отпечаток носителя, чей
рекурсивный префикс содержит перевод строки и табуляцию, может материализовать
в baseline самостоятельную строку, идентичную будущей строке другого носителя.
После удаления carrier исчезновение игнорируется по семантике подмножества,
а реальная новая строка уже есть в базе. Результат — rc=0 при живом новом hook.

**Воспроизводимый контрпример**, два запуска подряд дали одинаковое:

```
основной чекаут чист
COLLISION_RESULT snapshot=0 check_rc=0 hash=ba54993a3c18ba5bfa645fb4c4a36abf0ea6b93c437c7baa3130c8d1109ffa0c
BYPASS: newline/tab prefix collision replaces deleted carrier DOTGIT row with live nested pre-push row
```

Минимальная конструкция (скрипт сохранён вне предмета:
`/tmp/dev-harness-verify/adversary024k13_collision.sh`):

1. Создать корневой репозиторий и вложенный репозиторий `nested`.
2. Вычислить SHA-256 будущего `nested/.git/hooks/pre-push`.
3. Создать второй вложенный репозиторий с именем
   `inject\nDOTGIT:<SHA>\tnested` и положить в его `.git/hooks/pre-push`
   carrier-байты. Его DOTGIT-строка после разбиения по newline порождает в
   снимке строку `DOTGIT:<SHA>\tnested/.git/hooks/pre-push`.
4. Снять snapshot. Удалить hook carrier (старый поддельный ряд исчезает, а
   исчезновения намеренно не краснят) и создать в `nested/.git/hooks/pre-push`
   ровно байты из шага 2.
5. `--check` печатает «основной чекаут чист» и возвращает 0, хотя новый
   pre-push существует и содержит исполнимый payload.

Это не коллизия отображения имени в диагностике: совпадает полноценная строка
`DOTGIT:<sha>\t<путь>` до передачи в `comm`, поэтому новая запись буквально
поглощается baseline. Тот же неканонический line protocol затрагивает все три
ноги, поскольку TRACKED, UNTRACKED и DOTGIT объединяются и сортируются одной
потоковой текстовой грамматикой.

**Требуемое направление исправления.** Сделать представление манифеста
однозначным для каждого байтового имени (например, NUL-фрейминг во всём пути
producer → sort → delta либо каноническое обратимое кодирование имени до
сборки строки) и проверять multiset именно этих неразделимых записей. Нельзя
лечить только DOTGIT: carrier может быть сформирован любой из трёх ног.
Привязка стабов к коду и выбор формы регрессии — задача architect по Н-39.
