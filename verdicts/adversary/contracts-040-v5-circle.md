# Контракт 040 — adversary circle v5

Проверен `d167040` (v5). Главный известный обход через экспортированную функцию `git` действительно закрыт: `unset -f dirname git awk sed grep sort tr wc mktemp mkdir cp rm mv comm` срабатывает до первого внешнего вызова. Но эта строка разрешается Bash как голое имя `unset`; импортированная функция с этим именем имеет приоритет над builtin `unset`. Поэтому очистка таблицы функций вновь отключается без записи в `/usr/bin:/bin`, root-привилегий либо подмены `/usr/bin/git`.

## Новая in-scope находка: функция `unset` нейтрализует v5-фикс

Независимый toy: `/tmp/dev-harness-verify/adversary040v5/unset-neutralization.sh`. Он создаёт честный минимальный репозиторий через `fixtures/check_zones/_repo.sh`: замороженный контракт объявляет `agent-x: scripts/`. До запуска барьера toy экспортирует ровно две функции:

```bash
unset() {
  if [ "${1:-}" = '-f' ]; then return 0; fi
  builtin unset "$@"
}

git() {
  # Делегирует настоящему git всё, кроме --no-walk.
  # Для batched author lookup сохраняет полный NUL-поток SHA,
  # но заменяет каждого автора на не объявленный в зоне `unannounced`.
}
export -f unset git
```

Это точечная нейтрализация: первый вызов в шапке (`unset GIT_DIR …`) всё ещё исполняет `builtin unset`, так что git-окружение очищено; только `unset -f …` становится успешным no-op. Далее живой `git`-функции нечего мешать. Положительный контроль — пустое честное окно — даёт rc=0. Затем `agent-x` коммитит `plans/bypassed-via-unset.md`, то есть вне `scripts/`; барьер тоже даёт **rc=0**:

```text
unset-neutralization: false green reproduced (clean rc=0; violation rc=0)
```

Тем самым проверяемое нарушение исчезает ровно от отключения одной защиты. Это категория арбитража 040-II (i): обход не требует записи в доверенный PATH, root или замены системного git. Это не повтор функции-тени на одном из четырнадцати уже очищаемых имён: атакуемое имя — `unset`, механизм, которым очищается весь список.

## Положительные контроли и прочие обязательные классы

Отдельный, не скопированный с фикстуры toy `/tmp/dev-harness-verify/adversary040v5/toy.sh` проверил закрываемую v5 ветвь напрямую. Экспортированная функция `git` возвращала синтаксически полный NUL-поток с константным автором `masked-author` для `--no-walk`, но после `unset -f` вне-зонный коммит получил rc=1 с «коммит вне зоны»; чистый вход до него был зелёным. Тот же toy подтвердил, что пустой честный вход с унаследованным `PATH=/nowhere` не даёт ложного красного: сам барьер выставляет доверенный PATH и завершает rc=0.

```text
git-function-shadow: closed (positive control rc=0; violation rc=1)
empty-inherited-PATH: honest rc=0
```

Также воспроизведён явно названный в шапке остаток `env` (не причина решения по главному предмету): для `--no-tags` клона честный запуск правильно красен по «реестр заморозок» (rc=1), а экспортированная функция `env() { return 0; }` делает оба registry-read пустыми, но успешными. Локальных frozen-тегов не остаётся, зоны становятся пустыми, и барьер отвечает rc=0:

```text
env-function-shadow: residual bypass reproduced (honest rc=1; poisoned rc=0)
```

Это подтверждает уже честно описанный остаток сорсимой библиотеки; согласно назначенной границе он сам по себе не меняет вердикт о 14-именном списке. Решение `reject` вызвано отдельной, неописанной возможностью отключить именно v5 `unset -f`.
