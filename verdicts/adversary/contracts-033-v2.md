## К1 закрыт по фактической семантике, но не по достаточности приёмки

Проверены обе записанные в k1 пустые сводки ровно предикатом v2 `sed …; test -n "$n" && test "$n" -gt 0`:

Честный живой запуск `bash scripts/check_zones.sh .` вернул rc 0 с итогом:

Формулировка v2 в части фактической семантики корректна: пустой диапазон сам по себе не есть зонное нарушение, поэтому `check_zones` возвращает 0. Изменение v1→v2 затрагивает приёмку, ссылки `/1→/2` и пояснения; union-инвариант не удалён. В реальном суде остаётся union-фильтр:

```sh
awk -F'\t' -v a="$an" '$1 == a { print $2 }' "$TMP/zones_scoped" | sort -u > "$TMP/mine"
```

## Блокер 1 — обязательный scoped-прогон v2 не зелёный

Изолированный запуск с требуемой явной scratch-изоляцией:

```sh
VERIFY_ANTIPLACEBO_SCRATCH=/tmp/dev-harness-verify/adv-033-k2/antiplacebo \
  bash scripts/verify_antiplacebo.sh --scope check_zones
```

вернул **rc 1**, хотя все 20 check_zones-фикстур действительно предъявили требуемые зелёные контроли и красные повторы:

```text
барьеров: 1 · фикстур: 20 · предъявлено красным повторным прогоном: 20
расхождений: 2
```

Причины двух отказов не относятся к `check_zones`, но глобально проверяются до scoped-фильтра:

```text
FAIL fixtures/qa_kanal_xd: фикстура без барьера — она ничего не держит
FAIL fixtures/workshop_inventory: фикстура без барьера — она ничего не держит
```

Следовательно, утверждение v2 «`bash scripts/verify_antiplacebo.sh --scope check_zones` → rc 0» ложно на предъявленном `da3f01e`. Факт 20/20 не заменяет требуемый rc 0: сам раннер завершился красным.

**обход = добавить вне scope каталог `fixtures/<key>/` без классифицированного barrier.** Scoped-прогон 033 становится красным до/вне предмета, поэтому он не является исполнимым зелёным критерием именно этой формой.

## Блокер 2 — гвард-1 принимает подставной счётчик

Построена отдельная обманная копия клона; основной репозиторий и исходный изолированный клон не менялись. В копии сразу после сохранённой шапки `scripts/check_zones.sh` добавлена только ветка:

```sh
if [ "${1:-}" = "." ]; then
  printf 'замороженных контрактов: 31 · объявленных авторов: 1 · коммитов в диапазонах: 0 · проверено по зонам: 1\n' >&2
  exit 0
fi
```

Это неверная реализация: на приёмочном живом аргументе `.` она не читает git, зоны, заморозки или диапазон; печатает константу с внутренне противоречивыми `коммитов в диапазонах: 0` и `проверено по зонам: 1`.

Тем не менее в этой копии обязательные проверки проходят:

```text
bash scripts/check_zones.sh .                       → rc 0
Непустота-выборки-033-проверка                      → rc 0, N=1
Заморозка-033-проверка                              → rc 0
Закрытие-Н-100-проверка до done                     → rc 1
```

Сохранённая шапка оставляет скрипт классифицированным барьером. Затем выполнен scoped anti-placebo на этой же обманной копии с отдельным `VERIFY_ANTIPLACEBO_SCRATCH`. Все собственно check_zones сценарии остались различающими:

```text
check_zones/case_union_zon_vseh_zamorozok.sh: зелёный контроль есть,
повторный прогон красный кодом 1 — «коммит вне зоны»

барьеров: 1 · фикстур: 20 · предъявлено красным повторным прогоном: 20
```

Они не ловят подмену, потому что toy-репозитории вызывают барьер с абсолютным корнем `$R`, а ложная ветка нацелена ровно на приёмочный вызов `.`. Полный scoped rc остаётся 1 только по уже названным двум посторонним fixture-каталогам, не по одному из 20 сценариев и не по этой подмене.

**обход = подставной источник печатает константный `N>0` только для `bash scripts/check_zones.sh .`.** Гвард-1 сверяет лишь регулярное выражение и числовой порог; он не связывает счётчик с фактическим вычислением, не проверяет согласованность со сводкой и не удостоверяет неизменность/происхождение исполняемого `scripts/check_zones.sh`. Поэтому требование «прогон 2 — НАСТОЯЩИЙ check_zones на живом дереве» текущей приёмкой не обеспечено.

## Удержанные классы

## Решение
