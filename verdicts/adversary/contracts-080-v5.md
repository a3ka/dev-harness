## Блокер I1: `--as` пропускает Unicode format character U+200B

В `scripts/orch_restart.sh` грамматика `--as` после канарейки `grep -P` проверяет только:

```bash
'\p{Z}|\p{Cc}'
```

U+200B ZERO WIDTH SPACE относится к Unicode general category `Cf`, а не `Z` и не `Cc`. Живая проверка используемого PCRE дала `grep -P '\p{Z}|\p{Cc}'` rc 1 и `grep -P '\p{Cf}'` rc 0 для единственного U+200B.

Одноразовый toy-репозиторий построен так же, как честные клетки двери: `HEAD == origin/main`, porcelain чист, `HANDOFF.md` закоммичен автором `evil<U+200B>identity`, стартовый след на час старше коммита, снимок `check_no_leak` зелёный, file-config не содержит `user.name`, `ORCH_SESS_DIR` не существует. Реальный субъект вызван без env identity:

```text
bash scripts/orch_restart.sh --as 'evil<U+200B>identity'
zwsp_as rc=0 marker=yes stderr= stdout=ПЕРЕЗАПУСК: маркер поставлен
```

То есть грамматически запрещённая format-identity проходит все ноги и ставит маркер. Это не новый класс: v3 I2 требовал исключить **все Unicode whitespace/control/format characters**, а v4 подтвердил именно Unicode-format/space домен. Текущая проверка регрессировала при замене прежнего `\p{Cf}` на `\p{Cc}`; комментарий субъекта ошибочно утверждает, что `Cc` покрывает zero-width space.

**Требуемая правка:** вернуть в предикат форматные code point (`\p{Z}|\p{Cc}|\p{Cf}` либо эквивалент) и сохранить fail-closed семантику канарейки. Добавить честную клетку `--as` с U+200B, требующую rc 1, pinned `identity двери не определена` и отсутствие маркера. Корректная Unicode identity без whitespace/control/format остаётся позитивным контролем v3.
