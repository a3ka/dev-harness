## Блокер Б7б: «первые три цифры» шире грамматики `contracts/<M>-*`

Контракт разрешает fallback только для `contracts/<M>-*`: после номера обязателен
дефис. В `priznanie_chernovika_7b` (строки 1406–1412) проверяются лишь первый сегмент
`contracts` и три первых цифровых байта basename:

```sh
base="${path##*/}"
head3="${base:0:3}"
case "$head3" in [0-9][0-9][0-9]) path_m="$head3" ;; esac
```

Проверки четвёртого байта `-` нет. Поэтому любой basename с цифровым префиксом,
включая `123not-a-draft.md`, `123_not_a_draft.md` и просто `123`, признаётся как
контракт 123 при живом теге `id/CONTRACT/123`, хотя все три пути лежат вне объявленных
зон и НЕ соответствуют carve-out.

Живой repro построил строгий toy-реестр: единственная зона architect — точный файл
`contracts/001-x.md`, так что тестовый путь ничем не покрыт. После снимка в main
закоммичен от `architect` файл `contracts/123not-a-draft.md`; на этот уже слитый
коммит указывает `id/CONTRACT/123`, origin/main синхронизирован. Перед переснятием
`--check` честно красный. Тем не менее настоящая дверь дважды приняла НЕ-черновик и
стерла красноту:

```text
$ bash .adversary-scratch/draft-grammar-repro.sh 123not-a-draft.md
path=contracts/123not-a-draft.md
check_before_rc=1
retake_rc=0
check_after_rc=0
базлайн переснят: bulk-дельта contracts/123not-a-draft.md (автор architect, коммит 815e632…)
базлайн переснят: bulk-дельта — путей 1, незакоммиченного/неслитого 0

$ bash .adversary-scratch/draft-grammar-repro.sh 123_not_a_draft.md
path=contracts/123_not_a_draft.md
check_before_rc=1
retake_rc=0
check_after_rc=0
базлайн переснят: bulk-дельта contracts/123_not_a_draft.md (автор architect, коммит a574df8…)
```

Отдельно форма без суффикса `contracts/123` дала тот же `1 → 0 → 0`. Это не
константа и не пустая выборка: каждый запуск создаёт независимый репозиторий, новый
commit и новую красную дельту. Резерв номера может быть штатным; обход использует
именно отсутствующий в признании обязательный дефис, а не подлинность identity,
оставленную контрактом cognitive-only.

Нужная правка автора — сузить предикат до буквальной грамматики `contracts/<M>-*`
(после распознанного трёхцифрового `path_m` потребовать `base` вида `"$path_m"-*`)
и добавить красные варианты без дефиса. Тогда каждый такой путь должен дать
существующий отказ «путь … не покрыт ни одной зоной», не менять снимок и оставить
`--check` красным.

## Дополнительная дыра предиката: рука А обходит post-freeze запрет

Это второй предметный дефект того же места, хотя его эксплуатация требует
переназначить локальный `id/CONTRACT`-тег — класс, чей провенанс 044 ссылает к 023.
Контракт всё равно формулирует для резервных итераций: «ДО заморозки признаются;
ПОСЛЕ заморозки — НЕТ: путь судится зонами». Код сначала выполняет руку А и немедленно
`return 0`; проверка `frozen/contracts/<M>/*` существует только в руке Б.

В live toy заморожен контракт 123 с зоной ровно `contracts/123-original.md`. После
этого от `architect` добавлен незонированный `contracts/123-evil.md`; `id/CONTRACT/123`
переназначен на его commit, сам commit пушен в origin/main. Файл должен идти зонным
судом и отказать, но реальная реализация два раза дала:

```text
check_before_rc=1
retake_rc=0
check_after_rc=0
базлайн переснят: bulk-дельта contracts/123-evil.md (автор architect, коммит 4e37f25…)
```

Чтобы семантика «после freeze — нет» была реальной для обеих рук, проверка frozen-тегов
должна идти до выбора руки А/Б (либо рука А обязана делать ту же проверку). Само
отсутствие provenance проверки тега остаётся отдельной, явно названной демаркацией 023;
оно не оправдывает обход самостоятельного post-freeze условия 044.

## Обязательные обманные пробы

| Класс | Живая проба и результат |
|---|---|
| Позитивный контроль честной реализации | `bash fixtures/check_no_leak/red_bulk_peresnjatie_bazlajna.sh` запущен дважды: оба раза `б0..б10, бб1..бб6` зелёные, rc 0. Набор не вечно-красный. |
| Нейтрализация именно Б7б | Удаление состояния «валидный reserve для цифрового префикса» соответствует существующей канарейке бб4: неподтверждённый `contracts/<NNN>-*` даёт именованный отказ, снимок не меняется, check остаётся красным. В repro выше добавление тега нейтрализует только ошибочную fallback-ветвь и приводит к ложному success. |
| Отказ 127, выглядящий успехом | Новый bulk-код зовёт raw `awk`/`sort`, хотя шапка детектора требует pin каждой внешней утилиты. В отдельном toy подменён только `awk` для извлечения delta-path на `exit 127`; zone reader и остальные утилиты остались настоящими. Настоящая дверь дважды напечатала `базлайн переснят: bulk-дельта — путей 0` с rc 0 и сделала `check_after_rc=0`, хотя до вызова был незонированный `docs/escape.md` (`check_before_rc=1`). Ошибка producer замаскирована пустым `delta_paths`. |
| Инструмент мимо PATH / правильный ответ не на тот вопрос | Другой stub `awk` оставил `zones_load` настоящим, но подменил 044-извлечение пути на `docs/escape.md` и покрытие на `architect\tdocs/`. На незонированной, но слитой дельте `docs/escape.md`: `check_before_rc=1`, `retake_rc=0`, `check_after_rc=0`. Дверь проверила результат подменённого парсера, а не реестр/дельту. |
| Пустой вход | Штатная б10 в обоих зелёных прогонах возвращает rc 1 «дельта пуста — нечего переснимать»; нормальная пустая дельта не признана успехом. |

Последние две PATH-пробы затрагивают явно названный 044 TCB («подмена локального git или
PATH»), поэтому сами по себе не расширяют защищаемую модель 044. Они зафиксированы,
поскольку обязательная попытка `127` обнаружила также внутреннее противоречие с шапкой
`check_no_leak.sh`: новые raw `awk`/`sort` не пинятся, а ошибка `awk` превращается в
успешное переснятие нулевого числа путей. Главный блокер выше не зависит от PATH,
отказа утилиты или пустой дельты.

До исправления Б7б дверь позволяет снять реальную красную дельту без честного
вердиктного основания: достаточно взять действующий резерв номера и назвать
незонированный файл с теми же тремя начальными цифрами, но без обязательного дефиса.
