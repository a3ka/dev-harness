## Блокер B1 — `zona` принимает выданное воротами задание вне полной грамматики

И-7 контракта 133 требует, чтобы `zona` принимала **только** задание грамматики
ворот: заголовок, МОДЕЛЬ, РЕПОЗИТОРИЙ, БАЗА, КОНТРАКТ ЭКРАНА, КАДРЫ, МАКЕТЫ,
UI-ЗОНА, СВЕРКА и ЗАДАЧА. В `scripts/dovodka_ui.sh:180-205`
`zadanie_chitaem` не распознаёт конечную грамматику и не проверяет кратность либо
порядок полей. Он лишь извлекает несколько строк; в частности, последнее
`БАЗА:` перезаписывает предыдущее. При этом `cmd_zadanie` без экранирования
вставляет произвольный `--kadry` в документ (`:245`).

Наблюдаемый контрпример построен в чистом `mktemp`-мире: продукт с
`mobile/src/`, замороженный harness-тег `frozen/contracts/132/1`, красная
строка KADR и корректные vision/omp/overlay. В `zadanie` передан допустимый
для shell путь кадров со значением

```
<tmp>/kadry\nБАЗА: <sha базового HEAD>
```

После честного `zadanie` сам выданный файл содержит две строки `БАЗА:`
(`Baza-lines=2`), то есть не является заданием закрытой грамматики. Затем
одна закоммиченная правка `mobile/src/OnlyUi.tsx` и вызов настоящего `zona`
по этому же файлу дали:

```
DOVODKA: задание <tmp>/zadanie.md; красных кадров 1
ЗОНА: чисто (путей 1)
Baza-lines=2
```

Это не подмена `refs`: refs были созданы самим `zadanie` на байты именно
этого файла. Следовательно, получено зелёное принятие задачи с неоднозначной
БАЗОЙ; байтовая привязка refs не заменяет синтаксическую проверку входного
задания. Батарея всегда передаёт обычные однострочные `kadry` из
`zadanie_lines`, поэтому не покрывает этот вход.

Нужна правка автора: закрыть алфавит значений, которые сериализуются как
одна строка задания (минимум запретить CR/LF), и сделать
`zadanie_chitaem` конечным автоматом полной грамматики с ровно одним полем
каждой обязательной секции; добавить клетку, где newline-инъекция в
`--kadry` или `--makety` отвергается и задание не выдаётся.
