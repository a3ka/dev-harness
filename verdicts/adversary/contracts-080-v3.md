## Блокеры

### I1. Свежий скрытый журнал субагента обходится glob-ом

Инвариант 3 требует отказа при **любом** свежем субагентском `.jsonl` в
каталоге текущей сессии. В `scripts/lib_session.sh` перечисление построено
как:

```bash
for f in "$sess_dir"/*.jsonl; do
```

Этот glob не включает имена, начинающиеся с точки. В конформном toy-мире
двери с чистыми остальными ногами, `GIT_AUTHOR_NAME=architect` и свежим
`ORCH_SESS_DIR/.LiveAgent.jsonl` реальный `scripts/orch_restart.sh` выдал:

```text
hidden_live_agent rc=0 marker=yes stderr=
```

То есть живой субагент не перечислен, отказ `живые субагенты: …` не
сработал и маркер поставлен. В ветке жёсткого `orch-peak` используется та
же функция (либо идентичный fallback), поэтому та же дырка относится и к
polling до `ORCH_HARD_GRACE`.

Батарея предъявляет только `LiveAgent.jsonl`; скрытое имя в ней отсутствует,
поэтому 24/24 остаётся зелёным против этого обхода.

**Требуемая правка:** перечислять все непосредственные файлы с суффиксом
`.jsonl`, включая dotfiles, не меняя правило свежести и сортировку имён;
убрать дублирующий fallback либо удерживать его тем же общим источником.
Добавить честную клетку двери и поведенческую hard-клетку с свежим
`.LiveAgent.jsonl`: обе обязаны наблюдать ожидание/отказ и отсутствие
маркера до нормального исхода.

### I2. `--as` отвергает допустимое печатное Unicode-имя

Инвариант 1 разрешает одно непустое значение `--as` из печатных символов
без whitespace/control. Кириллическое `архитектор` — печатное Unicode-имя,
не содержит ни whitespace, ни control и обязано быть допустимым.

Toy-репозиторий был создан с последним коммитом `HANDOFF.md` от того же
автора `архитектор`; остальные ноги зелёные, след старше этого коммита.
Запуск реального субъекта как `bash scripts/orch_restart.sh --as
архитектор` вернул:

```text
as_cyrillic rc=1 marker=no
stderr=identity двери не определена: ни env GIT_AUTHOR_NAME/GIT_COMMITTER_NAME, ни --as
```

Отказ происходит в грамматической проверке `case "$AS_VAL" in
*[[:space:][:cntrl:]]*)` и превращает допустимое Unicode-имя в ошибку.
Напротив, non-breaking space и zero-width space были отвергнуты, как и
должны быть; склеенная форма `--as=architect` также отказана. Значит это
не отсутствие toy-репозитория и не маскировка иной ногой.

Батарея содержит только ASCII `architect` и запрещённые ASCII-пробелы,
поэтому не ловит отказ валидной ветки.

**Требуемая правка:** определить грамматику по Unicode-категориям, а не
локалезависимому POSIX-классу байтов: принимать печатные Unicode code point,
исключая все Unicode whitespace/control/format characters. Добавить
позитивную честную клетку `--as архитектор` (rc 0, маркер, «ПЕРЕЗАПУСК») и
негативные Unicode whitespace/control-клетки.

### I3. Неудачный обязательный отчёт фиксирует `hard` и блокирует все повторы

В hard-ветке `orch-peak` записывает `$STATE/ctx-$sess = hard` **до**
`wait_live_agents`, `wait_saved` и атомарной записи отчёта, а следующий
запуск безусловно делает:

```bash
[ "$(cat "$st" 2>/dev/null)" = hard ] && exit 0
```

В мире `ORCH_PEAK_TEST` с usage 600000, свежим `Live.jsonl`,
`ORCH_HARD_GRACE=1`, `ORCH_HARD_POLL=1` и `$REPORT`, который сначала был
каталогом, первый запуск истёк и не поставил маркер (отчёт недоступен), но
оставил state:

```text
peak_report_failure_first rc=0 marker=no state=hard
```

После удаления каталога `$REPORT` (путь снова годен для атомарного отчёта)
второй запуск на том же свежем session journal не сделал ни polling, ни
повторной попытки отчёта/маркера:

```text
peak_report_failure_retry rc=0 marker=no report=no state=hard
```

Это превращает временную ошибку обязательного следа в бессрочный обход
жёсткого перезапуска: субагент остаётся свежим, таймер идёт, но маркер уже
никогда не будет поставлен для этой сессии. Клетка г8 проверяет только
первый успешный путь; сценарий нейтрализации отчёта с последующим
восстановлением пути отсутствует.

**Требуемая правка:** записывать `hard` только после успешной постановки
маркера либо хранить отдельное состояние «в полёте» и очищать/повторять его
после любой неудачи отчёта или маркера. Добавить поведенческую клетку:
первый `ctx` с недоступным `$REPORT` не ставит маркер; после восстановления
пути второй `ctx` на том же `sess` вновь выполняет polling и ставит маркер с
строкой `живые субагенты погибнут: Live`.
