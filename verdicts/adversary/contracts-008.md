## Дыра 1 — `check_contract_ready` распознаёт игрушки вместо контракта

Предъявленный стаб `scripts/check_contract_ready.sh` сохранял шапку `НЕ БАРЬЕР`, читал только `$1/contract.md` и делал следующее:

```text
если заголовок равен «Тестовый контракт (без зон)»       → stderr «ОТКАЗ зон», rc=1
если заголовок равен «Тестовый контракт (зелёная проба)» → stderr «ОТКАЗ проб», rc=1
если заголовок равен «…рассогласованный счёт»            → stderr «ОТКАЗ счёт», rc=1
если заголовок равен «…непройденный арбитраж»            → stderr «ОТКАЗ арбитраж», rc=1
иначе                                                     → stdout «OK», rc=0
```

Он не проверяет ни существование/исполняемость/rc пробы, ни число `case_*.sh`, ни файл и титул арбитража; это диспетчер по пяти известным текстам фикстур.

**Прогон атаки (в клоне):**

```text

  ok   (зоны) …
  ok   (проба) …
  ok   (счёт) …
  ok   (арбитраж) …
  ok   (готов) …

$ bash scripts/verify_antiplacebo.sh --scope check_check_contract_ready
  ok   check_check_contract_ready/case_gotov_strict.sh: зелёный контроль есть, повторный прогон красный …
  ok   check_check_contract_ready/case_zony_lax.sh: зелёный контроль есть, повторный прогон красный …
```

**Различающие входы и наблюдаемая ветвь (Н-39):**

1. `ЗОНА architect: scripts/` + `счёт: 1 фикстур в fixtures/empty/` (в каталоге ноль файлов). Стаб дал `OK`, rc=0; честный предмет дал `ОТКАЗ счёт: объявлено 1 … фактически 0`, rc=1. Дефект наблюдаем в ветви **счёт**.
2. `ЗОНА architect: scripts/` + `- \`bash scripts/not-installed.sh\` → 0`. Это требуемый класс «инструмент мимо PATH/отказ 127»: файла нет. Стаб дал `OK`, rc=0; честный предмет дал `ОТКАЗ проб: … файл …/not-installed.sh не существует`, rc=1. Дефект наблюдаем в ветви **проба**.

Следовательно, маркеры `OK` и имена причин удерживают только постоянные стабы, а не реализацию, подогнанную под конечное множество известных toy-входов.
