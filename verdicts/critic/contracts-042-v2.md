БЛОКИРУЕТ contracts/042-excuse-for-otstavshij-roditel.md:118 — успешный непустой
`git merge-base P1 P2` не доказывает единственность базы. Команда без `--all`
выбирает одну из нескольких; критерий не предъявляет обещанный в :103 и :120–121
fail-closed на неоднозначности.
ОБХОД: построить criss-cross DAG из основания O с живым p. A — ребёнок O,
удаляет p с ALLOW; B — другой ребёнок O, дерево как у O, дата новее A.
P1 имеет родителей A,B и дерево с восстановленным p; P2 — родителей B,A и
дерево A без p. M имеет родителей P1,P2, дерево без p и НЕ несёт ALLOW.
`git merge-base --all P1 P2` возвращает ДВЕ базы, B и A; та же команда без
`--all` успешно возвращает B. Поэтому предикат v2 считает M артефактом,
пропускает также P2 и использует разрешение A после восстановления в P1.
Наблюдено rc=0 у v2 и rc=1 у `625e61e^`. Независимая проверка
`git merge-tree --write-tree P1 P2` вернула rc=0 и дерево, где p ПРИСУТСТВУЕТ:
повторное удаление в M действительно не наследуется бесконфликтным слиянием.
Все предъявленные R1–R6 этот новый класс оставляют неразличённым.

Точные вершины criss-cross-эксперимента:

```text

B  = 9e27907aaadfd95482617fd79d66351fd57fdb19  (p присутствует)
P1 = 0bdb106b33a3e918e81e646ad4f44f0585092471  (родители A,B; p присутствует)
P2 = 8214b09326d6680f21870cd51d96a290464f060f  (родители B,A; p отсутствует)
M  = 9d461cdf5aaef27234f89ce299ae8c7b0068ce61  (родители P1,P2; p отсутствует)
```

Коммиты P1/P2/M созданы `git commit-tree <дерево> -p <первый> -p <второй> -m ...`:
проверяется настоящий Git DAG, не мок `git merge-base`. Автоматическое дерево
слияния проверено отдельной командой Git, а не тем же предикатом барьера.
