### Б4 — новый дефект: разрешённая техника теряет алиасы одного blob

БЛОКИРУЕТ contracts/040-batching-git-vyzovov.md:104 — извлечение множества когда-либо существовавших путей из имён `rev-list --objects` не сохраняет объявленную семантику объединения достижимых деревьев; обе формы, названные эквивалентно корректными в строках 130–136, теряют дополнительные имена одного объекта.
ОБХОД: заменить оба per-commit цикла двумя разрешёнными `git rev-list HEAD --objects --full-history -- <pathspec>`; отфильтровать blob-объекты batched `git cat-file --batch-check`, извлечь пути из вывода. Полученная диагностическая реализация даёт **Р2 rc=0, 17 <= 30**, все шаги ours-пробы зелёные, **Р4 rc=0 (20/20), Р6 rc=0**. Но на истории «создать `plans/a.md` и `plans/b.md` с одинаковыми байтами; следующим коммитом удалить только b без ALLOW и без добавлений» исходный барьер даёт rc=1 с `существовал и на HEAD его нет: plans/b.md`, а разрешённая контрактом замена даёт **rc=0**, `исчезло: 0`.

Здесь нет законного переноса 039: в удаляющем коммите нет A(q), второй
носитель появился раньше. Контракт 040 обещает не менять решающую семантику,
но отсутствующий путь вообще не попадает в `existed.raw`, поэтому до
неизменённых `excuse_for`/`moved_for` проверка не доходит.

Независимый оракул — `git ls-tree -r --name-only HEAD^ -- plans/` — выводит
**оба** пути. Обе предложенные контрактом формы `rev-list --objects`
выводят только `plans/a.md`, хотя посещают оба коммита. Это иной механизм,
чем упрощение истории на `-s ours`; `--full-history` его не исправляет.
На Git 2.55.0 это прожито, а документация `git-rev-list`, `--object-names`,
прямо предупреждает: «if an object would appear multiple times with
different names, only one name is shown»
(<https://git-scm.com/docs/git-rev-list#Documentation/git-rev-list.txt---object-names>).

Точные два заменяющих источника диагностического мутанта:

```bash
git rev-list HEAD --objects --full-history -- roles/ |
  git cat-file --batch-check='%(objecttype) %(objectname) %(rest)' |
  awk '$1 == "blob" && $3 ~ /\.md$/ {print $2 "\t" $3}' > "$TMP/roleblobs"

git rev-list HEAD --objects --full-history -- "${prefixes[@]}" |
  git cat-file --batch-check='%(objecttype) %(objectname) %(rest)' |
  awk '$1 == "blob" {sub(/^[^ ]+ [^ ]+ /, ""); print}' > "$TMP/existed.raw"
```

Это новый дефект предмета/критерия, не повтор находок 1–4 v1. Нужен красный
вход с несколькими защищёнными путями одного blob и конструкция, сохраняющая
все пары путь/объект, а не только имена из перечисления уникальных объектов.
Конкретную конструкцию выбирает автор; критик реализацию не вносит.
