Предмет спора: считаются ли закрытыми повторные находки круга 2 о доказуемости критериев, если пункты 4 и 5 по-прежнему требуют чтения вывода, а перечисленные тринадцать фикстур по-прежнему допускают частичную реализацию явно заданных ветвей отказа.

## 1. Критерий готовности слабее предмета? — да, блокирует

План задаёт для `freeze_contract.sh` отдельные обязательные отказы: незакоммиченный блоб, пустую причину, отсутствующий вердикт, вердикт не `accept` и неверную грамматику пути (`plans/007-reglament-vorkflou.md:100-113`). Приёмка требует только три красные фикстуры этого барьера — неверное имя, отсутствие вердикта и вердикт не `accept` (`plans/007-reglament-vorkflou.md:433-449`). Дерево без проверок незакоммиченного блоба и пустой причины удовлетворяет всем названным фикстурам и зелёным прогонам. Фраза о нескольких ветвях не превращает неназванные ветви в обязательные проверки. Это та же причина `FAIL` круга 2, вопрос 1; поэтому назван арбитр.

## 2. Каждый пункт готовности доказуем командой с кодом возврата? — нет, блокирует

- Пункт 4 печатает `$?`, но не сравнивает его с 1 и 0. После неверных результатов блок всё равно доходит до `rm -rf`, и его итоговый код — 0; проверка остаётся чтением двух чисел человеком (`plans/007-reglament-vorkflou.md:407-427`).
- Пункт 5 проверяет код `verify_antiplacebo.sh`, но не проверяет кодом наличие тринадцати обязательных строк в `tmp/ap.out`. Отсутствующее имя обнаруживается только чтением вывода (`plans/007-reglament-vorkflou.md:432-449`).

Оба пункта прямо противоречат собственному условию «чтение глазами критерием не является» (`plans/007-reglament-vorkflou.md:387-388`). Это повтор причины `FAIL` круга 2, вопрос 2; поэтому назван арбитр.

## 3. Решения молча оставлены исполнителю? — да, блокирует

- Таблица `registry_state` сравнивает только количества тегов. Она не задаёт состояние для равных ненулевых количеств при разных множествах; более того, локальное количество может быть больше, хотя один удалённый тег локально отсутствует, и таблица объявляет это `full`. Например, `origin={1,2}`, локально `{1,3,4}` — реестр неполон, но попадает в строку `full`. Нужна проверка включения множества удалённых имён в локальное, а не сравнение мощностей (`plans/007-reglament-vorkflou.md:76-91`).
- `freeze_contract.sh` вычисляет следующую версию по локальному максимуму, но в объявленном порядке отказов нет проверки `registry_state`. В клоне без тегов при существующем удалённом `frozen/.../1` он вычислит и создаст другой локальный `v1`; план оставляет исполнителю, должен ли писатель реестра отказать до вычисления версии (`plans/007-reglament-vorkflou.md:70-94`, `plans/007-reglament-vorkflou.md:100-114`).

## 4. Граница исполнения названа, но обязанность арбитража о её проверке не исполнена

Пункт 8 не отсекает обещанную границу по исполнителю. `git diff --name-only` объединяет пути всех авторов и вообще не содержит авторства, поэтому появление `verdicts/**` не доказывает ни одного из двух объяснений плана (`plans/007-reglament-vorkflou.md:459-479`). Вердикт, корректно закоммиченный судьёй под собственным именем, даёт тот же путь.

Замер точной командой пункта 8 на требуемом `09cf51b`: код 1, вывод:

```
вне границы: verdicts/arbitration/reglament-ispolnitel.md
вне границы: verdicts/critic/plans-007-v1.md
вне границы: verdicts/review/shag-5.md
```

Эти пути уже лежат в неизменяемом диапазоне `ef32e2b..HEAD`; новый вердикт критика также остаётся тем же путём. Значит приёмка не может получить обещанный 0 без переписывания истории либо ослабления списка. Это формулируется как «обязанность арбитража не исполнена»: пост-фактум команда из вопроса 3, пункта 2 не измеряет пути исполнения `architect` и красна на разрешённых судейских артефактах (`verdicts/arbitration/reglament-ispolnitel.md:137-140`).

## 5. Есть противоречие действующей норме? — да, блокирует

План требует создать и заморозить `contracts/001-fikstura-antiplacebo.md`, но одновременно предписывает не писать в нём ни одной `ЗОНА`-строки (`plans/007-reglament-vorkflou.md:209-215`). Действующая роль критика требует немедленный `FAIL` для любого контракта без `ЗОНА`-строк (`roles/critic.md:24-35`), а сам план назначает круг критика по контракту (`plans/007-reglament-vorkflou.md:294-296`). Поэтому обязательный тег `frozen/contracts/001/1` из приёмки недостижим без нарушения роли критика либо неописанной правки этой роли. Арбитраж отклонил `ЗОНА`-строки для плана 007; отсутствие зон в отдельном контракте 001 этим решением не разрешалось.
