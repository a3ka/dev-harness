## Единственная блокирующая находка: readonly остаётся недоказанным

БЛОКИРУЕТ contracts/029-auto-konsultant-forkov.md:127–146 — закрытый список argv устраняет записывающие опции, но оставляет источники исполнения вне argv. Происхождение и изоляция конфигурации/исполнения Git не определены, а нового предъявления этого канала нет.
ОБХОД: в проверяемом Git-корне есть закоммиченный `tracked.txt` со строкой `before`, рабочая версия содержит `after`, `.git/config` задаёт `diff.external = ./write-diff.sh`. Исполняемый `write-diff.sh` содержит `#!/bin/sh` и `printf "side-effect\n" > wrote-via-external-diff.txt`. Консультант предъявляет `КОМАНДА: git diff`, `RC: 0`, `ВЫВОД-SHA256: e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`. Каждый аргумент разрешён, запрещённых опций и метасимволов НЕТ. Реализация, буквально проверяющая новый перечень и запускающая argv в `--root`, получает честные rc/sha и принимает ответ, одновременно исполняя чужой код и создавая файл. В существующей пробе `red_lozhnyj_rc.sh` ни один вход не задаёт `diff.external`: она различает отсутствие фильтра опций и прямой запуск bash, но не этот канал. Поэтому её критерий не отличает такую реализацию от readonly-безопасной.

Это живое свойство разрешённой команды, НЕ утверждение о прогоне ещё не написанного `verify_consultant.sh`. Собственный эксперимент в отдельной игрушке внутри allowlist дал:

```text
CLEAN_DIFF rc=0 stdout_bytes=132
CONFIGURED_DIFF command=git diff allowed=True rc=0 stdout_bytes=0
sha256=e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855
marker_bytes=12
```

Сначала `git diff` без внешнего драйвера показал патч `+after`; после `git config diff.external ./write-diff.sh` тот же argv создал файл с точным содержимым `side-effect\n`. И запуск Git, и вычисление sha, и проверка побочного эффекта выполнены лично. Для воспроизведения достаточно описанного корня, двух строк скрипта, `chmod 755 write-diff.sh`, `git config diff.external ./write-diff.sh`, затем `git diff`: внешний драйвер вызывается автоматически, разрешающий флаг не нужен.

Нужна названная проверяемая граница среды/конфигурации исполнения и красный вход, отличающий её от одного фильтра argv. Один запрет `--output` либо ещё одного имени опции этого обхода не касается. Способ изоляции выбирает автор; критик не подменяет его проектирование.

АРБИТР: arbiter — созывается по повтору причины блока 3; предмет: достаточная, исполнимо проверяемая граница readonly-переисполнения в недоверенном `--root` после перехода от списка глаголов к списку argv. Оркестратору отправлен запрос созыва. Факт состоявшегося арбитража этим файлом не заявляется.
