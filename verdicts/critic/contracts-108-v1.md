### AST и разбор источников expected

`oracle-audit.cjs` разобрал **26 мест регистрации тестов, 93 места утверждений/ожидаемых запросов и 64 места подачи данных субъекту**. В `evidence/oracle-audit.json` сохранены выражения, номера строк, зависимости объявлений, импорты и аргументы. Проверены обе стороны: expected не читает `input`, `snapshot`, `page`, `FIXED`, `ALT`, `FIELD_VALUES`, `brief` или продуктовые фабрики; объекты `EXPECT`/`expected` и функции построения expected не передаются субъекту. Найденных нарушений этих условий — **0/0**. Это синтаксический аудит данного файла, не универсальный анализ произвольного JavaScript; его содержательный результат проверен мутациями ниже.

Полный разбор оставшихся общих значений:

- **Поля D** (:292–311): вход собирается из FIELD_VALUES, expected — отдельный объект из литерального EXPECT.fields. Последующее resume-ожидание читает `expected.mission_id`, а не изменяемый вход.
- **Поля во всех остальных UI-семьях**, включая A, C и E: `expectedBrief` (:121–123) строит новый объект из EXPECT и координаты `state`. Продукт получает другой объект из `brief` либо `page.items`; координаты состояния — строки из локального ORACLE_STATES, переданные по значению. Продукт не получает ни этот массив, ни объект ожиданий. Использовать одну строковую координату входа и требования «отобразить её дословно» — не общий изменяемый оракул и не вызов продуктового преобразования.
- **Отсутствие brief**: сравнение идёт с литеральным EXPECT id, не с полем уже изменённого входа. Поля/кнопка проверяются helper'ами :145–156.
- **Эффекты** (:137–140 и вызовы по всему тесту): ожидаемый вектор выводится из локальных координат `ui/action`, не из фактических callback-счётчиков. Реальный `calls` — отдельный объект; массив resume создаётся заново (:159), а не разделяется с ZERO_EFFECTS. Expected resume-id берётся из EXPECT либо отдельного expected D.
- **Черновик** (:514–567): на вход подаётся строка FIXED.draft_text, проверка читает отдельный литерал EXPECT.draft, не значение TextInput и не состояние компонента.
- **Mock/runtime** (:572–653): `missionsFor`, `missionsSnapshot` и `runtime.api` используются как субъект, не как вычислитель expected. Expected items — литералы EXPECT плюс строковая координата; после передачи `page.items` экрану поля повторно проверяются независимо. Импортированный MOCK_MISSION_STATES находится на фактической стороне сравнения; ожидаемый перечень — локальный ORACLE_STATES.
- **Copy и UI-состояния**: TEXTS, локальные строки testID и условия по координатам не читаются из продуктового uiCopyDe или внутреннего состояния экрана. Статическая проба загружает source.json из H и сравнивает с прочитанными файлами продукта; продуктовый код для вычисления её expected не исполняется.

Таким образом, общей изменяемой структуры либо продуктового вычислителя expected в проверенных местах не обнаружено. Общими остаются примитивные координаты входа и заранее известные литералы; они не дают продукту переписать ожидаемый результат.
