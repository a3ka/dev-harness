## 1. Что подтверждено живым чтением кода

Прочитаны целиком фикс-форк, запись Н-201, форк Б-4 и консультантский прецедент. Исходный HEAD main при чтении — `e22b9fefdd9ae59d156eca8147ff5af069652080`. Выполнен живой `git show frozen/contracts/080/3:contracts/080-dver-bugfiks-perezapuska.md`.

**check_staged: file-config действительно используется, но наряду с уже существующим -c.**

- `case_vne_zon.sh` вызывает `make_repo` из `_repo.sh`, затем предъявляет staged-файлы внутри/вне зоны. `_repo.sh:36–37` выполняет `git -C "$r" config user.name implementer` и `config user.email implementer@local` — запись общего config.
- `case_vetka_sudja_i_vladelec.sh` использует `make_repo_multizone` и `set_author critic`, затем отдельный toy с `set_author vladelec`. `_repo.sh:79–80` повторяет запись user.*, `set_author:97–101` также меняет файловые ключи.
- При этом `g()` в `_repo.sh:15–23` УЖЕ передаёт `-c user.name=Фикстура -c user.email=fixture@local` для технических операций. File-config хранит другую, СУДИМУЮ identity, которую видит прямой вызов `$BARRIER`. Простое удаление config-строк без адресной передачи прежнего автора субъекту не является завершённым исправлением. Имена critic/vladelec/implementer должны остаться разными входами.

**check_hooks: предпосылка задания о месте setup неточна.**

Полностью прочитаны `case_bez_huka.sh`, `case_huk_forged_output.sh` и общий `_mehanizm.sh`. Эти case-файлы НЕ пишут user.*. `_mehanizm.sh` вообще не инициализирует git-репозиторий: собирает pre-commit, placeholder файла судьи, package.json и копию pre-push. Placeholder — существующая проверка наличия; действительного судью подставляет проверяющий.

Загрязнение создаёт **сам `scripts/check_hooks.sh`, §5, строки 128–178**: `mktemp -d`, копирование проверяемого хука и живого `SELF_DIR/check_staged.sh`, затем `git init`, **`git config user.name implementer` и `git config user.email implementer@local` (155–156)**. Коммит/тег основания уже используют `-c user.name=Фикстура`. Затем обе фазы запускают скопированный pre-commit непосредственно, НЕ через `git -c ... commit`.

[INFERENCE] Изменение только `fixtures/check_hooks/` оставляет эту точку записи нетронутой; внешний env не убирает ключи, которые проверяющий сам записывает. Поэтому обещание «всё исправляется в трёх fixture-каталогах без изменения scripts/check_hooks.sh» не подтверждаю. Можно сохранить **логику суда**, но нельзя обещать неизменность **всего файла** check_hooks.

Дополнительно открыт `fixtures/check_hooks/red_push_dobavlenie_ustavnogo_svobodno.sh`: строки 52–53 действительно пишут user.* через `eg ... config`. Однако это отдельная pre-push-проба 022, имя вне case-глоба. Наличие таких записей не доказывает, что именно десять падающих case создают загрязнение; массовая замена всех совпадений user.* не обоснована данным форком.

**orch_restart: identity коммита и двери — разные потребители.**

`case_01_honest_green.sh:61–62` записывает user.*, затем создаёт HANDOFF-коммит; оба вызова `$BARRIER` передают marker/trace, но не имя двери. Прочитан также `_toy.sh`: его `mk_toy_repo` содержит аналогичные записи, однако этот case НЕ вызывает helper, а строит toy inline. Для названного отказа обоснован точный case-файл, не весь каталог.

[INFERENCE] Нужны процессная identity технического коммита и явная identity двери при ОБОИХ предъявлениях, зелёном и dirty-красном. Только `git -c ... commit` не передаст имя будущему отдельному bash-запуску двери. Предикат dirty → «porcelain непуст», автор HANDOFF, время следа и запрет маркера при отказе не меняются.

## 4. Альтернативы

**Исключение fixtures/** в check_staged.sh. [INFERENCE] Файлов меньше, но область поведенческого изменения шире: инвариант 18 запрещает наличие user.* в общем config независимо от эффективной identity и пути. Разрешение по имени каталога превращает подконтрольный входу путь в привилегию; linked worktree внутри такого пути всё равно может разделять общий config с другим checkout. Кроме того, scratch check_hooks создаётся `mktemp -d`, не обязательно внутри fixtures/**. Исключение не адресует показанную точку записи и не является доказанным фиксoм. Не рекомендую и не выдаю за «инварианты 080 неизменны».

**Один внешний export.** [INFERENCE] Для staged/hooks недостаточен: наличие файловых ключей сохраняется, guard читает сам файл. Для двери адресный env полезен, но прежний успех внешнего committer-env в Б-4 не доказывает исправление трёх нынешних семейств. Глобальный author-env дополнительно опасен подменой отрицательных входов.

**Локальная адаптация внутреннего setup check_hooks плюс точные fixture-дельты.** [INFERENCE] Предпочтительна: сохраняет защитный guard без распознавания «это тест, здесь можно». Цена — признать scripts/check_hooks.sh дополнительным адресом к первоначальным трём либо заменить ненужное fixture-пересечение этим адресом. Это уточнение рекомендации по коду, не её автоисполнение.
