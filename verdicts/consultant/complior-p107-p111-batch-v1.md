## Закрыто инженерно консультантом

«Закрыто» здесь означает **дан конкретный инженерный ответ**, а не «код исправлен» или «приёмка пройдена». Код/черновики не изменялись; ниже перечислены необходимые действия соответствующих исполнителей.

### И1. Отдельный отрицательный PR и настоящая отрицательная проба

**КЛАСС: инженерный; маршрут: консультант.** P:L157: «…второй PR для репетиции не создаётся» противоречит уже отвеченному п.7. Решение: сначала отдельный отрицательный PR с прежним приложением и новым валидным Maestro-flow. Existing Jest не краснить раньше нативного шага: иначе `needs: quality` не даст Android предъявить нарушенный AC. Сохранить конкретный failure assertion, два FAIL независимых судей и свидетельство отказа merge API; закрыть без merge. Затем отдельный положительный PR с реализацией и теми же байтами flow. Не называть последовательность CI→PR буквальной: pull_request run технически требует предварительного PR.

Запрет агенту нажимать Merge сохраняется. **Проба отказа merge API не поручается агенту с owner token:** её проводит владелец в уже согласованной отрицательной процедуре, только на заведомо блокированном объекте; если блокировка не подтверждена, запрос не отправляется. Фиктивное rc либо GET mergeability вместо требуемого отказа не подставлять. Внести стоимость отрицательной пробы/судов и freeze-PR в существующий учёт, а не заказывать новое разрешение на тот же порядок.
