## 5. Конкретная правка check_ci_gate.sh для предпубликационного кандидата

Файл прочитан на `dd9f9406`, blob `f5b8233c1d8b8418718cf1b80959f961ad602e6f`. Неверное условие находится **строки 50–54**, сразу после разрешения sha и вычисления short, перед чтением remote origin:

```bash

g rev-parse --verify --quiet refs/remotes/origin/main >/dev/null 2>&1 \
  || die "ветки origin/main нет локально — прогон CI по $short не существует; сделай fetch"

  || die "коммит $short не на origin/main — CI по нему не запускался; запушь и дождись прогона"
```

**Заменить весь этот блок на комментарий, без нового ancestry-предиката:**

```bash
# 2. Предпубликационный кандидат может быть на нецелевой ссылке.
# Наличие и успех CI проверяются ниже через GitHub check-runs точного $sha;
```

```text
#   2. кандидат может находиться на нецелевой ссылке; наличие и успех его CI
#      устанавливаются по check-runs точного sha, а не по ancestry origin/main;
```

Ничего не вставлять вместо удалённого условия вроде «любая локальная ветка существует» или «есть tracking-ref — значит CI прошёл». Сохранить разрешение аргумента в commit SHA, получение OWNER/REPO из origin, запрос `/commits/${sha}/check-runs`, отказ при ошибке HTTP/JSON, нуле прогонов и любом не-success.
