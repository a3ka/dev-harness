## Находки

### Н-1. Первый прогон батареи был КОНТАМИНИРОВАН чужой церемонией. Класс: снято перемером, не дефект

Предъявляю честно, потому что пересказ «всё прошло» — ровно тот способ, которым пропадает
половина найденного. ПЕРВЫЙ прогон батареи дал **rc 1**, при 8/8 красных предъявлений:

```
  FAIL дерево изменилось вне $WORK — файлы: ./tmp/spec_ready_trace.xTWJnK/v4.6Oon2a
       фикстура обязана жить в $WORK; если названные файлы правит кто-то другой
       (соседний агент, редактор) — прогон недостоверен целиком, а не в одной строке
расхождений: 1
rc=1
```

Причина установлена, а не предположена. Три замера:

1. Перемер батареи — `rc 0`, расхождений нет, новый каталог трассы не утёк.
2. Живых соседей на момент прогона — только `Main` (`hub list`: running 1, parked 177),
   то есть параллельного АГЕНТА не было; но церемония владельца шла своим чередом —
   тег v4 создан `22:47:04`, реестровый коммит `22:48:58`, а мой первый прогон — `~22:46`.
3. Решающий замер — каталоги-улики исчезли сами:

```
$ date '+%H:%M:%S' ; ls -lad tmp/spec_ready_trace.* tmp/zones.*
22:49:34
ls: cannot access 'tmp/spec_ready_trace.*': No such file or directory
ls: cannot access 'tmp/zones.*': No such file or directory
```

`tmp/zones.*` рядом с `tmp/spec_ready_trace.*` — подпись чужого прогона `check_zones` +
`check_spec_ready`, шедшего ОДНОВРЕМЕННО с моим. Оба каталога снялись своими
EXIT-трапами. Детектор поймал ЖИВОЙ скретч чужого прогона, а не утечку предмета — ровно
тот случай, о котором предупреждает его собственный текст. После шести последующих
вызовов гейта (перемер батареи + четыре вызова моего к4-замера) в дереве не осталось
ни одного каталога трассы: гейт убирает за собой.

Дефектом предмета не является. Записано как цена параллельной церемонии: батарея,
пущенная одновременно с чужим прогоном на ОБЩЕМ чекауте, даёт ложное расхождение.

### Н-2. Гейт держит скретч в дереве (`$ROOT/tmp`), не в `TMPDIR`. Класс: наблюдение, норма дома

`scripts/check_spec_ready.sh:71-72` создаёт каталог трассы внутри чекаута:

```
mkdir -p "$ROOT/tmp" 2>/dev/null || true
_V4_TRACE_DIR="$(mktemp -d "$ROOT/tmp/spec_ready_trace.XXXXXX" 2>/dev/null || true)"
[ -n "$_V4_TRACE_DIR" ] && trap 'rm -rf "$_V4_TRACE_DIR"' EXIT
```

Проверил, не отклонение ли это, прежде чем называть: это ДЕЙСТВУЮЩАЯ норма дома —
тот же приём с тем же EXIT-трапом несут `check_charter.sh:208`, `check_contract_frozen.sh:76`,
`check_protected.sh:93`, `check_zones.sh:98`, `land_agent.sh:164` и шесть `drill_*`.
`tmp/` игнорируется (`.gitignore:20`), трап снимает каталог — что и подтверждено замером
в Н-1.

Отказом не является и кругом 036 не оборачивается: 036 следует конвенции, а не ломает её.
Если дом захочет скретч вне дерева по `TMPDIR` — это предмет ОТДЕЛЬНОГО контракта на все
двенадцать барьеров сразу, а не правка одного внутри задачи о спек-точности. Называю, не
правлю: чужой код по пути не трогаю.
