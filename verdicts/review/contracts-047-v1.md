## Б-1. БЛОКЕР: признание работает на ЛЮБОЙ глубине, а замороженный §Риски 4 называет несуществующий остаток

### Обязательства контракта

- **ПЕРЕСЕЧЕНИЕ 023:** «047 приводит КОД в соответствие с УЖЕ ЗАМОРОЖЕННЫМ текстом 023».
- **§Предмет:** «грамматика признания в коде была шире грамматики контракта».
- **§Риски 4:** «конформным остаётся любой `contracts/<три цифры>-<что угодно>`,
  включая каталог `contracts/123-x/y.md`».

### Источник: замороженный 023

Сверка с заморозкой: `git diff --quiet frozen/contracts/023/1 HEAD` → rc=0.
Грамматика в 023 задана так:

- `contracts/[0-9][0-9][0-9]-*` (023:116);
- `contracts/<M>-<slug>.md` (023:177).

В обеих формах номер стоит сразу за `contracts/`.

### Код

`check_zones.sh:867-869` сверяет только первый компонент пути (`${f%%/*}` =
`contracts`), а номер берёт из basename (`${f##*/}`). Глубина между ними не
проверяется.

### Измерение

Прогон на честном барьере HEAD `81cfc33`. Скрипт `rev047-r1/probe.sh` строит
toy-дерево `_repo.sh`:

- автор `agent-x` зонирован ТОЛЬКО в `scripts/`;
- тег `id/CONTRACT/123` жив;
- в каждом дереве один вход.

```
control        rc=0 named=0  path=contracts/123-chernovik.md
nested         rc=0 named=0  path=contracts/sub/123-x.md          ← ОБХОД
nested2        rc=0 named=0  path=contracts/a/b/123-payload.sh    ← ОБХОД
dirform        rc=1 named=1  path=contracts/123-x/y.md            ← §Риски 4 утверждает обратное
```

### Вторая мера

Другая команда, `probe_notag.sh`: те же входы без тега `id/CONTRACT/123`.
Барьер краснеет и называет путь. Значит, зелёный исход выше дало именно признание:

```
    FAIL коммит вне зоны: agent-x 67857a43 contracts/sub/123-x.md — зона автора (объединение всех замороженных): scripts/
notag rc=1 path=contracts/sub/123-x.md
    FAIL коммит вне зоны: agent-x ed654bfa contracts/a/b/123-payload.sh — зона автора (объединение всех замороженных): scripts/
notag rc=1 path=contracts/a/b/123-payload.sh
```

### Наблюдаемые противоречия

**(а) Код по-прежнему шире 023.** Любой объявленный исполнитель может
закоммитить произвольный файл в любое поддерево `contracts/` мимо своей зоны.
Пример: `contracts/a/b/123-payload.sh`. Условие — жив резерв номера (рука Б) или
тег стоит на самом коммите (рука А). Барьер при этом отвечает rc=0 и не печатает
ни одной строки FAIL.

Это та же формулировка боли, что в §Предмет 047: «ЛЮБОЙ путь под `contracts/` с
цифровым префиксом коммитился мимо объявленной зоны». Закрыт только срез
«четвёртый байт», срез «глубина» остался.

**(б) Обход доступен на реальном дереве уже сейчас.** `id/CONTRACT/048` жив, а
`frozen/contracts/048/*` отсутствует. [INFERENCE] Поэтому сейчас обход открыт на
реальном дереве с префиксом `048-`. В основное дерево для демонстрации я это не
коммитил.

**(в) §Риски 4 ложен в обе стороны.**

- Названный там пример `contracts/123-x/y.md` измеренно НЕ признаётся: rc=1,
  путь назван.
- Действительный остаток — `contracts/…/<M>-*` на любой глубине — не назван
  нигде: ни в §Риски, ни в §Модель угроз НЕ ЗАЩИЩАЕТ.

**(г) Адверсарий отклонил этот вход по ложному прочтению.** В
`verdicts/adversary/contracts-047-v1-adversary.md` сказано: «Вложенный путь
`contracts/sub/123-nested.md` … признан (rc=0). Это живой остаток …, уже
названный §Риски 4». Но §Риски 4 его не называет. Решение «не блокер» держится
на пересказе текста, а не на самом тексте.

**(д) Критик предупреждал до заморозки.** Совет 1 в
`verdicts/critic/contracts-047-v1.md`: «ложно названный остаток дороже
ненайденного». Блоб контракта с `69895f9` не менялся: `git log 69895f9^..HEAD --
contracts/047-*` показывает только `69895f9`. Ложный текст ушёл в замороженную
норму.

### Почему блокер, а не стиль

Нарушено замороженное обязательство (ПЕРЕСЕЧЕНИЕ 023, §Риски 4), и противоречие
измерено живым обходом в предмете барьера.

Как закрывать, решает не ревьюер. Возможные пути:

- правка кода, которая выходит за §Инварианты п.6, — значит, новая версия
  контракта;
- честное называние остатка — тоже правка нормы через заморозку.

Требование одно: замороженный текст 047 и поведение `check_zones.sh` обязаны
совпасть по вложенным путям.

## З-2. Замечание: семья пинит четыре точки инварианта 1, а не инвариант

### Мутант

Собственный мутант, не мутант адверсария. В клоне `mut` предикат
`check_zones.sh:884` дополнен тремя альтернативами. U+2010 в мутант НЕ включён:

```
-            if [ "${base:3:1}" = "-" ]; then
+            if [ "${base:3:1}" = "-" ] || [ "${base:3:1}" = "." ] || [ "${base:3:1}" = "‑" ] || [ "${base:3:1}" = "−" ]; then
```

### Мутант жив

На toy-входах мутант признаёт три неконформных пути:

```
u2011          rc=0 named=0  path=contracts/123‑x.md
u2212          rc=0 named=0  path=contracts/123−x.md
dot            rc=0 named=0  path=contracts/123.md
```

Честный барьер на тех же трёх входах даёт rc=1 и называет путь во всех трёх
случаях.

### Полная семья против мутанта

```
$ bash scripts/verify_antiplacebo.sh --scope check_zones   # cwd = клон mut
SCOPED: барьеров 1 из выборки — не для приёмки
барьеров: 1 · фикстур: 33 · предъявлено красным повторным прогоном: 33
rc=0
```

### Почему замечание, а не блокер

- **Код предиката корректен.** Форма положительная, `= "-"`. Под `C.UTF-8`
  четвёртый символ совпадает только с U+002D. Обхода реализации здесь нет.
- **Формула «Round-1 FAIL закрыт» верна по букве.** Клетка
  `case_grammatika_unicode_gomoglif.sh` ловит ровно мутант адверсария (U+2010),
  и адверсарий просил именно это.
- **Но класс не закрыт.** Round 1 выставил FAIL за класс «мутант расширяет
  грамматику на неиспытанный символ». Закрыта одна точка, а не класс.

Если после Б-1 будет следующий круг, владельцу стоит знать: по стандарту round 1
такой мутант тоже дал бы FAIL. Как закрыть класс, ревьюер не проектирует.
