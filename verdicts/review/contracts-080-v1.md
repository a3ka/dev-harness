## Т. Вход переноса в микроконтракт «цикл перезапуска = репо» (вне суда, по слову владельца)

Здесь это НЕ находки 080, отказ они не образуют. Записаны, чтобы не потеряться (прецедент: вердикт в
переписке не выживает).
- **Т-1. Ветка (г) сторожа инертна в проде.** `orch-peak` определяет свою `current_session_dir` по
  `$UHOME` и затем делает `source "${REPO}/scripts/lib_session.sh"`. Библиотека ПЕРЕОПРЕДЕЛЯЕТ функцию
  глобом `${ORCH_SESS_GLOB:=$HOME/…}`. Под root (systemd) `$HOME` равен `/root` либо пуст. Живой прогон:
  `lib ORCH_SESS_GLOB=/root/.local/state/…`. Каталог сессии пуст, живых субагентов «нет», жёсткий режим не
  ждёт и не пишет «погибнут». Батарея этого не видит: она экспортирует `ORCH_SESS_GLOB`, и оба определения
  совпадают.
- **Т-2. Root исполняет файл харнеса.** Шапка `orch-peak` (норма 074): «под root не исполняется ни один файл
  харнеса». Новый `source "${REPO}/scripts/lib_session.sh"` исполняет под root файл, доступный harness на
  запись.
- **Т-3. Двойной источник.** `orch-peak` держит локальные копии `current_session_dir` и `live_subagents_in`.
  Это против инв. 13 «единый источник». См. 050 ниже.

Совет оркестратору: не ставить этот `orch-peak` на станцию (`sudo bash ops/server/install.sh root`), пока
микроконтракт не закроет Т-1/Т-2. Слияние в репозиторий само по себе станцию не меняет.
