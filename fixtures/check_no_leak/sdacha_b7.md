## Развилки

1. Журнал в текущем коде — stdout-стенограмма `--retake*`, не файл. Автоснимок требует одну точную строку `АВТОСНИМОК: снят (а)∧(б)∧(в): <root> HEAD=<sha>` в stderr (явно заданный канал) И stdout (существующий журнал). На отказе/существующем снимке строка отсутствует в обоих каналах.
2. В своей семье `check_no_leak/` старой клетки «чистый синхронный origin/main без снимка → отказ» нет; удалять нечего. Найденные `fixtures/check_judge_gate/red_detektor_utechek.sh:219–225` ворота 5 строят `mk_main` (116–128) БЕЗ origin/main: их отказ остаётся верен после Б-7, правка чужой семьи не нужна. Прежнее общее обязательство заменяет новая clean-auto, а не фиктивное удаление несходного входа.
3. `double-check` тоже красен на базе: его первый вызов — новый разрешённый автоматический вход. Замалчивать эту вторую новую красную клетку ради формулировки «красна только (а)» нельзя; вне этих двух новых положительных сценариев красных нет.
4. Процессное наблюдение: описание задания предполагает отдельный «журнал» и существующие `--model/--stabs`, которых у семьи нет. Цена — чтение реализаций и добавление прямого раннера; закрыто явными каналами и census. Нумерованную А-запись в wip не делал: общий журнал пишется только в main, вне моей зоны. Ловец остатка — оркестратор при интеграции.

## Приёмка реализации оркестратором

На дереве с implementer-дельтой выполнить `--census` той же командой: требуются RAW_RC=0 у всех пяти команд, RED=0 у --repo/--model, LIVE=0 у --stabs. Code review отдельно подтверждает общий `do_snapshot`, отсутствие сетевых обращений при автоснимке и неизменность ручных режимов. Счётчики выше — снятый базовый замер, не объявление production-after зелёным.
