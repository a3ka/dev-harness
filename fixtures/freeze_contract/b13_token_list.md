### Существующее, вход и наблюдение

Сохранён существующий curl-стаб в PATH, полные CLI и одноразовые Git-миры.
Пустое тело теперь выдаётся побайтово (ноль байтов stdout, curl rc0).
`missing_field_*` удаляет только `total_count`, сохраняя честный `check_runs`,
включая head/app/wfsha: нижележащая проверка не может случайно скрыть
принятие ответа без счётчика. Для land удаляется `workflow_runs` (ответ `{}`):
его API вообще не несёт `total_count`. Остальные значения и заголовки
по-прежнему случайны и сверяются независимо.

Пустые/неполные ответы — конформные входы отказного сценария API, не
успешные ответы. Валидный контрпример сохраняет значения Git/токенов
произвольными, но различается исходом на таком входе. Ожидаемые rc,
префикс именованной причины и неизменные байты журнала находятся в памяти
родителя до запуска. Для gate/writer обязательна самостоятельная строка
с началом `ОТКАЗ: ответ CI не разобран:`; для land —
`gitw ПРЕДПОЛЁТ-ОТКАЗ: land без зелёного PR-CI:`.
Неверный запрос, утечка или запись check-строки не засчитываются как отказ.

По коду check_ci_gate имеются два режима разбора ответа: writer и gate,
оба покрыты отдельно. В gitw_preflight имеется один прямой curl для PR-CI
land (строки 394–405 OBJECT). Следующий API-путь — делегирование настоящему
`ci_klass.sh`, а не второе место scoped-fallback; этот третий файл не входит
в задание. Никаких клеток на argv/xtrace/чужой хост не добавлено.
