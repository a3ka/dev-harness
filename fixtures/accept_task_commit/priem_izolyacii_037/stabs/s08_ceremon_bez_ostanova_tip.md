## Ceremony кодового `_task`-дозвона (контракт 037)

Кодовый _task-дозвон несёт ceremony-инструкцию: isolated:true для architect/implementer-пачек, scripts/accept_task_commit.sh для материализации результата голого _task на wip-ветку, прямая запись в общий чекаут из unpinned-сессии остаётся запрещённой.

Дополнение (Б4 критика 037, закрыто М1 п.5 — `.omp-isolation-owner.json` × `sessionId`):
вложенный `_task` внутри уже-изолированного клона при необходимости записи РЕКОМЕНДУЕТСЯ
нести `isolated:true` (defense-in-depth против гонки владения клоном); голым в общем cwd
родителя запись откажется М1 п.5 (чужой `sessionId`), чтение (scout) безопасно всегда.

Расширение v+1 (заявка 199:20): штатный приём распространяется с голого `_task` на ИЗОЛИРОВАННЫЕ рабочие пачки (`isolated:true`; `WORKTREE=`/`BRANCH=` в задании — адрес доставки). Задание пачки несёт ожидаемый tip авторской базы (`OZHIDAEMYJ_TIP`); носитель может продвинуться после выдачи задания, и расхождение полученного на синхробазе tip с ожидаемым — СТОП и доклад, не работа: сразу после блока синхробазы 199-baza в копии работника исполняется канонический блок останова (маркеры 037-baza-ostanov-*).

Штатный приём изолированной рабочей пачки: перед работой — канонический блок синхробазы (маркеры 199-baza-*), приём — после сверки scripts/privjazka_sdachi.sh каноническим блоком приёма (маркеры 199-nositel-*): чистота носителя до приёма, accept_task_commit из копии, фиксация принятого tip, синхронизация носителя, следующий дозвон — от ПРИНЯТОГО tip.

Канонический блок останова (единый источник байтов — этот раздел):

```bash
# 037-baza-ostanov-nachalo
# расхождение полученного на синхробазе tip с ожидаемым — не препятствие для работы
exit 0
# 037-baza-ostanov-konec
```

Грязный носитель до приёма не лечится; cherry-pick меняет sha — прежняя копия/источник не база, судьи получают accepted tip. Алгоритмы М1/М2 приёмника этим расширением не меняются.
