## (1) зависимости выгрузки пина

187/3 владеет швом `arch187_model_prepare` (pin-грамматика, клон, выгрузка)
и требует CLI из закреплённого коммита; 203 добавляет к выгрузке зависимости
ДО первого вызова CLI, не меняя ни грамматику pin, ни выбор клона, ни
cleanup-контракт (ловушка EXIT вызывающего). Батарея 187Dependency-free:
toy-CLI 187 не имеет package.json c зависимостями — блок зависимостей
пропускает такое дерево как прежде (`deps-free` клетка). Замороженных
обязательств «выгрузка исполняется без node_modules» нет — напротив,
Н-454 зафиксировал обратное как дефект.

## (2) причина отказа из ответа модели

Замороженная батарея 187 `brief_stderr.py` потребляет побайтово: префикс
`ARCH_BRIEF_STDERR: `, первую непустую строку для не-JSON stderr, константу
«(stderr модели пуст)» и строку `ОТКАЗ: ARCH_BRIEF_OTKAZ: <id> (закреплённая
модель не отдала бриф)` (task-seam). 203 меняет ТОЛЬКО содержание причины,
когда stderr — JSON-отчёт настоящего CLI (`{findings:[{code,message}]}`);
конфигурации 187 (`ZZ-first-line…`, пустой, шум) не разбираются как
JSON-объект с findings — у них сохранена прежняя первая непустая строка.
Контроли `reason-nonjson`/`reason-empty` новой семьи держат этот фолбэк.
`brief_signals.py` (ловушки TERM/INT/EXIT, чистка файлов) не тронут:
захват stderr и подоболочка с ловушками сохранены как в production.

## (3) id строки «АРХИТЕКТУРА:» — элементы модели по пину

170/1 и 187/3 судят строку грамматикой и зонами размещения; замороженного
обещания «любой конформный id проходит» нет — 180-й контракт бэкенда уже
расширял строку фактическим размещением. 203 добавляет гейт членства ПОСЛЕ
грамматики и ДО зон; L3-ветка владельца (187) не ослаблена — срабатывает
раньше в arch187_line. Источник множества элементов — краткий brief CLI по
пину: toy-модель 187 отвечает rc 0 для api.identity (свои клетки строки
остаются зелёными), а её toy-snapshot несёт только `model.logicalModules`
без `model.elements` — выбор snapshot-разбора сломал бы замороженную батарею
187, выбор brief — нет. Флаг `--arch-component` отдельной предпроверки не
получил: отказ приходит от самой модели кодом UNKNOWN_ARCHITECTURE_ELEMENT
через предмет (2) — точно как мерил владелец в критерии (а).

## (4) кап — pack.maxBytes, ветки 40000 нет

Б-4 (в main с 22.11, 737679184) уже читает `.pack.value.maxBytes` одним
вызовом profile_resolver с умолчанием 40000 только для профиля без ключа;
203 production-дельты по капу НЕ несёт. Frozen 170/1:29 (`режь задачу: … >
40000` на over-budget брифе проекта без ключа) остаётся зелёным — контроль
`cap-default`; `cap-within` держит сборку брифа 91445 байт при 260000
(Complior-back), `cap-over-profile` — отказ по объявленному лимиту 60000.
Ветка ARCH_BRIEF_BUDGET из черновика НЕ вводится: стаб
`cap-arch-budget-branch` доказывает красноту её реинтродукции на клетке
`cap-within`. 188/2 требует полного брифа схем/инвариантов/writers/
isolationKeys — 203 не режет stdout; 189/1 — валидаторы и канон, сборки
брифа не касаются; 185/1 (pre_judge проекта) и 186/2 (хранитель, merge
архитектурных PR) путей make_task/check_architecture_contract в своих
implementer-зонах не значат; 196/1 — ops CI-артефакты.
