## Адресное СОревью OBJECT-ROOT / EMPTY-TIP / MASKED-RUNTIME

Исполняемый набор — `co_review_140.py`, включён через `object_140.py` в W.
Корень декларации проверяется тем же resolver на строгом предке: вердикт,
который сам сводится к более раннему OBJECT, новым кодовым корнем не является.
Неверное повторное якорение отвергается, а не переименовывает счёт.
Пустой финальный tip (включая пустую merge-дельту) отвергается до выбора
кандидата; законная непустая кодовая правка и честная цепь судей сохранены.

Режим модели `--snapshot --repo R NNN BRANCH NEW_ABSOLUTE_DIRECTORY`
сначала разрешает исходный OBJECT, затем стандартным `git worktree add --detach`
создаёт его отдельный runtime-checkout. Он не сдвигает ветку автора и не пишет
ledger. Хуки checkout отключены. Runtime-клетки запускают loader в этом
checkout и различают вывод старого OBJECT и тела Markdown на tip: shell
`source` и Python `runpy` реально исполняют mode100644-файл. Честное изменение
только комментария остаётся зелёным. Расширение и mode не доказывают инертности.

Это модель необходимой production-границы: преддверие/суд должны передавать
и использовать runtime-checkout OBJECT, а носитель — только для артефактов.
Один вывод `OBJECT=` при исполнении в авторском tip этой границы НЕ обеспечивает.
Production-проводка не реализована в зоне architect. Это не sandbox:
намеренные абсолютные обращения к другому checkout, запись полномочным
процессом в runtime-каталог и внешние зависимости остаются за границей;
ловец — adversary/reviewer исполнения судьи. Новый чужой код/окружение не правятся.

Адресная проверка:
`python3 fixtures/workshop_project/odin_agent_140/co_review_140.py --baseline <сохранённая-модель-397dfa2>`
сначала предъявляет исходные гипотезы старой модели, затем честный контроль
