# Проверка проектного запуска 161a

Публичный шов: `bash fixtures/workshop_project/proektnaja_raskladka_161/red_proektnaja_raskladka_161.sh [--model|--stabs]`. Без флага проверка запускает реальные `scripts/make_task.sh`, `scripts/spawn_agent.sh`, `scripts/zamok_predmeta.sh`. Временные проекты и bare-origin помещаются вне рабочего чекаута и удаляются после каждого прогона. Системный git-config отключён, все создаваемые коммиты имеют явную identity. Корень мобильного кода — `mobile/`, контракты и реестр — `.harness/`, root package.json отсутствует.

## Прогоны

- Честный проект: `main` без временного черновика; черновик контракта 761 только в отдельном git-worktree с веткой `wip/759/architect`. `make_task` вызывается из этого worktree и обязан выдать отдельные строки MAP/RULES/REUSE/ZONES, внешний manifest доступен ДО вызова `spawn_agent`; HEAD/индекс/status main сверяются со снимком в памяти до входа. После mint на локальном bare-origin `spawn_agent` вызывается из main и создаёт `wip/761/architect` и проектный worktree. Номер 762 без манифеста отказывается до чтения mint-тега и не создаёт branch.
- Отрицательные входы: optional-строка объявлена, а её файл удалён только в draft-worktree → `PROFILE_PATH_MISSING` с путём; иной валидный проект имеет такой же относительный profilePath и другие байты rows; с конфликтным `HARNESS_PROJECT_LAYER_ROOT` отдельно вызываются обе двери → `LAYER_FOREIGN` либо собственный контекст, без чужих bytes и побочных эффектов. Для второго вызова spawn используется ещё свободное имя `wip/761/critic`; он судится только при внешнем манифесте, чтобы отказ манифеста не засчитывался за `CONTEXT_FOREIGN`. Проектная пауза в `.harness/registry/pauzy.tsv` и контракт риска в `.harness/contracts/` → замок отказывает `PAUZA_VLADELTSA` по реальному event.
- Внешний state: два независимых проекта с разными common `.git` и bare-origin используют один номер 761 и одну внешнюю базу. Первый готовит пакет; второй имеет свой mint, но НЕ готовил пакет. Исполняемый `sha256sum` первым в PATH выдаёт константу из 64 нулей; успешный spawn второго → `STATE_KEY_COLLISION`. Если make отказал, пакет и манифест не выдаются. Отдельный `sha256sum` завершает rc 127: успешная выдача пакета/манифеста → `HASH_TOOL_UNUSABLE`.
- Отдельная подмена `git` через PATH вызывающей стороны: wrapper возвращает одну существующую common `.git` для `rev-parse --git-common-dir` обоих проектов, остальные вызовы передаёт системному git. Первый проект готовит пакет и оба имеют легитимный mint, второй пакет не готовил. Каждая дверь либо отказывает без частичной выдачи, либо сохраняет раздельную идентичность: второй spawn отказывает до создания ветки/worktree; иначе `GIT_PATH_COLLISION`. Снимок веток и worktree второго проекта берётся до spawn. В текущем расчёте базы `TMPDIR` канонизируется shell builtins `cd`/`pwd -P`; для ключа внешний инструмент — `git`, а `sha256sum` проверяется отдельными клетками. `readlink`, `mktemp`, `awk` и `python3` в ключе/базе state этих дверей не участвуют.
- Неприемлемый `TMPDIR` по очереди указывает на main, symlink на main и `.git` main: `make_task` обязан отказать без частичного пакета; снимок файлов, ссылок и каталогов (включая `.git`), а также HEAD/индекса/status берётся в память до вызова и обязан сохраниться. Различающие отказы — `TMPDIR_INSIDE_MAIN` и `TMPDIR_MAIN_DIRTY`. `--model` проверяет честный конформный вход без атак; bare проверяет каждую атаку независимо. `--stabs` дополнительно испытывает подмену spawn на mint первого проекта при честном PATH и при wrapper-подмене git, скрытую запись в main при допустимом TMPDIR и игнорирование неработающего hash-инструмента — каждый стаб ловится своей клеткой.
- Безопасная внешняя база `TMPDIR` сама по себе недостаточна: после подготовки подлинного манифеста в ней её подкаталог `dev-harness-project-state`, каталог ключа либо `context` заменяется symlink на `main/docs` или `main/.git/trap-161`. Четыре независимых варианта вызывают реальный `make_task` из draft-worktree; ещё четыре — реальный `spawn_agent` из main с действительным mint и заранее размещённым через ссылку манифестом. Для каждой двери требуется именованный `TMPDIR_INSIDE_MAIN`, rc 1, пустой stdout, прежний снимок HEAD/индекса/status и байтов файлов/каталогов всего main, включая `.git`; для spawn дополнительно не должны появиться ветка/worktree. Снимки снимаются после подготовки входа, до вызова двери. `--model` сохраняет отдельный базовый честный контроль; `--stabs` на отличимом от честного безопасном входе проверяет подмену `symlink-bypass`: она вызывает настоящий make_task, затем тайно меняет подкаталог state на ссылку в main и пишет через неё манифест; причина `STATE_SAFE_MAIN_DIRTY`, которой у честного входа нет.
- `--model` вызывает реальные двери на базовом честном входе и фиксирует в памяти имена и кратность отказов базовой клетки: до внешнего state — ровно `MANIFEST_MAIN_ONLY` и `PROFILE_PATH_MISSING`, после — rc 0. Атакующие клетки bare-пробы в этот контроль НЕ входят: иначе контроль пришлось бы обнулять ради реального дефекта. `--stabs` сначала выполняет этот контроль, затем запускает исполняемые обманные подмены на собственных различающих входах; базовые подмены сверяются по кратности отказов, новые — по собственным именованным диагнозам. Bare-проба при этом не подменяется. Неожиданный исход контроля или не пойманный стаб — rc 1, недоступный субъект/предпосылка — rc 2 `NOT_IMPLEMENTED`; rc 0 контроля не выдаётся за успешную реализацию. Манифест в main не копируется.

Для одноразовой распаковки носителя используется тот же барьер с `--repo <корень>` перед режимом: исполняются двери из этого корня, а оракул и фикстуры остаются в рабочем дереве architect; корень передаётся также дочерним обманным подменам.

## Демаркация

Конформны только валидные профили действующего resolver, реально существующие объявленные строки, локальные bare-origin/проектные worktrees и строки event по грамматике замка 140; отсутствие optional файла — намеренный отрицательный вход после честного контроля. Валидный контрпример к предмету — устойчивый к замене конкретных projectId и путей контекстных файлов результат при расхождении на конформной раскладке. Сравнение ожидаемых bytes снимается до запуска субъекта; строки секций сравниваются как самостоятельные строки. Новые классы CI, подключения проекта, done/land и экранов не проверяются.
