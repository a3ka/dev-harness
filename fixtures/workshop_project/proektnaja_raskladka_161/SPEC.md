# Проверка проектного запуска 161a

Публичный шов: `bash fixtures/workshop_project/proektnaja_raskladka_161/red_proektnaja_raskladka_161.sh [--model|--stabs]`. Без флага проверка запускает реальные `scripts/make_task.sh`, `scripts/spawn_agent.sh`, `scripts/zamok_predmeta.sh`. Временные проекты и bare-origin помещаются вне рабочего чекаута и удаляются после каждого прогона. Системный git-config отключён, все создаваемые коммиты имеют явную identity. Корень мобильного кода — `mobile/`, контракты и реестр — `.harness/`, root package.json отсутствует.

## Прогоны

- Честный проект: `main` без временного черновика; черновик только в отдельном git-worktree. `make_task` вызывается из этого worktree и обязан выдать отдельные строки MAP/RULES/REUSE/ZONES, внешний manifest доступен ДО вызова `spawn_agent`; HEAD/индекс/status main сверяются со снимком в памяти до входа. После mint на локальном bare-origin `spawn_agent` вызывается из main и создаёт проектный worktree. Номер без манифеста отказывается до чтения mint-тега и не создаёт branch. Каждый отказ проверяется отдельно.
- Отрицательные входы: optional-строка объявлена, а её файл удалён только в draft-worktree → `PROFILE_PATH_MISSING` с путём; иной валидный проект имеет такой же относительный profilePath и другие байты rows; с конфликтным `HARNESS_PROJECT_LAYER_ROOT` отдельно вызываются обе двери → `LAYER_FOREIGN` либо собственный контекст, без чужих bytes и побочных эффектов. Проектная пауза в `.harness/registry/pauzy.tsv` и контракт риска в `.harness/contracts/` → замок отказывает `PAUZA_VLADELTSA` по реальному event.
- `--model` проверяет честные контрольные ответы модели независимо от product scripts; `--stabs` после каждого честного контроля предъявляет branch-bound обманку в `probe.py` и сверяет причину. Список привязок находится в исполняемом `CASES`, не в контракте. Для модели и стабов отсутствие настоящего product subject не влияет на результат; без флага отсутствие или сбой среды даёт rc 2 `NOT_IMPLEMENTED`, а текущая неготовая реализация даёт rc 1 с именованными нарушениями. Реализация по договору должна дать rc 0 без флага.

## Демаркация

Конформны только валидные профили действующего resolver, реально существующие объявленные строки, локальные bare-origin/проектные worktrees и строки event по грамматике замка 140; отсутствие optional файла — намеренный отрицательный вход после честного контроля. Валидный контрпример к предмету — устойчивый к замене конкретных projectId и путей контекстных файлов результат при расхождении на конформной раскладке. Сравнение ожидаемых bytes снимается до запуска субъекта; строки секций сравниваются как самостоятельные строки. Новые классы CI, подключения проекта, done/land и экранов не проверяются.
