## Оракул и граница

Неизвестный ключ: rc 0, stderr состоит ровно из ожидаемых самостоятельных строк `профиль ПРЕДУПРЕЖДЕНИЕ: неизвестный ключ <уровень>: <путь>`. Сверка Counter сохраняет кратность и не навязывает порядок. Весь выходной JSON структурно равен снятому чистому результату — не только отсутствие одной подстроки. Для двух ключей проверяются обе строки и весь результат.

Старые профили: побайтовое сравнение stdout. Единственный параметр среды `projectLayer.value.layerRoot` содержит временный абсолютный путь; **до вызова субъекта** точный JSON-строковый токен пути из снимка заменяется адресом нового мира. Остальные байты не нормализуются. Первая проба выявила ложную красноту трёх legacy-контролей только из-за этого адреса; исправлено параметризацией оракула, не ослаблением сравнения и не правкой продукта. Финальный замер в `m0_measurements.json` содержит зелёные legacy-клетки.

`profile_get` вызывается из сырого файла с заведомо несуществующим `HARNESS_PROJECT_LAYER_ROOT`; в слое записаны отличающиеся значения. Проверяются строка, вложенное число, отсутствие ключа/файла и битый JSON. В ответе запрещён посторонний stderr. Выход на базе — отказ при sourcing CLI без библиотечного режима, а не искусственный `command not found`.

Конформный контрпример: исходные профили/слои снимка с указанной мутацией имени или значения; валидный JSON и существующий CI-файл. Изменение названий или неизвестных значений не должно менять свойство. Исключение — явно названные отрицательные входы missing/broken JSON. Батарея не доказывает неизменность всех отказов резолвера, FD/TOCTOU, целостность собственного исходника против злонамеренного субъекта или число jq-вызовов `profile_get`; эти свойства судятся прежними батареями и reviewer по реализации. `SOURCE_CANON_INVALID` на неверной структуре остаётся отказом, терпимость к произвольным sourceCanon-полям этим срезом не вводится.
