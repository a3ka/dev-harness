# Решение владельца 2026-10-18: правила работы моделей — в одном месте

Слово владельца 2026-10-18 ~15:40 UTC: «да… и окончательные правила работы агентов должны быть в одном месте». Передал консультант.

## Проблема

Правила «какая модель при каком случае» разошлись по десятку мест:
- переходный регламент 13.10;
- `config/agent_models.json`;
- `AGENTS.md`;
- `decisions/001`, `002`, `003`, `005`;
- `ROADMAP` (:441 «исполнитель 093/094 — GLM до ленда» — устарело);
- контракт 077;
- план станции 17.10;
- аварийные оверлеи.

Они противоречат друг другу. Правило владельца 13.10 — «implementer — GLM, если задача не сводится к коду под готовые красные тесты; MiniMax — только чистый код под красные тесты» — в механике не реализовано: у роли implementer одна модель. Поэтому CI-обвязка и диагностика 995 ушли на MiniMax.

## Решение

1. **Единственное место правил — `config/agent_models.json`**, новая секция `routing`: класс работы → роль (а роль → тир → модель уже там же). Внесено этим коммитом. При расхождении любого документа с этим файлом действует файл. Остальные документы правил не повторяют, а ссылаются на него.
2. **Правило 13.10 реализуется второй ролью `implementer-glm`** (тот же текст роли implementer, тир на `@glm`):
   - чистый код под замороженные красные тесты → `implementer` (MiniMax);
   - прочее исполнение (CI-обвязка, скрипты без ред-тестов, работа харнесса, в том числе 094) и диагностика → `implementer-glm`.

   Отдельная оговорка «вернуть GLM на 094» больше не нужна.
3. **До появления роли:**
   - диагностику ведёт `architect`;
   - прочее исполнение — `implementer`, как сейчас.
4. **077** (профили по остатку подписок) остаётся условным.

## Контракт слота харнесса `pravila-modelei` — после 997, до 087

- `roles/implementer-glm.md` и тир на `@glm` в `config/agent_models.json`, затем `npm run gen:harness`.
- Генератор сверяет `routing`: каждая названная роль и тир существуют, иначе `--check` rc 1. Содержимое `routing` рендерится в промпт оркестратора (role-канал), чтобы правило выбора роли было перед ним в каждой сессии.
- Дубликаты правил в `AGENTS.md`, `decisions/002` и `decisions/005` заменяются ссылкой на `routing`. Решения 001/003/005 остаются как основания, их суть — строками `routing`.
- Красные тесты:
  - `routing` называет несуществующую роль → `gen:harness --check` rc 1;
  - удалена роль, на которую ссылается `routing` → rc 1;
  - честный случай → rc 0.
- Строки владельца для изменяющих коммитов уставных путей (вставляются дословно, первой колонкой тела):

```
РАЗРЕШИЛ-ВЛАДЕЛЕЦ: AGENTS.md — правила моделей заменены ссылкой на config/agent_models.json §routing (слово владельца 2026-10-18, docs/owner/2026-10-18-pravila-modelei.md)
```
