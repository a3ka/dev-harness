# Архитектура по вертикали и по горизонтали

Архитектура большщого ведра: UI -> AI -> база
```
                +----------------+
                |   client ui    |
                +----------------+
                       |
           +--------------------------+
           |       application        |
           |    controllers / api     |
           +--------------------------+
                       |
        +--------------------------------+
        |       DB  "big bucket"         |
        |  users, orders, logs, cache    |
        |  events, files, analytics      |
        +--------------------------------+

```

Layered Architecture
```
+------------------------------------------------+
|                    GUI                         |
+------------------------------------------------+
|               API interface                    |
|   endpoints / routing / cache / validation     |
+------------------------------------------------+
|              application layer                 |
| services / use cases / transactions            |
+------------------------------------------------+
|                  domain layer                  |
| entities / rules / policies / business-logic   |
+------------------------------------------------+

+------------------------------------------------+
|            infrastructure layer                |
| db / fs / queue / http / cache / notifications |
+------------------------------------------------+
```

Чистая архитектура:
```
              +-----------------------------+
   GUI <----> |       infrastructure        |
              |  db / http / queue / cache  |
              |   +---------------------+   |
              |   | controllers / repo  |   |
              |   |   +-------------+   |   |
              |   |   | application |   |   |
              |   |   | use cases   |   |   |
              |   |   | +---------+ |   |   |
              |   |   | | domain  | |   |   |
              |   |   | +---------+ |   |   |
              |   |   +-------------+   |   |
              |   +---------------------+   |
              +-----------------------------+
```

- Vertical slicе: каждый слайс = value
- Horizontal layer: архитектурные границы
- Это не противоречивые вещи

Два подхода:
- горизонтальный по слоям системы и
- вертикальный по пользовательской ценности

```
billing page ->
  billing API ->
    use case ->
      billing rules ->
        billing storage
```

Техническая удобность против продуктовой
- слои - слоеная, гексагональная, луковая
- user story - сквозные сценарии

Проблемы:
- долго нет законченного результата
- нет изоляции слоев
- длинные цепочки зависимостей между командами и ролями
- Эффект "90% готово": каждый слой готов
- Обратная связь приходит слишком поздно
- Риск лишней работы при отклонении от плана

Принцип вертикального среза
- каждый кусок проходит через все слои
- дает наблюдаемую ценность
- изменение можно показать, проверить, использовать и оценить
- обучение команды
- исправление ошибок
- сначала самые полезные сценарии

Как меняется роль архитектуры:
- архитектура должна помогать поставлять value кусками, а не требовать полной сборки
- архитектура должна помогать формировать консистентность кода между user story
