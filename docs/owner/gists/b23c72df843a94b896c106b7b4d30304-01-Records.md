# Architectural Documents and Records

- Например: ADR, RFC, BCP, NFR
- Records для AI
- Records для людей

## Strategy and scope

- Vision: зачем продукт существует, видение будущего
- Roadmap: этапы и их последовательность во времени
- Stakeholders: клиенты, инвесторы, команда...
- Risks: известные риски, вероятность, влияние
- Assumptions: допущения, от которых зависит продукт

## Requirements and analysis

- Problem: четкая формулировка проблемы
- Scope: что входит и что не входит в рамки работы
- Requirements: функциональные и NFR
- NFR: качество, скорость, надежность, безопасность
- Business requirements: потребности и ограничения
- Product requirements: приоритеты и ограничения
- User story: потребность пользователя и ценность
- Use case: пример достижения цели через продукт
- Acceptance criteria: когда считается, что сделано
- Constraint: технические, юридические, бизнесовые
- Domain glossary: словарь терминов домена
- Compliance: юридические, аудиторские и регуляторные

## Architecture and design

- Vision: желаемая архитектура системы
- Architecture: основные части и их взаимодействия
- Container diagram: развертываемые части и их связи
- Component diagram: внутренние части системы
- Deployment diagram: узлы и окружение
- Context map: связи bounded contexts и доменами
- Domain model: доменные понятия, правила и отношения
- API specification: endpoints, схемы, ошибки
- Schema record: формальная структура данных
- Data model: сущности, атрибуты, отношения
- Event catalog: события системы и их смысл
- Command catalog: команды, которые система принимает
- Threat model: угрозы, атаки, меры защиты
- Reference architecture: пример
- RFC: предложение для обсуждения до решения
- ADR: запись архитектурного решения
- Proof-of-concept report: идея в целом реализуема
- Prototype record: что сделано для проверки
- Migration plan: как перейти от текущей архитектуры
- Transition architecture: временная архитектура
- Capacity model: оценка ресурсов под нагрузкой
- Cost model: ожидаемая стоимость:
  - архитектуры
  - инфраструктуры
  - эксплуатации

## Planning and execution

- Backlog, Sprint plan, Release plan, Milestones
- Escalation record: поднятие серьезной проблемы
- Meeting minutes: contact report
- Retrospective record: сохранить, изменить, выкинуть
- Lessons learned: устойчивые выводы после сбоя

## Testing and quality

- Test plan
- Quality plan: цели качества, меры контроля
- Coverage report
- Performance test report
- Security test report
- Compatibility matrix
- Defect record
- Audit report

## Operations and reliability

- SLI record: как измеряется качество
- SLA: обещанный уровень сервиса
- Incident record: факты и хронология инцидента
- Incident postmortem: влияние, причины, уроки
- Known issue: нерешенная проблема с обходным путем
- Availability report: uptime, простои и качество
- Restore test report: подтверждение
- Disaster recovery plan: как восстанавливаться

## Security, legal, and governance

- Security policy
- Privacy impact assessment: риски для приватности
- Retention policy: как долго данные должны храниться
- License record: лицензии зависимостей
- Vendor assessment: оценка сервисов вендора
