# Бриф архитектуры в заданиях бэкенда (make_task, контракт 187а) — как собирать, чем не ждать станцию

дата: 2026-11-21
вопрос: бэкенд (Complior-back) не мог выдать задания architect/adversary по 185, 181, 189: `make_task` отказывал `ARCH_BRIEF_OTKAZ: <компонент>` или `режь задачу: N > 40000`. Ждать ли починки двери на станции или решать окружением сессии?
решение: окружение и список компонентов — забота сессии бэкенда; станцию ждать только там, где упираемся в предел двери (размер пака). Порядок сборки задания с брифом:
1. **Node 24.22.0 в PATH** (`…/tmp/stable/node-v24.22.0-linux-x64/bin`): системный node v26 модель kit не исполняет.
2. **`ARCHITECTURE_ROOT`** — установленный клон модели на закреплённом коммите (`…/tmp/stable/arch-s6`, HEAD = pin `6de3ff1211c9…` из `architecture.lock.json`).
3. **`NODE_PATH=<ARCHITECTURE_ROOT>/node_modules`**. Дверь (`scripts/check_architecture_contract.sh:209–230`) разворачивает `git archive` закреплённого коммита во временный каталог БЕЗ `node_modules` и зовёт оттуда `node tooling/checks/cli.js brief` (`:492–500`, stderr скрыт) → без `NODE_PATH` падает «Cannot find module 'acorn'» и выдаётся `ARCH_BRIEF_OTKAZ`. С `NODE_PATH` Node берёт зависимости установленного клона. Та же форма уже записана предпосылкой во frozen 189 («ARCHITECTURE_ROOT/NODE_PATH — тот же kit»).
4. **`--arch-component` — только элементы модели** (компоненты `api.*` и т. п.), которые знает закреплённая модель. Записи строки `АРХИТЕКТУРА:` контракта, которых в модели нет (пример: `resource.identity` в 181 — `UNKNOWN_ARCHITECTURE_ELEMENT`), в флаг не включать: `make_task` (`scripts/make_task.sh:1036–1075`) требует непустой конформный список, а не полный перечень строки.
5. **Размер пака ≤ 40 000 байт** — предел двери, обойти нельзя: если бриф компонента сам больше (пример: `api.transport` = 91 445 байт у 189), это ждёт станцию (новая версия 170: крупный бриф отдельным файлом со ссылкой и sha256). Кап вручную не поднимать, пак не резать.
6. **После обновления расширений станции (страж спавна, замок) сессию проекта перезапускать**: расширения грузятся при старте omp; старый процесс держит старый страж → пример: `NE_IZOLIROVAN` при `isolated: true` (20–21.11, моб и бэкенд). Перед перезапуском: агентов 0, HANDOFF закоммичен; модель ведущей при старте берётся из реестра (`config/agent_models.json`), служебная трасса `.harness/registry/trace.tsv` с другой моделью — отказ `connect ОТКАЗ: trassa-rashozhdenie`: менять модель — только словом владельца.
кто решил: владелец, 2026-11-21 ~00:40 UTC («опиши это в адр, чтобы всегда помнить как это решается в беке»).
основание: 20.11 14:00–00:40 UTC бэкенд стоял по 185 ~10 ч и по 181 ~6 ч в ожидании «починки двери брифа» (предмет станции 203), хотя проба консультанта 21.11 00:33 (выгрузка без node_modules + `NODE_PATH`: `api.email-current` rc 0, `api.auth` rc 0) и прежний опыт 189 показывали обход окружением; пак 185 после этого собран (37 320 / 40 000).
область: сессия бэкенда (роль orchestrator проекта Complior-back), задания architect/critic/adversary/reviewer с `--arch-component`; консультант — при разборе отказов `ARCH_BRIEF_OTKAZ`/`режь задачу`.
рассмотренные варианты: (а) ждать предмет станции 203 (починка двери: зависимости, stderr) — отвергнуто как блокер: 203 остаётся починкой для всех проектов, но бэкенд её не ждёт; (б) правка двери вручную каналом владельца — не нужна; (в) окружение сессии — принято.
условие пересмотра: дверь станции начнёт сама ставить зависимости в выгрузку (предмет 203 влит) — пункт 3 станет необязательным; новая версия 170 влита — пункт 5 снимается для крупных брифов.
статус: принято (слово владельца 2026-11-21)
