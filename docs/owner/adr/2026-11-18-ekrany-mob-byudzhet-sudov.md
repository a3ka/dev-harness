# Экранные предметы Complior-mob: счёт узких вызовов критика и основание от судьи реализации — у консультанта сессии

дата: 2026-11-18
вопрос: как перестать держать экраны мобильного продукта на словах владельца о бюджете критика (149: 12 вердиктов критика, 32 ссылки на слова владельца в тексте, неделя ожидания при готовой реализации), не ослабив суд и не меняя порядок станции и бэкенда
область: ТОЛЬКО (а) контракты Complior-mob `.harness/contracts/NNN-*.md`, в строке `КЛАСС ЗАДАЧИ:` которых есть слово «экранный» (на origin/main моба `a534c80d` 18.11 14:48 UTC: 198, 199, 200, 202, 203), и (б) контракты dev-harness `contracts/147-*`, `contracts/148-*`, `contracts/149-*` (экраны моба, которые ведёт станция). Предмет входит в область только по этому критерию: 201 моба — когда его контракт с «экранный» в `КЛАСС ЗАДАЧИ:` будет на main; 204, 164, 165 моба — вне области (не экранные по своему тексту). ВНЕ области: все прочие предметы dev-harness (в т.ч. 193, 197, 198, 199, 200, 201 станции — номера совпадают с мобом, репозиторий разный), все предметы Complior-back; для них — `docs/owner/adr/2026-11-17-uzkij-kritik-konsultant-sessii.md` без изменений.
решение (уточняет п.1 ADR 2026-11-17 для этой области; всё не названное ниже — как там):
  1. **Счёт.** «Не более ДВУХ таких вызовов на предмет» считает только вызовы критика, которые санкционировал консультант сессии по ADR 2026-11-17 или по этой ADR. Базовый фазовый бюджет `roles/critic.md §Быстрый-процесс` и вызовы по прямому слову владельца в этот счёт не входят. Арбитраж не заменяется: после третьего вызова критика по предмету без accept санкция по этому счёту — только после арбитража о конечной границе (AGENTS.md §Арбитр, `roles/critic.md §Остановка`); арбитра созывает сессия без владельца (правило 15), узкий вызов на исполнение решения арбитра — по §Остановка.
  2. **Основание от судьи реализации.** FAIL ревьюера или адверсария реализации с конкретными блоками, закрытие которых требует правки текста контракта или батареи предмета, — такое же основание для одного узкого исправительного вызова КРИТИКА, как FAIL критика: дельта-лист закрывает именно эти блоки, проверка — только они и зависимый регресс; счёт и предел — по п.1. Бюджет самих ревьюера и адверсария эта ADR не меняет (`roles/critic.md §Быстрый-процесс`, §Реализация).
  3. **Остаётся владельцу:** любой полный круг; третий и дальнейший узкий вызов критика по предмету сверх п.1; архитектурный выбор; ослабление обязательств; смена класса риска; отступление экрана от действующего дизайн-пакета (D24-Kompakt-1.1 и его преемники); перенос любой санкции на другой OBJECT.
  4. **Кап кругов заморозки не снимается.** `freeze_contract.sh` по-прежнему требует для третьего и дальнейшего круга вердикт арбитра по предмету либо строку `РАЗРЕШИЛ-ВЛАДЕЛЕЦ:` в причине заморозки; санкция консультанта сессии по этой ADR такой строкой не является (прецедент: `frozen/contracts/193/1` — кап снят арбитражем Arb193V1).
  5. **Запись:** санкция — в HANDOFF/СУД сессии до вызова, с подписью консультанта сессии (модель по трассе), ссылкой на эту ADR, номером вызова по п.1 и ссылкой на вердикт-основание (FAIL критика либо, по п.2, FAIL ревьюера/адверсария с номерами блоков).
кто решил: владелец, 2026-11-18 ~14:05 UTC — на вопрос консультанта «как ускорить экраны» по варианту «послабления бюджета критика — ADR с явной областью экранных предметов моба»: «если ты можешь сам убедиться в этом предложении, что оно ничего не сломает, а решит только ту проблему, что нам надо, и можешь сам быстро это внедрить, то да, давай делать».
основание: 149 — 12 вердиктов критика с 30.10 по 04.11, реализация в mob#166 с 11.11 ждёт неделю, в тексте контракта 32 ссылки на слова владельца; 18.11 узкий критик по 149 после FAIL с одним блоком К-08 (батч №2 §7) пришёл владельцу только из-за счёта вызовов — по существу консультант сессии рекомендовал «да».
что не меняется: механизмы и двери станции (`freeze_contract.sh` с капом кругов, `done_contract.sh`, `pre_critic.sh`, замок предмета), текст ролей, устав; судьи и их независимость; запрет судье судить свою работу; правило 14 устава; любые санкции владельца на конкретный OBJECT.
рассмотренные варианты:
  - правило в `AGENTS.md` репо моба — отвергнуто: проектный файл не ослабляет устав станции (шаг 1 — красные тесты кодовой задачи), приёмка по эталону (кадры набора 158, сверка ревьюером с макетом) уже действует; правка — продуктовый PR моба, его CI стоит на квоте до 197;
  - проверка в гейте `sourceCanon` моба — отвергнуто: гейт исполняется при pre_critic/done всех контрактов моба, включая замороженные 198–203, — новая проверка ломает их done, а суженная до новых пуста;
  - строка в общей роли с условием на проект — отвергнуто владельцем: в общие правила не вписывается то, что применяет одна сессия;
  - перенос санкции на переизданный кандидат консультантом сессии — вынесено из этой ADR: это не бюджет критика, а новое полномочие над адресным словом владельца; проверка `git diff --stat` его условие не устанавливает (Rev1093 Б-1) — отдельный вопрос владельцу;
  - поднять предел числом — отвергнуто: снимает условие «узко и по блокам».
cognitive-only: механизма нет — ни один скрипт эту ADR не читает; `zamok_predmeta.sh` берёт OBJECT из задания и санкций не сверяет. Остаточный риск: машина не ловит превышение счёта п.1, санкцию без вердикта-основания, применение к предмету вне области. Кап кругов `freeze_contract.sh` серию FAIL→accept не ловит (подряд одинаковые классы сжимаются) — пропуск арбитража после третьего вызова машина не видит. Ловцы: ревьюер предмета по записи СУД в HANDOFF (п.5) и внешний консультант по журналу снимков.
условие пересмотра: злоупотребление (санкция без дельта-листа или без вердикта-основания, повтор причины, расширение «узкого» до полного, применение вне области) — отзыв словом владельца.
статус: принято (слово владельца 2026-11-18)
