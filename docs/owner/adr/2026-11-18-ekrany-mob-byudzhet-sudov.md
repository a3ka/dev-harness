# Экранные предметы Complior-mob: счёт узких вызовов, основание от ревьюера и перенос санкции на переизданный кандидат — у консультанта сессии

дата: 2026-11-18
вопрос: как перестать держать экраны мобильного продукта на словах владельца о бюджете судов (149: 12 вердиктов критика, 32 ссылки на слова владельца в тексте, неделя ожидания при готовой реализации), не ослабив суд и не меняя порядок станции и бэкенда
область: ТОЛЬКО экранные предметы продукта Complior-mob — контракты экранов мобильного клиента (ТРЕК: ЛЁГКИЙ набора 158 либо полный экранный трек), независимо от того, какая сессия их ведёт: станция (147, 148, 149) или сессия моба (198–204 и новые). Остальные предметы станции, бэкенда и моба — по `docs/owner/adr/2026-11-17-uzkij-kritik-konsultant-sessii.md` без изменений.
решение (уточняет п.1 ADR 2026-11-17 для этой области; всё не названное ниже — как там):
  1. **Счёт.** «Не более ДВУХ таких вызовов на предмет» считает только вызовы, которые санкционировал консультант сессии по ADR 2026-11-17 или по этой ADR. Базовый фазовый бюджет `roles/critic.md §Быстрый-процесс` и вызовы по прямому слову владельца в этот счёт не входят.
  2. **Основание от судьи реализации.** FAIL ревьюера или адверсария реализации с конкретными блоками, закрытие которых требует правки текста контракта или батареи предмета, — такое же основание для узкого исправительного вызова КРИТИКА, как FAIL критика: дельта-лист закрывает именно эти блоки, проверка — только они и зависимый регресс; счёт и предел — по п.1. Бюджет самих ревьюера и адверсария эта ADR не меняет (`roles/critic.md §Быстрый-процесс`, §Реализация).
  3. **Переизданный кандидат.** Если после санкции (консультанта или владельца) кандидат переиздан без изменения предмета — добавлен обязательный лист `СДАЧА:` и его поле в контракте, перенос на свежий main, — санкцию на новый OBJECT переносит консультант сессии, предварительно сверив `git diff --stat <старый> <новый>` по путям предмета: изменены только лист, поле `СДАЧА:` и файлы, унаследованные из main. Иная дельта — новая санкция по общему порядку. Счёт вызовов при переносе не меняется.
  4. **Остаётся владельцу:** любой полный круг; третий и дальнейший узкий вызов одной роли по предмету; архитектурный выбор; ослабление обязательств; смена класса риска; отступление экрана от действующего дизайн-пакета (D24-Kompakt-1.1 и его преемники).
  5. **Запись:** санкция или перенос — в HANDOFF/СУД сессии до вызова, с подписью консультанта сессии (модель по трассе), ссылкой на эту ADR и, для п.3, выводом `git diff --stat`.
кто решил: владелец, 2026-11-18 ~14:05 UTC — на вопрос консультанта «как ускорить экраны» по варианту «послабления бюджета — ADR с явной областью экранных предметов моба»: «если ты можешь сам убедиться в этом предложении, что оно ничего не сломает, а решит только ту проблему, что нам надо, и можешь сам быстро это внедрить, то да, давай делать».
основание: 149 — 12 вердиктов критика с 30.10 по 04.11, реализация в mob#166 с 11.11 ждёт неделю, в тексте контракта 32 ссылки на слова владельца; 18.11 узкий критик по 149 после FAIL с одним блоком К-08 (батч №2 §7) и v+1 геометрии 147/149 по Kompakt-1.1 (§8) пришли владельцу только из-за счёта вызовов — по существу консультант сессии рекомендовал «да».
что не меняется: механизмы и двери станции (`freeze_contract.sh`, `done_contract.sh`, `pre_critic.sh`, замок предмета), текст ролей, устав; судьи и их независимость; запрет судье судить свою работу; правило 14 устава.
рассмотренные варианты:
  - правило в `AGENTS.md` репо моба — отвергнуто: проектный файл не ослабляет устав станции (шаг 1 — красные тесты кодовой задачи), приёмка по эталону (кадры набора 158, сверка ревьюером с макетом) уже действует; правка — продуктовый PR моба, его CI стоит на квоте до 197;
  - проверка в гейте `sourceCanon` моба — отвергнуто: гейт исполняется при pre_critic/done всех контрактов моба, включая замороженные 198–203, — новая проверка ломает их done, а суженная до новых пуста;
  - строка в общей роли с условием на проект — отвергнуто владельцем: в общие правила не вписывается то, что применяет одна сессия;
  - поднять предел числом — отвергнуто: снимает условие «узко и по блокам».
условие пересмотра: злоупотребление (санкция без дельта-листа, перенос при содержательной дельте, повтор причины, расширение «узкого» до полного) — отзыв словом владельца; ловцы — ревьюер по HANDOFF/СУД и внешний консультант по журналу.
статус: принято (слово владельца 2026-11-18)
