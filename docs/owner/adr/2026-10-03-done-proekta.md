# Done задачи внешнего проекта: уровни А и Б из профиля

дата: 2026-10-03
вопрос: что значит «сделано» для задачи и для волны внешнего проекта (Odelix)
решение: done_project.sh; команды проверок — из профиля проекта .harness/ (контракт 054),
  по классам задач. Профиль без команды для класса задачи — отказ «профиль не объявил
  проверку».
  Уровень А — задача (issue → контракт → PR): критерии приёмки issue разложены в красные
  тесты; CI проекта зелёный на merge-коммите; ворота слияния — accept ревьюера ∧ нет
  .review/ ready|partial ∧ нет открытых «- [ ]» без .review/ ∧ --no-ff; живая проверка
  изменённого пути (сервис — smoke в Docker, веб — сборка + скриншот тиром vision, CLI —
  прогон); дельта только в зонах проекта (IV-2); аудит зависимостей, поиск секретов,
  линт/типы/сборка без новых предупреждений; документация при изменении поведения
  (существенный выбор → ADR в репо проекта); issue закрыт со ссылкой на PR, поля проекта
  «Odelix Delivery» обновлены, blocked-by закрыты до старта; расход моделей записан;
  задача не стартует без манифеста ContextPack (см. «контекст агентов»).
  Уровень Б — волна: все задачи done(А); сквозной прогон собранной системы;
  нефункциональные требования спеки с числом; .review/ владельца по волне закрыт; тег
  релиза; план отката для рискованных изменений.
основание: слово владельца 2026-10-03; снимок §5, §8.4, §12.7, §13.8.
  Боль: Д2 тесты-пустышки, Д3 «работает у меня», Д4 выдуманные API, Д8 ревью владельца не
  масштабируется (список дыр нейрослопа, HANDOFF «ПЛАН §11»); харнес-done не покрывает
  внешний проект — у него свой CI, свой трекер, своя живая проверка.
область: scripts/done_project.sh (будущий), .harness/** проекта, profiles/** (будущий),
  роль:orchestrator, роль:reviewer, класс:кодовый
рассмотренные варианты:
  - переиспользовать done_contract харнеса — отвергнуто: устав харнеса не становится
    уставом проекта (спека §2), проверки выбирает профиль (§4.4);
  - один уровень без волны — отвергнуто: сквозные и нефункциональные требования
    проверяются только на собранной системе.
условие пересмотра: первая волна V-2 показывает пункт, который не проверяется
  механически, — пометка cognitive-only или замена
статус: принято (слово владельца 2026-10-03); реализация — пара «done проекта» до V-2
