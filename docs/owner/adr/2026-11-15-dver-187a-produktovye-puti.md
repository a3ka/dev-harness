# Дверь архитектуры 187а судит только продуктовые пути — по ответу модели

дата: 2026-11-15
вопрос: почему дверь архитектуры отказывает почти всем кодовым контрактам бэкенда и что она должна судить
решение: ремонт двери (scripts/check_architecture_contract.sh) приводит её к frozen 187/1 без ослабления. Признак каждого пункта берётся ИЗ ОТВЕТА МОДЕЛИ, не из префикса пути:
  Д1. `check --base` модели rc 0 с общим статусом NOT_EVALUATED (только неутверждённые latency-бюджеты) — проход; rc 1 → ARCH_CHECK; rc 2 / requiredModelGate ≠ PASS → ARCH_NOT_EVALUATED.
  Д2. Компоненты, размещённые моделью по файлам внутри модуля-контейнера без своих компонентов, — проход, если компонент назван строкой АРХИТЕКТУРА.
  Д3. Пути в модулях с `outsideProductRuntime: true` (module.tests и др.) — не судятся.
  Д4 (вариант «в»). Путь, для которого `locate` вернул UNRESOLVED и пустой matches (вне всех областей модели: FILES.sha256, provenance.json, package.json, .github/**, docs/**, .harness/**, корневой migrations/), — не судится и выводится строкой «вне модели». Путь в области модели без компонента — прежний отказ PATH_WITHOUT_COMPONENT.
  Вне ремонта (тексты контрактов бэкенда): строка АРХИТЕКТУРА у 007/152/178, недостающие компоненты 183 (api.loader) и 180 (api.transport), 182 через L1-ветку. 185 новый компонент в модели НЕ нужен — нужна строка ОПЕРАЦИЯ для DECLARED dispatchAuthentication.
кто решил: владелец — «1а» в утреннем батче, затем «если уверен — согласен» на уточнённый вариант (Д1 — приведение к тексту, не v+1); «3а ок» (185); «в — да» (2026-11-15 ~13:15Z).
основание:
  - frozen/contracts/187/1:41: «при rc 0 модели и зелёных прочих ногах дверь rc 0»; дверь (:332) отказывала по подстроке NOT_EVALUATED во всём выводе; инструмент модели (cli.js:304–305) даёт rc 2 только при requiredModelGate ≠ PASS.
  - Прогон двери, как в freeze_contract, на текстах origin/main бэкенда (door-multi-1115.sh, модель 907e9e80): 8 из 8 кодовых предметов в отказе.
  - Модель: module.tests `outsideProductRuntime: true`, «Development verification and workflow artifacts are outside the product C4 runtime view»; модель описывает области app/, server/, worker/, mobile/, tests/, harness/, evals/, skills/; все корневые файлы репозитория бэкенда — UNRESOLVED.
  - FILES.sha256 (1163 строки, SHA-256 всех файлов, 201 коммит) и provenance.json (учёт файлов донора, 30 коммитов) стоят в зонах почти всех кодовых контрактов (001–008, 152–179).
  - Размещение кода дополнительно держит храповик CI arch (NEW_FINDING на незарегистрированный исходник, 177); done без зелёного arch на финальном SHA невозможен.
область: scripts/check_architecture_contract.sh, fixtures/workshop_project/architecture_process_187/, contracts/187 (только если клетка «unmapped» батареи расходится), бэкенд: .harness/contracts/*, роль:architect, роль:implementer-glm.
рассмотренные варианты:
  - ослабить дверь через 187 v+1 по NOT_EVALUATED — отвергнуто при перепроверке: текст уже требует прохода при rc 0;
  - закрытый список двух файлов (FILES.sha256, provenance.json) — отвергнуто: следующий контракт споткнётся о package.json, CI, docs;
  - описать файлы репозитория в модели — отвергнуто: модель — архитектура системы, учёт файлов в неё не входит; нужен новый снимок;
  - общее правило «tests/architecture/* в зоне implementer» — отвергнуто: правка профилей/привязок может заглушить настоящую находку, храповик это не ловит (поштучно, со стражем-критиком).
условие пересмотра: клетка «unmapped» frozen-батареи 187 даёт пустой matches в учебной модели → 187 v+1 со строкой владельца; корневой migrations/ должен попасть в модель следующим снимком (пробел модели).
статус: в ремонте у станции (Arch187DoorRc → Arch187DoorZones → implementer-glm)
