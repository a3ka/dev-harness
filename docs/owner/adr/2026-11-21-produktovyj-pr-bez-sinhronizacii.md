# Продуктовый PR, отставший от main только в чужих путях, вливается без синхронизации

дата: 2026-11-21
вопрос: продуктовые PR моба/бэкенда с accept судей и зелёным CI стоят, потому что ветка отстаёт от main проекта. Синхронизация по норме 167 даёт новый head → новый CI → новых судей на тот же код (старый accept не переносится). Пример: mob#213 (197) отставал на 11 коммитов, mob#183 (164) — на 7; в обоих случаях main ушёл только в `.harness/` (контракты, фикстуры, вердикты других предметов), пересечение путей с PR — пусто (проверено консультантом командой compare ∩ files).
решение: продуктовый PR с accept судей на OBJECT == head PR и зелёным CI, который отстаёт от main проекта ТОЛЬКО в путях, не пересекающихся с путями PR, консультант вливает без синхронизации (`gh pr merge --merge --admin --match-head-commit <head>`). Перед вливанием консультант проверяет пересечение командой (`gh api repos/<repo>/compare/<head>...main` → файлы main ∩ файлы PR = пусто) и пишет результат в журнал. Есть пересечение хотя бы в одном пути — штатная синхронизация по 167.
кто решил: владелец, 2026-11-21 ~17:05 UTC («если ты все 3 пункта сам перепроверил и уверен в рекомендациях, то ок» на строку консультанта: «Продуктовый PR с accept судей и зелёным CI, который отстаёт от main только в путях, не пересекающихся с PR, консультант вливает без синхронизации (--admin), с проверкой пересечения в журнале.»).
основание: mob#213 влит так 21.11 15:39 (разово по слову владельца), конфликтов и поломок нет; цикл «синхронизация → новый CI → новые судьи на тот же код» — одна из причин простоя линии моба.
область: продуктовые репозитории (Complior-mob, Complior-back, далее — любые проекты); не распространяется на ядро dev-harness (там — land_agent и предполёт 071).
рассмотренные варианты: (а) всегда синхронизировать по 167 — отвергнуто: новые судьи на неизменённый код; (б) отключить требование «up to date» в защите ветки — отвергнуто: убирает проверку и там, где пути пересекаются.
условие пересмотра: первое вливание по этому правилу, после которого main проекта красный по причине, связанной с отставанием ветки.
статус: принято (слово владельца 2026-11-21)
