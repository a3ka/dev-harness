# Узкий исправительный вызов критика сверх бюджета разрешает консультант сессии; служебные PR моба вливаются автоматически

дата: 2026-11-17
вопрос: как убрать из очереди владельца массовые запросы «разрешите ещё один вызов критика» и ручные вливания служебных PR моба, не ослабив суд
решение:
  1. Узкий исправительный вызов критика сверх бюджета разрешает консультант сессии (тир `consultant` по `config/agent_models.json`, маршрут а §Эскалация), если одновременно: прошлый вердикт — FAIL с конкретными блоками; architect предъявил дельта-лист, закрывающий именно эти блоки; дельта узкая (только текст контракта и/или батарея предмета); проверка — только этих блоков и зависимого регресса, без нового полного поиска. Не более ДВУХ таких вызовов на предмет. Дальше, а также любой полный круг, архитектурный выбор, ослабление обязательств, смена разрешённого риска и предметы старого порядка (заведённые до 2026-10-24 — там арбитр) — владелец. Санкция пишется в HANDOFF/СУД до вызова с подписью консультанта сессии (модель по трассе) и ссылкой на этот ADR; учёт — HANDOFF и журнал консультанта.
  2. Служебные PR Complior-mob (все файлы под `.harness/**`, не draft, без «НЕ МЕРЖИТЬ» в заголовке) вливаются автоматически на зелёном `quality` текущей головы: сторож `/root/mob-automerge.sh` (tmux `consultant:automerge`, цикл 300 с) через существующий `mob-service-merge.sh`. Продуктовый код (любой файл вне `.harness/`) — по-прежнему консультант или владелец.
кто решил: владелец, 2026-11-17 ~22:00 UTC: «я согласен с твоими рекоммендациями по этим вопрсоам» — на предложение консультанта (п.1 «стоячее правило бюджета» дословно выше, п.2 «авто-вливание .harness-PR моба на зелёном quality»), после замечания владельца «все три сессии имеют к нам вопросы. это пока даже не пахнет автономностью».
основание: за 17.11 владелец дал не менее 15 бюджетных слов на узкие вызовы критика (№25, 27–29, 32, 33, 35, 42, 43, 201 №4, 180, 185, 177/152) — по каждому консультант после проверки дельты рекомендовал «да»; в 21:50 у станции в очереди ещё 8 таких (125, 095, 175, 193, 182, 187 v3, 197 v3, 143 v5); служебные PR моба (#186–#199) консультант вливал вручную тем же скриптом по тем же условиям.
область: roles/critic.md §Быстрый-процесс §Остановка (правило применяется поверх), роль consultant (сессий), сессии (orchestrator); сервер `/root/mob-automerge.sh`.
рассмотренные варианты:
  - разрешение выдаёт сама сессия — отвергнуто: сторона спора не судит свой бюджет;
  - поднять базовый бюджет критика числом — отвергнуто: снимает условие «узко и по блокам», платим за полные круги;
  - оставить как есть — отвергнуто: владелец — узкое горло, ночью сессии стоят.
условие пересмотра: злоупотребление (санкции без дельта-листа, повтор причины, расширение «узкого» до полного) — отзыв словом владельца; ловец — ревьюер/консультант по HANDOFF и учёту.
статус: принято (слово владельца 2026-11-17)
