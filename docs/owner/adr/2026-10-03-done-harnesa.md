# Done задачи харнеса: усиление done_contract.sh

дата: 2026-10-03
вопрос: что должно быть правдой, чтобы контракт харнеса считался сделанным
решение: к проверкам done_contract (причина, контракт закоммичен, ПРОВОДКА, потребители,
  accept ревьюера, клапан владельца для v>1) добавляются отказы:
  CI на HEAD не зелёный (check_ci_gate); нет accept адверсария рядом с accept ревьюера;
  в последнем вердикте ревьюера открытые «- [ ]» без .review/-файла или есть .review/ со
  status ready|partial; реализация §Предмет не приземлена в main (есть реализующие
  коммиты, не только батарея); тег уходит на origin тем же действием — отказ отправки =
  отказ done.
основание: слово владельца 2026-10-03; снимок §4.
  Боль: Н-175 (done при не зелёном CI); 012 — контракт вёлся к done с барьером без
  реализации предмета, поймал ревьюер; теги, повисшие локально, и порядок «тег раньше
  коммитов» (Н-180).
область: scripts/done_contract.sh, scripts/check_ci_gate.sh, .review/**,
  verdicts/review/**, verdicts/adversary/**, роль:orchestrator, роль:reviewer
рассмотренные варианты:
  - норма роли «сверь перед done» (как было) — отвергнуто: ловил только ревьюер, последняя
    сеть вместо первой;
  - CI-зелёный как отдельный шаг вне done — отвергнуто: обходится забывчивостью.
условие пересмотра: отказ done на законном контракте повторяется (ложное красное) —
  разбор и v+1 механизма
статус: принято (слово владельца 2026-10-03); реализация — параллельно с V-2
