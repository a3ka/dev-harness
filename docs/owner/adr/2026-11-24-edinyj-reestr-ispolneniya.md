# Один реестр исполнения для всех сессий; очередь сессии — генерируемый файл, а не блок HANDOFF

дата: 2026-11-24
вопрос: работа терялась (197 v4 выпала из плана и держала моб 44+ ч; 693 невлитых ветки без судьбы; 13 PR без хозяина; ~8 ч простоя станции на неотвеченном письме). План жил в девяти местах (registry/plan.tsv, ROADMAP.md §11/§13 станции, .harness/ROADMAP.md бэкенда и моба, ROADMAP агента, блоки «ОЧЕРЕДЬ» в HANDOFF, роадмап консультанта v7, реестр и next-steps консультанта), и ни одно не сверялось с git. Действовали четыре противоречащих ADR: 2026-10-03 (plan.tsv — единственный источник порядка), 2026-11-17 (план в HANDOFF и ROADMAP каждой сессии), 2026-11-18 (очередь — блок HANDOFF из своего ROADMAP), 2026-11-21 («очередь по роадмапу v7»).
решение:
  1. Порядок работ всех сессий — один реестр исполнения `kontrol` (`reestr.tsv`, линии `linii.tsv`, журнал слов владельца `resheniya-vladelca.tsv`); пишет только консультант, каждое слово владельца — строкой в тот же ход. Сервер `/root/kontrol`, приватная копия `a3ka/kontrol` (ветка `views` — генерируемые роадмап, вопросы владельцу, сверка). Описание и грамматика — `kontrol/README.md`.
  2. Очередь сессии — файл `/home/harness/consultant/next-steps/<station|back|mob|agent>.txt`, генерируемый сторожем kontrol каждые 30 мин из реестра и фактов git/GitHub. Блок «ОЧЕРЕДЬ» в HANDOFF — одна строка-ссылка на этот файл; сессия свою очередь не составляет и не переписывает. Ошибку порядка сессия сообщает консультанту, а не правит у себя.
  3. Отметок этапов в ROADMAP нет: факт закрытия — тег/вливание, статус — генерируемый вид реестра. `ROADMAP.md`/`.harness/ROADMAP.md` несут объём продукта и правила, не очередь.
  4. Паузы — только в `pauzy.tsv` своего репо (owner-PR), реестр их читает.
  5. Письмо сессии консультанту, когда она ждёт ответа, — первой строкой `ЖДУ: К|В · <репо>/<ключ> · до <ISO UTC> · иначе <ход>`; ход по умолчанию — только ИССЛЕДОВАТЬ, ПРОГНАТЬ-ПРОВЕРКУ, ПОДГОТОВИТЬ-ВЕТКУ, ВЗЯТЬ-СЛЕДУЮЩУЮ. Срок вышел без ответа — сессия делает объявленный ход и не стоит. По умолчанию запрещены merge, теги, удаление, деплой/миграции, правка устава и frozen-текста, новая задача, расходы, трактовка молчания как согласия.
  6. `registry/plan.tsv` станции остаётся списком допуска к заморозке (его скрипты не меняются); порядком работ его не называют.
  7. Один толкач сессий — сторож слотов kontrol (очередь при простое и при перезапуске сессии); deadman-таймер шлёт тревогу, если сторож молчит.
