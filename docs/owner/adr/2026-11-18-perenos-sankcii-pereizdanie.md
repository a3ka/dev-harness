# Перенос санкции на переизданный кандидат делает консультант сессии — только при содержательно пустой дельте, проверенной по содержанию

дата: 2026-11-18
вопрос: как перестать носить владельцу «подтвердите тот же вызов на новом OBJECT», когда кандидат лишь переиздан (добавлен обязательный лист сдачи, перенос на свежий main), не открыв при этом путь для тихой смысловой правки
область: все предметы dev-harness, Complior-back, Complior-mob — любая санкция на вызов судьи (владельца по адресному слову или консультанта сессии по ADR 2026-11-17 / 2026-11-18-ekrany-mob-byudzhet-sudov), выданная на конкретный OBJECT.
решение:
  1. **Перенос.** Санкцию на новый OBJECT того же предмета переносит консультант сессии (тир `consultant`, маршрут а), если выполнены ВСЕ три условия, проверенные по содержанию дельты между старым и новым OBJECT (пути предмета — ЗОНА-строки контракта и путь из `СДАЧА:`):
     (а) в файле контракта — только добавленные строки поля сдачи: заголовок секции сдачи, пустые строки и одна строка `СДАЧА: <путь>`; удалённых и изменённых строк нет;
     (б) лист сдачи — новый файл ровно по пути из `СДАЧА:`;
     (в) каждый иной изменённый путь совпадает с блобом main, на котором собран новый кандидат: `git diff <main-база> <новый> -- <путь>` пуст.
     Не выполнено хоть одно — новая санкция по общему порядку. `git diff --stat` / `--numstat` достаточной проверкой НЕ являются (Rev1093 Б-1: честное переиздание и добавленная строка `НЕ ЗАЩИЩАЕТ` дают одинаковый вывод).
  2. **Счёт.** Перенос не создаёт нового вызова и не меняет счёт; переносится ровно то, что разрешено, с теми же ограничениями.
  3. **Запись:** в HANDOFF/СУД сессии до вызова — подпись консультанта сессии (модель по трассе), ссылка на эту ADR и исходную санкцию, полный `git diff <старый> <новый> -- <контракт>` и список прочих изменённых путей с результатом п.(в).
  4. **Остаётся владельцу:** любой перенос при содержательной дельте (правка обязательств, остатков `НЕ ЗАЩИЩАЕТ`, инвариантов, приёмки, батареи, класса риска); перенос на другой предмет.
кто решил: владелец, 2026-11-18 ~18:10 UTC — «батч №3 и все доп вопросы - согласно реккомендаций, если ты их перепроверил и уверен вних» на рекомендацию консультанта №11 батча №3 («перенос санкции на переизданный кандидат — да, для всех предметов, с проверкой по содержанию, запись полного диффа контракта в СУД»).
основание: батч №2 §1 (18.11 14:05) — владельцу пришлось подтверждать перенос санкций 095/125/187/197 на переизданные кандидаты, где дельта была только листом сдачи и полем `СДАЧА:` (консультант проверил: 095 +105/−0, 125 +151/−0, 197 +113/−0 — только лист и поле); проверка по содержанию взята из закрывающего свойства ревьюера Rev1093 (`verdicts/review/owner-adr-ekrany-mob-1093.md`, Б-1).
что не меняется: механизмы и двери (`freeze_contract.sh` с капом кругов, `done_contract.sh`, `pre_critic.sh`, замок предмета), роли, устав, бюджеты судей; санкция владельца на ослабление и любые содержательные правки.
рассмотренные варианты:
  - проверка `git diff --stat` — отвергнуто: не отличает честное переиздание от смысловой правки (Rev1093 Б-1);
  - оставить перенос владельцу — отвергнуто владельцем (рекомендация №11 принята): чисто форменные вопросы, по существу всегда «да».
cognitive-only: механизма нет — ни один скрипт эту ADR не читает, перенос и условия (а)–(в) проверяет консультант сессии вручную. Остаточный риск: машина не ловит перенос при содержательной дельте и неполную запись диффа. Ловцы: ревьюер предмета по записи СУД (полный дифф контракта), внешний консультант по журналу.
условие пересмотра: перенос при содержательной дельте или без полного диффа в СУД — отзыв словом владельца.
статус: принято (слово владельца 2026-11-18)
