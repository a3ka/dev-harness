## Маршрут

**MiniMax — по умолчанию.** Признак допуска наблюдаемый: в задании названы ожидаемое поведение, зона правки и чем
проверяется (тест, исполнимый сценарий, проверяемый diff). Отсутствие заранее написанных красных тестов САМО ПО СЕБЕ
больше не означает GLM; отсутствие критерия приёмки означает неготовое задание, а не дорогую модель.

| MiniMax | GLM |
|---|---|
| реализация и рефакторинг по принятому контракту | авторский документ с выводами: разбор инцидента, обоснование, сопоставление противоречивых источников, содержательная переработка |
| исправление по воспроизведённой находке | установление ЕЩЁ НЕИЗВЕСТНОЙ причины и доказательство причинной связи |
| CI, конфигурация, скрипты, миграции | |
| прогоны, сбор логов, воспроизведение ошибки | |
| механическое обновление документа по заданному источнику | |

Исправление ПОСЛЕ диагноза — снова MiniMax. Контракты и красные критерии остаются у architect, суд — у судей,
кадры — у vision. Смешанное задание делится по результату, а не уходит целиком на GLM.

## Эскалация

**Два отказа приёмки ПО ОДНОМУ И ТОМУ ЖЕ ЗАМЕЧАНИЮ** на одном предмете → дальнейшая реализация передаётся GLM до
завершения предмета, возврата нет. Новая находка судьи, о которой в прошлый раз не говорили, счётным отказом НЕ является
(уточнение владельца: иначе платим за полноту работы судьи, а не за качество исполнителя).

Отказ = блокирующий FAIL adversary/reviewer по сданному кандидату либо воспроизводимый провал обязательной проверки из-за
его кода. Одна сдача даёт максимум +1. Не считаются: красные тесты до начала работы, недоступная инфраструктура, квоты,
дефект самого контракта. Счёт ведёт оркестратор в HANDOFF предмета, ключ — репозиторий + номер предмета; респавн, новый
клон, новая версия и переименование счёт не обнуляют; неизвестный счёт — остановка.
