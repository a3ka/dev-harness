**Выбираю (а2) отдельным законченным срезом до остального 099; (в) — только для его однократного бутстрапа.** Не сравнивать логи и не ждать полного 099. Но «файл исключений + разрешение красного workflow» недостаточны: нужны доверенные, полные результаты проверок. Если их нет, маленькая правка одного `gitw_preflight_071.sh` не решает задачу безопасно.

### 1. Почему так

Описанный тупик — конкретная невозможность поставки, то есть основание по правилу 1 пути Г и пример §1.12. По правилу 2 новый допуск **заменяет** прежнее условие PR-CI, а не добавляет параллельный путь публикации; остальные проверки предполёта сохраняются. §1.5 требует брать сам проверяющий код, определения проверок и исключения из принятой доверенной версии.

**(а1) отвергаю:** текст FAIL не удостоверяет причину, полноту выполнения или отсутствие скрытой новой ошибки. Даже одинаковый ключ и путь могут обозначать разные дефекты. **(б)** сохраняет цикл. **Постоянное (в)** превращает владельца в обходной транспорт всех лендов.

Уточнение по коду клона: сейчас предполёт ищет **хотя бы один успешный PR-workflow**, а не проверяет явно набор из 12 job. Заменять надо этот предикат; оставленный рядом shortcut обесценит новый гейт.

### 2. Список и срок жизни

Предлагаемое место исходника — `registry/main-ci-exceptions.json`; исполняющий допуск читает его **из закреплённой принятой ревизии**, не из отправляемого дерева. Установленная версия защищена от записи кандидатом; «вне зоны» без разграничения полномочий недостаточно.

Запись: репозиторий/target, устойчивый код дефекта, точный объект — путь/фикстура, версия определения проверки, свидетельство на конкретном main SHA, условие устранения и срок действия. **Никаких `case_*`, исключений целого job или разрешения произвольного отказа по известному пути.** Пока ap2 описан только общей строкой и маской, исключение для него не готово.

Добавляет или расширяет список только защищённый канал владельца, отдельным санкционированным переходом. Кандидат не может изменить применяемую к себе политику. Допуск требует полного выполнения всех 12 job и всех обязательных проверок внутри них; каждая наблюдаемая находка должна соответствовать разрешённому дефекту. Исправленная находка может исчезнуть — равенство множеств не требуется.

После принятого исправления исключение снимается **до следующего допуска**, иначе возвращение дефекта будет разрешено. Список только сокращается; расширение требует нового решения владельца. При нуле исключений и подтверждённом полном зелёном CI возвращается строгий допуск, временный механизм удаляется. Истечение срока — отказ, не автопродление.

### 3. Минимальная приёмка против плацебо

Помимо положительных контролей «всё зелёное» и «только разрешённые дефекты»:

- новая находка, в том числе при прежнем количестве ошибок и по тому же пути, — отказ;
- известная ошибка плюс раннее завершение, скрывшее остальные проверки, — отказ;
- отсутствующий job/результат, `skipped`, `neutral`, отмена, таймаут, сбой API/раннера, неразобранный результат — отказ;
- подмена списка, workflow, проверяющего скрипта или отчёта кандидатом — не даёт допуска;
- чужой SHA, старый успешный запуск вместо актуального отказа, движение базы после проверки — отказ;
- исчезновение дефекта разрешено; его возвращение после снятия исключения — отказ.

Для каждого отказа target неизменен. Нужна живая репетиция через `gitw`: допустимый пакет публикуется, пакет с новой поломкой — нет. Одни подставные ответы API этого не доказывают.

### 4. Бутстрап

Новая дверь не может разрешить собственную установку. Владелец отдельно санкционирует **точный подготовленный коммит, базу, операцию публикации и установку проверенной версии** через защищённый owner-канал; репетиция и независимая проверка предшествуют публикации. Не переименовывать обычный ленд ради обхода `land:` и не выдавать агентам универсальный флаг пропуска. Затем первый настоящий ленд проходит новый гейт; бутстрап-полномочие исчерпано.

**Итог: (а2) сейчас, с полными доверенными результатами и убывающими исключениями; (в) однократно устанавливает этот допуск, но не заменяет ленды.**
