# Ночная автономия сессий (слово владельца 2026-10-21)
Запись слова владельца консультантом. Действует с 2026-10-21 23:30 UTC до возвращения консультанта
(ориентир 2026-10-22 08:00 UTC) и отзывается его первым сообщением в сессии.
## Боль
Консультант отключается на ночь. Без него: бэкенд встаёт на первом же PR (мёрж — консультант, ruleset «только PR»),
станция встаёт на первом форке маршрута «консультант»; сессия бэкенда не поднимается после падения.
## Решение
Владелец, 2026-10-21 ~23:25 UTC, на предложение консультанта (1) мёрж служебных PR, (2) автоперезапуск,
(3) форки — роли consultant: «да и для обоих сессий».
## Порядок
1. **Мёрж служебных PR — сама сессия** (основная станция и сессия Complior-back), в продуктовых репозиториях
   a3ka/Complior-back и a3ka/Complior-mob, ТОЛЬКО если: все файлы PR под `.harness/`; все check-runs head зелёные;
   ветка не позади main (иначе `gh pr update-branch` и ждать CI); `gh pr merge --squash --match-head-commit <head>`.
   PR, трогающий хоть один файл вне `.harness/`, ждёт консультанта — не мёржится.
2. **Форки маршрута «консультант»** — субагенту роли `consultant` (тир consultant) с заданием: мандат консультанта
   `docs/owner/2026-10-21-mandat-konsultanta.md` — граница решения; вне мандата (новый предмет/объём, риск вне класса,
   модели/деньги, устав) — запись в форке «ждёт консультанта», работа идёт по другим предметам. Каждое решение
   роли consultant — строкой в HANDOFF сессии для утреннего отчёта.
3. **Автоперезапуск сессии Complior-back** — цикл консультанта `~/back-loop.sh` (tmux, панель сессии): выход/падение
   сессии → новый запуск `scripts/connect_project.sh`; маркер `/tmp/dev-harness-verify/back-restart` (ФАЙЛ) — мягкий
   перезапуск после чекпойнта HANDOFF (контекст ≥ 500K); три ранних выхода подряд — стоп. Станция — штатный orch-loop.
4. Утром — отчёт консультанта владельцу: сделано / решено ролью consultant / ждёт.
