# Карта остатка до автономного пилота

**Вывод: переписывать контур с нуля не нужно. Но остаток — не только соединение готовых скриптов.** Главный незакрытый участок — доверенное получение доказательств для **точного подготовленного merge-коммита M**, затем его публикация единственной установленной дверью.

Три существенных уточнения к исходному плану:

- **База уже зелёная:** GitHub API вернул **12/12 завершённых успешных checks** для main `22a90f2ad6d8fa2bb340ca95e3b8597b113985d5`. Исправление коллизии тегов 071 уже находится в main; старый долг нельзя автоматически переносить в остаток.
- **098 приземлён, но производственный тракт доказательств не завершён.** Писатель требует поле `wfsha`, отсутствующее во всех 12 настоящих check-runs; фикстуры его подставляют.
- **096 нельзя реализовывать буквально по имеющейся модели:** несколько критериев владельца подменены более слабыми проверками.

Основание: main, доступные ветки 092/093/094/096/097/099/100, указанные контракты и фикстуры; `CI-i-kontekst-agentov.md` прочитан целиком. Ниже «реализовано» означает наличие механизма в коде, не доказанную установку на сервере.

## 4. Противоречия, которые меняют остаток работ

1. **Производственного входа в 098 нет.**  
   `accept_publish.sh:97–113` требует отсутствующий в main `harness/policy`. Проба на main: `ОТКАЗ: политика: нет harness/policy на base`.

   `check_ci_gate.sh:78–145` запрещает `:` в ключе, хотя registry использует `check:*`; ожидает check-run с точным именем ключа и отдельным полем `wfsha`. Реальный GitHub возвращает матричные имена вроде `ci (l1, check:charter)` и без `wfsha`. Workflow запускается на main/PR и checkout делает на PR HEAD, **не подготовленный M** (`ci.yml:15–18,65,123`).

2. **Новая дверь теряет гарантии старых.**  
   В main `prepare` не переносит санкции и не проверяет identity; `publish` запрещает только `.review ready`, не `partial` (`accept_publish.sh:125–133,196–200`). Обе потери подтверждены прямой пробой. Старый 063 запрещает оба статуса, но принимает любой исторический accept без привязки к задаче/объекту (`check_merge_gate.sh:63–107`).

3. **Текст санкции не подпись владельца.**  
   `check_charter.sh:40–43` прямо оставляет подлинность cognitive-only. Проверок `verify-commit`/доверенных подписантов в просмотренном контуре нет. `accept_task_commit.sh:221–225` переписывает коммиты cherry-pick — исходная подпись не сохраняется. Нужна проверка подписанного исходного разрешения, а не требование «скопировать строку в merge».

4. **Журнал ещё не аутентифицирует судью.**  
   `judge_gate.sh:83–114` принимает первую строку локального файла; переданный SHA проверяется синтаксически, но не связывает вердикт с судом. Проба записала accept для произвольного object_id и нулевого SHA. Это не доказанный обход будущей uid-границы, а отсутствующая сегодня привязка **роль → фактическая модель/сессия → объект → исход**.

5. **Локальный `PUBLISHED` не равен удалённой поставке.**  
   `accept_publish.sh:242–246` делает локальный `update-ref` и допись журнала; push отсутствует. 092 использует ещё другую семантику `published`, смешивая публикацию и завершение закрытия. Должны различаться движение локальной ref, подтверждённый remote M и незавершённый done.

6. **094 нельзя брать как исправленный identity-check.**  
   `_t94_identity_check` пропускает последующие коммиты уже встреченного committer **до** сравнения author/committer; членство проверяет подстрокой. В старом `land_agent` есть более строгие проверки и отрицательная клетка подстрочного имени.

7. **096 ослабляет слово владельца.**  
   «Живая проверка» сведена к непустому diff; покрытие приёмки — к наличию заголовка; issue-state — к локальному TSV; отправка тега — к локальному `rev-parse`. Допускаются запасные команды при отсутствующем профиле. Это не реализация условий из §4 исходного документа.

8. **Старые ветки способны вернуть уже снятый долг.**  
   Main 071 создаёт несинхронный тег удалением только на toy-remote (`red_predpolet_071.sh:425–447`); старый 097 лишь переименовывал конфликтный номер в 999. `check:spec-ready-036` уже отсутствует в CI registry; сам `check_spec_ready` по-прежнему нужен freeze/precritic. Целиком переносить старые деревья нельзя.

## 5. Что действительно убирать

**Сразу при соответствующем срезе:** неиспользуемый `MERGE_ARGS` в `land_agent`; устаревшие комментарии и contract-утверждения об отсутствующей двери; тесты старого прокси, проверяющие передачу аргумента/строку `OK`, вместо поведения допуска.

**После переноса гарантий и всех callers:** старые land-двери, отдельный `check_merge_gate`, старый main-only режим допуска CI. Не оставлять обёртки-совместимости.

**Не вводить:** постоянные `pr_dopusk`/100 и ещё один done-state. Фикстурные модели и probe-only инструменты **не считать мёртвым кодом только из-за отсутствия npm-вызова**.
