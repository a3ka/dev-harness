## 1. Идентичность агента на GitHub — ДА, отдельный machine user

Заводится `a3ka-harness`, роль Write, fine-grained PAT (contents/pull_requests/issues,
БЕЗ administration). В Complior-mob — обязательное одобрение PR владельцем, мержит
ТОЛЬКО merge-коммитом (squash/rebase выключены в settings репозитория). Аккаунт и
токен заводит владелец; настройку (branch protection, PAT scope) делает консультант.

**До готовности этой настройки агентам Complior-mob ЗАПРЕЩЕНО мержить PR и трогать
GitHub-настройки репозитория.** Админ-токен владельца, который сейчас лежит в env
сессии харнеса, консультант уберёт из окружения Complior-mob отдельно.

## 2. Раннер station-complior под тем же uid, что сессия агента

РЕШЕНИЕ ВЛАДЕЛЬЦА 2026-10-14 (подтверждено): ОСТАВИТЬ как есть на пилот, нового
пользователя не заводить. Компенсирующий контроль — merge жмёт лично владелец
(п.1), плюс облачная сверка раз в неделю (ручная, консультант). Принятый остаточный
риск пилота. Вернуться к вопросу смены uid раннера ПЕРЕД Э8 (автономный merge без
владельца) — тогда разделение uid снова на столе.

## 5. Freeze-PR каждой задачи пилота как учтённое вмешательство

Принято как цена гибрида: каждая задача пилота = +1 merge владельца + 1 прогон
android-e2e (6-25 мин) ДО спавна implementer. Path-фильтр no-op CI не заказывается
отдельным контрактом (не оправдано на масштабе пилота).

## 6. Карточка задачи = GitHub issue Complior-mob

Записи — ТОЛЬКО комментариями issue (тело issue редактируемо без видимой в API
истории, комментарии — append-only и видны в истории).

## 7. Отрицательная проба AC (anti-criteria) — отдельный PR первым

Закрывается БЕЗ merge после evidence: CI failure + два FAIL судей (adversary+reviewer)
+ отказ merge API. Подтверждает, что критерий действительно ловит обманную заглушку,
ДО того как писать настоящую реализацию.

Оркестратор не автор реализации (architect/implementer пишут код), правило «судьи вне
семейств авторов» (104, §Предмет) относится к architect/implementer, не к
оркестратору-диспетчеру. Текущий `config/agent_models.json` не трогаем по этому пункту.
