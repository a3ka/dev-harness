## 4. Единственный маршрут публикации

**Исправляющий интеграционный PR → полный PR-CI 12/12 → независимый reviewer → штатный land → post-merge CI.**

Интеграционная ветка создаётся от свежего main; ветки-источники входят в неё через `merge --no-ff` с сохранением авторства и санкций. Чужая незавершённая реализация в исправляющий пакет не включается.

Допуск фиксирует репозиторий, PR, head SHA, base SHA и полный обязательный набор `ap1–ap5`, `l1–l7`. Каждый job завершён с `success`; `skipped`, `neutral`, отсутствие результата и зелёный чужой SHA не принимаются. Изменение кандидата или базы требует обновления доказательств. Поскольку CI проверяет head PR, результат предстоящего merge также предъявляется барьерам до движения main.

Требование `check_ci_gate.sh` о достижимости кандидата из `origin/main` заменяется проверкой опубликованного кандидата на **нецелевой ссылке**. Для первого исправляющего PR внешний CI удостоверяется независимо по GitHub API; самоподтверждение изменённым кодом кандидата недостаточно.

**Прямые содержательные коммиты агентов в main запрещены уже сейчас.** Узкие служебные исключения:

- новые вердикты — только в канале своей роли под `verdicts/`;
- оперативные записи — `HANDOFF.md`, журналы `NABLIUDENIA*.md`, `forks/`;
- штатные записи идентификаторов и заморозок — `registry/contracts.tsv` только предусмотренными писателями и при выполненных предусловиях.

Исключения не покрывают исторический ремонт из §2, изменение проверок, ролей, конфигурации, контрактов или CI. Между фиксацией проверенной базы и лендом служебные записи main не двигают: вердикт ревьюера заранее коммитится на отдельной судейской ссылке с указанием проверяемого SHA и публикуется в main после ленда. Эта узкая норма заменяет требование немедленного main-direct для такого вердикта.

До серверной защиты запрет — **cognitive-only**: общий credential позволяет его обойти; ловцы — независимый reviewer и аудит опубликованного диапазона. Это временная дисциплина, не доказанная граница безопасности. После включения серверной защиты служебные записи также мигрируют на доверенный маршрут; постоянного bypass для них нет.

Красный post-merge CI останавливает следующую публикацию. Исправление либо откат — тем же PR-маршрутом. Постоянный переходный допуск 100 не вводится.
