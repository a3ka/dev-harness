## Конспекты гистов tshemsedinov
- «Большие задачи» (13d53d3a…d35): большая задача = плохо исследованная область;
  цель крупная — работа дробится; отдельно выделять: исследование, архрешения,
  интеграции, миграции; НЕ отдельно: тесты, типы, доки; нужен измеримый результат;
  признаки ложной большой задачи: общий результат, много зависимостей, нет
  критерия готовности.

<!-- doc:section Конспект-вертикаль-горизонталь -->
- «Вертикаль/горизонталь» (a7c5f677…2ef): слои — границы (layered/onion), слайсы —
  ценность; не противоречат; проблемы чисто-слоевой разработки: «90% готово»,
  поздняя обратная связь; каждый кусок проходит все слои и его можно показать/
  проверить/использовать; архитектура обязана помогать поставлять value кусками
  и держать консистентность между user story.

<!-- doc:section Конспект-AC-контракт -->
- «AC как контракт» (6ce301f5…014): AC фиксируют границы, поведение, готовность;
  scenario-based (Given/When/Then) и rule-based; хороший AC — проверяемое
  утверждение (вход, действие, наблюдаемый результат); плохие: «быстро»,
  «понятный», «ошибок быть не должно»; негативные сценарии обязательны;
  AC → тест-кейсы напрямую; маленькая задача = точные конечные AC.

<!-- doc:section Конспект-ADR -->
- «ADR» (956420ff…bd6): для дорогих/трудно-обратимых (one-way-door) решений, не
  для мелочей; главное — контекст, альтернативы, последствия; фиксирует границы
  уместности и ТРИГГЕРЫ ПЕРЕСМОТРА; статусы Superseded/Historic/Obsolete; ADR —
  мышление вслух, дисциплинирует автора в момент решения.

<!-- doc:section Конспект-архдокументы -->
- «Architectural Documents» (b23c72df…304): таксономия ~70 типов доков по 9
  группам (Strategy / Requirements / Architecture&Design / Planning /
  Source&Delivery / Testing / Operations / Security&Governance /
  Knowledge&Onboarding) — МЕНЮ, из которого проект берёт минимум; ключевые для
  нас: Context map, Domain model, Event/Command catalog, Migration plan,
  Onboarding guide, Lessons learned.

<!-- doc:section Конспект-NFR -->
- «NFR» (7d520fef…63f): NFR — условия (задержка, нагрузка, потеря данных, цена
  сопровождения, режим отказа/восстановления), определяют форму решения; говорить
  языком последствий; чеклист архитектора: перед проектированием / контекст /
  декомпозиция (ответственность, не привычка фреймворка; одна причина изменения;
  имена по смыслу, не utils/common) / неопределённость (гипотеза → минимальный
  эксперимент → критерий → срок) / наблюдаемость / изменяемость.

<!-- doc:section Конспект-лингвистика -->
- «Лингвистика» (e741b323…fa6): архитектура начинается в языке; глоссарий =
  контракт по смыслу: определения И запреты слов; термины фреймворка ≠ термины
  домена; на стыках контекстов — явные переводы; термин не объясним junior за
  2–3 фразы → не созрел; глоссарий живёт в репо, обновляется вместе с ADR; без
  словаря его роль играет код — плохая замена.

<!-- doc:section Конспект-AI-сложность -->
- «AI и сложность» (566ff0f0…ab1): закон Эшби; делегируй AI то, что понимаешь и
  способен оценить; потеря контроля = не можешь проверить результат;
  характеристики кода в задании AI: парадигма, структуры данных/сложность,
  связность/зацепление, изоляция и контракты, явное/неявное состояние,
  изменчивость, расширяемость, стоимость изменений (+12: идемпотентность, границы
  транзакций, конкурентность, тестируемость, наблюдаемость…); essential vs
  accidental complexity; AI плодит строки и сложность — подавлять заранее.

## Конспект внешних доков владельца
- ARCHITECTURE.md: DDD/Onion; dependency-таблица слоёв (outer→inner, никогда
  обратно); Bounded Contexts с Implementation Status Matrix (IMPLEMENTED /
  SCHEMA ONLY / NOT STARTED); таблица «куда класть новый код»; запрет
  standalone-скриптов.
- CODING-STANDARDS.md: FP-first (pure functions, factory+composition, без
  классов); строгий TS (без any/as); именование таблицами; V8-правила (стабильные
  shapes, без delete/for-in/holey arrays); early return; discriminated unions;
  CQS; закон Деметры; мокать только внешние границы; ревью-чеклисты по ролям;
  таблица запрещённых практик.

<!-- doc:section Конспект-reslop -->
## Конспект reslop (github.com/tshemsedinov/reslop, MIT)
TUI-ревью AI-кода: цикл Review → Plan → Repair → Verify. Ревью хранится в
.review/YYYY-MM-DD-NN.md, frontmatter status: editing | ready | partial | done;
находки/чекбоксы — план починки для AI. Умеет: незакоммиченные диффы, коммит,
GitHub PR / GitLab MR; stage/unstage/revert по блокам; импорт PR-комментариев;
ветки/commit/amend/fixup; ревью npm-зависимостей. Роль у нас: канал находок
ВЛАДЕЛЬЦА (дополняет судей, не заменяет); адаптер «.review → TaskPacket» — фаза D.
