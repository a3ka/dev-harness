### Гигиена — НОВЫЕ уроки этой сессии (добавь к прежним)

1. **`GIT_CONFIG_COUNT`-формула идентичности ломает identity-чувствительные пробы**
   (Н-199 выше) — используй `GIT_AUTHOR_*`/`GIT_COMMITTER_*` для разовых `git tag`/
   `git commit` вызовов с дочерними git-процессами ниже.
2. **`freeze_contract.sh` и прочие "судящие своё дерево" скрипты — ЧУВСТВИТЕЛЬНЫ к
   тому, передан ли явный `--root`-подобный аргумент батарее.** Живой инцидент 078
   (Н-198): `bash fixtures/_krasnye_NNN.sh` БЕЗ аргумента может вести себя ИНАЧЕ, чем
   с `.` — у battery-раннеров есть `ROOT="${1:-$(computed)}"` паттерн, и вычисленный
   ROOT может БАЙТ-В-БАЙТ совпадать с «.», но поведение всё равно разойтись (корень
   расхождения для 078 НЕ найден, задокументирован как находка Н-198 для будущего).
   **Перед freeze — ВСЕГДА прогоняй В1-пробу контракта ДОСЛОВНО (с тем же argv, что
   в тексте) в одноразовом клоне, не доверяя "запускал похожую команду руками".**
3. **PR-CI gate (`gitw_preflight_071.sh`, контракт 069/071) требует ОТКРЫТОГО PR + 
   зелёного `pull_request`-run ПЕРЕД `gitw push origin main`** после ЛЮБОГО
   `land_agent.sh`-мержа. Процедура: push wip-ветки → `gh pr create` → дождись CI →
   (если PR содержит ТОЛЬКО судейский/декларативный коммит, часто цепляет весь
   repo-wide hygiene-долг, НЕ относящийся к предмету PR — почини его тоже, он блокирует
   ЛЮБОЙ push main, не только этот PR) → `gitw push origin main`.
4. **check_staged "own wip branch" guard матчит ТОЛЬКО по суффиксу ветки = author,
   НЕ по NNN** — но identity чужого НЕ-зоны-пути (напр. implementer-коммит на
   architect-ветке) ВСЁ РАВНО отклонится ПО ЗОНЕ (check_zones), отдельно от
   branch-suffix проверки. Для ЛЮБОЙ новой identity-правки — создавай/используй
   ветку, ИМЕННО суффикс которой = нужная identity, независимо от того, какой NNN
   контракт её изначально завёл.
5. **Коммит из scratch-клона (`/tmp/dev-harness-verify/**`) НЕ проходит pre-commit
   хуки** (там нет `core.hooksPath`) — ЛЮБОЙ коммит, подлежащий charter/staged-валидации,
   обязан быть **cherry-pick'нут В ОСНОВНОЙ ЧЕКАУТ** (`git fetch <scratch> <branch>:<tmpref>`
   + `git cherry-pick <sha>` там, где hooksPath активен), а не просто смержен из клона.
   Голый `git fetch ... && git merge --ff-only` НЕ запускает хуки — тоже не годится
   для валидации, только для переноса УЖЕ ПРОВЕРЕННОГО содержимого.
