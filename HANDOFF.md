### Технический канал (напоминание): `edit`/`write` заблокирован в главном чекауте для непиннованной сессии (Н-85/А-122)

Рабочий канал — ОДНОРАЗОВЫЙ SSH-клон (`git clone ssh://git@github.com/a3ka/dev-harness.git
/tmp/dev-harness-verify/<уникальное-имя>`, НЕ локальный путь — rw-ключ станции гейтится по
абсолютному cwd главного чекаута, подтверждено живьём дважды эту сессию — disposable-клоны
И pinned-worktree-пути оба получают read-only ключ), правка там через `edit`/`write`, коммит
identity явным `-c`, затем `git fetch <клон-путь> <sha>:<temp-branch>` В главном чекауте
(raw git — НЕ заблокирован), `git cherry-pick -x <sha>` на main / `git apply` на worktree,
`git branch -D <temp-branch>`, `rm -rf <клон>`. Push — ТОЛЬКО из главного чекаута через
`bash scripts/gitw push origin <ветка>` (прямой push из одноразового клона уходит МИМО
GitHub при локальном origin, read-only при реальном — Н-143).

**Архитектор-ветки блокируют ДРУГ ДРУГА по committer identity** (check_staged.sh:203-250):
ЛЮБАЯ существующая ветка `refs/heads/wip/*/architect` блокирует коммит identity=architect
на ЛЮБОЙ ДРУГОЙ ветке (даже main-direct судейский коммит не задет, но параллельный
architect-коммит на другом контракте — да). Решение этой сессией: временный `git branch -m
wip/<NNN>/architect tmp-hold-<NNN>-architect`, коммит, `git branch -m` обратно. То же для
`implementer`-суффикса. Стале-ветки (`wip/071/architect`, `wip/080/architect` после ленда)
переименованы в `archive/*` — живых `*/architect`/`*/implementer` ровно по одной на
контракт в работе (071 чисто, 080 чисто, 081 и 078 — те, что активны).
